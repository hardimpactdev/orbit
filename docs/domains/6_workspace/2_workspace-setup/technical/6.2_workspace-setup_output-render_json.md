# Technical Contract: `orbit workspace:setup` (JSON Renderer)

**Renderer:** JSON.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

[Back to the canonical technical contract.](1_workspace-setup.md)

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "set_up"
      },
      "workspace": {
        "name": "feature-a",
        "app": "my-app",
        "node": "app-1",
        "path": "/var/www/my-app/feature-a",
        "url": "https://feature-a.my-app.orbit.local",
        "php_version": "8.5",
        "php_inherited": true,
        "adopted": false,
        "lifecycle_status": "expected"
      }
    },
    "meta": {
      "node": "app-1",
      "http_probe": {
        "url": "https://feature-a.my-app.orbit.local",
        "result": "healthy",
        "status_code": 200,
        "duration_ms": 240
      },
      "warnings": []
    }
  }
}
```

### Fields

- `result.action`: One of `set_up`, `adopted`, `converged`. Describes what
  this run did.
  - `set_up` — first-time setup of a workspace path that is already in
    gateway configuration (typically just created by `workspace:new`).
  - `adopted` — first-time setup where the path existed on the node but
    was unmanaged. `workspace.adopted` is set to `true` for this run.
  - `converged` — idempotent re-application where no observable artifact
    change was needed. The durable `workspace.adopted` value is preserved
    across converged re-runs.
- `workspace`: Canonical workspace entity defined in
  [`6_workspace/README.md`](../../README.md#workspace-json-entity).
- `workspace.adopted`: Stays `true` on subsequent converged re-runs after a
  path was adopted through setup.
- `meta.node`: The owning node slug for execution context.
- `meta.http_probe`: HTTP probe result from setup time. This is command metadata,
  not durable workspace state and not the registry lifecycle status rendered by
  `workspace:list`.
- `meta.http_probe.url`: URL probed by the command.
- `meta.http_probe.result`: `healthy` or `unhealthy`.
- `meta.http_probe.status_code`: HTTP status code when a response was received;
  `null` when the probe timed out before a response.
- `meta.http_probe.duration_ms`: Probe duration in milliseconds.
- `meta.warnings`: Structured non-fatal command and family handoffs. Command
  warnings are not doctor issue codes unless their `code` is explicitly owned
  by a state family.
- `meta.warnings[].family`: Stable state family for doctor handoffs, or `null`
  for command-owned warnings that are not doctor issue codes.

## Error Envelope

### Setup-step failure

Returned when a sequential setup step exits non-zero. Earlier-phase
configuration and runtime artifacts remain in place; the retry path is
re-running the command.

```json
{
  "error": {
    "code": "workspace.setup_step_failed",
    "message": "Setup step 'npm install' failed with exit code 1.",
    "meta": {
      "step": "npm install",
      "exit_code": 1,
      "node": "app-1",
      "path": "/var/www/my-app/feature-a",
      "phase": "setup_steps"
    }
  }
}
```

### CWD is app root, not a workspace path

```json
{
  "error": {
    "code": "workspace.path_is_app_root",
    "message": "The current directory is the 'my-app' app root, not a workspace path. Use 'orbit workspace:new' to create a workspace, or change into an existing workspace path and rerun 'orbit workspace:setup'.",
    "meta": {
      "app": "my-app",
      "path": "/var/www/my-app",
      "next_command": "orbit workspace:new"
    }
  }
}
```

### Agent-IDE adapter probe failed

```json
{
  "error": {
    "code": "workspace.agent_ide_path_resolution_failed",
    "message": "The 'polyscope' adapter could not resolve the current directory to a managed workspace.",
    "meta": {
      "adapter": "polyscope",
      "path": "/var/www/my-app/.worktrees/feature-a",
      "reason": "adapter_unreachable"
    }
  }
}
```

### Validation failure (non-absolute `--path`)

```json
{
  "error": {
    "code": "validation_failed",
    "message": "The --path value must be an absolute path on the owning node.",
    "meta": {
      "field": "path",
      "reason": "must_be_absolute"
    }
  }
}
```

### Apply failure

```json
{
  "error": {
    "code": "workspace.enactment_failed",
    "message": "Workspace artifact application on node 'app-1' stopped before Orbit could classify remaining drift.",
    "meta": {
      "node": "app-1",
      "phase": "artifacts",
      "reason": "SSH stream closed before artifact probe completed"
    }
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'workspace:setup' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "workspace:setup",
      "serving_node": "app-1"
    }
  }
}
```

## Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (invalid workspace name, non-absolute `--path`, missing required field). `error.meta.field` names the offending input. |
| `workspace.path_is_app_root` | CWD is an app's own path, not a workspace path. Hint runs [`workspace:new`](../../1_workspace-new/workspace-new.md). `error.meta.{app, path, next_command}`. |
| `workspace.agent_ide_path_resolution_failed` | Agent-IDE adapter probe errored while resolving CWD. `error.meta.{adapter, path, reason}`. |
| `workspace.path_outside_policy` | The supplied generic `--path` resolves outside the parent app's `.worktrees/` workspace policy. `error.meta.path`. |
| `authorization_failed` | The caller lacks `workspace:setup` on the resolved workspace's owning node. `error.meta.reason=missing_permission`, `error.meta.missing_permission=workspace:setup`, and `error.meta.serving_node` names that node when known. |
| `workspace.enactment_failed` | Registry write succeeded, but downstream execution failed before Orbit could classify the result as repairable drift or a command-owned setup failure. `error.meta.{phase, node, reason}`. |
| `workspace.setup_step_failed` | A sequential setup step returned non-zero. `error.meta.{step, exit_code, node, path, phase=setup_steps}`. Earlier phases are not rolled back; retry by re-running `workspace:setup`. |

Retryable runtime container, runtime, or proxy drift is reported under
`success.meta.warnings[]` instead of `workspace.enactment_failed`.

## Common Warning Codes

Non-fatal command warnings and repair handoffs are reported in
`success.meta.warnings[]`. Command-owned warnings are not doctor issue codes.
State-family warnings use the stable family code that owns the repair handoff.

| Code | Family | Meaning |
| --- | --- | --- |
| `workspace.http_probe_unhealthy` | `null` | The setup-time HTTP probe returned `>= 500` or timed out. The warning is not a `workspace` doctor issue code; inspect the app or rerun `workspace:setup` after fixing application health. |
| `workspace.runtime_container_missing` | `workspace` | Workspace runtime container configuration could not be installed during application. `doctor --fix --family=workspace --restore` will repair it. |
| `workspace.runtime_config_missing` | `workspace` | Managed workspace runtime configuration is absent on the node. `doctor --fix --family=workspace --restore` will repair it. |

The `error.code` values listed here are exhaustive for `workspace:setup`.
Add a new value to this renderer contract before implementing another JSON
failure code.
