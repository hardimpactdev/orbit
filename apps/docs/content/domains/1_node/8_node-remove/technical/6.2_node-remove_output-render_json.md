# JSON Renderer: `orbit node:remove [name]`

[Back to `node:remove` technical contract.](1_node-remove.md)

This page describes the JSON-rendered output for `node:remove`.

**Renderer:** JSON renderer.

## Primitive

None. JSON renderer emits the standard envelope only.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](5.2_node-remove_input-mode_non-interactive.md), even
when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "name": "app-1",
      "action": "removed",
      "removed_self": false,
      "wireguard_peer_removed": true,
      "grants_removed": 2
    },
    "meta": []
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `name` | string | The removed node name. |
| `action` | string | Always `removed`. |
| `removed_self` | boolean | `true` when the removed node was the authenticated caller's own node record. |
| `wireguard_peer_removed` | boolean | `true` when the WireGuard peer was removed, `false` when it was already absent. |
| `grants_removed` | integer | Count of deleted `node_access` records. |

Current `RemoveNode` always returns `warnings: []` on success. Peer detach is
reported only as the boolean `wireguard_peer_removed` field, not as structured
warnings. DNS projection reconciliation failures return a retryable error and
roll registry deletion back. Peer teardown failures also return an error and
retain Orbit registry state for retry.

### Success removing the current caller without a managed peer

```json
{
  "success": {
    "data": {
      "name": "operator-1",
      "action": "removed",
      "removed_self": true,
      "wireguard_peer_removed": false,
      "grants_removed": 1
    },
    "meta": []
  }
}
```

## Error Shapes

### Missing required input

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Node name is required.",
    "meta": {
      "field": "name"
    }
  }
}
```

### Missing destructive consent

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to remove this node.",
    "meta": {
      "field": "force"
    }
  }
}
```

### Node not found

Already-absent removal returns this error shape. `node:remove` is an imperative
command against an existing gateway-owned node record, not an idempotent
absent-state convergence command.

```json
{
  "error": {
    "code": "node.not_found",
    "message": "Node 'app-1' not found.",
    "meta": {
      "name": "app-1"
    }
  }
}
```

### Gateway node removal

Returned for any target node with role `gateway`.

```json
{
  "error": {
    "code": "node.gateway_removal_denied",
    "message": "The gateway node cannot be removed with this command.",
    "meta": {
      "name": "gateway-1",
      "role": "gateway"
    }
  }
}
```

### Self-removal with a managed peer

```json
{
  "error": {
    "code": "node.self_removal_requires_remote_caller",
    "message": "Remove this node from the gateway or another authorized node.",
    "meta": {
      "name": "operator-1"
    }
  }
}
```

### WireGuard peer teardown failed

```json
{
  "error": {
    "code": "node.wireguard_peer_removal_failed",
    "message": "Node 'app-1' could not be removed because its WireGuard peer could not be detached.",
    "meta": {
      "name": "app-1",
      "retryable": true,
      "wireguard_peer_removed": true
    }
  }
}
```

The failure retains the node, Orbit peer, grants, and firewall rows. Retry the
same command after the gateway VPN runtime is healthy.

### Private DNS reconciliation failed

```json
{
  "error": {
    "code": "node.dns_reconciliation_failed",
    "message": "Node 'app-1' could not be removed because its private DNS records could not be reconciled.",
    "meta": {
      "name": "app-1",
      "retryable": true
    }
  }
}
```

The gateway rolls peer-row, grant, firewall-row, and node deletion back. Retry
the same command after private DNS activation is healthy. An already-absent
durable or live WireGuard peer is accepted during the retry. The
`wireguard_peer_removed` field records whether teardown completed before DNS
failed.

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to remove a node.",
    "meta": []
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'node:remove' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "node:remove",
      "serving_node": "app-1"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `action` | `removed` |
| `error.code` | `validation_failed`, `node.not_found`, `node.gateway_removal_denied`, `node.self_removal_requires_remote_caller`, `node.wireguard_peer_removal_failed`, `node.dns_reconciliation_failed`, `gateway_unavailable`, `authorization_failed` |

The `error.code` values listed here are exhaustive for `node:remove`. Add a new
value to this renderer contract before implementing another JSON failure code.
