# Interactive Input Mode: `orbit doctor --fix`

[Back to `doctor` technical contract.](1_doctor.md)

**Input mode:** Interactive.

Use this input mode only when `--fix` is supplied, the process is attached to a TTY, and `--json` is not present. `--fix` is the interactive driver; `--restore` and `--adopt` select bulk non-interactive modes and never enter this prompt flow.

## Prompt Contract

After probes complete, `doctor --fix` walks categories in doctor order. For each finding with at least one supported direction, render a choice prompt:

| Prompt id | Primitive | Label | Options |
| --- | --- | --- | --- |
| `doctor_fix_action` | `select` | `Resolve <finding summary>` | `restore`, `adopt`, `skip`, `details` when details exist |

## Rules

- Show only supported directions for the finding.
- `restore` applies gateway configuration to node/runtime reality.
- `adopt` updates gateway configuration from compatible observed node/runtime reality.
- `skip` records a skipped action and leaves the finding unresolved.
- `details` shows family-supplied context and returns to the same finding.
- If a category has no actionable findings, render its category status and move on without prompting.
- Prompt cancellation records no action for the current finding and exits with a command failure.
