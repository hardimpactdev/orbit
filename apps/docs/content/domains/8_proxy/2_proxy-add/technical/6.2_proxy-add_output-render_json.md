# JSON Renderer: `orbit proxy:add`

[Back to `proxy:add` technical contract.](1_proxy-add.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Error Shape

```json
{
  "error": {
    "code": "proxy.enactment_failed",
    "message": "The proxy route was saved, but backend apply failed.",
    "data": {
      "route": {
        "domain": "vite.docs.test",
        "kind": "proxy",
        "owner": {
          "type": "custom",
          "name": null
        },
        "node": "app-1",
        "target": {
          "type": "upstream",
          "value": "http://127.0.0.1:5173"
        },
        "redirect_code": null,
        "tls": {
          "managed_by": "orbit",
          "trusted_by_gateway_ca": true
        },
        "status": "expected"
      }
    },
    "meta": {
      "next_command": "doctor --family=proxy --restore --node [--node-transport=<transport>]=app-1"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.route` | object | Created or updated custom proxy route. |
| `success.meta.action` | `created`, `updated`, or `converged` | Command outcome. |
| `success.meta.warnings[]` | array | Deferred proxy restore warning and, for host-local upstreams, a `firewall_rule.host_upstream_may_block` firewall-rule warning. |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `proxy.domain_conflict`, `proxy.replacement_consent_required`, `proxy.enactment_failed` | Stable command failure code. |
| `error.data.route` | object | Proxy route configuration when a post-configuration apply failure occurred. |
| `error.meta` | object | Field, node, caller, conflicts, or recovery context for automation. |

`proxy.enactment_deferred` and `firewall_rule.host_upstream_may_block` are
command-level handoff warnings. They are not proxy or firewall doctor issue
codes; they name the family that owns the next operator action.

There is no gateway-side coverage for this command-local mapping: input handling and renderer behavior live in `apps/cli`. Gateway API behavior is mapped in the command contract file when a gateway-side surface exists.
