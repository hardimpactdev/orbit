**Does:** record one directed consumer → serving grant in the Gateway. **Does not:** change WireGuard, firewall or reachability, contact Nodes, start an Operation, manage credentials, or add bulk/wildcard grants.

## Usage

```bash
orbit node:access:add <consumer> <serving> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `consumer` | yes | Positive numeric ID of the Node that sends commands. If omitted, select this Node first using the [shared finite searchable selector](/reference/cli-ux#prompt-selection). |
| `serving` | yes | Positive numeric ID of the Node that the commands act on. If omitted, select it after the consumer using the same selector. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Machine-readable output under the [shared CLI standard](/reference/cli-ux). |

```bash
orbit node:access:add 4 7
```

## How it works

<div className="flow-at" data-chart="node/access-add"></div>

Grant administration requires [Gateway authority](/cli/node#authority); a grant only to the target does not authorize grant creation.

Both Nodes must be active. A [task VM](/reference/compute-drivers#placement-invariant) cannot be the consumer. Orbit reads these conditions from recorded Gateway state, so the command works even when either Node is unreachable.

A new grant creates exactly one `node_access` row with `consumer_node_id` and `serving_node_id` for the selected pair and preserves unrelated grants. It authorizes Gateway commands from the consumer to the serving Node, not the reverse direction or a network path. The result includes both Nodes' names and IDs as `consumer_node` and `serving_node`, with `already_exists: false`.

Repeating an existing grant succeeds with `Skipped — already granted (node_access.exists)` and `already_exists: true`. It writes nothing and creates no duplicate access row.

## Errors

| Code | Meaning |
| --- | --- |
| `node_access.consumer_id_invalid` | The consumer ID is not a positive integer. |
| `node_access.serving_id_invalid` | The serving ID is not a positive integer. |
| `http.404` | Either Node is unknown or inactive. |
| `task_vm.access_refused` | The consumer is a task VM Node. |
| `node_access.required` | The caller lacks Gateway authority under the rule above, even if it has a grant to the target. |

Every refusal leaves relevant records unchanged. Invalid supplied IDs are refused locally before a grant request.

[Verification cases](https://github.com/hardimpactdev/orbit/blob/main/swamp/proof/node/access-add.cases.yaml) cover repeats and refusals and name the missing proof capabilities.
