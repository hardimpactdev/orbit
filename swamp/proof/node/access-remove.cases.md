# node:access:remove verification cases

`node:access:remove` changes a grant and, for a grant to the Gateway Node, reloads Caddy there, so it has no chart. The proof runs the built CLI against a fresh nested topology with several Nodes and a Metrics stack, and compares the result with the Gateway records and real command access. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Remove a grant | A consumer acts on a serving Node through a grant. Remove it. | The grant is gone and the same command on the serving Node is refused. Other grants of the consumer still work. |
| Gateway grant | Remove a consumer's grant to the active `gateway` Node, with a Metrics role present and without. | The consumer cannot act through the Gateway afterwards. With Metrics, Caddy reloads on the Gateway Node and Grafana access that depends on the grant is revoked. Without Metrics, no reload runs. |
| Reload fails | Make the Caddy reload fail, then run the command again. | `metrics.caddy_publication_failed` (502), with the grant already deleted. The rerun reports `node_access.absent` and finishes the revocation. |
| Self-lockout | Remove your own access to the Gateway Node, then a consumer that is the Gateway Node's serving host. | The first result warns in human output and carries `self_lockout` in JSON. The serving host keeps its authority, so no warning appears. Fails today: the warning is set whenever the caller is the consumer. |
| Repeat | Remove a grant that is absent. | Exit 0, skipped with `node_access.absent` in human and JSON output. Nothing changes. Fails today: the result is only an `already_absent` flag with no reason code. |
| Consent | In a terminal, read the prompt, decline it, then confirm. Also run noninteractively and with `--json` without `--force`. | The prompt names both Nodes and the effect, with No selected. Declining ends with `input.cancelled`. Ctrl-C and end of input also end with `input.cancelled`. The noninteractive calls are refused with `node_access.confirmation_required` before any request. No removal request is sent until confirmed. Fails today: the CLI looks up both Nodes before it asks, and its prompt may name only IDs. |
| Inactive or unknown Node | An inactive consumer, an inactive serving Node, and an unknown ID. | `http.404`. Nothing changes. |
| Records only | Make a Node unreachable over SSH, then remove a grant for it that does not target the Gateway Node. | The grant is removed and nothing is sent to any Node. |
| Missing input | In a terminal, run the command with no arguments, then with only the consumer. Then run it noninteractively and with `--json` without the consumer, and without the serving Node. | The terminal asks for the consumer and then the serving Node from interactive lists. Ctrl-C ends with `input.cancelled` and no request. The noninteractive calls are refused with `node_access.consumer_id_invalid` and `node_access.serving_id_invalid`, with no request. Fails today: the arguments are required and nothing prompts. |
| IDs only | Pass a name, `0` and `-1` for a Node. | `node_access.consumer_id_invalid` or `node_access.serving_id_invalid`, with no request. |
| Refusals and callers | A caller without a grant to the Gateway Node, then the Gateway Node itself and its serving host. | `node_access.required` for the first, with nothing changed. The other two may remove grants. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | The result names both Nodes by name and ID and shows the request ID. The piped output has no animation or escape codes. With `--json`, stdout holds only the JSON. |
