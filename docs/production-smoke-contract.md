# Production smoke: slice 2 contract

Swamp observes the selected successful release through the Gateway. It never executes repo code or talks to GitHub. `productionSmoke` in a private project extension opts in with `{instance, baseUrl, workflow, ref, timeoutSeconds}`. The URL is an HTTPS origin; workflow is `.github/workflows/<name>.yml|yaml`. Timeout is 30–600 seconds (default 600). Omit the field to opt out. No project is enabled or scheduled by this slice. Runner selection stays in the repo.

The unscheduled `production-smoke` workflow takes `projectId`, `projectType` and `mode`. It defaults to `mode=observe`: no new intent is created. Observation is GET-only except for one bounded retry of an already saved transient admission refusal. Explicit `mode=baseline` admits one smoke for the selected release. One stable behavior per Project saves intent before dispatch. Each tick has a two-minute abort budget, including configuration and Gateway reads/writes, and respects caller cancellation. Each workflow invocation uses one native ten-second durable wait, then reads again. Re-run a pending baseline to keep observing it; it keeps its original deadline and request key. This slice does not hold deploys, roll back, resume, repair or merge.

## Orbit additions (paired implementation)

Use existing Gateway-peer authorization, JSON envelopes and operation framework. Add MCP tools `instance-smoke-context`, `instance-smoke` and `instance-smoke-receipt` for the three routes below; no new human CLI is needed. New routes below are proposals until the Orbit pair ships. Preserve existing deploy contracts. Dispatch requires repository-scoped `Actions: write`; update the Gateway App manifest and require existing installations to accept that grant before use. Result reads keep `Actions: read`. No runner credential or maintainer token is introduced.

1. `GET /api/v1/instances/{instance}/smoke/context` → `200 {data: context}`: `{instance_id:int, project_id:int, repository_url:string, production:bool, base_urls:string[], selected:{deployment_id:int, commit:sha, release:string}|null, retained_releases:string[]}`. Read the actual current selection, not a cached policy projection. `selected` must match a successful deploy/rollback row and a retained release; return null when no such receipt exists. Production requires an active app-prod role without app-dev. URLs are active public Route HTTPS origins only. Swamp checks identity, Route ownership and retention.
2. `POST /api/v1/instances/{instance}/smoke`, required `Idempotency-Key`: `{deployment_id:int, commit:sha, release:string, base_url:string, workflow:string, ref:string}` → `202 {data: OperationData}`. Operation kind `instance.smoke`, target `instance_smoke`/Instance ID; do not take the deploy operation lock. Fingerprint caller, target and full body. Bind the selected successful deployment, Project repository and Route at admission. Reject unknown fields, non-production, stale selection or foreign URLs. Dispatch the named repo workflow with `{commit, deployment_id, base_url}`. Resolve and retain the workflow ref's SHA; do not infer it from the tested commit.
3. `GET /api/v1/instances/{instance}/smoke/receipt?request_key=<key>` → `200 {data:{request_key:string, found:bool, operation:OperationData|null, smoke:result|null}}`, bound to the original caller/Instance/key. Retain keyed operations and evidence. Lookup never dispatches; missing means unresolved. A matching operation can exist before its GitHub run is known.

`result` repeats the exact POST body and adds `{state:"pending"|"passed"|"failed"|"unknown", run_id:int|null, run_attempt:int|null, workflow_sha:sha|null, run_url:string|null, conclusion:string|null, tests:int, failures:int, errors:int, skipped:int, output:string, artifacts:{name:string,url:string}[]}`. Counts are nonnegative; output is capped at 64 KiB. All response fields are required, including nulls. `sha` is a full 40-character GitHub SHA. Existing OperationData must include its bound input, target and error_code.

Gateway owns GitHub dispatch and result verification. Before the external POST, record dispatch intent. A lost reply or interrupted send must not resend it. Reconcile a unique workflow_dispatch run by workflow, ref SHA, deployment/SHA run name and admission time. Multiple matches stay unknown. Verify the run ID and attempt against the target JSON artifact and JUnit from website#18, plus workflow identity/ref, checkout SHA, deployment ID and URL. A pass requires the run's success conclusion, positive test count, and zero failures/errors/skips. Only verified executed JUnit failures/errors count as a failed smoke; worker loss, cancellation, supersession and workflow infrastructure failures without that proof are unknown. Retain test output and screenshot links; absent, expired, corrupt or mismatched evidence is unknown, never success. Poll through reads, without holding a queue worker while GitHub runs. Normal request conflicts use the operation framework; state refusal is `409 instance.smoke_selection_changed`, invalid input, ownership, eligibility or missing Actions write uses `422 instance.smoke_invalid`; a GitHub token/installation lookup outage before admission uses `503 instance.smoke_github_unavailable` and creates no operation. Access/queue failures retain existing codes.

Swamp uses `smoke.<instance>.<deployment_id>` and saves the exact body before every admission POST. Receipt lookup precedes any retry. After an uncertain admission send with `found:false`, one later explicit baseline tick may resend the identical key/body once; the permanent job saves that allowance before sending, even across a crash between job and state writes. A found operation is only read. A definite HTTP 4xx refusal or known `503 instance.smoke_github_unavailable` is `unknown` with its Gateway code retained and does not spend uncertain-send recovery; a later explicit baseline tick may retry that refused admission once per invocation after a missing receipt. These retries never change the key, body or original deadline. After the native ten-second wait, the next observe tick may retry `409 operation.target_busy` or `503 instance.smoke_github_unavailable` once while the original smoke deadline and tick budget permit. It saves a separate automatic-refusal allowance before POST; a repeated refusal cannot loop. Other observe ticks remain GET-only. This is a retry of Gateway admission; Gateway must not repeat an uncertain external GitHub dispatch.

Swamp validates operation/input/result identity and reads the receipt before applying the original smoke deadline. Final pass, verified failure or unknown results take precedence over timeout and stay final. Timeout applies only without a final result; later invocations keep reading and can adopt late results even after reporting `timed_out`. A failed/cancelled operation without verified test failure is `unknown`, with result output or, when empty, the operation error code preserved. This slice records these states; deploy holds and assistance/alerts belong to failure handling.

Gateway cancels an older smoke holder for another deployment, including queued, waiting and running operations, retaining an unknown receipt; it never cancels a newer holder for an old request. A holder that has not yielded can still refuse admission with `409 operation.target_busy`; Swamp retries the saved admission as described above.

The Gateway caps each operation observation at 720 seconds and reports `unknown` with `instance.smoke_observation_expired` when that limit expires. Swamp has its separate 30–600 second deadline and continues reading late final receipts. Clean JUnit with a failure, timed_out or cancelled GitHub conclusion is `unknown`, with `instance.smoke_run_unsuccessful` on the operation, and never triggers code rollback.

Fresh context must still select that release before storing a baseline pass. New selection leaves `superseded` visible for that tick and retains the old job; a subsequent baseline can admit the new release. Configuration changes cannot relabel existing evidence. Historical jobs retain receipts and admission/refusal metadata; the last passing baseline is separate from current status. The permanent job is authoritative when its write is newer than the state projection.

Tests cover read-only/disabled configuration, lost sends/replies and bounded same-key recovery, definite refusals, identity mismatches, unproven operation failures, late final results, cancellation budgets and durable wait recovery across native serve restart.
