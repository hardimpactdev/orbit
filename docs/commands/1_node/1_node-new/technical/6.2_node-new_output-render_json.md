# JSON Renderer: `orbit node:new [name]`

[Back to `node:new` technical contract.](1_node-new.md)

This page describes the JSON-rendered output for `node:new`.

**Renderer:** JSON renderer.

## Primitive

None. JSON renderer emits the standard envelope only.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](5.2_node-new_input-mode_non-interactive.md), even
when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Input mode failures, domain validation failures, authorization failures,
network failures, SSH failures, platform failures, and provisioning failures
must all use this envelope. Successful `node:new` responses do not include
`success.meta` unless a specific success case needs non-payload execution
context.

## Node Fields

Node fields and address fields must be explicit and role-specific. Do not
expose an ambiguous top-level `host` field in the JSON node object. Keep the
SSH/bootstrap endpoint under `provisioning.host`; keep canonical node addresses
under `node.addresses`.

Fields that are structural members of the node object, such as
`node.environment`, `node.tld`, and `node.platform`, are serialized as `null`
when they do not apply to the node role, or as `unknown` when the field applies
but the command cannot detect the value yet. Purely optional metadata fields,
such as `node.addresses.public_ipv4` and `node.addresses.public_ipv6`, are
omitted when absent and never serialized as `null`.

| JSON field | Registry source | Meaning |
| --- | --- | --- |
| `provisioning.host` | `nodes.host` | SSH/bootstrap endpoint used during bootstrap. May be a DNS name, private IP, public IP, or `null` when no SSH provisioning happens. |
| `node.tld` | `nodes.tld` | Development TLD for development app nodes. `null` for production app nodes, gateways, and control nodes. |
| `node.platform` | `nodes.platform` and platform probes | Structural platform-version identifier. Format: `<platform>_<version>` with version dots normalized to hyphens, e.g. `ubuntu_24-04` or `macos_15-4`. Use `unknown` only when platform detection is not yet possible. |
| `node.addresses.wireguard` | `nodes.wg_ip` | Orbit network address assigned to the node identity. CLI callers use the gateway address for API access; the gateway may use app-node addresses for SSH reachability. Present for every role. |
| `node.addresses.gateway_endpoint` | Gateway endpoint config | WireGuard endpoint written into generated peer configs for gateway nodes. For first-gateway bootstrap, this starts as the resolved `node_new.host`. Present only for gateway nodes. |
| `node.addresses.public_ipv4` | `nodes.public_ipv4_address` | Operator-supplied public IPv4 metadata recorded through `node:update`. Omitted when not stored; never serialized as `null`. |
| `node.addresses.public_ipv6` | `nodes.public_ipv6_address` | Operator-supplied public IPv6 metadata recorded through `node:update`. Omitted when not stored; never serialized as `null`. |

The bootstrap `--user` value is intentionally absent from successful JSON
payloads. After provisioning, Orbit stores the managed SSH user in gateway
node configuration as `nodes.user` (normally `orbit`) and uses that stored
value for later gateway-to-node work.

Public IPv4/IPv6 fields are operator-supplied metadata only. `node:new` does
not detect, infer, or store them. They are not required for any node role, are
not inferred from `provisioning.host`, are not drift-checked by node doctor, and
do not decide the gateway endpoint after bootstrap.

When public address metadata was previously stored through `node:update`, it is
included in `node.addresses`:

```json
{
  "addresses": {
    "wireguard": "10.6.0.7",
    "public_ipv4": "203.0.113.20"
  }
}
```

## Enum and identifier values

JSON enum values and structured identifiers are part of the renderer contract:

| Field | Values |
| --- | --- |
| `node.role` | `gateway`, `app`, `control` |
| `node.environment` | `development`, `production`, `null`. `null` is returned for non-app node roles; it is never a valid input value. |
| `node.platform` | Platform-version identifier such as `ubuntu_24-04` or `macos_15-4`; `unknown` when not detectable yet. |
| `node.status` | `provisioning`, `active` |
| `result.action` | `created`, `enrolled`, `provisioned`, `adopted`, `converged` |
| `provisioning.transport` | `ssh`, `wireguard`, `none` |
| `provisioning.status` | `complete`, `already_provisioned`, `enrolled`, `adopted` |
| `development_tld.gateway_dns.status` | `configured`, `already_configured` |
| `local_onboarding.wireguard` | `installed`, `already_installed` |
| `local_onboarding.gateway_trust` | `trusted`, `already_trusted` |
| `local_onboarding.gateway_config` | `stored`, `already_stored` |
| `local_onboarding.gateway_api` | `verified` |
| `gateway_trust.status` | `trusted`, `already_trusted` |
| `gateway_trust.trusted` | `true` |
| `error.meta.caller_role` | `gateway`, `app`, `control` — the role the gateway derived for the authenticated caller. |
| `error.code` | `validation_failed`, `caller_role_not_allowed`, `gateway_unavailable`, `authorization_failed`, `node.incompatible`, `node.ssh_unreachable`, `node.unsupported_platform`, `node.provisioning_incomplete`, `node.gateway_api_error` |

The `error.code` values listed here are exhaustive for `node:new`. Add a new
value to this renderer contract before implementing another JSON failure code.

## Result action and node status

`node.status` is durable registry lifecycle, not the outcome of this command
run. Command outcomes are returned as `result.action`. Bootstrap and enrollment
details are returned under `provisioning.status`.

| Human action | JSON `result.action` | JSON `provisioning.status` | JSON `node.status` after success |
| --- | --- | --- | --- |
| `created` | `created` | `complete` | `active` |
| `enrolled` | `enrolled` | `enrolled` | `active` |
| `provisioned` | `provisioned` | `complete` | `active` |
| `adopted` | `adopted` | `adopted` | `active` |
| `converged` | `converged` | `already_provisioned` | `active` |

When gateway configuration has been written but node bootstrap/readiness has not
completed yet, persisted node lifecycle is `provisioning`. Once `node:new`
returns success, the returned node lifecycle is `active`.

## Next Steps

`success.data.next_steps` is a human onboarding checklist for successful
`node:new` paths. It may be an empty array. Items are prose instructions and may
include commands inside the text, but they are not machine-runnable recovery
handoffs.

Use `next_command` only in warning or error metadata when Orbit can name one
specific recovery command.

## App-Node Success

```json
{
  "success": {
    "data": {
      "result": {
        "action": "provisioned"
      },
      "node": {
        "name": "app-1",
        "role": "app",
        "environment": "development",
        "tld": "test",
        "platform": "ubuntu_24-04",
        "addresses": {
          "wireguard": "10.6.0.7"
        },
        "status": "active"
      },
      "provisioning": {
        "transport": "ssh",
        "host": "app-1.ssh.example.com",
        "status": "complete"
      },
      "development_tld": {
        "tld": "test",
        "gateway_dns": {
          "domain": "*.test",
          "target": "10.6.0.7",
          "status": "configured"
        }
      },
      "next_steps": []
    }
  }
}
```

Production app-node JSON sets `node.tld` to `null` and omits
`development_tld`. `development_tld` is a path-specific payload for
development app-node provisioning, not a structural member of every successful
`node:new` response.

## Gateway Already Provisioned

Gateway convergence returns success when the gateway is already provisioned,
active, and compatible.

```json
{
  "success": {
    "data": {
      "result": {
        "action": "converged"
      },
      "node": {
        "name": "gateway-1",
        "role": "gateway",
        "environment": null,
        "tld": null,
        "platform": "ubuntu_24-04",
        "addresses": {
          "wireguard": "10.6.0.2",
          "gateway_endpoint": "203.0.113.2"
        },
        "status": "active"
      },
      "provisioning": {
        "transport": "none",
        "host": "203.0.113.2",
        "status": "already_provisioned"
      },
      "next_steps": []
    }
  }
}
```

## First-Gateway Bootstrap Success

First-gateway bootstrap from an unconfigured control node returns the gateway
node, the initiating control node identity named by the resolved
`node_new.control_name`, local onboarding status, and no manual `gateway:add`
next step.

```json
{
  "success": {
    "data": {
      "result": {
        "action": "created"
      },
      "node": {
        "name": "gateway-1",
        "role": "gateway",
        "environment": null,
        "tld": null,
        "platform": "ubuntu_24-04",
        "addresses": {
          "wireguard": "10.6.0.2",
          "gateway_endpoint": "203.0.113.2"
        },
        "status": "active"
      },
      "provisioning": {
        "transport": "ssh",
        "host": "203.0.113.2",
        "status": "complete"
      },
      "local_control_node": {
        "name": "control-1",
        "role": "control",
        "environment": null,
        "tld": null,
        "platform": "macos_15-4",
        "addresses": {
          "wireguard": "10.6.0.8"

        "status": "active"
      },
      "local_onboarding": {
        "wireguard": "installed",
```

## Validation Error

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Node role must be one of gateway, app, or control.",
    "meta": {
      "field": "role"
    }
  }
}
```

An invalid control-node name resolved during first-gateway bootstrap returns a validation failure
owned by the input mode and rendered with `field=control_name`:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Control node name must be a valid node name.",
    "meta": {
      "field": "control_name"
    }
  }
}
```

## Authorization Error

Caller authorization failures use caller metadata:

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "The caller is not allowed to create or provision nodes.",
    "meta": {
      "ability": "node.create",
      "caller_node": "control-1"
    }
  }
}
```

Gateway SSH authorization failures use SSH metadata:

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "Gateway cannot SSH to root@178.105.116.104.",
    "meta": {
      "host": "178.105.116.104",
      "user": "root",
      "step": "ssh_authorization",
      "error": "root@178.105.116.104: Permission denied (publickey,password)."
    }
  }
}
```

## Incompatible Existing Gateway Error

```json
{
  "error": {
    "code": "node.incompatible",
    "message": "Existing gateway is incompatible with the requested host or identity.",
    "meta": {

  }
}
```
