# Human Renderer: `orbit node:show [name]`

[Back to `node:show` technical contract.](1_node-show.md)

This page describes the human-rendered terminal output for `node:show`.

**Renderer:** Human renderer.

## Primitive

- Detail: [Show detail](../../../../ux/commands/details/show-detail.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[`interactive input mode`](5.1_node-show_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Progress Tree

`node:show` is a registry read. Execution is expected to complete below one
second and does not perform slow external work or live node probes. No progress
tree is rendered.

## Success Output

When the node is found:

```text

┌  Node: app-1
│
├  Roles         app-development, database (error)
│
├  OS            ubuntu_24-04
│
├  Peer IP       10.6.0.7
│
├  Serving       control-1: *
│
└  Consuming     —

```

The human renderer treats role assignments as the primary role view:

- when multiple role assignments exist, it renders `Roles`;
- when exactly one role assignment exists, it renders `Role`;
- when no role assignments exist, it falls back to the legacy registry `role`
  field and renders `Role`.

Role labels are ordered by assignment order and annotate non-active assignments
inline, for example `database (error)`.

The human renderer does not render `Environment`. App environment is expressed
by the `app-development` or `app-production` role assignment. JSON output keeps
the derived `environment` field for machine compatibility.

Grant labels are rendered from this node's perspective:

- `Serving` lists nodes that are allowed to consume this node;
- `Consuming` lists nodes this node is allowed to consume.

When the node has one role assignment, the singular `Role` label is rendered:

```text

┌  Node: app-1
│
├  Role        app-development
│
├  OS          ubuntu_24-04
│
├  Peer IP     10.6.0.7
│
├  Serving       control-1: *
│
└  Consuming     —

```

When the node has no role assignments, `Role` falls back to the legacy registry
role:

```text

┌  Node: legacy-control
│
├  Role        control
│
├  OS          macos_15-4
│
├  Peer IP     10.6.0.3
│
├  Serving     —
│
└  Consuming   —

```

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Missing node

```text
Node 'app-1' not found or not visible.
```

### Not authorized

```text
This node is not authorized to inspect 'app-1'.
```

### Gateway unavailable

```text
Gateway connection is required to show node details.
```
