This guide is written for you and your coding agent together. Your agent runs the commands; you handle the provider-side steps and verify each checkpoint. By the end, you will have a running Gateway, one development Node, and a sample project served at `https://hello.test`.

## Hand this page to your agent

Open this page in your agent from the top menu, or paste its URL with a prompt like this:

```markdown
Read https://orbit.nckrtl.com/docs/quickstart and guide me through it. I have two fresh Ubuntu 26.04 machines. You can reach them as root@<GATEWAY_IP> and root@<NODE_IP>. Ask me when you need something only I can do.
```

Your agent needs a shell that can reach both machines over SSH (your laptop is fine). Every code block below names the machine and account it runs on.

## Your part

Before starting, prepare the following:

- Two fresh Ubuntu 26.04 machines reachable over SSH as `root` (one for the Gateway, one for the development Node), both with outbound access to package sources and GitHub.
- UDP port `51820` open to the Gateway machine in your cloud provider firewall for WireGuard.
- Provider console access open for both machines. Orbit closes public SSH on a Node once its role is active, and you will read one SSH host fingerprint from the console.
- The WireGuard subnet `10.44.0.0/24` free on your network (otherwise tell your agent which subnet to use).

Steps that need your input are marked with **You:**.

## Your agent's part

Before running any command:

- Confirm with the user which machine is the Gateway and which is the Node.
- Check for an existing Gateway install with `id orbit` and `systemctl is-active wg-quick@orbit`. Reuse an existing installation rather than bootstrapping over it.
- Run every command on the machine and account shown in its header.
- On failure, read the error code, fix the root cause, and retry the same command. Do not rename records or add duplicate machines to work around errors.
- Never disable TLS verification (`--insecure` or equivalent).
- Keep keys, tokens, and `.env` secrets out of chat and out of Git repositories.

Verify each checkpoint before moving to the next step.

<Steps>
  <Step title="Prepare the Gateway machine" titleSize="h2">
    Install the required system packages and create the `orbit` account that owns the Gateway:

    ```bash Gateway machine · root
    apt-get update
    apt-get install --yes git curl unzip openssl sqlite3 sudo gnupg python3 \
      openssh-server ca-certificates iproute2 ufw wireguard-tools dnsmasq
    adduser --disabled-password --gecos '' orbit
    printf 'orbit ALL=(ALL) NOPASSWD:ALL\n' > /etc/sudoers.d/orbit
    chmod 0440 /etc/sudoers.d/orbit
    ```

    The `orbit` account needs passwordless sudo so bootstrap can configure Caddy, WireGuard, dnsmasq, and UFW. Run the remaining Gateway steps as `orbit` (for example with `sudo -iu orbit` or `ssh orbit@<GATEWAY_IP>`).

    **Checkpoint:** `sudo -iu orbit whoami` prints `orbit`.
  </Step>

  <Step title="Install Orbit" titleSize="h2">
    Clone the repository under `/home/orbit/orbit` and install the CLI and Gateway dependencies:

    ```bash Gateway machine · orbit
    git clone https://github.com/hardimpactdev/orbit.git /home/orbit/orbit
    cd /home/orbit/orbit
    sudo bin/php-build install --profile=gateway
    composer --working-dir=apps/cli install --prefer-dist --no-interaction
    composer --working-dir=apps/cli check-platform-reqs
    composer --working-dir=apps/gateway install --prefer-dist --no-interaction
    composer --working-dir=apps/gateway check-platform-reqs
    echo 'export PATH="/home/orbit/orbit/apps/cli:$PATH"' >> ~/.profile
    export PATH="/home/orbit/orbit/apps/cli:$PATH"
    orbit --version
    git rev-parse HEAD
    ```

    This installs `main`. If a release tag is available, check it out with `git checkout --detach <TAG>` before running Composer. Save the commit hash from `git rev-parse HEAD` to report at the end and include in any [bug report](/reference/alpha#feedback).

    `bin/php-build install` installs the pinned PHP and Composer versions from the [machine software recipe](/reference/compute-drivers#php-build). The `gateway` profile installs PCOV disabled by default. If `bin/php-build` or `check-platform-reqs` fails, stop and report the error rather than passing `--ignore-platform-reqs`.

    Create the Gateway `.env` file:

    ```bash Gateway machine · orbit
    cd /home/orbit/orbit/apps/gateway
    cp .env.example .env
    ```

    Set these values in `.env` and leave the rest at their defaults:

    ```dotenv apps/gateway/.env
    APP_ENV=production
    APP_DEBUG=false
    APP_URL=https://10.44.0.1
    ORBIT_HOME=/home/orbit/.orbit
    ORBIT_GATEWAY_CHECKOUT=/home/orbit/orbit/apps/gateway
    ```

    `APP_URL` is the Gateway's WireGuard address (adjust it if you chose another subnet), and `ORBIT_GATEWAY_CHECKOUT` must point to `apps/gateway`, not the repository root. Keep `CACHE_STORE=file` (or use `redis`, `memcached`, or `dynamodb`): the Gateway requires cross-process locks, so `array`, `null`, and `database` cache stores are unsupported.

    Create the state directory and initialize the SQLite database:

    ```bash Gateway machine · orbit
    cd /home/orbit/orbit/apps/gateway
    umask 077
    mkdir -p /home/orbit/.orbit
    touch /home/orbit/.orbit/gateway.sqlite
    chmod 0700 /home/orbit/.orbit
    chmod 0600 .env /home/orbit/.orbit/gateway.sqlite
    php artisan key:generate --no-interaction
    php artisan migrate --force
    ```

    The application key encrypts stored secrets, so back it up alongside `gateway.sqlite`. See [Update and recover a Gateway](/reference/gateway-recovery).

    **Checkpoint:** `orbit --version` prints a version and `php artisan migrate --force` finishes without errors.
  </Step>

  <Step title="Bootstrap the Gateway" titleSize="h2">
    **You:** confirm UDP port `51820` is open to the Gateway machine.

    Run bootstrap with the public address your Node will use to reach the Gateway:

    ```bash Gateway machine · orbit
    cd /home/orbit/orbit/apps/gateway
    php artisan orbit:bootstrap '<GATEWAY_PUBLIC_HOST>' --no-interaction
    ```

    Bootstrap records the Gateway Node with its `gateway` and `vpn` roles, generates the Orbit root CA and Gateway SSH key, and records the host key. Re-running it keeps the existing CA and SSH key. Pass `--wireguard-ip` and `--wireguard-subnet` if you are using a custom WireGuard subnet.

    **Checkpoint:** all four services report `active`, and `caddy version` is 2.9.0 or newer:

    ```bash Gateway machine · orbit
    sudo systemctl is-active php8.5-fpm caddy wg-quick@orbit dnsmasq
    caddy version
    ```
  </Step>

  <Step title="Use Orbit DNS on the Gateway" titleSize="h2">
    Managed Nodes configure Orbit DNS automatically, but the Gateway machine does not. Point its resolver at the Gateway's WireGuard address so it can resolve `hello.test` later:

    ```bash Gateway machine · orbit
    sudo install -d /etc/systemd/resolved.conf.d
    printf '[Resolve]\nDNS=10.44.0.1\nDomains=~.\n' | \
      sudo tee /etc/systemd/resolved.conf.d/orbit-gateway.conf >/dev/null
    sudo ln -sfn /run/systemd/resolve/stub-resolv.conf /etc/resolv.conf
    sudo systemctl restart systemd-resolved
    ```

    Orbit DNS forwards public domains to upstream resolvers so normal internet lookups keep working. See [Private DNS](/reference/private-dns).

    **Checkpoint:** both lookups return an IPv4 address:

    ```bash Gateway machine · orbit
    getent ahostsv4 gateway.orbit
    getent ahostsv4 github.com
    ```
  </Step>

  <Step title="Connect the CLI" titleSize="h2">
    Add the Gateway as a CLI profile. The CLI fetches the root certificate, verifies it against the file bootstrap created, and installs it in the system trust store (which may prompt for sudo):

    ```bash Gateway machine · orbit
    orbit gateway:add 10.44.0.1 --use --ca=/home/orbit/.orbit/ca/root.pem
    orbit gateway:status
    orbit node:list
    ```

    The Gateway authenticates callers by their WireGuard address rather than a token, and the Gateway Node itself has access to the entire fleet. Profiles live in `~/.orbit/config.json`; see the [gateway CLI](/cli/gateway) for profile management and trust recovery.

    **Checkpoint:** `gateway:status` succeeds over HTTPS and `node:list` shows the Gateway Node.
  </Step>

  <Step title="Add a development Node" titleSize="h2">
    **You:** open the Node in your provider console, run `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256`, and share the `SHA256:` fingerprint with your agent. Reading the fingerprint from the console proves you are connecting to the right machine.

    Verify that the network host presents the same fingerprint before connecting:

    ```bash Agent machine
    ssh-keyscan -t ed25519 '<NODE_PUBLIC_HOST>' 2>/dev/null | ssh-keygen -lf -
    ```

    Print the Gateway's public SSH key and authorize it on the Node:

    ```bash Gateway machine · orbit
    cat /home/orbit/.orbit/ssh/id_ed25519.pub
    ```

    ```bash Node machine · root
    install -d -m 0700 /root/.ssh
    echo '<GATEWAY_PUBLIC_KEY>' >> /root/.ssh/authorized_keys
    chmod 0600 /root/.ssh/authorized_keys
    ```

    Enroll the Node with the `app-dev` role and a `.test` development TLD:

    ```bash Gateway machine · orbit
    orbit node:add dev '<NODE_PUBLIC_HOST>' \
      --role=app-dev \
      --tld=test \
      --host-key-fingerprint='SHA256:<FINGERPRINT>'
    orbit node:list
    ```

    Orbit connects as `root` (pass `--user` if your provider uses another account), creates the managed `orbit` user, joins the Node to WireGuard, and installs `app-dev`. Once active, public SSH closes on the Node and Orbit reaches it over WireGuard only. Let the user know this is expected. See [Node provisioning](/reference/node-provisioning) for error codes.

    **Checkpoint:** `node:list` shows `dev` with an active `app-dev` role. Record its numeric ID.
  </Step>

  <Step title="Create a Project and Instance" titleSize="h2">
    A Project tracks one Git repository; an Instance is a running copy of that Project on a Node with its own domain. This example uses MDN's public learning repo so it serves a page with no dependencies or database. For private repositories, configure Git access first and keep credentials out of the URL.

    ```bash Gateway machine · orbit
    orbit project:create hello laravel-app https://github.com/mdn/learning-area.git \
      --default-branch=main --root=html/introduction-to-html/getting-started
    orbit instance:create <PROJECT_ID> <NODE_ID> default
    ```

    Use the Project ID returned by `project:create` and the Node ID from the previous step. Naming the Instance `default` gives it `hello.test`; any other name gives `<name>.hello.test`.

    <Note>
    An active Instance means Orbit prepared its source, runtime, and Route. For a real application, install dependencies, set an app key, and attach a database next. See the [Applications guide](/domains/applications).
    </Note>

    **Checkpoint:** `instance:create` prints `https://hello.test` and marks the Instance active. Record the Instance ID.
  </Step>

  <Step title="Verify the page and fleet" titleSize="h2">
    Resolve `hello.test` and fetch it using the Orbit root certificate:

    ```bash Gateway machine · orbit
    getent ahostsv4 hello.test
    curl --fail --cacert /home/orbit/.orbit/ca/root.pem https://hello.test
    ```

    The first request can return HTTP 401 while Orbit wakes the Instance; wait a moment and retry `curl`. See [runtime wake](/reference/app-dev-runtime-hibernation#wake).

    Run a fleet health check and inspect the audit log:

    ```bash Gateway machine · orbit
    orbit doctor
    orbit activity:list
    ```

    `orbit doctor` compares expected Gateway state against each Node and exits `1` on drift without changing anything. `orbit activity:list` shows recent actions across the fleet.

    If DNS fails, check WireGuard and [Private DNS](/reference/private-dns). If HTTPS fails, inspect the certificate, Caddy, and `orbit node:show <NODE_ID>`. If the wrong page renders, verify the branch and web root.

    **Checkpoint:** the response contains `This is my page` and `orbit doctor` exits `0`.
  </Step>
</Steps>

## Report back

Share these details with the user once everything passes:

- The live URL (`https://hello.test`) along with the Project, Node, and Instance IDs.
- The installed commit hash from `git rev-parse HEAD`.
- What their own laptop needs to open `https://hello.test` in a browser: WireGuard access, Orbit DNS, and the Gateway root CA trusted locally (`orbit gateway:add` installs the CA; on macOS, [`orbit dns:resolve`](/cli/dns) configures only the resolver).
- How to clean up the sample when finished: `orbit instance:destroy <INSTANCE_ID>` removes the example while keeping the Node.
