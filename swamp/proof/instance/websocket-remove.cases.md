# instance:websocket:remove verification cases

`instance:websocket:remove` removes the Reverb app from an Instance's stored configuration and has no chart. The proof runs the built CLI against a fresh nested topology with the websocket role, an active Instance that holds an app and unrelated stored keys, a production Laravel Instance that holds an app on its public Route, and an Instance that is not active. It compares the output with the Gateway records and the stored keys. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Remove | Remove the app with `--force`. | The attachment and the seven keys are gone. The unrelated keys stay, and the app stays registered. No task starts, and the workload `.env` is unchanged until `env:sync`. |
| Public app | Remove an app that is published on the public Route. | The Route's Caddy sites no longer serve the Reverb paths before the call returns, and the Route itself is unchanged. |
| Publication failure | Make the Route's serving Node unreachable, then remove a public app. | `websocket.route_publication_failed`. The attachment and the keys are already removed. After the Node is back, `node:converge NODE --force` withdraws the paths. |
| Partly stored keys | Remove an attachment of which a hand edit left only some of the seven keys. | The existing keys are removed, `Keys` still lists the seven names, and Stored keys equals the keys left. |
| Unknown attachment | An app the Instance does not hold, an app that is not registered, and a repeat after a success, with and without `--force`. | `websocket.attachment_missing`, `http.404` and `websocket.attachment_missing`, with nothing changed and no prompt in a terminal. Fails today: a terminal asks for consent first, and a call without `--force` gives `websocket.confirmation_required` before the attachment is checked. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C and end of input. Then run it noninteractively and with `--json` without `--force`. | The prompt names the app, the Instance by name and the effect, including the withdrawal of a public app's paths, with No selected. Each decline ends with `input.cancelled` and removes nothing. The noninteractive and `--json` calls are refused with `websocket.confirmation_required` and remove nothing. With `--force` there is no prompt, also with `--json`. Fails today: the prompt shows the Instance selector as typed and never mentions the public paths. |
| Selector | With `--force`: `--instance` by ID, by exact Route domain, by a domain that is not exact, and `--instance=0`, `--instance=-1` and `--instance=abc`. | The ID and the exact domain work. Each other value is refused with `http.404` and nothing is removed. |
| Instance state | With `--force`: an Instance that is not active, an Instance whose Route is changing, an Instance without a recorded source profile, and an Instance whose remaining stored configuration is already invalid. | `env.owner_unavailable`, `env.owner_unavailable`, `instance.source_profile_missing` and `env.configuration_invalid`. Nothing is removed. |
| Unknown and access | An invalid app name and a caller without a grant to the Instance's Node, in a terminal and noninteractively without `--force`. | `websocket.name_invalid` and `node_access.required`, reported before any prompt or `websocket.confirmation_required`. Nothing is removed. Fails today for `node_access.required` and an unknown Instance: the CLI sends the request after consent, so a terminal prompts first and a call without `--force` gives `websocket.confirmation_required`. |
| Missing input | In a terminal, run the command with no arguments and cancel each list. Then run it noninteractively and with `--json`. | The terminal lists the Instances and then offers the app the Instance holds. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `websocket.name_required` or `websocket.instance_required`, with no request. Fails today: the app is a required argument, so a call without it is refused by the parser, and the Instance is never prompted for. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail with the fields on the page at the wide width and labeled records at the narrow one. Keys lists the seven names, and Stored keys equals the number of keys left on the Instance. The piped output has no animation or escape codes. With `--json`, stdout holds the fields and `request_id`. Fails today: the detail names the Instance by ID only. |
| Competing changes | Remove while `env:sync`, `env:update` or another change runs on the same Instance. | Both changes complete, no write is lost, and the stored keys equal those of running the two in some order. |
| Activity | After a successful removal and a failed one. | Activity and the error hold no key value. |
