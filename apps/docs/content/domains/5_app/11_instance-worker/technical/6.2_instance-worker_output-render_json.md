# JSON Renderer: `orbit instance:worker`

[Back to `instance:worker` technical contract.](1_instance-worker.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via
`$this->line(...)`.

The JSON renderer returns the worker payload under the standard
`success`/`error` envelope.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts even when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shapes

### Show — worker disabled

```json
{
  "success": {
    "data": {
      "app": "docs",
      "instance": "development",
      "worker_enabled": false,
      "worker_config": null
    },
    "meta": []
  }
}
```

### Show — worker enabled

```json
{
  "success": {
    "data": {
      "app": "docs",
      "instance": "development",
      "worker_enabled": true,
      "worker_config": {
        "workers": "auto",
        "max_requests": 500
      }
    },
    "meta": []
  }
}
```

### Enable — readiness passed and state mutated

```json
{
  "success": {
    "data": {
      "app": "docs",
      "instance": "development",
      "worker_enabled": true,
      "worker_config": {
        "workers": "auto",
        "max_requests": 500
      },
      "changed": true
    },
    "meta": []
  }
}
```

### Enable — already enabled (no-op)

```json
{
  "success": {
    "data": {
      "app": "docs",
      "instance": "development",
      "worker_enabled": true,
      "worker_config": {
        "workers": "auto",
        "max_requests": 500
      },
      "changed": false
    },
    "meta": []
  }
}
```

### Disable — state mutated, configuration retained

```json
{
  "success": {
    "data": {
      "app": "docs",
      "instance": "development",
      "worker_enabled": false,
      "worker_config": {
        "workers": "auto",
        "max_requests": 500
      },
      "changed": true
    },
    "meta": []
  }
}
```

### Disable — already disabled (no-op)

```json
{
  "success": {
    "data": {
      "app": "docs",
      "instance": "development",
      "worker_enabled": false,
      "worker_config": null,
      "changed": false
    },
    "meta": []
  }
}
```

### Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `project` | string | Project identity slug. |
| `instance` | string | Selected instance name, unique within `project`. |
| `worker_enabled` | boolean | Whether FrankenPHP worker mode is enabled for this instance. |
| `worker_config` | object \| null | Worker policy stored on the instance. `null` only when worker mode has never been enabled. |
| `worker_config.workers` | string \| integer | `"auto"` lets FrankenPHP pick a count based on CPU; an integer pins the worker count. |
| `worker_config.max_requests` | integer | Requests each worker handles before recycling. Surfaced to the worker process as the `MAX_REQUESTS` env consumed by Laravel's stock `public/frankenphp-worker.php`. |
| `changed` | boolean | Whether the action mutated state. Present on `enable` and `disable`; omitted from `show`. |

## Error Shapes

### Missing or invalid action

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Action must be one of: show, enable, disable.",
    "meta": {
      "field": "action",
      "allowed": ["show", "enable", "disable"]
    }
  }
}
```

### Missing instance

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Instance is required.",
    "meta": {
      "field": "instance"
    }
  }
}
```

### Instance not found

```json
{
  "error": {
    "code": "instance.not_found",
    "message": "Project 'docs' not found.",
    "meta": {
      "app": "docs"
    }
  }
}
```

### Concrete instance required

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Project 'docs' requires a concrete instance selector.",
    "meta": {
      "field": "instance",
      "reason": "instance_required",
      "app": "docs",
      "instances": ["development", "production"]
    }
  }
}
```

### Unsupported runtime

```json
{
  "error": {
    "code": "instance.worker_unsupported_runtime",
    "message": "Worker mode requires runtime=php; app 'docs' uses 'static'.",
    "meta": {
      "app": "docs",
      "missing": ["runtime=php"],
      "runtime": "static"
    }
  }
}
```

### Serving node missing from the selected instance

```json
{
  "error": {
    "code": "instance.worker_unknown_node",
    "message": "Instance 'docs.development' has no serving node; cannot validate worker readiness.",
    "meta": {
      "instance": "docs.development",
      "missing": ["driver_config.node"]
    }
  }
}
```

### Source path missing from the selected instance

```json
{
  "error": {
    "code": "instance.worker_missing_path",
    "message": "Instance 'docs.development' has no source path; cannot validate worker readiness.",
    "meta": {
      "instance": "docs.development",
      "serving_node": "app-1",
      "source_path": null,
      "missing": ["driver_config.path"]
    }
  }
}
```

### Readiness failed

`error.meta.missing` enumerates every unmet condition. The worker-file entry
in `missing` and `error.meta.worker_file` always reflect the configured
`document_root`. For example, an app with `document_root=web` reports
`web/frankenphp-worker.php` instead of `public/frankenphp-worker.php`.
`error.meta.probe_output` contains the raw probe stdout for debugging.

```json
{
  "error": {
    "code": "instance.worker_readiness_failed",
    "message": "Instance 'docs.development' is not ready for worker mode.",
    "meta": {
      "instance": "docs.development",
      "serving_node": "app-1",
      "source_path": "/home/orbit/apps/docs",
      "missing": [
        "vendor/laravel/octane",
        "public/frankenphp-worker.php",
        "octane.server=frankenphp"
      ],
      "probe_output": "",
      "worker_file": "public/frankenphp-worker.php"
    }
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'instance:worker' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "instance:worker",
      "instance": "docs.development",
      "serving_node": "app-1"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to manage worker mode.",
    "meta": []
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `action` argument | `show`, `enable`, `disable` |
| `worker_config.workers` | `"auto"` or a positive integer |
| `error.code` | `validation_failed`, `instance.not_found`, `instance.worker_unsupported_runtime`, `instance.worker_unknown_node`, `instance.worker_missing_path`, `instance.worker_readiness_failed`, `authorization_failed`, `gateway_unavailable` |

The `error.code` values listed here are exhaustive for `instance:worker`. Add a
new value to this renderer contract before implementing another JSON failure
code.

## Test Mapping

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/App/AppWriteCommandTest.php` | JSON envelope shape, worker payload for show/enable/disable, and the `changed` flag. |
| `apps/gateway/tests/Feature/Http/Api/AppWorkerControllerTest.php` | API JSON envelope shape, success payload, HTTP status mapping for `instance.not_found` (404) and `instance.worker_readiness_failed` (422), and `authorization_failed` for the `instance:worker` permission. |
| `apps/gateway/tests/Unit/Services/Apps/AppWorkerReadinessTest.php` | Service-level `instance.worker_unknown_node` (missing instance `driver_config.node`) and `instance.worker_missing_path` (empty instance `driver_config.path`) error code paths. |

JSON rendering itself is owned by `apps/cli`; gateway and unit rows cover API
and service error sources. Documented `error.code` values named for coverage
tracking: `validation_failed`, `instance.not_found`,
`instance.worker_unsupported_runtime`, `instance.worker_unknown_node`,
`instance.worker_missing_path`, `instance.worker_readiness_failed`,
`authorization_failed`, `gateway_unavailable`. Linked tests cover only the
mapped assertions above; remaining assertions for renderer codes stay as
coverage gaps until focused tests land.

The `instance.worker_unknown_node` path is covered at unit level because normal
command resolution rejects an instance with incomplete driver placement before
the readiness service is invoked through the full command path.
