---
title: "orbit node:role:list"
sidebarTitle: "node:role:list"
description: "List the roles of one Node with their status and failed step."
---

```bash
orbit node:role:list <node> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `node` | yes | Numeric Node ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Print the roles as JSON: `assignments`, each with `id`, `role`, `status`, `failed_step` and `error_code`, which are null when unset. |

```bash
orbit node:role:list 7
```

In a terminal, an omitted Node is chosen from an interactive list. A noninteractive or `--json` call without it is refused with `node.id_invalid` and sends no request, and so is an ID that is not a positive integer. The caller needs an access grant to the Node (`node.access_denied`), and an unknown Node is refused with `http.404`.

The list shows what Orbit has recorded for the Node. It does not contact the Node, so it works while the Node is unreachable. It has one row per role assignment, sorted by role name, with the columns ID, ROLE, STATUS, FAILED STEP and ERROR CODE. A missing value shows `—`. A Node without roles says `No roles.`.

A role's status is `provisioning`, `active`, `failed`, or `removing`. A failed role keeps its failed step and error code. A `converge:` failure is retried with [`node:role:add`](/cli/node/role-add) and `--converge`. A `remove:` failure is retried by running [`node:role:remove`](/cli/node/role-remove) again. A `provisioning` or `removing` role is in progress until its claim goes stale.
