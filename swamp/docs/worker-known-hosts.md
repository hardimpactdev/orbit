# Worker known-hosts publication

The Gateway records Node SSH host pins. When a persisted pin or WireGuard address changes, it admits `node.worker_known_hosts`, targeting Node209. The public intent contains the complete recorded WireGuard host-key lines and their content digest. Missing pins are omitted; this workflow never scans a host or accepts a first-contact key. The existing `SwampSshExecutionInput` remains the target and identity supplier.

Official `@swamp/cfgmgmt` version `2026.10.27.1` exposes no host-key or known-hosts connection input. Its documented `accept-new` SSH policy requires the runner's `~/.ssh/known_hosts` to be seeded before the first connection. Its file model is SSH-only, including for localhost. The shared publication therefore uses Swamp core `command/shell`, placed on209, with one shipped local script. Families consume that preseed and add no trust adapter or writer.

The script resolves the executing account's home through the account database, rather than the worker's `HOME` environment override. It creates a missing `.ssh` directory as0700 and atomically replaces `known_hosts` with a0600 regular file. Identical content with the correct mode stays unchanged. Failure before replacement preserves the old file. The script prints only public readiness, content digest and change metadata. It reads no key, opens no SSH connection and changes no worker unit.

The Gateway serializes admissions on the control Node record and keeps one unfinished publication. If pins change while it runs, terminal projection admits a new snapshot of the current pins. A failed publication is not retried without a new pin snapshot. HTTP idempotency for the caller remains separate from this automatic intent. Native execution, ordering and terminal history remain Swamp-owned.

Publish and validate the native workflow, establish the existing Gateway principal's exact workflow run/read authority, then take up the Gateway source. A successful terminal publication is the live prerequisite for cfgmgmt consumers. Source merge, an SSH authentication proof, or a configured worker capacity alone does not establish it. Quiet windows and worker maintenance remain separately owned; this source authorizes no immediate host change.
