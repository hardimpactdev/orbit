# JSON Renderer: `orbit app:list`

[Back to `app:list` technical contract.](1_app-list.md)

This page describes the JSON-rendered output for `app:list`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

The app array is rendered as a flat array under `success.data.apps`. Apps are
sorted by app name (ascending, case-insensitive). Each logical app appears at
most once and includes its placement-visible registered workspaces under
`workspaces`, sorted by workspace name (ascending, case-insensitive). A parallel
`success.data.inventory` array uses the same ordering and contains the visible
instance and workspace counts keyed by app name.

`app:list` does not include `success.data.context` because it has no resolved
node or execution context.

The canonical app entity still contains a `node` field. That field is
logical-app default metadata, not list scope or proof of concrete placement.

## Success Shape

```json
{
  "success": {
    "data": {
      "apps": [
        {
          "name": "docs",
          "node": "app-1",
          "url": "https://docs.test",
          "path": "/home/docs/app",
          "root": "public",
          "repository": null,
          "runtime": "php",
          "runtime_config": {
            "proxy_transport": "http"
          },
          "php_version": "8.5",
          "worker_enabled": false,
          "worker_config": null,
          "adopted": false,
          "workspaces": [
            {
              "name": "feature-a",
              "url": "https://feature-a.docs.test",
              "lifecycle_status": "active"
            }
          ]
        }
      ],
      "inventory": [
        {
          "app": "docs",
          "instance_count": 1,
          "workspace_count": 1
        }
      ]
    },
    "meta": []
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `apps` | array | Ordered list of visible logical apps, with every app included at most once. |
| `apps[]` | object | Canonical app JSON entity plus the placement-visible `workspaces` inventory. App registry rows are desired state; no separate app `status` field is emitted. |
| `apps[].workspaces` | array | Placement-visible workspaces registered to the app, ordered by workspace name. Empty when no workspaces are visible. |
| `apps[].workspaces[].name` | string | Workspace identity slug. |
| `apps[].workspaces[].url` | string | Primary intended workspace URL. |
| `apps[].workspaces[].lifecycle_status` | string | Registry configuration lifecycle from the workspace row. This is not setup-run status and not a live readiness result. |
| `inventory` | array | Placement counts ordered alongside `apps`. |
| `inventory[].app` | string | Logical app name matching the corresponding canonical app item. |
| `inventory[].instance_count` | integer | Number of placement-visible app instances. |
| `inventory[].workspace_count` | integer | Number of placement-visible workspaces across the visible instances. |

## Error Shapes

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to list apps.",
    "meta": []
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to read the app registry.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "app:read"
    }
  }
}
```
