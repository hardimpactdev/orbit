description: "List a Project's setup steps in order."
---

```bash
orbit instance:setup-step:list --project=ID [--json]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--project=ID` | prompt | Numeric Project ID. |
| `--json` | off | Print the steps as JSON. |

```bash
orbit instance:setup-step:list --project=4
```

In a terminal, an omitted Project is chosen from an interactive list. A noninteractive or `--json` call without it is refused with `project.id_invalid` and sends no request, and so is a value that is not a positive integer.

The list shows what the Gateway stored for the Project. It does not contact any Node, so it works while a Node is unreachable. The Gateway Node, and any Node with a grant to it, can list every Project. Any other caller needs a grant to one Node that holds an Instance of the Project, or to the Gateway Node when the Project has none. [Activity](/cli/activity) never holds command text.

| Column | Meaning |
| --- | --- |
| `POSITION` | The step's place in the list, from 1. The steps run in this order. |
| `NAME` | The step name. |
| `TIMEOUT` | The step's timeout in seconds, such as `240s`. |
| `COMMAND` | The shell command. A long command wraps and is never cut, and the lines of a multiline command are kept. |

An empty list says `No setup steps found.`. The human output ends with the request ID. With `--json`, stdout holds `{ steps, request_id }`: the steps in order, each with `name`, `command` and `timeout_seconds`, and an empty `steps` list when there are none. JSON has no `position`; the array order carries it. See [Instance setup and teardown](/reference/instance-setup) for the limits and the execution contract.

## Errors

| Code | Meaning |
| --- | --- |
| `project.id_invalid` | The Project is missing in a call that cannot prompt, or is not a positive integer. |
| `input.cancelled` | You cancelled the Project list. |
| `http.404` | The Project is unknown, also for a caller with no grants. |
| `node_access.required` | The caller has no access grant to a Node that holds an Instance of the Project, or to the Gateway Node when it has none. |
