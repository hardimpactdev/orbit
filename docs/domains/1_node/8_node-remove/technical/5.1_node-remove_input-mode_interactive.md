# Interactive Input Mode: `orbit node:remove [name]`

[Back to `node:remove` technical contract.](1_node-remove.md)

This page describes how interactive input mode resolves `node:remove` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_node-remove_input-mode_non-interactive.md`](5.2_node-remove_input-mode_non-interactive.md) even if the process has a TTY.

App-role callers and unconfigured operator callers are rejected before this input
mode renders any prompt.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- Require destructive confirmation before side effects.
- Skip the confirmation prompt when `--force` is present.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `node_remove.name` | `[name]` is missing. |
| 2 | `node_remove.confirm` | `--force` is absent and the resolved name is valid and not a gateway node. |

## Prompt Mapping

### `node_remove.name`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select a node to remove` |
| Source | `[name]` |
| Required | yes |
| Choices | Visible active nodes. |
| Default | none |
| Validation timing | When `[name]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

### `node_remove.confirm`

| Property | Value |
| --- | --- |
| Primitive | `confirm` |
| Label | `Remove node '{name}'? This cannot be undone.` |
| Self-removal label | `Remove this client from the fleet? This machine will lose Orbit gateway access.` |
| Source | interactive destructive consent |
| Required | yes |
| Default | `false` |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | If declined, fail before side effects with `Operation cancelled.` |

Use the self-removal label when the target node record matches the
authenticated operator caller identity. The self-removal prompt uses the same
prompt ID, primitive, default, and cancellation behavior.

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid supplied node input fails before side effects. Prompted node input is
  selected from visible active nodes.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If the target node is any gateway node, fail before side
  effects after the name is resolved.
- If `--force` is present, skip `node_remove.confirm`.
- If the user declines the confirmation prompt, exit with the standard command
  failure status and do not start side effects.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
