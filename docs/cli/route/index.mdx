A Route is a domain that reaches an Instance or a Node service. Orbit creates a Project Route for every Instance of a web-serving Project. The `route` family creates explicit Project Routes and custom proxy Routes, changes their targets, domains, and publication, and removes them.

The [Routes reference](/reference/routes) describes the Route record, domain selection, traffic setup, and the rules that refuse a change while an active Instance depends on a Route.

## Commands

| Command | Result |
| --- | --- |
| [`route:create`](/cli/route/create) | Create an explicit app Route for an Instance or a Node-owned custom proxy Route. |
| [`route:list`](/cli/route/list) | List Routes. |
| [`route:show`](/cli/route/show) | Show one Route. |
| [`route:update`](/cli/route/update) | Change the domain, publication, or web root of a Project Route. |
| [`route:target:set`](/cli/route/target-set) | Set the target, or a complete production target set. |
| [`route:target:unset`](/cli/route/target-unset) | Clear the target. |
| [`route:destroy`](/cli/route/destroy) | Remove a Route. |

Every command accepts `--json`. Route, Project, Instance, and Cluster arguments are numeric IDs. Human lists show a table with every target of a pool. `route:show` shows a detail tree with identity, scope, targets, publication, lifecycle, and replacement fields. Writes record an Operation and return HTTP 202. Swamp executes its recorded intent. The CLI follows the Operation and shows its proven steps; `--json` returns the final Operation. Use `--idempotency-key=KEY` to replay the same admission after a lost reply. Read the resulting Route with `route:show`.

## How it works

Node Caddy builds and Gateway release handoffs publish the complete captured configuration through one native run. Route changes compose their own contributions inside their parent run.
