# Command development pipeline

Design the proof, implement the feature, and pass its end-to-end proof in one container task copy before opening any pull request. Commit the spec (chart, page, and cases) first, follow with implementation on the same branch, and open one complete PR. CI confirms a result you already proved.

The stage charts in `docs/reference/pipeline/` own the flow. The [contributor guide](/contributor-guide) owns contribution checks, and [Build a feature in one copy](/reference/tasks#build-a-feature-in-one-copy) owns the inner loop.

| Stage | Current state |
| --- | --- |
| [1. Prep](#1-prep) | Contributor workflow; no automated prep operation |
| [2. Development environment](#2-development-environment) | Container task copy with an optional nested fleet |
| [3. Proof](#3-proof) | Author proof in the task copy; merge-base replay unavailable |
| [4. PR and CI](#4-pr-and-ci) | Complete PR after proof; CI proof gated by `ORBIT_PROOF_ENABLED` |
| [5. Automatic Swamp release](#5-automatic-swamp-release) | Runs when automatic releases are enabled and unpaused |
| [6. Per-Node seed refresh](#6-per-node-seed-refresh) | Refreshes nested-fleet default seeds after verified releases |

## 1. Prep

Define the intended behavior before writing code: draw the chart, write the CLI page, and author runnable proof cases as the branch's first commit. Validate the spec and have an independent agent review it before implementing. Record unsupported assertions as `uncovered` instead of inventing runner steps, and close those gaps before claiming proof.

## 2. Development environment

[`task:start`](/cli/task/start) clones a copy of the Project's default container Instance. Command development uses a Project with a nested fleet (`gateway`, `app-dev`, `app-prod` containers inside the copy) that mounts the copy's checkout directly. Task copies consume no CI places and get no separate Node identity. Apply migrations and service changes inside the copy before exercising the nested Gateway API.

<div className="flow-at" data-chart="reference/pipeline/2-development-environment"></div>

- **Commands:** [`task:start`](/cli/task/start), [`task:sync`](/cli/task/sync), [`task:cancel`](/cli/task/cancel)
- **Contracts:** [Task copy](/reference/tasks#task-copy), [Nested fleet](/reference/development-containers#nested-fleet)
- **Skill:** [developing-commands](https://github.com/hardimpactdev/orbit/blob/main/.agents/skills/developing-commands/SKILL.md)

## 3. Proof

Run the proof end to end in the same task copy before opening a PR: `orbit proof COMMAND --group=GROUP` ([`orbit proof`](/cli/proof/proof)). It tests the copy's current checkout (committed or uncommitted), plans cases, resets the nested fleet to `base` before each batch, applies the checkout, checks readiness, and runs the cases under the runner's locks. No reset runs after the final batch so you can inspect receipts and fleet state.

**Merge-base replay is unavailable in copies.** `fails_on_base` stays as case metadata rather than an executed check ([ProofMergeBaseReplay](https://github.com/hardimpactdev/orbit/blob/main/apps/gateway/app/Domain/Proof/ProofMergeBaseReplay.php), [old paths](/reference/old-paths#the-task-vm-proof-run)).

## 4. PR and CI

Run an independent review on the complete diff (including the [plug-in point checklist](/reference/extensions#add-a-plug-in-point) when relevant), fix findings, re-run affected checks and proofs, and open one complete PR against `main` with proof evidence in the body.

CI selects checks by changed paths and aggregates them in `Required checks`. CI proof (`proof-run` and `proof-outside.yml`) requires `ORBIT_PROOF_ENABLED=true`; while unset or `false`, green CI does not substitute for author proof. When enabled and selected by `swamp/proof/selection.txt`, `bin/ci-proof-run` calls [`proof:run COMMIT`](/cli/proof/run) on separate copies of the proof Project's default Instance (requiring maintainer approval and the `run-proofs` label on fork PRs) and destroys those copies when the run ends. Keep `ORBIT_PROOF_ENABLED` separate from the Gateway's `proof.execution` switch ([the execution switch](/cli/proof/run#the-execution-switch)).

After CI and review pass, PRs merge through the [merge queue](/reference/implementation-loop#merge-queue). Main verifies the queue's commit and promotes its delivery inputs.

## 5. Automatic Swamp release

When automatic releases are enabled and unpaused, the Gateway polls every five minutes for the newest delivery-ready commit on `main`. One Swamp run builds the release, snapshots and migrates, waits for active Operations, loads Swamp, drains Horizon, switches the release, verifies health and version (rolling back on failure), and restarts Horizon.

<div className="flow-at" data-chart="reference/pipeline/5-automatic-release"></div>

- **Owners:** [Automatic releases](/reference/gateway-recovery#automatic-releases), [`gateway:release:deploy`](/cli/gateway/release-deploy)

## 6. Per-Node seed refresh

When `ORBIT_INSTANCES_NESTED_FLEET_REFRESH` is enabled, a verified Gateway release admits best-effort deployment of each nested-fleet default Instance after Horizon starts. The refresh updates the inner fleet, retakes `base` where needed, and snapshots the new container/volume seed pair for future clones. Existing task copies keep their own fleet.

<div className="flow-at" data-chart="reference/pipeline/6-task-image-seed-refresh"></div>

- **Owners:** [Refresh after a release](/reference/development-containers#refresh-after-a-release), [fleet-refresh.mmd](https://github.com/hardimpactdev/orbit/blob/main/docs/cli/instance/container/fleet-refresh.mmd)

## Capacity model

Task copies do not consume CI places. `proof:run` shares CI places with runner jobs, balances batches across available warm or newly cloned copies, waits up to 120 minutes from Operation creation for capacity, and destroys every proof copy at run end ([`proof:run`](/cli/proof/run#the-run)).
