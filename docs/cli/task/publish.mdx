Push an [eligible checked candidate's](/reference/tasks#check-an-external-group) commit for an external group. When hosted CI is required, the owning handoff operation must have succeeded with passed CI on that check/commit. Optionally open or update its pull request. See [Publish an external group](/reference/tasks#publish-an-external-group).

```bash
orbit task:publish 42 --check=17 --title="Deliver the feature" --body="Adds the feature."
```

The optional `task` argument is the numeric task group ID. `--check` supplies the eligible handoff check ID. Supply `--title` and `--body` together to publish a pull request, or omit both to push only. Add `--draft` to open a new pull request as a draft; it needs `--title` and `--body`, and an open pull request keeps its state. `--idempotency-key` reuses an operation start. The command follows the operation with the shared display and supports `--json`.

A group whose workspace is a [task copy](/reference/tasks#task-copy) publishes the same way and gets the same result. Its commit leaves the copy as a bundle; the push and the pull request run on the Swamp worker, so the copy never holds a token. A range from the copy's start that holds the copy's `.env` in any commit fails with `tasks.publish_secret_path`, and nothing is pushed. A range that holds the `.env` content or one of its values under another name fails with `tasks.publish_secret_content`, which names the commit; a content check that cannot run fails with `tasks.publish_secret_unchecked`. A copy publishes only for a nested-fleet trial Project or a Project on the Gateway's `ORBIT_TASKS_COPY_PUBLISH_PROJECTS` list. Any other copy publish fails at once with HTTP 409 `tasks.copy_publish_held`; the checked commit stays in the copy until the Project is released for publishing. A copy whose last completion failed answers HTTP 409 `tasks.copy_completion_failed` until a [retried completion](/cli/task/start#when-the-start-fails) succeeds. A copy that is not `active` yet answers `tasks.copy_not_ready`. Each long step of a copy's publish names its Swamp behavior by the group, so publishes of two groups whose copies share a Node never wait for each other ([Two groups on one Node](/reference/tasks#two-groups-on-one-node)). A step that still waits too long for a behavior lock fails with `tasks.publish_lock_timeout`; run the command again.

For a group whose workspace is a task copy, `task:publish <group>` without `--check`, `--title` and `--body` releases the group once its work is done. It publishes the group's done check with a title and body that Orbit writes, and opens a ready pull request, as the [automatic publish](/reference/tasks#publish-by-itself) of a `pr_when_done` group does. It fails with `tasks.not_done` (409) while the work is not done, and a group without a task copy still needs `--check` (422). `task:show` reports the group as `waiting_for_release` until then. A done check whose automatic publish failed on a lock timeout is started again by the tick, up to 3 attempts; this release publishes it at once, whatever the tick does.

```bash
orbit task:publish 42
```

A task copy's publish also carries the waiver lines of its proposed pull request body, `.git/orbit/proposed-pr-bodies/task-<id>.md`, into the body: each `Docs-unaffected:` line that the body lacks is appended while the body stays within the limit, and the `.env` content check reads the final body. See [Docs-impact waivers in a copy](/reference/tasks#docs-impact-waivers-in-a-copy).

Orbit merges no pull request of a group whose workspace is a task copy; a person merges it on GitHub. See [No merge](/reference/tasks#no-merge).
