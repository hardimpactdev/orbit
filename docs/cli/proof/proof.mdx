```bash
orbit proof <orbit-command> [--group=ID] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `orbit-command` | yes | The Orbit command whose cases to run, such as `firewall:allow`. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--group=ID` | the caller's own VM | Prove in the workspace of this task group: its task copy or its task VM. For a Node with Gateway access, such as an operator machine. A task copy is always named this way. |
| `--idempotency-key=KEY` | generated | Retry the same start with a permanent key. See [Start keys](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Print the final result as JSON, with the verdict of each case. |

```bash
orbit proof firewall:allow
```

```bash
orbit proof firewall:allow --group=4993
```

The workspace is a [task copy](/reference/tasks#task-copy) or a task VM. Task VMs are [off in the live fleet](/reference/old-paths#off-in-the-live-fleet), so today the workspace is a task copy, named with `--group` from a Node with Gateway access. On a task VM the Gateway can also find the VM and its task group by the calling Node. The command takes no commit. The route needs Gateway access, which a task VM does not hold, so a Node with Gateway access, such as an operator machine, names the group with `--group` instead. In a terminal, an omitted command is asked for with a text prompt. A noninteractive or `--json` call that omits it is refused with `proof.command_invalid`, and so is a value that is not `family:command`. A refused call sends no request.

Built, not yet passed live: the run in a task copy, and the restore of `base` on either workspace. A task copy has no restore of `base` yet: the run skips the first and the last restore, and only the first batch runs. A copy starts as `base`, so its first batch starts from the right state. Each later batch is `unrun` with cause `infrastructure`, so the command does not pass until the restore lands. A copy proves once: cases undo nothing, so after a proof or an agent turn in the copy its fleet may have moved, and a new proof is refused with `proof.copy_fleet_used`. Start a new task copy. The run needs the pinned Ansible controller in the copy; until the image carries it, the runner builds it with `python3 -m venv`, which needs the `python3-venv` package in the copy.

The cases file is `swamp/proof/<family>/<command>.cases.yaml` in the checkout of the workspace (`/srv/workspace` in a task copy), so the cases run against the code that you have now, committed or not. Colons after the family become hyphens in the file name: `orbit proof node:role:add` runs `swamp/proof/node/role-add.cases.yaml`. The CLI under test is the one built from that checkout. This is the stage 3 proof of the [command development pipeline](/reference/command-development-pipeline#3-proof), run in the development environment you already have. [`proof:run`](/cli/proof/run) is the CI path: it proves a commit on a VM of its own. The execution switch of `proof:run`, `ORBIT_PROOF_RUN_EXECUTION`, does not apply here: this command creates no group, no copy and no VM.

The command is `family:command`, optionally with more colon-separated command parts. Each part starts with a lowercase letter. The family accepts lowercase letters, digits and underscores; command parts also accept hyphens. Only a command that has a cases file can be proved.

## The run

The Gateway records the intent as the operation `proof.verify`, on the task group, and starts the Swamp workflow `proof-fleet-verify` with the workspace as input. No step calls the Gateway, and the run gets no secret. In a task copy, each runner call goes over SSH to the copy's Node, then `incus exec` into the copy and `runuser -u agent`, as a [copy turn](/cli/task/turn#a-task-that-runs-in-a-copy) does. The runner runs as `agent` against the copy's own nested fleet. The command on the Node has the fixed shape of a copy turn. Only the Incus project and container name stand before the `--` of `incus exec`. They come from the Gateway's record of the copy, never from the copy or from the caller, and the Gateway refuses a name that is not one plain Incus name. Everything the copy's checkout supplies goes after the `--`. Unlike a copy turn, the runner keeps the copy's recorded Incus environment, so it reaches the network through the copy's proxy, and its stdin is closed. On a task VM, each call goes over SSH into the VM. The workflow:

1. Reads the cases file and plans the batches. A missing or invalid file fails the run here, before the fleet changes.
2. Restores the snapshot `base` of the nested fleet, because the fleet may have moved since your last proof (about 16 seconds; each snapshot restore has 45 seconds, then readiness waits at most 120 seconds for a healthy Doctor; no retry).
3. On a task VM, when the Swamp tokens in `base` are older than 20 days, renews them with the step of the provision, checks readiness and takes `base` again, so that the batches keep the new tokens. A task copy skips this: the refresh after each release renews the tokens of the seed it is copied from.
4. Runs the batches in the order of `swamp/proof/batches.yaml`: one restore of `base` per batch but the first, the start state of the batch, then each case on its own resources with no undo. A case that did not pass triggers a restore before the next.
5. Restores `base` once more, so that you keep working on a clean fleet that runs your latest code. This runs also after a failed case.

A run that you cancel with Ctrl-C leaves the fleet as it is. The next proof restores `base` first.

While the run holds the task group, another operation on the group is refused with `operation.target_busy`. The turn of the agent that calls does not count: an agent can run `orbit proof` from inside its own turn. The operation has a budget of 50 minutes.

## Verdicts

Each case ends `passed`, `failed` or `unrun`, as in [`proof:run`](/cli/proof/run#verdicts). The result names the command, the cases file and each case with its verdict, duration, cause and failed checks. Human output prints the table, then one line for each case that did not pass, with its cause and failed checks. The receipt of each case stays in the evidence directory of the workspace, `.orbit-artifacts/<group>/verify` in its checkout, so you can read the full output of a failed case there.

| Outcome | Exit status |
| --- | --- |
| Every case passed and the last restore succeeded. | `0` |
| A case failed or did not run, or the last restore failed. | Nonzero. The command names each case that did not pass. |
| Orbit refused the request. | Nonzero, with the one-line error envelope. |
| You pressed Ctrl-C. | `130`. |
| The process received SIGTERM. | `143`. |

## Errors

| Code | Meaning |
| --- | --- |
| `proof.command_invalid` | The command is missing or is not `family:command`, and the CLI cannot prompt. |
| `proof.group_invalid` | `--group` is not a positive number. The CLI sends no request. |
| `proof.no_task_vm` | The calling Node is not a task VM, and no `--group` names one. Run the command on the VM you develop in, or name its group. |
| `tasks.group_missing` | The group that `--group` names does not exist. |
| `proof.wrong_project` | A task VM's group is not on the Orbit Project, or a task copy's Project has no nested fleet. Cases exist only for the Orbit repository, and they need a nested fleet. |
| `tasks.no_workspace` | The group has no owned task VM workspace and no task copy. |
| `tasks.copy_not_ready` | The task copy is not `active` yet. |
| `tasks.instance_not_running` | The container of the task copy is not running. |
| `proof.copy_fleet_used` | A proof or an agent turn has already run in the task copy, and a copy cannot restore its fleet yet. Start a new task copy. |
| `tasks.copy_turn_unended` | An earlier turn may still run in the task copy. Run `task:cancel` to end it with the copy. |
| `tasks.group_closed` | The task group has ended. |
| `operation.target_busy` | Another operation holds the task group. The details name it. |
| `proof.cases_failed` | A case failed or did not run. The result holds each verdict. |
| `proof.run_failed` | The plan, the first restore or a step before the cases failed, or the cases printed no verdict. Every case is `unrun`. |
| `proof.restore_failed` | Every case passed, but the last restore failed, so the fleet is not clean. Run `orbit proof` again to restore it. |
| `node_access.required` | The calling Node has no access grant to the Gateway Node. |
| `extension.disabled` | The tasks extension is off. |
