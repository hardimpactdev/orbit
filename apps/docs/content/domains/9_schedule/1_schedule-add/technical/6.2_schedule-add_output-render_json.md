# JSON Renderer: `orbit schedule:add`

[Back to `schedule:add` technical contract.](1_schedule-add.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "result": {
        "action": "created"
      },
      "schedule": {
        "name": "laravel-scheduler",
        "scope": "instance",
        "target": {
          "type": "instance",
          "name": "docs.production",
          "node": "app-1"
        },
        "interval": "every minute",
        "timezone": "Europe/Amsterdam",
        "execution": {
          "type": "command",
          "value": "php artisan schedule:run",
          "timeout_seconds": 900
        },
        "enabled": true,
        "status": "expected",
        "last_run": null
      }
    },
    "meta": []
  }
}
```

## Error Shape

```json
{
  "error": {
    "code": "schedule.name_collision",
    "message": "Schedule 'laravel-scheduler' already exists for this target.",
    "meta": {
      "name": "laravel-scheduler",
      "instance": "docs.production"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.result.action` | string | `created`. |
| `success.data.schedule` | object | Schedule entity defined in [`9_schedule/README.md`](../../README.md#schedule-json-entity). |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `schedule.name_collision` | Stable command failure code. |
| `error.meta` | object | Field, name, scope, caller, or authorization context for automation. |

`schedule:add` does not emit a scheduler pickup result. The gateway-only Orbit
Scheduler reads the gateway database every tick; target reachability is verified
at dispatch time, not at add time.
