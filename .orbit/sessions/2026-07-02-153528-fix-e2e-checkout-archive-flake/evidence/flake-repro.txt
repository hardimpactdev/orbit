# Reproducer: E2ECurrentCheckoutTest "reuses the shared checkout archive after flushing in-process checkout state"

Failing assertion (pre-fix): apps/gateway/tests/Feature/E2ESupport/E2ECurrentCheckoutTest.php:1245
  "Failed asserting that 2 is identical to 1." ($tarBuilds expected 1, got 2)

## Mechanism reproducer (deterministic stand-in for parallel workers)

The test's archive cache key is E2ECurrentCheckout::treeHash(), computed from the LIVE
shared working tree (shell_exec git ls-files + hash_file), which escapes Process::fake.
Any sibling process creating/deleting an unignored file in the repo between the two
treeHash() computations (install #1 vs install #2 after flushCache()) flips the key,
misses the disk archive, and forces a second tar build.

Sibling mutator (simulates what parallel Pest workers / quality-check lanes do):

    cd /Users/nckrtl/orbit/.worktrees/fix-e2e-checkout-archive-flake
    while [ ! -f /tmp/orbit-flake-mutator-stop ]; do
        touch flake-mutator-probe.txt; sleep 0.15
        rm -f flake-mutator-probe.txt; sleep 0.15
    done &

    for i in $(seq 1 10); do
        bin/orbit-gateway-pest --compact \
          --filter="reuses the shared checkout archive after flushing in-process checkout state" \
          tests/Feature/E2ESupport/E2ECurrentCheckoutTest.php
    done
