# Role convergence proof variants

Run one complete fixture with `bin/swamp-proof run node.role_converge --variant database`, `ingress`, `app-prod` or `websocket`. Each variant declares the supported `app-prod` topology Node. A bounded `before_request` helper lists the current role, removes it through the normal operator CLI when needed, and assigns the selected role. It accepts only these four role variants and refuses mixed or unrelated roles. This permits all variants in one topology in filename order and repeated single-variant runs. An already matching assignment is preserved. The helper never edits Gateway records directly. The request under proof is always `node:role:add <node> <role> --converge`.

The Database, Ingress and WebSocket preparation requires lane21's native role-add parent and canonical role removal. It must not fall back to a per-Node worker. The prepare CLI captures the topology target ID. The helper records the real assignment ID as public precondition evidence before the request, and parity checks it against the admitted and projected identity. The partial `Operation.input.native_role` expectation uses the typed positive-integer matcher for this generated assignment ID. The complete admitted input remains in the proof receipt. The fixture does not carry a native envelope, private values or production credentials into the topology.

WebSocket uses the topology Gateway's normal certificate primitive and its own CA for the real `reverb.orbit` leaf. There is no disposable signer, signer address input or `proof.targets` binding. Its parity check verifies the public certificate against the admitted root hash and published topology root and observes the exact pinned release and loopback Reverb listener. No private certificate key or WebSocket environment content is read.

Parity reads the projected Operation and role assignment through the operator CLI, compares public native output facts, and checks the target's observer pin and service state. It also checks Docker for Database, exact Caddy publication for Ingress and AppProd, installed PHP and Composer for AppProd, and the signed certificate and runtime for WebSocket. These checks are read-only. They run through `PROOF_EXEC` inside the disposable allocation.

The current fixtures prove warm convergence: the topology image has AppProd tools, and preparation uses the normal role-add path. They do not establish cold role installation. The 1,200-second run ceiling and individual phase ceilings are provisional F8 budgets; the first F10 receipt supplies actual timings. Source checks and binary-boundary fixtures do not substitute for that receipt. No topology has been admitted by adding these fixture files.

The phase selectors name `effects/*` in the `node-role-converge` child of the operation dispatcher. The proof runner must resolve these child history rows; this needs runner integration confirmation. No fixture adds a private native history reader or custom polling path.
