# Human Renderer: `orbit node:update [name]`

[Back to `node:update` technical contract.](1_node-update.md)

This page describes the human-rendered terminal output for `node:update`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../ux/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[`interactive input mode`](5.1_node-update_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Progress Tree

Render the complete progress tree after input resolution, before update side
effects begin. `node:update` performs gateway-owned registry writes and may
re-apply node artifacts, so the human renderer must not leave the operator
without progress feedback even when the happy path usually completes quickly.

Full flow:

```text
┌ Updating Node
○ Validate node
○ Apply and verify node change
○ Apply node artifacts
└ Working...
```

When no fields actually changed (all values equal current stored values), the
apply step completes as a no-op and the footer shows:

```text
┌ Updating Node
○ Validate node
○ Apply and verify node change
└ Node `app-1` unchanged
```

When artifact re-applying fails after configuration is written, the re-apply step
completes as a warning and the footer shows drift:

```text
┌ Updating Node
○ Validate node
○ Apply and verify node change
○ Apply node artifacts
└ Node `app-1` updated with drift

Drift detected: <artifact>: <error message>
```

## Success Output

When update succeeds with no drift:

```text
Node 'app-1' updated
  Changed: host, public_ipv4
```

When update succeeds but no fields changed:

```text
Node 'app-1' unchanged
  No fields were modified.
```

When update succeeds but artifact re-applying partially failed:

```text
Node 'app-1' updated
  Changed: host
  Drift detected: <artifact>: <error message>
```

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Missing node

```text
Node 'app-1' not found.
```

### No field provided (non-interactive)

```text
At least one field must be provided to update a node.
```

### Duplicate field flag

```text
Field 'host' was supplied more than once.
```

### Field role-incompatible

```text
The field 'environment' is not valid for node 'gateway-1' (role: gateway).
```

The same prose form is used for `--host`, `--public-ipv4`, and `--public-ipv6`
when the target node role is `control`, with the field name and role
substituted accordingly.

For `--tld`, the same prose form is used when the target is a gateway node, a
control node, or an app node whose effective environment is `production`:

```text
The field 'tld' is not valid for node 'gateway-1' (role: gateway).
```

### TLD already in use

```text
Development TLD 'test' is already assigned to another node.
```

### Gateway unavailable

```text
Gateway connection is required to update a node.
```

### Authorization failed

```text
This control node is not authorized to update nodes.
```

### Caller role not allowed

```text
This command may only be run from a control or gateway node.
```
