# JSON Renderer: `orbit tool:remove`

[Back to `tool-remove` technical contract.](1_tool-remove.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "name": "composer",
      "node": "app-1",
      "routes_removed": 1
    },
    "meta": []
  }
}
```

Removal success is a compact outcome payload, not a full tool entity. It always
includes `name` and `node`. Optional outcome fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.routes_removed` | integer | Count of tool-owned proxy routes removed after successful cleanup. |
| `success.data.process` | object | Present when a related process teardown ran first. |
| `success.data.process.warnings` / `success.data.warnings` | array | Optional process runtime-unit warnings when related process teardown ran first. |
| `success.data.stale_record` | boolean | Present when residual registry/runtime facts were cleaned without a live managed install. |
| `success.data.tool_row_removed` | boolean | Present when the response reports whether a `NodeTool` row was deleted. |
| `success.data.stale_routes_removed` | integer | Present on some residual removals as the count of stale tool-owned routes removed. |

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Required input is missing or invalid.",
    "meta": {
      "field": "tool"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `tool.not_found`, `tool.unsupported_action`, `tool.remote_action_failed` | Stable command failure code. |
| `error.message` | string | Human-readable failure summary. |
| `error.meta` | object | Field, target, caller, or remote-action context for automation. |

### Missing destructive consent

JSON mode returns this failure when `--force` is missing. Renderer selection
never grants destructive consent.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to remove this tool.",
    "meta": {
      "field": "force",
      "reason": "cancelled"
    }
  }
}
```

### Missing target

```json
{
  "error": {
    "code": "validation_failed",
    "message": "A node or instance target is required. Provide --node, --instance, configure node:default, or select a target interactively.",
    "meta": {
      "fields": [
        "target"
      ]
    }
  }
}
```
