```bash
orbit tasks:provision <group> [--idempotency-key=KEY] [--json]
```

Provision the numeric task `group` through the Gateway's `tasks.provision` operation. The group must use external orchestration and be `todo`. If you omit `group` in a terminal, choose a todo group from the prompt. Machine mode requires its ID. The command follows capacity waits until the workspace is ready. It starts no subtask or check. `--idempotency-key` reuses the same operation on a repeated start. Ctrl-C stops following; it leaves the operation running. Use `tasks:cancel` to end the group and stop a waiting provision. See [Provision an external group](/reference/tasks#provision-an-external-group).

The workspace gets the Project's runtime through the same children as `instance:create`:

| Project has | The workspace gets |
| --- | --- |
| A web root and `task_workspace_routed` on | A private Route on the development Cluster, created by the `operation-route-create` child |
| Development Process definitions | One Instance Process per definition, created and started by `operation-process-create` |
| Development Schedule definitions | Disabled copies. A task VM fires no scheduled work until `schedule:enable` turns one on |

No host with room or a usable image makes the task wait with `capacity`; it starts when a VM is destroyed or an image is promoted. A failed step leaves the VM and its checkout; `tasks:cancel` ends the group and removes the VM.
