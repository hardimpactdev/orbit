# Ansible input

Swamp expressions have no JSON encoder. Full intents also exceed the 128 KiB limit for one environment string. This behavior writes the non-secret object to a mode `0600` file and locates the playbooks delivered through native `additionalFiles` and `ctx.extensionFile`.

Checked the Swamp workflow inputs and command/shell contracts, and official SSH and cfgmgmt file behaviors. None writes a whole input object as a local JSON file. The behavior executes no Node work. The workflow owns secrets, phase order and completed-run cleanup.

PHP and DNS delta publication stay with the shared native publishers. Their three-way composition preserves changes from other admissions; the pinned Ansible modules have no equivalent. Ansible still applies the Caddy snapshot, ordinary files, firewall state and exporter pools. Prometheus config uses checksum-guarded `dd` on stdin: atomic host-file replacement would leave its Docker file bind on the old inode.

Container clone phases use the official SSH transport and shipped direct commands as a measured exception to Ansible. The worker supplies public source and intent as argv and resolves secrets only as private stdin. Five native phase steps keep ordinary Operation progress. The cold one-connection prototype reached T3 in 7.128 s; two fresh native creates with the four-slot SSH pool completed in 13.450/14.005 s (load1 9.44→10.35). The measured production Ansible T3 phase took 7.340 s by itself. The fixed `ic-clone-<Node>-<Instance id modulo 4>` pool bounds auto-definition growth while separating method locks. Agent and T3 use a second fixed pool, `ic-clone-t3-<Node>-<Instance id modulo 4>`, so they run beside the workspace phase. Each phase script only manages its named container; publication, registration and compensation remain native workflow steps.
