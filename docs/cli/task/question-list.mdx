---
title: "orbit task:question:list"
sidebarTitle: "task:question:list"
description: "List the questions that implementers and reviewers asked, newest first, across every task you can read. Each question marks a subtask that its brief did not fully decide."
---

```bash
orbit task:question:list [--project=ID] [--cause=CAUSE] [--status=STATUS] [--since=DATE] [--json]
```

| Option | Default | Effect |
| --- | --- | --- |
| `--project=ID` | every Project | Only questions from this Project's tasks. |
| `--cause=CAUSE` | every cause | `brief_unclear`, `contract_gap`, `scope`, `environment`, or `missed_contract`. |
| `--status=STATUS` | every status | `open`, `escalated`, `answered`, or `superseded`. |
| `--since=DATE` | no limit | Only questions asked on or after this ISO 8601 date or time. |

An invalid filter fails with `tasks.project_invalid`, `tasks.cause_invalid`, `tasks.status_invalid`, or `tasks.since_invalid` before the request.

Human output prints one header line for each question, with its time, task and subtask reference, asker, status, and cause. The question and the answer follow, each indented by two spaces. An empty list says `No questions match.` JSON holds the records under `questions`. The [tasks reference](/reference/tasks#questions) defines each field, the relay routes, and the consult limit. The limit counts the consult records of the current implementer attempt, and a relay does not count. A direction resolution does not start a new implementer attempt.
