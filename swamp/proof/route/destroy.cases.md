# route:destroy verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN Node, an `app-dev` Node, a Cluster with a Router, an Ingress and `app-prod` Nodes, and checks the Gateway record, Caddy, certificates, DNS, firewalls and real HTTPS requests. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Private custom proxy Route | Remove a private custom proxy Route. | The task succeeds and the Route record is gone. The Caddy site, certificate and DNS record are gone, the domain no longer answers and it is free for a new Route. |
| Untargeted app Route | Remove a Route whose Instances are not active. | The sites and certificates leave every Node and the PHP-FPM pools of its development Instances are withdrawn. The Instances stay without a Route. |
| Domain outside the TLD | Remove a Route whose domain is outside the TLD, then one inside it. | The first removes the private DNS record and the catalog entry first and waits 31 seconds before the site is withdrawn. The second changes no DNS and does not wait. |
| Cluster-scoped and public Routes | Remove a Cluster-scoped Route, then a public one, while another Route needs the same LAN and edge rules. | The unused rules go. The shared rules stay and the other Route keeps serving. With no other Route, the rules go too. |
| Check at the end | Leave a captured file, certificate scope or firewall rule behind after the removal. | The task fails with `route.removal_check_failed`. The Route is unchanged and the task names the failed step. |
| Failed step | Make each of the DNS removal, the DNS grace, the site withdrawal, the PHP-FPM convergence and the LAN rule step fail, and one failure outside these steps. | The task fails with `private_dns.publication_failed`, `route.dns_grace_failed`, `route.withdraw_failed`, `route.pool_converge_failed`, `route.lan_firewall_failed` and `route.withdrawal_failed`. The Route is unchanged and the task names the failed step. Finished steps stay. The same command after the fix runs every step again and succeeds without duplicates. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step and the rerun finishes. |
| Unreachable Node | Take a Node the removal changes offline and run the command without `--offline`, then with it. | The first fails at the step that reaches the Node with that step's code, and the Route is unchanged. The second succeeds. |
| Offline removal | Run with `--offline` with one Node unreachable and one inactive. | The Nodes that answer keep every step. The Route record is deleted and the result lists the skipped Nodes, with their names and steps, under `retained_on_nodes`. After the Node answers, `node:converge` removes the residue. A failure on a Node that answers still stops the removal. Fails today: the result carries each Node's ID and steps but not its name. |
| VPN Node offline | Remove a Route whose domain is outside the TLD with `--offline` while the VPN Node is unreachable. | The removal fails with `private_dns.publication_failed`; the VPN Node is not skipped. |
| Replacement that never activated | Remove a `pending` and a `failed` replacement Route, also with `--offline`. | The replacement and its target are deleted, its sites and staging certificates are gone, the old domain's URL and DNS are restored, and the replaced Route and its target are unchanged. |
| Active dependency | Remove a Route that an active Instance depends on, and a replacement that has cut over. Then remove an additional web-root site of an active Instance. | The first two give `route.target_conflict` and change nothing. The site is removed, the Instance keeps serving, and `APP_URL` comes from the Instance's own Route. |
| Live public edge and pair | Remove an active app Route with a live public edge, and the replaced Route of a pair, each with no active Instance depending on it. | `route.reconciliation_required`. Nothing changes. |
| Managed Route | Remove an analytics tracking Route. | `route.tracking_managed`. Nothing changes. |
| Open transfer | Remove a Route that an open Instance transfer owns. | `instance.transfer_incomplete`. Nothing changes. |
| Confirmation | In a terminal answer the prompt with No, Enter, Ctrl-C, and end of input. Then run it noninteractively and with `--json` without `--yes`. | The prompt names the Route's domain and the effect, and No is selected. Each decline ends with `input.cancelled` and starts no removal. The noninteractive and `--json` calls are refused with `input.confirmation_required`. With `--yes` there is no prompt, also with `--json`. Fails today: the prompt names only the domain. |
| Missing Route | In a terminal run the command with no arguments, choose a Route, and cancel the list. Then run it noninteractively and with `--json`. | The terminal lists Routes by domain and the choice is confirmed. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `route.id_invalid`, with no request. Fails today: the Route is a required argument, so every call without it is refused by the parser. |
| IDs only | A Route by domain, the ID `0`, the ID `-1`, and `abc`. | `route.id_invalid`, with no request. |
| Idempotency option | Run with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers it and skips the confirmation when it is set. |
| Unknown Route | An ID that does not exist. | `http.404`. Nothing changes. |
| Access | A caller with no grant to the Route's Node, to any member Node of a Cluster-scoped Route, and for a public custom proxy to only one of its Ingress and Process Nodes. | `node_access.required`. Nothing changes. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one task exists for the removal. |
| No coordinator | Remove a Route while no active Gateway Node can coordinate the run. | `route.coordinator_required`. Nothing changes. |
| Repeat and busy | Repeat the command after a successful removal, and start it while another task holds the Route. | `http.404` for the first and `operation.target_busy` for the second. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, because task replies carry no step progress, then the final result naming the Route by its domain, with the task and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final task. |
