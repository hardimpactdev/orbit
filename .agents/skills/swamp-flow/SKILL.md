# Build a Swamp flow

Build or change one command's workflow per change, and prove it on the nested fleet of your task VM (F13). The Gateway admits and projects; Swamp does the work. Write only to `hardimpactdev/orbit`, never `ohdearapp/*` or another repository.

Start from the command's chart. [flow-tighten](../flow-tighten/SKILL.md) decides its steps, and for Node work whether each phase is native Swamp or an Ansible phase (rule 22). This skill builds the Swamp side. [ansible-phase](../ansible-phase/SKILL.md) covers the playbook; another agent can write it in parallel.

Load the official [swamp skill](../swamp/SKILL.md) for Swamp mechanics. Its routing table owns workflow scaffolding and validation, behaviors, placement, vaults, serve and troubleshooting. Load [flow-tighten](../flow-tighten/SKILL.md) for flow design. Its Swamp gotchas and flow rules own write declarations, lock waits, Node parallelism, end checks, cleanup and reruns. Rule 22 supersedes older script and end-check recipes. Use [swamp-getting-started](../swamp-getting-started/SKILL.md) only for onboarding.

Before building a tool, harness, test approach or script, find the Swamp documentation and cite it in the PR. Use the Swamp default; name an uncovered gap before adding custom code.

This skill adds Orbit constraints. The [shape guide](../../../swamp/docs/swamp-shape.md) and [boundary decisions](../../../docs/swamp/porting.md#check-all-seven-boundary-decisions) apply. Use the [porting reference](../../../docs/swamp/porting.md) for Orbit integration details, subject to current decisions and the tightened chart; older recipes do not override them.

## The loop (F13)

1. Call Recall `resolve` for the command and its family. Current decisions replace older instructions.
2. Chart first. Charts live in `docs/cli/<family>/<command>.mmd` ([where a chart lives](../../../docs/cli/README.md#where-a-chart-lives)). Apply flow-tighten and pass `bin/check-flows`. Land the chart and workflow in one push, with Swamp lane labels equal to step names. Add the kind to `docs/cli/flows-migrated.txt` when the workflow follows its chart.
3. The chart and the command's documentation are the behavior spec, including edge cases and values rewritten at admission, such as setup macros (#2304). For a change, today's public behavior is the spec for what the chart keeps. Write the Gateway admission tests and the cases file first, and explain every change to a phase order.
4. Prove in your task VM with [verifying-commands](../verifying-commands/SKILL.md). The nested fleet, the proof and the proof CI are stages 2 to 4 of the [command development pipeline](../../../docs/reference/command-development-pipeline.mdx); the stage charts own the steps.
5. Build and run the whole path: request, admission, Swamp, Nodes and terminal projection. Read full stderr and per-step timings; fix Gateway and Swamp bugs alike. Start a writer's repair proof with missing or stale state; setup must not make a no-op pass. Read the case verdicts and step timings and check every phase budget (F8). State the fleet's limits: test repositories, Orbit CA, no production data or scale.
6. A case that needs shared or broken state gets its own batch in `swamp/proof/batches.yaml` ([verification cases](../../../docs/reference/verification-cases.mdx)).
7. Rebase on fresh main and inspect the full push diff. The PR, CI and merge are [stage 4](../../../docs/reference/pipeline/4-pr-and-ci.mmd); [developing-commands](../developing-commands/SKILL.md) says how. Never REST merge. Never restore unrelated files from a stale tree (Routes restoration, `ebdfafdf46`). Before every push, run `bin/docs-impact --gate --base origin/main`. Watch CI to green after every push. Whoever turns main red fixes it first, forward. Every main SHA must finish Required checks; cancelled Swamp jobs are not green ([CI concurrency](../../../docs/reference/implementation-loop.md#ci)). Use `timeout` on every `gh` call; do not SSH to other machines. A short live check after the release load confirms uptake; it is not a second proof.

Never build or prove a flow against production serve, and never log in to 209 for it. Use the [role-installed binary](../../../docs/reference/node-provisioning.md#role-prerequisites) at `/usr/local/bin/swamp` for control-host calls, never a hand-installed copy. The role installs versioned binaries and switches the link; never overwrite a running executable. Never restart or reload serve; config changes go through the swamp role and a release. The [release load](../../../docs/reference/gateway-recovery.md#load-swamp) refreshes manifest `additionalFiles` on reload without a restart (Lab #4282 fixed in pinned Swamp). Send real Swamp gaps to the orchestrator with evidence; do not build around them.

## Build it

Use the official swamp skill to create or edit the workflow. Apply the Orbit [workflow and Gateway templates](../../../docs/swamp/porting.md#fill-the-workflow) only where they match the tightened chart.

- **Admission:** freeze the full non-secret intent under `intent`, with names-only `{vault, key}` descriptors under `execution_secrets`. Encode empty maps as objects (#2273). Expand Gateway macros before execution (#2304). Reserve publication before capturing runtime definitions whose content depends on its domain. A prepared-runtime marker requires every recorded Process to be covered and every publication prerequisite to succeed; empty `forEach` placeholders alone do not prove readiness (L22-INSTANCE-REGISTER).
- **Workflow reuse:** apply [flow-tighten rule 27](../flow-tighten/SKILL.md#what-a-good-flow-looks-like) before adding a workflow for another action. For extracted phases, use Swamp's native [`type: workflow`](https://swamp-club.com/manual/reference/workflows#workflow-workflow), `workflowIdOrName` and `inputs`; the caller consumes the child's outputs through `steps.<call>.outputs`. Check the pinned runtime's workflow reference for composition semantics.
- **Placement:** all steps use only `labels: {role: swamp}`, with no inherited `target`; expanded proof topology workers carry the same label. Plain task VMs carry no Swamp binary, worker or worker token; 209 runs their actions over SSH (Recall `task-vms-swamp-via-ssh`). Run official Node behaviors from 209 with the admitted identity, host-key pins and account. Keep admitted owner IDs; replace Node-bound callbacks when moving execution. Copy placement from `operation-firewall-direct`.
- **Node work ([rules 22 and 28](../flow-tighten/SKILL.md#what-a-good-flow-looks-like)):** build each phase and its failure handling as the chart decided: native cfgmgmt or exec argv steps, or an Ansible phase. Add no other shipped script; name an uncovered gap in the report and extension README. Add cleanup or restoration only for the command's agreed failure contract, using native dependencies. TypeScript only shapes typed inputs and outputs; explain custom growth (F15). Task VMs reuse IPs: pin SSH execs; enrollment replaces cfgmgmt's shared `known_hosts` entry with the observed key, and destroy removes it (`397fbbf948`).
- **Ansible phases:** follow [ansible-phase](../ansible-phase/SKILL.md) for the playbook and the parts the first flow adds. In the workflow:
  - Order: the intent job, the secret job, the build step, the phases, then cleanup.
  - The intent job runs `@nckrtl/ansible-input` with the whole `inputs.intent`. It creates the run folder and writes the intent file. Env values must be strings, and Swamp expressions have no JSON encoder.
  - The secret job is guarded on the secret's presence, because Swamp evaluates `vault.get` arguments in both branches of a `?:` expression. A `command/shell` step gets the value as an environment variable from `vault.get` and writes it to a 0600 file in the run folder.
  - The build step (`command/shell`) runs the playbook's input builder. It writes the inventory, the vars and `known_hosts`, and removes the secret file.
  - Each phase is one `command/shell` step that runs `timeout <phase budget> ansible-playbook --tags <phase>`, with the run's `known_hosts` in `ANSIBLE_SSH_ARGS`. Work on several Nodes stays in one step; Ansible runs the Nodes in parallel. A phase that changes Nodes declares `writes: true`; the read-only `check` phase does not.
  - Keep native: Gateway calls such as certificate signing, single commands, and work that must not run twice.
  - The `check` phase is the end check. Keep the step and job names the Gateway reads, such as job `role` with "Check the role" (`apps/gateway/app/Domain/Nodes/direct-operations.php`). If the Gateway cannot find the end check of a succeeded run, the Operation stays running.
  - A cleanup step depends on every job that writes to the run folder, with the condition `completed`. It removes the folder, including the vars that hold the secret, also after a failure.
- **Docker Processes (tighten2):** pull with `@swamp/cfgmgmt/docker_image`; create with plain `docker run -d --name orbit-<id> --env-file … -w … <image> <cmd>` via SSH exec argv; verify with `docker_container check`. Store its `state` in the execution vault: it includes environment values. Record missing options in `swamp-evaluation.md`, not a script.
- **Managed folders (tighten2):** use `cfgmgmt directory` to converge owner and mode of existing folders. Refuse `/`, `/home`, a home directory itself, `/etc` and `/usr` at Gateway admission.
- **Downloads (tighten2):** fetch and fingerprint-check keys on 209 before any Node contact. Use `cfgmgmt copy_file` for binary keys (`file` accepts UTF-8), and `file` for deb822 sources. Share staged data through a run-specific absolute path; dispatch-relative directories differ between steps. Scoped APT refresh sets `APT::Get::List-Cleanup=false` to preserve other indexes (Decision 7 proof). No script or Node download.
- **Secrets:** no secret bytes in inputs, outputs or argv. Declare every vault read by parent and child workflows. Keep vault values small: large public request envelopes break serve's redaction regex (op 8235). For mixed requests, frame one small secret with public `intent` fields on SSH exec stdin only as the [shape gate permits](../../../swamp/docs/swamp-shape-gate.md#automated-checks). For private text, use `vault.get` directly as cfgmgmt `file` content with mode 0600 (Q-SECRET receipt); never output the value or its base64 form. SSH `env` relies on `SendEnv`, so do not assume it reaches the target. Generate Gateway-owned secrets at admission; Node-held keys stay on the Node. Secret imports use a one-shot vault key, read once by the Gateway with `vault.read-secret`, then deleted with `vault.delete`; both exist in pinned Swamp. Token authority only shrinks: revoke only the removed Node's exact worker principal, failing closed; never mint or widen it.
- **Names:** follow [behavior naming](../../../docs/cli/README.md#behavior-names). Use the effect Node for SSH names, even when the Operation belongs to the Gateway. One name has one behavior type; disambiguate fixed names by type. Never share one per-Node SSH name across step families: differing global arguments rewrite its definition. Per-run names require an always-run delete; leaked auto-definitions caused serve's lookup CPU incident (Lab #4280). Sanitize dots with `split(".").join("-")`; the shape gate enforces names.
- **Fan-out compatibility:** use inputs or an earlier job's outputs in `forEach.in`; e459 expanded it before same-job outputs existed. Keep each host's failure scope as the chart states it. Keep inputs bounded: no history-growing query or whole fleet `steps` map; pass only required statuses (#2310, #2334).
- **Temporary files:** private import cleanup also follows a failed staging write or partial copy. A guard requiring staging success can leak private bytes; wait for staging and copying to settle and remove the run-scoped paths. A skipped vault step still needs worker-copy cleanup (L22-ENV-IMPORT). Before deleting temporary certificates, restore final Caddyfiles for every staged workload, including retained ones (#2546).
- **Errors:** keep refusal codes and setup exit cases stable, or explain changes. Map native failure exit codes in the Gateway; failed command steps keep no outputs on e459. SSH records stdout and stderr before later shaping: capture private command output in files, copy privately to the worker, redact with the [shared output filter](../../../docs/reference/tasks.md#keep-command-output-out-of-run-history), then delete. Scan history, data and logs in the topology proof. Use shared diagnostics, never a result-reporting step. Fresh credential checks cannot reuse an earlier request's success; completed verification may survive native resume (vault.setup retro).
- **Serve throttling:** diagnose `swamp.vault_sync_unavailable` from the Gateway warning's `phase` and HTTP status ([logs](../../../docs/reference/gateway-recovery.md#gateway-request-logs)). A connection HTTP 429 is admission throttling; check SQLite warnings separately. Reuse the shared [connection and transport recovery](../../../docs/reference/swamp-command-steps.md#terminal-outputs); add no per-request connections or unbounded retries. Missing, mismatched or running history is not retried (`f1d508f701`).
- **Budgets (F8):** use the [budget table](../../../docs/swamp/porting.md#set-the-time-budget). A measured explicit budget wins; otherwise start at 30 minutes, then use 1.5× the longest success. Do not size budgets from runs that skipped or deferred the work (`2bde8d5bed`). Never borrow a flat budget. Every workflow, children included, sets `queueTimeout`, equal to the proof's `queue_timeout_seconds`. Bound phase commands with literal `timeout <seconds>`; a remote read may instead set SSH `timeoutSec`, while writes keep a remote-side bound (#2334). No family timer or timeout epilogue.
- **Polling exception:** only an existing script for a named gap may poll external HTTPS state, under a literal phase timeout, at a fixed shorter interval, with failing GETs and no retried requests. State interval and budget in the change report. Never poll Gateway or Orbit state or retry failed actions. Use the reference's [gate requirements](../../../docs/swamp/porting.md#set-the-time-budget); add no baseline row (#2325, #2366). An Ansible phase may wait for a service it just started, and may retry a task that fails on a transient external error (a 503 from `snapshot.ubuntu.com`) with the tool's own retry: `until`, `retries` and a fixed `delay`, or a module option such as `update_cache_retries`. It runs inside a phase command that starts with a literal `timeout`; the PR states the retries and delay. It never retries any other failed action, and never with a shell loop.
- **Gateway:** use shared `StartSwampRun`, `SwampCommandStep::executionCopy` and the family projector. New flows declare [native terminal results](../../../docs/reference/swamp-command-steps.md#read-swamps-run-data-instead-of-a-result-step): `terminal_result` names the end check with `native => true`; read status through `NativeRunResult::stepStatus`. Use `captures` for producer JSON; the step summary truncates stdout at 4 KiB (tasks.script retro). After cleanup failure, keep the Operation failed while retaining completed producer observations (tasks.turn retro). No `outputs: false` or result step. One shared terminal history reader; no family callbacks, holds, pollers, timers, retries or second readers. Preserve an exact native terminal that met its budget even after Gateway expiry. A failed projection must leave expiry armed; no queued marker may suppress it (L17-PR-2348-01).
- **Delete:** trace production admissions and child-workflow callers; remove uncalled standalone roots instead of proving them (#2529, #2532). Remove the steps, behaviors, scripts, tests and paths that the change replaces, in the same change (F15). Do not touch `apps/agent`. Remove the kind's shape-baseline rows.

## Check and review

- Follow the official workflow validation guide on the pinned runtime. Run fast Deno unit tests for Orbit TypeScript logic, script lint and Gateway Pest admission/projection tests. Add no native workflow tests or custom runtime harness; drop cases that test Swamp, shell or CEL behavior. Use the [test layout](../../../docs/swamp/porting.md#test-layout). Restore fixture DNS overrides and temporary addresses after parity, including failure; a retained GitHub alias broke `node.converge`. Parity reads the [execution envelope](../../../swamp/proof/README.md#fixtures) from `PROOF_OPERATION_FILE`; a full Operation in an environment value can exceed `MAX_ARG_STRLEN`. For admissions that complete without a run, assert an empty `PROOF_NATIVE_RUN` (#2524). Public show/cancel replies are summaries; proof execution envelopes come from the internal Operation. Fake privileged host tools such as `groupadd`; serialize shared fixture state used by parallel steps. Fixture package installs refresh APT indexes first (vault.setup proof). Real-Docker tests require `ORBIT_DISPOSABLE_DOCKER=1` inside a disposable proof VM, never a shared host; clean up with `docker rm --force --volumes` (#2358). A killed test can skip cleanup; destroy the VM afterwards.
- Before every push, commit and run `bin/swamp-shape-gate` from the repository root (about a minute). It is the one definition that CI runs: pinned linters, Ansible phase checks, shape regression tests, the shape gate, the frozen-base policy, behavior names and the frozen agent command check; with `SWAMP_API_KEY` and `SWAMP_SIGNIN_TOKEN` set it also runs workflow validation, placement lint and `bin/check-grant-patterns.py`. Do not leave the shape gate to CI. Without the credentials it names the validation steps as skipped, and CI runs them. Grant patterns must pass pinned `swamp serve check-config` on Gateway-rendered grants; a standalone regex helper misses full CEL validation and can leave serve unable to start. Their CI lives at root `.github/workflows/swamp-shape.yml`, never under `swamp/.github` (#2372).
- Run root `bin/check-operation-kinds` too. Every intended vault grant, including native sensitive output fields, must appear in its kind's `execution_copies` declaration. Native `serve check-config` validates CEL, not this Orbit policy parity; a passing topology does not check the registry entrypoint (Vault rule 22).
- Report measured p95, sample, run budget and `queueTimeout`. Report Orbit net lines, then `swamp/` growth split into behaviors, workflows, scripts, tests and fixtures, with a reason for each (F15). Prefer case verdicts over duplicate mocked fixtures.
- Attach the proof verdicts ([stage 3](../../../docs/reference/command-development-pipeline.mdx#3-proof)) for workflow, behavior, script or Gateway execution-contract changes (#2266, #2273, #2304). Deletion-only, docs and test changes need none. An outage exception names the omitted receipt and the live check after load (#2332).

Review against the [checklist](../../../docs/swamp/porting.md#pr-and-review-checklist), current chart and flow-tighten. Missing budgets, required receipts, explained growth or reasons for phase-order changes fail review. An Ansible phase also needs the [ansible-phase](../ansible-phase/SKILL.md) proof: a rerun with zero changes. Read the change report before calling a reason missing. Keep source conformance, CI, served-source uptake and live evidence separate. Report PASS or deviations as `file:line`, broken rule and native replacement, with reviewed SHA and skill version.

Use the official workflow references to check guard, dependency and output semantics before alleging a silent skip. On e459, missing intent fields fail CEL evaluation (#2369). An added intent field needs its Gateway release live before the Swamp load; pre-release runs are re-admitted, not resumed. Remove a checkout script mode only after the served workflow stops calling it: release load moves checkout before workflow reload. Check the whole workflow's `queueTimeout` (L17-PR-2363-02). When captures become sparse, inspect every guard that used the full form (#2383). Main is not `deno fmt` clean; do not block on unrelated formatting (#2332).

## Improve this skill

For a missing-key CEL failure in a fixture, trace the admission and projection first. Keep explicit null keys and current phase names in the fixture when the live input already supplies them.

Keep target identity outside optional lifecycle inputs. A ready task VM skips resume, but vault setup and terminal projection still need its VM id.

After a landed behavior change, replace the affected rule in `docs/swamp/porting.md` the same hour. Keep Swamp mechanics in the official swamp skill, shared flow rules in flow-tighten and playbook rules in ansible-phase.

Before filtering a policy run on a recorded commit, trace the field from terminal projection through the API. Container snapshot seeds live on InstanceRuntime; checkout seeds live on Instance. Use one shared effective seed accessor. Container identity comes from InstanceRuntime, not `source_layout=checkout`, which container and checkout Instances share. Automatic development discovery and admission reuse the ready container-default query that Conn's Project list uses; never select a user's checkout working tree. Recheck development-specific eligibility: generic automatic eligibility also admits production. Keep development admission, receipt lookup and fencing bound to the same development command. When quiet ticks stop entering policy, settle successful deployment status in its terminal projection and publication markers in the Route owner. Recheck automatic eligibility when queued execution input is built. Operator controls use the same policy without requiring an already-enabled flag. Share configured-check verdicts, not copies of them. Retained pending Operation IDs must read their terminal status from the Gateway and settle for the admitted commit; an older result or backoff must not hold a newer eligible head.

Development retry accounting combines failed deployment history and retained terminal failures without rows in one per-commit ordinal; a fixed delay alone cannot enforce an attempt limit. Replace retained evidence only when its history row carries the same pinned SHA and automatic origin. Derive terminal status fixtures from the Gateway projection and history DTO: interruption stays interrupted, queued cancellation has no row, and container failures may retain a null SHA. Every terminal outcome must release a pending development intent and remain bounded for its admitted commit. A retained succeeded Operation proves up_to_date only when the current runtime seed matches its commit. Test a lost development admission reply against the development receipt route, including a missing admission fenced before retry. Cross each intent form with unfinished projection, a later manual deployment, and eligibility changes before and after execution. A manual history boundary supersedes the terminal intent as well as its failure accounting; check the current seed and head in that tick. Scope admitted-SHA overrides to development so unpinned production failures keep their observed release SHA.

Keep development-only policy decoders, terminal classification and receipt handling out of production modules. Select the development implementation at its entry point and keep production projection behind one variant router. Pin shared production behavior with a baseline-generated guard over real receipt/history shapes and every intent form. An enable watermark is operator control, never a manual deployment boundary; retry resets require actual manual history. Exercise the real off/on API response after one, two and three failures, including pending and retained evidence.

A per-SHA retry limit must outlive prunable deployment history. Keep the total and deduplication identities in Gateway rows keyed by Instance and SHA; read and publish only the head, pending intent and evidence being settled, and expose only the recorded head in Instance responses; history and receipts only contribute evidence. Never expire a stopped SHA by age when a branch can return to it. Persist the ledger before releasing a retained admission intent.

Optional client publication must leave observer SSH intent and terminal checks intact. A partial fleet admission retains the publication retry for waiting clients; a Node that gains a client caller treats a previously absent client version as drift.
