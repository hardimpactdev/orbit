# JSON Renderer: `orbit workspace:log <run>`

[Back to `workspace:log` technical contract.](1_workspace-log.md)

This page describes the JSON-rendered output for `workspace:log`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces non-interactive input
mode for the canonical contract.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

The captured run is rendered as a single object under `success.data.run`.
This pairs with `workspace:history`'s `success.data.runs` array: history
returns the registry of runs, log returns the captured detail for one run.

## Success Shape

```json
{
  "success": {
    "data": {
      "run": {
        "id": 12,
        "workspace": "feature-docs",
        "app": "docs",
        "node": "app-1",
        "type": "setup",
        "status": "failed",
        "started_at": "2026-04-30T10:00:00Z",
        "finished_at": "2026-04-30T10:00:12Z",
        "duration_ms": 12500,
        "steps": [
          {
            "name": "Install dependencies",
            "command": "composer install",
            "status": "failure",
            "exit_code": 1,
            "stdout": "...",
            "stderr": "...",
            "stdout_truncated": false,
            "stderr_truncated": false,
            "started_at": "2026-04-30T10:00:03Z",
            "finished_at": "2026-04-30T10:00:11Z",
            "duration_ms": 8200
          }
        ]
      }
    },
    "meta": {
      "registry_only": true
    }
  }
}
```

## Run Object Fields

| Field | Type | Description |
| --- | --- | --- |
| `run.id` | `int` | Unique gateway-owned run identifier. |
| `run.workspace` | `string` | Workspace slug that owns the run. |
| `run.app` | `string` | Parent app slug. |
| `run.node` | `string` | Owning node slug recorded on the workspace. |
| `run.type` | `string` | Run type. See [Run Type Enum](#run-type-enum). |
| `run.status` | `string` | Run status. See [Run Status Enum](#run-status-enum). |
| `run.started_at` | `datetime` | ISO 8601 run start time. |
| `run.finished_at` | `datetime\|null` | ISO 8601 run finish time; `null` while the run is still `running`. |
| `run.duration_ms` | `int\|null` | Total run duration in milliseconds; `null` while the run is still `running`. |
| `run.steps[]` | `object[]` | Captured per-step output and timing. Empty array if the run produced no steps. |

## Step Object Fields

| Field | Type | Description |
| --- | --- | --- |
| `steps[].name` | `string` | Step name as defined by the workspace setup or teardown step record. |
| `steps[].command` | `string` | Command line executed for the step. |
| `steps[].status` | `string` | Step status. See [Step Status Enum](#step-status-enum). |
| `steps[].exit_code` | `int\|null` | Process exit code; `null` when `status=skipped`. |
| `steps[].stdout` | `string` | Captured stdout. May end with the literal `[TRUNCATED]` marker. |
| `steps[].stderr` | `string` | Captured stderr. May end with the literal `[TRUNCATED]` marker. |
| `steps[].stdout_truncated` | `boolean` | `true` if the captured stdout exceeded the gateway storage cap and was truncated. |
| `steps[].stderr_truncated` | `boolean` | `true` if the captured stderr exceeded the gateway storage cap and was truncated. |
| `steps[].started_at` | `datetime\|null` | ISO 8601 step start time; `null` when `status=skipped`. |
| `steps[].finished_at` | `datetime\|null` | ISO 8601 step finish time; `null` when `status=skipped`. |
| `steps[].duration_ms` | `int\|null` | Step duration in milliseconds; `null` when `status=skipped`. |

The lifecycle environment variables documented in
[`6_workspace/README.md`](../../README.md#lifecycle-step-environment) are
**not** captured into step metadata. Workspace and app configuration
(`workspace:show`, `workspace:history`) are the canonical source of those
values.

## Run Type Enum

| Value | Meaning |
| --- | --- |
| `setup` | Workspace setup run. |
| `teardown` | Workspace teardown run. |
| `lifecycle` | Other lifecycle action that produced captured output (for example, `php_update` if the orchestrator emits steps for it in future). |

## Run Status Enum

| Value | Meaning |
| --- | --- |
| `running` | The run is currently in progress. `finished_at` and `duration_ms` are `null`. |
| `completed` | The run finished successfully. |
| `failed` | The run finished with at least one failed step. |
| `cancelled` | The run was cancelled before completion. |

## Step Status Enum

| Value | Meaning |
| --- | --- |
| `success` | The step ran and exited zero. |
| `failure` | The step ran and exited non-zero. |
| `skipped` | The orchestrator did not execute this step because an earlier step failed. |

## Truncation Reporting

Truncation is reported in two complementary ways so both humans and
automation see the same signal:

- The captured stream itself ends with the literal `[TRUNCATED]` marker so a
  reader who only sees the stdout/stderr text knows it is incomplete.
- `stdout_truncated` and `stderr_truncated` booleans let JSON consumers
  detect truncation without parsing stream bytes.

The cap is a gateway storage limit (1 MB per stream per run). It is not
caller-tunable; this contract does not introduce a line-cap or tail flag.

## Error Shapes

### Validation failed

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Workspace run ID is required.",
    "meta": {
      "field": "run"
    }
  }
}
```

### Run not found

```json
{
  "error": {
    "code": "workspace.run_not_found",
    "message": "Workspace run 999 not found.",
    "meta": {
      "id": 999
    }
  }
}
```

### Log not found

```json
{
  "error": {
    "code": "workspace.log_not_found",
    "message": "Captured output for run 12 has been pruned.",
    "meta": {
      "id": 12
    }
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This caller is not authorized to read logs for workspace 'feature-docs'.",
    "meta": {
      "workspace": "feature-docs",
      "app": "docs"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to read workspace run logs.",
    "meta": []
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `run.type` | `setup`, `teardown`, `lifecycle` |
| `run.status` | `running`, `completed`, `failed`, `cancelled` |
| `steps[].status` | `success`, `failure`, `skipped` |
| `error.code` | `validation_failed`, `workspace.run_not_found`, `workspace.log_not_found`, `workspace.unsupported_for_production`, `authorization_failed`, `gateway_unavailable` |

The `error.code` values listed here are exhaustive for `workspace:log`. Add
a new value to this renderer contract before implementing another JSON
failure code.
