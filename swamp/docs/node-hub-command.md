# Parent-callable existing-hub peer mutation

`NodeWireGuardCommandInput::capture(Node $context, ?string $prospectiveAddress = null): array` captures public intent before the parent changes the context identity. It also works while a removal parent has recorded Removing. It reads no hub private key. The result contains `schema_version`, `hub_id`, `hub_address`, `port`, `context_node_id`, complete `inventory`, `before` (exact prior peer or null) and `desired` (the context Node's name, address and nullable public key). Capture this once in the admission transaction. Restore uses this same immutable capture even while the Gateway still records Removing.

`@nckrtl/node-hub-command.read` takes `{intent, mode, prepared_peer?}`. Modes are `publish`, `remove`, `restore-publish` and `restore-remove`. A network parent passes its native preparation output as `{node_id, public_key}`; it can replace only this context's key. Restore reverses the exact forward entry pair. Prior absence restores to absence. Metadata returns `{script, action_json}`; it reads public intent and resolves the shipped script, with no subprocess or Gateway request.

The callable `node-hub-peer-mutation` workflow uses the canonical lane21 runner's `--action-file`, `--interpreter python3`, `--as-root` and `--env ORBIT_HUB_CONTEXT` interface. Both asset methods and the mutation have identical exact hub placement; mutation depends on both asset methods succeeding. The **executing command model**, with `writes: true`, is always `wireguard-hub-<hub_id>`, including compensation. Never name that model after an Operation or run. The old behavior-type model identity must be migrated with its callers before activation; this source checkpoint does not perform a live model migration.

`hub_peer.py` is the one action. Under native serialization, it reads the current protected existing hub configuration, validates its interface and closed peer fields, changes only the exact context key/address entry, and preserves all unrelated current entries. Captured inventory is public audit intent, not an authoritative stale replacement. A foreign or changed same-context entry, collision, missing/foreign configuration, or inactive hub refuses. Repeating an already-applied entry is idempotent and still synchronizes kernel state to repair an interrupted file publication. Filesystem and activation errors restore the prior file and kernel configuration. The existing `/run/lock/orbit-wireguard-peer.lock` tool lock also coordinates canonical writers during their migration; it adds no custom lock, ledger, retry or control protocol.

The hub private key remains host-local in its protected configuration and temporary tool files; it never becomes a workflow input, argv or stdout. This existing-hub path needs no execution-copy secret (`execution_secrets` is empty). Missing configuration refuses; initial hub provisioning and global inventory reconciliation are separate work. This script changes no resolver/DNS policy and restarts no tunnel.

A successful action prints one public object: `{schema_version, hub_id, context_node_id, projected:true, restored:boolean, changed:boolean}`. `restored` is true only for a successful restore mode. Failure prints a closed `error_code` and exits nonzero. Parents aggregate native outputs into their own fixed terminal result; no mid-run projection, bound GET or `beginRestoration` call is needed.
