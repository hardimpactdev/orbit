# JSON Renderer: `orbit doctor`

[Back to `doctor` technical contract.](1_doctor.md)

This page describes the final-frame JSON output for `doctor`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as one machine-readable object via
`$this->line(...)`.

## Selection

Use this renderer when `--json` is present and `--stream-json` is absent.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even when
the process has a TTY. `--json` and `--stream-json` are mutually exclusive.

## Envelope

Validation failures that happen before the gateway stream opens use the shared
[JSON Envelope](../../../README.md#json-envelope). Gateway terminal frames are
preserved as `event`/`data` objects for plain `--json`, so the diagnostic is a
single final machine-readable result and not a progress stream.

## Terminal Frame

Machine-mode doctor requests (`--json` and `--stream-json`) ask the gateway for
`compact_progress=true`. Intermediate progress frames omit the full aggregate
doctor report; the terminal complete/error frame remains full. The CLI consumes
intermediate `tree` and `step` events silently under plain `--json` and emits
only the gateway terminal frame as one JSON object. Plain `--json` is not a
progress stream.

Successful diagnostics emit:

```json
{
  "event": "complete",
  "data": {
    "exit_code": 0,
    "data": {
      "footer": "Doctor completed.",
      "doctor": {
        "mode": "verify",
        "healthy": true,
        "scope": {
          "self": true,
          "node": "mini",
          "app": null,
          "instance": null,
          "workspace": null,
          "key": null,
          "families": ["node"]
        },
        "summary": {
          "issues": 0,
          "fixed": 0,
          "adopted": 0,
          "skipped": 0,
          "conflicts": 0,
          "failed": 0,
          "planned": 0
        },
        "issues": [],
        "actions": []
      }
    }
  }
}
```

Drift or probe failures emit:

```json
{
  "event": "error",
  "data": {
    "exit_code": 1,
    "message": "Doctor detected drift.",
    "data": {
      "code": "drift_detected",
      "message": "Doctor detected drift.",
      "meta": [],
      "data": {
        "doctor": {
          "mode": "verify",
          "healthy": false,
          "scope": {
            "self": false,
            "node": "app-1",
            "app": null,
            "workspace": null,
            "key": null,
            "families": ["node"]
          },
          "summary": {
            "issues": 1,
            "fixed": 0,
            "adopted": 0,
            "skipped": 0,
            "conflicts": 0,
            "failed": 0,
            "planned": 0
          },
          "issues": [
            {
              "family": "node",
              "node": "app-1",
              "kind": "unverifiable",
              "code": "node.transport_unreachable",
              "key": "node.transport_unreachable",
              "summary": "Gateway cannot reach app-1 through Agent push.",
              "restorable": false,
              "adoptable": false
            }
          ],
          "actions": []
        }
      },
      "footer": "Doctor detected drift."
    }
  }
}
```

When validation fails before the gateway stream opens, the shape is:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "--self and --node are mutually exclusive.",
    "meta": {
      "fields": ["self", "node"]
    }
  }
}
```

## Doctor Payload

The terminal frame carries the doctor diagnostic under
`data.data.doctor` for `event=complete`, and under
`data.data.data.doctor` for `event=error` when the gateway supplies a doctor
diagnostic payload.

| Field | Type | Meaning |
| --- | --- | --- |
| `doctor.mode` | string | One of: `verify`, `interactive`, `restore`, or `adopt`. |
| `doctor.healthy` | boolean | `true` when no drift or probe errors remain after the selected mode completes. |
| `doctor.scope` | object | Resolved family, node, project, instance, workspace, and self scope. |
| `doctor.scope.instance` | string \| null | Resolved concrete instance selector when the run is fenced with `--instance=<app.instance>`; otherwise `null`. |
| `doctor.scope.role` | string | Primary role for single-node runs (`Node::displayRole()`), or `fleet` for `--all`. |
| `doctor.scope.roles` | list of strings | Complete active canonical roles in stable sorted order for single-node runs (operator nodes surface as `["operator"]`). Absent on fleet scope, which keeps `role=fleet` and places per-node roles on `doctor.nodes[]`. |
| `doctor.nodes[].role` | string | Primary role for one fleet target (`Node::displayRole()`). |
| `doctor.nodes[].roles` | list of strings | Complete active roles for one fleet target in stable sorted order. |
| `doctor.scope.key` | string \| null | The exact issue-key filter supplied by `--key`. |
| `doctor.summary` | object | Counts for discovered issues and completed, skipped, failed, conflicted, and planned actions. Restore adds `passes`, `stop_reason`, and `dispositions` counts. |
| `doctor.convergence` | object | Present on node-scoped restore results: `passes`, `stop_reason` (`converged` \| `no_progress` \| `max_passes` \| `no_restorable`), and `max_passes`. |
| `doctor.dry_run` | boolean | Present and `true` only when `--dry-run` planned actions without applying changes. |
| `doctor.issues` | array | Findings discovered by verify probes and remaining after actions. |
| `doctor.actions` | array | Empty for verify mode; action records for resolution modes (`interactive`, `restore`, `adopt`). |

Issue objects contain generic fields plus family-specific detail:

| Field | Type | Meaning |
| --- | --- | --- |
| `family` | string | Product family key. |
| `node` | string \| null | Node name when the issue is node-scoped; `null` when not node-scoped. |
| `kind` | string | Generic doctor issue kind (compatibility). |
| `disposition` | string | Public outcome classification: `genuine_drift`, `blocked_inspection`, `invalid_intent`, or `runtime_incident`. |
| `restore_action` | string \| null | Catalog-declared restore action id when disposition is `genuine_drift`; otherwise `null`. |
| `code` | string | Concrete family issue code, such as `node.transport_unreachable`. For node update posture this is one of the `node.updates_*` codes. |
| `key` | string | Stable affected-resource or family sub-scope key within the family and scope. For node update posture this is `node.updates`. |
| `summary` | string | Human-readable issue summary. Automation must not parse it. |
| `restorable` | boolean | Whether the issue can be restored by `doctor --restore` mode or accepted as the restore option in `doctor --fix` prompts. Equals disposition `genuine_drift` with a declared restore action. |
| `adoptable` | boolean | Whether the issue can be adopted by `doctor --adopt` mode or accepted as the adopt option in `doctor --fix` prompts. |
| `details` | object | Optional family-specific diagnostic metadata. Omitted when absent. |

Action objects are emitted only when a resolution mode is selected
(`--fix`, `--restore`, or `--adopt`). Verify-mode runs do not emit action
records. Dry-run action objects use `status=planned` and must not remove their
matching issue from `issues[]`.

## Enum and identifier values

| Field | Values |
| --- | --- |
| `event` | `complete`, `error` |
| `doctor.mode` | `verify`, `interactive`, `restore`, `adopt` |
| `doctor.scope.families[]` | `node`, `instance`, `workspace`, `process`, `proxy`, `firewall_rule`, `tool`, `schedule`, `database_connection` |
| `doctor.issues[].kind` | `missing`, `extra`, `divergent`, `unverifiable` |
| `doctor.issues[].disposition` | `genuine_drift`, `blocked_inspection`, `invalid_intent`, `runtime_incident` |
| `doctor.convergence.stop_reason` | `converged`, `no_progress`, `max_passes`, `no_restorable` |
| `doctor.actions[].status` | `completed`, `created`, `updated`, `skipped`, `conflict`, `failed`, `planned` |
| `data.data.code` | `drift_detected`, `mode_not_supported`, `probe_failed`, `scope_not_found`, `authorization_failed`, `gateway_unavailable` |

The `data.data.code` values listed here are exhaustive for gateway terminal
doctor failures. Add a new value to this renderer contract before implementing
another JSON failure code.

Pre-stream validation failures use the shared envelope with
`error.code=validation_failed` instead of the terminal-frame shape.
