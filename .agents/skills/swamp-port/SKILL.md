# Port a kind to Swamp

Port one family or parent kind per change, inside a production-equivalent dev topology (F13). The Gateway admits and projects; Swamp does the work. Write only to `hardimpactdev/orbit`, never `ohdearapp/*` or another repository.

Load the official [swamp skill](../swamp/SKILL.md) for Swamp mechanics. Its routing table owns workflow scaffolding and validation, behaviors, placement, vaults, serve and troubleshooting. Load [flow-tighten](../flow-tighten/SKILL.md) for flow design. Its Swamp gotchas and flow rules own write declarations, lock waits, Node parallelism, end checks, cleanup and reruns. Rule 22 supersedes older script and end-check recipes. Use [swamp-getting-started](../swamp-getting-started/SKILL.md) only for onboarding.

Before building a tool, harness, test approach or script, find the Swamp documentation and cite it in the PR. Use the Swamp default; name an uncovered gap before adding custom code.

This skill adds Orbit migration constraints. The [shape guide](../../../swamp/docs/swamp-shape.md) and [boundary decisions](../../../docs/swamp/porting.md#check-all-seven-boundary-decisions) apply. Use the [porting reference](../../../docs/swamp/porting.md) for Orbit integration details, subject to current decisions and the tightened chart; older recipes do not override them.

## The loop (F13)

1. Take the assigned kind and proof slot from the orchestrator. Use local sources on beast: the repo, main and relevant PR branches. Do not request machine links or reach other machines. Current decisions replace older instructions. Call Recall `resolve` for the kind and family.
2. Rule 22 work stays first. Read local `designs/tighten2/ALL-DECISIONS.md` and `designs/tighten3/migrated/README.md` under `~/swamp-execution`; use their assigned target chart. Preserve newer landed designs and respect `tighten3/held` ownership; decisions override stale chart details. Land the chart and workflow in one push, Swamp lane labels equal to step names. Charts live in `docs/cli/<family>/<command>.mmd` ([where a chart lives](../../../docs/cli/README.md#where-a-chart-lives)). Apply flow-tighten and pass `bin/check-flows`; add the kind to `docs/cli/flows-migrated.txt` when the workflow follows its chart.
3. Read the legacy Gateway action, agent actions and feature tests at `6291bb036`. Public behavior is the parity spec (F9), including edge cases and values rewritten at admission, such as setup macros (#2304). Write parity tests first; explain phase-order changes and record F9 deviations in `docs/swamp/porting-retros.md`.
4. Wave 3 owns one shared proof topology version in `swamp/proof/topologies/`; never fork per-lane `minimal@N`. Proof VMs run on shark and beast. Start with `bin/swamp-proof up --topology <name>`. The Gateway VM carries `gateway` and `swamp`; its Nodes carry the kind's roles, joined by WireGuard (F14). Wave 3 fixes topology faults and bumps the shared version (F12).
5. Port and run the whole topology path: request, admission, Swamp, Nodes and terminal projection. Read full stderr and per-step timings; fix Gateway and Swamp bugs alike. Start a writer's repair proof with missing or stale state; topology setup must not make a no-op pass. Read the final receipt with `bin/swamp-proof receipt` and check every phase budget (F8). State the topology's limits: test repositories, Orbit CA, no production data or scale.
6. Reuse one topology across consecutive fixtures; mark only state-sensitive fixtures `"clean": true` so the harness restages the held VM with fresh Nodes and a fresh Gateway database. Then run `bin/swamp-proof down` and verify the proof VM is gone; the lane is not done while it is up. Do not rely on expiry: the reaper cancels groups over 90 minutes old without a heartbeat from the last hour, even without a reachable VM. See [proof lifetimes](../../../swamp/proof/README.md) (F11).
7. Rebase on fresh main and inspect the full push diff. Land port PRs through the enabled merge queue with `timeout 30 gh pr merge <number> --auto`, never REST merge. Never restore unrelated files from a stale tree (Routes restoration, `ebdfafdf46`). Before every push, run `bin/docs-impact --gate --base origin/main` (also enforced by the [bootstrap hook](../../../docs/contributor-guide.md)). Watch CI to green after every push. Whoever turns main red fixes it first. Every main SHA must finish Required checks; cancelled Swamp jobs are not green ([CI concurrency](../../../docs/reference/implementation-loop.md#ci)). Use `timeout` on every `gh` call; do not SSH to other machines. A short live check after the release load confirms uptake; it is not a second proof.

Never port against production serve or log in to 209 for a port. Use the [role-installed binary](../../../docs/reference/node-provisioning.md#role-prerequisites) at `/usr/local/bin/swamp` for control-host calls, never a hand-installed copy. The role installs versioned binaries and switches the link; never overwrite a running executable. Never restart or reload serve; config changes go through the swamp role and a release. The [release load](../../../docs/reference/gateway-recovery.md#load-swamp) refreshes manifest `additionalFiles` on reload without a restart (Lab #4282 fixed in pinned Swamp). Send real Swamp gaps to the orchestrator with evidence; do not build around them.

## Build it

Use the official swamp skill to create or edit the workflow. Apply the Orbit [workflow and Gateway templates](../../../docs/swamp/porting.md#fill-the-workflow) only where they match the tightened chart.

- **Admission:** freeze the full non-secret intent under `intent`, with names-only `{vault, key}` descriptors under `execution_secrets`. Encode empty maps as objects (#2273). Expand Gateway macros before execution (#2304). Reserve publication before capturing runtime definitions whose content depends on its domain. A prepared-runtime marker requires every recorded Process to be covered and every publication prerequisite to succeed; empty `forEach` placeholders alone do not prove readiness (L22-INSTANCE-REGISTER).
- **Placement:** all steps use only `labels: {role: swamp}`, with no inherited `target`; expanded proof topology workers carry the same label. Plain task VMs carry no Swamp binary, worker or worker token; 209 runs their actions over SSH (Recall `task-vms-swamp-via-ssh`). Run official Node behaviors from 209 with the admitted identity, host-key pins and account. Keep admitted owner IDs; replace Node-bound callbacks when moving execution. Copy placement from `operation-firewall-direct`.
- **Node work ([rule 22](../flow-tighten/SKILL.md#what-a-good-flow-looks-like)):** add no shipped script; replace one added by the current port with cfgmgmt or exec argv, or name the uncovered gap in the report and extension README. Drop rollback chains and runtime ownership checks. TypeScript only shapes typed inputs and outputs; explain custom growth (F15). Task VMs reuse IPs: pin SSH execs; enrollment replaces cfgmgmt's shared `known_hosts` entry with the observed key, and destroy removes it (`397fbbf948`).
- **Docker Processes (tighten2):** pull with `@swamp/cfgmgmt/docker_image`; create with plain `docker run -d --name orbit-<id> --env-file … -w … <image> <cmd>` via SSH exec argv; verify with `docker_container check`. Store its `state` in the execution vault: it includes environment values. Record missing options in `swamp-evaluation.md`, not a script.
- **Managed folders (tighten2):** use `cfgmgmt directory` to converge owner and mode of existing folders. Refuse `/`, `/home`, a home directory itself, `/etc` and `/usr` at Gateway admission.
- **Downloads (tighten2):** fetch and fingerprint-check keys on 209 before any Node contact. Use `cfgmgmt copy_file` for binary keys (`file` accepts UTF-8), and `file` for deb822 sources. Share staged data through a run-specific absolute path; dispatch-relative directories differ between steps. Scoped APT refresh sets `APT::Get::List-Cleanup=false` to preserve other indexes (Decision 7 proof). No script or Node download.
- **Secrets:** no secret bytes in inputs, outputs or argv. Declare every vault read by parent and child workflows. Keep vault values small: large public request envelopes break serve's redaction regex (op 8235). For mixed requests, frame one small secret with public `intent` fields on SSH exec stdin only as the [shape gate permits](../../../swamp/docs/swamp-shape-gate.md#automated-checks). For private text, use `vault.get` directly as cfgmgmt `file` content with mode 0600 (Q-SECRET receipt); never output the value or its base64 form. SSH `env` relies on `SendEnv`, so do not assume it reaches the target. Generate Gateway-owned secrets at admission; Node-held keys stay on the Node. Secret imports use a one-shot vault key, read once by the Gateway with `vault.read-secret`, then deleted with `vault.delete`; both exist in pinned Swamp. Token authority only shrinks: revoke only the removed Node's exact worker principal, failing closed; never mint or widen it.
- **Names:** follow [behavior naming](../../../docs/cli/README.md#behavior-names). Use the effect Node for SSH names, even when the Operation belongs to the Gateway. One name has one behavior type; disambiguate fixed names by type. Never share one per-Node SSH name across step families: differing global arguments rewrite its definition. Per-run names require an always-run delete; leaked auto-definitions caused serve's lookup CPU incident (Lab #4280). Sanitize dots with `split(".").join("-")`; the shape gate enforces names.
- **Fan-out compatibility:** use inputs or an earlier job's outputs in `forEach.in`; e459 expanded it before same-job outputs existed. Preserve the legacy host failure scope at `6291bb036`. Keep inputs bounded: no history-growing query or whole fleet `steps` map; pass only required statuses (#2310, #2334).
- **Private import copies:** cleanup also follows a failed staging write or partial copy. A guard requiring staging success can leak private bytes; wait for staging and copying to settle and remove the run-scoped paths. A skipped vault step still needs worker-copy cleanup (L22-ENV-IMPORT).
- **Errors:** preserve legacy refusal codes and setup exit cases, or explain changes. Map native failure exit codes in the Gateway; failed command steps keep no outputs on e459. SSH records stdout and stderr before later shaping: capture private command output in files, copy privately to the worker, redact with the [shared output filter](../../../docs/reference/tasks.md#keep-command-output-out-of-run-history), then delete. Scan history, data and logs in the topology proof. Use shared diagnostics, never a result-reporting step. Fresh credential checks cannot reuse an earlier request's success; completed verification may survive native resume (vault.setup retro).
- **Serve throttling:** diagnose `swamp.vault_sync_unavailable` from the Gateway warning's `phase` and HTTP status ([logs](../../../docs/reference/gateway-recovery.md#gateway-request-logs)). A connection HTTP 429 is admission throttling; check SQLite warnings separately. Reuse the shared [connection and transport recovery](../../../docs/reference/swamp-command-steps.md#terminal-outputs); add no per-request connections or unbounded retries. Missing, mismatched or running history is not retried (`f1d508f701`).
- **Budgets (F8):** use the [budget table](../../../docs/swamp/porting.md#set-the-time-budget). A measured explicit budget wins; otherwise start at 30 minutes, then use 1.5× the longest success. Do not size budgets from runs that skipped or deferred the work (`2bde8d5bed`). Never borrow a flat budget. Every workflow, children included, sets `queueTimeout`, equal to the proof's `queue_timeout_seconds`. Bound phase commands with literal `timeout <seconds>`; a remote read may instead set SSH `timeoutSec`, while writes keep a remote-side bound (#2334). No family timer or timeout epilogue.
- **Polling exception:** only an existing script for a named gap may poll external HTTPS state, under a literal phase timeout, at a fixed shorter interval, with failing GETs and no retried requests. State interval and budget in the change report. Never poll Gateway or Orbit state or retry failed actions. Use the reference's [gate requirements](../../../docs/swamp/porting.md#set-the-time-budget); add no baseline row (#2325, #2366).
- **Gateway:** use shared `StartSwampRun`, `SwampCommandStep::executionCopy` and the family projector. New ports declare [native terminal results](../../../docs/reference/swamp-command-steps.md#read-swamps-run-data-instead-of-a-result-step): `terminal_result` names the end check with `native => true`; read status through `NativeRunResult::stepStatus`. Use `captures` for producer JSON; the step summary truncates stdout at 4 KiB (tasks.script retro). After cleanup failure, keep the Operation failed while retaining completed producer observations (tasks.turn retro). No `outputs: false` or result step. One shared terminal history reader; no family callbacks, holds, pollers, timers, retries or second readers. Preserve an exact native terminal that met its budget even after Gateway expiry. A failed projection must leave expiry armed; no queued marker may suppress it (L17-PR-2348-01).
- **Delete:** trace production admissions and child-workflow callers; remove uncalled standalone roots instead of proving them (#2529, #2532). Remove the old executor, tests, embedded scripts, callbacks and paths used only by it in the same change. An F9 rebuild also removes replaced behaviors and tests (F15). Do not touch `apps/agent`. Remove the kind's shape-baseline rows.

## Check and review

- Follow the official workflow validation guide on the pinned runtime. Run fast Deno unit tests for Orbit TypeScript logic, parity tests, script lint and Gateway Pest admission/projection tests. Add no native workflow tests or custom runtime harness; drop cases that test Swamp, shell or CEL behavior. Use the [test layout](../../../docs/swamp/porting.md#test-layout). Remove fixture DNS overrides after parity so restaging can download real artifacts; a retained GitHub alias broke `node.converge`. Parity reads `PROOF_OPERATION_FILE`; a full Operation in an environment value can exceed `MAX_ARG_STRLEN`. For admissions that complete without a run, assert an empty `PROOF_NATIVE_RUN` (#2524). Public show/cancel replies are summaries; proof execution envelopes come from the internal Operation. Fake privileged host tools such as `groupadd`; serialize shared fixture state used by parallel steps. Fixture package installs refresh APT indexes first (vault.setup proof). Real-Docker tests require `ORBIT_DISPOSABLE_DOCKER=1` inside a disposable proof VM, never a shared host; clean up with `docker rm --force --volumes` (#2358). A killed test can skip cleanup; destroy the VM afterwards.
- Run the shape gate, `bin/lint-behavior-names.ts`, placement lint and `bin/check-grant-patterns.py --cache <runtime-cache>` in `swamp/`. Grant patterns must pass pinned `swamp serve check-config` on Gateway-rendered grants; a standalone regex helper misses full CEL validation and can leave serve unable to start. Their CI lives at root `.github/workflows/swamp-shape.yml`, never under `swamp/.github` (#2372).
- Run root `bin/check-operation-kinds` too. Every intended vault grant, including native sensitive output fields, must appear in its kind's `execution_copies` declaration. Native `serve check-config` validates CEL, not this Orbit policy parity; a passing topology does not check the registry entrypoint (Vault rule 22).
- Report measured p95, sample, run budget and `queueTimeout`. Report Orbit net lines, then `swamp/` growth split into behaviors, workflows, scripts, tests and fixtures, with a reason for each (F15). Prefer receipts and parity tests over duplicate mocked fixtures.
- Attach a receipt and [proof file](../../../swamp/proof/README.md) for workflow, behavior, script or Gateway execution-contract changes (#2266, #2273, #2304). Deletion-only, docs and test changes need no receipt. An outage exception names the omitted receipt and the live check after load (#2332).

Review against the [checklist](../../../docs/swamp/porting.md#pr-and-review-checklist), current chart and flow-tighten. Missing budgets, required receipts, explained growth or reasons for legacy phase changes fail review. Read the change report before calling a reason missing. Keep source conformance, CI, served-source uptake and live evidence separate. Report PASS or deviations as `file:line`, broken rule and native replacement, with reviewed SHA and skill version.

Use the official workflow references to check guard, dependency and output semantics before alleging a silent skip. On e459, missing intent fields fail CEL evaluation (#2369). An added intent field needs its Gateway release live before the Swamp load; pre-release runs are re-admitted, not resumed. Remove a checkout script mode only after the served workflow stops calling it: release load moves checkout before workflow reload. Check the whole workflow's `queueTimeout` (L17-PR-2363-02). When captures become sparse, inspect every guard that used the full form (#2383). Main is not `deno fmt` clean; do not block on unrelated formatting (#2332).

## Improve this skill

After a landed behavior change, record the retro and proof receipt in `docs/swamp/porting-retros.md`, including kind versus topology faults. Replace the affected rule the same hour; use canonical finding IDs instead of duplicate rows. Keep Swamp mechanics in the official swamp skill and shared flow rules in flow-tighten.

Every two hours, read local lane reports and main commits since the last update. Fold in only new Orbit migration lessons; replace superseded text and add lines only for new rules. Follow the checks and main discipline above. Put questions and reports in the final message, at most five lines; the orchestrator reads it every 15 minutes.
