# JSON Renderer: `orbit vpn-web-ui:change-password`

[Back to `vpn-web-ui:change-password` technical contract.](1_vpn-web-ui-change-password.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces
non-interactive input mode and never grants destructive consent.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "vpn": {
        "password_changed": true,
        "sessions_invalidated": true
      }
    },
    "meta": {}
  }
}
```

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to rotate the VPN web UI password.",
    "meta": {
      "field": "force",
      "reason": "destructive_consent_required"
    }
  }
}
```

## Rotation Failure Shape

```json
{
  "error": {
    "code": "vpn_credential_rotation_failed",
    "message": "VPN credential rotation failed.",
    "meta": {
      "step": "credential_store"
    }
  }
}
```

The new password must never appear in `success`, `error`, or `meta` fields.

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.vpn.password_changed` | boolean | Always `true` on success. |
| `success.data.vpn.sessions_invalidated` | boolean | Whether existing backend admin sessions were invalidated. |
| `error.code` | `validation_failed`, `vpn_runtime_unavailable`, `vpn_runtime_ssh_unavailable`, `authorization_failed`, `vpn_backend_unavailable`, `vpn_backend_auth_failed`, `vpn_credential_rotation_failed` | Stable command failure code. |
| `error.meta` | object | Validation, gateway SSH, authorization, backend, authentication, or rotation failure context. |
