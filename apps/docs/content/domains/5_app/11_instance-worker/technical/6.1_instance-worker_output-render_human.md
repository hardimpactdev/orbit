# Human Renderer: `orbit instance:worker`

[Back to `instance:worker` technical contract.](1_instance-worker.md)

## Primitive

None. Human output is a short status line plus an indented configuration
summary.

The human renderer summarizes the resulting worker-mode state and, when
worker mode is enabled, the active worker configuration.

## Progress Tree

No progress tree is rendered because `instance:worker` is expected to stay below
one second. `show` and `disable` perform fast gateway database reads/writes;
`enable` runs a single readiness probe against the selected instance's serving
node and then writes instance configuration.

## Output Strings

The renderer uses the `action` vocabulary as the JSON renderer. Human strings
phrase the state in plain language; the JSON renderer is authoritative for
machine consumers.

### Show — worker disabled

```text
Instance 'docs.development' worker mode is disabled.
```

### Show — worker enabled

```text
Instance 'docs.development' worker mode is enabled.
  workers: auto
  max_requests: 500
```

### Enable — changed

```text
Instance 'docs.development' worker mode enabled.
  workers: auto
  max_requests: 500
```

### Enable — already enabled (no change)

```text
Instance 'docs.development' worker mode already enabled.
  workers: auto
  max_requests: 500
```

### Disable — changed

```text
Instance 'docs.development' worker mode disabled.
  workers: auto
  max_requests: 500
```

`disable` continues to show the stored `worker_config` because the
configuration is retained for the next enable.

### Disable — already disabled (no change)

```text
Instance 'docs.development' worker mode already disabled.
```

## Failure Output

### Readiness failed

```text
Instance 'docs.development' is not ready for worker mode.
```

### Unsupported runtime

```text
Worker mode requires runtime=php; instance 'docs.development' uses 'static'.
```

Authorization failures originate at the API permission middleware and are
documented as part of the JSON renderer contract (see
[`6.2_instance-worker_output-render_json.md`](6.2_instance-worker_output-render_json.md)).
The command's human renderer does not own that failure shape, so it is not
covered here.
