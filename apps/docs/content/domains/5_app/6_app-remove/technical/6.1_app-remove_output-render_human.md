# `app:remove` Human Renderer

[Back to `app:remove` technical contract.](1_app-remove.md)

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

This file owns the human-rendered terminal output for `app:remove`.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[`interactive input mode`](5.1_app-remove_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Destructive Frame

The command begins with a framed destructive confirmation message (see
[`5.1_app-remove_input-mode_interactive.md`](5.1_app-remove_input-mode_interactive.md)).

## Progress Tree

Render the complete progress tree after input resolution and destructive
consent, before removal side effects begin.

```text
┌ Removing App
○ Validate removal
○ Apply and verify app removal
○ Remove app-owned proxy routes
○ Remove app-owned schedules
○ Remove app-owned workspaces
○ Stop and remove app processes
○ Clean node-side runtime artifacts
└ Working...
```

When a step encounters non-fatal drift (e.g. a proxy route could not be
removed, a runtime container configuration could not be cleaned), the step completes as a warning,
subsequent steps still run, and the footer reports drift:

```text
┌ Removing App
○ Validate removal
○ Apply and verify app removal
○ Remove app-owned proxy routes
○ Remove app-owned schedules
○ Remove app-owned workspaces
○ Stop and remove app processes
○ Clean node-side runtime artifacts
└ App `my-app` removed with drift

Drift detected:
- app: runtime container configuration could not be removed (run `doctor --family=app --restore`)
```

## Success Output

When removal succeeds with no drift:

```text
App 'my-app' removed
```

When removal succeeds but cleanup leaves drift behind:

```text
App 'my-app' removed
  Drift detected:
  - app: runtime container configuration could not be removed (run `doctor --family=app --restore`)
  - proxy: app-owned proxy route could not be removed (run `doctor --family=proxy --restore`)
```

Each drift line corresponds to one structured warning in the JSON renderer's
`success.meta.warnings[]`.

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Missing app

Already-absent removal renders this validation failure. It is not a successful
idempotent removal.

```text
App 'my-app' not found.
```

### Missing destructive consent

Rendered for non-interactive human output when `--force` is absent.

```text
Use --force to remove this app.
```

### Missing remove permission

```text
This node is not authorized for 'app:remove' on 'app-1'.
```

### Gateway unavailable

```text
Gateway connection is required to remove an app.
```

### Remove authorization failed

```text
This client is not authorized to remove this app.
```

### Gateway configuration removal failure

Rendered when Step 1 itself fails. No dependent or node-side cleanup has run.

```text
Failed to remove the gateway app record for 'my-app'.
```

### Cancelled confirmation

```text
Operation cancelled.
```
