# `process:update` Interactive Input Mode

[Back to `process:update` technical contract.](1_process-update.md)

This page describes how interactive input mode resolves `process:update` input.

**Input mode:** Interactive.

## Selection

Use this input mode only when the process is attached to a TTY and `--json` is not present.

## Prompt Behavior

Prompt for missing required input in this order:

| Field | Prompt primitive | Notes |
| --- | --- | --- |
| `apps/gateway/tests/Feature/Http/Api/ProcessUpdateControllerTest.php` | Gateway API validation, authorization, rename uniqueness, runtime cleanup, unsupported rename, and warning envelopes. |
| `apps/gateway/tests/Feature/Http/Api/ProcessUpdateControllerTest.php` | Gateway API validation, authorization, rename uniqueness, runtime cleanup, unsupported rename, and warning envelopes. |
| `instance` | Datatable | Show concrete instances the caller is authorized to manage when instance context is absent. A supplied ambiguous bare project slug fails with `validation_failed`, `field=instance`, and `reason=instance_required` instead of prompting. |
| `name` | Datatable | Select from existing processes for the resolved instance. If no process exists, fail before prompting for an open value. |

Editable fields are not prompted when none are supplied. Instead, show a validation message that at least one editable option is required, then let the operator provide an option or cancel. If `--name` is supplied, validate the new slug as soon as the current process and owning scope are known.

Prompt validation runs as soon as the field needed for a decision is known.
