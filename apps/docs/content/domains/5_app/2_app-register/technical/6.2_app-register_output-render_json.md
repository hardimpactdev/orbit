# Technical Contract: `orbit app:register` (JSON Renderer)

This contract defines the **JSON renderer** for `app:register`.

[Back to the canonical contract.](1_app-register.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "registered"
      },
      "app": {
        "name": "docs",
        "node": "app-1",
        "url": "https://docs.test",
        "path": "/home/orbit/apps/docs",
        "root": "public",
        "repository": null,
        "runtime": "php",
        "runtime_config": {
          "proxy_transport": "http"
        },
        "php_version": "8.5",
        "adopted": false
      }
    },
    "meta": {
      "node": "app-1",
      "warnings": []
    }
  }
}
```

### Fields

- `result.action`: One of `registered`, `adopted`, `moved`, `partial`, or
  `converged`. Describes what
  this run did.
  - `registered` — first-time registration of a known path that is not yet
    managed by Orbit.
  - `adopted` — first-time registration where the path existed on the node
    but was unmanaged. `app.adopted` is set to `true` for this run.
  - `converged` — idempotent re-application where no observable artifact change
    was needed. The durable `app.adopted` value is preserved across
    converged re-runs.
  - `partial` — a re-application persisted route intent but proxy enactment
    failed. `meta.warnings[]` identifies the failed layer, node, and operation.
- `app`: The canonical app JSON entity defined in
  [`5_app/README.md`](../../README.md#app-json-entity). `app.adopted` is
  `true` once the path was adopted via registration and stays `true` on
  subsequent converged re-runs.
- `meta.warnings`: Structured non-fatal drift and retry handoffs. Each entry
  carries `code`, `family`, `message`, and `next_command`.


## Error Envelope

### Path collision

Returned when the supplied `--path` on the resolved node is already owned by a
different registered app. Fails before any side effects.

```json
{
  "error": {
    "code": "app.path_collision",
    "message": "Path '/home/orbit/apps/docs' on node 'app-1' is already owned by app 'docs-archive'.",
    "meta": {
      "path": "/home/orbit/apps/docs",
      "existing_app": "docs-archive",
      "node": "app-1"
    }
  }
}
```

### Apply failure

```json
{
  "error": {
    "code": "app.enactment_failed",
    "message": "Failed to complete non-retryable app application on node 'app-1'.",
    "meta": {
      "step": "enact_runtime_artifacts",
      "node": "app-1",
      "reason": "Permission denied"
    }
  }
}
```

### Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (e.g. malformed `--domain`, unsupported `--php-version`, missing required field). `error.meta.field` names the offending input. |
| `app.path_collision` | The supplied `--path` on the resolved node is already owned by a different registered app. `error.meta.path`, `error.meta.existing_app`, `error.meta.node`. |
| `app.ineligible_node` | The caller may run `app:register`, but the resolved target node does not have the active app role required for the requested registration mode. `error.meta.required_role` is `app-dev` when `--domain` is absent and `app-prod` when `--domain` is supplied. |
| `app.enactment_failed` | Registry write succeeded but node-side execution failed in a way that cannot be retried through convergence. Fields: `error.meta.step`, `error.meta.node`, `error.meta.reason`. |
| `authorization_failed` | The caller lacks `app:register` on the resolved target app node. |

Retryable runtime or configuration drift is reported as
`success.meta.warnings[]` instead of `app.enactment_failed`. Managed app
configuration uses `app.*` codes; concrete runtime containers use
`process.runtime_unit_*` with `family: "process"`.

### Common Warning Codes

Non-fatal drift is reported in `success.meta.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`.

| Code | Family | Meaning |
| --- | --- | --- |
| `proxy.domain_inactive` | `proxy` | The production domain is not yet active because DNS or TLS prerequisites are pending. Retry with `app:register [name] --domain=<host>`. |
| `app.php_version_unavailable` | `app` | The requested PHP version is supported by Orbit but the matching image is not yet available on the owning node. Make the image available, then `doctor --family=app --restore` converges. |
| `process.runtime_unit_missing` | `process` | The concrete app-instance runtime container could not be rendered or started. `doctor --family=process --restore` will repair it. |

## Enum and identifier values

| Field | Values |
| --- | --- |
| `result.action` | `registered`, `adopted`, `moved`, `partial`, `converged` |
| `error.code` | `validation_failed`, `app.path_collision`, `app.ineligible_node`, `app.enactment_failed`, `authorization_failed` |

The `error.code` values listed here are exhaustive for `app:register`. Add a
new value to this renderer contract before implementing another JSON failure
code.
