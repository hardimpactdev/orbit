title: "orbit firewall:remove"
sidebarTitle: "firewall:remove"
description: "Remove the one operator rule that matches a port from UFW and delete its record."
---

```bash
orbit firewall:remove <port> --node=ID [--from=SOURCE] [--protocol=PROTO] [--yes] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `port` | yes | Destination port or ordered range of the rule. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--node=ID` | required | Numeric target Node ID. |
| `--from=SOURCE` | any source | Match only the rule with this source. `--from=any` matches only a rule for any source. |
| `--protocol=PROTO` | any protocol | Match only the rule with this protocol, `tcp` or `udp`. |
| `--yes` | prompt | Confirm without prompting. |
| `--idempotency-key=KEY` | generated | Reuse a key to retry the same [Operation start](/reference/operations#start-an-operation). |
| `--json` | off | Print the result as JSON. |

```bash
orbit firewall:remove 5432 --node=7 --from=10.6.0.0/24
orbit firewall:remove 5432 --node=7 --from=10.6.0.0/24 --protocol=tcp --yes
```

The port, and `--from` and `--protocol` when given, must match exactly one rule. No match is refused with `firewall.rule_not_found`. Several matches are refused with `firewall.rule_ambiguous`, and the error lists each match; add `--from` or `--protocol` to pick one.

The CLI asks `Remove firewall rule [443/tcp from any] from Node beast?`, naming the Node, with No selected. Declining, Ctrl-C or end of input exits 1 with `input.cancelled`. Without `--yes`, a command that cannot prompt exits 1 with `input.confirmation_required`. `--json` never implies consent. A declined removal sends no request.

Only one firewall change can run on a Node at a time. Another change is refused with `operation.target_busy`.

Orbit deletes the lines on the Node that belong to this rule alone. A line that Orbit also needs for a role or for WireGuard peer trust stays. A line that is already gone is skipped. If every line is already gone, the command still deletes the record and succeeds with `Skipped — already removed (firewall.rule_absent)`. The other rules keep their order. Removing a deny reopens the port to the sources it blocked, and removing an allow closes it to the sources it admitted. To lift a restriction without an exposure window, remove the deny before the allows, as [the change order](/cli/firewall#change-rules-without-an-exposure-window) says.

Completion deletes the rule record. A failure leaves the rule marked `failed` and does not restore lines already removed. Repeating the command finishes the removal.
