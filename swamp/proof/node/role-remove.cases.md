# node:role:remove verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a Metrics Node and a managed Linux Node that holds several roles. It checks the Gateway record, the machine state and real traffic. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Remove a role | A Node with `database` and another role. Remove `database` with `--force`. | The Operation succeeds and the assignment is gone. The role's services are stopped, its files, configuration, containers, firewall rules and certificates are gone, and its port is closed. The other role is untouched. |
| Fleet withdrawal | A role with PHP pools, Caddy sites, private DNS, a Metrics exporter entry and role certificates on other Nodes. Remove it. | All of them are withdrawn from the other Nodes. The sites no longer answer. |
| Last role | Remove the only role of a Node, then make the public SSH restore fail. | Public recovery SSH is restored first, so the Node stays reachable over SSH throughout. After a failed restore the Node is still reachable and the rerun restores it. |
| Role data | Remove `metrics`, then add it again and remove it with `--purge-data`; likewise `websocket` and `ci-runner`. | Without the option, the volumes, credentials and checkout stay. With it, the Prometheus and Grafana volumes and the stored credentials, the Reverb checkout, or the Incus project, network and ACL are gone. Without a terminal, `--purge-data` without `--force` is refused with `validation.failed`. |
| CI role | Remove `ci-runner` with guests running, then after they are drained. | The run fails with `node.removal_incomplete` and the role is `failed` at that step while guests run. The rerun after they are drained succeeds. CI resources and release data stay. |
| Dependents and protected roles | `app-dev` on a Node with Instances, `app-dev` or `app-prod` with Route targets, `ingress` with public Routes, `analytics` with tracking hosts, and `vpn`, `router` and `swamp`. | `validation.failed` for each, and `analytics.tracking_hosts_exist` for `analytics`, with no change. An inactive or unmanaged Node gives `operation.kind_unavailable`. |
| Consent | In a terminal, run without `--force`, read the review, decline, then confirm. Also run noninteractively and with `--json` without `--force`. | The review shows the removal and its dependent cleanup. The prompt names the Node and the role, with No selected. Declining ends with `input.cancelled`. The noninteractive and `--json` calls get `validation.failed` with `field: force` and `reason: destructive_consent_required`. No Operation starts until confirmed. Fails today: the Gateway sends no dependents for the review, and the prompt names `Node #ID` instead of its name. |
| Offline | Stop the machine and remove a role with `--offline --force`. Then remove a role from a reachable Node with `--offline --force`, and from an unreachable Node without `--offline`. | The work on other Nodes runs and the machine is untouched. The reachable Node gets ordinary cleanup. The unreachable one fails with `node.removal_incomplete`. Fails today: the code refuses `--offline` with `operation.kind_unavailable`. |
| Role states | Remove a role that is `failed`, one `provisioning`, one `removing` with a fresh claim, and one with a stale claim. | The failed and stale ones are removed. The others are refused with `validation.failed`. Fails today: removal does not check the claim. |
| Failed step | Make a removal step fail. | The Operation fails with the step's own error code. The role stays `failed` at `remove:<step>` with that code. Finished steps stay. |
| Rerun after failure | Fix the cause and run the same command. | The Operation succeeds, the assignment is gone, and nothing is repeated that already finished. The run folder is removed after both runs. |
| Concurrent removals | Start two removals of one role together, then a third after they finish. | The second is refused with `operation.target_busy` and the first is unaffected. The third gets `http.404`. Fails today: no Node hold is taken for a removal. |
| Role not held | Remove a role the Node never had, and `ingress` the Node does not hold. | `http.404` for the first. The `ingress` removal succeeds and changes nothing. Fails today: `ingress` also gets `http.404`. |
| Busy | Start a second add, converge or remove while one runs. | `operation.target_busy`. The first run is unaffected. |
| Missing input | In a terminal, run the command with no arguments. Then run it noninteractively and with `--json` without the Node, then without the role. | The terminal asks for the Node from an interactive list and the role from the Node's roles. Ctrl-C ends with `input.cancelled` and no request. The noninteractive calls are refused with `node.id_invalid` and `node_role.role_required`, with no request. Fails today: the arguments are required and nothing prompts. |
| Node by ID only | Pass a Node name instead of its ID. | `node.id_invalid`, with no request. Fails today: the CLI accepts a name. |
| Dropped inputs and lost response | Run with `--idempotency-key`, and lose the response to the start. | The option is refused as unknown, and exactly one Operation exists. Fails today: the CLI offers `--idempotency-key`. |
| Refusals | A Node the caller has no access grant to, and an unknown ID. | `node.access_denied` and `http.404`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result with the Operation and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Operation. |
