Doctor compares current Node and runtime facts with the Gateway's recorded intent. It reports differences and never repairs them. Native provisioning, deployment, Route, Tool, Schedule and database operations own their configuration checks. Doctor reuses the native firewall comparison for operator rules, matched by port, protocol and source.

## Commands

| Command | Result |
| --- | --- |
| [`doctor`](/cli/doctor/doctor) | Read current Node, role-service, Process and firewall state. |

## Why it works this way

### Verify only

For each Node, Doctor prints the agent's liveness line before its findings and marks the findings of a Node whose agent is offline "possibly outdated". Doctor reports from the facts each Node's agent reported, and shares its firewall comparison with `firewall:list --live`. Each native family owns the checks that establish its configuration. Repeating those implementations in Doctor creates a second execution engine and competing definitions of success.

### Informational findings stay healthy

An informational finding is not drift or unverifiable. A parked task VM does not become unhealthy merely because Doctor skips it.

### No stored reports

Each request compares the latest facts and returns the report; nothing stores it. Scheduled collection records bounded fingerprints, not raw host output or private values.

### One observation per Node

Every host fact belongs to its admitted Node. Doctor does not infer remote state from another Node's successful read.

### A closed family list

The API keeps its fixed family names. The table above defines the current inspection scope. A zero-check family cannot clear an old incident.

### Bounded values

Expected and observed issue values contain at most 255 characters. Recovery evidence names only the codes actually compared. It never claims whole-resource coverage, so retiring a check does not silently resolve its old findings. Checks without a usable fact share the `node:ID` check identity within their family; a later request clears that inspection failure only when every check for that family and Node has a usable fact. Old numeric-resource inspection failures remain outside this reduced scope.

## Scheduled collection

Collection runs the same Doctor comparison. Then the Gateway reads its own Laravel log in `storage/logs` from the stored cursor; no Swamp step and no Node read is involved. It reads at most 1 MiB per pass, finishing a record up to an 8 MiB cap. It keeps exception class, safe source frame, request ID and timestamp; messages and raw logs never leave the reader.

The first pass starts at the current end. Rotation preserves unread records by inode; truncation resumes at the shorter end. An unreadable log result preserves the cursor. The Gateway commits returned fingerprints and the cursor together. Activity and assistance collection keep their existing bounded database cursors and redacted inputs.

For Cluster LAN DNS, Doctor uses the last member capability receipt and current health-unit observations. It reports unsupported delegates and failed Cluster lookups. It never switches a member to VPN after a Router or LAN outage. See [private DNS](/reference/private-dns#repair-one-peer).
