# Relocate the gateway role

## Problem

Initial bootstrap places `gateway` and `vpn` on one Node. Moving `gateway` to a dedicated machine while keeping the WireGuard hub and private DNS on the original Node requires [`node:role:relocate`](/cli/node/role-relocate) plus manual handoff steps ([native role relocation](/reference/node-provisioning#native-role-relocation)).

## Cause

`vpn` never moves, and `gateway` is a singleton: removing and re-adding it would drop Gateway authority and remove `gateway.orbit` from private DNS. Relocation keeps one active assignment throughout the move, but does not copy files or the SQLite database.

## Solution

1. **Free the name if reusing `gateway`:** Node names are unique, so rename the existing Node first:

```bash
orbit node:update gateway --name=vpn
orbit node:add gateway <new-host>
```

2. **Prepare the target Node:** Ensure it holds none of the conflicting roles (`app-dev`, `app-prod`, `database`, `analytics`, `ingress`, `ci-runner`), install PHP-FPM and Caddy, copy the Gateway checkout, `ORBIT_HOME` (Orbit CA and Gateway SSH keys), and Gateway `.env`, and ensure both Nodes have SSH management recorded.
3. **Relocate the assignment:**

```bash
orbit node:role:relocate gateway gateway --force
```

If private DNS routing fails on the target, follow the command returned in `follow_up`. If cleanup fails on the source, re-run with `--from`.

4. **Complete the manual cutover:**
   - Stop and drain all SQLite writers on the old Gateway (`orbit-runtime-hibernator.timer`, `orbit-runtime-hibernator.service`, Horizon, the scheduler, `orbit-agent-view.service`, `orbit-gateway-engine.service` if installed, Caddy, and PHP-FPM) and keep them stopped through handover so no writes or WAL checkpoints race with the copy ([Back up before an update](/reference/gateway-recovery#back-up-before-an-update)).
   - Copy the quiescent SQLite database (`gateway.sqlite` plus any `-wal`/`-shm` files) from the old Node to the target, then start Caddy and PHP-FPM on the target.
   - Note that `gateway.serving_node_id` still points at the old Node until a Gateway bootstrap updates it.
   - Run `orbit node:converge <node-id>` on each Node so its [Node agent](/reference/node-agent#how-it-connects) picks up the new Gateway address.
   - Update CLI profiles referencing the old WireGuard address.

Private DNS now publishes over SSH to `/var/lib/orbit/private-dns/catalog.json` on the `vpn` Node, which retains `/etc/wireguard/orbit.conf` and needs no Orbit checkout.

## Limits

Relocate does not install Laravel, copy SQLite or the Orbit CA, or relocate `swamp` (`node.role_relocate_swamp_held`).

## Verification

Run these checks with numeric Node IDs:

```bash
orbit node:role:list <old-node-id>
orbit node:role:list <new-node-id>
orbit doctor --node=<new-node-id>
curl --fail https://gateway.orbit/up
```

Confirm `gateway` is on the new Node, `vpn` remains on the old Node, `orbit node:show` lists access to `vpn` (and `metrics` if present), `https://<new-wireguard-ip>/up` answers, and converging a Route updates `/var/lib/orbit/private-dns/catalog.json` on the `vpn` Node.
