# Stream JSON Renderer: `orbit doctor`

[Back to `doctor` technical contract.](1_doctor.md)

This page describes the newline-delimited JSON stream output for `doctor`.

**Renderer:** Stream JSON renderer.

## Primitive

None. The renderer emits one JSON object per line. It does not render ANSI,
the human doctor panel, a progress tree, or a spinner.

## Selection

Use this renderer when `--stream-json` is present and `--json` is absent.

`--stream-json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even when
the process has a TTY. `--stream-json` and `--json` are mutually exclusive.
`--stream-json` is rejected with `--fix` because `--fix` is an interactive
prompt flow.

Validation failures that happen before the gateway stream opens use the shared
[JSON Envelope](../../../README.md#json-envelope) without an `event` key:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "doctor --json and --stream-json cannot be combined.",
    "meta": {
      "fields": ["json", "stream-json"]
    }
  }
}
```

## Frame Contract

After the stream opens, every output line is one JSON object with an `event`
field. The renderer consumes the existing gateway Server-Sent Events transport
and preserves the gateway event order.

Frames that are not terminal carry the gateway payload under `data`:

```json
{"event":"tree","data":{"title":"Running Doctor","steps":[{"key":"node","label":"Check node"}]}}
```

```json
{"event":"step","data":{"key":"node","status":"running","message":"Checking node"}}
```

The successful terminal frame carries the standard success envelope as a
sibling of `event`. The doctor diagnostic is under `success.data.doctor`.

```json
{"event":"complete","success":{"data":{"doctor":{"mode":"verify","healthy":true,"scope":{"self":false,"node":"beast","app":null,"workspace":null,"key":null,"families":["node"]},"summary":{"issues":0,"fixed":0,"adopted":0,"skipped":0,"conflicts":0,"failed":0,"planned":0},"issues":[],"actions":[]}},"meta":{"exit_code":0}}}
```

The error terminal frame carries the standard error envelope as a sibling of
`event`. When the gateway provides a doctor diagnostic, it is under
`error.data.doctor`.

```json
{"event":"error","error":{"code":"drift_detected","message":"Doctor detected drift.","meta":{},"data":{"doctor":{"mode":"verify","healthy":false,"scope":{"self":false,"node":"beast","app":null,"workspace":null,"key":null,"families":["node"]},"summary":{"issues":1,"fixed":0,"adopted":0,"skipped":0,"conflicts":0,"failed":0,"planned":0},"issues":[{"family":"node","node":"beast","key":"node.wireguard_peer_missing","code":"node.wireguard_peer_missing","kind":"missing","summary":"WireGuard peer for node beast is missing.","restorable":true,"adoptable":false}],"actions":[]}}}}
```

If the transport fails after at least one progress frame has been emitted, the
renderer emits a final `event=error` frame instead of switching back to the
pre-stream envelope shape:

```json
{"event":"error","error":{"code":"gateway_unavailable","message":"Gateway progress stream closed without a terminal frame.","meta":{}}}
```

## Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `event` | string | Gateway progress event type: `tree`, `step`, `complete`, or `error`. |
| `data` | object | Gateway progress payload for non-terminal `tree` and `step` frames only. |
| `success` | object | Standard success envelope for `event=complete`. |
| `success.data.doctor` | object | Final doctor diagnostic payload. |
| `success.meta.exit_code` | integer | Gateway terminal exit code. |
| `error` | object | Standard error envelope for `event=error`. |
| `error.code` | string | Stable machine-readable failure code. |
| `error.message` | string | Human-readable failure prose. Automation must not parse it. |
| `error.meta` | object | Stable machine-readable failure metadata. Empty when no stable metadata exists. |
| `error.data.doctor` | object | Final doctor diagnostic payload when available. |

The doctor object uses the same field meanings documented in the
[final-frame JSON renderer](6.2_doctor_output-render_json.md#doctor-payload).

## Test Mapping

Required coverage:

No gateway-side coverage is required for this renderer because `--stream-json`
is a CLI-only adapter over existing gateway progress events; gateway tests own
the doctor payload and error-code production.

The CLI test covers frame shapes, terminal doctor payloads, bulk restore/adopt
routing, post-progress transport failures, renderer incompatibilities, and no
ANSI or human panel leakage.

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/Operation/DoctorCommandTest.php` | Frame contract, renderer validation, transport failure, and exhaustive error code coverage for documented stream errors. |
