# Human Renderer: `orbit node:list`

[Back to `node:list` technical contract.](1_node-list.md)

This page describes the human-rendered terminal output for `node:list`.

**Renderer:** Human renderer.

## Primitive

- Output table: [`Laravel\Prompts\table`](../../../../ux/commands/lists/table.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `node:list` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

`node:list` is a read-only registry query. Execution is expected to complete
below one second and does not perform slow external work.
No progress tree is rendered.

## Success Output

Human output renders a compact status indicator first, followed by the node name,
WireGuard peer IP, platform, and role assignments. The status indicator column
has no label. Active nodes render a green filled circle; non-active nodes render
a red filled circle. The human table does not render the lifecycle status text.

The `PEER IP` column renders the node's WireGuard peer address from
`addresses.wireguard`. It never renders the node's bootstrap or public `host`
metadata. When the WireGuard address is not recorded, `PEER IP` renders
`unknown`. The `PLATFORM` column renders the human OS family label such as
`ubuntu`; it renders `unknown` only when the gateway has not detected or
recorded the platform yet.

The `ROLES` column renders composable role assignments such as
`app-dev, database` and marks non-active assignments inline, for example
`database (error)`. When a node has no role assignments, `ROLES` renders `—`.

```text
   NAME        PEER IP   PLATFORM   ROLES
●  app-1       10.6.0.4  ubuntu     app-dev, database
●  app-2       10.6.0.5  ubuntu     app-prod
●  gateway-1   10.6.0.2  ubuntu     gateway, vpn, router
●  operator-1  10.6.0.3  ubuntu     —
```

When filters reduce the result set:

```text
   NAME   PEER IP   PLATFORM   ROLES
●  app-1  10.6.0.4  ubuntu     app-dev
```

When no nodes match the filters, or when no nodes are visible to the
authenticated caller:

```text
No nodes found.
```

## Failure Output

Human-rendered failures must show:

- the failing field or condition;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Invalid filter value

```text
Invalid value for --role: 'invalid'. Allowed values: gateway, vpn, router, app-dev, app-prod, database, agent, ingress, websocket, s3, metrics.
```

### Gateway unavailable

```text
Gateway connection is required to list nodes.
```

### Authorization failed

```text
This node is not authorized to read the node registry.
```
