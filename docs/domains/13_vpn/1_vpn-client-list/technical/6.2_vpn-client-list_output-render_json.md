# JSON Renderer: `orbit vpn-client:list`

[Back to `vpn-client:list` technical contract.](1_vpn-client-list.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "clients": [
        {
          "id": "client-1",
          "name": "laptop",
          "address": "10.6.0.7",
          "enabled": true,
          "latest_handshake_at": "2026-04-26T10:00:00Z",
          "kind": "admin"
        }
      ]
    },
    "meta": {
      "count": 1
    }
  }
}
```

## Error Shape

```json
{
  "error": {
    "code": "vpn_backend_auth_failed",
    "message": "VPN backend authentication failed.",
    "meta": {
      "reason": "totp_required"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.clients[]` | array | Clients visible to Orbit on the active `vpn` role runtime backend. |
| `success.data.clients[].kind` | `admin`, `node`, `unknown` | Orbit classification of the backend peer. |
| `success.meta.count` | integer | Number of clients returned. |
| `error.code` | `caller_role_not_allowed`, `vpn_runtime_unavailable`, `vpn_runtime_ssh_unavailable`, `authorization_failed`, `vpn_backend_unavailable`, `vpn_backend_auth_failed` | Stable command failure code. |
| `error.meta` | object | Caller, VPN runtime availability, VPN runtime SSH, authorization, backend, or authentication failure context. |
