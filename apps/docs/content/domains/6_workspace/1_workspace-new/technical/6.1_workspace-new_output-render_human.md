## Progress Tree

`workspace:new` performs remote work (source provisioning through the selected
workspace driver, registration, proxy route, workspace environment, runtime
container, setup steps, and inherited runtime units) that
typically exceeds one second. It uses the shared step-tree renderer to
visualize progress in real time.

```text
┌ Creating Workspace
○ Creating git worktree
○ Apply workspace registration
○ Register proxy routes
○ Initialize workspace environment
○ Install workspace runtime container
○ Run workspace setup steps
○ Render inherited runtime units
○ Check workspace readiness
└ Working...
```

The worktree provisioning step creates `<app path>/.worktrees/<workspace>` and
checks out branch `<workspace>` from the requested `--base` ref.

## Completion Summary

Upon success the progress tree finishes with a single footer line:

```text
Workspace 'feature-a' created
```

The workspace URL and its PHP version are not printed here; read them with
[`workspace:show`](../../4_workspace-show/workspace-show.md) or the
[JSON renderer](6.2_workspace-new_output-render_json.md).

## Warning Display

Drift that is non-fatal surfaces inline under the affected step and again in a
`Warnings:` block beneath the completion summary. Each warning entry shows
the human-readable message and a retry hint pointing at `next_command`,
mirroring the `app:new`/`instance:register` shape. Examples:

- A workspace path that did not get created during application prints
  "Workspace path is missing on 'app-1'." with the hint
  `Resolve with: orbit workspace:setup`.
- A missing managed workspace runtime configuration prints its message with
  the hint `Resolve with: orbit workspace:setup`. Concrete runtime-unit drift
  is process-family and uses `doctor --family=process --restore`.
- A pending workspace proxy route prints the corresponding
  `proxy`-family warning with its own `next_command`.

## Failure Display

Failures are rendered as prose errors with troubleshooting hints. If a
failure occurs during the progress tree, the affected step shows a red
error dot. Validation failures detected before side effects (reserved name
`main`, slug regex, per-app workspace-name collision, unsupported
`--php-version`, unresolved concrete instance) are rendered without a
progress tree. A bare parent app that has zero or multiple instances reports
that one concrete instance selector is required; Orbit never selects a
app-level node implicitly.

```text
✗ Failed to create workspace 'feature-a'
  Workspace 'feature-a' already exists for instance 'my-project.development'.
```

```text
✗ Failed to create workspace 'main'
  The name 'main' is reserved and cannot be used as a workspace name.
```
