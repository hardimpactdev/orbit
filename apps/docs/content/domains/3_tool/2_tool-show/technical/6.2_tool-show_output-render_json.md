# JSON Renderer: `orbit tool:show`

[Back to `tool-show` technical contract.](1_tool-show.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "tool": []
    },
    "meta": []
  }
}
```

Command-specific result data uses the canonical tool entity from
[`README.md`](../../README.md#tool-json-entity) unless the command returns
credentials. Service endpoint metadata that is not secret may be embedded
under `success.data.tool.endpoints` using the canonical
`{name, kind, url, host, port, upstream_port}` shape when derived (agent
consumer HTTPS URLs include `url`; `port` is public HTTPS `443` and
`upstream_port` is the proxy loopback listen port); credential secrets must
never be rendered by `tool-show`.

`--live` opts into live state through Agent push. Without `--live`, the registry
payload owned by the gateway remains schema-stable with
`success.data.tool.observed_state: null` and
`success.data.tool.observed_version: null`, and no node transport runs. With
`--live`, the gateway probes the selected `NodeTool` through Agent push and
overlays these fields.

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.tool.observed_state` | string \| null | Primary live lifecycle state from the selected node, such as `running`, `stopped`, `installed`, or `absent`. |
| `success.data.tool.observed_version` | string \| null | Live observed version when the probe can determine it. This field is distinct from `version`, which remains the gateway-owned intended or registry-known version. |

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Required input is missing or invalid.",
    "meta": {
      "field": "tool"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `tool.not_found`, `tool.unsupported_action`, `tool.remote_action_failed` | Stable command failure code. |
| `error.message` | string | Human-readable failure summary. |
| `error.meta` | object | Field, target, caller, or remote-action context for automation. |

`tool.remote_action_failed` is returned when the gateway can read the tool row
but live inspection fails. Its metadata includes:

| Field | Type | Meaning |
| --- | --- | --- |
| `error.meta.tool` | string | Tool name being inspected. |
| `error.meta.node` | string | Target node name. |
| `error.meta.reason` | `probe_exception` \| `empty_snapshot` | Stable failure reason. |
