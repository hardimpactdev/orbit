# Realtime events with Reverb

## Problem

The web app and `realtime:logs` rely on Gateway broadcasts over WebSockets ([Realtime events](/reference/events)). Without an active `websocket` role, the Gateway broadcasts nothing. [Reverb apps](/reference/websocket-apps) owns the server, registry, upgrades, and recovery.

## Cause

Reverb holds long-lived connections outside the Gateway process via the `websocket` role and serves clients at `wss://reverb.orbit`.

## Solution

Assign the `websocket` role using a numeric Node ID:

```bash
orbit node:role:add <node-id> websocket
```

`websocket` is a singleton with no role conflicts, so it can share a Node with `gateway` and `vpn`. Move or remove it with [`node:role:relocate`](/cli/node/role-relocate) and `node:role:remove` (see [Remove a dead websocket Node](/reference/websocket-apps#remove-a-dead-websocket-node)).

Common failure modes:

- **Composer fails on Ubuntu 26.04:** Requires `php-curl` and `php-xml` (installed by the role baseline).
- **Agents emit no events:** Reverb apps carrying agent traffic must set `accept_client_events_from` to `members` ([Node agent channels](/reference/events#node-agent-channels)).
- **Gateway reports disconnected:** Reverb reports `serving` every 5 seconds; the Gateway expires stale reports after 60 seconds (15 seconds for app operations) and clears confirmation on reboot.
- **Converge refuses or rollback fails:** Preflight refuses Nodes missing a bindable Caddy listen address without changing state. Activation failures require forward recovery; a failed rollback returns `websocket.rollback_failed`.

Override defaults in Gateway `.env` with `ORBIT_WEBSOCKET_REPOSITORY`, `ORBIT_WEBSOCKET_INSTALL_PATH`, and `ORBIT_WEBSOCKET_PORT` (the pinned server ref comes from the Gateway release).

## Limits

One `websocket` role runs one Reverb server serving multiple [Reverb apps](/reference/websocket-apps). Package upgrades still require an announced reconnect window.

## Verification

Run these checks from a peer trusting the Orbit CA:

```bash
orbit realtime:show
orbit doctor --node=<node-id> --family=role
getent ahostsv4 reverb.orbit
curl -i -X POST https://reverb.orbit/apps/<app-id>/events
```

`orbit realtime:show` reports `configured` and `wss://reverb.orbit`, `getent` resolves to the role Node's WireGuard IP, `systemctl is-active orbit-websocket` returns `active`, and the unauthenticated `POST` returns `401` (`Authentication signature invalid`).
