# JSON Renderer: `orbit app:prune`

[Back to technical contract](1_app-prune.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

This file owns the JSON output contract for `app:prune`.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "target": {
        "app": "my-app",
        "app_instance": "my-app.development",
        "serving_node": "app-1"
      },
      "stale_workspaces": [
        {
          "name": "feature-docs",
          "removed": true
        },
        {
          "name": "stale-experiment",
          "removed": true
        }
      ],
      "dry_run": false
    },
    "meta": []
  }
}
```

`app:prune` returns a command-specific `target` identity instead of pretending
that a logical app owns placement. Callers that need canonical app or instance
entities should run `app:show` against the returned logical slug.

### Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `target.app` | string | Logical app identity slug. |
| `target.app_instance` | string | Selected dotted instance selector. |
| `target.serving_node` | string | Selected instance's serving node. |
| `stale_workspaces[]` | array | Workspaces owned by the selected instance and absent from all of its effective agent IDE sources. |
| `stale_workspaces[].name` | string | Workspace identity slug. |
| `stale_workspaces[].removed` | boolean | `true` when the workspace was actually removed during this run; `false` for dry runs or when removal failed and surfaced under `success.meta.warnings[]`. |
| `dry_run` | boolean | `true` when `--dry-run` was passed and no removals were attempted. |
| `meta.warnings[]` | array | Structured non-fatal failures from individual workspace removals. Each entry carries `code`, `family`, `message`, and `next_command`. Omitted when nothing failed. |

### Partial Failure (Cleanup Failure)

If one workspace removal fails, that entry's `removed` is `false` and the
failure is captured in `success.meta.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`.

```json
{
  "success": {
    "data": {
      "target": {
        "app": "my-app",
        "app_instance": "my-app.development",
        "serving_node": "app-1"
      },
      "stale_workspaces": [
        {
          "name": "feature-docs",
          "removed": false
        }
      ],
      "dry_run": false
    },
    "meta": {
      "warnings": [
        {
          "code": "workspace.remove_failed",
          "family": "workspace",
          "message": "Failed to remove workspace 'feature-docs': Permission denied.",
          "next_command": "workspace:remove feature-docs --app=my-app.development --force"
        }
      ]
    }
  }
}
```

## Error Envelope

```json
{
  "error": {
    "code": "app.no_agent_ide_adapter",
    "message": "No effective agent IDE source is configured for app instance 'my-app.development'.",
    "meta": {
      "app_instance": "my-app.development",
      "serving_node": "app-1"
    }
  }
}
```

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'app:prune' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "app:prune",
      "serving_node": "app-1"
    }
  }
}
```

| Field | Values |
| --- | --- |
| `error.code` | `validation_failed`, `app_instance.not_found`, `authorization_failed`, `workspace.unsupported_for_production`, `app.no_agent_ide_adapter`, `app.agent_ide_query_failed` |

`success.meta.warnings[].code` carries one `app:prune`-owned handoff code plus
the passthrough warning codes that `RemoveWorkspace` actually emits for each
stale workspace `app:prune` processes:

| Code | Family | Owner | Meaning |
| --- | --- | --- | --- |
| `workspace.remove_failed` | `workspace` | `app:prune` | The inner `workspace:remove` action raised an unhandled exception while removing a stale workspace. `next_command` points at `workspace:remove <name> --app=<app.instance> --force` to retry the single failed entry. |
| `workspace.artifact_extra` | `workspace` | `workspace:remove` passthrough | A workspace artifact (worktree) could not be removed and remains on the node. `next_command` is `doctor --family=workspace --restore`. |
| `workspace.teardown_step_failed` | `workspace` | `workspace:remove` passthrough | A workspace teardown step exited non-zero during cleanup. The warning carries the offending `step_id` and `exit_code` alongside the standard fields. `next_command` is `doctor --family=workspace --restore`. |
| `process.runtime_unit_extra` | `process` | `workspace:remove` passthrough | An inherited runtime unit could not be stopped or removed. `next_command` is `doctor --family=process --restore`. |

The `error.code` and warning `code` values listed here are exhaustive for
`app:prune`. Add a new value to this renderer contract before implementing
another JSON failure or warning code. `workspace.remove_failed` and
`workspace.teardown_step_failed` are registered as command handoffs in
`config/librarian-command-docs/warning_codes.php`; the two doctor-family
passthrough codes (`workspace.artifact_extra`, `process.runtime_unit_extra`)
are documented in `workspace-doctor.md` and `process-doctor.md` respectively.
