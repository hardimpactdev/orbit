# Native Fleet recipe

`operation-fleet-recipe-direct` owns one Node visit. All steps run on 209. Official SSH uses the admitted address, account and stored host keys. The Gateway keeps desired-only plan/state, maintenance order, admission, a generic Node target hold and terminal projection.

The DAG separates inspection, the signed package transaction, browser, JavaScript, PHP, service restart planning, restarts, dependency settling, health, observer files, Caddy, peer/private DNS, residue, PHP runtime, tmpfiles, CLI and delivery verification. Native dependencies stop later required effects. Native resume retains completed actions. Tolerated residue failures retain their skipped artifact receipt.

The package transaction keeps sources, indexes, exact installation, provider retirement, preferences and receipts together. The shipped recipe policy is also the existing Nodes JavaScript policy; its parent supplies the script through the manifest context. Node role and recipe callers use the shared native PHP runtime, private DNS and Route residue workflows. There is no second recipe policy or per-Node Fleet executor.

`recipe.py` is the named open rule 22 gap for the signed package transaction, Incus drain and repacked PHP build. Its remaining rollback and ownership logic is part of that pending conversion. The CLI step runs the shared native `node-cli-install` child; no CLI script ships. Native SSH exposes service actions separately. The existing PHP and updater tool locks are explicit `flock` commands, not new workflow or admission locks.

The Gateway captures the agent key's public verifier digest and the desired public files at admission. A bounded `sha256sum --check --strict` command checks the installed binary, recorded key and files. No observer secret is copied into the execution vault. No worker enrollment, credential rotation or worker retirement is part of a recipe visit.

Source checks use the frozen official runtime in an isolated local repository. SSH fixtures never contact Nodes. Live publication, grants and any 12-Node rollout remain separate owner actions.

Private DNS uses the shared node-private-dns workflow. It writes files through official cfgmgmt, validates the configuration before activation, and checks the loaded catalog. A failure stops delivery without a rollback chain. PHP runtime and Route residue use their existing native workflows; tmpfiles is one official file resource. The replaced PHP and DNS scripts, adapters and mirrored tests are deleted.

Role files now use official `file` resources. The observer key check is one bounded `sha256sum` argv and native assert; checkout cleanup is one bounded `find` argv. Their three shipped scripts and manifest entries are deleted.
