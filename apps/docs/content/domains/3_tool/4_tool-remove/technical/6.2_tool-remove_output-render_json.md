# JSON Renderer: `orbit tool:remove`

[Back to `tool-remove` technical contract.](1_tool-remove.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "tool": {
        "name": "composer",
        "node": "app-1",
        "expected_state": "absent",
        "observed_state": null,
        "version": null,
        "observed_version": null,
        "managed": false,
        "endpoints": [],
        "routes_removed": 1
      }
    },
    "meta": []
  }
}
```

Command-specific result data uses the canonical tool entity from
[`README.md`](../../README.md#tool-json-entity), plus optional remove-outcome
fields when present:

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.tool.routes_removed` | integer | Count of tool-owned proxy routes removed for the target node after successful cleanup. |
| `success.data.tool.legacy_runtime_cleanup` | boolean | Present and `true` only for removal-only residual teardown paths. The closed residual slug set is listed on the public `tool:remove` contract. |
| `success.data.tool.stale_record` | boolean | Present and `true` when the removal cleaned residual registry/runtime facts without a live managed product install. |
| `success.data.tool.tool_row_removed` | boolean | Present on residual teardown when the response reports whether a `NodeTool` row was deleted. Residual slugs are listed on the public `tool:remove` contract. |
| `success.data.tool.stale_routes_removed` | integer | Present on some stale-intent removals as the count of stale tool-owned routes removed. |
| `success.data.process.warnings` / `success.data.warnings` | array | Optional process runtime-unit warnings when `relatedProcess()` teardown ran first. |

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Required input is missing or invalid.",
    "meta": {
      "field": "tool"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `tool.not_found`, `tool.unsupported_action`, `tool.remote_action_failed` | Stable command failure code. |
| `error.message` | string | Human-readable failure summary. |
| `error.meta` | object | Field, target, caller, or remote-action context for automation. |

### Missing destructive consent

JSON mode returns this failure when `--force` is missing. Renderer selection
never grants destructive consent.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to remove this tool.",
    "meta": {
      "field": "force",
      "reason": "destructive_consent_required"
    }
  }
}
```

### Missing target

```json
{
  "error": {
    "code": "validation_failed",
    "message": "A node or instance target is required. Provide --node, --instance, configure node:default, or select a target interactively.",
    "meta": {
      "fields": [
        "target"
      ]
    }
  }
}
```
