# Upgrade an existing native worker

`node-worker-upgrade` upgrades only an existing selected persistent worker. Each host action is a placed `command/shell` step. The full public input includes the Node and configured user, the approved official artifact manifest, the expected current binary and unit digests, and the existing units to restart. The caller supplies the canonical approved installer manifest; this workflow owns no second pin. Its download repository is fixed to `swamp-club/swamp`. It accepts no artifact URL, credential value, vault reference, enrollment request, or selection change.

Read-only preflight verifies the root-owned Node configuration, effective account, exact worker cgroup, enabled canonical unit, binary inode and digest, credential-file custody without opening their contents, and available memory. Nodes1 and18 refuse. On209, the input must include every installed proxy unit as well as the persistent unit; no new proxy unit is installed. Every listed unit must already run as the configured user from its canonical root-owned definition, without drop-ins.

Native dependencies separate staging, download, artifact verification, executable mode, atomic publication, cleanup, and each nonblocking restart. Guards skip mutation when the desired digest is already installed. Publication rechecks the expected current binary and unit digests. A changed binary uses a new inode. The running old worker is preserved until the declared restart step. Existing unit definitions, public CA files, selection, credentials and operator pause state are preserved. No full Node converge, agent action, issuer, Gateway callback, compatibility fallback or manual binary-copy route is involved.

The terminal public JSON reports verified installation and accepted restart requests. It does not claim reconnection. Use native history and resume after a failure; do not launch a second run because a self-restarting worker's reply is late. After an authorized run, the owner independently verifies the installed and running digest and exact worker roster.

This is an administrative workflow with no Gateway Operation or StartSwampRun integration, so no Gateway result helper is needed.
