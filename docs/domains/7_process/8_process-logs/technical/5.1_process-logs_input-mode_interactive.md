# `process:logs` Interactive Input Mode

[Back to `process:logs` technical contract.](1_process-logs.md)

This page describes how interactive input mode resolves `process:logs` input.

**Input mode:** Interactive.

## Selection

Use this input mode only when the process is attached to a TTY and `--json` is not present.

## Prompt Behavior

Prompt for missing required input in this order:

| Field | Prompt primitive | Notes |
| --- | --- | --- |
| `app` | Datatable | Show apps the caller is authorized to read when app context is absent or ambiguous. |
| `name` | Datatable | Select from existing processes visible for the resolved app or across apps. If no process exists, fail before prompting for an open value. |

Do not prompt for `lines` or `follow`; those remain explicit options with documented defaults.
`--workspace` is an explicit filter. If a supplied workspace name is ambiguous,
the command fails and asks the operator to pass `--app`.
