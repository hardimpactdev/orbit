Bring the branch of the pull request and the default branch into the workspace of an external task group. A task VM holds no GitHub credential, so it cannot fetch. When origin moved, because main was merged into the branch or the owner pushed a correction, the author syncs, then merges or rebases, and the push fast-forwards.

There is no `orbit` command yet. Use the API or the MCP tool `task-sync`.

```bash
curl -X POST "$GATEWAY/api/v1/task-groups/42/sync" \
  -H "Idempotency-Key: sync-42-1"
```

The route needs a Node with an access grant to the Gateway and a required `Idempotency-Key`. It takes no body. The reply is `202` with the operation. Follow it with `operation:show` until it ends. A parked VM is woken by the admission, which answers `409 tasks.vm_resuming`; repeat the call once the VM runs.

The fetch writes `refs/remotes/origin/<default branch>` and `refs/remotes/origin/task-42` in the workspace. It does not touch HEAD, the working tree or the local branches.

## Errors

| Code | When |
| --- | --- |
| `tasks.group_closed`, `tasks.no_workspace`, `operation.target_busy` | the group has ended, has no workspace, or another operation runs on it |
| `tasks.vm_resuming` | the task VM was parked; its resume is admitted |
| `tasks.sync_failed` | a step of the run failed, such as the clone of a branch that does not exist on origin |
