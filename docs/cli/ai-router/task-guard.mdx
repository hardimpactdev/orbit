```bash
orbit ai-router:task-guard [--remove] [--yes] [--idempotency-key=KEY] [--json]
```

| Option | Required | Meaning |
| --- | --- | --- |
| `--remove` | no | Take the guard, its keys and its UFW rules off the router's Node. |
| `--yes` | with `--remove`, in noninteractive and JSON modes | Confirm the removal without a prompt. |
| `--idempotency-key` | no | Reuse a key to retry the same start. |

The command starts `ai_router.task_guard` and follows the run to its end. The run applies the [task VM guard](/reference/ai-router#task-vm-guard): its Caddy, its keys and its rules. The Gateway's API route is `POST /api/v1/ai-router/task-guard`, with `{"remove": true}` for a removal. The MCP tool of the same route does the same.

Each release applies the guard again by itself when its config changed. See [The guard follows its config](/reference/ai-router#the-guard-follows-its-config). Run this command after the first setup, after a key changes, or to take the guard off before a teardown.

A removal cuts every task VM and container off from the models until the guard is applied again. In a terminal the command asks first. Without `--yes`, a noninteractive or JSON removal fails with `input.confirmation_required` and sends nothing.

## How it works

The Gateway renders the guard from its sources and records the intent with vault copies of both keys. Swamp applies it on the router's Node and proves that the guard refuses a source outside its range.

## Errors

| Code | Meaning |
| --- | --- |
| `ai_router.disabled` | The ai-router is not set up. |
| `operation.target_busy` | Another guard or forwarder run holds the guard. Run the command again when it ends. |
| `input.confirmation_required` | `--remove` ran without `--yes` where the command cannot ask. |
| `extension.disabled` | The `ai-router` extension is disabled at the Gateway. |
