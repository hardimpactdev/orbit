```bash
orbit proof:run <commit> [--all] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `commit` | yes | Full 40 or 64 character lowercase commit SHA. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--all` | off | Run every case, not only the cases that the commit selects. |
| `--idempotency-key=KEY` | generated | Retry the same start with a permanent key. See [Start keys](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Print the final result as JSON, with the verdict of each case. |

```bash
orbit proof:run 0123456789abcdef0123456789abcdef01234567
```

In a terminal, an omitted commit is asked for with a text prompt. A noninteractive or `--json` call that omits it is refused with `proof.commit_invalid`, and so is a value that is not a full lowercase SHA. A refused call sends no request.

The command takes the commit and nothing else. The calling Node needs an access grant to the Gateway Node. Continuous integration calls it for every change to command code; see [the proof CI](/reference/feature-flow#the-proof-ci).

Built so far: the trust check, the case selection, the run in a task VM and the verdict of each case. The CI job `proof-run` exists but is report-only until a run passes end to end. Not built yet: the receipt store.

## Which commits Orbit proves

Orbit proves only code that it can trust. The commit must be the head of a branch of the Orbit repository. A commit from a pull request from elsewhere is accepted only when it is the head of that open pull request, the pull request carries the label `run-proofs`, and a maintainer approved exactly that commit. A new push needs a new approval. Orbit fetches the commit itself, so a caller cannot change what runs.

## Which cases run

Orbit lists the files that differ between the commit and its merge base with `main`, and maps each path to commands with the selection list in the commit. The runner runs the cases file `swamp/proof/<family>/<command>.cases.yaml` of each of those commands. `--all` runs every case. A change to the selection list, or a file list that GitHub returns incomplete, also runs every case. [Choose the cases](/reference/feature-flow#choose-the-cases) holds the mapping rule.

When only paths that need no proof changed, such as documentation and charts, the command succeeds with `Skipped — nothing to prove (proof.nothing_to_prove)`. It starts nothing. A path that matches no line of the selection list is refused with `proof.path_unmapped`, so a new kind of file never passes unproven by accident. Paths that are marked as having no case yet, and commands without a cases file, are listed as uncovered in the result and do not fail the run.

## The run

Orbit starts one run for each selected command, all at once, and each run has a task VM of its own. A command that fails does not stop the others. For each run Orbit creates a task group on the Orbit Project and admits the whole run as the operation `proof.command`. Orbit's own Swamp then runs the workflow `operation-proof-run` for it, with three children in turn:

1. The task provision, `operation-task-provision`, the same one every task uses. The workspace starts exactly at the commit that you prove. The VM is a regular task VM, so it carries the Pi token and the model key of every task VM. It also gets the proof Swamp Club key that the nested fleet needs, through the same protected delivery as the `swamp-proof` Project; no other task of the Orbit Project gets it. If no host has room, the admission is refused with `tasks.capacity_unavailable` and no run starts.
2. The cases of the command, `proof-fleet-verify`, on Node 209, which reaches the VM over SSH like every other step. The runner reads the cases file of the command, `swamp/proof/<family>/<command>.cases.yaml`, at the tested commit and runs its cases with the CLI built from the commit.
3. The destruction of the VM, `operation-task-cancel`, whatever the cases did.

Not built: the nested test fleet of the VM and its memory snapshot `base`. The old reset was removed, and Orbit's own Swamp will build the fleet inside the provision.

The cases run in batches. Each batch applies its declared start state first. Inside a batch the cases run one at a time. Each case asserts the promised effect, the recorded state and the Node state, on its own resources, and undoes nothing. Not built: the restore of `base` before each batch and after a case that did not pass; the old restore was removed. A batch setup that fails stops the run: the cases that did not run end `unrun` with cause `infrastructure`, and the verdicts already reached stay. Orbit retries nothing. [Verification cases](/reference/verification-cases#the-run) describes the workflow.

Each case has its own timeout, 180 seconds unless the case sets another. The operation `proof.command` has a budget of 60 minutes, and the `proof.run` that you follow has 65 minutes.

No step of a run calls the Gateway. Each run is recorded once, from its terminal event: its verdicts, its VM and the end of its group. The `proof.run` that you follow closes when the last run has ended, and it passes only when every run passed.

## The execution switch

`proof:run` works in two stages. Admission checks the commit and selects the cases. Execution creates the group and runs them. Execution is off by default: the Gateway setting `proof.execution` (`ORBIT_PROOF_RUN_EXECUTION`) is `false`. While it is off, a commit that selects cases is refused with `proof.execution_disabled`, and the error details name the selected cases and the uncovered paths. The command then works as a dry run: it creates no group and starts nothing. A commit with nothing to prove still succeeds, and every refusal of admission still applies.

## Verdicts

Each selected case ends `passed`, `failed` or `unrun`. A case that exceeds the budget is `failed`. A case is `unrun` when its setup could not start or the run stopped before it. Neither `failed` nor `unrun` counts as a pass. If the fleet never becomes ready, every selected case is `unrun`.

The result names the commit, each case with its command, verdict and duration, and the uncovered paths. The `program` of a case is the cases file and the case id, `swamp/proof/firewall/allow.cases.yaml#new-restricted-allow`; a `failed` or `unrun` case also carries its cause and the failed checks. The VM is destroyed after the run, so the evidence lasts only as long as a receipt store is not built; the verdicts stay in the result.

| Outcome | Exit status |
| --- | --- |
| Every selected case passed, or nothing needed a proof. | `0` |
| A selected case failed or did not run. | Nonzero. The command names each such case and the receipt link. |
| Orbit refused the request. | Nonzero, with the one-line error envelope. |
| You pressed Ctrl-C. | `130`. |
| The process received SIGTERM. | `143`. |

Ctrl-C, or `operation:cancel` on the proof, ends every run at once and cancels their groups, which destroys the VMs. A case that was running stops with its VM. Each group ends when its run ends.

## After the run

The run destroys its VM after success and after failure, and Orbit records the end of the group from that step. If the destroy step did not run or failed, because the run was cancelled, timed out or failed early, Orbit cancels the group the normal way, which destroys the VM. The verdicts stay as they are. If that cancel fails, the group stays for another `tasks:cancel`.

A repeat starts a new run, because a proof checks the commit as it is now. The same `--idempotency-key` returns the original run instead of starting another.

## Errors

| Code | Meaning |
| --- | --- |
| `proof.commit_invalid` | The commit is missing or is not a full lowercase SHA, and the CLI cannot prompt. |
| `proof.commit_not_found` | The Orbit repository has no such commit. |
| `proof.commit_untrusted` | The commit is not the head of a branch of the Orbit repository, nor the head of an open pull request with the label `run-proofs` and a maintainer's approval of exactly that commit. |
| `proof.path_unmapped` | A changed path matches no line of the selection list. The details name the path. |
| `proof.cases_failed` | A selected case failed or did not run. The result holds each verdict. |
| `proof.run_failed` | The VM or the test fleet of a run did not become ready, or its cases printed no verdict. Every selected case of that command is `unrun`. |
| `tasks.capacity_unavailable` | No host with a usable nested fleet seed has room for a VM for each selected command. No run starts. A host whose seed holds no ready copies of the current format is skipped, even with free slots. |
| `proof.execution_disabled` | Cases are selected, and proof execution is switched off. The details hold the commit, the selected cases and the uncovered paths. |
| `proof.selection_invalid` | The selection list of the commit is malformed. The details name the line. |
| `proof.github_unavailable` | GitHub could not be read, so the commit or its cases cannot be checked. Run the command again. |
| `proof.swamp_unavailable` | No active Swamp Node exists to run the proof. |
| `node_access.required` | The calling Node has no access grant to the Gateway Node. |
| `extension.disabled` | The tasks extension is off. |
