# One package per update group

The manual `website-package` workflow accepts one existing external website group, one manager (`composer` or `js`), package, exact stable version, purpose (`major` or `security`) and advisory IDs with their source URLs from detection. It never creates a live group by itself. Each group has exactly one child. Start only after Nick authorizes a live run.

Admission records the immutable target in Swamp. The group must be an unused backlog group for Project 20. Before admitting a new package, the previous package run must have completed after its PR merged (or completed unchanged). A failed/parked run blocks the sequence. To abandon it, use the existing cancellation and cleanup path, then explicitly acknowledge its factory assistance gate to reach terminal `failed`; only a clean cancelled group with destroyed VM and ended children releases the sequence. Safety or operator assistance still blocks admission. Admission and ticks reuse the behavior lock, keyed jobs and official `@swamp/software-factory`; there is no queue or new engine. Provision obtains a new task VM from the Project's current main, after the previous group's completion. Reuse of a VM or a pre-provisioned group is refused.

`provision → package script → handoff check → publish → wait for merge → complete`

The tracked script receives only literal arguments: `package <composer|js> <package> <x.y.z> <major|security> [advisory-id ...]`. A failed script or local check gets one repair turn, a fresh run of the same package script, then one recheck. That script rerun independently verifies the security audit after repair; a ready agent receipt alone cannot prove a fix. Cumulative changed-tree evidence survives this rerun. A blocked turn, second red check, unknown command result or infrastructure failure parks. The repair must finish that exact package command, preserve other direct ranges and policy, and never add another package upgrade. Publication uses the passed check. No-change completion remains available. Board assistance is separate from factory consent.

Detection runs the tracked script's `detect` mode in a task VM through the existing script operation. It combines Composer major-only outdated, Vite+ outdated JSON and both audit results into package candidates. Detection is evidence only: choose an explicit version before admission. A finding is not permission to bypass an advisory or age policy. Truncated/invalid output cannot select a target. No report, proposal or dependency-specific records are added to Orbit.

Security targets require advisory IDs and source URLs, included in the repair prompt and PR. The website script allows only its documented package-specific security age exception and verifies that the selected advisories no longer affect that package. First intended acceptance is `livewire/livewire` for `PKSA-xhv3-nr94-h8db` and `PKSA-bgw4-5zmg-2njg`; obtain a fixed version from current advisory/registry evidence before starting. No fixed version is guessed here. Slice-1 group 2093 proved provision, script, one repair and parking; it did not prove a green publication or ADR 0229 interruption recovery. Routine group 2093 belongs to Nick and must not be touched. The routine rerun is deferred to 2026-10-30 and still needs Nick's live-run authorization.

Fixture acceptance covers two packages in sequence, refusal before the first merges/completes, fresh provision identity, immutable single-package args, lost replies/restarts, green and one-repair paths, the repair cap, safety/assistance preservation and no publication before passed checks. Live acceptance is separate: merge the script/workflow PRs, apply only the reviewed Swamp commit, then authorize one Livewire group, inspect script/audit/check evidence and return its exact PR head without merging. No service restart or live group is part of implementation.

Rollback: stop ticking the explicit item; reconcile any active operation before cancellation or cleanup. Retain Swamp target and receipt state. Revert the additive workflow/client and script modes only after no package operation is active. Never resolve operator/safety assistance to make rollback proceed.

Run the manual workflow with a local JSON input file (use real versions/URLs from current detection, not fixture versions):

```json
{"workItem":"tg-<new-group>","manager":"composer","package":"livewire/livewire","version":"<fixed-x.y.z>","purpose":"security","advisories":["<current-PKSA-id>"],"advisoryUrls":["https://github.com/advisories/<current-GHSA-id>"]}
```

`swamp workflow run website-package --input-file <input.json>` admits/starts the explicit item and performs one tick. Repeat the same command to reconcile it, or tick `orbit-driver-package` for that same item. Return the published PR and exact head to Nick and stop at human review; no merge action exists here. Never use the fixture's synthetic versions as a live target.

Local validation: `~/.swamp/deno/deno test --allow-all tests/package_stage_test.ts tests/package_routing_test.ts tests/routine_stage_test.ts tests/routine_routing_test.ts tests/gateway_stage_test.ts tests/group_assistance_test.ts tests/driver_test.ts`. These use disposable repos and a loopback fixture Gateway. Never reset an admitted package run to reuse its group; keep target/receipt state and use a new group after operator reconciliation.
