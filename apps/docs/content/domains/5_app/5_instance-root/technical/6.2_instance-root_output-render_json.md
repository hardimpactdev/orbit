# JSON Renderer: `orbit instance:root`

[Back to technical contract](1_instance-root.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces
non-interactive behavior even when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

`changed=false` is a documented success path. `instance:root` is idempotent and
re-applies on every successful run, so calling it with the same
root as a "redo apply" recovery path is safe.
`artifacts_reenacted=false` reports that re-application found no observable
node change; `artifacts_reenacted=true` would still be a valid converged
re-run if application had to repair drift.

### Success with Drift Warning

If the configuration is written but application fails, the command still returns a
`success` envelope (because the configuration change was persisted), and the drift
is reported as a structured warning under `success.meta.warnings[]`.

### Fields

- `app`: The canonical app JSON entity defined in
  [`5_app/README.md`](../../README.md#app-json-entity). It is unchanged by this
  command.
- `instance`: The canonical selected instance entity. Its
  `driver_config.root` is the current document root after the run.
- `result.hostname`: The selected instance hostname.
- `result.changed`: `true` when this run mutated gateway configuration; `false` when
  the supplied root equalled the current configuration and the run was a converged
  no-op.
- `meta.instance`: The selected dotted instance selector.
- `meta.serving_node`: The selected instance's serving-node slug.
- `meta.artifacts_reenacted`: `true` when re-application found observable
  changes on the node; `false` when re-application completed as a clean
  idempotent no-op. Both values are valid success outcomes.
- `meta.warnings[]`: Structured non-fatal drift and retry handoffs. Each
  entry carries `code`, `family`, `message`, and `next_command`.

## Error Envelope

### Example: Instance Not Found

```json
{
  "error": {
    "code": "instance.not_found",
    "message": "Instance 'docs.missing' not found.",
    "meta": {
      "instance": "docs.missing"
    }
  }
}
```

### Example: Invalid Root

```json
{
  "error": {
    "code": "instance.invalid_root",
    "message": "The root path resolves outside the application path.",
    "meta": {
      "field": "root",
      "root": "../outside",
      "resolved_path": "/srv/orbit/outside",
      "instance": "my-app.development",
      "instance_path": "/srv/orbit/apps/my-app"
    }
  }
}
```

`instance.invalid_root` is gateway-side, lexical-only validation against the selected
`instance_path`. Filesystem-level reality (a symlink that escapes the instance path,
or a missing directory on the node) is not detected here; it surfaces as
`instance.root_outside_path` or `instance.root_missing` from `doctor --family=instance`
per [`instance-doctor.md`](../../instance-doctor.md).

### Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation. Ambiguous bare selection uses `error.meta.reason=instance_required`; `error.meta.field` names other offending input. |
| `instance.invalid_root` | `root` failed gateway-side string validation against the selected instance path. Metadata includes `field`, `root`, `resolved_path`, `instance`, and `instance_path`. |
| `instance.not_found` | The specified concrete instance could not be resolved. |
| `authorization_failed` | The caller lacks `instance:root` on the selected instance's serving node. |

### Common Warning Codes

Non-fatal drift is reported in `success.meta.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`. Codes reuse the vocabulary of
the family that owns the drift.

| Code | Family | Meaning |
| --- | --- | --- |
| `process.runtime_unit_mismatch` | `process` | The instance's concrete runtime container could not be re-applied to match its process-backed runtime definition. |
| `process.runtime_unit_missing` | `process` | The instance's concrete runtime container could not be rendered or started while applying. |
| `instance.runtime_config_mismatch` | `instance` | Managed app runtime configuration could not be re-applied to match gateway configuration. |
| `instance.runtime_config_missing` | `instance` | Managed app runtime configuration could not be installed while applying. |

Process warnings use `doctor --family=process --restore`. Managed-configuration
warnings use `doctor --family=instance --instance=<app.instance> --restore`.

## Enum and identifier values

| Field | Values |
| --- | --- |
| `result.changed` | `true`, `false` |
| `meta.artifacts_reenacted` | `true`, `false` |
| `error.code` | `validation_failed`, `instance.invalid_root`, `instance.not_found`, `authorization_failed` |
| Warning `code` | `process.runtime_unit_mismatch`, `process.runtime_unit_missing`, `instance.runtime_config_mismatch`, `instance.runtime_config_missing` |

The `error.code` and warning `code` values listed here are exhaustive for
`instance:root`. Add a new value to this renderer contract before implementing
another JSON failure or warning code.
