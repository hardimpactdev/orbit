# JSON Renderer: `orbit tool:remove`

[Back to `tool-remove` technical contract.](1_tool-remove.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

Gateway success wraps the removal outcome under `success.data.tool` (not flat
`success.data`). Canonical tool entity fields are not returned.

This page documents public CLI output from `orbit tool:remove --json`. Empty
`success.meta` is an array `[]` on that surface: the gateway controller may
emit `"meta":{}` via PHP `(object) []`, but `GatewayApiClient` decodes JSON
associatively and `EmitsCanonicalEnvelopes::renderSuccess` re-encodes through
`JsonEnvelope::success`, so the CLI prints `"meta":[]`. Do not document raw
gateway wire shape here.

```json
{
  "success": {
    "data": {
      "tool": {
        "name": "composer",
        "node": "app-1",
        "routes_removed": 1
      }
    },
    "meta": []
  }
}
```

Removal success is a compact outcome payload under `success.data.tool`, not a
full tool entity. It always includes `name` and `node`. Optional outcome fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.tool.name` | string | Catalog tool name that was removed. |
| `success.data.tool.node` | string | Target node that owned the install. |
| `success.data.tool.routes_removed` | integer | Count of tool-owned proxy routes removed after successful cleanup. |
| `success.data.tool.process` | object | Present when a related process teardown ran first. |
| `success.data.tool.process.warnings` | array | Optional process runtime-unit warnings when related process teardown ran first. |
| `success.data.tool.warnings` | array | Optional tool-level warnings when the remover reports them. |
| `success.data.tool.stale_record` | boolean | Present when residual registry/runtime facts were cleaned without a live managed install. |
| `success.data.tool.tool_row_removed` | boolean | Present when the response reports whether a `NodeTool` row was deleted. |
| `success.data.tool.stale_routes_removed` | integer | Present on some residual removals as the count of stale tool-owned routes removed. |

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Required input is missing or invalid.",
    "meta": {
      "field": "tool"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `tool.not_found`, `tool.unsupported_action`, `tool.remote_action_failed` | Stable command failure code. |
| `error.message` | string | Human-readable failure summary. |
| `error.meta` | object | Field, target, caller, or remote-action context for automation. |

### Destructive consent in JSON mode

`--json` supplies destructive consent (`destructive_consent_source=json`), so a
missing-`--force` consent failure is unreachable in JSON mode. Interactive
decline uses `reason=cancelled`; non-interactive human mode without `--force`
or `--json` uses `reason=destructive_consent_required`. Neither path applies to
the JSON renderer.

### Missing target

```json
{
  "error": {
    "code": "validation_failed",
    "message": "A node or instance target is required. Provide --node, --instance, configure node:default, or select a target interactively.",
    "meta": {
      "fields": [
        "target"
      ]
    }
  }
}
```
