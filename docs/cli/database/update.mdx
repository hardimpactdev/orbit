description: "Replace the supplied fields on one connection. The command requires at least one field option and accepts the same field options as `database:create`."
---

```bash
orbit database:update <slug> [options]
```

| Option | Meaning |
| --- | --- |
| `--driver=DRIVER` | `mysql`, `pgsql`, `sqlite`, or `redis`. |
| `--node=NODE` | Node ID or registered name. An empty value, `--node=`, clears the association. |
| `--host=HOST` | Hostname or IP for mysql, pgsql, and redis. |
| `--port=PORT` | TCP port for mysql, pgsql, and redis. |
| `--database=NAME` | Database name for mysql and pgsql, or the numeric database index for redis. |
| `--path=PATH` | Unix absolute sqlite path. |
| `--username=USER` | Username. |
| `--password=SECRET` | Password. |

```bash
orbit database:update app --password=rotated-secret
orbit database:update app --node=
```

Supply at least one field option. A slug alone returns `database.update_required`. Most changes return a succeeded Operation without a Swamp run. Only a changed, non-null database index on a managed Valkey server starts a run to check the live index limit. A connection that Orbit manages on a Database server keeps its identity and credentials: such a change returns `database.server_connection_managed`. On a Valkey server only the index may change.

Updating a record does not rewrite the keys already stored on attached Instances. Run `instance:database:add` again with the same prefix to re-project them, then `env:sync` to install them.

Use `--idempotency-key=KEY` to retry the same native update admission.
