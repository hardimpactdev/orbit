# JSON Renderer: `orbit process:update [name]`

[Back to `process:update` technical contract.](1_process-update.md)

This page describes the JSON-rendered output for `process:update`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces non-interactive input mode.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Success data contains the updated process definition, changed fields, old process name when identity changed, and derived runtime units. Partial post-configuration drift is reported under `success.meta.warnings[]`.

Warning objects contain:

| Field | Meaning |
| --- | --- |
| `apps/gateway/tests/Feature/Http/Api/ProcessUpdateControllerTest.php` | Gateway API validation, authorization, rename uniqueness, runtime cleanup, unsupported rename, and warning envelopes. |
| `apps/gateway/tests/Feature/Http/Api/ProcessUpdateControllerTest.php` | Gateway API validation, authorization, rename uniqueness, runtime cleanup, unsupported rename, and warning envelopes. |
| `apps/gateway/tests/Feature/Http/Api/ProcessUpdateControllerTest.php` | Gateway API validation, authorization, rename uniqueness, runtime cleanup, unsupported rename, and warning envelopes. |
| `code` | Singular product warning code, such as `process.runtime_unit_missing`, with the owning family recorded separately. |
| `family` | State family that owns the warning. |
| `message` | Human-readable warning summary. |
| `next_command` | Suggested command to inspect or repair the warning. |

## Success Example

```json
{
  "success": {
    "data": {
      "process": {
        "name": "app-mysql",
        "command": "docker run mysql:8.4",
        "restart_policy": "never",
        "crash_notification": "none",
        "runtime": "docker"
      },
      "old_name": "mysql",
      "changed": [
        "name"
      ],
      "runtime_units": [
        {
          "name": "orbit_node_database_1_app_mysql",
          "context": "node"
        }
      ]
    },
    "meta": {
      "warnings": []
    }
  }
}
```

## Error Example

```json
{
  "error": {
    "code": "validation_failed",
    "message": "At least one editable field is required.",
    "meta": {
      "field": "editable_fields"
    }
  }
}
```

## Authorization Error

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to update processes on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "process:edit",
      "serving_node": "app-1"
    }
  }
}
```

## Error Code Vocabulary

- `validation_failed`: missing `name` or node/app/workspace context, invalid new process name, invalid enum value (`restart_policy`, `crash_notification`, `runtime`), empty `command`, invalid runtime scope, or no editable fields supplied.
- `authorization_failed`: caller lacks process-configuration mutation permission on the resolved owning node.
- `process.not_found`: the named process does not exist for the resolved owner scope.
- `process.name_conflict`: `--name` matches another process in the resolved owner scope.
- `process.rename_unsupported`: the selected runtime/backend cannot safely replace derived unit identity.
- `gateway_unavailable`: the CLI cannot reach the gateway API before configuration is changed.
