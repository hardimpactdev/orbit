# Interactive Input Mode: `orbit deploy:step-remove`

[Back to `deploy:step-remove` technical contract.](1_deploy-step-remove.md)

**Input mode:** Interactive.

## Mode Selection

This contract applies only when the process is attached to a TTY and `--json`
is not present.

## Prompt Flow

Prompts render after gateway reachability is known and before any gateway
policy mutation.

| Prompt ID | Primitive | Rendered when | Validation |
| --- | --- | --- | --- |
| `deploy.step_remove.app` | `search` | `app` argument omitted. | Visible production app-instance selector the caller may manage. |
| `deploy.step_remove.step` | `search` | `step` argument omitted. | Existing step for the selected app instance. |
| `deploy.step_remove.confirm` | `confirm` | Always after the step is resolved unless `--force` is present. | Explicit destructive consent. |

The confirmation text names the app, step id, title, command, and history
preservation boundary.

Rejected confirmation fails before side effects with
`error.code=validation_failed`, `error.meta.field=force`, and
`error.meta.reason=destructive_consent_required`.
