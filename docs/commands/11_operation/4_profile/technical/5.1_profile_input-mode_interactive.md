# Interactive Input Mode: `orbit profile [target]`

[Back to `profile` technical contract.](1_profile.md)

This page describes how interactive input mode resolves `profile` input.

**Input mode:** Interactive.

## Selection

Use interactive input mode when the command runs in a TTY and `--json` is not
present. `--json` always selects the
[non-interactive input mode](5.2_profile_input-mode_non-interactive.md), even
when the process has a TTY.

## Prompt Contract

| Prompt id | Field | Primitive | Label | Choices / validation |
| --- | --- | --- | --- | --- |
| `profile.app` | `target` | `datatable` | `Select an app to profile` | Visible apps, filtered by `--node` when supplied. Rows include app hostname, node, and repository when known. |
| `profile.uri` | `uri` | `text` | `Request URI` | Non-empty path, normalized to start with `/`. Prompt only when a future profile path explicitly asks for URI input; the current command uses the default unless `--uri` is supplied. |

No prompt is rendered for auth mode. Authenticated profiles require explicit
flags so automation and humans cannot accidentally profile as an application
user.

## Resolution Rules

- If `[target]`, `--app`, or current-directory context resolves an app, do not
  prompt.
- If no app can be resolved and visible apps exist, prompt with `profile.app`.
- Apply `--node` before rendering `profile.app`.
- If no visible app exists, fail with a clear message instead of rendering an
  empty prompt.
- If target validation fails after a prompt, show the validation message and
  return to app selection when the user can choose a different app.
- Prompt abort exits with the standard command failure status and no HTTP
  request.

## Failure Output

Interactive validation failures are rendered by the human renderer. The prompt
flow must not render JSON envelopes.
