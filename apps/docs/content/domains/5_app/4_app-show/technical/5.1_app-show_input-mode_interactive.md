# Interactive Input Mode: `orbit app:show [app]`

[Back to `app:show` technical contract.](1_app-show.md)

This page describes how interactive input mode resolves `app:show` input before
command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_app-show_input-mode_non-interactive.md`](5.2_app-show_input-mode_non-interactive.md)
even if the process has a TTY.

## Responsibilities

- Read any supplied arguments and options.
- Apply the default resolution chain when `[app]` is missing.
- Prompt for `app` only when the default resolution chain cannot produce a
  target.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.

## Default Resolution

When `[app]` is missing, interactive input mode resolves the target in this
order:

1. **CWD resolution.** Attempt to resolve the app from the current working
   directory context (matching the workspace or app source path of a known app).
2. **Prompt.** If CWD resolution fails, prompt for `app_show.app`.

The prompt primitive is `datatable` with label `Select an app`. Rows are visible
logical apps, with app identity, repository, instance count, and workspace
count columns. The
selected row resolves the existing app name; supplied arguments can still be an
app name or hostname. Name match wins on collision; see
[Input Resolution](1_app-show.md#input-resolution).

## Prompt Mapping

### `app_show.app`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select an app` |
| Source | `[app]` |
| Required | yes (when defaults cannot resolve) |
| Choices | Visible registered apps. |
| Default | none |
| Validation timing | When `[app]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

There is no node-disambiguation prompt. App slugs are globally unique in the
gateway app registry, so a resolved app name maps to exactly one record.

## Failure Semantics

- Missing required input is collected by prompt before side effects, but only
  when the default resolution chain cannot produce a target.
- Invalid supplied field-local input fails before side effects. Prompted values
  are selected from visible registered apps.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If the target app does not exist or is not visible, fail
  before side effects after the name is resolved.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
