```bash
orbit gateway:status [--json]
```

Human output is a detail tree with the profile URL, the Gateway name, status, Orbit version, PHP version, Laravel version, the release it runs from, the automatic release state, and request ID. JSON returns the same values with the profile name and URL. `release` and `release_sha` are null outside the [release layout](/reference/gateway-recovery#release-layout). `auto_release` holds `enabled`, `paused`, `last_checked_at`, and `last_result`. It is null for a caller that is not an active WireGuard peer, and when the Gateway could not read that state.

When this machine is an active WireGuard peer, the Gateway also returns its [desired fleet state](/reference/self-update#desired-fleet-state), as last resolved. It is absent until the Gateway resolves it. Human output then adds `CLI release`, the version of the Gateway's CLI release or why it is unavailable, and `Agent version`, the pinned agent. JSON carries the whole state as `desired_fleet_state`, which is null for any other caller. [`self-update`](/cli/self-update) installs that state.

For an active WireGuard peer, `doctor` holds `collected_at`, the last successful full fleet collection time, `last_run_ms`, its stored duration, and `issues`, the findings observed since that collection started, grouped by Node and issue code. A finding that only an older collection recorded is not shown; it stays in the Problems store as history. `collected_at` is null before the first collection; `last_run_ms` is null until cost has been recorded. An anonymous caller gets `doctor: null`.

Beside `doctor`, `reconcile` holds `finished_at`, the last completed Operation reconciliation pass time, `last_pass_ms`, its duration, and `unsettled_count`, the number of proven terminal runs still awaiting Operation settlement. A healthy Gateway completes a pass every minute and normally reports `unsettled_count: 0`. Missing or malformed facts give null times and duration, and a count of 0. The object is visible only to an active peer that is the Gateway Node or can access it under the same Node access rule as `doctor.issues`. Other callers, including anonymous callers, get `reconcile: null`.

Human output adds one `Reconcile` line with the pass time, duration when known, and unsettled count. Before the first pass, it says `not run yet`.

The list follows [Node access](/cli/node#authority): it includes the caller's own Node and Nodes it has a direct grant to. Gateway and control-plane authority see every Node. Own-Node visibility is specific to this status read; it does not grant access to other commands. `hidden_nodes` counts other Nodes with issues, without exposing their names, codes, or issue counts.

Each group has `node_id`, `node_name`, `code`, `count`, `since` (oldest first seen), and `newest_since` (newest first seen). `count` sums the latest collection’s issues, including issues that share one stored fingerprint. A single-row group also has `resource`, with its `type` and `id`; larger groups have a null resource. Groups sort by newest `newest_since` first. A new resource with an old issue code increases the count and advances `newest_since`.

Human output shows the collection time, the last run duration when known, and one line per group, including the count, first-seen date, and single resource. An empty visible list says Doctor is healthy when a collection has succeeded, or has not run when its time is null. When `hidden_nodes` is positive, one extra line says how many more Nodes have issues the caller cannot see. Collection runs [every five minutes](/reference/gateway-queue#scheduled-work); the status request reads stored findings and starts no check.

A last run longer than 1,000 ms adds `gateway.doctor_collection_slow` for the Gateway Node, with count 1, the collection time as `since` and `newest_since`, and a null resource. It follows the same Node access and disappears after a run at or below that limit. This group comes from collection state; it creates no fingerprint or task.

These Gateway Node groups report [Operation reconciliation health](/reference/operations#recover-a-terminal-native-result). They use the same Node access and have a null resource:

| Code | Meaning |
| --- | --- |
| `gateway.operation_reconcile_stalled` | No pass completed within five minutes. Before the first pass, a native Operation must have been open for more than five minutes. Count is 1; `since` and `newest_since` are the last pass end, or null before the first pass |
| `gateway.operation_settlement_stuck` | A proven terminal run remains unsettled more than five minutes after completion. Count is the number of affected Operations; `since` and `newest_since` are their oldest run completion. A later pass with none clears it |
| `gateway.proof_place_stale_child` | Orbit excludes child rows that exceeded the [proof place bound](/cli/proof/run#the-run) from the place. Count is the number of stale children; `since` and `newest_since` are the oldest last activity. Status reads current rows without changing them |

The command fails with `gateway.profile_missing` when no profile is active and with `gateway.unreachable` when the Gateway does not answer. A Gateway response without an error code uses `gateway.request_failed`; transport failures use `gateway.unreachable`.
