---
title: "orbit node:show"
sidebarTitle: "node:show"
description: "Show one Node with its status, agent, roles, addresses, apps folder, and access grants."
---

```bash
orbit node:show <node> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `node` | yes | Numeric Node ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Print the Node as JSON, including its stored `settings`. |

```bash
orbit node:show 7
```

The command shows what Orbit has recorded for the Node. It does not contact the Node, so it works while the Node is unreachable. The caller needs an access grant to the Node.

| Field | Meaning |
| --- | --- |
| `ID`, `Status` | The Node's ID and recorded status. |
| `Agent` | The Node agent's liveness, below. |
| `Roles` | Every assigned role, including assignments that are not active. |
| `SSH` | The managed user, public address and port. |
| `Cluster` | The name of the Cluster the Node belongs to. |
| `WireGuard`, `LAN` | The Node's addresses. |
| `WireGuard public key`, `WireGuard endpoint override`, `DNS server override` | The Node's network settings. |
| `TLD` | The Node's development TLD, with a leading dot. |
| `Platform` | The platform and architecture. |
| `Apps folder` | The [apps folder](/reference/node-settings#set-the-apps-root) where Instances live. |
| `Access to`, `Accessible by` | The Nodes this Node has an access grant to, and the Nodes that have one to it, each as name and ID. |
| `Failure` | The failed step and error code, only when the Node has a recorded failure. |

JSON includes `assignments` with the [shared recorded lifecycle and failure details](/cli/node#recorded-role-assignments).

A missing value shows `—`.

The JSON field `agent` has a `state` and a `since`:

| `state` | Meaning |
| --- | --- |
| `online` | An agent event arrived in the last 15 seconds. |
| `offline` | No event for longer; `since` is the time of the last one. |
| `not_seen` | The Gateway never received an event from this agent. |
| `unknown` | The Gateway's [agent view](/reference/node-agent#gateway-view) is down, so it cannot tell. |

Human output shows an offline agent as `offline since <time>`. A Node that runs no observing agent, such as an unmanaged Node, has `agent: null`.

An ID that is not a positive integer is refused with `node.id_invalid`. A Node the caller has no access grant to is refused with `node_access.required`.
