# Human Renderer: `orbit version`

[Back to `version` technical contract.](1_version.md)

This page describes the human-rendered terminal output for `orbit version`.

**Renderer:** Human renderer.

## Primitive

None. The command emits fixed detail rows and does not use a table, list, or
progress primitive.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `version` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

None. `version` performs local reads plus requests for release metadata that may
fail, and with `--local` on zsh may ensure shell integration without a progress
tree, so it must not render a progress tree.

## Output Shape

Human output renders exactly three rows:

```text
Version       0.1.105
Released at   17-06-2026 - 12:47
Installed at  17-06-2026 - 12:54
```

When a newer release exists, the version row includes the available version:

```text
Version       0.1.105 (new version available: 0.1.108)
Released at   17-06-2026 - 12:47
Installed at  17-06-2026 - 12:54
```

Human timestamps render as `dd-mm-yyyy - HH:MM`. The display timezone is
resolved from `ORBIT_DISPLAY_TIMEZONE`, then `TZ`, then the host OS timezone,
then the process timezone. Missing timestamps render as `unknown`.

## Test Mapping

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/Operation/VersionCommandTest.php` | Human output, release timestamps, install timestamps, and newer-release annotation. |

There is no gateway-side coverage for this renderer: `version` is local-only,
public command ownership lives in `apps/cli`, and the gateway installer test
covers metadata creation rather than terminal rendering.
