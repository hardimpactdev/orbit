```bash
orbit task:check <task> --phase=baseline|handoff [--idempotency-key=KEY] [--json]
```

Run a baseline or handoff check through `tasks.check` on the Gateway. The group must use external orchestration and have a workspace. The subtask must be its current open subtask. A terminal prompts for missing inputs; machine mode requires them. The command follows waits for VM resume, workspace ownership, and the detached check. A failed check is a successful operation with `result.outcome=failed`; inspect the result, including deliverables and redacted output. A passed handoff records its commit. In a task copy, a baseline runs no setup steps, because the copied seed already ran them; it runs the Project check alone. Ctrl-C stops following. Use `operation:cancel` to stop the check, or `task:cancel` to end the group. See [Check an external group](/reference/tasks#check-an-external-group).

The agreed [hosted handoff CI prerequisite](/reference/tasks#check-an-external-group) adds `result.ci` to JSON output without changing these inputs or adding a caller-selected CI option. This is docs-first, not a runtime delivery claim: external review-and-merge admission remains unsupported. For a Project requiring CI, the operation also waits for its handoff push and hosted check on `result.commit`, the candidate HEAD; `result.head` is the earlier pre-commit snapshot. Baseline/no-policy returns `ci: null`. Waiting observation is not a usable passed candidate. Cancellation after push stops observation, not GitHub workflows, and retains check evidence. Reviewer and publish commands require the shared candidate eligibility rule, including passed CI from the owning successful operation when required.
