Doctor compares current Node and runtime facts with the Gateway's recorded intent. It reports differences and never repairs them. Native provisioning, deployment, Route, Tool, Schedule, firewall and database operations own their configuration checks; Doctor does not repeat them.

## Commands

| Command | Result |
| --- | --- |
| [`doctor`](#orbit-doctor) | Read current Node, role-service and Process state. |

## orbit doctor

```bash
orbit doctor [--node=ID] [--family=FAMILY ...] [--json]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--node=ID` | accessible Nodes | Inspect one positive numeric Node ID. |
| `--family=FAMILY` | all families | Repeat to select families. Current checks belong to `node`, `role`, and `process`. |
| `--json` | false | Return the report as JSON. |

The API admits one `doctor.inspect` Operation with HTTP 202. The CLI follows it and renders `result.report`. Node access applies before admission. Nodes sort by name and ID; the family order is fixed.

Human output lists Node, Family, Status, Checked, Resource and Finding. JSON returns the same report, with node/family/check counts and counts of drift, unverifiable and informational issues. Exit 0 means the performed checks have no drift or unverifiable findings. Exit 1 means a check found drift, could not be verified, or the request failed.

### How Swamp inspects

Every read runs through official `@swamp/ssh` from the Node209 control worker, using stored host pins and the approved worker identity. The Gateway supplies full public expectations. A pure plan lists native argv; each read is a separate native step. One typed comparison step emits the report for the existing shared terminal projector. There is no Gateway callback, private-material fetch, binding wait, remote script bundle, or repair action.

The commands are `uname -sm`, `df -Pk /`, `systemctl show` with selected state properties, a filtered `docker container ls` showing only name and state, and `test -e` for a managed hibernation marker. Process reads use sudo. Docker environment, command arguments, service file contents and credentials are never requested.

Failed or malformed reads produce one unverifiable inspection finding for their family and Node. Other reads continue. A parked or unmanaged Node dispatches no SSH reads and supplies no positive recovery evidence. Parked task VMs have an informational finding.

### What each family checks

| Family | Checks |
| --- | --- |
| `node` | Recorded lifecycle; platform and architecture; root filesystem free space; Linux agent service presence/state; freshness of the Gateway's continuous agent observation at comparison time. |
| `role` | Recorded lifecycle and current state of each service required by an active Linux role. |
| `process` | Current registered systemd unit or Docker container presence and running/stopped state. A systemd `activating/auto-restart` snapshot is crash-loop evidence. A cumulative restart count alone is not. |

A stopped, non-keep-alive development Process desired running is healthy only when its managed awake marker is proven absent. An unavailable marker does not count as sleep. This inspection takes no timed samples and does not infer a restart rate.

The existing family selectors `project`, `instance`, `schedule`, `tool`, `firewall`, `database_connection`, `route` and `database_server` remain accepted by the API, but have zero Doctor checks. A healthy family with `checked: 0` supplies no verdict on its resources. Use the owning native operation and its result for configuration validation.

`checked` counts the focused reads performed for a family. Auxiliary awake-marker reads do not add another Process check. Lifecycle findings can exist without a host read. Missing reads remain in the count and produce unverifiable findings.

### Informational package discoveries

Doctor does not discover packages. Use the Tool family's native scan and adoption operations. Doctor reads no package-manager scope and stores no inventory.

## Why it works this way

### Verify only

Doctor reports current liveness. Each native family owns the checks that establish its configuration. Repeating those implementations in Doctor creates a second execution engine and competing definitions of success.

### Informational findings stay healthy

An informational finding is not drift or unverifiable. A parked task VM does not become unhealthy merely because Doctor skips it.

### No stored reports

Native run history holds the public report. The Gateway projects the Operation result. Scheduled collection records bounded fingerprints, not raw host output or private values.

### One observation per Node

Every host fact belongs to its admitted Node. Doctor does not infer remote state from another Node's successful read.

### A closed family list

The API keeps its fixed family names. The table above defines the current inspection scope. A zero-check family cannot clear an old incident.

### Bounded values

Expected and observed issue values contain at most 255 characters. Recovery evidence names only the codes actually compared. It never claims whole-resource coverage, so retiring a check does not silently resolve its old findings. Unavailable native reads share the existing `node:ID` check identity within their family; a later run clears that inspection failure only when every retained read for that family and Node is usable. Old numeric-resource inspection failures remain outside this reduced scope.

## Scheduled collection

Collection uses the same Doctor workflow. One focused Gateway log read remains because no native command supplies record-aware Laravel cursors and redaction. It runs as an official SSH script with public path/cursor input. The script reads at most 1 MiB per pass, finishing a record up to an 8 MiB cap. It returns exception class, safe source frame, request ID and timestamp; messages and raw logs stay on the Gateway host.

The first pass starts at the current end. Rotation preserves unread records by inode; truncation resumes at the shorter end. An unreadable log result preserves the cursor. The Gateway commits returned fingerprints and the cursor together. Activity and assistance collection keep their existing bounded database cursors and redacted inputs.
