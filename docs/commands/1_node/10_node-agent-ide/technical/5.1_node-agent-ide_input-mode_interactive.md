# Interactive Input Mode: `orbit node:agent-ide [name] [agent_ide]`

[Back to `node:agent-ide` technical contract.](1_node-agent-ide.md)

This page describes how interactive input mode resolves `node:agent-ide` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_node-agent-ide_input-mode_non-interactive.md`](5.2_node-agent-ide_input-mode_non-interactive.md) even if the process has a TTY.

App-node callers and unconfigured control callers are rejected before this input
mode renders any prompt.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `node_agent_ide.name` | `[name]` is missing. |
| 2 | `node_agent_ide.adapter` | `[agent_ide]` is missing. |

## Prompt Mapping

### `node_agent_ide.name`

| Property | Value |
| --- | --- |
| Primitive | `text` |
| Label | `Node name` |
| Source | `[name]` |
| Required | yes |
| Choices | none |
| Default | none |
| Validation timing | When `[name]` is read or when the prompt is submitted. |
| Invalid terminal behavior | Show validation message and re-prompt. |

### `node_agent_ide.adapter`

| Property | Value |
| --- | --- |
| Primitive | `select` |
| Label | `Agent IDE adapter` |
| Source | `[agent_ide]` |
| Required | yes |
| Choices | The reserved node-scope token `none` followed by the gateway-owned adapter registry. Core adapter names registered by core Orbit are `opencode` and `polyscope`. Adapters registered by installed Orbit extensions appear in the same list. Gateway callers read the registry locally; configured control callers query the gateway over HTTPS through WireGuard before rendering the prompt. The CLI caller does not maintain a local adapter manifest, does not scan installed extensions on the control machine, and does not fall back to a hard-coded core list. |
| Default | none |
| Validation timing | When `[agent_ide]` is read or when the prompt is submitted. Validation uses the same gateway-owned adapter registry that backs the choices list. |
| Invalid terminal behavior | Show validation message and re-prompt. |

If the gateway is unreachable while gathering choices for a configured control
caller, the command collapses to the `gateway_unavailable` failure defined in
[`../1_node-agent-ide.md`](1_node-agent-ide.md#failure-semantics) before
prompts complete.

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid field-local input shows a validation message and re-prompts until the
  value is valid or the user aborts.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If the target node does not exist, fail before side effects
  after the name is resolved.
- If the user aborts a prompt, exit with the standard command failure status and
  do not start side effects.
