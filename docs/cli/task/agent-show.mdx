---
title: "orbit task:agent:show"
sidebarTitle: "task:agent:show"
description: "Show one redacted read of an agent thread's conversation."
---

```bash
orbit task:agent:show [task] [session] [--after-sequence=CURSOR] [--json]
```

| Input | Choices | Meaning |
| --- | --- | --- |
| `group` | a list of tasks | The numeric task ID. |
| `session` | the task's agent threads | The numeric agent thread ID, as `task:agent:list` shows it. |
| `--after-sequence=CURSOR` | the `cursor` of a previous read | Return only the entries after that cursor, when the thread's Pi server can resume from it. |

In a terminal the command prompts for each omitted input. The thread list shows the ID, role, subtask ID, driver, and state. It leaves out stored `t3` threads, which have no transcript. A noninteractive call fails before the request with `task.task_required` or `task.agent_thread_required`, and an invalid ID fails with `task.task_invalid` or `task.agent_thread_invalid`. The command needs Gateway access.

Human output shows the state, the kind, the source, the cursor, the token metrics, the line diff, the number of input requests, and the errors. The kind is `snapshot` for the whole transcript, or `delta` for only the entries after `--after-sequence`. The source is `live` for a read from the thread's Node, or `saved transcript` when Orbit read its saved copy. Each transcript entry follows, oldest first, under a heading with its time, kind, and label. Entry times are the driver's UTC times, to the minute. JSON output returns the read with `request_id`. [Read a thread](/reference/tasks#read-a-thread) defines the fields and the cursor. To see newer entries, run the command again with the last `cursor` as `--after-sequence`.

A thread that has not started yet shows no entries. A `t3` thread fails with `tasks.agent_transcript_unavailable`. A thread whose Node is gone fails with `tasks.agent_unavailable` when Orbit saved no transcript. A thread whose Pi server cannot serve the read fails with `tasks.agent_read_failed` when Orbit saved no transcript. An invalid `--after-sequence` fails with `validation.failed`.
