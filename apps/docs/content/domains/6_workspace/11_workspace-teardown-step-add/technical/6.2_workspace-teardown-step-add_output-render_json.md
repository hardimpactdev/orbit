# Technical Contract: `orbit workspace-teardown-step:add` (JSON Renderer)

**Renderer:** JSON.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

[Back to the canonical contract.](1_workspace-teardown-step-add.md)

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "added"
      },
      "step": {
        "id": 18,
        "app": "hauser",
        "app_instance": "nmbp",
        "phase": "teardown",
        "order": 1,
        "command": "dropdb docs_feature",
        "timeout_seconds": 600
      }
    },
    "meta": []
  }
}
```

### Fields

- `result.action`: Literal `"added"`. The only outcome verb for this
  command. `workspace-teardown-step:add` is additive and never converges
  by command text; running the same `add` twice produces two separate
  records.
- `step.id`: Newly assigned numeric registry identifier. Stable across
  re-runs for the same record.
- `step.app`: The logical app slug of the resolved instance.
- `step.app_instance`: The required app instance that owns the step.
- `step.phase`: Literal `"teardown"`. The discriminator that separates
  this policy list from setup steps.
- `step.order`: The absolute position of this step in
  `(app_instance, phase=teardown)`.
- `step.command`: The shell command string as supplied. Not parsed or
  expanded by the gateway; the runner executes it as-is in the workspace
  path on the owning node during `workspace:remove` /
  `app:prune`.
- `step.timeout_seconds`: Strict positive integer. Default `600`.

`workspace-teardown-step:add` does not emit non-fatal warnings. Drift
between gateway configuration and node reality is reported by
[`doctor --family=workspace`](../../workspace-doctor.md), not by this
write command. Per-step execution failures are reported by the consumer
commands ([`workspace:remove`](../../5_workspace-remove/workspace-remove.md)
and [`app:prune`](../../../5_app/7_app-prune/app-prune.md)); this
command's JSON renderer never carries warnings.

The step record exposes only the fields above. There is no `name`,
no `working_directory`, no `env_overrides`, and no per-step `on_failure`
field. Working directory is pinned to `ORBIT_WORKSPACE_PATH` by the
[Workspaces README](../../README.md#lifecycle-step-environment) and
failure policy is owned by `workspace:remove` / `app:prune` (best-effort
continue with structured warnings).

## Error Envelope

### Validation failure (timeout)

Returned when `--timeout` is non-positive (including `0`). Fails before
any side effects.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Timeout must be a positive integer.",
    "meta": {
      "field": "timeout",
      "reason": "must_be_positive_integer"
    }
  }
}
```

### Validation failure (app)

Returned when the app instance cannot be resolved from `--app`,
`.orbit/config`, or gateway path-ownership lookup, and prompting is
disabled (non-interactive mode).

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Could not resolve app instance.",
    "meta": {
      "field": "app",
      "reason": "missing_required_input"
    }
  }
}
```

### Invalid position

Returned when both insertion flags are supplied.

```json
{
  "error": {
    "code": "workspace.invalid_position",
    "message": "Both insertion flags cannot be supplied.",
    "meta": {
      "before": 18,
      "after": 19
    }
  }
}
```

### Step not found

Returned when the referenced insertion step does not exist for the
resolved `(app_instance, phase=teardown)`.

```json
{
  "error": {
    "code": "workspace.step_not_found",
    "message": "Referenced insertion step '19' not found for app 'docs' in phase 'teardown'.",
    "meta": {
      "id": 19,
      "app": "docs",
      "phase": "teardown"
    }
  }
}
```

### App not found

```json
{
  "error": {
    "code": "workspace.app_not_found",
    "message": "App 'docs' not found.",
    "meta": {
      "app": "docs"
    }
  }
}
```

## Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (empty `--command`, non-positive `--timeout`, unresolved app instance). `error.meta.field` names the offending input. |
| `workspace.app_not_found` | Resolved app slug does not exist in gateway configuration. `error.meta.app`. |
| `workspace.invalid_position` | Both insertion flags were supplied. `error.meta.{before, after}`. |
| `workspace.step_not_found` | Referenced insertion step does not exist for the resolved app and `phase=teardown`. `error.meta.{id, app, phase}`. |
| `authorization_failed` | The caller lacks `workspace:write` on the target app's owning node. `error.meta.reason=missing_permission`, `error.meta.missing_permission=workspace:write`, and `error.meta.serving_node` names that node. |

## Enum and identifier values

| Field | Values |
| --- | --- |
| `result.action` | `added` |
| `step.phase` | `teardown` |
| `error.code` | `validation_failed`, `workspace.app_not_found`, `workspace.invalid_position`, `workspace.step_not_found`, `authorization_failed` |

The `error.code` values listed here are exhaustive for
`workspace-teardown-step:add`. Add a new value to this renderer contract
before implementing another JSON failure code.
