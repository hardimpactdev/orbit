```bash
orbit task:start <task> [--idempotency-key=KEY] [--json]
```

Start the work place of a parent task in Todo. The task must use external orchestration and have no claimed workspace. The command follows the Operation it gets until that Operation ends. It starts no subtask, check, turn, or publication.

Orbit first decides where the task runs. A Project whose default Instance is a container, or that has the [`nested_fleet`](/reference/projects#nested-fleet-setting) flag on, gets a task copy. A Project whose default is a host checkout gets a task VM.

## A task copy

The task starts as a copy of the Project's default Instance. Orbit clones the default into the Instance `task-<id>`, on the new branch `task-<id>`, as [`instance:create`](/cli/instance/create) clones it. The task owns the copy. Orbit returns the `instance.create` Operation. The task is `running` once that Operation succeeded and the copy is `active`, which is fully set up. The copy's T3 server registers with Conn as every clone's does, labelled with the Project name and `task-<id>`. The copy has its own database, Route and Processes, as every clone does. Only a copy of a nested-fleet Project carries an inner fleet.

Orbit refuses the start at once and records nothing in these cases:

| Code | When |
| --- | --- |
| `tasks.copy_source_unavailable` (409) | The default Instance is missing, not active, stopped, or has no seed snapshot. One read of its container, at most about 6 s, confirms that it runs, whatever its record says: a stopped, asleep or unreachable container refuses |
| `tasks.copy_name_taken` (409) | An Instance named `task-<id>` exists |
| `tasks.copy_capacity_full` (409) | Nested-fleet Project only: the default's Node holds as many nested-fleet task copies as the Gateway allows. There is no wait |
| `tasks.copy_id_range_full` (409) | With the copy placed, the default's Node would keep no free [isolated ID range](/reference/development-containers#isolated-id-ranges) for the next seed of a default on it. The details name `free`, `size` and `seed_sizes_short`. There is no wait |
| `tasks.copy_id_ranges_unreadable` (409) | One bounded read of the Node's ID ranges, at most about 4 s, did not answer. Without it no free range can be shown |

Every copy takes an isolated ID range of the Node, and the default's next seed needs one for a moment. So each start reads the Node's real ranges and keeps one free for the seed ([isolated ID ranges](/reference/development-containers#isolated-id-ranges)). The Gateway setting `ORBIT_TASKS_COPIES_MAX` in the Gateway's `.env` is an upper bound on top of that: how many nested-fleet task copies one Node holds at once. The default is 1. Every nested copy that a task owns counts, also one whose create failed or that is being destroyed. A copy of any other Project is a plain clone: it does not count and has no task cap. Turns and proofs in two copies on one Node do not wait for each other ([turn](/cli/task/turn#in-a-task-copy), [proof](/cli/proof/proof#the-run)).

When the create fails, is refused by Swamp, or is cancelled before its run starts, the task is `failed` and Orbit destroys the copy with force. When the create's run budget expires, the task stays `reserved` with its copy, because the run may still be stopping. If the destroy fails, the task also keeps owning the copy. Run `task:cancel` or `orbit instance:destroy <id> --yes --force` to destroy it.

The copy's agent gets the fixed task model key, as every clone does; the key is not per task. Per-task model keys are an open decision. A stopped copy, for example after a reboot of its Node, stays stopped until Orbit starts it.

## A task VM

A task of a Project whose default is a host checkout takes a task VM through the existing `tasks.provision` operation. Task VMs are [off in the live fleet](/reference/old-paths#off-in-the-live-fleet): every host has 0 task places, so no task VM starts. A task VM serves only the proof Project, because the base VM carries only its checkout. Orbit refuses a task of another Project at once with HTTP 409 `task_vm.project_unsupported` and records no Operation.

When no task place is free, or an earlier task is waiting, the operation waits in the shared task queue, first come, first served. It holds no VM, and the task stays in Todo. `operation:show` and `task:show` report `capacity_wait`: the queue position and the tasks that hold the places, with each one's status and last activity. `task:status` shows the places of every host and the whole queue. The wait ends with `tasks.capacity_timeout` after two hours. [Task places](/reference/tasks#task-places) defines these fields. A failed start releases its place. Changing a task's status with `task:update --status=todo` changes board state only; it does not start a VM.

`--idempotency-key` reuses the same operation for a transport retry, also the `instance.create` of a task copy. Ctrl-C stops following and leaves the operation running. Use `task:cancel` to end the parent task.
