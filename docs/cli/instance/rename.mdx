```bash
orbit instance:rename <instance> [--branch=BRANCH] [--domain=HOST] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Positive numeric Instance ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--branch=BRANCH` | none | Record this local branch. Symbolic `HEAD` must already name it. |
| `--domain=HOST` | none | Refused with `operation.kind_unavailable`, also when `--branch` is supplied; Route replacement is not available through rename. |
| `--json` | off | Return the recorded Instance JSON, or an error, without prompts or progress. |

Supply at least one of `--branch` and `--domain`, and neither empty; otherwise the CLI refuses with `validation.failed` and sends no request. The command needs no `--yes` or `--force`. In a terminal, an omitted Instance is chosen from an interactive list; a noninteractive or `--json` call without it is refused with `instance.id_invalid` and sends no request, and so is a value that is not a positive integer.

The command does not rename the Instance, move its directory, change its starting commit, or change Git `HEAD`. It accepts a plain checkout and a linked worktree alike: the Node agent reports both, and a worktree records the branch its own `HEAD` names.

Rename the branch locally before recording it. The [Node agent](/reference/node-agent#checkouts) reports the checkout shortly after the change. The Gateway trusts the report only while the agent is online, which means it sent an event in the last 15 seconds. It checks that report: the checkout's top level and origin, and the branch that symbolic `HEAD` names. The Gateway reads nothing on the Node and starts no task. A dirty or unpublished branch can be recorded. Normal removal still requires clean, published source.

```bash
# In the Instance checkout:
git branch -m t3code/login-redirect
orbit instance:rename 1 --branch=t3code/login-redirect
```

A changed branch updates `selected_branch` and `branch_override`. Recording the already recorded branch writes nothing and preserves its existing override, or the absence of one. The command is safe to repeat, but it runs the same report checks first, so a repeat while the agent is offline is refused. A repeat that changes nothing has no skip marker or reason code. See [recorded branch behavior](/domains/applications#record-a-renamed-branch).

The Gateway trusts the report only while the Node agent is online. When the agent is silent, or has not reported the checkout, the command refuses with `instance.branch_not_checked_out` and says it can't verify. Try again when the agent reports.

## Human output

The command prints a detail titled `Instance: <name>` with ID, Project (by slug), Node (by name), Selected branch, Branch override and Request ID. Success exits with status `0`; a refusal exits with status `1`.

## JSON and API output

The API is `POST /api/v1/instances/{instance}/rename` with `{"branch":"t3code/login-redirect"}`. It answers HTTP 200 with the Instance. The MCP tool is `instance-rename`, with `instance` and `branch`. Refusals use the shared API error shape.

## Errors

| Code | Meaning |
| --- | --- |
| `validation.failed` | Neither field was supplied, or a supplied value is null, empty, wrong-type, or an invalid Git branch name. |
| `operation.kind_unavailable` | A domain was supplied; Route replacement is unavailable through rename. Or the Instance runs in a container. |
| `instance.id_invalid` | The Instance is missing in a call that cannot prompt, or is not a positive integer. |
| `input.cancelled` | You cancelled the Instance list. |
| `instance.rename_unsupported` | The Instance is production, or is not a development checkout or linked worktree. |
| `instance.rename_inactive` | The development checkout or worktree is not active. |
| `instance.lifecycle_busy` | The Instance is being removed, has an unfinished transfer, or is the candidate of a clone in progress. |
| `instance.branch_not_checked_out` | The reported symbolic `HEAD` names another branch or is detached, the checkout's top level or origin differs from its record, or the Node agent has not reported it recently. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |
