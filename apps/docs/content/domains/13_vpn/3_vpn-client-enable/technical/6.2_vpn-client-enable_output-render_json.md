# JSON Renderer: `orbit vpn-client:enable <name>`

[Back to `vpn-client:enable` technical contract.](1_vpn-client-enable.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "client": {
        "name": "laptop",
        "enabled": true,
        "action": "enabled",
        "already_enabled": false
      }
    },
    "meta": []
  }
}
```

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "VPN client does not exist.",
    "meta": {
      "field": "name",
      "reason": "client_not_found"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.client.name` | string | Enabled client name. |
| `success.data.client.enabled` | boolean | Always `true` on success. |
| `success.data.client.action` | `enabled` | Command action. |
| `success.data.client.already_enabled` | boolean | Whether the backend was already in the desired state. |
| `error.code` | `validation_failed`, `vpn_runtime_unavailable`, `vpn_runtime_ssh_unavailable`, `authorization_failed`, `vpn_backend_unavailable`, `vpn_backend_auth_failed` | Stable command failure code. |
| `error.meta` | object | Validation, gateway SSH, authorization, backend, or authentication failure context. |
