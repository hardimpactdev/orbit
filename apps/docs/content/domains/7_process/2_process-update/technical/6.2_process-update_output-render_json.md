# JSON Renderer: `orbit process:update [name]`

[Back to `process:update` technical contract.](1_process-update.md)

This page describes the JSON-rendered output for `process:update`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces non-interactive input mode.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Success data contains the updated process definition, changed fields, previous
process name when identity changed, and derived runtime units. Partial
post-configuration drift is reported under `success.meta.warnings[]`.

Warning objects contain:

| Field | Meaning |
| --- | --- |
| `code` | Singular product warning code, such as `process.runtime_unit_missing`, with the owning family recorded separately. |
| `family` | State family that owns the warning. |
| `message` | Human-readable warning summary. |
| `next_command` | Suggested command to inspect or repair the warning. |

## Success Example

```json
{
  "success": {
    "data": {
      "process": {
        "key": "vite-production",
        "label": "Vite Dev Server",
        "name": "vite-production",
        "app": "docs",
        "instance": "production",
        "command": "npm run dev",
        "restart_policy": "never",
        "crash_notification": "none",
        "runtime": "systemd"
      },
      "old_name": "vite",
      "changed": [
        "name"
      ],
      "runtime_units": [
        {
          "name": "orbit_docs_production_main_vite-production",
          "context": "main"
        }
      ]
    },
    "meta": {
      "warnings": []
    }
  }
}
```

`success.data.process.key` is the stable process identity slug after the update.
`success.data.process.label` is the durable human display label (identity rename
via `--name` does not rewrite it). `success.data.process.name` is a deprecated
compatibility alias equal to `key`; new consumers must use `key` and `label`.

## Error Example

```json
{
  "error": {
    "code": "validation_failed",
    "message": "At least one editable field is required.",
    "meta": {
      "field": "editable_fields"
    }
  }
}
```

## Authorization Error

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to update processes on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "process:update",
      "serving_node": "app-1"
    }
  }
}
```

## Error Code Vocabulary

- `validation_failed`: missing `name` or node/instance/workspace context, invalid new process name, invalid enum value (`restart_policy`, `crash_notification`, `runtime`), empty `command`, invalid runtime scope, or no editable fields supplied. An ambiguous bare app selector uses `error.meta.field=instance` and `error.meta.reason=instance_required`.
- `authorization_failed`: caller lacks process-configuration mutation permission on the resolved node or instance serving node.
- `process.not_found`: the named process does not exist for the resolved owner scope.
- `process.name_conflict`: `--name` matches another process in the resolved owner scope.
- `process.rename_unsupported`: the selected runtime/backend cannot safely replace derived unit identity.
- `gateway_unavailable`: the CLI cannot reach the gateway API before configuration is changed.
