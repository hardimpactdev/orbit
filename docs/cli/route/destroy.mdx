Remove a Route and its DNS records, Caddy sites, certificates, and firewall rules. For a Route whose Instances are not active, also withdraw the PHP-FPM pools of its development Instances. See [Remove a Route](/reference/routes#remove-a-route). On a `pending` or `failed` replacement Route that never activated, it abandons the domain change and keeps the Route it would replace. See [Remove a replacement that never activated](/reference/routes#remove-a-replacement-that-never-activated).

```bash
orbit route:destroy <route> [--yes] [--offline] [--idempotency-key=KEY] [--json]
```

| Option | Meaning |
| --- | --- |
| `--yes` | Confirm removal without prompting. |
| `--offline` | Swamp probes each Node once from 209 and skips unreachable Nodes. Each Node that answers keeps every step. |
| `--json` | Return machine-readable JSON. |

When a Node the removal changes does not answer, the Gateway returns `route.node_unreachable`. The message names the Node and `--offline`. With `--offline`, the response lists each skipped Node and its remaining steps under `retained_on_nodes`. Run `orbit node:converge NODE` once that Node answers. See [Remove a Route from an unreachable Node](/reference/routes#remove-a-route-from-an-unreachable-node).

<Warning>
The Gateway refuses removal with `route.target_conflict` while an active Instance depends on the Route. A replacement that never activated is the exception, because its Instance keeps the Route it replaces. Remove the Instance with `instance:destroy` instead. That removal deletes the Route when it removes the last target. The Gateway also refuses direct removal of analytics tracking Routes with `route.tracking_managed`; disable analytics on the Instance instead. A Route kind that cannot be destroyed returns `route.kind_invalid`.
</Warning>

`route:destroy` and `route:target:unset` resolve the Route and then ask for confirmation, with No selected. Pass `--yes` for automation, also with `--json`. Declining, Ctrl-C, or end of input returns `input.cancelled` and sends nothing. A call without a terminal and without `--yes` returns `input.confirmation_required`.

Private DNS outside the TLD is removed first, followed by a 31-second grace for the old answer to expire. The site and certificate are withdrawn together; shared LAN and public firewall rules stay while another Route needs them. Unreachable VPN Nodes cannot be skipped. The final official resource checks and native assertion require the captured files, certificate scopes and firewall rules to match the removal. Drift fails the run and keeps the Route record for a retry.
