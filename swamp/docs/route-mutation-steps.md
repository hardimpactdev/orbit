# Same-root Route mutation steps

`operations/routes/mutation-steps.ts` exposes `readRouteMutationParticipant(gateway, args, signal?, {recovery?})`, `routeMutationActions(workloads?, network?, certificates?, lan?)` and `routeMutationDnsGrace(signal?)` for a Cluster or Node parent's native DAG. `args` keeps the parent's `operation_id`, `kind`, `node_id` and `run_id`, and adds the placed `target_node_id` and captured original `route_id`.

The authenticated public input contains `route_mutations: [{route_id, node_ids, route, workloads, publication, environment_fields, environment_workloads, firewall, probes, cleanup, cleanup_lan}]`. The selector requires one matching original Route, the truthful root identity, an unfinished parent, and exact participant/workload placement. A forward read refuses cancellation. Explicit recovery ignores cancellation while keeping all identity and placement checks.

`routeMutationActions()` exposes `prepare`, `lan`, `firewall`, `verify`, `synchronizeEnvironment` and `cleanup`. Preparation and environment writes reuse the canonical target workload actions. Cleanup accepts only the fresh selected view. Its certificate removals preserve user and optional home; its LAN removals use the canonical shared UFW engine. All effects run on the selected Node transport, including Nodes 1 and 18. No action or observer invocation goes through the frozen agent.

The Gateway's `NativeRouteMutationPlan` captures the reconciler proposals and implements stored-state checkpoints. The composing parent owns admission, its private-material declaration and callback, checkpoint selection, and the batch DAG. Certificate request/sign/publish uses the existing canonical certificate model. Caddy/PHP/DNS publication uses the existing `@nckrtl/route-publication` methods, which read fresh stored state inside the Node publication lock. There is no child Operation or Route-root impersonation.

Prepare staging leaves, record `workloads-prepared`, publish candidate workloads, record `router-prepared` after Router leaves exist, then publish and verify the candidate Router before `commit`. Publish fresh DNS and record `dns-published`. Wait one 31-second batch grace before `withdraw`; issue live leaves, republish, remove fresh obsolete scopes and call `complete`. Before commit, recovery restores DB state with `rollback`, republishes and restores LAN/environment on the original view, waits the grace, removes fresh candidate residue, and calls `rollback-complete`. After commit, recover forward. The parent stores `state.native_route_mutations_rollback: true` in the same transaction as its rollback checkpoint so subsequent public/private reads select the original plans.

Private environment writes use the fresh admitted `environment_workloads` union and run once per placed Node. LAN cleanup retires obsolete exact Route-owned allowances under the existing whole-program UFW lock and keeps the current desired allowance. It refuses a missing desired survivor before deletion.
