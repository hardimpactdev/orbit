# Non-Interactive Input Mode: `orbit workspace-teardown-step:remove`

[Back to `workspace-teardown-step:remove` technical contract.](1_workspace-teardown-step-remove.md)

This page describes how non-interactive input mode resolves
`workspace-teardown-step:remove` input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces non-interactive input mode even
when the process has a TTY. It never authorizes destructive consent; `--force`
must be passed explicitly.

## Responsibilities

- Read supplied arguments and options.
- Fail before side effects when required input is absent.
- Fail before side effects when destructive consent (`--force`) is absent.
- Never render prompts.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `app` | `--app` is absent and local context cannot resolve a parent app. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=app`. |
| `step` | `--step` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=step`. |
| `force` | Non-interactive mode and `--force` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=force`. |

## Validation Failures

Fail before side effects when:

- `step` is not a positive integer.
- `step` ID does not exist for the resolved app and `phase=teardown`.
- The caller's grant does not include the permission required to manage
  workspace teardown step policy for the target app (surfaces as
  `error.code=authorization_failed` with `error.meta.missing_permission`).

The selected output renderer owns how these failures are displayed.
