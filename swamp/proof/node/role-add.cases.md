# node:role:add verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a Metrics Node and a blank managed Linux Node, plus a Node that already holds roles. It checks the Gateway record, the machine state and real traffic. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Add a role | Add `app-dev` to the blank Node. | The Operation succeeds and the assignment is `active`. The role's packages, files, services, ports and firewall rules are in place, and the final check passes. No Node agent or Orbit CLI is installed. |
| Role services | After the add, for `database`, `websocket` and `ingress` in turn. | Each role's service answers on its port over the allowed path, and a source outside the rule stays blocked. |
| Metrics | Add a role that joins Metrics. | The Node's exporters run, Prometheus on the Metrics Node scrapes them, and the firewall rules put each allow before its isolation deny. Unrelated rules stay. |
| Analytics | Add `analytics` with its two Processes, then without them in a terminal, then with `--json`, then `--converge` with only one. | The role is `active` and the application answers. The terminal lists the matching Docker Processes and asks for each missing option. The `--json` call and the incomplete `--converge` are refused with `node_role.storage_process_required` or `analytics.settings_missing` and no request. |
| Swamp role | Add `swamp` to a Node, then converge it with serve and workers running. | The pinned Ansible, the Swamp binary beside the running one, its link, identity, serve unit and worker units are applied, and the check passes. The running serve and workers keep dispatching through the swap. |
| Gateway role | Add `gateway` to a new Node with `vpn` and `metrics` on other Nodes. | The new Gateway Node can reach them. Its static runtime is installed and the old release timer, services and Documents start hook are gone. |
| Certificates and sites | A role that needs certificates, sites and private DNS. | The certificates are signed and installed, the PHP pools are published first, the sites answer over TLS, and the private DNS records are published last, after the firewall is open. |
| Failed first add | Make a step fail. | The Operation fails with the failed step. The assignment stays `failed` at `converge:<step>`. Finished host changes stay and nothing is rolled back. Running services keep their last valid configuration, and Caddy does not reload one that fails validation. |
| Interrupted run | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step. The assignment stays `provisioning`, and after 11 minutes `--converge` takes over the stale claim and finishes. |
| Downloads | A pinned package whose mirror is unreachable, and one with a bad checksum. | A transport failure falls back to upstream. A checksum failure stops the run and removes the staged file. |
| Retry with converge | Fix the cause and run `--converge`. | The assignment becomes `active`, with no duplicate packages, units, rules or sites. |
| Converge an active role | Change a unit and a firewall rule by hand, then run `--converge`. | Both are repaired, unrelated rules stay, and a second convergence reports no changes. |
| Failed converge | Make a step fail during `--converge` of an `active` role. | The role stays `active`, so its service keeps running. The failed step and error code are on the Operation. |
| Converge states | `--converge` for a role that is `failed` at a `converge:` step, one `provisioning` for 11 minutes with no holder, and one `provisioning` for less. | The first two converge: the role is marked `provisioning` for the run, and success clears the earlier failed step. A failure marks it `failed` again with the new step's code. The third is refused with `validation.failed`. Fails today: admission does not check the stale claim, so the third is accepted. |
| Not on the Node | `--converge` for a role the Node does not hold. | `validation.failed`, with no change. |
| Add again | Add a role the Node holds, with and without `--converge`, and an `active` `ingress` role without it. | Without `--converge`, `validation.failed` and no change, except `ingress`, which runs again. |
| Refused roles | `vpn` and `router`, an unknown role, a role that conflicts with one the Node holds, a singleton with a holder, `ingress` outside a Cluster or a second one in a Cluster, and `database` on a Node without a WireGuard address. | `validation.failed` for each, and `database.wireguard_ip_missing` for the last, before any change. `swamp` is not movable with `node:role:relocate`. |
| Unsupported Node | An inactive Node, a macOS Node and a Node not managed over SSH. | `operation.kind_unavailable`, with no change. |
| Busy | Start a second add on the Node while one runs. | `operation.target_busy`. The first run is unaffected. |
| Run files | After a successful run and after a failed one. | The intent, vault values and private configuration files are gone. Grafana's file, where present, is owned by its container account at mode `0600`. |
| CI runner | Add `ci-runner` to a CI-only Node, and with `gateway` or `vpn`. | The Incus host boundary is prepared and no container is created or registered. With `gateway` or `vpn`, `validation.failed`. |
| Storage directory | An application role with a storage directory that is a protected path. | Refused before any host work. |
| Missing input | In a terminal, run the command with no arguments. Then run it noninteractively and with `--json` without the Node, then without the role. | The terminal asks for the Node from an interactive list and for the role. Ctrl-C ends with `input.cancelled` and no request. The noninteractive calls are refused with `node.id_invalid` and `validation.failed`, with no request. Fails today: the arguments are required and nothing prompts. |
| Node by ID only | Pass a Node name instead of its ID. | `node.id_invalid`, with no request. Fails today: the CLI accepts a name. |
| Dropped inputs | Run the command with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers `--idempotency-key`. |
| Lost response | Lose the response to the start, then repeat the command. | Exactly one Operation exists for the add. Fails today: the CLI needs `--idempotency-key` to avoid a second Operation. |
| Refusals | A Node the caller has no access grant to, and an unknown ID. | `node_access.required` and a not-found error. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result with the Operation and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Operation. |
