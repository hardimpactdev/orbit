# `orbit instance:worker show|enable|disable [instance]`

[Back to App and instance commands.](../README.md)

Inspect or change FrankenPHP worker mode for one concrete instance.

Worker mode is an opt-in app runtime setting. It is disabled by default and
classic FrankenPHP request handling is the steady-state runtime path. Worker
mode keeps the Laravel application in memory between requests through Laravel
Octane's FrankenPHP integration, and `instance:worker` is the only command that
owns that state transition.

Worker mode lives on the instance entity. Different instances of one
app may use different worker settings. There is no workspace worker
mode in the current command surface; supported `app-dev` workspaces always use
the classic runtime, and production workspaces are rejected.

## Usage

```bash
orbit instance:worker show <app.instance> [--json]
orbit instance:worker enable <app.instance> [--json]
orbit instance:worker disable <app.instance> [--json]
```

## Examples

```bash
orbit instance:worker show docs.development
orbit instance:worker show docs.development --json
orbit instance:worker enable docs.development
orbit instance:worker disable docs.development --json
```

## Arguments and options

- `action`: one of `show`, `enable`, `disable`. Required.
- `instance`: dotted instance selector such as `docs.development`. A bare app
  name or hostname is shorthand only when that app has exactly one instance.
- `--json`: Output JSON.

## What Happens

Run `instance:worker` to inspect or change worker mode for one instance and to
update the worker configuration stored on that instance.

`instance:worker show` reads the selected instance state without touching gateway
configuration. You see the same `worker_enabled` and `worker_config` values
that `instance show` reports.

`instance:worker enable` first runs the readiness validator on the selected
instance's serving node and source path.
When readiness fails, the command exits with an error and leaves both
`worker_enabled` and `worker_config` unchanged. When readiness passes, the
command writes `worker_enabled=true` and the active worker configuration into
gateway-owned instance configuration.

`instance:worker disable` clears `worker_enabled` to `false` and preserves the
stored `worker_config` so re-enabling later restores your prior configuration.

`instance:worker` does not:

- Run `composer require`, publish Octane config, edit bootstrap files, or
  otherwise mutate your app to make it pass readiness.
- Restart the FrankenPHP runtime container directly. The runtime renderer
  picks up the new worker mode setting the next time the app runtime is
  enacted.
- Change workspace runtime behavior. Supported `app-dev` workspaces remain in
  classic mode regardless of the selected instance's worker setting;
  `app-prod` workspace operations are rejected before runtime rendering.

## Readiness

Use `enable` only when the selected instance source on its serving node carries
every piece of evidence below:

- `vendor/laravel/octane/` exists. Declaring `laravel/octane` in
  `composer.json` or `composer.lock` is not enough; the vendor directory
  must be installed so the runtime can load Octane.
- The FrankenPHP worker file exists at `<document_root>/frankenphp-worker.php`
  under the app source. The path is resolved against the app's configured
  `document_root`, so an app with the default `document_root=public` is
  checked at `public/frankenphp-worker.php`, an app with `document_root=web`
  at `web/frankenphp-worker.php`, and an app with `document_root=.` at
  `frankenphp-worker.php` directly under the app root. This file is
  generated by `php artisan octane:install --server=frankenphp`.
- `config/octane.php` references `frankenphp` outside of comments. The
  default commented example in `octane.php` does not count as readiness.

Static apps and apps with `runtime != php` always fail readiness;
worker mode requires the FrankenPHP app runtime container.

## Output

Human output is a single status line describing the resulting `worker_enabled`
value, followed by the active worker configuration when worker mode is
enabled.

JSON output returns the worker payload under the standard machine-readable
envelope. See the
[JSON renderer contract](technical/6.2_instance-worker_output-render_json.md) for
the exact payload shape, success and error codes, and field meanings.

## Requirements

- The CLI caller can reach the Orbit gateway.
- The selected instance's serving node is reachable for the readiness probe
  when calling `enable`.
- The current node identity is authorized to manage that instance on its
  serving node. Use `instance:read`
  for `show` and `instance:worker` for `enable` and `disable`.
