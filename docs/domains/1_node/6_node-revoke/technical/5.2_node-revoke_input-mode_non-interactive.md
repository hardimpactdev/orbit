# Non-Interactive Input Mode: `orbit node:revoke [consuming_node] [serving_node]`

[Back to `node:revoke` technical contract.](1_node-revoke.md)

This page describes how non-interactive input mode resolves `node:revoke` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY. Destructive consent follows the shared rule in
[`docs/domains/README.md`](../../../README.md#destructive-confirmation).

App-node callers and unconfigured operator callers are rejected before this input
mode reads command input beyond what is needed to identify the caller-role or
execution-context violation.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when destructive consent (`--force`) is absent.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are known.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `consuming_node` | `[consuming_node]` is absent. | Fail before side effects. |
| `serving_node` | `[serving_node]` is absent. | Fail before side effects. |
| `force` | Non-interactive mode and `--force` is absent. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `consuming_node` does not match an existing active node record;
- `serving_node` does not match an existing active node record.

The selected output renderer owns how these failures are displayed.
