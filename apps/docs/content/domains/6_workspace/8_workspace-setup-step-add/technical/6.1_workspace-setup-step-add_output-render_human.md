# Technical Contract: `orbit workspace-setup-step:add` (Human Renderer)

**Renderer:** Human.

## Primitive

None. The human renderer prints short prose/status lines only and does not render a table, spinner, or progress tree.

[Back to the canonical contract.](1_workspace-setup-step-add.md)

## Progress Tree

No progress tree is rendered. The command performs a single gateway database
write and is expected to complete below one second.

## Output Strings

### Success

```text
Setup step added for instance [app].[instance].
ID: [id]
Command: [command]
Order: [order]
Timeout: [timeout] seconds
```

`Order` shows the absolute position of the new step within
`(instance, phase=setup)`. The renderer does not show "step #N of M"; the full
ordered list is the responsibility of
[`workspace-setup-step:list`](../../9_workspace-setup-step-list/workspace-setup-step-list.md).

### Errors

Standard error strings as defined in
[Failure Semantics](./1_workspace-setup-step-add.md#failure-semantics).
Notable cases include:

- **Validation (timeout)**: "Timeout must be a positive integer."
- **Validation (app)**: "Could not resolve instance. Pass `--instance=<app.instance>`
  or run from inside a registered Instance source or workspace path."
- **Invalid position**: "Both `--before` and `--after` cannot be supplied."
- **Step not found**: "Referenced insertion step [id] not found for app
  '[app]' in phase 'setup'."

## Next Steps

- List current steps:
  `orbit workspace-setup-step:list --instance=[app.instance]`
- Test the setup:
  `orbit workspace:setup` (on a workspace belonging to `[app]`)
