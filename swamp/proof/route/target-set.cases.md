# route:target:set verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a Cluster with a Router and `app-prod` Nodes, development Instances and Routes, and checks the Gateway record, the Router and workload Nodes and real HTTPS requests. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Unpublished development Route | Set the target of an unpublished `pending` development Route. | The Operation has succeeded at once and the Route has the new target. No Node is contacted and no run starts. Setting the same target again is skipped with `route.target_unchanged`. Fails today: the unchanged Route is returned with no reason code. |
| Published development Route | Set the target of a published, not `active`, development Route to another Instance. | The task succeeds. The site moves to the new checkout and requests to the domain are served from it. The association is stored before the run. |
| Publish fails | Make the publish step fail. | The task fails at `Install cert, publish site` with `route.publish_failed`. The new target stays set, and the same request run again succeeds. |
| Production pool | A Cluster-scoped explicit Route with one target. Set a complete set of three. | Each added target is staged and answers the TLS probe with the Route's hostname before it joins the Router pool. The pool serves all three, requests keep succeeding, and the recorded set is cleared. |
| Reassign | Detach an Instance by reassigning it to another Route. | The Instance moves, and a `pending` destination Route becomes `active`. A detached Instance without a disposition is refused with `route.target_disposition_required`. |
| Remove | Detach an Instance with `--remove`. | The removal is authorized and the Instance is retired. Fails today: `--remove` is refused with `route.target_cleanup_unavailable` (503). |
| Same pool again | Repeat a completed pool request. | The request is skipped with `route.target_unchanged` and changes nothing. Fails today: it ends at once with no reason code. |
| Probe fails | Make an added target fail the TLS probe. | The task fails. The Router pool is unchanged and the original associations stay. The staged site serves no traffic. |
| Failure after the switch | Make the retire step fail. | The new associations are written, the new pool serves, and the recorded set and the failed step stay. A different request is refused with `route.target_set_conflict`. Running the same request again finishes. Fails today for a request with dispositions: it is refused with `route.target_disposition_required` because the Instances are already detached. |
| Private DNS | A Node-scoped Route outside the TLD. | Private DNS records and catalog move to the new target and the VPN Node reloads. |
| Single-target refusals | A target that belongs to another Route, and a change that detaches an active Instance from its only Route. | `route.target_conflict`, with nothing changed. |
| Other refusals | A custom proxy Route, a generated Route without an effective TLD, a malformed `--targets` value and a malformed `--reassign` value. | `route.kind_unsupported`, `route.tld_required`, `route.target_id_invalid` and `route.target_disposition_invalid`. Nothing changes. |
| Pool refusals | A duplicate Instance, two targets on one Node, a target of another Project, outside the Cluster, inactive, without a web root, a generated Route, an `app-dev` target, and a Route with a web root. | `route.target_conflict`, `route.target_app_conflict`, `route.target_scope_conflict`, `route.target_inactive`, `route.target_web_root_unsupported`, `route.pool_unsupported` and `route.web_root_unsupported`. Nothing changes. |
| Invalid dispositions | A disposition with an invalid destination, and one that both reassigns and removes. | `route.target_disposition_invalid`. Nothing changes. |
| Active Route | A single-target change of an `active` Route, development or production. | `route.reconciliation_required`. Nothing changes. |
| Busy | Start a second, different target-set change on the Route, and hold the projection lock with another operation. | `route.target_set_conflict` and `app-dev.projection_busy`. The first run is unaffected; an identical second request is accepted. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step. A rerun of the same request finishes. |
| Missing input | In a terminal, run the command with no arguments, then with only the Route. Then run it noninteractively and with `--json` without the Route, and without the target. | The terminal asks for the Route and then the target. Ctrl-C ends with `input.cancelled` and no request. The noninteractive calls are refused with `route.id_invalid` and `route.target_id_invalid`, with no request. Fails today: the arguments are required and nothing prompts. |
| Dropped inputs and lost response | Run with `--idempotency-key`, then lose the response to the start and repeat the command. | The option is refused as unknown, and exactly one Operation exists. Fails today: the CLI offers `--idempotency-key`. |
| Refusals | A caller with no access grant to the Route's Nodes, and an unknown Route or Instance. | `node_access.required` and `http.404`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result with the Operation and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Operation. |
