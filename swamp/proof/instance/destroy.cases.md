# instance:destroy verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, an `app-dev` Node with development Instances (clean, dirty, unpublished, with linked worktrees, with teardown steps, Processes, Schedules, a database and a Route) and an `app-prod` Node with a production Instance. It checks the Gateway records, the Node's files and processes, DNS, Caddy and real HTTPS requests. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Development removal | Remove a clean development Instance with teardown steps, Processes, Schedules, an owned database and a Route. | The teardown steps ran first, the Processes and Schedules are gone, the owned databases and SQLite files are gone, the Route and its DNS records are withdrawn, the checkout is deleted, and the Instance record is gone. |
| Production removal | Remove a production Instance. | The runtime, Processes and Route are removed, then the production user, home and source state. Only the local PHP-FPM tuning and its ownership marker stay. Fails today: the Gateway refuses every production Instance with `operation.kind_unavailable`. |
| Dirty source | A checkout with uncommitted work. | `instance.remove_refused`. Nothing in the checkout is deleted; the Schedule triggers are removed and the Instance is `removing`. With `--force` the work is deleted and the removal succeeds. |
| Unpublished work | A `HEAD` that no origin branch or tag contains. | `instance.remove_refused`; with `--force` the removal succeeds. |
| Linked worktrees | A checkout with registered linked worktrees. | `instance.remove_refused`; with `--force` the checkout and its registered worktrees are removed. Fails today: the Gateway snapshot holds only the Instance, so the refusal and the forced worktree removal are not implemented. |
| Force waives source refusals | A private repository with `gh_cli` source access, and an origin whose fetch fails, each with and without `--force`. | Without `--force` they give `operation.kind_unavailable` and `instance.remove_refused`. With `--force` the removal goes on. |
| Unsafe path | An Instance whose checkout path is not safe to delete. | `instance.checkout_path_unsafe`. Nothing is deleted. |
| Not removable | An Instance that is not active, one whose environment cannot be removed, one with a source layout that is not removable, and a web-serving Instance with no Route. | `instance.remove_refused` each time. Nothing changes. |
| No Route | An Instance of a Project that does not serve the web with no Route, one that never got past source resolution, and one that failed during creation. | The removal succeeds; the last two skip the teardown and the push check. |
| Incomplete clone | The candidate of an incomplete clone. | `instance.clone_in_progress`. |
| Open transfer | An Instance an open transfer owns. | `instance.transfer_incomplete`. Retry the identical transfer request to finish or roll it back. |
| Other removal | Remove an Instance that belongs to a different removal request, add `--force` to a removal that has not failed, and drop it from a rerun after a forced one. | `instance.removal_conflict` each time. After a failed non-forced removal, adding `--force` is accepted. |
| Refusals at admission | An Instance whose account is not an unprivileged account, one with public Reverb attachments, one with analytics tracking hosts, one with an owned database another Instance targets, and one whose Route Node is unavailable. | `instance.destroy_unsupported`, `websocket.route_in_use`, `analytics.tracking_hosts_exist`, `database.removal_conflict` and `route.withdrawal_node_unavailable`. Nothing is removed. |
| Busy | Start a removal while one runs. | `operation.target_busy`. The first run is unaffected. |
| Placement | A placement with no removal flow, and a removal that needs verified source access when it is unavailable. | `operation.kind_unavailable`. Nothing starts. |
| Teardown failure | Make a teardown step fail, then be missing, then outlast its limit. | The task fails with `instance.teardown_step_failed`, `instance.teardown_step_unavailable` and `command.deadline_exceeded`. The Instance stays, its Route is already withdrawn so HTTPS no longer answers, and the Schedule triggers stay removed. The next `instance:destroy` runs the teardown list again. |
| Route withdrawal | Make the Route withdrawal fail. | The task fails with `route.withdrawal_failed`. The Instance stays and a rerun withdraws it. |
| Resume | Interrupt a removal at each phase, then repeat the command. | The rerun finishes the removal without duplicates. A step that fails outside the mapped ones gives `instance.removal_incomplete`, and a failed source removal gives `instance.remove_refused`. |
| Branches | A private repository, a Route domain inside and outside the TLD, an external registered database, and hibernation files. | The token is used and removed also after a refusal, DNS records are removed only for a domain outside the TLD, the external database's records go while its host is unchanged, and the hibernation files are removed. |
| Interrupt | Cancel a run, let one time out, and stop the executor mid-run. | Each ends like a failed step and the rerun finishes. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C, and end of input, also with `--force`. Then run it noninteractively and with `--json` without `--yes`. | The prompt names the Instance by name and ID and the effect, and No is selected. With `--force` it also names dirty work and linked worktrees. Each decline ends with `input.cancelled` and no request. The noninteractive and `--json` calls are refused with `input.confirmation_required` after the read-only lookup of the Instance, which can give `http.404` or `node_access.required` first. `--force` alone never supplies consent. |
| Progress and output | Follow a removal in a terminal, a narrow terminal and a pipe, and press Ctrl-C. | A tree of the task's steps. Ctrl-C stops following, exits 130 and leaves the removal running. A success, a failure and a refusal exit `0`, nonzero naming the failed step, and nonzero with the one-line error. The piped output has no animation or escape codes. With `--json`, nothing prints while it follows, then stdout holds only the final task. Fails today: one `native` row replaces the tree. |
| Missing input | In a terminal, run the command with no argument and cancel the list. Then run it noninteractively and with `--json`. | The terminal lists Instances by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `instance.id_invalid`, with no request. Fails today: the Instance is a required argument, so every call without it is refused by the parser. |
| IDs only | An Instance by name, the ID `0`, the ID `-1` passed after `--`, and `abc`. | `instance.id_invalid`, with no request. Fails today: `-1` without `--` is read as an option and gives a parser error. |
| Idempotency option | Run with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers it. |
| Lost response | Lose the response to the start and repeat the command. | While the first run is live the repeat is refused with `operation.target_busy`; once it has finished, with `http.404`. Exactly one removal exists. |
| Unknown and access | An ID that does not exist, and a caller without a grant to the Instance's Node. | `http.404` and `node_access.required`. Nothing starts. |
