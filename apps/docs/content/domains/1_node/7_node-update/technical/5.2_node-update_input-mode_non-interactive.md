# Non-Interactive Input Mode: `orbit node:update [name]`

[Back to `node:update` technical contract.](1_node-update.md)

This page describes how non-interactive input mode resolves `node:update` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY.

Unconfigured clients are rejected before this input mode reads command input
beyond what is needed to identify the execution-context violation. Callers that
are configured but are not gateways resolve input locally and forward to the
gateway, where grant authorization is enforced.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when no supported field flags are provided.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are known.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `name` | `[name]` is absent. | Fail before side effects. |
| any field | No supported field flags are provided. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `name` does not match an existing active node record;
- `--tld` does not match the single lowercase DNS label syntax;
- `--tld` already belongs to another active node;
- `--gateway-endpoint` does not match the IP address or dotted DNS name syntax;
- `--host`, `--gateway-endpoint`, `--public-ipv4`, or `--public-ipv6` is
  supplied for an operator target node;
- the same field flag is supplied more than once in a single invocation.

The selected output renderer owns how these failures are displayed.
