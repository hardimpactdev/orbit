# Non-Interactive Input Mode: `orbit node:default [name]`

[Back to `node:default` technical contract.](1_node-default.md)

This page describes how non-interactive input mode resolves `node:default` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY.

For direct `set`, gateway hosts are rejected before local default writes.
Supported non-gateway callers validate the target against the configured
gateway or local node registry. The `show` and `clear` sub-actions remain
local-only in supported deployment contexts and perform no grant check.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are known.

## Required Input Failures

There are no required input failures for omitted target input. In
non-interactive input mode, omitting `[name]` and `--clear` selects
the `show` sub-action and returns the current local default.

The `set` sub-action is selected only when `[name]` is supplied. The `clear`
sub-action requires no positional input.

## Validation Failures

Fail before side effects when:

- both `name` and `--clear` are present (mutually exclusive);
- the selected target does not match a visible development node (set
  sub-action);
- the selected target matches a node that is not a development node (set
  sub-action);
- the command is running on a gateway host.

The selected output renderer owns how these failures are displayed.
