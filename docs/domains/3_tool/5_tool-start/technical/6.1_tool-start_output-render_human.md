# Human Renderer: `orbit tool-start`

[Back to `tool-start` technical contract.](1_tool-start.md)

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render an in-progress tree after input resolution and before gateway reads, node inspection, or node apply begins.

```text
┌ Starting Tool
○ Resolve target
○ Read gateway tool configuration
○ Run command action
└ Working...
```

## Success Output

Human success output is concise:

```text
Started <tool> on <node>.
```

Do not add expected lifecycle state, observed state, managed flag, version, or
configuration metadata to the human success line. Detailed inspection belongs to
`tool:show`, JSON output, `doctor --family=tool`, or `tool:logs`.

## Failure Output

Human-rendered failures show the failing field or condition, a concise prose error, and actionable recovery guidance when the operator can resolve the issue.

For `tool.remote_action_failed`, include the immediate apply diagnostic:

- exit code when present;
- a brief stderr summary when present;
- `orbit tool:logs <tool> [--node=<node>]` when the tool declares a log source;
- `orbit doctor --fix --family=tool --restore` for convergence repair.
