# `process:edit` Interactive Input Mode

[Back to `process:edit` technical contract.](1_process-edit.md)

This page describes how interactive input mode resolves `process:edit` input.

**Input mode:** Interactive.

## Selection

Use this input mode only when the process is attached to a TTY and `--json` is not present.

## Prompt Behavior

Prompt for missing required input in this order:

| Field | Prompt primitive | Notes |
| --- | --- | --- |
| `app` | Datatable | Show apps the caller is authorized to manage when app context is absent or ambiguous. |
| `name` | Datatable | Select from existing processes for the resolved app. If no process exists, fail before prompting for an open value. |

Editable fields are not prompted when none are supplied. Instead, show a validation message that at least one editable option is required, then let the operator provide an option or cancel.

Prompt validation runs as soon as the field needed for a decision is known.
