# Interactive Input Mode: `orbit app:prune`

[Back to technical contract](1_app-prune.md)

**Input mode:** Interactive.

This file owns the interactive prompt contract for `app:prune`.

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_app-prune_input-mode_non-interactive.md`](5.2_app-prune_input-mode_non-interactive.md)
even if the process has a TTY.

## Prompt Sequence

### 1. App Selection
If `[app]` is missing from the command line:

- **Prompt ID:** `app_prune.app`
- **Primitive:** `text`
- **Label:** `Which app do you want to prune?`
- **Placeholder:** `e.g. my-app or my-app.orbit.test`
- **Validation:** Must match an existing app record authorized for the caller.

### 2. Destructive Confirmation
If `--dry-run` is **not** present:

- **Prompt ID:** `app_prune.confirm`
- **Primitive:** `confirm`
- **Label:** `Pruning will permanently remove all stale workspaces for '[app]'. Continue?`
- **Default:** `false` (No)
- **Validation:** Boolean. If `false`, the command exits without side effects.

If `--dry-run` is present, this prompt is skipped.

If `--force` is present, this confirmation prompt is skipped and destructive
consent is resolved before side effects begin.

## Primitive References

- [`text`](../../../ux/inputs/text-prompt.md)
- [`confirm`](../../../ux/inputs/confirm-prompt.md)

## Prompt Logic

- **Correction:** An invalid app name causes the prompt to re-render with a validation error.
- **Abort:** A cancelled prompt (Ctrl-C) exits immediately with `ExitCode::FAILURE`.
- No side effects occur after an abort.
