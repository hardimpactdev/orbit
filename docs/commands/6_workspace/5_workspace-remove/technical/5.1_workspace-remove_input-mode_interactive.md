# `workspace:remove` Interactive Input Mode

[Back to canonical technical contract](1_workspace-remove.md)

This page describes how interactive input mode resolves `workspace:remove`
input before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_workspace-remove_input-mode_non-interactive.md`](5.2_workspace-remove_input-mode_non-interactive.md)
even if the process has a TTY.

## Responsibilities

- Read any supplied arguments and options.
- Deny app-node and unknown callers before prompts or side effects.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- Require destructive confirmation before side effects.
- Skip the confirmation prompt when `--force` is present.

## Prompts

### CWD Resolution Confirmation

When the workspace name is resolved from the current working directory rather
than the `[name]` argument, the renderer must confirm the resolved target
before proceeding to the destructive prompt.

| Property | Value |
| --- | --- |
| Prompt ID | `workspace_remove.confirm_cwd` |
| Primitive | `confirm` |
| Label | `Resolved workspace '{name}' from current directory. Use this workspace?` |
| Source | CWD-based workspace resolution |
| Required | yes |
| Default | `true` |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | If declined, fail before side effects with `Operation cancelled.` |

### Destructive Consent

Orbit requires explicit consent before any destructive action starts.

| Property | Value |
| --- | --- |
| Prompt ID | `workspace_remove.confirm` |
| Primitive | `confirm` |
| Label | `Remove workspace '{name}' from app '{app}' and all owned artifacts? This cannot be undone.` |
| Self-targeting label | `Remove workspace '{name}' from app '{app}'? You are currently inside this workspace's worktree and your shell's working directory will be invalidated.` |
| `--keep-files` label | `Remove workspace '{name}' from app '{app}'? Orbit intent and runtime artifacts will be removed; the worktree directory on the node will be preserved.` |
| Source | interactive destructive consent |
| Required | yes |
| Default | `false` |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | If declined, fail before side effects with `Operation cancelled.` |

The interactive prompt SHOULD list dependent artifact counts (proxy routes,
inherited processes, teardown steps) inline as part of the confirmation
message body so the operator can size the destructive scope before
consenting.

The self-targeting label and the `--keep-files` label use the same prompt ID,
primitive, default, and cancellation behavior. When both apply (operator is
inside the worktree AND `--keep-files` is set), the renderer composes both
sentences in the message body and notes that the worktree will be preserved
so the shell's CWD remains valid.

### Prompt Body — Destructive Consent

```text
You are about to remove the workspace `{name}` from app `{app}`.

This will:
- Delete the gateway intent record (workspace and proxy route rows).
- Stop traffic for the workspace hostname.
- Stop and remove inherited processes.
- Run configured teardown steps.
- Remove the workspace PHP-FPM pool.
- Delete the worktree directory on the node.

Continue?
```

#### Body Delta — `--keep-files`

When `--keep-files` is present, the final bullet is replaced so the operator
sees that the worktree is preserved:

```text
- Leave the worktree directory on the node.
```

#### Body Delta — Self-Targeting

When the caller's CWD is inside the resolved workspace's worktree, prepend
the body with a self-targeting notice:

```text
You are currently inside this workspace's worktree. Removing it will
invalidate your shell's working directory.
```

When both `--keep-files` and self-targeting apply, the self-targeting notice
is softened to acknowledge that the worktree (and therefore the shell's CWD)
will be preserved.

## Flow

1. **Caller Role:** Resolve the caller role and deny `app` or `unknown`
   before any prompt is rendered.
2. **Resolution:** Resolve the workspace from `name` or CWD.
3. **CWD Validation (Optional):** If resolved from CWD, ask
   `workspace_remove.confirm_cwd`. If declined, fail with
   `validation_failed` and `error.meta.field=force`.
4. **Destructive Consent:**
   - If `--force` is present, skip to execution.
   - If `--force` is absent, ask `workspace_remove.confirm` with the
     label and body text resolved for the selected workspace. If declined, fail with
     `validation_failed` and `error.meta.field=force`.
5. **Execution:** Proceed to Phase A (gateway intent removal) and Phase B
   (node-side enactment) per the canonical contract.

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- App-node and unknown callers fail before prompts or side effects.
- Invalid field-local input shows a validation message and re-prompts until
  the value is valid or the user aborts.
- Path eligibility is evaluated as soon as the prompt result makes the
  selected path knowable. If the resolved workspace does not exist, fail
  before side effects after the name is resolved.
- If `--force` is present, skip `workspace_remove.confirm`.
- If the user declines the confirmation prompt, exit with the standard
  command failure status and do not start side effects.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
