# Human Renderer: `workspace:history`

[Back to technical contract.](1_workspace-history.md)

## Primitive

- Output table: [`Laravel\Prompts\table`](../../../../ux/commands/lists/table.md)

## Progress Tree

No progress tree is rendered because execution is a gateway-local database read expected to stay below one second and performs no slow external work.

## Run List

The human renderer outputs a table sorted by `started_at` descending.

### Header
`Workspace History: <project>/<workspace>`

### Table Columns
- **ID**: Run ID or event UUID.
- **Action**: Lifecycle action (e.g., `setup`, `php_update`).
- **Status**: Current status with color coding (Green: `completed`, Red: `failed`, Yellow: `running`, Gray: `cancelled`).
- **Started**: Relative timestamp (e.g., `2 minutes ago`).
- **Duration**: Total time, or `—` (em dash) when start or finish timing is
  unavailable.

### Example

```text
Workspace History: ohdear/feature-docs

ID  ACTION      STATUS      STARTED         DURATION
12  setup       completed   2 minutes ago   45s
11  setup       failed      10 minutes ago  12s
10  creation    completed   1 hour ago      < 1s
```

### Empty State
When no runs match, render:

```text
No run history found.
```

### Run Summary
If a run failed, the renderer may surface the last failed step if available in the history record. For full logs, the user is directed to `workspace:log [id]`.
