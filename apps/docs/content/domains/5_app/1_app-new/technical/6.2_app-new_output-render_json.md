# `app:new` JSON Renderer

[Back to technical contract](1_app-new.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

The JSON renderer returns structured output for automation.

## Envelope

`app:new` consumes a gateway progress stream even when `--json` is selected.
It suppresses intermediate progress and emits exactly one terminal frame.
This is the streamed-command exception allowed by the shared
[JSON Envelope](../../../README.md#json-envelope) contract. Use
`--stream-json` when callers need every newline-delimited progress frame; that
renderer follows [Stream JSON Frames](../../../README.md#stream-json-frames).

## Success Frame

```json
{
  "event": "complete",
  "data": {
    "exit_code": 0,
    "data": {
      "footer": "App 'docs' created.",
      "operation_run": {
        "id": "01J...",
        "operation_id": "f0d...",
        "type": "app:new",
        "status": "succeeded"
      },
      "result": { "action": "created" },
      "app": {
        "name": "docs",
        "node": "app-1",
        "url": "https://docs.example.com",
        "path": "/home/docs/app",
        "root": "public",
        "repository": "git@github.com:my/repo.git",
        "runtime": "php",
        "runtime_config": {
          "proxy_transport": "http"
        },
        "php_version": "8.5",
        "worker_enabled": false,
        "worker_config": null,
        "adopted": false
      },
      "warnings": []
    }
  }
}
```

### Fields

- `event`: `complete` on success.
- `data.exit_code`: `0` on success.
- `data.data.result.action`: Always `created` for `app:new`.
- `data.data.app`: The canonical app JSON entity defined in
  [`5_app/README.md`](../../README.md#app-json-entity). `app.repository` is
  the canonicalized cloned repository or the canonicalized `--new-repo`
  destination. It is never the template repository.
  No `auth_method` or credential metadata is included; credentials are owned by
  the target node, not by `app:new`.
- `data.data.warnings`: Structured non-fatal drift and retry handoffs. Each entry
  carries `code`, `family`, `message`, and `next_command`.

## Error Shapes

Validation, authorization, or connectivity failure before the progress stream
starts uses the normal shared error envelope:

```json
{
  "error": {
    "code": "app.collision",
    "message": "App name 'docs' is already registered in the gateway app registry on node 'app-2'.",
    "meta": {
      "name": "docs",
      "node": "app-2"
    }
  }
}
```

After the progress stream starts, failure is emitted as one terminal
`{"event":"error","data":{...}}` frame containing the gateway error payload
and non-zero `exit_code`.

### Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (e.g. unsupported `--php-version`). `error.meta.field` names the offending input. |
| `app.ineligible_node` | The caller may run `app:new`, but the resolved target node is not a node with an app role. |
| `app.collision` | The app name is already registered in the gateway app registry. `error.meta.node` reports the existing owning node. |
| `app.source_creation_failed` | Template repository generation or repository clone failed on the target node before gateway app configuration was written. `error.meta.reason` describes the failure; `error.meta.transport=github\|ssh\|https` identifies the repository transport. |
| `app.enactment_failed` | Registry write succeeded but node-side artifacts failed in a way that cannot be retried through convergence. |

### Common Warning Codes

Non-fatal drift is reported in `data.data.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`.

| Code | Family | Meaning |
| --- | --- | --- |
| `app.php_version_unavailable` | `app` | The requested PHP version is supported by Orbit but the matching image is not yet available on the owning node. Make the image available, then `doctor --family=app --restore` converges. |
| `proxy.domain_inactive` | `proxy` | The production domain is not yet active because DNS or TLS prerequisites are pending. Retry with `app:register [name] --domain=<host>`. |
| `proxy.enactment_failed` | `proxy` | App-owned proxy route configuration was recorded, but backend proxy artifact application needs retry through `doctor --family=proxy --restore`. |
| `process.runtime_backend_unavailable` | `process` | App-instance-owned process definitions exist, but the selected process runtime backend is unavailable on the instance's serving node. `doctor --family=process --restore` will converge once the backend is available. |
| `process.runtime_unit_missing` | `process` | An app-instance-owned runtime artifact—either a configured process unit or the instance's concrete runtime container—could not be rendered, loaded, or started during initial application. `doctor --family=process --restore` will repair it. |
