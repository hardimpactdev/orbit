# JSON Renderer: `orbit node:list`

[Back to `node:list` technical contract.](1_node-list.md)

This page describes the JSON-rendered output for `node:list`.

**Renderer:** JSON renderer.

## Primitive

None. JSON renderer emits the standard envelope only.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even
when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Input mode failures, domain validation failures, authorization failures,
and network failures must all use this envelope.

The node array is rendered as a flat array under `success.data.nodes` rather
than wrapped in a `success.data.list.items` object. When pagination is
introduced in the future, pagination metadata attaches to
`success.meta.pagination` per the shared envelope rules in
[`docs/domains/README.md`](../../../README.md#json-envelope), so the
`success.data.nodes` array contract remains stable.

## Success Shape

```json
{
  "success": {
    "data": {
      "nodes": [
        {
          "name": "app-1",
          "role": "app",
          "environment": "development",
          "platform": "ubuntu_24-04",
          "status": "active",
          "roles": [
            {
              "role": "app-development",
              "status": "active",
              "settings": {
                "tld": "orbit.test"
              }
            },
            {
              "role": "database",
              "status": "error",
              "settings": {}
            }
          ]
        }
      ]
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `node` | array | Ordered list of visible nodes matching the applied filters. |
| `nodes[].name` | string | Node name in the gateway registry. |
| `nodes[].role` | string | Node role: `gateway`, `app`, or `control`. |
| `nodes[].environment` | string \| null | App-node environment: `development` or `production`. `null` for non-app nodes. |
| `nodes[].platform` | string | Structural platform-version identifier such as `ubuntu_24-04` or `macos_15-4`. `unknown` when the gateway has not yet detected the platform. Never `null`. |
| `nodes[].status` | string | Durable registry lifecycle: `provisioning` or `active`. |
| `nodes[].roles` | array | Composable role assignments for the node, ordered by role. Empty when no role assignments exist. |
| `nodes[].roles[].role` | string | Hosted or special role assignment name, such as `gateway`, `app-development`, `app-production`, or `database`. |
| `nodes[].roles[].status` | string | Role assignment convergence status: `pending`, `active`, `error`, or `removing`. |
| `nodes[].roles[].settings` | object | Role-local desired settings for that assignment. Empty object when the role has no stored settings. |

Nodes that are not visible to the authenticated caller are omitted from the
array. `node:list` does not return placeholder rows for hidden nodes and does
not include a per-node `visible` field. Callers whose identity is not
authorized to read the registry at all receive `error.code=authorization_failed`
instead of an empty array.

### Success with `--doctor`

`--doctor` is an explicit secondary operation. Doctor results attach under
`success.meta.doctor` as a top-level summary object, not under each
`nodes[]` entry. This keeps the durable registry payload separate from
execution-time inspection data and matches the precedent set by
[`node:remove`](../../8_node-remove/technical/6.2_node-remove_output-render_json.md),
which reports secondary node-family drift under `success.meta.warnings[]`.

The command exits zero whenever the registry read succeeds, regardless of
how many doctor failures are reported. Doctor findings are informational
metadata on a successful list response. Operators who want
exit-on-drift semantics should run `orbit doctor --family=node [--json]`.

```json
{
  "success": {
    "data": {
      "nodes": [
        {
          "name": "app-1",
          "role": "app",
          "environment": "development",
          "platform": "ubuntu_24-04",
          "status": "active",
          "roles": [
            {
              "role": "app-development",
              "status": "active",
              "settings": {
                "tld": "orbit.test"
              }
            }
          ]
        }
      ]
    },
    "meta": {
      "doctor": {
        "checked": 3,
        "issues": 1,
        "failures": [
          {
            "node": "app-1",
            "code": "node.wireguard_peer_missing",
            "message": "WireGuard peer not responding.",
            "family": "node",
            "next_command": "doctor --family=node --node=app-1"
          }
        ]
      }
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `doctor.checked` | integer | Number of nodes checked by doctor. |
| `doctor.issues` | integer | Number of nodes with issues. |
| `doctor.failures` | array | Per-node failure summary. Omitted when no issues exist. |
| `doctor.failures[].node` | string | Node name with the issue. |
| `doctor.failures[].code` | string | Stable node-family issue code from [`node-doctor.md`](../../node-doctor.md#node-issue-codes), namespaced under singular `node.*`. |
| `doctor.failures[].message` | string | Human-readable issue description. Automation must not parse it. |
| `doctor.failures[].family` | string | Doctor family that owns the drift. Always `node` for `node:list --doctor`. |
| `doctor.failures[].next_command` | string | Suggested follow-up command, such as `doctor --family=node --node=app-1` for unsupported issues or `doctor --restore --family=node --node=app-1` for restorable issues. |

### Empty result

When no nodes match the filters:

```json
{
  "success": {
    "data": {
      "nodes": []
    }
  }
}
```

## Error Shapes

### Invalid filter value

`--role` and `--environment` accept a single enum value each. Comma-separated
input is not supported and fails with the same `validation_failed` shape
because the supplied string is not one of the allowed values.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Invalid value for --role: 'invalid'. Allowed values: gateway, app, app-development, app-production, database, control.",
    "meta": {
      "field": "role",
      "value": "invalid",
      "allowed": ["gateway", "app", "control"]
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to list nodes.",
    "meta": {}
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to read the node registry.",
    "meta": {
      "caller_role": "app"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `nodes[].role` | `gateway`, `app`, `control` |
| `nodes[].environment` | `development`, `production`, `null` |
| `nodes[].platform` | Platform-version identifier such as `ubuntu_24-04` or `macos_15-4`; `unknown` when not detectable yet. Never `null`. |
| `nodes[].status` | `provisioning`, `active` |
| `nodes[].roles[].role` | `gateway`, `app-development`, `app-production`, `database` |
| `nodes[].roles[].status` | `pending`, `active`, `error`, `removing` |
| `doctor.failures[].code` | Singular node issue codes from [`node-doctor.md`](../../node-doctor.md#node-issue-codes), such as `node.wireguard_peer_missing` or `node.app_ssh_unreachable`. |
| `doctor.failures[].family` | `node` |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed` |

The `error.code` values listed here are exhaustive for `node:list`. Add a new
value to this renderer contract before implementing another JSON failure code.
