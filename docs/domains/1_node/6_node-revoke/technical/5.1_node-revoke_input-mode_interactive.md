# Interactive Input Mode: `orbit node:revoke [consuming_node] [serving_node]`

[Back to `node:revoke` technical contract.](1_node-revoke.md)

This page describes how interactive input mode resolves `node:revoke` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_node-revoke_input-mode_non-interactive.md`](5.2_node-revoke_input-mode_non-interactive.md) even if the process has a TTY.

App-node callers and unconfigured operator callers are rejected before this input
mode renders any prompt.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- Require destructive confirmation before side effects.
- Skip the confirmation prompt when `--force` is present.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `node_revoke.consuming_node` | `[consuming_node]` is missing. |
| 2 | `node_revoke.serving_node` | `[serving_node]` is missing. |
| 3 | `node_revoke.confirm` | `--force` is absent and both node names are valid. |

## Prompt Mapping

### `node_revoke.consuming_node`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select the consuming node` |
| Source | `[consuming_node]` |
| Required | yes |
| Choices | Visible active nodes. |
| Default | none |
| Validation timing | When `[consuming_node]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

### `node_revoke.serving_node`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select the serving node` |
| Source | `[serving_node]` |
| Required | yes |
| Choices | Visible active nodes. |
| Default | none |
| Validation timing | When `[serving_node]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

### `node_revoke.confirm`

| Property | Value |
| --- | --- |
| Primitive | `confirm` |
| Label | `Revoke access from '{consuming_node}' to '{serving_node}'? This cannot be undone.` |
| Self-lockout label | `Revoke this operator node's gateway access? This machine will lose Orbit gateway access.` |
| Source | interactive destructive consent |
| Required | yes |
| Default | `false` |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | If declined, fail before side effects with `Operation cancelled.` |

Use the self-lockout label when `node_revoke.self_lockout=true` (the consuming
node matches the authenticated operator caller and the serving node is the
gateway). The self-lockout prompt uses the same prompt ID, primitive, default,
and cancellation behavior.

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid supplied field-local input fails before side effects. Prompted values
  are selected from visible active nodes.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If a target node does not exist, fail before side effects after
  that name is resolved.
- If `--force` is present, skip `node_revoke.confirm`.
- If the user declines the confirmation prompt, exit with the standard command
  failure status and do not start side effects.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
