# Human Renderer: `orbit update:all`

[Back to `update:all` technical contract.](1_update-all.md)

This page describes the human-rendered terminal output for `update:all`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../ux/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `update:all` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

`update:all` performs local and remote update work and may take longer than one
second. The human renderer must show an in-progress tree after caller-role and
authorization checks pass and before side effects begin.

```text
┌ Updating Orbit nodes
○ Pulling source - local
○ Pulling source - gateway
○ Pulling source - app-1
└ Working...
```

Each row represents one Orbit checkout target. While a target is being updated,
the row label changes to the active stage:

```text
┌ Updating Orbit nodes
● Done - local
◉ Installing dependencies - gateway
○ Pulling source - app-1
└ Working...
```

This example shows a control caller whose local checkout is not the gateway.
The non-local target list is populated after gateway intent has been resolved;
until then, the caller-local checkout is shown by its local target row.

Valid in-progress labels are:

- `Pulling source - <node name>`;
- `Installing dependencies - <node name>`;
- `Running migrations - <node name>`.

When a target succeeds, its row changes to `Done - <node name>`. When it fails,
its row changes to `Failed - <node name>` and the command prints the captured
failure output below the tree.

For control callers, gateway-owned work is streamed back over the typed
Gateway API as progress events. The control CLI renders those events locally so
the operator sees gateway and app-node targets move through the same stage
labels without waiting for one blocking response.

## Success Output

On full success:

```text
┌ Updating Orbit nodes
● Done - local
● Done - gateway
● Done - app-1
└ Successfully updated 3 nodes
```

The exact target labels come from the caller-local target and gateway node
intent. The success output must not claim that app deployments, state-family
drift, or runtime readiness have been verified.

## Failure Output

Human-rendered failures must show:

- every target that succeeded;
- every target that failed;
- the failed update output when available;
- no JSON envelope.

When the local checkout fails, remote targets are not attempted:

```text
Failed to update local Orbit checkout.
composer not found
```

When a remote target fails, later targets continue:

```text
┌ Updating Orbit nodes
● Done - local
● Done - gateway
✖ Failed - app-1
● Done - app-2
└ Failed
Failed to update node app-1.
Permission denied (publickey).
```
