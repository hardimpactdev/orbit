# JSON Renderer: `orbit update`

[Back to `update` technical contract.](1_update.md)

This page describes the JSON-rendered output for `update`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even
when the process has a TTY.

## Relationship to human progress

The JSON renderer does not emit ANSI progress trees or live step events. It
reports the terminal state of the same local update steps that the human
renderer displays live: `pull_source`, `install_gateway_dependencies`, and
`run_gateway_migrations`. The gateway dependency and migration steps are
gateway-context steps only; source-mounted targets update the mounted source
and keep `/usr/local/bin/orbit` pointed at `<source>/apps/cli/orbit`.

Consumers that need machine-readable progress should use the stable
`steps[]` identifiers and statuses from the final JSON envelope. Human terminal
progress remains owned by the human renderer.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Local prerequisite failures, update-step failures, and migration failures must
all use this envelope.

## Success Shape

```json
{
  "success": {
    "data": {
      "update": {
        "scope": "local",
        "target": "local",
        "status": "completed",
        "steps": [
          {
            "name": "pull_source",
            "status": "completed"
          },
          {
            "name": "install_gateway_dependencies",
            "status": "completed"
          },
          {
            "name": "run_gateway_migrations",
            "status": "completed"
          }
        ]
      }
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `update.scope` | string | Always `local` for `orbit update`. |
| `update.target` | string | Always `local` for the caller-machine checkout. |
| `update.status` | string | `completed` when all local update steps succeed. |
| `update.steps[]` | array | Ordered local update steps. |
| `update.steps[].name` | string | Stable step identifier. |
| `update.steps[].status` | string | Step status. Successful output uses `completed`. |

## Error Shapes

### Local update failed

```json
{
  "error": {
    "code": "local_update_failed",
    "message": "Failed to update local Orbit checkout.",
    "data": {
      "output": "local Orbit entry point did not respond to --version"
    },
    "meta": {
      "failed_step": "install_gateway_dependencies"
    }
  }
}
```

### Local checkout unavailable

```json
{
  "error": {
    "code": "local_checkout_unavailable",
    "message": "Local Orbit checkout cannot be updated.",
    "meta": {
      "path": "/home/orbit/orbit"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `update.scope` | `local` |
| `update.target` | `local` |
| `update.status` | `completed` |
| `update.steps[].name` | `pull_source`, `verify_entry_point`, `install_gateway_dependencies`, `run_gateway_migrations` |
| `update.steps[].status` | `completed`, `failed` |
| `error.code` | `local_update_failed`, `local_checkout_unavailable` |

The `error.code` values listed here are exhaustive for `update`. Add a new
value to this renderer contract before implementing another JSON failure code.
Captured command output is diagnostic data and belongs under `error.data.output`,
not `error.meta`.
