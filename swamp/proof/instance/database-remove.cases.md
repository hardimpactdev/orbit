# instance:database:remove verification cases

`instance:database:remove` removes a Database connection from an Instance's stored configuration and has no chart. The proof runs the built CLI against a fresh nested topology with an active Instance that has two connections under different prefixes, an Instance that is not active, and unrelated stored keys. It compares the output with the Gateway records and the stored keys. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Remove | Remove one connection with `--force`. | The mapping and the keys of its prefix are gone. The other prefix and the unrelated keys stay, and the connection stays registered. No Node is touched, no task starts, and the workload `.env` is unchanged until `env:sync`. |
| Prefix | Remove with the default prefix and with `--prefix=REPORTING`. | Only the attachment with that prefix goes. |
| Unknown attachment | A connection that is not added, one added under another prefix, and a repeat after a success, with and without `--force`. | `database.attachment_missing` for each, with nothing changed and no prompt in a terminal. Fails today: a terminal asks for consent first, and a call without `--force` gives `database.confirmation_required` before the attachment is checked. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C and end of input. Then run it noninteractively and with `--json` without `--force`. | The prompt names the slug, the Instance by name, the prefix and the effect, with No selected. Each decline ends with `input.cancelled` and removes nothing. The noninteractive and `--json` calls are refused with `database.confirmation_required` and remove nothing. With `--force` there is no prompt, also with `--json`. Fails today: the prompt shows the Instance selector as typed, and the CLI asks before it checks the attachment. |
| Selector | `--instance` by ID, by exact Route domain, by a domain that is not exact, and `--instance=0`, `--instance=-1` and `--instance=abc`. | The ID and the exact domain work. Each other value is refused with `http.404` and nothing is removed. | Run with `--force`.
| Instance state | With `--force`: an Instance that is not active, an Instance whose Route is changing, an Instance without a recorded source profile, and an Instance whose remaining stored configuration is already invalid. | `env.owner_unavailable`, `env.owner_unavailable`, `instance.source_profile_missing` and `env.configuration_invalid`. Nothing is removed. |
| Unknown and access | An unknown connection slug, an invalid slug, and a caller without a grant to the Instance's Node, in a terminal and noninteractively without `--force`. | `http.404`, `database.slug_invalid` and `node_access.required`, reported before any prompt or `database.confirmation_required`. Nothing is removed. Fails today: the CLI sends the request after consent, so a terminal prompts first and a call without `--force` gives `database.confirmation_required`. |
| Invalid prefix | A lowercase prefix, one that starts with a digit, an empty `--prefix=`, `--prefix=DB-X`, and one of 33 characters. | `database.prefix_invalid` for each, with no request. |
| Partly stored prefix | Remove an attachment of which a hand edit left only some keys. | All keys of the prefix that exist are removed, and `Keys` still lists the six names. |
| Missing input | In a terminal, run the command with no arguments and cancel each list. Then run it noninteractively and with `--json`. | The terminal lists the Instances and then the connections added to the Instance. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `database.slug_required` or `database.instance_required`, with no request. Fails today: the slug is a required argument, so a call without it is refused by the parser, and the Instance is never prompted for. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail with the fields on the page at the wide width and labeled records at the narrow one. The piped output has no animation or escape codes. With `--json`, stdout holds the fields and `request_id`. The Host and Port show `—`, Changed is `true`, and Stored keys equals the number of keys left on the Instance. Fails today: the detail names the Instance by ID only. |
| Competing changes | Remove while `env:sync`, `env:update` or another database change runs on the same Instance. | Both changes complete, no write is lost, and the stored keys equal those of running the two in some order. |
| Activity | After a successful removal and a failed one. | Activity and the error hold no stored value. |
