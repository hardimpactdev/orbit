---
title: Prospective Route Node rendering
description: Capture admitted enrollment values and role readiness before Node identity commits.
---

An enrollment parent keeps its stored Node identity unchanged until success. `NativeRouteNodeRender($guestNodeId, $admittedWireguardIp, $admittedTld)` carries the admitted address and normalized TLD for rendering, with an optional captured role certificate plan for prospective publication. It is not a Node model or an Operation. The parent authenticates its original aggregate and selects that descriptor explicitly for forward public reads. Restoration uses the fresh stored identity instead.

`RouteRenderContext::render($candidate, fn () => $canonicalPublicInput())` scopes those values to one render and restores the previous context even on error. The canonical DNS, Route and Caddy readers use the descriptor only when the actual stored Node ID matches. Every other Node and all Route rows still come from fresh stored state. The basic address/TLD descriptor changes neither the parent root identity nor its target, participants, worker transport, account, certificates, or custody.

The Node enrollment parent selects the descriptor from its immutable admitted guest and candidate. It keeps the existing public metadata and actual parent Node. It does not use a worker ID or coordinator ID as the guest identity. It wraps its existing fresh public input builder in the render scope. While `state.node_wireguard_restoring` is true, it omits the scope and renders fresh stored values. Other family publication paths omit the scope and continue to render stored values.

The scope applies to DNS suffixes, exact Route answers, requester address keys, Caddy listener and upstream addresses, and native Route endpoint probes. Literal Route domains, explicit upstream URLs and all placement rules remain stored policy. A missing candidate address in a stored provisioning row does not hide that admitted Node from prospective DNS. The scope never writes Node values, moves Route ownership, changes credentials or selects an effect worker. Native Swamp steps still perform every effect.

`NativeNodeRolePublicationInput::capture(Node, RoleName, ?NodeEnrollmentCandidate)` captures an existing admitted role assignment for a standalone role root. It returns the unchanged `NodeRoleCertificateInput` certificate plan, `publications` with each participant's connection and immutable `before`/`after` snapshots, and `participant_node_ids` including209. The role's existing publication duties select Caddy, PHP pools and private DNS for each snapshot. A component is `null` when the Node has no admitted duty for it; parents skip that component. It reads the complete Route site catalog so unrelated sites and pools remain present.

The `before` snapshot uses actual stored certificate and serving markers. The `after` render uses only the certificate leaves in the admitted plan as prospective readiness. Existing role site sources still own their render policy. Prospective WebSocket DNS selects the admitted target after its Caddy publication, without writing a serving marker. The render restores its previous scope even on failure. Capture writes no Node, role, certificate or serving state and creates no Operation. This helper supports convergence of an existing assignment; relocation and removal keep their owning admissions.

The parent passes the public capture unchanged to native steps. It orders certificate publication before the captured Caddy/PHP configuration and private DNS after Caddy succeeds. Compensation selects the captured `before` snapshot. Terminal projection alone records the observed certificate and serving markers. Native steps make no Gateway reads.

For enrollment, the optional immutable candidate has the same actual Node ID. `RouteRenderContext::renderEnrollment()` extends the canonical readers to its name, account, WireGuard address, TLD, LAN address and Cluster membership. The existing three-field Route descriptor keeps its address/TLD behavior. Capture renders `before` outside candidate and planned-certificate scopes and renders a fresh complete site catalog for `after`. Nested scopes restore their original values after success or failure. Neither render changes the actual Node or assignment.

A candidate without a stored complete host key has an explicit pending publication target: its real `node_id`, `control_node_id:209`, candidate WireGuard address and account, port22, the canonical209 identity file, and `host_keys:null`. Null requires native binding; it is never an accepted SSH pin list.

Before any authenticated effect, the composing parent compares the official bootstrap collection with the admitted fingerprint. It binds only the pending row matching that candidate ID, address, account and port to the verified full host keys through its full SSH globals. Other participants keep their stored full pins. A pinned candidate keeps the canonical stored keys with its prospective address and account.

`rolePublicationBindingSteps(name, publicationsExpr, candidateExpr, fullGlobals, dependency?, guard?)` emits one pure metadata step on209. Its `outputs.publications` preserves stored participants and replaces only the matching pending row's null keys with the verified keys in the parent's `target` host globals. Wrong IDs, addresses, users, ports, identity paths, duplicate pending rows, missing targets and empty pins fail before dependent effects. It does not collect keys, authenticate to a target or replace the parent's fingerprint comparison.

Enrollment passes its already captured role certificate plan as the optional fourth argument, `roleCertificates`, to `NativeRouteNodeRender`. `NativeRouteNodeMutationInput::capture` applies that plan only while rendering prospective Route publications, including prepared, withdrawn, final Caddy/PHP and private DNS snapshots. Actual `before` and restore snapshots retain stored certificate readiness. The parent publishes the role certificates before these prospective Route configurations. It does not wrap the whole capture in a certificate render scope or record certificate markers early. Omitting the plan preserves ordinary Node capture behavior; the capture, native factory and terminal projection contracts stay unchanged.

Enrollment Route capture may pass the same `NodeEnrollmentCandidate` as the optional fifth `NativeRouteNodeRender` argument. Its Node ID, WireGuard address and TLD must match the descriptor and actual aggregate. Discovery, BEFORE and restoration artifacts use stored identity. AFTER scopes the full candidate name, account, LAN and cluster values through the canonical enrollment readers and scopes prospective role certificate readiness independently.

A candidate with no stored host pin produces an explicit `host_keys: null` publication row in both directions, with its admitted WireGuard address and account. The parent must bind that row using the existing `rolePublicationBindingSteps` for each phase's `publications` before composing `routeMutationSteps`. The binder requires the same candidate ID, address, account, canonical identity and verified full host keys. Every other participant requires stored pins. Stored targets retain their actual restoration connection and account; capture never clones or persists a Node.
