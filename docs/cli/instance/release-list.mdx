title: "orbit instance:release:list"
sidebarTitle: "instance:release:list"
description: "List the releases in the home of a production Instance and the selected one."
---

```bash
orbit instance:release:list <instance> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID of an active production Instance, or of a development `default` Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Print the releases as JSON. |

```bash
orbit instance:release:list 14
```

In a terminal, an omitted Instance is chosen from an interactive list. A noninteractive or `--json` call without it is refused with `instance.id_invalid` and sends no request, and so is a value that is not a positive integer.

The command answers from the Gateway's deployment history and contacts no Node. Every deploy and rollback is a run whose terminal result the Gateway records, so the history knows which releases a deploy's cleanup removed. The list holds the retained releases, sorted by name, not by age: the first release, `initial`, sorts after the timestamp-named ones. A clean home keeps 3 releases, as [Retained releases](/reference/deployments#retained-releases) describes. The list is what the history retains, not a scan of the Node: a release that someone removed by hand is still listed, and a release that the Node keeps because a running process uses it is not. The history holds the newest 50 runs of the Instance, so a run that is older than that is not counted, and a deploy that timed out records no selection. This is the same history that a rollback checks.

The output has these parts:

- The table, with the columns `RELEASE` and `SELECTED`. `SELECTED` reads `yes` for the release the Instance serves and `no` for the others.
- `Selected release:` with the selected release, or `—` when none is selected.
- The request ID.

An Instance with no release says `No retained releases found.`. A development `default` Instance deploys in its checkout, so its list is empty. A development Instance with another name is refused with `deployment.identity_invalid`.

With `--json`, stdout holds `{ releases, selected_release, request_id }`, and `selected_release` is null when none is selected. See [`instance:deployment:list`](/cli/instance/deployment-list) for the recorded run history behind the releases.

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The Instance is missing or is not a positive integer, and the CLI cannot prompt. |
| `input.cancelled` | You cancelled the Instance list. |
| `deployment.identity_invalid` | The Instance is not an active production Instance with a release layout and a recorded user and home. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |
