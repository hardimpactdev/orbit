## Usage

```bash
orbit node:converge <node> [--force] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `node` | yes | Node ID; see the [Node selector contract](/cli/node). |

| Option | Default | Meaning |
| --- | --- | --- |
| `--force` | off | Re-apply every footprint artifact even when its recorded digest matches. Access, eligibility and locking checks still apply. **Target restart policy:** restart only for changed state, not merely because this option was passed (stage-2 requests `effect:binaries` and `effect:force` below). |
| `--idempotency-key=KEY` | none | Shared [keyed-start option](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Use the [CLI standard's machine output](/reference/cli-ux#input-and-output-modes). |

```bash
orbit node:converge 7
orbit node:converge 7 --force
```

[Required-input interaction](/reference/cli-ux#input-and-output-modes) follows the CLI standard.

## How it works

Orbit admits only an active, managed Linux Node that the calling Node has an access grant to. It reserves the target and its VPN hub against another converge.

The [footprint reference](/reference/node-provisioning#converge-the-orbit-footprint) owns artifact identities, digests and the workload boundary: converge does not run `node:add`, replace an Instance checkout, or change role assignments. It can repair a Node that owns Instances.

### Target flow

The six-phase flow below is an unimplemented target, not a guarantee of the current command. The runnable `required-phases` cases check phase names and counts, not machine effects. Stage 2 must implement the missing effects and add the fixtures and assertions named under `uncovered` in the [proof specification](https://github.com/hardimpactdev/orbit/blob/main/swamp/proof/node/converge.cases.yaml). Each target names its capability request:

1. **Orbit binaries** (`effect:binaries`). Install the release-pinned Node agent and Orbit CLI, the agent's configuration and service, `orbit-env` access to Instance `.env` files, and the temporary-file cleanup rule.
2. **Role software** (`effect:software`). Apply the release recipe's common and role software before Tools. Keep recipe packages held so a Tool cannot move tested software, while allowing Ubuntu security updates.
3. **Roles** (`effect:roles`). Apply the active roles' configuration. Treat Instance `.env` permission cleanup and recorded Route residue cleanup as best effort.
4. **Tools** (`path:tools`). Apply recorded Tools, if any. Mark a failed Tool on its own record, continue with the others, and allow the task to succeed.
5. **Network** (`path:network`, `effect:no-network`). Apply the recorded network, hub first and then the Node. Skip this phase without a recorded hub; write no file and reload nothing when live state matches.
6. **Check** (`effect:check`). Check the required software, units, sites, and a recent tunnel handshake. A hub with no peers needs no handshake check.

The target repeat checks live required state rather than trusting the recorded digest alone (`effect:check`). If everything matches and no Tool failed, it must succeed as skipped with `node.footprint_unchanged`. The runnable `already-applied` case checks the skip reason and presence of the check phase; the live-state and Tool assertions still need the capabilities above.

The target failure contract retains completed work and partial changes within a failed phase, skips later work, and performs no rollback. A new invocation starts at the first phase and repairs what does not match; stage-2 request `effect:partial-failure` covers the missing fault injection and state assertions.

Target cleanup removes temporary execution files after work stops on success or failure, reports incomplete cleanup without hiding the original failure, and waits for confirmation that interrupted work has stopped. A worker crash alone proves no cleanup; stage-2 request `effect:cleanup` covers folder inspection and cleanup/interruption faults.

## Errors

| Code | Meaning |
| --- | --- |
| `node.id_invalid` | The supplied numeric Node ID is outside the accepted positive-integer range. |
| `node.converge_unsupported` | The Node is not an active, managed Linux Node. |
| `operation.target_busy` | Another converge holds the target or its VPN hub. |
| `node_access.required` | The calling Node has no access grant to the target. |
| `node.footprint_failed` | A required footprint part cannot be rendered, or a required part did not complete. |
| `operation.kind_unavailable` | A required footprint contribution has no supported action; refusal occurs before Node changes. |
| `operation.native_failed` | Execution failed; the failed phase identifies where it stopped. |
