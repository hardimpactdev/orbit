# JSON Renderer: `orbit doctor`

[Back to `doctor` technical contract.](1_doctor.md)

This page describes the JSON-rendered output for `doctor`.

**Renderer:** JSON renderer.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even when
the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Healthy diagnostics are returned under `success.data.doctor`. Drift,
probe/action failures, scope failures with a diagnostic, and unsupported mode
failures with a diagnostic return that diagnostic under `error.data.doctor`.

`issues` always means issues remaining after the selected mode completes.
`actions` records fixes, adoptions, skips, conflicts, and failures attempted
during `--fix` or `--adopt`.

## Success Shape

```json
{
  "success": {
    "data": {
      "doctor": {
        "mode": "verify",
        "healthy": true,
        "scope": {
          "self": true,
          "node": "mini",
          "app": null,
          "workspace": null,
          "families": ["node"]
        },
        "summary": {
          "issues": 0,
          "fixed": 0,
          "adopted": 0,
          "skipped": 0,
          "conflicts": 0,
          "failed": 0
        },
        "issues": [],
        "actions": []
      }
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `doctor.mode` | string | `verify`, `fix`, or `adopt`. |
| `doctor.healthy` | boolean | `true` when no drift or probe errors remain after the selected mode. |
| `doctor.scope` | object | Resolved family, node, app, workspace, and self scope. |
| `doctor.summary` | object | Counts for remaining issues and attempted actions. |
| `doctor.issues` | array | Remaining issues after the selected mode completes. |
| `doctor.actions` | array | Actions attempted during `--fix` or `--adopt`; empty in verify mode. |

Issue objects contain generic fields plus family-specific detail:

| Field | Type | Meaning |
| --- | --- | --- |
| `family` | string | Product family key. |
| `node` | string \| null | Node name when the issue is node-scoped; `null` when not node-scoped. |
| `kind` | string | Generic doctor issue kind. |
| `code` | string | Concrete family issue code, such as `node.app_ssh_unreachable`. |
| `key` | string | Stable affected-resource key within the family and scope. |
| `summary` | string | Human-readable issue summary. Automation must not parse it. |
| `fixable` | boolean | Whether the issue can be repaired by `--fix`. |
| `adoptable` | boolean | Whether the issue can be adopted by `--adopt`. |
| `details` | object | Optional family-specific diagnostic metadata. Omitted when absent. |

Action objects contain:

| Field | Type | Meaning |
| --- | --- | --- |
| `family` | string | Product family key. |
| `node` | string \| null | Node name when the action is node-scoped; `null` when not node-scoped. |
| `code` | string | Issue code or action code the action responds to. |
| `key` | string | Stable affected-resource key within the family and scope. |
| `mode` | string | `fix` or `adopt`. |
| `status` | string | `completed`, `skipped`, `failed`, or `conflict`. |
| `summary` | string | Human-readable action summary. Automation must not parse it. |
| `details` | object | Optional family-specific action metadata. Omitted when absent. |

## Error Shapes

### Drift detected

When drift remains, return an error envelope with the diagnostic payload under
`error.data.doctor`:

```json
{
  "error": {
    "code": "drift_detected",
    "message": "Doctor found drift.",
    "data": {
      "doctor": {
        "mode": "verify",
        "healthy": false,
        "scope": {
          "self": false,
          "node": "app-1",
          "app": null,
          "workspace": null,
          "families": ["node"]
        },
        "summary": {
          "issues": 1,
          "fixed": 0,
          "adopted": 0,
          "skipped": 0,
          "conflicts": 0,
          "failed": 0
        },
        "issues": [
          {
            "family": "node",
            "node": "app-1",
            "kind": "unverifiable",
            "code": "node.app_ssh_unreachable",
            "key": "app-1.ssh",
            "summary": "Gateway cannot reach app-1 over SSH.",
            "fixable": false,
            "adoptable": false
          }
        ],
        "actions": []
      }
    },
    "meta": {
      "issues": 1
    }
  }
}
```

### Caller role not allowed

```json
{
  "error": {
    "code": "caller_role_not_allowed",
    "message": "App-node callers may not run doctor --fix or doctor --adopt for this scope.",
    "meta": {
      "caller_role": "app",
      "mode": "fix"
    }
  }
}
```

### Validation failed

```json
{
  "error": {
    "code": "validation_failed",
    "message": "The --fix and --adopt options cannot be combined.",
    "meta": {
      "fields": ["fix", "adopt"]
    }
  }
}
```

### Mode not supported

```json
{
  "error": {
    "code": "mode_not_supported",
    "message": "The selected doctor issue does not support adoption.",
    "meta": {
      "mode": "adopt",
      "family": "process",
      "code": "process.runtime_unit_extra"
    }
  }
}
```

## Enum And Identifier Values

| Field | Values |
| --- | --- |
| `doctor.mode` | `verify`, `fix`, `adopt` |
| `doctor.scope.families[]` | `node`, `app`, `workspace`, `process`, `proxy`, `firewall_rule`, `tool`, `schedule` |
| `doctor.issues[].kind` | `missing`, `extra`, `divergent`, `unverifiable` |
| `doctor.actions[].mode` | `fix`, `adopt` |
| `doctor.actions[].status` | `completed`, `skipped`, `failed`, `conflict` |
| `error.code` | `drift_detected`, `probe_failed`, `scope_not_found`, `authorization_failed`, `caller_role_not_allowed`, `local_context_invalid`, `gateway_unavailable`, `mode_not_supported`, `validation_failed` |

The `error.code` values listed here are exhaustive for `doctor`. Add a new value
to this renderer contract before implementing another JSON failure code.
