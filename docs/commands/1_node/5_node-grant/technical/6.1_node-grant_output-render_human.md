# Human Renderer: `orbit node:grant [consuming_node] [serving_node]`

[Back to `node:grant` technical contract.](1_node-grant.md)

This page describes the human-rendered terminal output for `node:grant`.

**Renderer:** Human renderer.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `node:grant` has no interactive
prompts because both arguments are required. Non-interactive validation failures
are rendered here as prose errors when `--json` is absent.

## Progress Tree

`node:grant` performs only gateway-owned registry writes with no slow external
work. Execution is expected to complete well below one second on the happy path,
so no progress tree is rendered. If future implementation adds slow external
work, add a progress tree here.

## Success Output

When a new grant is created:

```text
Granted 'control-1' access to 'app-1'
```

When the grant already exists (idempotent success):

```text
'control-1' already has access to 'app-1'
```

## Failure Output

Human-rendered failures must show:

- the failing field or condition;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Missing consuming node

```text
Consuming node is required.
```

### Missing serving node

```text
Serving node is required.
```

### Consuming node not found

```text
Consuming node 'control-1' not found.
```

### Serving node not found

```text
Serving node 'app-1' not found.
```

### Grant policy violation (including self-grant)

```text
Grant from 'control-1' to 'app-1' violates node access policy.
```

### Gateway unavailable

```text
Gateway connection is required to grant node access.
```

### Authorization failed

```text
This control node is not authorized to grant node access.
```

### Caller role not allowed

```text
This command may only be run from a control or gateway node.
```

### Local context invalid

```text
Local node role setting is invalid.
```
