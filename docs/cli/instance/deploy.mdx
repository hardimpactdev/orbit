title: "orbit instance:deploy"
sidebarTitle: "instance:deploy"
description: "Deploy a production Instance as a fresh release, or deploy the newest commit of a development default Instance."
---

```bash
orbit instance:deploy <instance> [--commit=SHA] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID of a production Instance or of an `app-dev` `default` Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--commit=SHA` | newest commit | Deploy exactly this commit, as a manual action. The SHA is 40 or 64 lowercase hexadecimal characters, and the commit must be on the first-parent chain of the deployment branch. See [pinned commits](/reference/deployments#pinned-commits-and-automatic-callers). |
| `--json` | off | Print the final task as JSON, with every step, and nothing while it follows. |

```bash
orbit instance:deploy 15
orbit instance:deploy 15 --commit=3f2a9c1d4b7e8a5f6c0d1e2f3a4b5c6d7e8f9a0b
orbit instance:deploy 15 --json > deploy.json
```

In a terminal, an omitted Instance is chosen from an interactive list. A noninteractive or `--json` call without it is refused with `instance.id_invalid` and sends no request, and so is a value that is not a positive integer. An empty `--commit` is refused with `deployment.commit_required`, and a value that is not a full lowercase SHA with `validation.failed`.

A manual production deploy pauses automatic deployment of the Instance as soon as it is admitted, whether it succeeds or fails. See [automatic deployments](/reference/deployments#automatic-deployments).

For a production Instance, Orbit creates a fresh release, fetches the configured branch or the pinned commit, synchronizes the stored environment values, runs the `before_activation` steps, atomically replaces `current`, refreshes the PHP runtime cache, restarts the Processes that opt in, and runs the `after_activation` steps. For an `app-dev` `default` Instance, Orbit fetches the Project's default branch, checks out its newest commit in the default's checkout, and runs the Project's development deploy steps there. It refuses a checkout with uncommitted changes to tracked files, and a local branch with commits that the fetched commit lacks. A failed required step leaves the new commit checked out. A failed best-effort development step is a warning, and the deployment continues. A development step can fail with `deployment.branch_changed` when the checkout does not match the commit after the steps. See [Deploy](/reference/deployments#deploy) for the steps and the Processes that restart.

A `default` Instance in a container deploys in its container ([chart](https://github.com/hardimpactdev/orbit/blob/main/docs/cli/instance/container/deploy-default.mmd)). Orbit starts the container when it is stopped, fetches the commit into the Node's mirror, and pushes it in. The same refusals apply, and a pinned commit off the branch is refused with `deployment.commit_not_on_branch`. The development deploy steps run as `orbit` in the workspace. After they pass, Orbit takes the seed snapshot that clones copy. See [the default Instance](/reference/development-containers#the-default-instance).

Only `default` can be deployed on an `app-dev` Node. Another development Instance is refused with `deployment_config.unavailable`. Releases, rollback and deploy-step changes are production-only.

The command starts a task and follows it until it ends. Human output shows a progress tree of the task's steps. Glyphs and color show pending, running, succeeded, failed and cancelled steps. The run history keeps no command output, so the tree shows no step output. On failure the tree marks the failed step and shows its error code under it, and the final lines add the failed step, the error code, the selected release when known, the task ID and the request ID. [`instance:deployment:show`](/cli/instance/deployment-show) shows the recorded outcome afterwards.

Pressing Ctrl-C stops following, not the deploy. In human output the CLI prints the command that shows the task, such as `orbit operation:show 42`, and exits 130; with `--json` it prints no line and exits 130. It sends no cancel request; [`operation:cancel`](/cli/operation/cancel) stops a deploy.

| Outcome | Exit status |
| --- | --- |
| The task succeeded. | `0` |
| The task failed or was cancelled. | Nonzero. The command names the failed step and the selected release when the result has one. |
| The Gateway refused the request. | Nonzero, with the one-line error. |
| You pressed Ctrl-C. | `130`. The deploy keeps running. |

A failure while fetching the release, synchronizing the environment, or running a `before_activation` step leaves the prior `current` selected. A failure in the activation steps (Caddy access, `current.next` or the swap) leaves the prior `current` selected when the swap did not happen. A failure after the swap leaves the fresh release selected: the PHP cache refresh, installing a Process or a Schedule timer, restarting a Process, or running an `after_activation` step. Orbit undoes no step and no data change, and the new release folder stays until a cleanup. Deploy again after the fix: it is a new task with a new release.

Deployment, rollback, deploy-step changes, environment changes and removal share one owner for each Instance. A second production deploy while one is queued or running is refused with `operation.target_busy`. A development `default` takes no such hold. A rollback cancels a deploy that no run has started; see [`instance:rollback`](/cli/instance/rollback).

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The Instance is missing or is not a positive integer, and the CLI cannot prompt. |
| `input.cancelled` | You cancelled the Instance list. |
| `deployment.commit_required` | `--commit` is empty. |
| `validation.failed` | `--commit` is not 40 or 64 lowercase hexadecimal characters. |
| `deployment_config.unavailable` | The Instance is not an active production Instance or an `app-dev` `default` Instance, or its account does not match its Project. |
| `deployment.repository_mismatch` | The Project's repository identity does not match its origin (pinned commit). |
| `deployment.projection_pending` | The default Route projection must finish before the deployment. |
| `env.configuration_missing` | A production Instance has no stored environment configuration. |
| `operation.target_busy` | Another operation holds the production Instance. |
| `deployment.source_access_unsupported` | The Project's source access cannot be used for a development deploy. |
| `deployment.commit_not_on_branch` | The pinned commit is not on the first-parent chain of the branch. |
| `deployment.checkout_dirty` | A development default has uncommitted changes to tracked files. |
| `deployment.branch_diverged` | The local default branch has commits that the fetched commit lacks. |
| `deployment.source_failed` | Fetching the repository or preparing the release failed. |
| `deployment.step_failed` | A required `before_activation` or `after_activation` step failed. |
| `deployment.branch_changed` | The development checkout does not match the commit after the steps. |
| `schedule.install_failed` | Installing a Schedule service or timer failed. |
| `deployment.selection_invalid` | Selecting or reading back `current` failed. |
| `deployment.php_runtime_unconfirmed` | The PHP runtime did not confirm the new release. |
| `process.install_failed`, `process.restart_failed` | Installing or restarting a Process failed. |
| `deployment.vp_store_failed`, `deployment.vp_requirements_invalid` | The Vite+ store or the Project requirements failed. |
| `env.sync_unconfirmed`, `env.sync_would_drop_keys` | The `.env` write was not confirmed, or it would drop keys Orbit does not manage. |
| `instance.lifecycle_busy` | A setup or teardown step holds the checkout. |
| `deployment.cancelled`, `operation.timed_out` | The deploy was cancelled, or outlasted its deadline. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |
