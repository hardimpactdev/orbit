Run one turn on the current subtask of an external group. Orbit records the receipt and workspace evidence without advancing the lifecycle. See [Run an external turn](/reference/tasks#run-an-external-turn).

```bash
orbit task:turn <task> --role=implementer --prompt="Implement the brief." --thread=new --idempotency-key=feature.implement.c1
orbit task:turn 43 --role=reviewer --prompt="Review the checked commit." --thread=new --check=19 --json
```

The VM receives the title, brief and deliverables of the subtask, then your prompt, for every role. Send only what this turn adds; do not paste the brief.

`--model` selects a new thread's model. A continued thread keeps its model. A consult uses a reviewer thread and preserves the working tree.

### A task that runs in a copy

A task that owns a [task copy](/reference/tasks#task-copy) runs its turns in it. `task:start` makes one for a Project whose default Instance is a container or that has a nested fleet; a nested-fleet task without a copy refuses with `tasks.no_workspace`. Its turn is the Operation `tasks.copy_turn`: Swamp runs the turn with T3's own CLI in the copy, as `agent`, and records it as it records a task VM turn. What differs:

- Only a new implementer thread runs. A reviewer turn, `--thread=ID` and `--model` answer `tasks.copy_turn_unsupported`.
- The model is the Gateway's `ORBIT_TASKS_COPY_TURN_MODEL`, `claudeAgent/claude-opus-5-5` by default. T3 picks the effort.
- The turn ends after one hour with `tasks.turn_timeout`. T3's CLI cannot stop a run, so the run may go on in the copy.
- While an earlier turn may still run, a turn or a check of the group answers `tasks.copy_turn_unended`. `task:cancel` ends the run with the copy.
- The transcript holds message text only, and the thread has no token metrics.

### In a task copy

<div className="flow-at" data-chart="task/copy-turn"></div>

Swamp locks the step that runs the turn for the whole turn, and a second run that needs the same lock waits 60 seconds and then fails. The lock carries the copy's Instance id: a turn acts only inside its copy and its own run folder. So turns in two copies on one Node run side by side, and one copy still takes one turn at a time.

## Errors

A turn in a task copy adds these answers and Operation errors:

| Code | When |
| --- | --- |
| `tasks.no_workspace` (409) | The group owns no task copy. |
| `tasks.copy_not_ready` (409) | The task copy is not `active` yet: its create or its completion still runs. |
| `tasks.copy_turn_unsupported` (422) | The turn is a reviewer turn, continues a thread or names a model. |
| `tasks.copy_turn_unended` (409) | An earlier turn may still run in the copy; `details.operation_id` names it. Run `task:cancel`. A check of the copy refuses the same way. |
| `tasks.copy_turn_model_invalid` (503) | `ORBIT_TASKS_COPY_TURN_MODEL` does not read `PROVIDER/MODEL`. |
| `tasks.turn_timeout` | The Operation's error: the turn ran past its one-hour bound. |
| `tasks.turn_failed` | The Operation's error: T3's run ended with a status other than `completed` or `waiting`. |
| `tasks.copy_turn_failed` | The Operation's error: T3 did not report the turn's end, for example while its server was down. |
