# Interactive Input Mode: `orbit agent-ide:message [message]`

[Back to `agent-ide:message` technical contract.](1_agent-ide-message.md)

This page describes how interactive input mode resolves `agent-ide:message`
input.

**Input mode:** Interactive.

## Selection

Use interactive input mode when the command runs in a TTY and `--json` is not
present. `--json` always selects the
[non-interactive input mode](5.2_agent-ide-message_input-mode_non-interactive.md),
even when the process has a TTY.

## Prompt Contract

| Prompt id | Field | Primitive | Label | Choices / validation |
| --- | --- | --- | --- | --- |
| `agent_ide_message.message` | `message` | `text` | `Message` | Non-empty text. |
| `agent_ide_message.target` | `app` / `workspace` | `datatable` | `Select an Agent IDE target` | Visible apps and workspaces. Rows identify kind, app, workspace, node, and effective adapter when known. |

## Resolution Rules

- If `[message]` is missing and `--stdin` is absent, prompt with
  `agent_ide_message.message`.
- If `--stdin` is present, read the message body from standard input and do not
  prompt for message text.
- If `[message]` and `--stdin` are combined, fail before target prompts.
- If `--app`, `--workspace`, or current-directory context resolves a target, do
  not prompt for target.
- If no target can be resolved and visible targets exist, prompt with
  `agent_ide_message.target`.
- If no visible target exists, fail with a clear message instead of rendering an
  empty prompt.
- If an adapter cannot be resolved after target selection, fail before delivery
  and do not ask for unrelated input.
- Prompt abort exits with the standard command failure status and no adapter
  delivery.

## Failure Output

Interactive validation failures are rendered by the human renderer. The prompt
flow must not render JSON envelopes.
