```bash
orbit proof:run <commit> [--base=SHA | --all] [--report-only] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `commit` | yes | Full 40 or 64 character lowercase commit SHA. |

The selection list maps the CLI, Gateway, SDK and native execution files for `node:role:add` to its approved cases. Changes to shared proof admission or failure rendering select every available cases file; test-only changes remain skipped.

| Option | Default | Meaning |
| --- | --- | --- |
| `--base=SHA` | none | Prove the union selected by every commit after this ancestor through `commit`, on the `commit` tree. Cannot be combined with `--all`. |
| `--all` | off | Run every case, not only the cases that the commit selects. A cases file with no case yet is listed as uncovered. |
| `--report-only` | off | Record reporting intent. Capacity waits and pool eligibility are the same with or without this flag. |
| `--idempotency-key=KEY` | generated | Retry the same start with a permanent key. See [Start keys](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Print the final result as JSON, with the verdict of each case. |

```bash
orbit proof:run 0123456789abcdef0123456789abcdef01234567
```

In a terminal, an omitted commit is asked for with a text prompt. A noninteractive or `--json` call that omits it is refused with `proof.commit_invalid`, and so is a value that is not a full lowercase SHA. A refused call sends no request.

Orbit selects the cases from the commit and optional ancestor base. The calling Node needs an access grant to the Gateway Node. Continuous integration calls it for every change to command code; see [the proof CI](/reference/feature-flow#the-proof-ci).

Built so far: the trust check, the case selection, the run in copies and the verdict of each case. The CI job `proof-run` is part of Required checks: when it runs, its result always gates the merge, and no switch makes it report-only. Main runs no proof after the merge. Today CI starts no proof: the repository variable `ORBIT_PROOF_ENABLED` is unset ([off in the live fleet](/reference/old-paths#off-in-the-live-fleet)). A failed case or missing verdict fails it. Capacity waits never pass as a proof. Not built yet: the receipt store.

The CI wrapper waits up to 270 minutes, covering the two-hour admission budget and two-hour execution budget with 30 minutes of margin. Its Actions jobs allow 275 minutes. See [CI time budgets](/reference/implementation-loop) for the separate fast-check limits.

The proof CI summary states the [remaining base-refresh limit](/reference/command-development-pipeline#2-development-environment), including when a run passes.

## Which commits Orbit proves

Orbit proves only code that it can trust. The commit must be the head of a branch of the Orbit repository. A commit from a pull request from elsewhere is accepted only when it is the head of that open pull request, the pull request carries the label `run-proofs`, and a maintainer approved exactly that commit. A new push needs a new approval. Orbit fetches the commit itself, so a caller cannot change what runs.

## Which cases run

Orbit lists the files that differ between the commit and its merge base with `main`, and maps each path to commands with the selection list in the commit. A code change runs the command’s whole cases file. A change only to its cases selects added or changed entries and users of changed fixtures, vars or batch setup. The runner expands and compares both definitions. Changes to the runner, selection code or selection list disable narrowing for every selected command. Tooling alone selects no commands. Unknown fixture keys select the whole file. CI publishes its exact base/head result, and Orbit reads it; a missing or invalid result runs the whole file. Deleted entries select nothing. `--all` and an incomplete file list run every case. A selection-list change alone selects nothing. [Choose the cases](/reference/feature-flow#choose-the-cases) holds the mapping rule.

With `--base`, Orbit first verifies that the full lowercase SHA is an ancestor of the tested commit. It selects each intervening commit against that commit's first parent, with that commit's selection list, and unions the selections. Changes that are later reverted still select their cases. Only the newest tree executes, and only the newest exact SHA must pass trust. This does not prove every intermediate tree.

A whole-file selection runs every current case of that file. Narrow selections union case ids, retaining those still present at the tested SHA. Removed files and ids are listed as uncovered with `gone at tested SHA`; they do not fail the proof. The case receipt format stays the same. An equal base and commit selects nothing. Missing or non-ancestor bases are refused; an incomplete history read cannot pass.

When only paths that need no proof changed, such as documentation and charts, the command succeeds with `Skipped — nothing to prove (proof.nothing_to_prove)`. It starts nothing. A path that matches no line of the selection list is refused with `proof.path_unmapped`, so a new kind of file never passes unproven by accident. Paths that are marked as having no case yet, and commands without a cases file, are listed as uncovered in the result and do not fail the run. So is a cases file that states `cases: []`, however it is selected; see [Choose the cases](/reference/feature-flow#choose-the-cases).

## The run

Only one `proof.run` works at a time, including `--report-only` proofs. Operator and CI parents wait in proof Operation id order. While another proof holds the place, the waiting step and recorded capacity reason read `Waiting for proof Operation <id> to finish.` Orbit retries every 20 seconds. A waiting proof has the status `waiting` and no start time, so `orbit operation:list --status waiting` finds it. At admission the status becomes `running`, the start time is set and the step clears. The shown execution duration starts at admission; the wait allowance starts at creation.

A waiting parent holds no proof place. An open parent with recorded runs or an unresolved child holds it. Stale children and their parent's run list cannot hold it alone. Children take no separate proof places. Proofs with nothing to prove, `proof.verify` and base refresh work take none.

What frees the place:

- All children ended and the parent closed.
- The parent was cancelled and its children ended.
- The proof ended while a child still waited its turn: the watchdog pass cancels that child.
- A child that became stale is cancelled and never started.
- A child timed out with a lock held, and the stale-hold release freed it after 60 minutes.
- A child row that nothing ends passed its own deadline plus 60 minutes. Without a deadline, the bound is its last activity plus the longest shard budget of 120 minutes, plus 60 minutes. A timed-out lock holder uses its finish time, or last activity if absent, plus 60 minutes. Orbit leaves the child unchanged, logs `A stale proof child no longer holds the proof place.` when admitting another proof, and reports `gateway.proof_place_stale_child` in [Gateway status](/cli/gateway/status).

A child waiting its turn to start stays protected while its parent is open and within 120 minutes of creation. After that, the bound for a child without a deadline applies. If its parent ended or is missing, the watchdog cancels the waiting child through normal group cleanup. If that recovery fails, the child stops holding the place 60 minutes after its last activity. Released children and children with a native run keep their own budgets and reconciliation. The status group counts stale children and uses the oldest last activity as `since`.

A proof that waits more than 120 minutes fails `proof.capacity_timeout`. This applies to operator and CI parents, including an older parent blocking the queue. Ended or cancelled parents and proofs with nothing to prove leave the queue. Two predecessors of up to two hours each exceed the allowance: a third proof behind them fails by the wait and must be run again.

Each run of a proof gets a copy of the proof Project's default Instance, the Orbit container with its inner fleet. A proof Project without a default container Instance fails its proof with `tasks.vm_runtime_removed`: task VMs are removed ([Task runtime](/reference/tasks#task-runtime)).

A proof puts its copies on free [CI places](/reference/node-settings#ci-places) across all CI Nodes ([ADR 0260](/decisions/0260-share-ci-places-between-runners-and-proof-copies)). A place runs one runner job or one proof copy. The proof takes one copy per free place, and at most one copy per batch. Operator and CI proofs follow the same rule. There is no `proof.copies` limit, and a proof does not read `orbit.tasks.copies_max`: task copies do not use CI places.

A Node offers places to a proof when it [offers proof places](/reference/node-provisioning#proof-copies-on-a-ci-node), records the [hold script](/reference/node-provisioning#proof-places-on-a-ci-node) that this release installs, and holds the default's current seed. The default's own Node holds the seed itself. A Node whose seed is behind offers no place, so one proof never mixes the fleets of two seeds. A Node whose `ci-runner` role has not installed this release's hold script offers no place until a `ci-runner` add or converge of the Node passes.

The free places of a Node are the smaller of two counts:

- its `ci_places` minus its busy runners and minus the proof copies already on it, of any proof (task copies take no place);
- the number of whole copy peaks that its available memory holds. One copy's peak is the Gateway setting `proof.copy_memory`.

Before the admission transaction, the Gateway reads each Node's runner state and its available memory (Linux `MemAvailable`) from Prometheus: the series of the [runner state](/reference/node-provisioning#runner-state-for-the-runner-view) and of the node exporter. A Node without a fresh read offers no place now. `ProofCopyHosts` holds this rule.

With no free place on any Node, the proof waits with the step "Wait for a free CI place" and retries every 20 seconds, within the same two-hour allowance. A busy pool makes a proof wait or take fewer copies; it never takes a busy runner's place.

While a proof holds places on a Node, that Node's idle runners stop, so the one count stays true. Each copy's create holds its place before the copy starts its inner fleet: under one lock per Node, it records its hold and stops idle runner services only down to a limit: the running runners must not exceed the Node's `ci_places` minus the proof holds on it. Exactly the stopped runners are recorded. A proof that takes 2 places on a Node with 5 places and no busy runner stops 2 idle runners and leaves 3 running. A runner is busy while a `Runner.Worker` process runs in it. A busy runner finishes its job and is never stopped. Each copy's destroy drops its hold. When the last hold on the Node goes, the destroy starts exactly the recorded runners again. Every run end, a failure and a cancel too, asks for the destroy. The runners start again when that destroy succeeds; a failed destroy keeps them stopped while the watchdog asks again. [Proof places on a CI Node](/reference/node-provisioning#proof-places-on-a-ci-node) gives the steps on the Node.

A runner can take a job between the read and its stop. It then keeps the job, and the Node runs one more job than its places until that job ends.

Orbit reads the cases at the trusted commit and expands their variant ids. It sums measured case durations from prior reports for each batch. The read-only cases of a batch with no setup, such as refusals and reads, form their own batch, which needs no reset. Each other batch also weighs 180 seconds for its reset and setup. Orbit then assigns the heaviest batches to the least loaded copy. Without the reset weight, many short batches would land on one copy, and that copy would end last. Unseen cases use the median measured duration, or one second when no measurements exist.

A batch that changes the fleet can split by case. While a place is free, Orbit takes the heaviest such batch with two or more cases and cuts it in two, with its cases in file order, where the case seconds of the two parts are closest. It keeps the cut only when the heaviest copy gets lighter, and then tries again. Each part runs on its own copy and pays its own reset and the batch's setup, so each part weighs 180 seconds more than its cases. A case never splits, so its stages stay on one copy. A read-only batch never splits. A batch can split because its cases undo nothing and use their own resources: they need the same starting state, not the same copy. A converge or role-add batch alone was longer than the proof's five minutes.

Each copy's share gets a run budget from its parts, at most two hours. When a share of more than one part needs more and a place on a Node is still taken by a busy runner, the proof waits for another place. With every place free, it runs anyway. Orbit records the verdicts of each batch as the batch ends, so a share that reaches its budget keeps them; only the cases of its unfinished batches are `unrun`.

Admission starts every copy in its transaction, after the trust check passed: a copy holds the inner fleet's Club key, so code that Orbit does not trust never reaches one. Each copy is an `instance.create` on the Node of its place, owned by the run's task group. It starts from that Node's seed: the default's seed pair on the default's Node, the [seed holder](/reference/development-containers#the-seed-on-each-ci-node) on a CI Node. The group has one subtask row and no agent thread.

Orbit starts the children of one proof together. It queues every start after all execution copies succeed. A refusal or definite start failure of one child does not hold its siblings.

A start with no confirmed answer is never submitted again. Recovery finds its run, or the released child's 600-second admission deadline ends it.

The [admission clock](/reference/operations#direct-swamp-starts) begins when a child is released. A child is released only when its copy is `active`; Orbit checks again every 20 seconds. A copy whose create ended without success, whose completion failed, or that is gone, fails its child with `proof.run_failed`, and its cases are `unrun`. A create that ended by its expired budget counts only once the expiry is settled, because Swamp can still reopen it: until then the child waits. The child's end cancels its group, which destroys the copy and releases its [CI place](/reference/node-provisioning#proof-places-on-a-ci-node). A held child that has no copy, which only a Gateway before the copy-only proof admitted, fails the same way.

In each copy, the run first brings in the commit: one Ansible phase on the copy's Node fetches the commit by its SHA from the public Orbit repository through the copy's own network route, as `agent`, the workspace's owner ([ADR 0268](/decisions/0268-one-owner-for-the-workspace)), and checks it out detached. A fetch that fails or takes more than 60 seconds fails the run by name; nothing retries. This fetch is the only way the commit comes in. So a proof copy needs no Git mirror of the Project on its Node: its clone brings no branch into a Node mirror, and a CI Node keeps none. The phase then runs each of the Project's development deploy steps whose inputs changed since the seed, as a deployment does, so `vendor/` and the generated files belong to the commit. Orbit checks that the workspace is at the commit, then runs the copy's assigned batches, read-only batches first. Before the first part, and after each part that can change the fleet, the copy's inner fleet goes back to `base`, which restarts the nested Gateway on the checkout and migrates it forward, and the runner applies the checkout's Swamp grants and Ansible collections. So the fleet runs the code of the commit, not of the seed. `base` holds Nodes that the seed's [refresh](/reference/development-containers#what-a-refresh-skips) converged with the default scope at the seed's commit. So a converge or role-add case finds nothing to change unless the commit under proof or the case's own setup changed an input. Each batch runs its declared setup. A setup failure leaves missing cases unrun. Execution retries nothing.

A proof does not replay flagged cases on the merge base (`fails_on_base: true`). Only the removed task VM run sent the replay its inputs; the replay comes back when it is ported to copies.

Every run end removes its copy: Orbit cancels the run's group with discard, which destroys the copy and drops its hold on the Node's places. That holds after a pass, a failure, a cancel, a timeout, an interruption and a run that never started. A copy that an Operation still holds is asked again. After a Gateway restart the queued cancel runs, and the watchdog asks again for every group that still owns a copy.

Orbit reads the full case reports, checks the expected case identities and merges every copy’s verdicts into one report. A missing, duplicate or unexpected verdict prevents a pass. The line on which a copy's batch reports the reset seconds of its inner fleet is evidence, not a verdict. The proof closes after all runs end and passes only when every selected command has all its cases passed. A selection with no command passes without a copy.

## The execution switch

`proof:run` works in two stages. Admission checks the commit and selects the cases. Execution creates the group and runs them. Execution is on by default: the Gateway setting `proof.execution` (`ORBIT_PROOF_RUN_EXECUTION`) is `true`. Set it to `false` and a commit that selects cases ends with `proof.execution_disabled`, and the proof Operation holds the selected cases and the uncovered paths. While it is off, the command works as a dry run: it creates no group and starts nothing. A commit with nothing to prove still succeeds, and every refusal of admission still applies.

## Verdicts

Each selected case ends `passed`, `failed` or `unrun`. A case that exceeds the budget is `failed`. A case is `unrun` when its setup could not start or the run stopped before it. Neither `failed` nor `unrun` counts as a pass. If the fleet never becomes ready, every selected case is `unrun`.

A run reported as `interrupted` keeps that status and records `outcome: interrupted`. Its coverage is inconclusive, even when every recorded case passed. Orbit keeps completed batch reports when interruption prevents the final report. Completed verdicts stay as they are, including failed cases; missing cases remain `unrun`. After every run ends, the proof is `failed` if any completed case failed or any non-interrupted run did not pass. Otherwise a native interrupted run makes the proof `interrupted`, with `proof.run_interrupted`. Thus a concurrent interruption cannot hide a completed failure. Cancellation, admission interruption, workspace mismatch and timeouts keep their existing failure rules; Orbit does not infer native interruption from them.

The CI summary and receipt preserve `interrupted` and the job exits nonzero. An interrupted outcome never passes, including with all passed rows. Malformed coverage or a nonzero CLI exit cannot pass either.

The result names the commit, each case with its command, selection reason, verdict and duration, and the uncovered paths. The `program` of a case is the cases file and the case id, `swamp/proof/firewall/allow.cases.yaml#new-restricted-allow`; a `failed` or `unrun` case also carries its cause, the failed checks and its failed CLI calls with their exit code, error code and stderr tail ([the run](/reference/verification-cases#the-run)). The copy is destroyed after the run, so the evidence lasts only as long as a receipt store is not built; the verdicts stay in the result.

| Outcome | Exit status |
| --- | --- |
| The proof completed with every selected case passed, or nothing needed a proof. | `0` |
| Native execution was interrupted. | Nonzero; the coverage is inconclusive. |
| A selected case failed or did not run. | Nonzero. The command names each such case and the receipt link. |
| Orbit refused the request. | Nonzero, with the one-line error envelope. |
| You pressed Ctrl-C. | `130`. |
| The process received SIGTERM. | `143`. |

A child whose turn has not come is cancelled without submission if its proof was cancelled or ended. Ctrl-C, or `operation:cancel` on the proof, closes the parent at once and requests cancellation of its runs and groups. Children can continue until cancellation and the copy's destroy finish. Each group ends when its run ends.

## After the run

Orbit cancels the run's group when the run ends, however it ends, which destroys the copy. The verdicts stay as they are. If that cancel fails, the group stays for another `task:cancel --discard`.

A repeat starts a new run, because a proof checks the commit as it is now. The same `--idempotency-key` returns the original run instead of starting another.

## How it works

The Gateway counts the free CI places on every CI Node, balances batches over them, splits a long batch that changes the fleet by case, and starts one copy per place from that Node's seed. Each copy's create stops the Node's idle runners; the destroy of the last copy there starts them again. The copies bring in the commit, run their batches, and the Gateway merges one result.

## Errors

The request answers at once with the proof Operation. The checks of the commit, the selection of the cases and the admission run after that, in a queue job. A refusal of the admission is therefore on the proof Operation, with its code and message, and the command prints it when it follows the proof. The request itself refuses only `proof.swamp_unavailable`, a start that the extension, the access check or the idempotency key refuses, and `proof.commit_invalid`, which the command checks before any request.

| Code | Meaning |
| --- | --- |
| `proof.run_interrupted` | Native execution stopped with inconclusive coverage, without a completed failure taking precedence. |
| `proof.base_invalid` | The range base is not a full lowercase SHA, or it is combined with `--all`. |
| `proof.base_not_ancestor` | The base is missing from the repository or is not an ancestor of the tested commit. |
| `validation.failed` | The request body is invalid. A body with `keep_failed` is refused by that field, whatever its value: the option kept the VM of a failed run, and every run in a copy removes its copy. An older CLI sends it for `--keep-failed`; this CLI has no such option and refuses it with `input.invalid` before any request. |
| `tasks.vm_runtime_removed` | The proof Project has no default container Instance. Task VMs are removed, so a run has nowhere to prove. No case ran. |
| `proof.commit_invalid` | The commit is missing or is not a full lowercase SHA, and the CLI cannot prompt. |
| `proof.commit_not_found` | The Orbit repository has no such commit. |
| `proof.commit_untrusted` | The commit is not the head of a branch of the Orbit repository, nor the head of an open pull request with the label `run-proofs` and a maintainer's approval of exactly that commit. |
| `proof.path_unmapped` | A changed path matches no line of the selection list. The message names the path. |
| `proof.cases_failed` | A selected case failed or did not run. The result holds each verdict. |
| `proof.workspace_commit_mismatch` | The workspace of a run's copy was not at the commit under proof when the run checked it, before any case. No case ran. The result names the commit that was expected and the one the copy had (`workspace.expected`, `workspace.found`, empty when it printed none), and the human output prints both. A failed fetch of the commit fails as `proof.run_failed`. Run the proof again. |
| `proof.run_failed` | The copy, its commit or its inner fleet did not become ready, or its cases printed no verdict. Every selected case of that command is `unrun`. |
| `proof.queue_unavailable` | The queue refused the job that admits the proof. No case ran. Run the command again. |
| `proof.admission_interrupted` | The job that admits the proof was lost before it started the runs. No case ran, and each selected case is `unrun`. Run the command again. |
| `proof.capacity_timeout` | The proof was not admitted within 120 minutes of creation, while waiting for its turn, the working proof or a free CI place. No case ran. |
| `proof.execution_disabled` | Cases are selected, and proof execution is switched off. The input of the proof holds the selected cases and the uncovered paths. |
| `proof.selection_invalid` | The selection list of the commit is malformed. The message names the line. |
| `proof.github_unavailable` | A GitHub read failed with a transport error or a 5xx answer, also after one more read, so the commit or its cases cannot be checked. The message names the read and the status or error class; a failure outside the read itself, such as a malformed answer or a missing App installation, gives GitHub's or the Gateway's own reason. Run the command again. |
| `proof.github_rate_limited` | GitHub refused a read at its primary or secondary rate limit. The message gives the reset time when GitHub sent one. Run the command again after the reset. |
| `proof.github_refused` | GitHub refused a read or the token request with 401, a 403 that is not a rate limit, or another answer that the read does not expect. The message names the read and the status. An operator must check the Gateway GitHub App and its access to the repository. |
| `proof.github_not_found` | A GitHub read answered 404 or 422: the commit, base or tree that the proof needs does not exist. The message names the read. Running the command again does not help. |
| `proof.swamp_unavailable` | No active Swamp Node exists to run the proof. |
| `node_access.required` | The calling Node has no access grant to the Gateway Node. |
| `extension.disabled` | The tasks extension is off. |
