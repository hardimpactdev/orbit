# instance:update verification cases

`instance:update` stores deployment settings on a production Instance and has no chart. The proof runs the built CLI against a fresh nested topology with production Instances and a development Instance, and compares the output with the Gateway records and the next deployment. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Deployment branch | Set `--branch=release`. | `deployment_branch` is `release`, `selected_branch` is unchanged, and the next `instance:deploy` fetches `release`. The result is at once, with no task and no change on any Node. A later Project default branch change does not replace it. |
| Branch names | A valid name with slashes, a name of 255 bytes, one of 256, `HEAD`, a leading `-`, `..`, `@{`, a trailing `.`, a name ending `.lock`, a space, a character from `~^:?*[\`, an empty component, and an empty `--branch=`. | The valid names are stored. The others give `validation.failed`, and the empty one `instance.branch_required` before any request. Fails today: every refusal gives the generic reason `The deployment configuration is invalid.` under `body`. |
| Same value | The stored override again, the selected branch while no override is stored, and the same shared paths again. | The first and the third succeed and change nothing. The second stores that override. No option clears it. |
| Typo | A branch that does not exist in the repository. | It is stored, and the next deploy fails at the fetch. |
| Shared paths | Set a list of two paths, `[]`, and `null`. | The list replaces the effective paths. `[]` disables sharing. `null` restores the Project-type default, `storage` for a Laravel app, and the human output shows that list. The next deploy links exactly those paths. |
| Path rules | An absolute path, one with `..`, a hidden top-level path and `var/.cache`, `releases`, `current`, `env`, `database.sqlite`, `releases/x` and `var/env`, a component starting with a dot, an empty path, a trailing `/`, a space, a non-ASCII character, two overlapping paths, a duplicate, 33 paths, one of 256 bytes, and 32 paths, one of 255 bytes and `Storage` next to `storage`. | `validation.failed` for the refused ones and success for `var/.cache`, `var/env`, 32 paths, 255 bytes and `Storage`. Nothing is stored for a refusal. A symlink or web-root conflict is found at the deploy, not at the update. Fails today: the reason is the generic `The deployment configuration is invalid.` under `body`. |
| Input shapes | `--shared-paths` with text that is not JSON, a JSON object, a list holding a number, `null` or `false`, a trailing comma, an empty `--shared-paths=`, and the text `"storage"`. | `instance.shared_paths_invalid` before any request, also when `--branch=` is empty: the shared-paths error comes first. |
| API and MCP | A body that is not a JSON object, one with an unknown key or `auto_deploy`, an empty body, a non-string `branch`, and an empty `branch`. | `validation.failed` each time, with the reason under `body`. Fails today: the reason does not name the failed field. |
| Both options | `--branch` and `--shared-paths` together, where the second is invalid. | Nothing is stored, not even the branch. |
| No option | The Instance only. | `instance.update_required` before any request. |
| Not available | A development Instance, and a production Instance that is neither source-resolved nor active. | `deployment_config.unavailable`. Nothing is stored. |
| Competing change | Update while another change to the Instance runs. | The update waits for the Instance row lock. |
| Automatic deployment | Update the branch of an Instance with automatic deployment on, once to a branch whose head descends from the deployed commit and once to one that does not. | The automatic deployment setting, its pause and its history are unchanged. The next check deploys the first head, and the second ends with `no_green_commit` or `commit_failed`. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail `Instance: <name>` with ID, Project and Node by name, Status, the Deployment branch when given, the Shared paths when given, the Selected branch and the request ID at the wide width, and labeled records at the narrow one. The piped output has no animation or escape codes. With `--json`, stdout holds the Instance with `deployment_branch`, `shared_paths`, `selected_branch`, `branch_override` and `request_id`. Fails today: the detail shows no Project or Node. |
| Missing input | In a terminal, run the command with no argument and cancel the list. Then run it noninteractively and with `--json`. | The terminal lists Instances by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `instance.id_invalid`, with no request. Fails today: the Instance is a required argument, so every call without it is refused by the parser. |
| IDs only | An Instance by name, the ID `0`, the ID `-1` passed after `--`, and `abc`. | `instance.id_invalid`, with no request. Fails today: `-1` without `--` is read as an option and gives a parser error. |
| Unknown and access | An ID that does not exist, and a caller without a grant to the Instance's Node. | `http.404` and `node_access.required`. Nothing is stored. |
