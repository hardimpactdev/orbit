# `workspace:remove` JSON Renderer

[Back to canonical technical contract](1_workspace-remove.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

This file owns the JSON schema and envelope for `workspace:remove`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[non-interactive input mode](5.2_workspace-remove_input-mode_non-interactive.md),
even when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

The success payload is flat under `success.data`, matching the resolved
[`app:remove`](../../../5_app/6_app-remove/technical/6.2_app-remove_output-render_json.md)
and [`node:remove`](../../../1_node/8_node-remove/technical/6.2_node-remove_output-render_json.md)
exemplars. There is no nested `workspace` wrapper.

```json
{
  "success": {
    "data": {
      "name": "feature-api",
      "app": "my-app",
      "action": "removed",
      "proxy_routes_removed": 1,
      "processes_removed": 0,
      "runtime_container_removed": true,
      "worktree_removed": true,
      "teardown_steps_run": 0
    },
    "meta": {
      "kept_files": false
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `name` | string | The removed workspace name. |
| `app` | string | The parent app slug for the removed workspace. |
| `action` | string | Always `removed`. |
| `proxy_routes_removed` | integer | Count of workspace-owned proxy route rows deleted in Phase A. |
| `processes_removed` | integer | Count of inherited process runtime units stopped and removed in Phase B. |
| `runtime_container_removed` | boolean | `true` when the workspace runtime container configuration was removed on the node. `false` when it was already absent or could not be removed (with a warning under `success.meta.warnings`). |
| `worktree_removed` | boolean | `true` when the worktree directory was deleted. `false` when it was already absent, was preserved by `--keep-files`, or could not be removed (with a warning under `success.meta.warnings`). |
| `teardown_steps_run` | integer | Count of configured workspace teardown steps that ran. |
| `meta.kept_files` | boolean | `true` when the run was invoked with `--keep-files`. Describes the execution mode, not the state of the worktree. |

`success.meta.warnings` is omitted when there are no warnings. When Phase B
node-side artifact cleanup leaves residue behind, the result remains
successful and the recovery warnings are reported under
`success.meta.warnings[]`.

`workspace:remove` does not duplicate drift item shapes for each family in its
own output. Detailed item-level drift belongs to the affected family doctor;
the warning's `next_command` points operators at that doctor.

### Success Delta — `--keep-files`

When `--keep-files` is set, `success.meta.kept_files` is `true` and
`success.data.worktree_removed` is `false`:

```json
{
  "success": {
    "data": {
      "name": "feature-api",
      "app": "my-app",
      "action": "removed",
      "proxy_routes_removed": 1,
      "processes_removed": 0,
      "runtime_container_removed": true,
      "worktree_removed": false,
      "teardown_steps_run": 0
    },
    "meta": {
      "kept_files": true
    }
  }
}
```

The two booleans answer different questions: `data.worktree_removed` is the
state-of-the-world result on the node; `meta.kept_files` is the operator's
choice at invocation time. Together they let automation distinguish
"preserved by request" from "could not be removed and warned."

### Success Delta — Partial Cleanup

If a Phase B step fails after Phase A has succeeded, the result is still
`success` and warnings are included in the metadata.

```json
{
  "success": {
    "data": {
      "name": "feature-api",
      "app": "my-app",
      "action": "removed",
      "proxy_routes_removed": 1,
      "processes_removed": 0,
      "runtime_container_removed": true,
      "worktree_removed": false,
      "teardown_steps_run": 0
    },
    "meta": {
      "kept_files": false,
      "warnings": [
        {
          "code": "workspace.artifact_extra",
          "family": "workspace",
          "message": "Workspace worktree could not be removed during cleanup.",
          "next_command": "doctor --family=workspace --restore"
        }
      ]
    }
  }
}
```

Warning fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `code` | string | Stable warning code keyed to the relevant family doctor. |
| `family` | string | Doctor family that owns the remaining drift. |
| `message` | string | Human-readable warning message. Automation must not parse it. |
| `next_command` | string | Suggested repair command, typically `doctor --family=<family> --restore`. |

## Error Shapes

### Workspace not found

Already-absent removal returns this error shape. `workspace:remove` is an
imperative command against an existing gateway-owned workspace record, not an
idempotent absent-state convergence command.

```json
{
  "error": {
    "code": "workspace.not_found",
    "message": "Workspace 'feature-api' not found in registry.",
    "meta": {
      "name": "feature-api",
      "app": "my-app"
    }
  }
}
```

### Ambiguous workspace name

```json
{
  "error": {
    "code": "workspace.ambiguous_name",
    "message": "Workspace name 'feature-api' matches multiple apps.",
    "meta": {
      "name": "feature-api"
    }
  }
}
```

### Unresolved CWD

```json
{
  "error": {
    "code": "workspace.unresolved_cwd",
    "message": "Current directory is not inside a registered workspace.",
    "meta": []
  }
}
```

### Missing destructive consent

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to remove this workspace.",
    "meta": {
      "field": "force"
    }
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'workspace:remove' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "workspace:remove",
      "serving_node": "app-1"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to remove a workspace.",
    "meta": []
  }
}
```

### Authorization failed after workspace resolution

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'workspace:remove' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "workspace:remove",
      "serving_node": "app-1"
    }
  }
}
```

### Gateway configuration removal failure (Phase A)

Returned only when Phase A (atomic delete of workspace-owned proxy route rows
and the `workspace` row) itself fails. No node-side artifacts have been
touched.

```json
{
  "error": {
    "code": "workspace.removal_failed",
    "message": "Failed to remove the gateway workspace record for 'feature-api'.",
    "meta": {
      "name": "feature-api",
      "app": "my-app",
      "reason": "gateway_database_write_failed"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `action` | `removed` |
| `error.code` | `validation_failed`, `workspace.not_found`, `workspace.ambiguous_name`, `workspace.unresolved_cwd`, `gateway_unavailable`, `authorization_failed`, `workspace.removal_failed` |

The `error.code` values listed here are exhaustive for `workspace:remove`.
Add a new value to this renderer contract before implementing another JSON
failure code.

## Common Warning Codes

Non-fatal drift after Phase A is reported in `success.meta.warnings[]`. Each
warning carries `code`, `family`, `message`, and `next_command`.

| Code | Family | Meaning |
| --- | --- | --- |
| `workspace.artifact_extra` | `workspace` | A workspace artifact (worktree or runtime container) could not be removed and remains on the node. `doctor --family=workspace --restore` will reconcile it. |
| `workspace.teardown_step_failed` | `workspace` | A workspace teardown step exited non-zero during cleanup. The warning carries the offending `step_id` and `exit_code` alongside the standard fields. `doctor --family=workspace --restore` will reconcile it. |
| `proxy.route_extra` | `proxy` | A workspace-owned proxy route could not be removed. `doctor --family=proxy --restore` will reconcile it. |
| `process.runtime_unit_extra` | `process` | An inherited runtime unit could not be stopped or removed. `doctor --family=process --restore` will reconcile it. |
