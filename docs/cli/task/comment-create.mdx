---
title: "orbit task:comment:create"
sidebarTitle: "task:comment:create"
---

Post a typed comment on a subtask. An `assistance_requested` comment flags the subtask and its task as a direction request and records the request in Activity. A `resolution` comment clears the flag. For a tick group, it goes to the subtask's reviewer on a direction request, and to the blocked agent thread on a failure. For an external group, it clears assistance and sends nothing. The [tasks reference](/reference/tasks#assistance-and-resolution) owns these effects.

```bash
orbit task:comment:create <task> [--type=TYPE] [--body=TEXT] [--author=NAME] [--agent-thread=ID] [--json]
```

| Input | Default | Meaning |
| --- | --- | --- |
| `--type=TYPE` | prompt | `assistance_requested` or `resolution`. |
| `--body=TEXT` | prompt | Comment text, at most 100,000 characters. |
| `--author=NAME` | prompt, with your local user name | Who wrote the comment, at most 255 characters. |
| `--agent-thread=ID` | none | Numeric Orbit agent thread ID that the comment concerns. |

A `--json` or `-n` call fails with `task.comment_type_required`, `task.comment_body_required`, or `task.comment_author_required` when a value is missing. An unknown type fails with `task.comment_type_invalid`. An agent thread ID that is not a positive integer fails with `task.agent_thread_invalid`.

A parent ID records assistance only on an open external task after all its subtasks end. Parent resolution clears Direction only. A child ID keeps child assistance and resolution rules. Neither starts work.
