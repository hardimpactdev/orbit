---
title: "orbit instance:mail:update"
description: "Apply the development SMTP path and loopback listeners to one running container."
---

Apply the same mail setup that create and development clone apply automatically. This command updates an existing container without recreating it. Orbit does not change the workspace or restart application Processes.

## Usage

```sh
orbit instance:mail:update 42
orbit instance:mail:update 42 --json
```

| Argument or option | Meaning |
| --- | --- |
| `instance` | Numeric Instance ID. |
| `--json` | [Machine output](/reference/cli-ux#input-and-output-modes). |

On a Node running the configured main Mailpit, Orbit admits only its SMTP endpoint in this Instance's own ACL and installs IPv4 listeners on `127.0.0.1:1025` and `127.0.0.1:2525`. They forward to the Node's bridge gateway and configured SMTP port. No Node converge or contributor configuration is needed.

The result reports applied, unchanged, or skipped. A foreign listener or unit file skips setup with a named reason and leaves the Project's Process running. A repeat with no drift writes nothing and restarts nothing. An endpoint change updates the proxy services; application Processes stay running. See [development containers](/reference/development-containers) for the network and lifecycle rules.

## Errors

| Code | Meaning |
| --- | --- |
| `operation.kind_unavailable` | The Instance has no container runtime. |
| `instance.host_unavailable` | Placement is not development or this Node has no main Mailpit endpoint. |
| `operation.target_busy`, `instance.lifecycle_busy` | Lifecycle work is unfinished. |
| `process.target_inactive` | The container is stopped; Orbit does not start it. |
