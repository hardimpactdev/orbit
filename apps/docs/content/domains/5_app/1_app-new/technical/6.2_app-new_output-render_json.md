# `app:new` JSON Renderer

[Back to technical contract](1_app-new.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

The JSON renderer returns structured output for automation.

## Envelope

`app:new` consumes a gateway progress stream even when `--json` is selected.
It suppresses intermediate progress and emits exactly one terminal frame.
This is the streamed-command exception allowed by the shared
[JSON Envelope](../../../README.md#json-envelope) contract. Use
`--stream-json` when callers need every newline-delimited progress frame; that
renderer follows [Stream JSON Frames](../../../README.md#stream-json-frames).

## Success Frame

Plain `--json` emits one terminal frame as
`{"event":"complete","data":{...}}`. The frame `data` object is the gateway
complete payload and includes both `exit_code` and an inner `data` object
(not the app fields at the outer `data.*` level, and not under
`success`). CLI process exit status remains the process exit code in addition
to the frame field. Use `--stream-json` when callers need every progress frame;
intermediate frames also use the stream envelope.

```json
{
  "event": "complete",
  "data": {
    "exit_code": 0,
    "data": {
      "footer": "Project 'docs' and instance 'docs.production' created.",
      "operation_run": {
        "id": "01J...",
        "operation_id": "f0d...",
        "type": "app:new",
        "status": "succeeded"
      },
      "result": { "action": "created" },
      "app": {
        "name": "docs",
        "repository": "git@github.com:my/repo.git",
        "runtime": "php",
        "runtime_config": {
          "proxy_transport": "http"
        },
        "php_version": "8.5",
        "dependency_audit_status": "unknown",
        "dependency_warning_count": 0,
        "dependency_danger_count": 0,
        "last_dependency_audit_at": null
      },
      "instance": {
        "app": "docs",
        "name": "production",
        "driver": "orbit",
        "driver_config": {
          "environment": "production",
          "node": "app-1",
          "url": "https://docs.example.com",
          "path": "/home/docs/app",
          "root": "public",
          "domain": "docs.example.com"
        },
        "adopted": false,
        "runtime": {
          "runtime": "php",
          "php_version": "8.5",
          "frankenphp_image": "ghcr.io/hardimpactdev/orbit-frankenphp:2-php8.5-bookworm",
          "mode": "classic",
          "configured_mounts": [],
          "required_php_extensions": []
        },
        "worker_enabled": false,
        "worker_config": null,
        "deploy_warmup_paths": [],
        "latest_deployment_status": null,
        "latest_deployment_run_id": null
      },
      "warnings": []
    }
  }
}
```

### Fields

- `event`: `complete` on success.
- `data.exit_code`: Gateway complete-frame exit status (`0` on success). This is
  a frame payload field, distinct from the CLI process exit code.
- `data.data.result.action`: Always `created` for `app:new`.
- `data.data.project`: The canonical project JSON entity defined in
  [`5_app/README.md`](../../README.md#project-json-entity). `project.repository` is
  the canonicalized cloned repository or the canonicalized `--new-repo`
  destination. It is never the template repository.
  No `auth_method` or credential metadata is included; credentials are owned by
  the target node, not by `app:new`.
- `data.data.instance`: The canonical first instance entity. Placement
  fields such as `node`, `url`, `path`, `root`, `domain`, and `environment`
  live in its `driver_config`; `adopted` also belongs to the instance.
- `data.data.footer`: Human footer string for the completed operation.
- `data.data.warnings`: Structured non-fatal drift and retry handoffs. Each entry
  carries `code`, `family`, `message`, and `next_command`.

## Error Shapes

Validation, authorization, or connectivity failure before the progress stream
starts uses the normal shared error envelope:

```json
{
  "error": {
    "code": "app.collision",
    "message": "App name 'docs' is already registered in the gateway app registry.",
    "meta": {
      "name": "docs"
    }
  }
}
```

After the progress stream starts, failure is emitted as one terminal
`{"event":"error","error":{"code":"...","message":"...","meta":{...}}}` frame
matching the shared stream error shape. Process exit status remains the CLI
process exit code.

### Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (e.g. unsupported `--php-version`). `error.meta.field` names the offending input. |
| `project.ineligible_node` | The caller may run `app:new`, but the resolved target node lacks the required `app-dev` role, or lacks `app-prod` when `--domain` is supplied. |
| `app.collision` | The app name is already registered in the gateway app registry. `error.meta.name` identifies it; no placement is implied. |
| `app.path_collision` | The derived first-instance path is owned by another instance. `error.meta.path` and `error.meta.existing_instances[]` identify each dotted selector and serving node. |
| `project.source_creation_failed` | Template repository generation or repository clone failed on the target node before gateway app configuration was written. `error.meta.reason` describes the failure; `error.meta.transport=github\|ssh\|https` identifies the repository transport. |
| `app.creation_failed` | Registry write succeeded but node-side artifacts failed in a way that cannot be retried through convergence. |

### Common Warning Codes

Non-fatal drift is reported in `data.data.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`.
The PHP-image warning names the dotted instance and serving node, and points to
`doctor --family=instance --instance=<app.instance> --restore` for convergence.

| Code | Family | Meaning |
| --- | --- | --- |
| `instance.php_version_unavailable` | `instance` | The requested PHP version is supported, but its image is unavailable on the first instance's serving node. |
| `proxy.domain_inactive` | `proxy` | The production instance domain is not yet active because DNS or TLS prerequisites are pending. Retry with `instance:register <project>.production --domain=<host>`. |
| `proxy.enactment_failed` | `proxy` | Instance-owned proxy route configuration was recorded, but backend proxy artifact application needs retry through `doctor --family=proxy --restore`. |
| `process.runtime_backend_unavailable` | `process` | Instance-owned process definitions exist, but the selected process runtime backend is unavailable on the instance's serving node. `doctor --family=process --restore` will converge once the backend is available. |
| `process.runtime_unit_missing` | `process` | An instance-owned runtime artifact—either a configured process unit or the instance's concrete runtime container—could not be rendered, loaded, or started during initial application. `doctor --family=process --restore` will repair it. |
