---

```bash
orbit instance:rollback <instance> --release=NAME [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID of a production Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--release=NAME` | prompt | The retained release to select, from [`instance:release:list`](/cli/instance/release-list). The name is letters, digits, dots, hyphens and underscores, at most 128 characters, and starts with a letter or digit. |
| `--idempotency-key=KEY` | generated | Reuse a key to retry the same [Operation start](/reference/operations#start-an-operation). |
| `--json` | off | Print the final task as JSON, with every step, and nothing while it follows. |

```bash
orbit instance:release:list 15
orbit instance:rollback 15 --release=20260914T101500Z
```

In a terminal, an omitted Instance is chosen from an interactive list, and an omitted release from the releases that `instance:release:list` shows for the Instance; an empty list fails and the command never invents a default. The list and the check read the same recorded history.

A successful deployment keeps the previous selection and one other release, so these are the rollback targets. A rollback selects the release through `current`, reloads the PHP-FPM service for an Instance that serves PHP, which empties its OPcache and changes no pool or unit, and restarts the active Processes that opt in, with the same opt-out as a deploy. Rolling back to the release that is already selected, or forward to a newer retained one, is admitted. It does not fetch Git, synchronize environment values, run deploy steps, or change database files. Orbit selects the older code only: you own any data or application recovery that the switch needs.

The Gateway checks the Instance and the release against the Instance's recorded deployment history before it records anything. A rollback pauses automatic deployment of the Instance as soon as it is admitted, also after a failure, and it blocks the commit it moved away from for automatic deploys. Automatic deployment stays paused until [`instance:auto-deploy:enable`](/cli/instance/auto-deploy-enable). See [Rollback](/reference/deployments#the-rollback-operation).

The command starts a task and follows it until it ends, as [`instance:deploy`](/cli/instance/deploy) does. Human output shows a progress tree of the steps `Activate release`, `Swap current`, `Refresh PHP cache` for an Instance that serves PHP, `Restart Processes`, `Read current back` and `Check the selection`. On failure the tree marks the failed step and shows its error code, and the final lines add the failed step, the error code, the selected release when known, the task ID and the request ID. `--json` prints nothing while it follows, then the final task document with every step.

A rollback wins over a deploy of the same Instance that no run has started: the deploy ends `cancelled` with `operation.superseded`, and the rollback starts. Today the rollback is refused with `operation.target_busy` instead. A deploy that a run has started keeps the Instance, also while it waits to resume after a lost run, and the rollback is refused with `operation.target_busy` and the deploy's task ID. [One operation at a time](/reference/deployments#one-operation-at-a-time) gives the rules.

Pressing Ctrl-C stops following, not the rollback. In human output the CLI prints the command that shows the task and exits 130; with `--json` it prints no line and exits 130. It sends no cancel request. [`operation:cancel`](/cli/operation/cancel) stops a rollback before its `Swap current` step. Once the release is selected, the rollback finishes the PHP refresh and the Process restarts.

| Outcome | Exit status |
| --- | --- |
| The task succeeded. | `0` |
| The task failed or was cancelled. | Nonzero. The command names the failed step and the selected release when the result has one. |
| The Gateway refused the request. | Nonzero, with the one-line error. Nothing changes. |
| You pressed Ctrl-C. | `130`. The rollback keeps running. |

A failure in `Activate release` or `Swap current` leaves the recorded selection in place, and the result's `selected_release` is null. A failure after the swap, in the PHP refresh, a Process restart or the read-back, leaves the rolled-back release selected and names the failed step; a failure in `Read current back` or `Check the selection` means `current` may not name it, so check it. A run that outlasts its deadline reports `selected_release` null even when the swap already ran, so check `current` then too. A failure outside these steps, such as a lost SSH connection, ends with `operation.native_failed`. Orbit undoes no step. After you fix the cause, run the same command again.

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The Instance is missing or is not a positive integer, and the CLI cannot prompt. |
| `deployment.release_required` | The release is missing and the CLI cannot prompt. |
| `input.cancelled` | You cancelled a list. |
| `deployment_config.unavailable` | The Instance is not a production Instance. |
| `rollback.release_not_retained` | The Instance's deployment history does not retain the release. Nothing changes. |
| `operation.target_busy` | A deploy that a run has started, or another operation, holds the Instance. |
| `operation.native_failed` | A failure outside the mapped steps, such as a lost SSH connection. |
| `validation.failed` | The release name is outside the allowed form. |
| `rollback.release_invalid` | Linking the release failed, for example because it was removed. |
| `deployment.selection_invalid` | Swapping `current` or reading it back failed. |
| `deployment.php_runtime_unconfirmed` | The PHP runtime did not confirm the release. |
| `process.restart_failed` | Reloading or restarting a Process failed. |
| `deployment.cancelled`, `operation.timed_out` | The rollback was cancelled, or outlasted its 900-second deadline. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |
