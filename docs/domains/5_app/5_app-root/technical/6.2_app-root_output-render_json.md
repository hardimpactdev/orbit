# JSON Renderer: `orbit app:root`

[Back to technical contract](1_app-root.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces
non-interactive behavior even when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

### Configuration changed

```json
{
  "success": {
    "data": {
      "app": {
        "name": "docs",
        "node": "app-01",
        "url": "https://docs.test",
        "path": "/home/docs/app",
        "root": "public",
        "repository": null,
        "php_version": "8.5",
        "adopted": false
      },
      "result": {
        "hostname": "docs.test",
        "changed": true
      }
    },
    "meta": {
      "node": "app-01",
      "artifacts_reenacted": true,
      "warnings": []
    }
  }
}
```

### Converged no-op (configuration unchanged, artifacts re-applied)

```json
{
  "success": {
    "data": {
      "app": {
        "name": "docs",
        "node": "app-01",
        "url": "https://docs.test",
        "path": "/home/docs/app",
        "root": "public",
        "repository": null,
        "php_version": "8.5",
        "adopted": false
      },
      "result": {
        "hostname": "docs.test",
        "changed": false
      }
    },
    "meta": {
      "node": "app-01",
      "artifacts_reenacted": false,
      "warnings": []
    }
  }
}
```

`changed=false` is a documented success path. `app:root` is idempotent and
re-applies on every successful run, so calling it with the same
root as a "redo apply" recovery path is safe.
`artifacts_reenacted=false` reports that re-application found no observable
node change; `artifacts_reenacted=true` would still be a valid converged
re-run if application had to repair drift.

### Success with Drift Warning

If the configuration is written but application fails, the command still returns a
`success` envelope (because the configuration change was persisted), and the drift
is reported as a structured warning under `success.meta.warnings[]`.

```json
{
  "success": {
    "data": {
      "app": {
        "name": "docs",
        "node": "app-01",
        "url": "https://docs.test",
        "path": "/home/docs/app",
        "root": "public",
        "repository": null,
        "php_version": "8.5",
        "adopted": false
      },
      "result": {
        "hostname": "docs.test",
        "changed": true
      }
    },
    "meta": {
      "node": "app-01",
      "artifacts_reenacted": false,
      "warnings": [
        {
          "code": "app.fpm_config_mismatch",
          "family": "app",
          "message": "Failed to re-apply PHP-FPM configuration on node 'app-01'.",
          "next_command": "doctor --fix --family=app --app=docs --restore"
        }
      ]
    }
  }
}
```

### Fields

- `app`: The canonical app JSON entity defined in
  [`5_app/README.md`](../../README.md#app-json-entity). `app.root` is the
  current document root recorded in gateway configuration after the run.
- `result.hostname`: The primary hostname for the app.
- `result.changed`: `true` when this run mutated gateway configuration; `false` when
  the supplied root equalled the current configuration and the run was a converged
  no-op.
- `meta.node`: The owning app-role slug.
- `meta.artifacts_reenacted`: `true` when re-application found observable
  changes on the node; `false` when re-application completed as a clean
  idempotent no-op. Both values are valid success outcomes.
- `meta.warnings[]`: Structured non-fatal drift and retry handoffs. Each
  entry carries `code`, `family`, `message`, and `next_command`.

## Error Envelope

### Example: App Not Found

```json
{
  "error": {
    "code": "app.not_found",
    "message": "Application 'missing-app' not found.",
    "meta": {
      "app": "missing-app"
    }
  }
}
```

### Example: Invalid Root

```json
{
  "error": {
    "code": "app.invalid_root",
    "message": "The root path resolves outside the application path.",
    "meta": {
      "field": "root",
      "root": "../outside",
      "resolved_path": "/srv/orbit/outside",
      "app_path": "/srv/orbit/apps/my-app"
    }
  }
}
```

`app.invalid_root` is gateway-side, lexical-only validation against the recorded
`app_path`. Filesystem-level reality (a symlink that escapes the app path,
or a missing directory on the node) is not detected here; it surfaces as
`app.root_outside_path` or `app.root_missing` from `doctor --family=app`
per [`app-doctor.md`](../../app-doctor.md).

### Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation. `error.meta.field` names the offending input. |
| `app.invalid_root` | `root` failed gateway-side string validation (resolves outside the app path, is empty, or is absolute). `error.meta.field=root`, `error.meta.root`, `error.meta.resolved_path`, `error.meta.app_path`. |
| `app.not_found` | The specified application could not be resolved. |
| `caller_role_not_allowed` | The gateway-identified caller role is not permitted to invoke `app:root` (e.g. an app-role peer). |
| `authorization_failed` | The caller does not have permission to manage the application. |

### Common Warning Codes

Non-fatal drift is reported in `success.meta.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`. Codes reuse the `app`
doctor vocabulary defined in [`app-doctor.md`](../../app-doctor.md).

| Code | Family | Meaning |
| --- | --- | --- |
| `app.fpm_config_mismatch` | `app` | The app's PHP-FPM configuration could not be re-applied to match gateway configuration. |
| `app.fpm_config_missing` | `app` | The app's PHP-FPM configuration could not be installed while applying. |
| `app.runtime_config_mismatch` | `app` | Managed app runtime configuration could not be re-applied to match gateway configuration. |
| `app.runtime_config_missing` | `app` | Managed app runtime configuration could not be installed while applying. |

`next_command` for each warning is `doctor --fix --family=app --app=<app> --restore`.

## Enum and identifier values

| Field | Values |
| --- | --- |
| `result.changed` | `true`, `false` |
| `meta.artifacts_reenacted` | `true`, `false` |
| `error.code` | `validation_failed`, `app.invalid_root`, `app.not_found`, `caller_role_not_allowed`, `authorization_failed` |
| Warning `code` | `app.fpm_config_mismatch`, `app.fpm_config_missing`, `app.runtime_config_mismatch`, `app.runtime_config_missing` |

The `error.code` and warning `code` values listed here are exhaustive for
`app:root`. Add a new value to this renderer contract before implementing
another JSON failure or warning code.
