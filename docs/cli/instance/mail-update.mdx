Repair mail for one existing development container Instance. Normally not needed: create, clone and migrate apply it. Contributors set nothing. The [development mail rule](/reference/development-containers#development-mail) defines the default and its limits.

## Usage

```sh
orbit instance:mail:update 42
orbit instance:mail:update 42 --json
```

| Argument or option | Meaning |
| --- | --- |
| `instance-id` | Numeric Instance ID. |
| `--json` | [Machine output](/reference/cli-ux#input-and-output-modes). |

Orbit prepares the SMTP path and the two loopback forwarders first. A Project listener or foreign unit succeeds with `mail_port_in_use` or `mail_unit_conflict` and leaves `.env` unchanged. Otherwise, Orbit matches exactly `MAIL_MAILER=log`, with or without matching single or double quotes, and replaces only `log` with `smtp`, preserving the quote style and line ending. The same three `smtp` forms return `already_smtp`. There is no prompt.

The result names the path status, forwarder ports, and mailer outcome: `changed`, `left_as_written`, `not_present`, or `already_smtp`. A preserved occurrence reports its 1-based line numbers in `lines`. A preceding line outside the [whitelist](/reference/development-containers#development-mail) reports its first 1-based line number as `guard_line`. Mentions in comments and other values also count. No value or file content appears. Repeating a completed update writes nothing and restarts nothing.

Only `changed` clears Laravel's config cache, when PHP and `artisan` exist, then restarts the Instance's running PHP unit and PHP worker Processes. Other Processes stay running. Config-clear failure does not fail the Operation. A failed path or write keeps completed path work and can be retried. The Operation shows a fixed failure code and recognized tool diagnostics, without file content. If its result is not readable yet, Orbit waits for another read instead of recording an empty failure. Atomic replacement preserves ACLs and extended attributes as well as owner, group and mode. The Node removes the one staging file, `/srv/workspace/.env.orbit-mail`, at entry and on exit, including after a forced container stop. The [mail rule](/reference/development-containers#development-mail) states the Node-loss window.

## Errors

| Code | Meaning |
| --- | --- |
| `operation.kind_unavailable` | The Instance has no container runtime. |
| `instance.host_unavailable` | Placement is not development or the Node has no main Mailpit endpoint. |
| `operation.target_busy`, `instance.lifecycle_busy` | Lifecycle or Process work is unfinished. |
| `process.target_inactive` | The container is stopped; Orbit does not start it. |
| `env.configuration_invalid` | The file could not be changed safely. |
