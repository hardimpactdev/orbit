# Human Renderer: `orbit schedule:add`

[Back to `schedule:add` technical contract.](1_schedule-add.md)

**Renderer:** Human terminal renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render an in-progress tree after input resolution. The final step notifies the
Orbit Scheduler so add-time pickup can be confirmed.

```text
┌ Adding Schedule
○ Validate schedule target
○ Validate execution source
○ Apply and verify schedule
○ Notify Orbit Scheduler
└ Working...
```

## Success Output

Render the schedule name, scope, target, interval, timezone, execution source,
execution timeout, enabled state, and scheduler pickup result
(`Scheduler pickup: confirmed` when the gateway heartbeat is present).

## Failure Output

Validation failures render the rejected field. Gateway and authorization
failures render the selected scope when available. When the schedule row was
recorded but the gateway scheduler heartbeat is missing, render
`schedule.target_unreachable` with the gateway node and next command
`doctor --family=schedule`. Application failures render the created schedule
name, drift status, and next doctor command: `doctor --family=schedule --restore`.
