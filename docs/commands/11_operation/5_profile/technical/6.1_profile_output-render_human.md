# Human Renderer: `orbit profile [target]`

[Back to `profile` technical contract.](1_profile.md)

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../ux/progress/progress-tree.md)


## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render this progress tree after input resolution and before the HTTP profile
request begins:

```text
┌ Profiling docs.test/
○ Resolve target
○ Authorize profile read
○ Send request
○ Collect timing data
└ Working...
```

Use the resolved URL path in the title. Use `/` when the profiled URI is the
root path.

Use this label lifecycle:

| Pending | Active | Completed |
| --- | --- | --- |
| `Resolve target` | `Resolving target` | `Resolved target` |
| `Authorize profile read` | `Authorizing profile read` | `Authorized profile read` |
| `Send request` | `Sending request` | `Sent request` |
| `Collect timing data` | `Collecting timing data` | `Collected timing data` |

When the command completes, replace the footer with the result:

```text
┌ Profiling docs.test/
● Resolved target
● Authorized profile read
● Sent request
● Collected timing data
└ Profiled docs.test/ in 115.42ms
```

## Success Output

The human renderer shows a compact request headline:

```text
GET https://docs.test/ 200 in 115.42ms
```

Then render timing rows in request order:

```text
DNS ....................................... 2.15ms
Connect ................................... 3.05ms
TLS ....................................... 8.10ms
Waiting for response .................... 101.18ms
Download response ......................... 5.12ms - 44.1KB
Total ................................... 115.42ms
```

When Toolbar summary data is available, render app-side stages under the
response wait row:

```text
Waiting for response .................... 101.18ms
  Caddy in ............................... 1.50ms
  PHP-FPM ................................ 10.50ms
  Middleware ............................. 10.50ms
  Controller ............................. 80.20ms
  View .................................... 2.30ms
  Toolbar ................................. 3.00ms
  Caddy out ............................... 1.20ms
  Transport ............................... 0.00ms
```

When Toolbar query data is available and query count is greater than zero:

```text
5 queries
```

Slow and duplicate query counts are appended when present:

```text
5 queries, 1 slow, 2 duplicate
```

## Failure Output

Human-rendered failures show the target or field, a clear prose error, and a
recovery command only when the operator can act on it.

Missing target in non-interactive mode:

```text
Specify a target or --app.
```

Conflicting target inputs:

```text
Use either target or --app, not both.
```

Conflicting auth modes:

```text
Use either --as-first-user or --user, not both.
```

Target not found:

```text
No linked app found for the requested profile target.
```

Gateway unavailable:

```text
Gateway connection is required to resolve this profile target.
```

Profile request failed:

```text
Failed to complete profile request.
```

If the failure points at app or proxy drift, render the owning doctor command:

```text
Run the proxy doctor fixer to repair route artifacts.
```
