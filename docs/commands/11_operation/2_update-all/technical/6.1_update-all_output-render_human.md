# Human Renderer: `orbit update:all`

[Back to `update:all` technical contract.](1_update-all.md)

This page describes the human-rendered terminal output for `update:all`.

**Renderer:** Human renderer.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `update:all` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

`update:all` performs local and remote update work and may take longer than one
second. The human renderer must show an in-progress tree after caller-role and
authorization checks pass and before side effects begin.

```text
Updating Orbit installations
  ○ Update local checkout
  ○ Resolve managed installations
  ○ Update gateway
  ○ Update app-1
  ○ Update app-2
```

This example shows a control caller whose local checkout is not the gateway.
The non-local target list is populated after gateway intent has been resolved.
Each target step is updated in place as it starts, succeeds, or fails. The
caller-local checkout is represented only by `Update local checkout`.

## Success Output

On full success:

```text
Updated local Orbit checkout.
Updated node gateway.
Updated node app-1.
Updated node app-2.
```

This example shows a control caller whose selected non-local targets are
`gateway`, `app-1`, and `app-2`. The exact target labels come from gateway node
intent. The success output must not claim that app deployments, state-family
drift, or runtime readiness have been verified.

## Failure Output

Human-rendered failures must show:

- every target that succeeded;
- every target that failed;
- the failed update output when available;
- no JSON envelope.

When the local checkout fails, remote targets are not attempted:

```text
Failed to update local Orbit checkout.
composer not found
```

When a remote target fails, later targets continue:

```text
Updated local Orbit checkout.
Updated node gateway.
Failed to update node app-1.
Permission denied (publickey).
Updated node app-2.
```
