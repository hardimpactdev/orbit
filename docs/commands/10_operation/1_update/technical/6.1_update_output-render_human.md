# Human Renderer: `orbit update`

[Back to `update` technical contract.](1_update.md)

This page describes the human-rendered terminal output for `update`.

**Renderer:** Human renderer.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `update` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

`update` may perform network, dependency installation, and migration work, so
the human renderer must show an in-progress tree after prerequisite validation
and before side effects begin.

```text
Updating local Orbit checkout
  ○ Pull source
  ○ Install dependencies
  ○ Run migrations
```

Each step is updated in place as it starts, succeeds, or fails. The final tree
must make the failed step visible when the command exits with failure.

## Success Output

On success:

```text
Updated local Orbit checkout.
```

The success message may appear after the completed progress tree. It must not
suggest that fleet drift or runtime readiness has been verified.

## Failure Output

Human-rendered failures must show:

- the failed update step;
- a clear prose error;
- captured command output from Git, Composer, or migrations when available;
- no JSON envelope.

Example:

```text
Failed to update local Orbit checkout.
composer not found
```
