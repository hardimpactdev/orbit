# node:role:relocate verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a `vpn` Node, a Metrics Node, and a source Node and a target Node that can each hold the roles. It checks the Gateway record, both machines and real traffic. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Move `websocket` | The source holds `websocket` with a Reverb app. Relocate it with `--force`. | The Operation succeeds and the role is `active` on the target only. A client of an existing Reverb app connects with its old credentials through the target, and the target's ports are open. The source runs no Reverb. The `APP_KEY` is copied only when the target had none. |
| Move `metrics` | The source holds `metrics`, and the target lacks its credentials. | The target runs Prometheus and Grafana with the copied credentials, and none of the target's existing credentials is overwritten. The source's runtime and publication are gone, but the fleet exporters keep running and the new Prometheus scrapes them, and `metrics.orbit` and its certificate still resolve. |
| Move `gateway` | The source holds `gateway`. Relocate it to a Node with an `orbit:gateway-https` rule closed. | The rule is open on the target and gone from the source. The new Gateway Node reaches the `vpn` and `metrics` Nodes, private DNS is published on the `vpn` Node, and the target has the DNS route. Clients on the old address keep working because the source still serves. `vpn`, the checkout, its database, the CA and the SSH keys did not move. |
| Certificate, DNS and ports | A `websocket` move and a role that needs a certificate, with the DNS answer cached by a client. | The certificate is published on the target, the websocket ports open on the target and the retired ones close, and the target's sites are published before DNS. The cached answer keeps working until it expires, and the source is removed only after that. |
| Gateway route fails | Make the DNS route on the target fail. | The move continues and succeeds. The result carries `follow_up`. |
| Metrics follow-up | Move `websocket` or `gateway` while a Metrics role exists. | `follow_up` names `node:role:add <metrics-node> metrics --converge`. Metrics is not reconciled. |
| Swamp | Relocate `swamp`. | `node.role_relocate_swamp_held` before anything is recorded. Nothing changes. |
| Refusals | A role that is not relocatable, a role that is not assigned, a role in a status it cannot be moved from, an unknown `--from`, a `--from` that does not own the move, a target with a conflicting role, and an inactive or unmanaged Node. | `validation.failed` for the first five, `node.role_conflict` and `operation.kind_unavailable`. Nothing changes. |
| Refused moves never prompt | In a terminal, ask for a move that admission will refuse. | The refusal comes before any confirmation prompt. Fails today: the consent check runs first, so the prompt appears and the move is refused afterwards. |
| Consent | In a terminal, read the prompt, decline it, then confirm. Also run noninteractively and with `--json` without `--force`. | The prompt names the Nodes and the role, with No selected. Declining ends with `input.cancelled`. Fails today: the prompt names `node #ID` and the role, with no source. The noninteractive calls get `validation.failed`. No Operation starts until confirmed. |
| Failed target step | Make a step on the target fail, for `gateway` and for `websocket`. | The Operation fails with the step's own code and the failed step `converge:<step>`. The role stays `active` on the target, and the Gateway still resolves its own access. The source still serves traffic. Finished steps stay and nothing is rolled back. Fails today: the role is marked `failed`, which demotes `gateway` and locks the Gateway out. |
| Failed source removal | Make the removal from the source fail. | The Operation fails at `remove:Remove from the source`. The role stays `active` on the target, and the target serves it. Fails today: the role is marked `failed`. |
| Cancel and interrupt | Cancel a run, let one time out, stop the worker mid-run, and press Ctrl-C while the CLI follows. | The claim stays `provisioning`, the Operation ends like a failed step, and the CLI stops following while the Operation continues. The retry with `--from` takes the claim over and finishes. |
| Repeat | Repeat a completed move without `--from`, then with a `--from` for which no earlier relocation exists. | `validation.failed` for both, with no change. |
| Rerun with `--from` | Fix the cause and run the same command with `--from`. | The Operation succeeds and the role is `active` on the target, with no duplicates on either Node. The run folder is removed after both runs. |
| Already on the target | The target holds the role and the source has leftovers. Run with `--from` naming the source. | The leftovers are removed from the source. The target is unchanged. |
| Busy | Start a second add, converge, remove or relocate on the target Node while one runs. | `operation.target_busy`. The first run is unaffected. |
| Missing input | In a terminal, run the command with no arguments. Then run it noninteractively and with `--json` without the Node. | The terminal asks for the Node from an interactive list and the role from the roles that can move. Ctrl-C ends with `input.cancelled` and no request. The noninteractive calls are refused with `node.id_invalid` and no request. Fails today: the arguments are required and nothing prompts. |
| Nodes by ID only | Pass a Node name instead of an ID, for the target and for `--from`. | `node.id_invalid`, with no request. Fails today: the CLI accepts names. |
| Dropped inputs | Run with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers `--idempotency-key`. |
| Lost response | Lose the response to the start, then repeat the command. | Exactly one Operation exists for the move. Fails today: the CLI needs `--idempotency-key` to avoid a second Operation. |
| Refusals on access | A caller without an access grant to the Gateway Node, an unknown target ID. | `node.access_denied` and a not-found error. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result with the Operation and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Operation. |
