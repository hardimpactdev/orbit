# Native Node role addition

`operation-node-role-add-direct` executes one parent run for all mutable roles. Its footprint stages come from `operations/node/footprint_workflows.ts`, the same template as `operation-node-converge-direct`. Do not copy the stage chain or create child workflows.

Gateway admission records public desired state and exact participants. Native system lowers install prerequisites, JavaScript, managers, CI services and role runtimes. Analytics configures ClickHouse on its admitted Node before initializing Plausible. Private runtime material stays inside the existing callback. The agent remains frozen and receives no action commands.

The parent reconciles the complete Metrics fleet, requests local role CSRs, signs on the canonical signer209 and publishes local certificate pairs. It records certificate state before fresh Caddy rendering and WebSocket serving state before DNS. It then captures the current canonical footprint and records trusted bounded outcomes. Confirmed Analytics runtime success remains recorded when later publication fails. Gateway DNS refusal becomes a follow-up warning; boot ordering remains required.

An enrolling `node.add` parent initializes Metrics only for its captured Metrics assignment. The public enrollment view binds the guest, executor, assignment, agent pin, candidate account and address to the fleet owner. Its native arguments retain the Gateway root identity. Other enrollment roles verify the existing Metrics credentials before updating its runtime; standalone Metrics roots retain their own Node binding.

All applicable placements keep exact Node names and string labels. Workerless required members refuse before effects. The root reports admission failures and unhandled native failures without polled recovery or receipt storage. Native fixtures inject host effects; they do not prove live placement or host readiness.

## Native role lifecycle

Role convergence uses the same target chain as addition. Removal records the assignment as removing before fresh publication, reconciles the complete Metrics fleet, withdraws the role site and DNS, then removes only its runtime, certificate pair and firewall rules. The last role restores public SSH before closing role access. Packages, managers and unrelated workloads remain. Offline assertions alone do not prove cleanup.

Relocation converges and publishes the exact target first. The parent records target readiness before source withdrawal. WebSocket source teardown follows the DNS withdrawal grace period. Source cleanup is a placed stage of that same parent; a source failure keeps the confirmed target active and reports incomplete cleanup. Nodes 1 and 18 retain their exact logical placements through the canonical SSH proxy transport.
