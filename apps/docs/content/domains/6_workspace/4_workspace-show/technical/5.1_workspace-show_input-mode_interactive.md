# Interactive Input Mode: `orbit workspace:show [name]`

[Back to `workspace:show` technical contract.](1_workspace-show.md)

This page describes how interactive input mode resolves `workspace:show` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_workspace-show_input-mode_non-interactive.md`](5.2_workspace-show_input-mode_non-interactive.md)
even if the process has a TTY.

## Responsibilities

- Read any supplied arguments and options.
- Apply the default resolution chain when `[name]` is missing.
- Prompt for a workspace row only when the default resolution chain cannot
  produce a target.
- Prompt with the same workspace data table when a supplied `name` is ambiguous
  across multiple apps and `--instance` was not supplied.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.

## Default Resolution

When `[name]` is missing, interactive input mode resolves the workspace in this
order:

1. **CWD resolution.** If the current working directory is inside a known
   workspace path, use that workspace.
2. **Prompt.** If CWD resolution fails, prompt for `workspace_show.workspace`.

When the resolved `name` matches multiple workspace records and `--instance` was not
supplied, prompt with a data table limited to those matching workspace rows.

## Prompts

### `workspace_show.workspace`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select a workspace` |
| Source | `[name]` |
| Required | yes (when defaults cannot resolve) |
| Choices | Visible workspace rows, including parent project and node. |
| Default | none |
| Validation timing | When `[name]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid or ambiguous values fail before side effects; prompted rows are already valid choices. |

## Failure Semantics

- Missing required input is collected by prompt before side effects, but only
  when the default resolution chain cannot produce a target.
- Invalid supplied field-local input fails before side effects. Prompted values
  are selected from visible workspace rows.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  workspace knowable. If the target workspace does not exist or is not visible,
  fail before side effects after the name is resolved.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
