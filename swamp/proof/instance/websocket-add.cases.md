# instance:websocket:add verification cases

`instance:websocket:add` writes a Reverb app's credentials into an Instance's stored configuration and has no chart. The proof runs the built CLI against a fresh nested topology with the websocket role, two registered apps, an active development Instance, an active production Laravel Instance with a public app Route, an Instance that is not active, and a second Instance on the same Route. It compares the output with the Gateway records and the stored keys. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Add an app | Add an app to an Instance without `--public`. | The seven keys are stored with `REVERB_HOST=reverb.orbit`, port 443 and scheme `https`. A private first add touches no Node, no task starts, and the workload `.env` is unchanged until `env:sync`. The output names the keys and holds no value. |
| Replace | Add a second app to an Instance that holds the first. Then repeat with the first app added with `--public`. | The Instance holds only the second app, and its values replace the first's. For the public first app, the Route's Caddy sites no longer serve its paths before the call returns. |
| Repeat | Add the app the Instance already holds. | The call is skipped with `websocket.attachment_unchanged` and `Changed: false`, and the stored keys do not change. Fails today: it succeeds with `Changed: false` and no explanation or reason code. |
| Public | Add an app with `--public` to the production Laravel Instance. Then add the same app again without `--public`. | The host is the Route's domain with port 443 and scheme `https`, and the Route's Caddy sites publish only the attached app's paths. The second call keeps the public choice. A preserving add fails with `websocket.route_collision` after a deployment adds an `/app` route. |
| Private again | Remove the public attachment and add the app without `--public`. | The host is `reverb.orbit`, and the public paths are gone. |
| Public refused | `--public` on a development Instance, on a production Instance without an active public app Route, on a Route that publishes another app, and on an application that declares `/app` routes. | `websocket.public_route_invalid`, `websocket.public_route_invalid`, `websocket.route_app_conflict` and `websocket.route_collision`. Add a case where the agent cannot inspect the routes: `websocket.route_inspection_failed`. Nothing is written. |
| Publication failure | Make the Route's serving Node unreachable, then add `--public`. | `websocket.route_publication_failed`. The stored keys and the attachment are already changed. After the Node is back, a repeat public add publishes. |
| Reserved app | Add the `gateway` app. | `websocket.app_reserved`. Nothing is written. |
| Selector | `--instance` by ID, by exact Route domain, by a domain that is not exact, and `--instance=0`, `--instance=-1` and `--instance=abc`. | The ID and the exact domain work. Each other value is refused with `http.404` and nothing is written. |
| Instance state | An Instance that is not active, an Instance whose Route is changing, an Instance without a recorded source profile, and an add whose keys would exceed the stored-configuration limit. | `env.owner_unavailable`, `env.owner_unavailable`, `instance.source_profile_missing` and `env.configuration_invalid`. Nothing is written. |
| Unknown and access | An unknown app, an invalid app name, and a caller without a grant to the Instance's Node. | `http.404`, `websocket.name_invalid` and `node_access.required`. Nothing is written. |
| Missing input | In a terminal, run the command with no arguments and cancel each list. Then run it noninteractively and with `--json`. | The terminal lists the apps and then the Instances. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `websocket.name_required` or `websocket.instance_required`, with no request. Fails today: the app is a required argument, so a call without it is refused by the parser, and the Instance is never prompted for. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail with the fields on the page at the wide width and labeled records at the narrow one. The piped output has no animation or escape codes. With `--json`, stdout holds the fields and `request_id`. No form holds a key value. Fails today: the detail names the Instance by ID only. |
| Competing changes | Add while `env:sync`, `env:update` or another change runs on the same Instance. | Both changes complete, no write is lost, and the stored keys equal those of running the two in some order. |
| Activity | After a successful add and a failed one. | Activity and the error hold no key value. |
