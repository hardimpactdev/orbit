# Technical Contract: `orbit workspace-teardown-step:add` (Interactive Input)

This contract defines behavior for **interactive input mode**.

[Back to the canonical contract.](1_workspace-teardown-step-add.md)

**Input mode:** Interactive.

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_workspace-teardown-step-add_input-mode_non-interactive.md`](5.2_workspace-teardown-step-add_input-mode_non-interactive.md)
even if the process has a TTY.

## Prompts

| ID | Primitive | Label | Required |
| --- | --- | --- | --- |
| `command` | `text` | Teardown step command | Yes |
| `timeout` | `text` | Step timeout in seconds | No (defaults to `600`) |

## Primitive References

- [`text`](../../../../ux/commands/inputs/text-prompt.md)

## Behavior

- **Validation**: Each field is validated as it is entered. Empty `command`,
  unauthorized `app`, and non-positive `timeout` (including `0`) trigger a
  re-prompt with a validation message. `--before` and `--after` are not
  prompt-driven; they are flag-only and always optional.
- **App Resolution**: `--app`, `.orbit/config`, or CWD path ownership resolves
  the parent app. If no parent app can be resolved, the command fails before
  side effects; it does not ask for an open app value.
- **Position Flags**: Interactive mode does not prompt for `--before` or
  `--after`. Operators choose the resulting position by re-running the
  command with the desired flag, or by reordering through future
  policy-edit surfaces.
