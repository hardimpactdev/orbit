# instance:create verification cases

The proof runs the built CLI against a fresh nested topology with an `app-dev` Node, a Project with a small web app, setup steps and a development Process definition, and a populated `default` Instance. It checks the Gateway record, the Node state and real requests. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Missing input | In a terminal, run the command with no arguments, then with only the project. Then run it noninteractively and with `--json` without the node. | The terminal asks for each omitted input: the Project and Node from interactive lists (Nodes limited to active `app-dev` Nodes), and the name as text with default `default`. An invalid name is asked again. Ctrl-C ends with `input.cancelled` and no request. The noninteractive and `--json` calls are refused with `input.invalid` naming the node, with no request and nothing created. Fails today: the arguments are required and nothing prompts. |
| Default Instance | Create `default` for a web-serving Project. | The task succeeds and the Instance is active at `<apps root>/<slug>/default` on the default branch. `.env` exists with `APP_URL`, a new `APP_KEY` and the database keys, mode 0640, group `orbit-env`. Setup steps ran in order, as the Node user. The terminal showed a progress tree with these steps, then a result that names the Project and the Node. The Processes run. The Route is active, and an HTTPS request to the domain reaches the application, not the wake page. |
| Named Instance | Create `feature-one` without `--branch`, then with `--branch` set to an origin branch, an existing local branch, and a missing one. | Each checkout is on the branch the table in the page names. A missing branch starts at the fetched default-branch commit. An existing local branch is not reset. |
| Default-branch name | Create with the Project's default branch name. | The `default` Instance is created. The result carries `name_converted_from`. |
| Branch cannot resolve | Remove the default branch from the fetched refs, then create a new branch. | `instance.branch_resolution_failed`, nothing created. Fails today: the Gateway has no such code. |
| Invalid branch name | Create with `--branch="a..b"`. | `validation.failed`. No Instance, no Node change. |
| Domain and root | Create with `--domain` and `--root`. | The Route uses the domain and serves the root. A domain owned by another Route is refused with `route.domain_conflict`, with no Instance created. |
| No web pages | Create for a Project that serves no web pages, then again with `--domain`. | The first has no Route and succeeds. The second is refused with `instance.route_unserved`. |
| SQLite copy | The `default` Instance has a SQLite database with rows. Create another Instance. | The new checkout has its own copy with the same rows, and `.env` names it. A change in the copy does not reach the `default` database. |
| Database on a server | Create with `--database-server`, then with a `default` MySQL database on a server. | The owner, database and test database exist on the server. `.env` and `.env.testing` name them. The MySQL data is copied in. Repeating `--database-server` for a finished Instance is refused with `instance.database_server_existing`. |
| Token handling | Create from a private repository. | The clone succeeds. The token is in no process argument, no output and no file left on the Node after the run. |
| Setup step fails | A setup step exits non-zero. | The task fails with `instance.setup_step_failed`, the step name and its output. The teardown steps ran. The Instance, its Route, checkout, database and Processes are gone from the Gateway and the Node. Other Instances and the `default` database are unchanged. A missing command gives `instance.setup_step_unavailable`. Fails today: the Instance is kept. |
| Later step fails | Make the database create, a Process or the site probe fail. | Same as above: the failed step and its error code are in the task, and nothing the run made is left. The Route is withdrawn. Fails today: the Instance is kept. |
| Retry after cleanup | After a failure, run the command again with a different `--branch`. | One Instance, one checkout, one Route and one set of Processes, on the new branch, with no duplicates. |
| Budget ends | Set a setup step longer than the run budget. | The task fails when the budget ends, and the cleanup runs as above. |
| Cleanup fails | Make a teardown step or the removal fail after a step failure. | The task fails with the original error code. The Instance stays marked failed with `details.cleanup = "incomplete"`. A retry with a different `--branch` or `--root` is refused with `instance.placement_conflict`. The same command finishes the cleanup first and then creates, with no duplicates. `instance:destroy` also finishes it. |
| Interrupted run | Stop the run after the clone and before setup, then repeat the command. | The incomplete state stays visible. The repeat finishes the cleanup and creates the Instance without a second checkout or a duplicate database, Process or Route. |
| Already created | Repeat the command for an active Instance. | Exit 0, skipped with `instance.exists` in human and JSON output. No step runs, and no checkout, Process or Route changes. Fails today: the task succeeds with no skip reason. |
| Refusals | A production Node, a task VM Node, an inactive Node, a Node without `app-dev`, an occupied checkout path, an Instance being removed, a database connection name that belongs to another owner, and a caller without an access grant. | `instance.candidate_required`, `instance.task_vm_node`, `instance.node_inactive`, `instance.node_not_app_dev`, `instance.path_taken` or `instance.default_path_occupied`, `instance.removal_conflict`, `instance.database_slug_taken` and `node_access.required`. Nothing is created and no Node changes. |
| Busy Instance | Start a second change to the Instance while a create runs. | `operation.target_busy`. The running create is unaffected. |
