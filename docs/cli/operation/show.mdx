```bash
orbit operation:show <operation> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `operation` | yes | Numeric operation ID. |

A show returns only the recorded state. It makes no Swamp request and never settles or expires an Operation. The terminal event queues the reconciler; a minute sweep also runs it. Terminal state depends on that queue.

JSON returns the parent record, as `GET /api/v1/operations/{operation}` does. The command exits `0` for any status; read `status` for the outcome. `overdue_since` records the existing deadline when a bound Operation times out. `hold_wait_reason` says why a waiting Route write or removal waits ([One Route write per Node](/reference/operations#one-route-write-per-node)); human output does not show it. Human output shows `Overdue since`. This [reporting-only addition](/reference/operations#native-run-budgets) does not ship the final soft/hard-limit design or change cancellation timing.


```bash
orbit operation:show 42
```

## A follow that ends early

A command that follows an Operation, such as `task:start`, `task:turn`, `proof` or `instance:deploy`, first prints the Operation it follows, unless the Operation has already ended:

```text
Following operation 23744. Read it with: orbit operation:show 23744
```

With `--json` the line goes to stderr, so stdout keeps one JSON document. A follow can end before its Operation does: by Ctrl-C, a timeout or a kill. A signal can end the process before the CLI prints anything more, so read the Operation later with this line's id. Ending the follow does not end the Operation, unless the command's page says otherwise.
