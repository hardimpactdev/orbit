# Human Renderer: `orbit process:stop [name]`

[Back to `process:stop` technical contract.](1_process-stop.md)

This page describes the human-rendered terminal output for `process:stop`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render the complete progress tree after input resolution and before side effects begin. `process:stop` performs remote runtime actions.

```text
┌ Stopping Processes
○ Resolve runtime units
○ Stop runtime units
○ Record process events
└ Working...
```

## Success Output

For a named process:

```text
Process 'vite' stopped for app instance 'docs.production'
```

For a workspace context:

```text
Process 'vite' stopped for workspace 'feature-docs' on app instance 'docs.development'
```

When `[name]` is omitted:

```text
2 processes stopped for workspace 'feature-docs' on app instance 'docs.development'
```

## Failure Output

Human-rendered failures must show the failing field or phase, clear prose, no JSON envelope, and next-step guidance only when the operator can act on it. Bulk failures must identify the failed process names and leave successful processes visible in the summary.
