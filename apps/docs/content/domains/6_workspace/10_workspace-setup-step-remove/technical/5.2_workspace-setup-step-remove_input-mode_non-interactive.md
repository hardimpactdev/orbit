# Technical Contract: `orbit workspace-setup-step:remove` (Non-Interactive Input)

This contract defines behavior for **non-interactive input mode** (e.g., CI,
scripts, or when `--json` is present).

[Back to the canonical contract.](1_workspace-setup-step-remove.md)

**Input mode:** Non-interactive.

Use this input mode when either condition is true:

- the command is running without a TTY (non-tty);
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode (forces
non-interactive) even when the process has a TTY. This input mode never
renders prompts and never waits for user input; there are no fallback
prompts.

## Responsibilities

- Read supplied arguments and options.
- Fail before side effects when required input is absent.
- Fail before side effects when destructive consent (`--force`) is absent.
- Never render prompts.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `step` | `--step` is absent. | Fail before side effects with `error.code=validation_failed`, `error.meta.field=step`. |
| `app` | A concrete app instance cannot be resolved from `--app`, `.orbit/config` marker, or gateway path-ownership lookup. | Fail before side effects with `error.code=validation_failed`, `error.meta.field=app`. |
| `force` | `--force` is absent. | Fail before side effects with `error.code=validation_failed`, `error.meta.field=force`. |

## Validation Failures

Fail before side effects when:

- `--step` is non-numeric, zero, or negative
  (`error.code=validation_failed`, `error.meta.field=step`,
  `error.meta.reason=must_be_positive_integer`).
- `--step` does not match an existing setup-step record for the resolved
  `(app_instance, phase=setup)` (`error.code=workspace.step_not_found`,
  `error.meta.{step_id, app}`).
- The caller lacks `workspace:write` on the target app's owning node
  (`error.code=authorization_failed`).

## Destructive Consent

Non-interactive callers must supply `--force`. `--json` selects the JSON
renderer and forces non-interactive input mode but never implies
destructive consent — `--json` callers must still supply `--force`. This
matches the resolved `node:remove` and `app:remove` exemplars.
