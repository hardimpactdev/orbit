# Realtime events with Reverb

## Problem

The web app and `realtime:logs` need the Gateway to push events, and without a working `websocket` role the Gateway broadcasts nothing. [Realtime events](/reference/events) defines the channels and events. [Reverb apps](/reference/websocket-apps) owns the server, the app registry, upgrades, and recovery.

## Cause

Reverb holds long-lived WebSocket connections, so it runs outside the Gateway process, as the `websocket` role, the way the `metrics` role runs Prometheus and Grafana. Clients subscribe at `wss://reverb.orbit`.

## Solution

```bash
orbit node:role:add gateway websocket
```

The role is a singleton and conflicts with no other role, so it can share a Node with `gateway` and `vpn`. No Project, Instance, Route, or `.env` edit is involved. To move or remove it, use [`node:role:relocate`](/cli/node/role-relocate) and `node:role:remove`; [Reverb apps](/reference/websocket-apps#remove-a-dead-websocket-node) covers a dead Node.

Four things go wrong:

- **Composer fails on a fresh Node.** `composer install` fails its platform check on Ubuntu 26.04 unless `php-curl` and `php-xml` are installed. The role baseline installs both.
- **Agents see no events.** Another Reverb app must set `accept_client_events_from` to `members`, as `orbit-reverb` does. Without it, the [Node agent channels](/reference/events#node-agent-channels) carry no agent events.
- **The Gateway reports no connection.** It reads the connection from published Reverb sites whose process has reported `serving` in the current registry history. Reverb reports every 5 seconds, and the Gateway accepts a report younger than 60 seconds, so a dead or hung process leaves after one minute. App operations keep a stricter 15-second window. A new boot clears the confirmation. A role in `provisioning`, `failed`, or `removing` still supplies realtime while such a process serves it, so a private DNS publication failure leaves `realtime:show` configured.
- **Converge refuses.** It refuses a Node that lacks an address its Caddy sites bind, before it changes anything. A preparation failure leaves the running process alone. An activation failure needs forward recovery with a compatible release, and a failed rollback reports `websocket.rollback_failed`. Orbit never starts a static app list that could hold revoked credentials.

`ORBIT_WEBSOCKET_REPOSITORY`, `ORBIT_WEBSOCKET_INSTALL_PATH`, and `ORBIT_WEBSOCKET_PORT` in the Gateway `.env` change the defaults. The server ref belongs to the Gateway release and has no environment override. The Gateway needs no broadcast setting in its `.env`.

## Limits

This covers one Reverb server behind one `websocket` assignment, which serves several [Reverb apps](/reference/websocket-apps). Production starts with one process. Package upgrades still need an announced reconnect window.

## Verification

```bash
orbit realtime:show
orbit doctor --node=<node-id> --family=role
getent ahostsv4 reverb.orbit
```

`orbit realtime:show` reports `configured` and `wss://reverb.orbit`. `getent` resolves `reverb.orbit` to the role Node's WireGuard address. On the Node, `systemctl is-active orbit-websocket` prints `active`. From a Node that trusts the Orbit CA, `curl -i -X POST https://reverb.orbit/apps/<app-id>/events` answers `401` with `Authentication signature invalid`, which proves that Reverb answers behind the Caddy site.
