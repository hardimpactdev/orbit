# `app:remove` Non-Interactive Input Mode

[Back to `app:remove` technical contract.](1_app-remove.md)

This page describes how non-interactive input mode resolves `app:remove` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY. It never authorizes destructive removal; `--force` must be
passed explicitly. In non-interactive input mode, `--force` is the only
available destructive consent surface.

App-node callers are rejected by the gateway before this input mode reads
command input beyond what is needed to identify the caller-role violation. CLI
callers that cannot reach the gateway fail with `gateway_unavailable`.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when destructive consent (`--force`) is absent.
- Fail before side effects when supplied input is forbidden or invalid.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `app` | `[app]` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=app`. |
| `force` | Non-interactive mode and `--force` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=force`. |

## Validation Failures

Fail before side effects when:

- `app` does not match an existing gateway app record (renders as
  `app.not_found`).

The selected output renderer owns how these failures are displayed.
