# `workspace:remove` Human Renderer

[Back to canonical technical contract](1_workspace-remove.md)

This file owns the human-rendered terminal output for `workspace:remove`.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[interactive input mode](5.1_workspace-remove_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Destructive Frame

The command begins with a framed destructive confirmation message rendered by
[interactive input mode](5.1_workspace-remove_input-mode_interactive.md).

```text
! WARNING !
-----------
You are about to remove the workspace 'feature-api' from app 'my-app'.
...
Continue? (yes/no) [no]:
```

## Progress Tree

`workspace:remove` performs slow network work (artifact cleanup over SSH).
Render the complete progress tree after input resolution and destructive
consent, before removal side effects begin. Phase A and Phase B steps appear
in the same tree in the order defined by the canonical contract.

```text
┌ Remove Workspace
○ Removing gateway intent
○ Stopping traffic for workspace hostname
○ Stopping inherited processes
○ Running teardown steps
○ Cleaning workspace PHP-FPM pool
○ Removing worktree
└ Workspace 'feature-api' removed
```

### Step Definitions

| Step ID | Label | Phase | Why it is shown |
| --- | --- | --- | --- |
| `intent` | Removing gateway intent | A | Atomic delete of workspace-owned `proxy_route` rows and the `workspace` row. |
| `routes` | Stopping traffic for workspace hostname | B | Re-rendering the proxy backend so the workspace stops serving. |
| `process` | Stopping inherited processes | B | Stopping and removing inherited process units. |
| `teardown` | Running teardown steps | B | Executing configured workspace teardown steps. |
| `fpm` | Cleaning workspace PHP-FPM pool | B | Removing the workspace PHP-FPM pool config and reloading PHP-FPM. |
| `files` | Removing worktree | B | Deleting the workspace directory on the app node. Skipped when `--keep-files` is set. |

### Step Delta — `--keep-files`

When `--keep-files` is set, the `files` step renders as skipped:

```text
○ Removing worktree ... [SKIPPED (--keep-files)]
```

### Step Delta — Already Absent

When a Phase B step finds the artifact already missing on the node (CWD-drift
or out-of-band cleanup), the step renders as already absent and is not a
warning:

```text
○ Removing worktree ... [ALREADY ABSENT]
```

### Step Delta — Drift After Failure

When a Phase B step fails, the step renders as a warning, subsequent steps
still run, and the footer reports drift:

```text
┌ Remove Workspace
○ Removing gateway intent
○ Stopping traffic for workspace hostname
○ Stopping inherited processes
○ Running teardown steps
○ Cleaning workspace PHP-FPM pool
○ Removing worktree
└ Workspace 'feature-api' removed with drift

Drift detected:
- workspace: worktree directory could not be removed (run `doctor --family=workspace --fix`)
```

## Success Output

When removal succeeds with no drift:

```text
Workspace 'feature-api' removed.
```

When removal succeeds but cleanup leaves drift behind:

```text
Workspace 'feature-api' removed.
  Drift detected:
  - workspace: worktree directory could not be removed (run `doctor --family=workspace --fix`)
  - proxy_route: workspace-owned proxy route could not be removed (run `doctor --family=proxy_route --fix`)
```

Each drift line corresponds to one structured warning in the JSON renderer's
`success.meta.warnings[]`.

When the operator was inside the worktree (self-targeting) and `--keep-files`
was not set, append a final notice that the previous CWD is now invalid:

```text
Note: your previous working directory belonged to this workspace and is now invalid.
```

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Workspace not found

Already-absent removal renders this validation failure. It is not a
successful idempotent removal.

```text
Workspace 'feature-api' not found.
```

### Ambiguous workspace name

```text
Workspace name 'feature-api' matches multiple apps. Pass --app=<app>.
```

### CWD not a workspace

```text
No workspace name was supplied and the current directory is not inside a registered workspace.
```

### Missing destructive consent

Rendered for non-interactive human output when `--force` is absent.

```text
Use --force to remove this workspace.
```

### Caller role not allowed

```text
This command may only be run from a control or gateway node.
```

### Gateway unavailable

```text
Gateway connection is required to remove a workspace.
```

### Authorization failed

```text
This caller is not authorized to remove this workspace.
```

### Gateway intent removal failure (Phase A)

Rendered when Phase A itself fails. No node-side cleanup has run.

```text
Failed to remove the gateway workspace record for 'feature-api'.
```

### Cancelled confirmation

```text
Operation cancelled.
```
