# Human Renderer: `orbit php:use`

[Back to `php:use` technical contract.](1_php-use.md)

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render this progress tree after input resolution and before side effects begin:

```text
┌ Updating PHP runtime to PHP 8.5
○ Resolve target
○ Validate version
○ Apply and verify PHP change
└ Working...
```

Use the resolved version and target scope in the title:

- app/workspace version change: `Updating PHP runtime to PHP <version>`;
- workspace inheritance: `Restoring workspace PHP inheritance`;
Use this label lifecycle:

| Pending | Active | Completed |
| --- | --- | --- |
| `Resolve target` | `Resolving target` | `Resolved target` |
| `Validate version` | `Validating version` | `Validated version` |
| `Apply and verify PHP change` | `Applying and verifying PHP change` | `Applied and verified PHP change` |

When the command completes, replace the footer with the result:

```text
┌ Updating PHP runtime to PHP 8.5
● Resolved target
● Validated version
● Applied and verified PHP change
└ Successfully updated PHP runtime to PHP 8.5
```

For `--inherit`, the footer is
`Successfully restored workspace PHP inheritance`.

## Success Output

Human output states the target scope, node, previous version or inheritance
state, selected version, and whether gateway configuration changed. When the command
clears a workspace override, the output states the inherited app version.

## Failure Output

Human-rendered failures show the target, field, and recovery command when
available:

- Inspect available images with `orbit php:list --node=<node>`.
- Repair partial app/workspace application with the doctor command named in
  the warning.
- Repair partial proxy backend application with
  `doctor --fix --family=proxy --restore`.
