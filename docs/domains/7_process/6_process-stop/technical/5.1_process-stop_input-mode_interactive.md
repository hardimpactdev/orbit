# `process:stop` Interactive Input Mode

[Back to `process:stop` technical contract.](1_process-stop.md)

This page describes how interactive input mode resolves `process:stop` input.

**Input mode:** Interactive.

## Selection

Use this input mode only when the process is attached to a TTY and `--json` is not present.

## Prompt Behavior

Prompt for missing required input in this order:

| Field | Prompt primitive | Notes |
| --- | --- | --- |
| `app` | Datatable | Show apps the caller is authorized to operate when app context is absent or ambiguous. |

`name` is optional. When `[name]` is omitted, interactive mode stops all process definitions for the resolved app or workspace context; it does not prompt for a process by default.
`--workspace` is an explicit filter. If a supplied workspace name is ambiguous,
the command fails and asks the operator to pass `--app`.

Prompt validation runs as soon as the field needed for a decision is known.
