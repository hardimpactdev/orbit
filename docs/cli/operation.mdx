An [operation](/reference/operations) is a long piece of work, such as an Instance deploy or rollback, that the Gateway runs on its queue. The command that starts it, such as [`instance:deploy`](/cli/instance#orbit-instancedeploy) or [`instance:rollback`](/cli/instance#orbit-instancerollback), returns or stops following without stopping the operation. These commands find it again.

When a deploy command follows an operation, it shows live output from the Node agent on the operation’s Reverb channel. A step that printed live does not print its stored output tail again. `operation:show` reads the retained tails; it does not subscribe to live output. See [following operations](/reference/operations#follow-an-operation-over-reverb).

## Commands

| Command | Result |
| --- | --- |
| [`operation:list`](#orbit-operationlist) | List the newest operations. |
| [`operation:show`](#orbit-operationshow) | Show one operation with its steps and their output. |
| [`operation:cancel`](#orbit-operationcancel) | Ask one operation to stop. |

Every command accepts `--json`. A production deploy and a rollback include a `process_restart` step. The progress tree labels it `Restart Processes`, `Restarting Processes`, or `Restarted Processes` as its state changes. A rollback's `rollback` step reads `Find retained release`, `Finding retained release`, or `Found retained release`.

## orbit operation:list

List the 50 newest operations on Nodes you can access, newest first.

```bash
orbit operation:list [--status=STATUS] [--kind=KIND] [--instance=ID] [--json]
```

| Option | Meaning |
| --- | --- |
| `--status=STATUS` | `queued`, `running`, `waiting`, `succeeded`, `failed`, or `cancelled`. |
| `--kind=KIND` | An operation kind, such as `instance.deploy`. |
| `--instance=ID` | Only operations on this Instance. |

The table shows ID, Kind, Target, Status, Step, By, and Started. JSON returns the list of records without steps.

```bash
orbit operation:list --status=running
```

## orbit operation:show

Show one operation: a detail tree of its kind, target, status, current step, failed step, error code, result, and times, then its steps as a table with each step's status and duration, then the output tail of each step that has output.

```bash
orbit operation:show <operation> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `operation` | yes | Numeric operation ID. |

JSON returns the record with every step, as `GET /api/v1/operations/{operation}` does. The command exits `0` for any status; read `status` for the outcome.

For [`tasks.analyze`](/cli/tasks#orbit-tasksanalyze), inspect `result.outcome`, not just operation status. A successful operation can report `blocked` or a changed checkout. `result.artifact` retains the complete bounded report with its digest and byte length; step output tails are not a substitute. Use `operation:show <operation> --json` to recover that complete evidence after the starting command stops following.

```bash
orbit operation:show 42
```

## orbit operation:cancel

Ask an operation to stop. A queued operation ends `cancelled` at once. A waiting one stops its current step through its stop hook before ending `cancelled`; an unconfirmed stop keeps it waiting and returns the step’s error. See [Cancel an operation](/reference/operations#cancel-an-operation). A running one finishes its running step and ends `cancelled`. A deploy or rollback whose release is already active finishes instead. Orbit never undoes the steps that ran.

```bash
orbit operation:cancel <operation> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `operation` | yes | Numeric operation ID. |

The command returns the record at once and does not wait for the operation to stop. A cancel of an operation that already ended changes nothing.

```bash
orbit operation:cancel 42
orbit operation:show 42
```
