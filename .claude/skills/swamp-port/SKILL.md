# Port a kind to Swamp

Port one family or parent kind per PR, inside a production-equivalent dev topology (F13). The PR carries the topology receipt. The Gateway admits and projects; Swamp does the work. The [porting reference](../../../docs/swamp/porting.md) holds the template, the legacy-to-native table, the anti-patterns and the changelog. The [Swamp shape guide](../../../swamp/docs/swamp-shape.md) and [PLAN boundary decisions](../../../docs/swamp/porting.md#check-all-seven-boundary-decisions) are binding. Where this skill and the guide disagree, the guide wins; tell lane 26.

## The loop (F13)

1. Claim the kind from `port-queue.md` in `~/swamp-execution` on beast (`port-queue-B.md` and `port-queue-C.md` feed it). At most five port lanes run at once, one per topology slot.
2. Call Recall `resolve` for the kind and its family. Read the [Swamp manual](https://swamp-club.com/manual) pages for workflows, behavior definitions, vaults and remote execution.
3. **The legacy sequence is the spec (F9).** Read the pre-Swamp Gateway action, its agent actions and its feature tests at the migration baseline: `git show 6291bb036:<path>`. List its phases in order, with each phase's Node and edge cases, including values the Gateway rewrites before execution, such as setup macros (#2304). Write the parity tests first.
4. Start the topology: `bin/swamp-proof up --topology <name>`. Its Gateway VM carries the `gateway` and `swamp` roles (F14); its Nodes carry what the kind needs (`app-dev`, `app-prod`, `app-prod-2`, optional `+ingress`, `router`, `database`), joined by WireGuard. Topologies are versioned in `swamp/proof/topologies/`.
5. Port in your beast worktree (Build it, below). Each legacy phase becomes one script-file step. A phase-order change needs a written reason in the PR body, approved by a sub-orchestrator; lane 26 lists it under "Documented F9 deviations" in `docs/swamp/porting-retros.md`.
6. Run the whole path in the topology as often as you need: request, Gateway admission and intent, Swamp, Nodes and terminal projection. Read full stderr and per-step timings. Fix Gateway and Swamp bugs alike.
7. When the parity tests pass within budget (F8), the final run writes the receipt (`bin/swamp-proof receipt` in B's tool); put it in the PR. The topology differs from production: test repositories, the Orbit CA, no production data or scale. Its Swamp worker enrolls as `orbit-node-209`, so workflows keep `target: orbit-node-209` unchanged. Run `bin/swamp-proof down`; a topology dies after 60 minutes without a run (8 hours at most), and a one-shot proof run 45 minutes after creation (F11). A topology fault fixes the topology in the same PR and bumps its version (F12).
8. Lane 26 reviews and records lessons; the sub-orchestrator merges. An outage-exception PR, or a first-up proof-path PR until `up` is live, merges on a sub-orchestrator's independent review instead, and lane 26 runs its retro after merge; one short live check after the load confirms it landed. It is not a second proof.

Never load `swamp/` into production serve or log in to 209 for a port. If Swamp has a real gap, stop and send it to your sub-orchestrator with evidence. Do not build around it.

## Build it

Copy the workflow and Gateway declaration from the [template](../../../docs/swamp/porting.md#fill-the-workflow) and fill every `REPLACE_*` token. `REPLACE_F1_RUN` stays a plain script invocation until lane 16 ships F1.

- **Inputs:** the full non-secret intent under `intent`, and names-only `{vault, key}` descriptors under `execution_secrets`. Secrets are never inputs. Encode empty maps as objects, not `[]` (#2273). Never pass a Gateway macro or alias to a shell; expand it through the Gateway supplier before the step runs (#2304).
- **Vaults:** list every vault the workflow reads, in parents and children. `vaults: []` when there is none, by convention.
- **Placement:** every step runs on `target: orbit-node-209`. Reach another Node with official `@swamp/ssh` from 209 using the intent's `identity_file`, stored `host_keys` and `sudo: true`. Use one selector in the effective placement: `target` only, with no `labels` at any inherited scope. Copy placement from `route-upstream-firewall`, not `node.bootstrap_probe`.
- **Scripts:** one script file per action group, shipped through the behavior manifest `additionalFiles` and run as a placed `command/shell` step on 209, or through `@swamp/ssh` `exec` with the body in argv for another Node; `script` only when the script reads no input or secret. Split only at a resume point, a Node change or a guard. TypeScript only shapes typed inputs and outputs, and a new TypeScript behavior states why native Swamp, an official extension, an existing shared helper or a script file cannot do the job (F15).
- **Secrets in steps:** one whole `${{ vault.get(...) }}` expression per variable in `task.inputs.env`, or in `@swamp/ssh` `exec` `stdin`. Hand it to tools on stdin or in a 0600 file, never argv. For a script on another Node that reads a secret or input, use `exec` with `argv: [timeout, N, python3, -I, -c, <asset body>, <public args>]` and the secret on `stdin`; `env` uses `SendEnv`, so do not rely on it. A Node never returns a secret to the Gateway or prints one as step output. Generate Gateway-owned secrets, such as `APP_KEY`, at admission; Node-held keys stay on the Node (decision 3). Swamp token authority only shrinks (decision 8): a kind may read the token list and revoke by exact name, but it selects only the removed Node's own worker principal, by exact equality and failing closed, and never mints or widens. Never rewrite a shipped script's source to inject input.
- **Few steps:** step count dominates run time. Op 6639 took 957 s for 4.6 s of SSH work. Until the extensions lane reports the cause, one script per Node per phase does the reads, precondition checks, writes and result JSON. Use a typed TypeScript step only for a result the script cannot print, and a separate check step only for another Node's read. Each extra step needs a named Node change or guard in the PR. Do not split for resume: pinned e459 loses inline SSH `globalArgs` when it resumes a failed run. Never wrap an SSH call in TypeScript envelope and decode steps (#2261 reached 66 steps). A typed result step returns `{stdout}` itself; add no `printf` step after it. Resolve assets once, outside `forEach`.
- **Refusals first:** the action script checks preconditions before its first write and prints a public `error_code`. Private stdout never goes into native history. F1 failure output is stderr only: redact the whole stderr, keep the last 4 KiB, re-redact the tail's start for split matches, and drop lines that still hold a partial known-secret prefix. A runner that discards stderr makes every failure unreadable (#2304). Preserve legacy setup exit-code and error-name cases, or explain each change in the PR body.
- **Control flow:** `dependsOn` with `condition`, `guard`, `allowFailure`, `concurrency`, per-kind `queueTimeout` (F8), native resume. No loops, sleeps, lock files or receipts, except one fixed literal sleep shorter than a literal timeout (the DNS grace is one case), or a bounded poll inside a phase script for external HTTPS state (VM started, image ready; no DNS-read allowance): fixed interval, coreutils `timeout <phase budget>`, nonzero exit with a readable F1 error on a bad state (the projector renders a timeout), interval and budget stated in the PR, counted toward the kind budget. Never poll to retry a failed action or to wait on Gateway or Orbit state. The shape gate accepts it (#2325, #2366; it follows imports into sibling modules in the same scripts directory, so use a strict read such as upcloud.py `poll_read()`, never the 404-tolerant `api()`): a literal positive timeout on every invocation of the polling file, a fixed literal interval shorter than the timeout, a GET to an external system (never the Gateway or Orbit state) that fails on HTTP errors, and no retried requests (#2325). Add no baseline row. Swamp has no step retry key. Never read outputs of a failed or skipped step.
- **Fan-out:** `forEach.in` never reads outputs of a step in the same job; official e459 expands it before they exist. Read `inputs`, literals, or outputs of an earlier job this job `dependsOn`. Otherwise pass the list as inputs to a `type: workflow` child. Give each item its own `behaviorName`. Keep the legacy failure scope from `6291bb036`, not from an earlier Swamp port: legacy sweep stopped a host's work at its first failure. Reproduce such a scope with one script per host, or one child per host on `allowFailure`, so a failure stops that host and other hosts continue. Find the legacy feature tests with `git show 6291bb036:<test path>` before calling parity unverifiable. Never give a step an input that grows with history or fleet size, such as `data.query` or `results: ${{ steps }}` over a fleet fan-out; read one stable record with `data.latest` and pass only the statuses you need (B7, #2310, #2334).
- **Errors (F1, pending, lane 16):** shipped scripts will run through the shared F1 wrapper, and the shared projector will report the failed step and the last 4 KB of redacted stderr for any failed step. Until it lands, add no family wrapper.
- **Result:** on e459 a step that exits nonzero keeps no outputs. The action step sets `ignoreExitCode: true`, prints the public JSON and is the `terminal_result`. An `accepted` assert on `steps.action.outputs.exitCode == 0` fails the run. With several effect steps, a `result` step on `condition: always` maps the first failed step to an `error_code`, reading `"x" in steps && steps.x.status`, never outputs.
- **Time budget (F8):** follow the [budget table](../../../docs/swamp/porting.md#set-the-time-budget). A measured, explicit budget wins; otherwise 30 minutes until the first success, then 1.5× the longest success; never a flat or borrowed budget (#2324). Set an explicit workflow `queueTimeout`; the proof file's `queue_timeout_seconds` equals it. Each phase command starts with a literal `timeout <phase budget>`, such as `run: timeout 30 python3 …` or argv `[timeout, '30', python3, …]`. On exit 124 the shared F1 projector renders `<step> timed out after <N>s` (OD2; lane 16, pending on main), so scripts print nothing and the gate rejects wrappers and epilogues such as `sh -c '…; printf …'`. A remote read may set `@swamp/ssh` `timeoutSec` to its phase budget instead (#2334), never the unset 300 s default; a remote write keeps a remote-side bound. Add no family timer.
- **Gateway:** projection keeps an exact native terminal that met its budget, even if it arrives after the Gateway expiry, and that terminal replaces the `timed_out` mark; it uses the single history read. Validate and record immutable intent at admission, start with shared `StartSwampRun`, push changed secrets with `SwampCommandStep::executionCopy`, project through the family projector. No callbacks, holds, pollers, timers, retries or second readers. A failed projection attempt must leave the expiry armed; no queued marker may suppress it (L17-PR-2348-01).
- **Delete** the old executor, its tests, its embedded scripts, its callbacks, and the CLI, SDK and docs paths that served only it, in the same PR. An F9 rebuild also deletes the old behaviors and tests it replaces (F15). Do not touch `apps/agent`. Remove the kind's rows from `swamp/config/swamp-shape-baseline.json`.

## Check it

- `swamp workflow validate` on the pinned runtime for every changed workflow.
- The family's native test under `swamp/` and `deno test` for changed behaviors; shellcheck or ruff for every script. Real-Docker tests clean up with `docker rm --force --volumes`; a forced removal beats `--rm` and leaks anonymous volumes (#2358).
- Parity tests: port the legacy feature tests so each legacy case gives the same public result natively.
- Gateway Pest tests for admission, identity, inputs envelope and projection, run with a file path or `--filter`.
- The shape gate and placement lint. Root `.github/workflows/swamp-shape.yml` is their only CI; never add a workflow under `swamp/.github`, because it never runs (#2372).
- **Growth (F15):** state the Orbit net, then `swamp/` growth for behaviors, workflows, scripts, and tests and fixtures separately. Each growth says why native Swamp, an official extension or an existing shared helper cannot do it. The migration total (+63,450 lines) must turn negative. Prefer topology receipts and parity tests over large mocked fixtures, and delete duplicate or mock-heavy tests.
- State the measured p95, its sample, the run budget and `queueTimeout` in the PR body. Every workflow, children included, sets an explicit `queueTimeout`.
- Receipt (F13): follow the [proof scope](../../../docs/swamp/porting.md#port-inside-the-topology-f13). A change to a workflow, behavior or script a kind runs, or a Gateway change to its admission, intent, inputs, vault pushes, minting, signing or terminal projection, carries a `bin/swamp-proof receipt` (#2266, #2273, #2304). Other Gateway changes need failing-without tests, docs and review; only deletion, docs and test PRs fix forward. An outage fix skips the receipt only if its body says "merges without a topology receipt" and names the live check that follows the load (#2332).
- Proof file: `swamp/proof/<kind>.json` (`swamp/proof/README.md`, or `designs/swamp-proof-fixture-v0.md` on beast until it lands) holds the `prepare` and `request` CLI calls, a partial expected `envelope`, budgets, F9 phases, parity tests, `queue_timeout_seconds` and default topology. No secret appears in the file or in argv; a kind gets secrets through the topology Gateway's normal path.

## Review a kind PR

An outage-exception PR merges on a sub-orchestrator's own independent Opus review against this skill, and then comes to lane 26 for a post-merge retro. Until `up` is live, a first-up proof-path PR takes the same path: the sub-orchestrator's own Opus review, merge on PASS, load within 10 minutes, then lane 26's retro. Lane 26's queue holds non-urgent kind PRs and this skill. When more than 3 PRs in lane 26's queue have waited over 30 minutes, lane 26 tells A, and the orchestrator adds a second skill reviewer.

Lane 26 reviews every non-urgent kind PR before merge, and every outage-exception or first-up proof-path PR after merge, against the [PR and review checklist](../../../docs/swamp/porting.md#pr-and-review-checklist) and the [anti-patterns](../../../docs/swamp/porting.md#anti-patterns). A kind PR fails review with `swamp/` growth that is not split by part or not explained (F15), without a measured p95 and a run budget, without a topology receipt when it changes behavior, with more than about two native steps per legacy call and no written reason, with a redesigned legacy sequence and no written reason, with a `forEach` over same-job step outputs, or with an extra step whose Node change or guard it does not name. Report PASS, or each deviation as `file:line`, the rule broken, and the native replacement. Keep source conformance separate from CI, served-source uptake and live evidence. Before alleging a silent skip or data loss, check native semantics: a CEL error in a `guard` fails the step. On pinned e459, a `guard` or `forEach` that reads an intent field the intent lacks fails with `No such key`; it never reads as false (#2369). A PR that adds an intent field needs its Gateway release live before the Swamp load, and pre-release runs are re-admitted, not resumed. Also, a dependency on `succeeded` or `skipped` does not run after a failure (manual, workflows guard). Read the PR body before calling a written reason missing; unread means unknown. Check the whole workflow's `queueTimeout`, not only the changed steps (L17-PR-2363-02). When a capture becomes sparse, list every guard that read its full form (#2383). Post the verdict as a one-line PR comment: PASS or FAIL, head SHA, skill version and the key finding. CI does not check `deno fmt` and main is not fmt-clean, so do not block on it (#2332). Review the slimming lane's deletion PRs at deletion speed: tests and docs, no receipt, unless a PR changes a kind's behavior.

## Improve this skill

After every merged PR that changes a kind's behavior, through `swamp/` or the Gateway, run a short retro: what was slow, what the reviewer or conformance audit flagged, what broke live. Add one row per PR to `docs/swamp/porting-retros.md`, and record each proof receipt in its Proof receipts table with the fault (kind or topology). Fold each lesson into the rule it changes the same hour, replacing text rather than appending it, so SKILL.md and porting.md stay lean. When a lesson comes from a conformance finding, cite its canonical ID and update that row instead of adding a duplicate.
