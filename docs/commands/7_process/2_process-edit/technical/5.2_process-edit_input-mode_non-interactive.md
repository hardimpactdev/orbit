# `process:edit` Non-Interactive Input Mode

[Back to `process:edit` technical contract.](1_process-edit.md)

This page describes how non-interactive input mode resolves `process:edit` input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces non-interactive input mode even when the process has a TTY.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when no editable fields are supplied.
- Fail before side effects when supplied input is forbidden or invalid.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `app` | `--app` is absent and local app context does not resolve exactly one app. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=app`. |
| `name` | `[name]` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=name`. |
| `editable_fields` | `--command`, `--restart-policy`, and `--crash-notification` are all absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=editable_fields`. |
