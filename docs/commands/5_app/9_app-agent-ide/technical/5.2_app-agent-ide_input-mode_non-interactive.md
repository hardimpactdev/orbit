# Non-Interactive Input Mode: `orbit app:agent-ide`

[Back to `app:agent-ide` technical contract.](1_app-agent-ide.md)

**Input mode:** Non-interactive.

This command uses non-interactive input mode when run with required
arguments, in a non-TTY environment, or with the `--json` flag.

Non-interactive input mode must never render prompts.

App-node callers and unknown local contexts are rejected before this input mode
reads command input beyond what is needed to identify the caller-role or
execution-context violation.

## Rules

- Caller role must be `control` or `gateway`.
- Both `app` and `agent_ide` are required.
- If `app` is missing, fail with `error.code=validation_failed` and
  `error.meta.field=app`.
- If `agent_ide` is missing, fail with `error.code=validation_failed` and
  `error.meta.field=agent_ide`.
- If an adapter switch would trigger workspace removal, the `--force` flag is
  **required** to provide destructive consent.
- Without `--force`, when workspaces would be removed, the command fails before
  side effects with `validation_failed` and `error.meta.field=force`.
- `--json` selects the JSON renderer and forces non-interactive input mode
  even when a TTY is present. `--json` is never treated as destructive
  consent; non-interactive callers must still pass `--force` to authorize
  workspace removal. A `--json` invocation without `--force` that would
  trigger cleanup fails before side effects with `validation_failed` and
  `error.meta.field=force`.
