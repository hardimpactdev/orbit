# instance:register verification cases

The proof runs the built CLI on a fresh `app-dev` Node of a nested topology with a Gateway, a Project, and Git checkouts and linked worktrees of its repository under `<apps-root>/<project-slug>/`, with and without a public `.env`. It checks the Gateway records, the Node's files and processes and real HTTPS responses. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Record only | Register a checkout with a private `.env`, no `--setup` and no `--domain`. | The result is at once with the active Instance, its branch, commit, PHP version and Laravel marker, and no task. Nothing on the Node changes. |
| Absent `.env` | Register a checkout with no `.env`. | The same: active at once, no task. |
| Readable `.env` | Register a checkout whose `.env` is world-readable, and one at `0640`. | A task starts for both. The `.env` becomes `0640` in group `orbit-env`, its contents are unchanged, and the Instance becomes active. The second repeat skips the finished step. |
| `.env` refusals | A `.env` that is a symlink, one owned by another account, and a report from an agent that sends no `env` key. | `instance.source_invalid` for the first and the third, and `instance.source_owner_invalid` for the second. Nothing is reserved. |
| Setup | Register with `--setup`, for a Project with setup steps and Process definitions, then for one with neither. | The first runs the steps in order, starts the Processes, and marks the runtime awake after the check. The second answers at once with no task. |
| Domain | Register with `--domain` below the Node's TLD. | A task creates the Route as `route:create` does, the Route answers over TLS, then the Instance becomes active and its prepared runtime is marked awake. `APP_URL` may change; the rest of the `.env` is preserved. |
| Domain refusals | A domain outside the Node's TLD, one equal to it, one on a Node with no TLD, one in a Cluster TLD, an invalid domain, and a domain another Route owns. | `route.domain_invalid` for a domain outside or equal to the TLD, on a Node with no TLD, and in a Cluster TLD; `validation.failed` for an invalid domain; and `route.domain_conflict` for an owned one. Nothing is recorded. |
| Linked worktree | Register a linked worktree whose branch was renamed after creation. | It is accepted and the recorded branch is the reported one. No Git metadata changes. |
| Name | A directory name, an explicit `--name` that differs from the directory, the Project's default branch name as a directory name, a directory name that is not a valid label, and a name of 64 characters. | The directory name is used by default, the explicit one when given, `default` for the default branch name, `instance.name_invalid` for the invalid label, and `validation.failed` for the 64 characters. |
| Root | A valid `--root` override, an invalid one, and one the Project type rejects. | The override is recorded. The invalid one gives `validation.failed` before any request, and the rejected one gives `validation.failed` from the Gateway. A Project with a stored invalid root gives `project.root_invalid`. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C and end of input. Then run it noninteractively and with `--json` without `--yes`. | The prompt names the path and the effect, and No is selected. Each decline ends with `instance.registration_cancelled` and no request. The noninteractive and `--json` calls are refused with `input.confirmation_required`. With `--yes` there is no prompt. |
| Source refusals | A directory outside Git, an origin with credentials, a password, a query, a local path, `git://` or no origin, a checkout of another repository, a checkout owned by another account, a checkout with no commit, a silent agent, and a checkout with unsafe Git metadata. | `instance.source_invalid` before the request for the first two kinds of origin, then `instance.source_identity_invalid`, `instance.source_owner_invalid`, `instance.source_invalid` and `app-dev.source_metadata_unsafe`. Nothing is reserved. |
| Placement | A checkout outside `<apps-root>/<project-slug>/`, and no Project. | `operation.kind_unavailable`. Nothing is recorded. |
| Worktrees flag | Run with `--include-worktrees`, in a terminal and with `--yes`. | `operation.kind_unavailable` before any prompt. Fails today: the CLI asks for consent first, naming all linked worktrees, and then the Gateway refuses. |
| Overlap | A checkout that overlaps another managed checkout. | `instance.source_conflict`. |
| Conflicting state | A checkout that belongs to an Instance made by `instance:create`, one in a state that cannot be registered, and one that is not a checkout of its reported shared repository. | `instance.registration_conflict`. Nothing changes. |
| Caller | Run on a Node that is not an active Linux `app-dev` Node, and with the Node account set to `root`. | `instance.caller_not_app_dev` and `instance.source_owner_invalid`. |
| Repeat | Repeat a completed registration without and with `--setup`, with a protected `.env` at `0640`. | The first returns the Instance and keeps its awake state; with the `0640` `.env` it starts a task that skips the finished step. The second checks and starts all Project-defined Processes before it marks the runtime awake. |
| Conflicting repeat | Repeat for the same checkout with another Project, name, root or domain. | `instance.registration_conflict`. Nothing changes. |
| Failed step | Make the `.env` protection, a setup step, a Process start or the Route fail. | The task fails with the failed step and its error code. The checkout and the Instance stay, the Instance is `reserved`, and completed work stays. The same command repairs it and the Instance becomes active. |
| Interrupt | Cancel a run, let one time out, and stop the executor mid-run. | Each ends like a failed step and the rerun finishes. |
| Progress and output | Run in a terminal, a narrow terminal and a pipe, and with `--json`. | One progress display for the inspection, then the follow of the task when one starts. The consent question wraps at the narrow width and is never truncated. A record-only result prints `Instance registered: <name>` with ID, Selected branch, Project, Node and Request ID. The piped output has no animation or escape codes. With `--json`, stdout holds only the Instance or the final task. Fails today: the detail shows no Project or Node. |
| Missing input | In a terminal, run the command with no `--project` and cancel the list. Then run it noninteractively and with `--json`. | The terminal lists Projects by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `project.id_invalid`, with no request. Fails today: a missing Project is sent to the Gateway and refused with `operation.kind_unavailable`. |
| IDs only | A Project by name, the ID `0`, the ID `-1`, and `abc`. | `project.id_invalid`, with no request. |
| Idempotency option | Run with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers it. |
| Lost response | Lose the response to the start and repeat the command while the first task runs. | Exactly one task exists: the repeat is refused with `operation.target_busy`. Fails today: no hold is taken, so a second run starts. |
| Unknown | A Project ID that does not exist. | `validation.failed` on `project_id`. Nothing is recorded. |
