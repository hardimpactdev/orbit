# `app:new` Human Renderer

[Back to technical contract](1_app-new.md)

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

The human renderer provides a live progress tree during app creation and a
concise summary upon completion.

## Progress Tree

`app:new` performs remote SSH work and multi-step registration, so it always
renders a progress tree.

```text
┌ Creating App
○ Create app source
○ Apply and verify app registration
○ Apply runtime container configuration
○ Apply proxy routes
└ Working...
```

### Steps

1. **Create app source:** Clones the repo or creates the directory on the
   target node.
2. **App registration:** Confirms Orbit has recorded the expected app configuration.
3. **runtime container:** Confirms the node-side artifact convergence.
4. **Proxy routes:** Confirms the gateway-side proxy record and application.
5. **Apply verification:** The footer means command-owned setup and
   artifact writes completed. It does not assert application HTTP readiness.

## Completion Summary

Upon success, a summary is rendered:

```text
App 'docs' created successfully on node 'app-1'.
URL: https://docs.test
```

## Warning Display

Drift that is non-fatal surfaces inline under the affected step and again in a
`Warnings:` block beneath the completion summary. Each warning shows the
human-readable message and a retry hint pointing at `next_command`. Examples:

- A pending production domain prints "Domain 'docs.example.com' is not yet
  active." with the hint
  `Retry with: orbit app:register docs --domain=docs.example.com`.
- When the PHP image is unavailable on the node, the output prints "PHP 8.5 is not available on
  'app-1'." with the hint
  `Resolve with: orbit doctor --family=app --restore`.

## Failure Display

Failures are rendered as prose errors with troubleshooting hints. If a failure
occurs during the progress tree, the affected step shows a red error dot.
Validation failures detected before any side effects (e.g. unsupported
`--php-version`, name collision) are rendered without a progress tree.

## Test Mapping

Primary test owners:

| Path | Coverage |
| --- | --- |
| `apps/gateway/tests/Feature/Commands/Apps/AppNewHumanRendererTest.php` | Human renderer for `app:new`: progress tree step labels and ordering, completion summary fields, inline warning rendering with retry hints, prose validation for pre-side-effect failures, and red-dot step rendering for mid-pipeline failures. |

Completion summary fields are name, node, and URL. Inline warning rendering
uses the `next_command` hint to suggest the next action.
