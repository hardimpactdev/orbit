---
title: "orbit tasks:agent:show"
sidebarTitle: "tasks:agent:show"
description: "Show one redacted read of an agent thread's conversation."
---

```bash
orbit tasks:agent:show [group] [session] [--after-sequence=CURSOR] [--json]
```

| Input | Choices | Meaning |
| --- | --- | --- |
| `group` | a list of tasks | The numeric task ID. |
| `session` | the task's agent threads | The numeric agent thread ID, as `tasks:agents` shows it. |
| `--after-sequence=CURSOR` | the `cursor` of a previous read | Accepted; recorded reads return a snapshot with a null cursor. |

In a terminal the command prompts for each omitted input. The thread list shows the ID, role, subtask ID, driver, and state. It leaves out stored `t3` threads, which have no transcript. A noninteractive call fails before the request with `tasks.group_required` or `tasks.agent_thread_required`, and an invalid ID fails with `tasks.group_invalid` or `tasks.agent_thread_invalid`. The command needs Gateway access.

Human output shows the recorded state, token metrics and transcript entries. The kind is always `snapshot` and the cursor is null. JSON output includes `request_id`. The source is `saved transcript` when recorded entries exist. Before the first transcript arrives, the response has no entries. A running turn keeps its last transcript until the result arrives. Reads never contact the task VM.

A `t3` thread fails with `tasks.agent_transcript_unavailable`. An invalid `--after-sequence` fails with `validation.failed`. See [Read a thread](/reference/tasks#read-a-thread).
