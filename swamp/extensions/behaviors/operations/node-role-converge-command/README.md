# Native Database role convergence

`operation-node-role-converge-209` executes existing Database-only assignments
from209 when no serving Metrics fleet needs reconciliation. The Gateway captures
the complete public intent and the canonical SSH identity and full target pins.
The observer digest uses its existing execution copy through official SSH exec
stdin. No worker or credential is installed.

The Database child composes canonical account, observer binary and OS package
actions, peer DNS repair, observer files and service, and CLI installation. Each
action is a native step through official SSH. The result is assembled from
completed steps; package or binary failure cannot prove the role. Footprint and
CLI failure remain explicit follow-ups. The terminal relay emits the shared subscriber’s public JSON `stdout` receipt.
Only the terminal subscriber updates Gateway state. No step reads an Operation or sends a progress callback.

Other role sets retain their current workflow. Its callback and signing requests
receive the actual dispatcher root run ID. Native Database admissions cannot use
those retained public or private callbacks.

This cut does not expose enrollment forward/restore/finalize factories or change
hub, peer, Metrics or Tool kinds. Whole-parent restoration remains unfinished.

Official cfgmgmt file actions cannot carry the admitted host keys in their SSH
schema. Root-owned observer files therefore use the preserved atomic file policy
via official SSH. Service control is a separate native step. DNS and CLI
metadata bind the existing canonical policy; they do not implement another
network or installation policy.
