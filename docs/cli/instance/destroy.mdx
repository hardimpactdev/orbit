```bash
orbit instance:destroy <instance> [--yes] [--force] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--yes` | prompt | Confirm the removal without prompting. Required without a terminal and with `--json`. `--force` does not supply consent. |
| `--force` | off | Delete dirty or unpublished development source after the identity checks pass; other worktrees that depend on its Git data, and a replication slot on an owned PostgreSQL database, always block removal. |
| `--idempotency-key=KEY` | generated | Reuse a key to retry the same [Operation start](/reference/operations#start-an-operation). |
| `--json` | off | Print the final task as JSON. |

```bash
orbit instance:destroy 12
orbit instance:destroy 12 --force
```

In a terminal, an omitted Instance is chosen from an interactive list. The CLI then asks to confirm with the Instance's name and ID and the effect, with No selected. For a production Instance the effect is to delete its production content, Route and runtime; for a development Instance, its owned source, Route and runtime, and with `--force` also dirty or unpublished work. Declining, Ctrl-C or end of input ends with `input.cancelled` and starts no removal. A noninteractive or `--json` call without the Instance is refused with `instance.id_invalid`, and one without `--yes` with `input.confirmation_required`; neither starts a removal. Without `--yes` the CLI first reads the Instance, so an unknown Instance or a missing grant is reported with `http.404` or `node_access.required` before the confirmation.

The command removes the Instance with its Route, Processes, Schedules and runtime. A development removal runs the teardown steps first and deletes the checkout. A production removal deletes its user, home, application data and source state after runtime cleanup. See [Instance removal](/reference/instance-removal).

Normal removal refuses dirty source and a `HEAD` that no origin branch or tag contains. `--force` waives dirty or unpublished source, the check that needs GitHub CLI source access, and a failed fetch of the origin.

Before removing Schedules or recording an Operation, Orbit reads Git on the Node through the existing SSH reader. A checkout that owns Git data used by another live worktree refuses with HTTP 409 `instance.worktree_dependents`, including with `--force`. Details contain visible dependent Instances (`id`, `name`, `project_id`), `other_dependents` and `unowned_paths`. Node access controls visibility across Projects. Orbit checks recorded checkout paths too, including renamed worktrees; it does not traverse the checkout tree. Recorded `source_layout` does not decide the check. The target’s unreadable Git refuses; unreadable checkouts elsewhere use bounded pointer checks and proceed when unrelated. Unknown checkouts produce `instance.checkout_unknown` warnings with their paths and Instance IDs. Unreadable candidate pointers remain warnings; containers, reserved sources, missing checkout paths and inactive Nodes skip it. The [removal limits](/reference/instance-removal) describe nested and bare repositories.

An owned PostgreSQL database with a replication slot also refuses before any change, with HTTP 409 `instance.database_replication_slot`, including with `--force`. Orbit reads the slots on the Database server's Node with the drop's own admin client, at most 5 seconds per server; when it cannot read them it refuses with HTTP 503 `instance.database_slots_unreadable`. Orbit never drops a slot: drop it by hand, then remove the Instance. See [Replication slots](/reference/instance-removal#replication-slots).

The dependency check runs only before admission changes records or withdraws Schedule triggers. The workflow and source-removal command are unchanged; neither a retry nor dispatch checks dependencies again. A worktree created during the queue wait or run is outside this protection. See the [known limits](/reference/instance-removal).

<Warning>
Production removal deletes the production account, source state, and whole home, including `releases/`, `.env`, shared data, and `database.sqlite`. Back up any application data you need before removal. Only the local PHP-FPM tuning stays.
</Warning>

The command starts a task and follows it until it ends, as [`instance:deploy`](/cli/instance/deploy) does: a progress tree of the task's steps, Ctrl-C stops following and not the removal and exits 130, and `--json` prints nothing while it follows. Run the same command again to resume an interrupted removal. A failed development teardown step keeps the Instance, and the next `instance:destroy` runs the teardown list again.

A failed removal rolls nothing back. The Route is already withdrawn, so its site stays down; the Schedule triggers stay removed; and the Instance is marked as having a failed removal. Add `--force` only after a failed non-forced removal: a rerun without `--force` after a forced one, or `--force` on a removal that has not failed, is refused with `instance.removal_conflict`.

An Instance without a Route skips Route withdrawal. A sole pending or failed Route is always withdrawn before its record is deleted. A first publication may have installed a site, certificates or DNS before a later step failed; neither its status nor `sites_published` proves absence. Withdrawal also accepts an already absent publication. Multiple owning Routes, a Route of another Project, an unsafe placement or a target set other than this Instance still refuse with `instance.remove_refused`. Source checks and teardown keep their usual rules.

A non-default container Instance, cloned or migrated, requires `--force` until guarded removal is built. It withdraws the Route, drops owned databases and stops and deletes the container with its Processes, T3 sessions, history, Incus storage, ACL and firewall rules. It removes Conn records and execution copies, then frees the T3 port. See [clone removal](/reference/development-containers#destroy).

A container default is removable only when two things hold: its Project is on the operator list `ORBIT_INSTANCES_DEFAULT_DESTROY_PROJECTS`, and no Instance has it as its clone source. Every other container default refuses with `operation.kind_unavailable`. The removal also needs `--force`. It deletes the container with its seed snapshots, and its [inner volume](/reference/development-containers#the-inner-volume) when it has one. A retry of a failed removal needs the Project still on the list.

A migrated Instance's [retained Git directory](/cli/instance/migrate#retained-git-data), `<old-checkout>.orbit-retired-git/`, survives destroy. It is purged only by hand under the [manual purge prerequisites](/cli/instance/migrate#manual-purge). After the Instance record is deleted, find its retained path and time in the successful destroy Operation: `orbit operation:show OPERATION --json` or `GET /api/v1/operations/{operation}` returns `result.retained_git_path` and `result.retained_git_at`.

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The Instance is missing or is not a positive integer, and the CLI cannot prompt. |
| `input.confirmation_required` | The call cannot prompt and has no `--yes`. |
| `input.cancelled` | You declined, pressed Ctrl-C, or the input ended. |
| `instance.remove_refused` | The Instance is not active, its environment or its Route cannot be removed, it has multiple owning Routes, its source layout is not removable, the source has dirty or unpublished work and `--force` is absent, or removing the source failed. |
| `instance.default_has_copies` | A removable container default still has an Instance that copies it. Remove the copies first. HTTP 409 before admission. |
| `instance.container_destroy_force_required` | A non-default container Instance, cloned or migrated, requires `--force` until guarded removal is built. |
| `instance.host_unavailable` | The Node could not be read for safe checkout removal; details distinguish unreachable, timeout or missing result. Nothing is removed. |
| `instance.worktree_dependents` | This checkout owns Git data used by another live worktree. HTTP 409 before admission; `--force` does not override it. |
| `instance.database_replication_slot` | An owned PostgreSQL database that the removal would drop has a [replication slot](/reference/instance-removal#replication-slots). HTTP 409 before admission; `--force` does not override it. Drop the slot by hand first; Orbit never drops one. |
| `instance.database_slots_unreadable` | Orbit could not read the replication slots on an owned database's server. HTTP 503 before admission; nothing is changed. Try again when the server answers. |
| `instance.checkout_path_unsafe` | The checkout path is not safe to delete. |
| `instance.clone_in_progress` | The Instance is the candidate of an incomplete clone. |
| `instance.removal_conflict` | The Instance belongs to a different removal request, or `--force` was added or dropped on a rerun against the rules above. |
| `operation.target_busy` | Another operation holds the Instance, such as a removal or a create that is still running. For a create, `details.operation_id` names it; wait for its end or cancel it, then destroy again. |
| `instance.destroy_unsupported` | The Node account is not an unprivileged account, or the placement is a member placement. |
| `websocket.route_in_use` | The Route has public Reverb attachments. |
| `analytics.tracking_hosts_exist` | The Instance has analytics tracking hosts. Disable analytics first. |
| `database.removal_conflict` | An owned database is targeted by another Instance. |
| `route.withdrawal_node_unavailable` | A Node that serves the Route is unavailable, so the Route cannot be withdrawn. |
| `instance.transfer_incomplete` | An open transfer owns the Instance. Finish or roll it back first. |
| `operation.kind_unavailable` | The placement has no removal flow, which is today every production Instance and every container default that is not removable, or the source access cannot be verified. |
| `instance.default_destroy_projects_invalid` | `ORBIT_INSTANCES_DEFAULT_DESTROY_PROJECTS` is not a JSON list of positive integer Project IDs. HTTP 500; nothing is recorded. |
| `instance.teardown_step_failed`, `instance.teardown_step_unavailable`, `command.deadline_exceeded` | A teardown step failed, was not found, or outlasted its limit. The Instance stays. |
| `route.withdrawal_failed` | Withdrawing the Route failed. |
| `instance.removal_incomplete` | A step outside the ones above failed. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |
