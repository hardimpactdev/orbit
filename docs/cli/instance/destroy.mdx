Remove an Instance with its Route, Processes, Schedules, and runtime. A development removal runs the teardown steps first and deletes the checkout. A production removal deletes its user, home, application data, and source state after runtime cleanup. See [Instance removal](/reference/instance-removal).

```bash
orbit instance:destroy <instance> [--yes] [--force] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID. |

| Option | Meaning |
| --- | --- |
| `--yes` | Confirm removal without prompting. Required for JSON and noninteractive calls. |
| `--force` | Delete dirty or unpublished development source after identity checks pass, and accept a checkout together with its registered linked worktrees. |

Interactive removal defaults to No. `--force` does not supply consent.

Normal removal refuses dirty source, a `HEAD` that no origin branch or tag contains, and a checkout with registered linked worktrees. `--force` waives only those three refusals. The source identity checks apply in both modes.

```bash
orbit instance:destroy 12
orbit instance:destroy 12 --force
```

<Warning>
Production removal deletes the production account, source state, and whole home, including `releases/`, `.env`, shared data, and `database.sqlite`. Back up any application data you need before removal. Only the local PHP-FPM tuning stays.
</Warning>

Repeat the same command to resume an interrupted removal. A failed development teardown step keeps the Instance, and the next `instance:destroy` runs the teardown list again.
