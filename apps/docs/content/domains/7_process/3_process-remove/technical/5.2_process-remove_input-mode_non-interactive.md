# `process:remove` Non-Interactive Input Mode

[Back to `process:remove` technical contract.](1_process-remove.md)

This page describes how non-interactive input mode resolves `process:remove` input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces non-interactive input mode even when the process has a TTY. It never authorizes destructive consent; `--force` must be passed explicitly.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when destructive consent (`--force`) is absent.
- Fail before side effects when supplied input is forbidden or invalid.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `app` | `--instance` is absent and local instance context does not resolve exactly one instance. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=instance`. |
| `app` | `--instance` is a bare project slug and that project has more than one instance. | Fail before side effects with `error.code=validation_failed`, `error.meta.field=instance`, and `error.meta.reason=instance_required`. |
| `name` | `[name]` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=name`. |
| `force` | Non-interactive input mode and `--force` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=force`. |
