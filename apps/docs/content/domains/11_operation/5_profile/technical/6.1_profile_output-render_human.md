# Human Renderer: `orbit profile [url]`

[Back to `profile` technical contract.](1_profile.md)

**Renderer:** Human renderer.

## Primitive

None. Renderer prints a completed request summary with a dotted timing breakdown and performs no multi-step progress rendering.


## Selection

Use this renderer when `--json` is not present.

## Progress Tree

No progress tree is rendered. `profile` is a single bounded diagnostic request
with its own timing report, and the useful feedback is the completed request
breakdown rather than a synthetic in-progress phase list.

## Success Output

The human renderer shows a compact request headline:

```text
GET https://docs.test/ 200 in 115.42ms
```

Then render timing rows in request order. The JSON timing fields stay
cumulative where the profiler reports cumulative values, but the human
breakdown renders phase durations: `Connect` excludes DNS time, and
`Waiting for response` excludes DNS, connect, and TLS time.

```text
DNS ...................................... 2.15ms
Connect .................................. 3.05ms
TLS ...................................... 8.10ms
Waiting for response ................... 101.18ms
Download response ........................ 5.12ms - 44.1KB
Total .................................. 115.42ms
```

When Toolbar summary data is available, render app-side stages under the
response wait row:

```text
Waiting for response ................... 101.18ms
  orbit-caddy in ......................... 1.50ms
  FrankenPHP ............................ 10.50ms
  Middleware ............................ 10.50ms
  Controller ............................ 80.20ms
  View ................................... 2.30ms
  Toolbar ................................ 3.00ms
  orbit-caddy out ........................ 1.20ms
  Transport .............................. 0.00ms
```

When Toolbar query data is available and query count is greater than zero:

```text
5 queries
```

Slow and duplicate query counts are appended when present:

```text
5 queries, 1 slow, 2 duplicate
```

## Failure Output

Human-rendered failures show the target or field, a clear prose error, and a
recovery command only when the operator can act on it.

Missing URL in non-interactive mode:

```text
URL to profile is required.
```

Conflicting auth modes:

```text
Use either --as-first-user or --user, not both.
```

Invalid URL:

```text
URL to profile must be an absolute HTTP or HTTPS URL.
```

Profile request failed:

```text
Failed to complete profile request.
```

When a `profile_request_failed` response includes caller request diagnostics,
render the safe caller fields below the generic failure line:

```text
Failed to complete profile request.
Origin: caller
URL: https://docs.test/
Error: Operation timed out
```

Input and request failures never trigger a gateway or doctor lookup.
