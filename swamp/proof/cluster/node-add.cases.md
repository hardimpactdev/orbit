# cluster:node:add verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN Node, an inactive and an active Cluster, and Nodes outside any Cluster that serve generated, explicit, custom proxy and public Routes, and checks the Gateway record, Caddy, certificates, firewalls, DNS and real HTTPS requests. The steps of the shared Route child have their own cases in `swamp/proof/route/reconcile.cases.md`. Today the command runs synchronously, changes the records and returns the Cluster at once, with no task, and takes no Cluster lock: every case about the task, its steps, a failure, an interrupt, a lock or a lost response fails today for that reason, and a failure past the cutover leaves the Node outside the Cluster with its Routes already moved. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Inactive Cluster | Attach an active Node that is not a member to an inactive Cluster. | The result is at once, with no task. The Node is a member and its Routes, generated domains, certificates and DNS answers are unchanged. No traffic changes. Fails today: the DNS selection is published to the VPN Node even for an inactive Cluster. |
| Active Cluster with a TLD | Attach a Node with generated Routes to an active Cluster with a TLD and a Router. | The task succeeds and the Node is a member. Its generated Routes have Cluster scope and domains in the Cluster TLD, with new sites, certificates and private DNS answers. The LAN ingress rules are open and requests through the Router succeed. |
| Active Cluster without a TLD | Attach a Node to an active Cluster without a TLD. | The Node's Routes take Cluster scope and its generated domains stay on the Node TLD. |
| Route kinds | The Node has generated, explicit, custom proxy and tracking-host Routes. | Generated Routes move into the Cluster namespace. An explicit Route keeps its domain. A custom proxy Route keeps its Node scope and keeps serving. A tracking host moves with its Instance's Route. Fails today: the legacy path refuses a tracking host with `route.analytics_native_required`. |
| Public Route | An active public Route that the change would move. | `route.reconciliation_required`. No task, no change. |
| No Routes | A Node that serves no Route, attached to an active Cluster with and without an active Router. | The task succeeds in both, the Node is a member, the LAN and DNS steps change nothing and the child does not run. |
| Router required | A Node with Routes that would take Cluster scope, attached to a Cluster with no active Router. | `route.router_required`. No task, no change. |
| Existing member | Attach a Node that is already a member of an active Cluster, and of an inactive Cluster, after its Router LAN rules were removed or left over. | Not skipped: the run restores the missing rules, prunes the left-over ones, and succeeds. Membership and Cluster state do not change. |
| Node refusals | An inactive Node, a Node in another Cluster, and a Node whose LAN address another member uses. | `cluster.node_inactive`, `cluster.membership_conflict` and `cluster.lan_ip_conflict`. No task, no change. |
| Route refusals | A proposed domain that collides with another Route, a generated Route that would have no effective TLD, targets that would span scopes, a tracking host without an active Instance, a Route with no generation basis or one that cannot be reconciled, a targetless Route that would leave its scope, and a Route with another domain change in progress. | `route.domain_conflict`, `route.tld_required`, `route.target_scope_conflict`, `route.target_invalid`, `route.generation_basis_missing`, `route.generation_basis_invalid`, `route.scope_invalid` and `route.domain_change_conflict`. No task and no Route changes, even for the Routes that were valid. |
| Busy | Start the command while a Router change holds the Cluster for more than 30 seconds, and while another Cluster change runs. | `cluster.router_busy`. The running change is unaffected. Fails today: no Cluster lock is taken. |
| Failure before the cutover | Make a CSR, signing, publish, probe, `APP_URL` or DNS move of the child, or the LAN rule step, fail. With no Routes, make the DNS selection fail. | The task fails with the failed step and its code (`app-dev.certificate_request_failed`, `app-dev.certificate_sign_failed`, `route.publish_failed`, `route.probe_failed`, `route.app_url_failed`, `private_dns.publication_failed` or `route.lan_firewall_failed`). The Node stays outside the Cluster and every Route keeps its domain and scope. The prune ran. A rerun after the fix succeeds without duplicates. |
| Failure after the cutover | Make the DNS grace, the withdrawal, the DNS selection or the prune fail. | The task fails with the failed step and its code (`route.dns_grace_failed`, `route.withdraw_failed`, `private_dns.publication_failed` or `route.lan_firewall_failed`). The Node is a member and the Cluster scope serves. |
| Rerun after the cutover | Rerun the command after that failure. | It is not skipped. It finishes the withdrawal and the prune, and the old Routes are deleted. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step and the rerun finishes. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one task exists for the change. |
| Missing input | In a terminal, run the command with no arguments, cancel the Cluster list, and cancel the Node list. Then run it noninteractively and with `--json` without the Cluster and without the Node. | The terminal lists Clusters by name, then the active Nodes that belong to no Cluster and that the caller has a grant to, by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `cluster.id_invalid` or `node.id_invalid`, with no request. Fails today: both are required arguments, so every call without them is refused by the parser. |
| IDs only | A Cluster or Node by name, the ID `0`, the ID `-1`, and `abc`. | `cluster.id_invalid` or `node.id_invalid`, with no request. |
| Unknown and access | A Cluster or Node ID that does not exist, and a caller without a grant to the Node being attached. | `http.404` and `node_access.required`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator for a task, then the final result naming the Cluster and the Node, with the task and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Cluster or task. |
