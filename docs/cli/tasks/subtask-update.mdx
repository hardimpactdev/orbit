---
title: "orbit tasks:subtask:update"
sidebarTitle: "tasks:subtask:update"
description: "Change a subtask's title, brief, position, or deliverables while its task is in `backlog`. In `todo`, `running`, `reviewing`, `settling`, or `waiting_for_review` tasks, change any of those fields only while the subtask is `todo`. Deliverables cannot be empty. A new position moves only among `todo` subtasks; it cannot put one before a started or finished subtask. Positions stay gapless. Started subtasks keep their existing restrictions, and tasks in `completed`, `failed`, or `cancelled` are read-only."
---

```bash
orbit tasks:subtask:update [group] [subtask] [--title=TEXT] [--brief=TEXT] [--position=N] [--deliverables=FILE] [--topology=JSON] [--status=STATUS] [--json]
```

| Option | Meaning |
| --- | --- |
| `--title=TEXT` | New title. |
| `--brief=TEXT` | New brief. |
| `--position=N` | New position, starting at 1. |
| `--status=STATUS` | External groups only: `todo` to `running`, `running` and `reviewing` in either direction, or either active status to `completed` or `failed`. Repeating the current status changes nothing. Other moves return `tasks.status_move_refused`. |
| `--deliverables=FILE` | JSON file with an array of at most five [deliverables](/reference/tasks#deliverables). It replaces the whole list. |
| `--topology=JSON` | JSON array of the test nodes the subtask needs. `[]` removes the declaration. Only a subtask that has not started can change it. |

```bash
orbit tasks:subtask:update 58 88 --deliverables=deliverables.json
```

In a terminal, the task list shows `backlog` tasks and tasks where a `todo` subtask can be edited. Without a change option, the CLI asks which fields to change and prompts for each one with its current value. It does not prompt for deliverables. A `--json` or `-n` call without a change option fails with `tasks.update_required`. A position that is not a positive integer fails with `tasks.position_invalid`. A title, brief, or position change where the task and subtask statuses do not permit it fails with `tasks.not_in_backlog`. A deliverables change for a subtask that has started fails with `tasks.deliverables_locked` and leaves the stored list unchanged. The command never reports success while ignoring that list. An unreadable or malformed file fails with `tasks.deliverables_invalid`.
