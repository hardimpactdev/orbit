# Non-Interactive Input Mode: `orbit dns:resolve-tld [tld] [target]`

[Back to `dns:resolve-tld` technical contract.](1_dns-resolve-tld.md)

This page describes how non-interactive input mode resolves `dns:resolve-tld`
input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY.

## Responsibilities

- Read supplied arguments and options.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when supplied input is forbidden or invalid.
- Require explicit destructive consent for reset.
- Evaluate path eligibility as soon as the fields needed for the rule are
  known.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `tld` | `[tld]` is absent. | Fail before side effects. |
| `target` | `[target]` is absent and `--reset` is absent. | Fail before side effects. |
| `force` | `--reset` is present and `--force` is absent. | Fail before side effects. |

Missing input failures use `error.code=validation_failed` with
`error.meta.field` naming the missing field.

## Forbidden Input Failures

| Field | Forbidden when | Behavior |
| --- | --- | --- |
| `target` | `--reset` is present. | Fail before side effects. |
| `force` | `--reset` is absent. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `tld` is not a single lowercase DNS label without a leading dot;
- `target` is not an IPv4 or IPv6 address.

The selected output renderer owns how these failures are displayed.
