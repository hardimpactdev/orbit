# `process:start` Interactive Input Mode

[Back to `process:start` technical contract.](1_process-start.md)

This page describes how interactive input mode resolves `process:start` input.

**Input mode:** Interactive.

## Selection

Use this input mode only when the process is attached to a TTY and `--json` is not present.

## Prompt Behavior

Prompt for missing required input in this order:

| Field | Prompt primitive | Notes |
| --- | --- | --- |
| `instance` | Datatable | Show concrete instances the caller is authorized to operate when instance context is absent. A supplied ambiguous bare app slug fails with `validation_failed`, `field=instance`, and `reason=instance_required` instead of prompting. |

`name` is optional. When `[name]` is omitted, interactive mode starts all process definitions for the resolved node, instance, or workspace context; it does not prompt for a process by default.
`--workspace` is an explicit filter. If a supplied workspace name is ambiguous,
the command fails and asks the operator to pass `--instance=<app.instance>`.

Prompt validation runs as soon as the field needed for a decision is known.
