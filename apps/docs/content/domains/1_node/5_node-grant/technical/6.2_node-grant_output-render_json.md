# JSON Renderer: `orbit node:grant [consuming_node] [serving_node]`

[Back to `node:grant` technical contract.](1_node-grant.md)

This page describes the JSON-rendered output for `node:grant`.

**Renderer:** JSON renderer.

## Primitive

None. JSON renderer emits the standard envelope only.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even
when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

### Newly granted

```json
{
  "success": {
    "data": {
      "consuming_node": "operator-1",
      "serving_node": "app-1",
      "action": "granted",
      "already_granted": false,
      "permissions": [
        "node:read",
        "tool:read"
      ]
    },
    "meta": {
      "warnings": []
    }
  }
}
```

### Already granted (idempotent)

```json
{
  "success": {
    "data": {
      "consuming_node": "operator-1",
      "serving_node": "app-1",
      "action": "granted",
      "already_granted": true,
      "permissions": [
        "node:read",
        "tool:read"
      ]
    },
    "meta": {
      "warnings": []
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `consuming_node` | string | The consuming node name. |
| `serving_node` | string | The serving node name. |
| `action` | string | Always `granted`. Idempotence is reported by `already_granted`, not by changing the action value. |
| `already_granted` | boolean | `true` when the grant already existed; `false` when this command created it. |
| `permissions` | string[] | Normalized permission set stored on the grant. Existing grants return their current permission set without editing it. |

`success.meta.warnings[]` contains warning objects. Redundant submitted
permissions are reported with `code=node.redundant_permissions` and a
`permissions` array listing the submitted entries that normalization removed.

| Warning field | Type | Meaning |
| --- | --- | --- |
| `code` | string | Stable warning code, such as `node.redundant_permissions`. |
| `family` | string | Always `node`. |
| `message` | string | One-line human-readable summary. |
| `next_command` | string \| null | Suggested follow-up command, or `null`. |
| `permissions` | string[] | Redundant submitted permissions. |

## Error Shapes

### Missing required input

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Consuming node is required.",
    "meta": {
      "field": "consuming_node"
    }
  }
}
```

Or for the serving node:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Serving node is required.",
    "meta": {
      "field": "serving_node"
    }
  }
}
```

### Consuming node not found

```json
{
  "error": {
    "code": "node.not_found",
    "message": "Consuming node 'operator-1' not found.",
    "meta": {
      "field": "consuming_node",
      "name": "operator-1"
    }
  }
}
```

`node.not_found` covers both unknown names and node records that are not in
the `active` lifecycle (for example, records still in `provisioning`). Live
reachability is not probed; convergence checks belong to
`doctor --family=node`.

### Serving node not found

```json
{
  "error": {
    "code": "node.not_found",
    "message": "Serving node 'app-1' not found.",
    "meta": {
      "field": "serving_node",
      "name": "app-1"
    }
  }
}
```

### Grant policy violation

```json
{
  "error": {
    "code": "node.grant_policy_violation",
    "message": "Grant from 'operator-1' to 'app-1' violates node access policy.",
    "meta": {
      "consuming_node": "operator-1",
      "serving_node": "app-1",
      "reason": "unspecified"
    }
  }
}
```

`error.meta.reason` is required and discriminates the specific policy rule
that rejected the grant. The seed enum is documented below; new policy rules
must extend the enum in this contract before they are surfaced as a distinct
reason value.

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to grant node access.",
    "meta": {}
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This action requires the node:grant permission on a grant to the gateway.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "node:grant",
      "serving_node": "gateway-1"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `data.action` | `granted` |
| `error.meta.reason` | `unspecified` |
| `error.code` | `validation_failed`, `node.not_found`, `node.grant_policy_violation`, `gateway_unavailable`, `authorization_failed` |

`error.meta.reason` is used with `node.grant_policy_violation` to
discriminate which policy rule rejected the grant. Add a new reason value to
this renderer contract before surfacing it. Self-grants are accepted and are
not a violation reason.

The `error.code` values listed here are exhaustive for `node:grant`. Add a new
value to this renderer contract before implementing another JSON failure code.
