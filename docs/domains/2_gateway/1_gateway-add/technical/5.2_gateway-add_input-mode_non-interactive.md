# Non-Interactive Input Mode: `orbit gateway:add [gateway_ip]`

[Back to `gateway:add` technical contract.](1_gateway-add.md)

This page describes how non-interactive input mode resolves `gateway:add` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY.

When the local process is running in gateway context, the CLI rejects the
command before this input mode reads command input.

## Responsibilities

- Read supplied arguments and options.
- Derive the gateway WireGuard API address from the active WireGuard network
  when `gateway_ip` is omitted.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are known,
  so non-interactive callers receive the earliest possible validation failure.
- Return a fully resolved input object to the canonical command flow.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `gateway_ip` | `gateway_ip` cannot be derived from the active WireGuard network and is not supplied. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `gateway_ip` is not a valid Orbit WireGuard IPv4 address in `10.6.0.0/16`;
- `gateway_ip` is not reachable as a gateway API endpoint.

The selected output renderer owns how these failures are displayed.
