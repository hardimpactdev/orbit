---
title: "orbit task:create"
sidebarTitle: "task:create"
description: "Create a task. It starts in `backlog` unless you ask for `todo`."
---

```bash
orbit task:create [title] [--project=ID | --parent=ID] [--deliverables=FILE] [--topology=JSON] [--brief=TEXT] [--status=STATUS] [--orchestration=MODE] [--subtasks=FILE] [--preview] [--current-recipe] [--review=MODE] [--implementer-provider=NAME] [--implementer-model=MODEL] [--implementer-effort=LEVEL] [--reviewer-provider=NAME] [--reviewer-model=MODEL] [--reviewer-effort=LEVEL] [--json]
```

| Input | Default | Meaning |
| --- | --- | --- |
| `title` | prompt | Short name of the feature. |
| `--project=ID` | prompt | Numeric Project ID. In a terminal, the CLI lists Projects to select from. |
| `--brief=TEXT` | prompt | Goal and acceptance. Pass a file with `--brief="$(cat brief.md)"`. |
| `--status=STATUS` | `backlog` | `backlog` or `todo`. `todo` needs at least one subtask, each with deliverables, and leaves it ready for `task:start`. |
| `--subtasks=FILE` | none | JSON file with an ordered array of at most 50 objects, each with a string `title` and `brief` and optional `deliverables` and `topology` arrays. |
| `--orchestration=MODE` | `external` | Swamp executes task groups. The only supported mode is `external`; any other value returns `task.orchestration_invalid`. Children can declare workload topology. |
| `--preview` | off | Keep the task's sandbox running during review. See [Request a preview](/reference/compute-drivers#request-a-preview). |
| `--review=MODE` | `manual` | How the gate of the task pull request is passed. `manual`: Nick approves the exact head. `automatic`: a fresh reviewer passes the head in review rounds ([stage 4](/reference/command-development-pipeline#4-pr-and-ci)). Any other value returns `tasks.review_invalid`. `task:show` returns the mode as `review`. |
| `--implementer-provider=NAME` | Project's, else Gateway's | The implementer's provider in a [task copy](/reference/tasks#copy-turn-agents), such as `claude`. |
| `--implementer-model=MODEL` | Project's, else Gateway's | The implementer's model in a task copy, such as `claude-opus-5-5`. |
| `--implementer-effort=LEVEL` | Project's, else Gateway's | The implementer's effort in a task copy: `low`, `medium`, `high`, `xhigh` or `max`. |
| `--reviewer-provider=NAME` | Project's, else Gateway's | The reviewer's provider in a task copy. |
| `--reviewer-model=MODEL` | Project's, else Gateway's | The reviewer's model in a task copy. |
| `--reviewer-effort=LEVEL` | Project's, else Gateway's | The reviewer's effort in a task copy. |
| `--current-recipe` | off | The task needs the current machine recipe. Its VM waits for the current recipe image and never starts from a fallback image. See [Image fallback](/reference/compute-drivers#image-fallback). |

```bash
orbit task:create "Add tasks CLI" --project=1 --brief="$(cat brief.md)"
orbit task:create "Add tasks CLI" --project=1 --brief="$(cat brief.md)" --subtasks=subtasks.json --status=todo
```

The CLI does not prompt for the status, the subtasks, or the notification. After the Gateway answers, the CLI shows the task as `task:show` does. A task created in `todo` waits for an explicit `task:start <id>`.

## Errors

| Error code | Meaning |
| --- | --- |
| `tasks.project_required`, `tasks.title_required`, `tasks.brief_required` | A `--json` or `-n` call omits a required input. |
| `task.project_invalid`, `task.title_invalid`, `task.brief_invalid`, `task.status_invalid` | A supplied value is outside the accepted form. |
| `task.subtasks_invalid` | The CLI cannot read the subtasks file, or its content is not an array of at most 50 entries with a valid title and brief and, when present, a `deliverables` array. |
| `tasks.no_subtasks` | `--status=todo` without subtasks. |
| `tasks.subtask_deliverables_missing` | `--status=todo` while a subtask has no deliverables. |
| `tasks.agent_driver_unavailable` | The Gateway's configured agent driver is unknown. The Gateway stores no task. |
| `task.agent_invalid` | An agent option is empty. |
| `validation.failed` | A provider or effort the task copy does not offer, or a model that is no model name. |

Use `--parent=ID` in place of `--project=ID` to append a subtask. Its Project and workspace are inherited. A contradictory Project, a child parent, or a deeper hierarchy is refused. `--deliverables=FILE` and `--topology=JSON` apply to child creation. Creating in Todo changes board state only. Use `task:start` to start the parent VM.

Parent creation refuses `--deliverables` and `--topology`. Child creation refuses the parent options `--status`, `--orchestration`, `--subtasks`, `--review`, `--preview`, `--current-recipe` and the agent options.

A task that names no agent value takes each one from its Project's default, then from the Gateway; [copy turn agents](/reference/tasks#copy-turn-agents) describes the order and how a turn checks the values against the copy.
