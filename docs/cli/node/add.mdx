title: "orbit node:add"
sidebarTitle: "node:add"
description: "Add a machine to the fleet. For an existing Node, the same command converges it again after you change its TLD, roles, or settings."
---

```bash
orbit node:add <name> [host] [--host-key-fingerprint=SHA256] [--ssh-port=PORT] [--user=USER] [--orbit-user=USER] [--platform=PLATFORM] [--architecture=ARCH] [--tld=TLD] [--role=ROLE]... [--cluster=ID] [--wireguard-ip=IP] [--lan-ip=IP] [--dns-server=IP] [--setting=PATH:VALUE] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `name` | yes | Unique Node name. |
| `host` | for a new Node, or an existing Node with no pinned host key | Public SSH host. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--host-key-fingerprint=SHA256` | none | Approved SSH host key fingerprint. Required for a new Node, or an existing Node with no pinned host key. For an existing Node it must equal the recorded one. |
| `--ssh-port=PORT` | `22` | Public SSH port. |
| `--user=USER` | `root` for a new Node, the managed user for an existing Node | Bootstrap SSH user. |
| `--orbit-user=USER` | `orbit` for a new Node | Managed user that every later Gateway command uses. |
| `--platform=PLATFORM` | `linux` | `linux` for Ubuntu service Nodes, or `macos` for tools on an existing account and tunnel. |
| `--architecture=ARCH` | the observed value | Machine architecture. A given value must equal the observed one. A Linux Node accepts only `x86_64`; another value, or a Linux machine that reports another architecture, fails with `node.architecture_unsupported`. |
| `--tld=TLD` | none | Node TLD. Required for `app-dev`, unless the Node joins an active Cluster with a TLD. A production Node needs it for [clone](/cli/instance/clone) preview domains. It cannot equal, be an ancestor of, or be a descendant of `orbit` or the configured VPN domain. Comparisons ignore case and the VPN domain’s optional root dot, and use DNS label boundaries. |
| `--role=ROLE` | none | Role to assign. Repeat for more roles. Without it, see [Nodes without roles](/reference/node-provisioning#nodes-without-roles). |
| `--cluster=ID` | none | Cluster to join. |
| `--wireguard-ip=IP` | generated | Stable WireGuard address. |
| `--lan-ip=IP` | none | LAN IPv4 address of this Node. A Cluster Router reaches the Node there, and a Node on the hub's private network reaches the hub at the hub's LAN address. See [The LAN endpoint](/reference/wireguard-endpoints#the-lan-endpoint). |
| `--dns-server=IP` | Orbit VPN DNS | A WireGuard-subnet DNS server for the complete Orbit private-name set. Public names keep the normal resolver. Existing overrides are cleared on upgrade. See [Private DNS](/reference/private-dns). A [Node without roles](/reference/node-provisioning#nodes-without-roles) does not use it. |
| `--setting=PATH:VALUE` | none | Node setting. The only path is `apps.path`. |
| `--json` | off | Print the final Operation as JSON. |

`--role` accepts `app-dev`, `app-prod`, `database`, `metrics`, `websocket`, `gateway`, and `vpn`. Add `ingress` and `analytics` with [`node:role:add`](/cli/node/role-add). A Cluster Router comes from [`cluster:router:set`](/cli/cluster/router-set).

```bash
orbit node:add beast beast.example.com \
  --host-key-fingerprint=SHA256:... \
  --role=app-dev \
  --tld=test \
  --setting=apps.path:/srv/orbit/apps

orbit node:add beast --role=app-dev --role=database
```

For macOS, use `node:add` with `--platform=macos` and set `--user` and `--orbit-user` to the same existing account. The machine must already join WireGuard and accept the Gateway's SSH key. No role is required. A role request fails with `node.platform_unsupported` before SSH. This path also enrolls an existing roleless peer whose SSH identity is not pinned, and it can correct that peer's platform and architecture from the machine. See [macOS Nodes](/reference/node-provisioning#macos-nodes).

In a terminal, an omitted name is asked for as text, and so are the host and the fingerprint for a new Node or an existing Node with no pinned host key. A noninteractive or `--json` call that omits one is refused with `input.invalid` for the name or host, or `node.ssh_host_fingerprint_required` for the fingerprint, and sends no request.

A Node with Instances cannot be enrolled again, including for a TLD change. Repeating the command for an active Node with unchanged settings converges it again and checks it; it succeeds with the usual result and creates no duplicates.

Orbit checks the machine's SSH host key against the approved fingerprint before it changes anything. It then sets up the machine, the WireGuard tunnel and the Node agent, converges the requested roles, and checks the Node. The first role closes public recovery SSH, so the Node is reachable over WireGuard only afterwards. The CLI shows one progress indicator while the Operation runs, then the final result with the Operation and request IDs.

A failed run retains the work it finished and does not roll back. A new Node stays, marked failed at the failed step. An existing Node keeps its earlier recorded identity and stays active until the full check passes. A role that the request created and that did not finish stays marked failed. Publishing the Orbit CLI is best effort and never fails the run. After you fix the cause, run the same command again: every step skips work that is already done. [`node:remove`](/cli/node/remove) removes a failed Node.

## Errors

| Code | Meaning |
| --- | --- |
| `input.invalid` | The name or host is missing and the CLI cannot prompt. |
| `node.ssh_port_invalid`, `node.platform_invalid`, `node.host_key_fingerprint_invalid`, `node.wireguard_ip_invalid`, `node.lan_ip_invalid` | An option value is malformed. Refused before the request. |
| `node.setting_unknown`, `node.setting_duplicate`, `node.setting_invalid` | A `--setting` path is not `apps.path`, is repeated, or has an invalid value. |
| `node.has_instances` | The Node already owns Instances, so it cannot be enrolled again. |
| `node.ssh_host_fingerprint_required` | A new Node, or an existing Node with no pinned host key, has no approved fingerprint. |
| `node.ssh_host_key_mismatch` | The machine's host key, or for an existing Node the given fingerprint, differs from the approved or recorded one. Nothing changes. |
| `node.ssh_host_key_changed` | The machine presents a different host key than the one recorded for this Node. |
| `node.architecture_unsupported` | The architecture is not `x86_64` on a Linux Node. |
| `node.hub_lan_unreachable` | The Node records a `lan_ip` on the hub's private network, but the hub's LAN address is not directly routed from it or does not answer. No tunnel file changed. See [The LAN endpoint](/reference/wireguard-endpoints#the-lan-endpoint). |
| `node.platform_unsupported` | A macOS Node was given a role, or a TLD, Cluster, DNS, tunnel or storage setting. Refused before SSH. |
| `node.macos_account_required`, `node.macos_account_mismatch`, `node.wireguard_required` | A macOS Node needs `--user` and `--orbit-user` naming the same existing account, and an existing WireGuard address. |
| `node.tld_required`, `node.tld_invalid`, `node.tld_taken`, `node.tld_conflict` | `app-dev` has no TLD, or the TLD is malformed, reserved, in use, or conflicts with another name Orbit serves. |
| `node.role_conflict` | A requested role cannot be assigned during enrollment or conflicts with the Node's roles. |
| `cluster.not_found`, `cluster.membership_conflict`, `cluster.lan_ip_conflict` | The Cluster does not exist, the Node cannot join it, or the LAN address is already used in it. |
| `node.invalid_linux_user`, `node.user_change_unsupported` | The managed user is not a valid Linux account name, or an existing Node's managed user cannot change. |
| `node.ssh_host_key_scan_failed`, `node.bootstrap_account_unavailable`, `node.enrollment_failed` | The run could not read the host key, log in to the bootstrap account, or finish enrollment. |
| `node.provisioning_busy` | Another lifecycle operation holds the Node's name lock. Nothing changes. |
