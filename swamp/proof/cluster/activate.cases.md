# cluster:activate verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN Node, a Cluster with a Router and member Nodes that serve generated, explicit, custom proxy and public Routes, and checks the Gateway record, Caddy, certificates, firewalls, DNS and real HTTPS requests. The steps of the shared Route child have their own cases in `swamp/proof/route/reconcile.cases.md`. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Activate with a TLD | An inactive Cluster with a TLD, a Router and members with Node-scoped Routes. Activate. | The task succeeds and the Cluster is `active`. The LAN ingress rules are open, private DNS answers Cluster names with the Router, and each affected Route has Cluster scope with generated domains in the Cluster TLD. Requests through the Router succeed, and a requester on the LAN gets the Router's LAN address while others get its WireGuard address. Fails today: the command changes the records and returns the Cluster at once, with no task. |
| Activate without a TLD | An inactive Cluster without a TLD. | The Cluster is `active`, Routes take Cluster scope, and generated domains stay on the Node TLDs. |
| Route kinds | Generated, explicit, custom proxy and tracking-host Routes. | Generated Routes move into the Cluster namespace. An explicit Route keeps its domain. A custom proxy Route keeps its Node scope and keeps serving. A tracking host moves with its Instance's Route. |
| Public Route | An active public Route that the change would move. | `route.reconciliation_required`. No task, no change. |
| No Routes | A Cluster whose members serve no Route. | The task succeeds, the LAN ingress rules and DNS selection are in place and the child does not run. |
| Skip | Activate an active Cluster with no unfinished change. | The command succeeds with `Skipped — already active (cluster.state_unchanged)`, starts no task and changes nothing. Fails today: it returns the Cluster without a reason code. |
| Router required | A Cluster with a TLD and no active Router, and a Cluster without a TLD that has affected Routes and no active Router. | `cluster.router_required` and `route.router_required`. No task, no change. |
| TLD owned elsewhere | A non-member Node owns the Cluster TLD. | `cluster.tld_conflict`. No task, no change. |
| Route refusals | A proposed domain that collides with another Route, a generated Route with no effective TLD, targets that would span scopes, a tracking host without an active Instance, a Route with no generation basis or one that cannot be reconciled, and a targetless Route that would leave its scope. | `route.domain_conflict`, `route.tld_required`, `route.target_scope_conflict`, `route.target_invalid`, `route.generation_basis_missing`, `route.generation_basis_invalid` and `route.scope_invalid`. No task and no Route changes, even for the Routes that were valid. |
| Reconciliation refused | A Route that depends on the change and cannot be reconciled by it. | `route.reconciliation_required`. No task, no change. |
| Busy | Start the command while a Router change holds the Cluster for more than 30 seconds, and while another Cluster change runs. | `cluster.router_busy`. The running change is unaffected. |
| Failure before the cutover | Make the LAN rule step (`route.lan_firewall_failed`) or a publish, probe, `APP_URL` or DNS step of the child fail. | The task fails with the failed step and its code (`route.publish_failed`, `route.probe_failed`, `route.app_url_failed` or `private_dns.publication_failed`). The Cluster stays inactive and every Route keeps its domain and scope. The prune ran: the LAN rules and DNS selection the stored state does not need are gone. A rerun after the fix succeeds without duplicates. |
| Failure after the cutover | Make the DNS grace, the withdrawal or the prune fail. | The task fails with the failed step and its code (`route.dns_grace_failed` or `route.withdraw_failed`). The Cluster is `active` and the new placement serves. |
| Rerun after the cutover | Rerun the command after that failure. | It is not skipped. It finishes the withdrawal and the prune, and the old Routes are deleted. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step and the rerun finishes. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one task exists for the change. |
| Missing input | In a terminal, run the command with no arguments and cancel the list. Then run it noninteractively and with `--json` without the Cluster. | The terminal lists Clusters by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `cluster.id_invalid`, with no request. Fails today: the Cluster is a required argument, so every call without it is refused by the parser. |
| IDs only | A Cluster by name, the ID `0`, the ID `-1`, and `abc`. | `cluster.id_invalid`, with no request. |
| Unknown and access | An ID that does not exist, and a caller without a grant to a member Node. | `http.404` and `node_access.required`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result naming the Cluster, with the task and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final task. |
