# Interactive Input Mode: `orbit node:new [name]`

[Back to `node:new` technical contract.](1_node-new.md)

This page describes how interactive input mode resolves missing `node:new`
input before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_node-new_input-mode_non-interactive.md`](5.2_node-new_input-mode_non-interactive.md) even if the process has a TTY.

Authorization is owned by the gateway. Callers that are configured but are not
gateways resolve input like other clients and may receive a gateway
authorization failure after the request is forwarded. Unconfigured clients can
only use the first-gateway bootstrap path.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- Return a fully resolved input object to the canonical command flow.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `node_new.name` | `[name]` is missing. |
| 2 | `node_new.template` | Neither `--template`, `--operator`, nor `--roles` is supplied. |
| 3 | `node_new.host` | A host-provisioned template or role set is selected and `--host` is missing. |
| 4 | `node_new.app_production_public_traffic` | `app-production` template or `app-prod` role is selected. |
| 5 | `node_new.ingress_node` | Private `app-prod` placement is selected and `--ingress` is missing. |
| 6 | `node_new.operator_name` | First-gateway bootstrap is selected and `--operator-name` is missing. |
| 7 | `node_new.redis_node` | `websocket` template or role is selected and `--redis-node` is missing. |
| 8 | `node_new.user` | SSH provisioning is used and `--user` is missing; the prompt lets the operator override the `root` default. |

When neither `--template`, `--operator`, nor `--roles` is supplied after the
template prompt, interactive input mode may continue down the bare client
identity path with no assigned roles.

Render `node_new.operator_name` only for first-gateway bootstrap. The default is
the local short hostname normalized to the node name format used by the gateway registry:
lowercase it, replace each run of unsupported characters with one hyphen, and
trim leading or trailing hyphens. If that default is empty, invalid, or
conflicts with the gateway node name, keep the operator at the prompt until a
valid client name is entered or the prompt is aborted.

When no node role is selected for a client identity, do not render
`node_new.host`, `node_new.operator_name`, `node_new.tld`, or `node_new.user`.

When canonical `app-prod` is selected through a template expansion or explicit
role set, render the public traffic prompt before later prompts that depend on
placement:

```text
Serve public traffic from this node? [yes]
```

`yes` resolves to colocated `app-prod` + `ingress`. `no` resolves
to a private backend `app-prod` node and requires `node_new.ingress_node`.

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid field-local input shows a validation message and re-prompts until the
  value is valid, the answer changes the selected path so the prompt is no
  longer needed, or the user aborts. There is no generic retry cap.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If a blocker is already knowable and the current prompt can
  correct it, show a validation message and re-prompt at that prompt instead of
  asking for later unrelated input. If the blocker cannot be corrected by the
  current prompt flow, stop before side effects.
- Forbidden input follows the canonical input contract. If a forbidden value was
  collected by prompt and the current prompt can correct it safely, show a
  validation message and re-prompt. If the value was supplied as an option or
  argument, or cannot be corrected safely in the current prompt flow, fail
  before side effects.
- Gateway-side `authorization_failed` rejections (missing `node:new` on the
  caller's grant) surface before prompts or side effects.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
