```bash
orbit instance:create <project> <node> <name> [--root=PATH] [--domain=HOST] [--branch=BRANCH] [--database-server=SLUG] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `project` | yes | Numeric Project ID. |
| `node` | yes | Numeric ID of an active Node with the `app-dev` role. |
| `name` | yes | Instance name. `default` is the Project's default development source. A name that equals the Project `default_branch`, such as `main`, creates the `default` Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--root=PATH` | the Project root | Relative web-root override for this Instance. |
| `--domain=HOST` | generated | Route domain. Without it, Orbit generates one from the active Cluster TLD, then the Node TLD. |
| `--branch=BRANCH` | see [branch selection](#branch-selection) | Source branch. |
| `--database-server=SLUG` | none | Create the Instance's database on this [Database server](/reference/database-servers) before setup. See [database on a server](/domains/applications#database-on-a-server). |
| `--json` | off | Print the result as JSON. |

In a terminal, an omitted project and node are chosen from interactive lists, with the Nodes limited to active `app-dev` Nodes, and an omitted name is asked for with the default `default`. A noninteractive or `--json` call that omits one is refused with `input.invalid`, naming the input, and sends no request.

```bash
orbit instance:create 4 7 default
orbit instance:create 4 7 feature-one --branch=release --domain=feature.example.test
orbit instance:create 4 7 t3-1a2b3c4d --branch=t3code/1a2b3c4d
```

In a terminal, the CLI shows the steps below as a progress tree, then the result with the task and request IDs. It names the Project and the Node, not only their IDs. Create runs these steps on the Node, in order. Steps 1 and 2 run together as the `checkout` phase and step 5 runs as the `setup` phase. A failed setup step stops the run, and its name is in the failed step's log.

1. Clone the repository and check out the branch. Orbit mints a read token for this one repository, valid one hour. The token is never part of a command line and is removed from the Node after the clone.
2. Write `.env` from the Project's env template, with `APP_URL`, a new `APP_KEY` and the database keys. The file has mode 0640 and group `orbit-env`. An owned MySQL or PostgreSQL database also gets `.env.testing`.
3. When the Project's `default` Instance has a SQLite database, copy it to the same path in the new checkout. The copy is the Instance's own `<project>-<instance>` connection, and `.env` already names it.
4. With `--database-server`, or when the `default` Instance's database is MySQL on a Database server, create the Instance's owner, database and test database there, as [`database:create --instance`](/reference/database-servers#create-a-database-on-a-server) does. A MySQL `default` database is then copied in.
5. Run the Project setup steps, such as `composer install` and `php artisan migrate`, in order, as the Node's configured user.
6. Create and start the Processes from the Project's development Process definitions.
7. For a web-serving Project, create its Route (its key, CSR and signature are made at the start, beside the checkout) as [`route:create`](/cli/route/create) does, and probe the site over TLS. When this run starts every Process of the Instance, the Instance also becomes awake, so the first request reaches the application and not the wake page.

The run has 60 seconds, plus the setup step timeouts, 30 seconds for the Processes, 180 seconds for the Route, and 180 seconds for a database copy or a database on a server.

A Project that serves no web pages has no Route and takes no `--domain` (`instance.route_unserved`). A domain that another Route owns, or a reserved name such as `gateway.orbit`, is refused with `route.domain_conflict`.

## On a container Node

On a Node of the [build list](/reference/development-containers#the-build-list), the Project's first `default` Instance is a container, not a checkout ([chart](https://github.com/hardimpactdev/orbit/blob/main/docs/cli/instance/container/create-default.mmd)). Orbit creates the container from the Node's image and fetches the default branch into a mirror on the Node. It pushes the branch in, writes `.env`, and runs the Project's [development deploy steps](/reference/deployments#development-deploy-steps) as `orbit`; there are no setup steps. Then it starts FrankenPHP, publishes the Route to it, and takes the first seed snapshot. A Project has one `default` in the fleet, and its other Instances are made on that `default`'s Node. [The default Instance](/reference/development-containers#the-default-instance) has the details and what a container default cannot run yet.

A failed create leaves the container stopped, with its workspace; the same command resumes it.

## Branch selection

| Creation input | Checkout | Selected branch |
| --- | --- | --- |
| `default` or the default branch name, without `--branch` | `<node-apps-root>/<project-slug>/default` | The Project `default_branch`. |
| Another name without `--branch` | `<node-apps-root>/<project-slug>/<name>` | The matching origin branch, otherwise the existing local branch, otherwise a new branch from the fetched `default_branch` commit. |
| Any name with `--branch` | The checkout for the requested name | The requested origin branch, otherwise the existing local branch, otherwise a new branch from the fetched `default_branch` commit. It need not match the Instance name. |

An existing local branch is not reset. If the fetched `default_branch` is needed and missing, create fails with `instance.branch_resolution_failed`. An invalid Git branch name is refused with `validation.failed` before anything changes. When the name equals the default branch, the result carries `name_converted_from` with the requested name, and `--branch` keeps its meaning. See [a default-branch name means default](/domains/applications#a-default-branch-name-means-default).

## Repeat and failure

The Instance and its Route become active only after every step succeeds. A successful create means every setup step succeeded; an empty list counts as success. The application can still fail for other reasons.

Repeating the command for an Instance that is already created succeeds with `Skipped — already created (instance.exists)`.

A failed create withdraws the Route it published: the Caddy site, the PHP pool, the private DNS records and the certificate folders. It keeps the reserved Instance, its checkout, its Processes and its database, marked failed; `instance:destroy` removes them. The task keeps the failed step and its error code, so nothing on the Node is needed to see what failed. A setup step that is missing or not executable fails with `instance.setup_step_unavailable`, naming the step and the Node. Any other setup failure is `instance.setup_step_failed`.

Run the command again with a new idempotency key once the task has ended, or run `instance:destroy` first.

If the cleanup does not finish, the Instance stays marked failed with `details.cleanup = "incomplete"`. Run the same command again to finish the cleanup and create the Instance, or run [`instance:destroy`](/cli/instance/destroy). A changed `--root` or `--branch` is refused with `instance.placement_conflict` until the cleanup is done.

## Errors

| Error code | Meaning |
| --- | --- |
| `instance.candidate_required` | The Node is a production Node. Create a production Instance with [`instance:clone`](/cli/instance/clone). |
| `instance.node_inactive`, `instance.node_not_app_dev` | The Node is not active, or has no active `app-dev` role. |
| `instance.task_vm_node` | The Node is a task VM. A task gets its workspace from [`task:start`](/reference/tasks#provision-an-external-group). |
| `instance.default_path_occupied`, `instance.path_taken` | The checkout path is in use on the Node. |
| `instance.placement_conflict` | A repeat changed the root or branch while an earlier failed create is still being cleaned up. |
| `instance.removal_conflict` | The Instance is being removed. |
| `instance.route_unserved` | `--domain` was given for a Project that serves no web pages. |
| `route.domain_conflict` | Another Route owns the domain, or the name is reserved. |
| `instance.database_server_existing` | `--database-server` was given for an Instance that finished its first setup. |
| `instance.database_slug_taken` | The database connection name belongs to another owner. |
| `instance.setup_step_failed`, `instance.setup_step_unavailable` | A setup step failed, or its command is missing. |
| `instance.branch_resolution_failed` | The default branch could not be fetched. |
| `operation.target_busy` | Another change to the Instance is running. |
| `instance.default_missing` | The Project's `default` runs in a container on another Node, or a build-list Node has no `default` of the Project yet. |
| `instance.host_unavailable` | The container Node is not prepared, its bridge is full, or its runtime folder lacks the Project's PHP build. |
| `operation.kind_unavailable` | The request needs a part of the container runtime that is not built yet. |
