# JSON Renderer: `orbit workspace:list`

[Back to `workspace:list` technical contract.](1_workspace-list.md)

This page describes the JSON-rendered output for `workspace:list`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

The workspace array is rendered as a flat array under
`success.data.workspaces`. Workspaces are sorted by owning node name (ascending,
case-insensitive), then by parent project name (ascending, case-insensitive), then by
workspace name (ascending, case-insensitive). This matches the order shown in
human output, so both renderers represent the same result.

`workspace:list` does not include `success.data.context`. Its `--instance` and
`--node` inputs are registry filters, not a resolved execution context. Use
`success.meta` for stable filter echoes if a future renderer contract needs to
expose them.

## Success Shape

```json
{
  "success": {
    "data": {
      "workspaces": [
        {
          "name": "feature-docs",
          "project": "docs",
          "instance": "development",
          "node": "app-1",
          "url": "https://feature-docs.docs.test",
          "lifecycle_status": "expected"
        }
      ]
    },
    "meta": []
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `workspace` | array | Ordered list of visible workspaces matching the applied filters. |
| `workspaces[].name` | string | Workspace name slug. |
| `workspaces[].project` | string | Parent project slug. |
| `workspaces[].instance` | string | Required selected instance name. |
| `workspaces[].node` | string | Effective workspace node slug. |
| `workspaces[].url` | string | Canonical HTTPS URL of the workspace. The proxy/TLS/backend artifact behind this URL is owned by `proxy`; `workspace:list` only reports the workspace's intended URL. |
| `workspaces[].lifecycle_status` | string | Registry configuration lifecycle: one of `expected`, `setup-pending`. Not setup-run status or a live HTTP probe result. Removed workspaces disappear from list output; no retained removal state is emitted. |

### Empty result

When no workspaces match the filters or the visible set is empty:

```json
{
  "success": {
    "data": {
      "workspaces": []
    },
    "meta": []
  }
}
```

## Error Shapes

### Invalid filter value

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Unknown instance: 'unknown-instance'.",
    "meta": {
      "field": "instance",
      "value": "unknown-instance"
    }
  }
}
```

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Unknown node: 'unknown-node'.",
    "meta": {
      "field": "node",
      "value": "unknown-node"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to list workspaces.",
    "meta": []
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to read the workspace registry.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "workspace:read"
    }
  }
}
```
