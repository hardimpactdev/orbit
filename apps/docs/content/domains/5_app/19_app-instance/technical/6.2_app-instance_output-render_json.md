# JSON Renderer: `orbit app:instance`

[Back to `app:instance` technical contract.](1_app-instance.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope.

## Selection

Use this renderer when `--json` is present.

`--json` also selects non-interactive input. For `remove`, it never implies
destructive consent; `--force` is required.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Error Shapes

Missing non-interactive consent, including `remove --json` without `--force`:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Pass --force to remove this app instance.",
    "meta": {
      "field": "force",
      "reason": "destructive_consent_required"
    }
  }
}
```

Serving-node authorization failure:

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This client is not authorized to remove 'billing.development'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "app:write",
      "app_instance": "billing.development",
      "serving_node": "app-dev-1"
    }
  }
}
```

Other command-specific errors use the standard envelope. Common validation and
gateway failures follow the shared command contract. Interactive cancellation
uses `validation_failed` with `meta.field=force` and `meta.reason=cancelled`.
