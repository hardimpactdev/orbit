# Non-Interactive Input Mode: `orbit profile [target]`

[Back to `profile` technical contract.](1_profile.md)

This page describes how non-interactive input mode resolves `profile` input.

**Input mode:** Non-interactive.

## Selection

Use non-interactive input mode when the command runs without a TTY or when
`--json` is present. `--json` forces non-interactive input mode.

## Resolution Rules

- Never render prompts.
- Resolve app target from `[target]`, `--app`, or current-directory context.
- If no app can be resolved, fail before the HTTP request with
  `validation_failed`.
- If `[target]` and `--app` are both supplied, fail before app resolution.
- If `--as-first-user` and `--user` are both supplied, fail before app
  resolution.
- If a full URL target is supplied, parse it before validation so automation may
  pass a copy-pasted URL.
- `--json` selects the JSON renderer and this input mode only; it does not
  change auth, target visibility, or request-origin rules.

## Failure Mapping

| Condition | `error.code` | `error.meta` |
| --- | --- | --- |
| Missing target and no cwd app can be resolved | `validation_failed` | `field=target`, `reason=missing_required_input` |
| `[target]` and `--app` combined | `validation_failed` | `field=target`, `reason=conflicts_with_app` |
| `--as-first-user` and `--user` combined | `validation_failed` | `field=auth`, `reason=conflicting_auth_modes` |
| Invalid `--uri` | `validation_failed` | `field=uri`, `reason=invalid_path` |
| Invalid `--node` | `validation_failed` | `field=node`, `reason=unknown_node` |
