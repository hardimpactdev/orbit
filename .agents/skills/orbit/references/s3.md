# S3 Commands

S3 commands manage Orbit's fleet object-storage surface. The backend is
SeaweedFS behind the `s3` role, but callers use the product surface:
`s3.orbit`, public S3 host publication, and service credentials. Spec:
[`apps/docs/content/domains/18_s3/`](../../../../apps/docs/content/domains/18_s3/).

The `s3` role runs one SeaweedFS backend in a Docker runtime container rendered
by Orbit. It binds only to the node's WireGuard address. Public S3 traffic
flows `ingress -> router -> S3 backend pool`; ingress never routes directly to
S3 role nodes.

S3 is not its own doctor state family in v1. State is coordinated through:
`node` for the `s3` role assignment and data path, `tool` for the `seaweedfs`
tool row/credentials/capability state, `process` for SeaweedFS runtime
lifecycle, and `proxy` for private and public routes.

## Commands

```bash
orbit s3:credentials [--node=<node>] [--json]
orbit s3:publish [<host>] [--node=<node>] [--json|--stream-json]
orbit s3:unpublish [<host>] [--node=<node>] [--force] [--json|--stream-json]
```

`s3:publish` and `s3:unpublish` support `--stream-json` for JSONL progress.
`s3:unpublish --stream-json` still requires `--force`; stream mode does not
imply destructive consent.

Examples:

```bash
orbit node:new storage-1 --template=s3 --host=10.0.0.20 --tld=storage-1 --s3-data-path=/srv/orbit/s3/data
orbit s3:credentials --node=storage-1 --json
orbit s3:publish s3.example.com --node=storage-1
orbit s3:unpublish s3.example.com --node=storage-1 --force
```

V1 does not manage buckets, bucket policy, per-app credentials, virtual-hosted
bucket routes, wildcard bucket DNS/TLS, distributed SeaweedFS, or public
SeaweedFS console exposure.
