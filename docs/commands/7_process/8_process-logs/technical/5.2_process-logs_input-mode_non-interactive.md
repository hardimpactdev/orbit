# `process:logs` Non-Interactive Input Mode

[Back to `process:logs` technical contract.](1_process-logs.md)

This page describes how non-interactive input mode resolves `process:logs` input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces non-interactive input mode even when the process has a TTY.

## Responsibilities

- Read supplied arguments, options, and local context.
- Apply documented defaults.
- Never render prompts.
- Fail before opening the log stream when required input is absent.
- Fail before opening the log stream when supplied input is forbidden or invalid.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `app` | Neither `--app` nor local context resolves exactly one app, and `--workspace` does not resolve an app. | Fail before opening the log stream with `error.code=validation_failed` and `error.meta.field=app`. |
| `name` | `[name]` is absent. | Fail before opening the log stream with `error.code=validation_failed` and `error.meta.field=name`. |
| `json` | `--json` is present with `--follow`. | Fail before opening the log stream with `error.code=validation_failed` and `error.meta.field=json`. |
