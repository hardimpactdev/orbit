# Human Renderer: `orbit workspace:log <run>`

[Back to `workspace:log` technical contract.](1_workspace-log.md)

This page describes the human-rendered terminal output for `workspace:log`.

**Renderer:** Human renderer.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `workspace:log` does not
prompt for input; missing or invalid `<run>` values fail with a prose error
when `--json` is absent and with the JSON envelope when `--json` is present.

## Progress Tree

`workspace:log` reads **past** captured history from the gateway. The
progress tree shows the completed or failed state of each captured step;
it does not transition in real time. No spinner is rendered because
execution is a gateway-local database read. Step labels describe work captured
from the original lifecycle run, not work performed by `workspace:log`.

```text
Workspace Log Run #12  (docs/feature-docs on app-1)
✔ Validate workspace intent
✔ Captured app-node connection step (app-1)
✔ Create workspace directory
✘ Install dependencies (composer install)
  [EXIT CODE 1]

  STDOUT:
  > Loading composer repositories with package information
  > Updating dependencies

  STDERR:
  > Your requirements could not be resolved to an installable set of packages.
  >   - spatie/laravel-orbit[v1.0.0, ..., v1.1.0] require php ^8.2 -> your php version (8.1.0) does not satisfy that requirement.

Run #12 failed (started 2026-04-30 10:00:00, duration 12.5s)
```

## Step Display Rules

1. **Header.** Single-line header naming the run ID, owning app/workspace,
   and owning app-node. Skipped when the gateway read fails before run
   resolution.
2. **Step status icon.** `✔` for `success`, `✘` for `failure`, `·` for
   `skipped`.
3. **Step context.** Show the step name and, when present, the executed
   command in parentheses.
4. **Exit code.** Show the exit code line only for failed steps.
5. **Captured output.**
   - For failed steps: always show `STDOUT:` and `STDERR:` blocks, omitting
     a block only when its captured stream is empty.
   - For successful steps: only show output when the captured stream is
     non-empty.
   - For skipped steps: do not show output blocks; the step list line is
     enough.
   - When the captured stream was truncated by the gateway, the `[TRUNCATED]`
     marker appears at the end of the stream as captured. The renderer does
     not invent a separate "truncated" message; the marker is part of the
     captured text.
6. **Footer.** Final line shows `Run #<id> <status>` plus the run start
   time and total duration. The status word is colored using the same
   palette as `workspace:history` (Green: `completed`, Red: `failed`,
   Yellow: `running`, Gray: `cancelled`).

The renderer does not display per-step `started_at`/`finished_at` or
`duration_ms` by default. Step timing is durable data captured by the
canonical contract; surfacing it inline is a future renderer choice that
does not require a contract change.

## Failure Output

Human-rendered failures must show:

- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Validation failed

```text
Workspace run ID is required.
```

### Run not found

```text
Error: Workspace run 999 not found.
Check 'orbit workspace:history' for available run IDs.
```

### Log not found

```text
Error: Captured output for run 12 has been pruned.
```

### Authorization failed

```text
This caller is not authorized to read logs for workspace 'feature-docs'.
```

### Gateway unavailable

```text
Gateway connection is required to read workspace run logs.
```
