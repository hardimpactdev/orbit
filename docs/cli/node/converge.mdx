---
title: "orbit node:converge"
sidebarTitle: "node:converge"
description: "Bring one Node fully to the release: Orbit binaries, role software, roles, Tools, and network. It never changes an Instance or a role assignment, so it works on a Node that owns Instances, unlike `node:add`."
---

```bash
orbit node:converge <node> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `node` | yes | Numeric Node ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Print the final Operation as JSON. |

```bash
orbit node:converge 7
```

In a terminal, an omitted Node is chosen from an interactive list. A noninteractive or `--json` call without it is refused with `node.id_invalid` and sends no request.

Every run applies all phases in order, and each phase skips what already matches:

1. **Orbit binaries.** The Node agent and the Orbit CLI at the release's pins, the agent's configuration and unit, the `orbit-env` access to Instance `.env` files, and the temporary-file cleanup rule. The agent restarts only when a file changed.
2. **Role software.** The common and role tools at the pins of the release. They are held, so a Tool cannot move tested software. Ubuntu security updates still pass.
3. **Roles.** The configuration of the Node's active roles. It changes no role assignment. Closing world access on Instance `.env` files and clearing Route residue are best effort and never fail the run; the next converge tries again.
4. **Tools.** The Node's recorded Tools, when it has any. A Tool that fails is marked failed on its own record, the other Tools still run, and the task still succeeds.
5. **Network.** The WireGuard peer and the hub change together: the hub first, then the Node. A rerun with no drift writes no file and reloads nothing.
6. **Check.** The role software, units, sites and a recent tunnel handshake. This is the one end check. A hub with no peers has no handshake to check, and a Node with no recorded hub skips the network phase.

Only an active, managed Linux Node can be converged; any other Node is refused with `node.converge_unsupported`. Only one converge runs at a time for a Node and for the hub: another is refused with `operation.target_busy`. The CLI follows the task and prints the final result with the request ID.

A failed phase fails the task with that phase. The run's private files are removed after success or failure. Finished phases stay and nothing is rolled back. After you fix the cause, run the same command again; it starts from the first phase and skips what matches.

## Errors

| Code | Meaning |
| --- | --- |
| `node.id_invalid` | The Node is missing or is not a positive integer, and the CLI cannot prompt. |
| `node.converge_unsupported` | The Node is not an active, managed Linux Node. |
| `operation.target_busy` | Another converge holds the Node or the hub. |
| `node.access_denied` | The caller has no access grant to the Node. |
