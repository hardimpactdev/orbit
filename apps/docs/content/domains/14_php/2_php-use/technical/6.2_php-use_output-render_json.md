# JSON Renderer: `orbit php:use`

[Back to `php:use` technical contract.](1_php-use.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "php": {
        "supported": ["8.5", "8.4", "8.3"],
        "available_images": ["8.5"],
        "image_inventory_status": "confirmed",
        "cli": "8.5",
        "app": {
          "name": "docs",
          "php_version": "8.5"
        },
        "instance": {
          "name": "development",
          "app": "docs",
          "php_version": "8.3"
        },
        "workspace": null
      },
      "result": {
        "target": "instance",
        "node": "app-dev-1",
        "app": "docs",
        "instance": "development",
        "workspace": null,
        "previous": "8.4",
        "version": "8.5",
        "image": "ghcr.io/hardimpactdev/orbit-frankenphp:2-php8.5-bookworm",
        "inherits": false,
        "changed": true
      }
    },
    "meta": {
      "warnings": []
    }
  }
}
```

Instance and workspace results include `success.data.result.image` with the approved
FrankenPHP image tag for the resolved version. Workspace results report the
image for the workspace's stored version after applying the write.
Node CLI results omit `success.data.result.image`; host CLI selection is
governed by the `php-cli` toolchain, not FrankenPHP runtime images.

Workspace runtime and proxy warnings may still use the owning-family warning
contract. Every `success.meta.warnings[]` entry carries `code`, `family`,
`message`, and `next_command`. `family` is `instance` for instance
runtime drift, `process` for runtime-unit drift, `workspace` for workspace
artifact drift, and `proxy` for proxy-backend drift. There is no sibling
fan-out warning: an instance write changes that instance's version alone.

## Error Shape

The gateway emits `reason=missing_required_input` when the version is missing
after the request reaches `/api/php/use`:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "PHP version is required.",
    "meta": {
      "field": "version",
      "reason": "missing_required_input"
    }
  }
}
```

The CLI validates client-side first and emits `reason=missing` for the same
missing version:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "A PHP version is required.",
    "meta": {
      "field": "version",
      "reason": "missing"
    }
  }
}
```

When CLI PHP selection is combined with instance or workspace targets, the
failure uses plural `fields` and `reason=mutually_exclusive_input`:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "CLI PHP selection cannot be combined with instance or workspace targets.",
    "meta": {
      "fields": ["cli", "instance", "workspace"],
      "reason": "mutually_exclusive_input"
    }
  }
}
```

When `--node` names a node that does not own the resolved app, the command
fails before any gateway configuration write with this shape:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Node 'image-node' does not own app 'docs'.",
    "meta": {
      "field": "node",
      "reason": "target_mismatch",
      "node": "image-node",
      "app": "docs",
      "owning_node": "app-dev-1"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.php` | object | PHP runtime view after the gateway configuration write. |
| `success.data.result.target` | `instance`, `workspace`, `node_cli` | Scope selected by the command. |
| `success.data.result.image` | string | Approved FrankenPHP image tag for instance and workspace results. Omitted for `node_cli` targets. |
| `success.data.result.changed` | boolean | Whether gateway configuration changed. |
| `success.data.result.app` | string or null | Parent app for instance and workspace targets. |
| `success.data.result.instance` | string or null | Concrete instance selected directly or through workspace placement. |
| `success.meta.warnings[]` | array | Structured non-fatal instance, process, workspace, or proxy Doctor handoffs. |
| `success.meta.warnings[].code` | string | Stable owning-family warning code. |
| `success.meta.warnings[].family` | `instance`, `process`, `workspace`, `proxy` | Stable state family that owns repair. |
| `success.meta.warnings[].message` | string | Human-readable warning text. |
| `success.meta.warnings[].next_command` | string | Single machine-runnable owning-family Doctor command. |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `workspace.unsupported_for_production` | Stable command failure code. |
| `error.meta.field` | string | Input field the failure is attributed to (for example `version`, `node`). |
| `error.meta.fields` | array | Present on `mutually_exclusive_input`. Names the conflicting inputs. |
| `error.meta.reason` | `missing_required_input`, `missing`, `mutually_exclusive_input`, `missing_target`, `unsupported`, `unsupported_cli_version`, `not_installed`, `php_cli_missing`, `inventory_unavailable`, `serving_node_unresolved`, `target_mismatch` | Stable validation reason. Gateway missing-version uses `missing_required_input`; CLI missing-version uses `missing`. |
| `error.meta.node` | string | Selected node name. Present on `target_mismatch` and `not_installed`. |
| `error.meta.app` | string | Resolved app name. Present on `target_mismatch`. |
| `error.meta.owning_node` | string | Node that owns the resolved app. Present on `target_mismatch`. |
| `error.meta.next_command` | string | Single recovery command when one command repairs the failed result. |

Every warning object has these fields:

| Warning field | Type | Meaning |
| --- | --- | --- |
| `code` | string | Stable warning code owned by the named family. |
| `family` | `instance`, `process`, `workspace`, `proxy` | Stable state family that owns repair. |
| `message` | string | Human-readable warning text. |
| `next_command` | string | Single machine-runnable Doctor command for that family. |

## Test Mapping

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/Php/PhpUseCommandTest.php` | Instance JSON success, workspace and proxy warning payload shapes, and no-tree JSON mode. |

There is no gateway-side coverage for this renderer: JSON rendering is owned by `apps/cli`. Documented `error.code` values named for coverage tracking: `validation_failed`, `gateway_unavailable`, `authorization_failed`, `workspace.unsupported_for_production`. Linked tests cover only the mapped assertions above; remaining assertions for renderer codes stay as coverage gaps until focused tests land.
