# Port a kind to Swamp

Port one family or parent kind per change, inside a production-equivalent dev topology (F13). The Gateway admits and projects; Swamp does the work. Write only to `hardimpactdev/orbit`, never `ohdearapp/*` or another repository.

Load the official [swamp skill](../swamp/SKILL.md) for Swamp mechanics. Its routing table owns workflow scaffolding and validation, behaviors, placement, vaults, serve and troubleshooting. Load [flow-tighten](../flow-tighten/SKILL.md) for flow design. Its Swamp gotchas and flow rules own write declarations, lock waits, Node parallelism, end checks, cleanup and reruns. Rule 22 supersedes older script and end-check recipes. Use [swamp-getting-started](../swamp-getting-started/SKILL.md) only for onboarding.

This skill adds Orbit migration constraints. The [shape guide](../../../swamp/docs/swamp-shape.md) and [boundary decisions](../../../docs/swamp/porting.md#check-all-seven-boundary-decisions) apply. Use the [porting reference](../../../docs/swamp/porting.md) for Orbit integration details, subject to current decisions and the tightened chart; older recipes do not override them.

## The loop (F13)

1. Take the assigned kind and proof slot from the orchestrator. Use local sources on beast: the repo, main and relevant PR branches. Do not request machine links or reach other machines. Current decisions replace older instructions. Call Recall `resolve` for the kind and family.
2. Apply flow-tighten to the kind's [chart](../../../docs/flows/README.md) before porting. Preserve reviewed meaning unless Nick has decided otherwise. Pass `bin/check-flows`; workflow step names equal chart labels. Add the kind to `docs/flows/migrated.txt` when the workflow follows it.
3. Read the legacy Gateway action, agent actions and feature tests at `6291bb036`. Public behavior is the parity spec (F9), including edge cases and values rewritten at admission, such as setup macros (#2304). Write parity tests first; explain phase-order changes and record F9 deviations in `docs/swamp/porting-retros.md`.
4. Wave 3 owns one shared proof topology version in `swamp/proof/topologies/`; never fork per-lane `minimal@N`. Proof VMs run on shark and beast. Start with `bin/swamp-proof up --topology <name>`. The Gateway VM carries `gateway` and `swamp`; its Nodes carry the kind's roles, joined by WireGuard (F14). Wave 3 fixes topology faults and bumps the shared version (F12).
5. Port and run the whole topology path: request, admission, Swamp, Nodes and terminal projection. Read full stderr and per-step timings; fix Gateway and Swamp bugs alike. The final passing run writes `bin/swamp-proof receipt` within budget (F8). State the topology's limits: test repositories, Orbit CA, no production data or scale.
6. Reuse one topology across consecutive fixtures; mark only state-sensitive fixtures `"clean": true` so the harness restages the held VM with fresh Nodes and a fresh Gateway database. Then run `bin/swamp-proof down` and verify the proof VM is gone; the lane is not done while it is up. Do not rely on expiry: 60 minutes idle, 8 hours maximum, or 45 minutes for a one-shot run (F11).
7. Push directly to main and watch CI to green after every push. Whoever turns main red fixes it first. A superseded, cancelled Swamp job can fail Required checks; check the successor commit. Use `timeout` on every `gh` call; do not SSH to other machines. A short live check after the release load confirms uptake; it is not a second proof.

Never port against production serve or log in to 209 for a port. Never restart or reload serve; config changes go through the swamp role and a release. New manifest `additionalFiles` reach workers only after a serve restart (Lab #4282); the release handles it. Send real Swamp gaps to the orchestrator with evidence; do not build around them.

## Build it

Use the official swamp skill to create or edit the workflow. Apply the Orbit [workflow and Gateway templates](../../../docs/swamp/porting.md#fill-the-workflow) only where they match the tightened chart.

- **Admission:** freeze the full non-secret intent under `intent`, with names-only `{vault, key}` descriptors under `execution_secrets`. Encode empty maps as objects (#2273). Expand Gateway macros before execution (#2304).
- **Placement:** all steps use only `labels: {role: swamp}`, with no inherited `target`; topology workers carry the same label. Run official Node behaviors from 209 with the admitted identity, host-key pins and account. Copy Orbit placement from `route-upstream-firewall`, not `node.bootstrap_probe`.
- **Node work (rule 22):** use official `@swamp/cfgmgmt` behaviors; the behavior's `check` is the end check. A single command uses `@swamp/ssh exec` argv. Add no shipped script: replace one added by the current port with cfgmgmt or exec argv, or name the uncovered gap in the report and extension README. No step copies scripts to a Node. Drop rollback chains and runtime ownership checks. TypeScript only shapes typed inputs and outputs; explain custom growth (F15).
- **Secrets:** no secret bytes in inputs, outputs or argv. Declare every vault read by parent and child workflows. Use official behavior inputs and vault resolution for transport; SSH `env` relies on `SendEnv`, so do not assume it reaches the target. Generate Gateway-owned secrets at admission; Node-held keys stay on the Node. Secret imports use a one-shot vault key, read once by the Gateway with `vault.read-secret`, then deleted with `vault.delete`; both exist in pinned Swamp. Token authority only shrinks: revoke only the removed Node's exact worker principal, failing closed; never mint or widen it.
- **Names:** follow [behavior naming](../../../docs/flows/README.md#behavior-names). Never share one per-Node SSH name across step families: differing global arguments rewrite its definition. Per-run names require an always-run delete; leaked auto-definitions caused serve's lookup CPU incident (Lab #4280). Sanitize dots with `split(".").join("-")`; the shape gate enforces names.
- **Fan-out compatibility:** pinned e459 expands `forEach.in` before same-job outputs exist; use inputs or an earlier job's outputs. Preserve the legacy host failure scope at `6291bb036`. Keep inputs bounded: no history-growing query or whole fleet `steps` map; pass only required statuses (#2310, #2334).
- **Errors:** preserve legacy refusal codes and setup exit cases, or explain changes. Map native failure exit codes in the Gateway; failed command steps keep no outputs on e459. Private stdout never enters history. Use shared failure diagnostics and redacted stderr, never a family wrapper or result-reporting step. Fresh credential checks cannot reuse an earlier request's success; completed verification may survive native resume (vault.setup retro).
- **Budgets (F8):** use the [budget table](../../../docs/swamp/porting.md#set-the-time-budget). A measured explicit budget wins; otherwise start at 30 minutes, then use 1.5× the longest success. Never borrow a flat budget. Every workflow, children included, sets `queueTimeout`, equal to the proof's `queue_timeout_seconds`. Bound phase commands with literal `timeout <seconds>`; a remote read may instead set SSH `timeoutSec`, while writes keep a remote-side bound (#2334). No family timer or timeout epilogue.
- **Polling exception:** only an existing script for a named gap may poll external HTTPS state, under a literal phase timeout, at a fixed shorter interval, with failing GETs and no retried requests. State interval and budget in the change report. Never poll Gateway or Orbit state or retry failed actions. Use the reference's [gate requirements](../../../docs/swamp/porting.md#set-the-time-budget); add no baseline row (#2325, #2366).
- **Gateway:** use shared `StartSwampRun`, `SwampCommandStep::executionCopy` and the family projector. New ports declare [native terminal results](../../../docs/reference/swamp-command-steps.md#read-swamps-run-data-instead-of-a-result-step): `terminal_result` names the end check with `native => true`; read status through `NativeRunResult::stepStatus`. No `outputs: false` or result step. One terminal history read; no callbacks, holds, pollers, timers, retries or second readers. Preserve an exact native terminal that met its budget even after Gateway expiry. A failed projection must leave expiry armed; no queued marker may suppress it (L17-PR-2348-01).
- **Delete:** remove the old executor, tests, embedded scripts, callbacks and paths used only by it in the same change. An F9 rebuild also removes replaced behaviors and tests (F15). Do not touch `apps/agent`. Remove the kind's shape-baseline rows.

## Check and review

- Follow the official workflow validation guide on the pinned runtime. Run native and parity tests, changed behavior tests, script lint and Gateway Pest admission/projection tests. Use the [test layout](../../../docs/swamp/porting.md#test-layout). Native test roots pull official extensions at the inventory-pinned version; never assume a local pulled cache exists. Fixture package installs refresh APT indexes first (vault.setup proof). Real-Docker tests clean up with `docker rm --force --volumes` (#2358).
- Run the shape gate, `bin/lint-behavior-names.ts` and placement lint. Their CI lives at root `.github/workflows/swamp-shape.yml`, never under `swamp/.github` (#2372).
- Report measured p95, sample, run budget and `queueTimeout`. Report Orbit net lines, then `swamp/` growth split into behaviors, workflows, scripts, tests and fixtures, with a reason for each (F15). Prefer receipts and parity tests over duplicate mocked fixtures.
- Attach a receipt and [proof file](../../../swamp/proof/README.md) for workflow, behavior, script or Gateway execution-contract changes (#2266, #2273, #2304). Deletion-only, docs and test changes need no receipt. An outage exception names the omitted receipt and the live check after load (#2332).

Review against the [checklist](../../../docs/swamp/porting.md#pr-and-review-checklist), current chart and flow-tighten. Missing budgets, required receipts, explained growth or reasons for legacy phase changes fail review. Read the change report before calling a reason missing. Keep source conformance, CI, served-source uptake and live evidence separate. Report PASS or deviations as `file:line`, broken rule and native replacement, with reviewed SHA and skill version.

Use the official workflow references to check guard, dependency and output semantics before alleging a silent skip. On pinned e459, missing intent fields fail CEL evaluation (#2369). An added intent field needs its Gateway release live before the Swamp load; pre-release runs are re-admitted, not resumed. Check the whole workflow's `queueTimeout` (L17-PR-2363-02). When captures become sparse, inspect every guard that used the full form (#2383). Main is not `deno fmt` clean; do not block on unrelated formatting (#2332).

Replace the affected rule the same hour; use canonical finding IDs instead of duplicate rows. Keep Swamp mechanics in the official swamp skill and shared flow rules in flow-tighten.

Every two hours, read local lane reports and main commits since the last update. Fold in only new Orbit migration lessons; replace superseded text and add lines only for new rules. Follow the checks and main discipline above. Put questions and reports in the final message, at most five lines; the orchestrator reads it every 15 minutes.
