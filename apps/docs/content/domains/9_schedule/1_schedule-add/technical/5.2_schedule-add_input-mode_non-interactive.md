# Non-Interactive Input Mode: `orbit schedule:add`

[Back to `schedule:add` technical contract.](1_schedule-add.md)

**Input mode:** Non-interactive.

Applies when the command is running without a TTY or when `--json` is present. `--json` forces non-interactive input mode.

## Behavior

No prompts are rendered.

## Resolution Rules

Non-interactive input mode never renders prompts and never waits for user input. All required fields must be supplied by arguments, options, or documented local defaults before side effects begin.

Missing `name`, unresolved target, missing `interval`, and missing execution source fail with `validation_failed`. Supplying both `--app` and `--node`, or both `--command` and `--script`, also fails with `validation_failed`.

An app target should be supplied as `app.instance`. A bare logical app is
accepted only when exactly one eligible instance is visible. No eligible
instance or multiple visible eligible instances fail with `validation_failed`
and `error.meta.reason=app_instance_required` before schedule intent is written.
When eligible instances exist but none is visible to the caller, the shared
authorization failure applies.

## JSON Interaction

When `--json` is present, validation failures use the JSON renderer and return the same stable error codes as gateway-side validation. No ANSI progress output is emitted.
