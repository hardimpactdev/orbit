# Technical Contract: `orbit workspace-teardown-step:add` (Human Renderer)

**Renderer:** Human.

## Primitive

None. The human renderer prints short prose/status lines only and does not render a table, spinner, or progress tree.

[Back to the canonical contract.](1_workspace-teardown-step-add.md)

## Progress Tree

No progress tree is rendered. The command performs a single gateway database
write and is expected to complete below one second.

## Output Strings

### Success

```text
Teardown step added for app instance [app].[app_instance].
ID: [id]
Command: [command]
Order: [order]
Timeout: [timeout] seconds
```

`Order` shows the absolute position of the new step within
`(app_instance, phase=teardown)`. The renderer does not show "step #N of M"; the
full ordered list is the responsibility of
[`workspace-teardown-step:list`](../../12_workspace-teardown-step-list/workspace-teardown-step-list.md).

### Errors

Standard error strings as defined in
[Failure Semantics](./1_workspace-teardown-step-add.md#failure-semantics).
Notable cases include:

- **Validation (timeout)**: "Timeout must be a positive integer."
- **Validation (app)**: "Could not resolve parent app. Pass `--app=<app>`
  or run from inside a registered app or workspace path."
- **Invalid position**: "Both `--before` and `--after` cannot be supplied."
- **Step not found**: "Referenced insertion step [id] not found for app
  '[app]' in phase 'teardown'."

## Next Steps

  `orbit workspace-teardown-step:list --app=[app]`
- Test the teardown:
  `orbit workspace:remove` (on a workspace belonging to `[app]`)
