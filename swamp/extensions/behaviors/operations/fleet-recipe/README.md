# Native Fleet recipe

`operation-fleet-recipe-direct` owns one Node visit. All steps run on 209. Official SSH uses the admitted address, account and stored host keys. The Gateway keeps desired-only plan/state, maintenance order, admission, a generic Node target hold and terminal projection.

The DAG separates inspection, the signed package transaction, browser, JavaScript, PHP, service restart planning, restarts, dependency settling, health, observer files, Caddy, peer/private DNS, residue, PHP runtime, tmpfiles, CLI and delivery verification. Native dependencies stop later required effects. Native resume retains completed actions. Tolerated residue failures retain their skipped artifact receipt.

The package transaction keeps sources, indexes, exact installation, provider retirement, preferences and receipts together. The shipped recipe policy is also the existing Nodes JavaScript policy; its parent supplies the script through the manifest context. Node footprint callers use the same shipped PHP and listener policies. There is no second recipe policy or per-Node Fleet executor.

Official cfgmgmt package actions were checked. They do not express the signed Ubuntu origin floor, exact artifact digest and metadata checks, Incus drain policy, PHP ownership and previous-build restoration. These remain single-purpose package transactions. Native SSH exposes service actions separately. The existing PHP and updater tool locks are explicit `flock` commands, not new workflow or admission locks.

Only the observer identity hash has an execution copy. Its exact positive-ID key is `recipe-operation-<id>-observer` in `orbit-control-inputs`. Native `vault.get` passes it to the observer identity check on stdin. No worker enrollment, credential rotation or worker retirement is part of a recipe visit.

Source checks use the frozen official runtime in an isolated local repository. SSH fixtures never contact Nodes. Live publication, grants and any 12-Node rollout remain separate owner actions.

Private DNS validates a staged snapshot before file publication. Native steps activate the listener and check one DNS answer plus its loaded catalog digest. Known activation failures restore the captured prior data and service state; compensation may finish after the maintenance window closes.

`role_prerequisites.py` is the single Caddy-package and role-prerequisite policy.
Both retained Node provisioning and native role contributions receive these
bytes through the Fleet manifest context. The optional `install_packages=false`
mode requires parent-verified package coverage and still checks the managed
account and Composer scope before creating directories. It does not run APT.

The shared Caddy VPN ordering action is shipped as `caddy_ordering.py`.
Retained Gateway roles and native application roles consume the same filesystem
checks, systemd drop-in and recovery policy.

The ordering action performs one ownership check, publication and service
transaction. Its old host lock and timed wait loop are removed; Swamp owns
execution ordering. The existing drop-in, directory and service recovery checks
still apply.
