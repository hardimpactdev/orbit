# JSON Renderer: `orbit app:list`

[Back to `app:list` technical contract.](1_app-list.md)

This page describes the JSON-rendered output for `app:list`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

The app array is rendered as a flat array under `success.data.apps`. Apps are
sorted by owning node name (ascending, case-insensitive) and then by app name
(ascending, case-insensitive). Each app includes its registered workspaces under
`workspaces`, sorted by workspace name (ascending, case-insensitive). This
matches the order shown in human output, so both renderers represent the same
result.

`app:list` does not include `success.data.context`. Its `--node` and
`--environment` inputs are registry filters, not a resolved execution context.
Use `success.meta` for stable filter echoes if a future renderer contract needs
to expose them.

## Success Shape

```json
{
  "success": {
    "data": {
      "apps": [
        {
          "name": "docs",
          "node": "app-1",
          "url": "https://docs.test",
          "path": "/home/docs/app",
          "root": "public",
          "repository": null,
          "runtime_kind": "php",
          "php_version": "8.5",
          "worker_enabled": false,
          "worker_config": null,
          "adopted": false,
          "workspaces": [
            {
              "name": "feature-a",
              "url": "https://feature-a.docs.test",
              "lifecycle_status": "active"
            }
          ]
        }
      ]
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `apps` | array | Ordered list of visible apps matching the applied filters. |
| `apps[]` | object | App list item. Includes the canonical app JSON entity fields from [`5_app/README.md`](../../README.md#app-json-entity) plus the `workspaces` inventory described below. App registry rows are desired-state rows; `app:list` emits no separate app `status` field. |
| `apps[].workspaces` | array | Workspaces registered to the app, ordered by workspace name. Empty when no workspaces are registered. |
| `apps[].workspaces[].name` | string | Workspace identity slug. |
| `apps[].workspaces[].url` | string | Primary intended workspace URL. |
| `apps[].workspaces[].lifecycle_status` | string | Registry configuration lifecycle from the workspace row. This is not setup-run status and not a live readiness result. |

## Error Shapes

### Invalid filter value

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Invalid value for --environment: 'staging'. Allowed values: development, production.",
    "meta": {
      "field": "environment",
      "value": "staging",
      "allowed": ["development", "production"]
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to list apps.",
    "meta": {}
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to read the app registry.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "app:read"
    }
  }
}
```
