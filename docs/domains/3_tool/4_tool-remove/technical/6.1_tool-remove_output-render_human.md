# Human Renderer: `orbit tool-remove`

[Back to `tool-remove` technical contract.](1_tool-remove.md)

**Renderer:** Human renderer.

## Primitive

- Confirm: [Confirm prompt](../../../../ux/commands/inputs/confirm-prompt.md)
- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render an in-progress tree after input resolution and destructive consent, and
before cleanup side effects. Pre-confirmation gateway reads needed to resolve
the target and tool row are allowed and do not start the progress tree.

```text
┌ Removing Tool
○ Resolve target
○ Read gateway tool configuration
○ Run command action
└ Working...
```

## Success Output

Human output presents the selected tool state using Orbit product vocabulary: tool, node, expected lifecycle state, observed state when available, managed flag, and version/config metadata when tracked by the tool definition.

Interactive destructive consent uses this prompt after target and tool
resolution:

```text
Remove tool 'redis' from 'app-1'?
```

## Failure Output

Human-rendered failures show the failing field or condition, a concise prose error, and actionable recovery guidance when the operator can resolve the issue.

- Confirmation decline: `Operation cancelled.`
- Missing consent in non-JSON non-interactive mode:
  `Use --force or --json to remove this tool.`
- Missing target source:
  `A node or app target is required. Provide --node, --app, configure
  node:default, or select a target interactively.`
