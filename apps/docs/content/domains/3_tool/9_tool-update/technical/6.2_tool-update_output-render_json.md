# JSON Renderer: `orbit tool:update`

[Back to `tool-update` technical contract.](1_tool-update.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

Use `--stream-json` instead of `--json` only when callers need
newline-delimited progress frames. That renderer follows the shared
[Stream JSON Frames](../../../README.md#stream-json-frames) contract.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "updated": []
    },
    "meta": []
  }
}
```

Command-specific result data uses the canonical tool entity from [`README.md`](../../README.md#tool-json-entity) unless the command returns credentials.

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Required input is missing or invalid.",
    "meta": {
      "field": "tool"
    }
  }
}
```

When the tool argument is omitted, an update can finish after one or more target
failures. The gateway then emits a `complete` progress event with a nonzero
`exit_code`. Both machine renderers return failure, keep `event=complete`, and
preserve every target result:

```json
{
  "event": "complete",
  "error": {
    "code": "operation_failed",
    "message": "Tool update failed",
    "meta": {
      "exit_code": 1
    },
    "data": {
      "updated": [],
      "failed": ["node"],
      "footer": "Tool update failed"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `operation_failed`, `tool.not_found`, `tool.unsupported_action`, `tool.remote_action_failed` | Stable command failure code. |
| `error.message` | string | Human-readable failure summary. |
| `error.meta` | object | Field, target, caller, or remote-action context for automation. |
