# `app:new` Non-Interactive Input Mode

[Back to technical contract](1_app-new.md)

**Input mode:** Non-interactive.

Non-interactive mode is used when the CLI is not attached to a TTY or when
`--json` or `--stream-json` is supplied. It fails fast if required input is
missing.

## Constraints

- **Missing Name:** Fails if `name` is not supplied as a positional argument.
- **Node Resolution:** Fails if `--node` is missing and no local `node:default`
  node is configured. There are no fallback prompts.
- **Source Resolution:** Requires exactly one complete source branch:
  `--repo`, or `--template-repo` together with `--new-repo`. Missing source,
  incomplete template input, and mixed clone/template input fail before
  gateway I/O. Credential-bearing or structurally invalid repository URLs also
  fail before gateway I/O.
- **Validation Errors:** Any validation failure (invalid slug, unsupported PHP
  version) results in an immediate exit with a non-zero exit code.
- **Instance name:** No instance-name input is accepted. Orbit deterministically
  creates `development` without `--domain` or `production` with `--domain`.

## Behavior

- **Machine-output forcing:** Providing `--json` or `--stream-json`
  automatically forces non-interactive mode even if a TTY is present.
- **No Prompts:** The command will never block on user input.

## Failure Metadata

Before a progress stream starts, machine-mode validation and resolution
failures use the `error` envelope with the failing field and reason in
`error.meta`. Source shape errors list the exact CLI option names in
`error.meta.fields`:
`repo`, `template-repo`, and `new-repo`.

## Test Mapping

Primary test owners:

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/App/AppWriteCommandTest.php` | Missing `--node` and invalid source combinations fail before HTTP; valid clone and template payloads are forwarded. |
| `apps/cli/tests/Feature/Commands/App/AppNewInteractiveInputModeTest.php` | JSON-mode app name slug validation before contacting the gateway stream endpoint. |

There is no gateway-side coverage for this command-local mapping: input handling and renderer behavior live in `apps/cli`. Gateway API behavior is mapped in the command contract file when a gateway-side surface exists.
