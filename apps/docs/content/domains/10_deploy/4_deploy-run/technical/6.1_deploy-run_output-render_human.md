# Human Renderer: `orbit deploy:run`

[Back to `deploy:run` technical contract.](1_deploy-run.md)

**Renderer:** Human terminal renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when neither `--json` nor `--stream-json` is present.

## Progress Tree

After `POST /api/deploy/run` returns a durable operation identity, subscribe to
its private operations WebSocket channel. Render replayed and live `tree` and
`step` frames through one progress tree. Journal replay must be visually
indistinguishable from live delivery and duplicate frame sequences must not be
rendered twice.

```text
┌  Running Deployment
│
●  Resolve production instance — docs.production
│
●  Create deployment run — #123
│
◉  Run migrations
│
○  Record deployment result
│
└  Working...
```

A terminal `complete` frame settles the tree with `Deployment completed`. A
terminal `error` frame settles it as failed and returns exit status `1`.

## Detached Output

`--detach` does not open the operations WebSocket. It prints the durable
operation identity and exits successfully:

```text
Deployment operation queued: 3fa85f64-5717-4562-b3fc-2c963f66afa6
```

## Failure Output

Input, gateway, authorization, and malformed operation-descriptor failures use
the shared human failure renderer. Execution failures arrive as terminal
operation error frames. If live WebSocket delivery fails, the subscriber first
replays the durable journal; it reports `gateway_unavailable` only when neither
live delivery nor replay yields a terminal frame.
