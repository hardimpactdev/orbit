# cluster:node:remove verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN Node, an inactive and an active Cluster with a Router, and member Nodes that have their own TLDs and serve generated, explicit, custom proxy and public Routes, and checks the Gateway record, Caddy, certificates, firewalls, DNS and real HTTPS requests. The steps of the shared Route child have their own cases in `swamp/proof/route/reconcile.cases.md`. Today the command runs synchronously, changes the records and returns the Cluster at once, with no task, and takes no Cluster lock: every case about the task, its steps, a failure, an interrupt, a lock or a lost response fails today for that reason, and a failure past the cutover leaves the Node a member with its Routes already moved. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Inactive Cluster | Detach a member of an inactive Cluster. | The result is at once, with no task. The Node is no longer a member. No Node is contacted and no traffic changes. Fails today: the DNS selection is published to the VPN Node even for an inactive Cluster. |
| Active Cluster with a TLD | Detach a member with Cluster-scoped generated Routes from an active Cluster with a TLD. | The task succeeds and the Node has left. Its Routes have Node scope and generated domains on its Node TLD, with new sites, certificates and private DNS answers. The Node's LAN ingress rules are gone and requests reach the Node directly. The other members are unchanged. |
| Active Cluster without a TLD | Detach a member of an active Cluster without a TLD. | The Node's Routes return to Node scope and its generated domains stay on the Node TLD. |
| Route kinds | The Node has generated, explicit, custom proxy and tracking-host Routes. | Generated Routes fall back to the Node TLD. An explicit Route keeps its domain. A custom proxy Route keeps its Node scope and keeps serving. A tracking host moves with its Instance's Route. Fails today: the legacy path refuses a tracking host with `route.analytics_native_required`. |
| Public Route | An active public Route that the change would move. | `route.reconciliation_required`. No task, no change. Fails today: the refusal comes after the LAN rules and DNS selection were expanded, and the prune undoes them. |
| Instances | A member that hosts Instances, with a Route that targets only this Node and one whose targets span this Node and another member. | The Instances stay and keep running. The first Route returns to Node scope. The second gives `route.target_scope_conflict` with no task and no change. |
| No Routes | A member that serves no Route. | The task succeeds, the Node has left and the child does not run. |
| Never-active Router | A member with a `router` assignment that never became active. | The assignment is deleted and the Node leaves. |
| Rules last | Probe the Node's LAN path to the Router (HTTPS and DNS) during the run. | The path works until the Routes and DNS have moved, and closes in the last step. |
| Guards | On an active and on an inactive Cluster: a Node that is not a member, a Node with an active, removing or failed `router` assignment, and a Node with the `ingress` role. On an active Cluster: a Node that shares the Cluster TLD. | `cluster.membership_missing`, `cluster.router_detach_forbidden`, `cluster.ingress_detach_forbidden` and, on the active Cluster only, `cluster.tld_conflict`. No task, no change. Fails today: the refusal comes after the LAN rules and DNS selection were expanded, and the prune undoes them. |
| Wrong Cluster | Rerun after a failure past the cutover, naming another Cluster. | `cluster.membership_missing`. Nothing changes. |
| Route refusals | A proposed domain that collides with another Route, a generated Route whose Node has no TLD, targets that would span scopes, a tracking host without an active Instance, a Route with no generation basis or one that cannot be reconciled, a targetless Route that would leave its scope, and a Route with another domain change in progress. | `route.domain_conflict`, `route.tld_required`, `route.target_scope_conflict`, `route.target_invalid`, `route.generation_basis_missing`, `route.generation_basis_invalid`, `route.scope_invalid` and `route.domain_change_conflict`. No task and no Route changes, even for the Routes that were valid. Fails today: the refusal comes after the LAN rules and DNS selection were expanded, and the prune undoes them. |
| Busy | Start the command while a Router change holds the Cluster for more than 30 seconds, and while another Cluster change runs. | `cluster.router_busy`. The running change is unaffected. Fails today: no Cluster lock is taken. |
| Failure before the cutover | Make a CSR, signing, publish, probe, `APP_URL` or DNS move of the child fail. | The task fails with the failed step and its code (`app-dev.certificate_request_failed`, `app-dev.certificate_sign_failed`, `route.publish_failed`, `route.probe_failed`, `route.app_url_failed` or `private_dns.publication_failed`). The Node stays a member and every Route keeps its domain and scope. A rerun after the fix succeeds without duplicates. |
| Failure after the cutover | Make the DNS grace, the withdrawal, the DNS selection or the prune (`route.lan_firewall_failed`) fail. | The task fails with the failed step and its code (`route.dns_grace_failed`, `route.withdraw_failed`, `private_dns.publication_failed` or `route.lan_firewall_failed`). The Node has left and the Node scope serves. |
| No Routes, step fails | A member with no Route, and the DNS selection or the prune fails. | The task fails. The Node is still a member, the prune removed what the stored state does not need, and a rerun succeeds. |
| Rerun after the cutover | Rerun the command for the same Cluster after that failure. | It is not refused with `cluster.membership_missing`. It finishes the withdrawal, the DNS update and the prune, the old Routes are deleted and the pending detach ends. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step and the rerun finishes. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one task exists for the change. |
| Confirmation | In a terminal answer the prompt with No, Enter, Ctrl-C, and end of input. Then run it noninteractively and with `--json` without `--force`. | The prompt names the Cluster, the Node and the effect, and No is selected. Each decline ends with `input.cancelled` and starts no change. The noninteractive and `--json` calls are refused with `cluster.confirmation_required`. With `--force` there is no prompt, also with `--json`. Fails today: the prompt names the Cluster and the Node by ID and does not state the effect. |
| Missing input | In a terminal, run the command with no arguments, cancel the Cluster list, and cancel the member list. Then run it noninteractively and with `--json` without the Cluster and without the Node. | The terminal lists Clusters by name, then the Cluster's members that the caller has a grant to, by name. A Cluster with none prints `No members.` and sends no request. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `cluster.id_invalid` or `node.id_invalid`, with no request. Fails today: both are required arguments, so every call without them is refused by the parser. |
| IDs only | A Cluster or Node by name, the ID `0`, the ID `-1`, and `abc`. | `cluster.id_invalid` or `node.id_invalid`, with no request. |
| Unknown and access | A Cluster or Node ID that does not exist, and a caller without a grant to the Node being detached. | `http.404` and `node_access.required`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator for a task, then the final result naming the Cluster and the Node, with the task and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Cluster or task. |
