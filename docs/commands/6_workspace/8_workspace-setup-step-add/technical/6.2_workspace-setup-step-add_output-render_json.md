# Technical Contract: `orbit workspace-setup-step:add` (JSON Renderer)

**Renderer:** JSON.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

[Back to the canonical contract.](1_workspace-setup-step-add.md)

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "added"
      },
      "step": {
        "id": 12,
        "app": "docs",
        "phase": "setup",
        "order": 2,
        "command": "composer install",
        "timeout_seconds": 600
      }
    },
    "meta": {}
  }
}
```

### Fields

- `result.action`: Literal `"added"`. The only outcome verb for this
  command. `workspace-setup-step:add` is additive and never converges by
  command text; running the same `add` twice produces two separate
  records.
- `step.id`: Newly assigned numeric registry identifier. Stable across
  re-runs for the same record.
- `step.app`: The resolved parent app slug.
- `step.phase`: Literal `"setup"`. The discriminator that separates this
  policy list from teardown steps.
- `step.order`: The absolute position of this step in
  `(app, phase=setup)`.
- `step.command`: The shell command string as supplied. Not parsed or
  expanded by the gateway; the runner executes it as-is in the workspace
  path on the owning app node.
- `step.timeout_seconds`: Strict positive integer. Default `600`.

`workspace-setup-step:add` does not emit non-fatal warnings. Drift between
gateway configuration and node reality is reported by
[`doctor --family=workspace`](../../workspace-doctor.md), not by this
write command.

The step record exposes only the fields above. There is no `name`,
no `working_directory`, no `env_overrides`, and no per-step `on_failure`
field. Working directory is pinned to `ORBIT_WORKSPACE_PATH` by the
[Workspaces README](../../README.md#lifecycle-step-environment) and
failure policy is the family-wide fail-fast contract resolved by
`workspace:setup`.

## Error Envelope

### Validation failure (timeout)

Returned when `--timeout` is non-positive (including `0`). Fails before
any side effects.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Timeout must be a positive integer.",
    "meta": {
      "field": "timeout",
      "reason": "must_be_positive_integer"
    }
  }
}
```

### Validation failure (app)

Returned when the parent app cannot be resolved from `--app`,
`.orbit/config`, or gateway path-ownership lookup, and prompting is
disabled (non-interactive mode).

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Could not resolve parent app.",
    "meta": {
      "field": "app",
      "reason": "missing_required_input"
    }
  }
}
```

### Invalid position

Returned when both insertion flags are supplied.

```json
{
  "error": {
    "code": "workspace.invalid_position",
    "message": "Both insertion flags cannot be supplied.",
    "meta": {
      "before": 12,
      "after": 13
    }
  }
}
```

### Step not found

Returned when the referenced insertion step does not exist for the
resolved `(app, phase=setup)`.

```json
{
  "error": {
    "code": "workspace.step_not_found",
    "message": "Referenced insertion step '13' not found for app 'docs' in phase 'setup'.",
    "meta": {
      "id": 13,
      "app": "docs",
      "phase": "setup"
    }
  }
}
```

### App not found

```json
{
  "error": {
    "code": "workspace.app_not_found",
    "message": "App 'docs' not found.",
    "meta": {
      "app": "docs"
    }
  }
}
```

## Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (empty `--command`, non-positive `--timeout`, unresolved parent app). `error.meta.field` names the offending input. |
| `workspace.app_not_found` | Resolved app slug does not exist in gateway configuration. `error.meta.app`. |
| `workspace.invalid_position` | Both insertion flags were supplied. `error.meta.{before, after}`. |
| `workspace.step_not_found` | Referenced insertion step does not exist for the resolved app and `phase=setup`. `error.meta.{id, app, phase}`. |
| `authorization_failed` | The caller is not authorized to manage workspace policy for the target app. |
| `caller_role_not_allowed` | The gateway denied the caller's WireGuard peer identity for this command. App-node peers are not authorized for workspace policy edits. |

## Enum And Identifier Values

| Field | Values |
| --- | --- |
| `result.action` | `added` |
| `step.phase` | `setup` |
| `error.code` | `validation_failed`, `workspace.app_not_found`, `workspace.invalid_position`, `workspace.step_not_found`, `authorization_failed`, `caller_role_not_allowed` |

The `error.code` values listed here are exhaustive for
`workspace-setup-step:add`. Add a new value to this renderer contract
before implementing another JSON failure code.
