# cluster:update verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN Node, a Cluster with a Router and member Nodes that serve generated, explicit, custom proxy and public Routes, and checks the Gateway record, Caddy, certificates, DNS and real HTTPS requests. The steps of the shared Route child have their own cases in `swamp/proof/route/reconcile.cases.md`. Today the command runs synchronously, changes the records and returns the Cluster at once, with no task: every case about the task, its steps, a failure, an interrupt or a lost response fails today for that reason, and a failure past the cutover leaves the old TLD recorded with its Routes already moved. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Name only | Rename an active Cluster. | The result is at once, with no task. The name changes in `cluster:show` and in `--json`. No Node is contacted and no Route, certificate or DNS record changes. |
| Inactive Cluster | Set, change and unset the TLD of an inactive Cluster. | Each is recorded at once with no task. No Node is contacted and no traffic changes. Fails today: a TLD change republishes the DNS selection on the VPN Node even for an inactive Cluster. |
| Change the TLD | Change the TLD of an active Cluster with generated Routes. | The task succeeds. Each generated Route has a domain in the new TLD, and its new site, certificate and private DNS answer are in place. The old domains stop answering. Explicit Routes keep their domains and custom proxy Routes keep their Node scope. A requester resolves each new name before its old site is withdrawn, at every moment of the run. |
| In-TLD names only | A change whose Routes all stay inside the TLD, so the child changes no DNS record. | The new TLD answers from the first DNS step, and the old answers go at the end. |
| No Routes | An active Cluster with no Route. | Only the DNS steps run and the child does not run. A failure of the first DNS step leaves the old TLD recorded. |
| Managed peers | After the task, wait for the peer DNS policy to reach a managed peer. | The peer resolves the new name through the Cluster's resolver and no longer resolves the old one. Until then it resolves the new name through its public resolver. |
| Set a TLD | Give an active Cluster without a TLD a TLD. | The task succeeds and generated domains move from the Node TLDs into the Cluster TLD. |
| Unset the TLD | Unset the TLD of an active Cluster whose Nodes have their own TLDs, with and without an active Router. | The task succeeds in both. Generated domains fall back to the Node TLDs. The Cluster keeps its Cluster scope. |
| Name and TLD together | Change both on an active Cluster. | One task. The name and the TLD are recorded together at the cutover. |
| Skip | Run with the current name alone, with the current TLD alone, and with both. Then repeat after a failure past the cutover. | The first three succeed with `Skipped — nothing to change (cluster.update_unchanged)`, start no task and change nothing. The repeat is not skipped. Fails today: the result carries no reason code. |
| Public Route | An active public Route that the change would move. | `route.reconciliation_required`. No task, no change. Fails today: the refusal comes only after the private Routes have moved. |
| Router required | Set a TLD on an active Cluster with no active Router. | `cluster.router_required`. No task, no change. |
| Policy limit | A TLD that pushes the private names over the DNS policy limit. | `vpn.peer_dns_policy_invalid`. No task, no change. Fails today: the failure comes at the save, after the Routes moved. |
| TLD owned elsewhere | A Node outside the Cluster owns the proposed TLD. | `cluster.tld_conflict`. No task, no change. |
| Route refusals | A proposed domain that collides with another Route, a generated Route that would have no effective TLD, targets that would span scopes, a tracking host without an active Instance, a Route with no generation basis or one that cannot be reconciled, a targetless Route that would leave its scope, and a Route with another domain change in progress. | `route.domain_conflict`, `route.tld_required`, `route.target_scope_conflict`, `route.target_invalid`, `route.generation_basis_missing`, `route.generation_basis_invalid`, `route.scope_invalid` and `route.domain_change_conflict`. No task and no Route changes, even for the Routes that were valid. |
| Input rules | No option, in a terminal and noninteractively, an empty name, a TLD that is not one DNS label, a name or TLD another Cluster uses, a TLD equal to `orbit`, the VPN domain or its last label, and for an API caller an empty name, an invalid TLD and a name over 255 characters. | `cluster.update_required` in both modes, `cluster.name_invalid` and `cluster.tld_invalid` before any request, then `validation.failed` for the rest. Nothing changes. |
| Busy | Start the command while a Router change holds the Cluster for more than 30 seconds, and while another Cluster change runs. | `cluster.router_busy`. The running change is unaffected. |
| Failure before the cutover | Make a CSR, signing, publish, probe, `APP_URL` or DNS step of the child fail. | The task fails with the failed step and its code (`app-dev.certificate_request_failed`, `app-dev.certificate_sign_failed`, `route.publish_failed`, `route.probe_failed`, `route.app_url_failed` or `private_dns.publication_failed`). The Cluster keeps its name and TLD and every Route keeps its domain and scope. A rerun after the fix succeeds without duplicates. Make the LAN rule step fail as well: `route.lan_firewall_failed`. |
| Failure after the cutover | Make the DNS grace, the withdrawal or the prune fail. | The task fails with the failed step and its code (`route.dns_grace_failed`, `route.withdraw_failed` or `private_dns.publication_failed`, at the prune). The new name and TLD are recorded and the new domains serve. |
| Rerun after the cutover | Rerun the command after that failure. | It is not skipped. It finishes the withdrawal and the prune, and the old Routes are deleted. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step and the rerun finishes. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one task exists for the change. |
| Missing input | In a terminal, run the command with no arguments and cancel the list. Then run it noninteractively and with `--json` without the Cluster. | The terminal lists Clusters by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `cluster.id_invalid`, with no request. Fails today: the Cluster is a required argument, so every call without it is refused by the parser. |
| IDs only | A Cluster by name, the ID `0`, the ID `-1`, and `abc`. | `cluster.id_invalid`, with no request. |
| Unknown and access | An ID that does not exist, a caller without a grant to a member Node, and for a Cluster with no members a caller without a grant to the Gateway Node. | `http.404` and `node_access.required`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator for a task, then the final result naming the Cluster, with the task and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Cluster or task. |
