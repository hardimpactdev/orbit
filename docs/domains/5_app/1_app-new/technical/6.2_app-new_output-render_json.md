# `app:new` JSON Renderer

[Back to technical contract](1_app-new.md)

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

The JSON renderer returns structured output for automation.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "created"
      },
      "app": {
        "name": "docs",
        "node": "app-1",
        "url": "https://docs.example.com",
        "path": "/home/docs/app",
        "root": "public",
        "repository": "git@github.com:my/repo.git",
        "php_version": "8.5",
        "adopted": false
      }
    },
    "meta": {
      "warnings": [
        {
          "code": "proxy.domain_inactive",
          "family": "proxy",
          "message": "Production domain 'docs.example.com' is not yet active. Retry with 'orbit app:register docs --domain=docs.example.com' once DNS has propagated.",
          "next_command": "app:register docs --domain=docs.example.com"
        }
      ]
    }
  }
}
```

### Fields

- `result.action`: Always `created` for `app:new`.
- `app`: The canonical app JSON entity defined in
  [`5_app/README.md`](../../README.md#app-json-entity). `app.repository` is
  the canonicalized `--repo` value or `null` when no repository was supplied.
  No `auth_method` or credential metadata is included; credentials are owned by
  the target node, not by `app:new`.
- `meta.warnings`: Structured non-fatal drift and retry handoffs. Each entry
  carries `code`, `family`, `message`, and `next_command`.

## Error Envelope

```json
{
  "error": {
    "code": "app.collision",
    "message": "App name 'docs' is already registered in the gateway app registry on node 'app-2'.",
    "meta": {
      "name": "docs",
      "node": "app-2"
    }
  }
}
```

### Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (e.g. unsupported `--php-version`). `error.meta.field` names the offending input. |
| `app.ineligible_node` | The caller may run `app:new`, but the resolved target node is not a node with an app role. |
| `app.collision` | The app name is already registered in the gateway app registry. `error.meta.node` reports the existing owning node. |
| `app.ssh_failure` | The gateway could not connect to the target node. |
| `app.source_creation_failed` | Source directory creation or repository clone failed on the target node before gateway app configuration was written. `error.meta.reason` describes the failure; `error.meta.transport=github\|ssh\|https` is included for clone failures. |
| `app.enactment_failed` | Registry write succeeded but node-side artifacts failed in a way that cannot be retried through convergence. |

### Common Warning Codes

Non-fatal drift is reported in `success.meta.warnings[]`. Each warning carries
`code`, `family`, `message`, and `next_command`.

| Code | Family | Meaning |
| --- | --- | --- |
| `app.php_version_unavailable` | `app` | The requested PHP version is supported by Orbit but not yet installed on the owning node. Operator installs the runtime, then `doctor --fix --family=app --restore` converges. |
| `proxy.domain_inactive` | `proxy` | The production domain is not yet active because DNS or TLS prerequisites are pending. Retry with `app:register [name] --domain=<host>`. |
| `proxy.enactment_failed` | `proxy` | App-owned proxy route configuration was recorded, but backend proxy artifact application needs retry through `doctor --fix --family=proxy --restore`. |
| `process.runtime_backend_unavailable` | `process` | App-owned process definitions exist, but Supervisor is unavailable on the owning node. `doctor --fix --family=process --restore` will converge once the backend is available. |
| `process.runtime_unit_missing` | `process` | A Supervisor program for an app-owned process definition could not be rendered or loaded. `doctor --fix --family=process --restore` will repair it. |
| `app.fpm_config_missing` | `app` | App PHP-FPM configuration could not be installed during initial application. `doctor --fix --family=app --restore` will repair it. |
