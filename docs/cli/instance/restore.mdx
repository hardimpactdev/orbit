`instance:restore` keeps an intact Instance whose removal failed. It restores serving, then returns the Instance to active. It does not undelete source, data or runtime. See [Instance removal](/reference/instance-removal#restore-a-failed-removal).

```bash
orbit instance:restore <instance> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric development Instance ID. An omitted ID uses the [finite record selector](/reference/cli-ux#prompt-selection) in a terminal. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--idempotency-key=KEY` | generated | Reuse an [Operation start](/reference/operations#start-an-operation). |
| `--json` | off | Print the final Operation as [JSON](/reference/cli-ux#input-and-output-modes). |

There is no force flag or recovery option. Orbit admits only a failed removal whose complete source, runtime and database inventory survives. It refuses removal that already deleted a container, member, Route target, source, Process, Schedule trigger or SQLite file, or ran teardown. It also refuses unfinished work, incomplete evidence and identity, ownership or database admission drift.

The same Route, targets and domain serve again. Only the awake marker is restored; the cold marker stays absent and serving creates the access log. Orbit reports the Instance and Route active only after publication and its check pass.

A failure keeps the Instance removing and the removal failed. Orbit withdraws partial publication before releasing its publication holds. A failed withdrawal is reported as incomplete recovery. Run `instance:restore` again to retry. A repeat after success checks the restoration receipt and current records, then succeeds with `instance.already_restored`. A later `instance:destroy` captures a new removal identity and inventory.

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The ID is missing or is not a positive integer, and the CLI cannot prompt. |
| `instance.restore_not_failed` | The Instance is not removing with a failed live removal. |
| `instance.restore_run_unsettled` | A native removal run has not conclusively stopped. |
| `instance.restore_busy` | Lifecycle, Process or Schedule work is queued, running or waiting. |
| `instance.restore_container_removed` | The removal deleted the Instance container. |
| `instance.restore_member_missing` | A planned Instance member is gone. |
| `instance.restore_route_missing` | The captured Route is gone or its identity changed. |
| `instance.restore_target_missing` | A captured Route target is gone or changed. |
| `instance.restore_source_removed` | Source deletion completed; the checkout is gone. |
| `instance.restore_processes_removed` | Removal already removed a Process. |
| `instance.restore_schedules_removed` | Removal already removed a Schedule trigger. |
| `instance.restore_sqlite_removed` | Removal already removed an owned SQLite file. |
| `instance.restore_teardown_ran` | A teardown step ran and cannot be reversed by publication. |
| `instance.restore_evidence_missing` | The saved removal or terminal evidence is incomplete. |
| `instance.restore_source_changed` | The checkout, workspace or Git identity does not match. |
| `instance.restore_database_missing` | A database in the complete captured plan is gone. |
| `instance.restore_user_missing` | A planned database user is gone. |
| `instance.restore_ownership_changed` | A surviving database or user has different ownership. |
| `instance.restore_database_identity_changed` | A captured database name or OID changed. |
| `instance.restore_database_admission_changed` | Database admission differs from the captured fence value, or the main database is closed. |
| `instance.restore_publication_failed` | Publication or its check failed; the Instance stays removing. |
| `instance.restore_compensation_failed` | Withdrawing the partial publication failed; recovery remains incomplete. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to its Node. |
