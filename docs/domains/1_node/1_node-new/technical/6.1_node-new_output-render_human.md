# Human Renderer: `orbit node:new [name]`

[Back to `node:new` technical contract.](1_node-new.md)

This page describes the human-rendered terminal output for `node:new`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[`interactive input mode`](5.1_node-new_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Progress Tree

Render the complete progress tree before side effects begin. Steps must move
from pending to active to success, failure, or warning. Skipped compatible steps
must be shown as warning or skipped steps, not silently omitted.

Client enrollment:

```text
┌ Enrolling Node
○ Validate node
○ Check gateway identity service
○ Mint WireGuard peer
○ Write node record
○ Render WireGuard config
└ Working...

Next steps:
- Install the WireGuard configuration on the client.
- Join the Orbit WireGuard network.
- Run `orbit gateway:add` on the client.
```

App-role provisioning:

```text
┌ Creating Node
○ Validate node
○ Connect over SSH
○ Verify platform
○ Install Orbit runtime
○ Mint WireGuard peer
○ Register node
○ Configure development TLD
○ Register development TLD mapping
○ Verify node readiness
└ Node `app-1` ready

Development TLD: .test
Development DNS: *.test -> 10.6.0.7
```

Gateway bootstrap:

```text
┌ Bootstrapping Gateway
○ Validate gateway
○ Connect over SSH
○ Verify platform
○ Install gateway runtime
○ Configure WireGuard
○ Register gateway
○ Mint local control identity
○ Install local WireGuard config
○ Trust gateway CA
○ Store gateway config
○ Verify gateway API
└ Gateway `gateway-1` ready

Local client `control-1` is onboarded.
Do not run `orbit gateway:add` on this client.
```

## Success Output

Human output ends with:

- node name;
- node role;
- action performed: created, enrolled, provisioned, adopted, or converged;
- next step when the operator must act manually.

Client enrollment must tell the operator to:

1. install the returned WireGuard configuration on the client;
2. join the Orbit WireGuard network;
3. run `orbit gateway:add` on the client.

First-gateway bootstrap from an unconfigured client must state that local
client onboarding is complete for the resolved `node_new.control_name`
and that `gateway:add` is not required on the initiating client.

Development app-role provisioning must mention the resolved development TLD and
development DNS mapping.

Already-provisioned gateway convergence must show exactly:

```text
Gateway is already provisioned.
```

Incompatible existing gateway failures must show:

```text
Existing gateway is incompatible with the requested host or identity.
```

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

Non-interactive input mode missing-field failures render as prose validation
errors and must not render prompts.

Partial provisioning failures must state that gateway configuration was written
but node applying did not complete, and that the node appears as drift until
provisioning is repaired by `doctor --family=node --restore`, adopted where safe,
or removed.
