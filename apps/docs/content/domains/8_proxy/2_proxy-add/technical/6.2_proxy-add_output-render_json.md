# JSON Renderer: `orbit proxy:add`

[Back to `proxy:add` technical contract.](1_proxy-add.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

Healthy one-step add (backend/TLS enacted):

```json
{
  "success": {
    "data": {
      "route": {
        "domain": "vite.docs.test",
        "kind": "proxy",
        "owner": {
          "type": "custom",
          "name": null
        },
        "node": "app-1",
        "target": {
          "type": "upstream",
          "value": "http://127.0.0.1:5173"
        },
        "redirect_code": null,
        "tls": {
          "managed_by": "orbit",
          "trusted_by_gateway_ca": true
        },
        "status": "converged"
      }
    },
    "meta": {
      "action": "created",
      "warnings": [
        {
          "code": "firewall_rule.host_upstream_may_block",
          "family": "firewall_rule",
          "node": "app-1",
          "message": "Containerized orbit-caddy reaches host-local upstreams from the Docker bridge; if UFW blocks that path, add a scoped firewall rule for the bridge/source and upstream port.",
          "upstream": "http://127.0.0.1:5173",
          "port": "5173",
          "next_command": "firewall:allow caddy-to-host-5173 --node=app-1 --port=5173 --from=<orbit-caddy-bridge-cidr> --to=<host-address> --reason=\"orbit-caddy to vite.docs.test\""
        }
      ]
    }
  }
}
```

Redirect success omits the host-local firewall warning when the target is not host-local:

```json
{
  "success": {
    "data": {
      "route": {
        "domain": "redirect.docs.test",
        "kind": "redirect",
        "owner": {
          "type": "custom",
          "name": null
        },
        "node": "app-1",
        "target": {
          "type": "redirect",
          "value": "https://docs.test"
        },
        "redirect_code": 302,
        "tls": {
          "managed_by": "orbit",
          "trusted_by_gateway_ca": true
        },
        "status": "converged"
      }
    },
    "meta": {
      "action": "created",
      "warnings": []
    }
  }
}
```

Partial enactment failure is still a **success envelope**. The route row remains
and `meta.warnings[]` carries the repair handoff:

```json
{
  "success": {
    "data": {
      "route": {
        "domain": "vite.docs.test",
        "kind": "proxy",
        "owner": {
          "type": "custom",
          "name": null
        },
        "node": "app-1",
        "target": {
          "type": "upstream",
          "value": "http://127.0.0.1:5173"
        },
        "redirect_code": null,
        "tls": {
          "managed_by": "orbit",
          "trusted_by_gateway_ca": true
        },
        "status": "failed"
      }
    },
    "meta": {
      "action": "created",
      "warnings": [
        {
          "code": "proxy.enactment_failed",
          "family": "proxy",
          "message": "Proxy route 'vite.docs.test' was recorded, but backend/TLS enactment failed. Run doctor to converge proxy artifacts.",
          "domain": "vite.docs.test",
          "node": "app-1",
          "next_command": "doctor --family=proxy --restore --node=app-1"
        }
      ]
    }
  }
}
```

## Error Shape

Hard errors reject before a healthy one-step outcome. Domain conflict example:

```json
{
  "error": {
    "code": "proxy.domain_conflict",
    "message": "Domain 'docs.test' is owned by project.",
    "meta": {
      "domain": "docs.test",
      "owner_type": "project"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.route` | object | Created or updated custom proxy route. |
| `success.data.route.status` | `converged`, `failed`, or `partial` | Persisted enactment after this command. `converged` is healthy one-step success. |
| `success.meta.action` | `created`, `updated`, or `converged` | Command outcome. |
| `success.meta.warnings[]` | array | Optional handoffs. `proxy.enactment_failed` is a success-envelope warning when backend/TLS apply failed after the row was saved. Host-local upstreams may also emit `firewall_rule.host_upstream_may_block`. |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `proxy.domain_conflict`, `proxy.replacement_consent_required` | Stable hard failure codes. Enactment apply failure is not an `error` envelope. |
| `error.meta` | object | Field, node, caller, conflicts, or recovery context for automation. |

`proxy.enactment_failed` and `firewall_rule.host_upstream_may_block` are
registered command-level handoff warnings, not proxy or firewall doctor issue
codes. The proxy handoff allows `doctor --family=proxy --restore` commands; the
firewall-rule handoff allows `firewall:allow` commands. Each warning names the
family that owns the next operator action.
