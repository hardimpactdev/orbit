# JSON Renderer: `orbit doctor`

[Back to `doctor` technical contract.](1_doctor.md)

This page describes the JSON-rendered output for `doctor`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even when
the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Healthy diagnostics are returned under `success.data.doctor`. Drift, probe failures, and scope failures with a diagnostic return that diagnostic under `error.data.doctor`.

`issues` means findings discovered by verify probes. `actions` is empty for verify mode; when in resolution modes (`interactive`, `restore`, `adopt`), action records are returned. When `--dry-run` is used, the result includes `dry_run=true` and action records with `status=planned`.

## Success Shape

```json
{
  "success": {
    "data": {
      "doctor": {
        "mode": "verify",
        "healthy": true,
        "scope": {
          "self": true,
          "node": "mini",
          "app": null,
          "workspace": null,
          "key": null,
          "families": ["node"]
        },
        "summary": {
          "issues": 0,
          "fixed": 0,
          "adopted": 0,
          "skipped": 0,
          "conflicts": 0,
          "failed": 0,
          "planned": 0
        },
        "issues": [],
        "actions": []
      }
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `doctor.mode` | string | One of: `verify`, `interactive`, `restore`, or `adopt`. |
| `doctor.healthy` | boolean | `true` when no drift or probe errors remain after the selected mode completes. |
| `doctor.scope` | object | Resolved family, node, app, workspace, and self scope. |
| `doctor.scope.key` | string \| null | The exact issue-key filter supplied by `--key`. |
| `doctor.summary` | object | Counts for discovered issues and completed, skipped, failed, conflicted, and planned actions. |
| `doctor.dry_run` | boolean | Present and `true` only when `--dry-run` planned actions without applying changes. |
| `doctor.issues` | array | Findings discovered by verify probes and remaining after actions. |
| `doctor.actions` | array | Empty for verify mode; action records for resolution modes (`interactive`, `restore`, `adopt`). |

Issue objects contain generic fields plus family-specific detail:

| Field | Type | Meaning |
| --- | --- | --- |
| `family` | string | Product family key. |
| `node` | string \| null | Node name when the issue is node-scoped; `null` when not node-scoped. |
| `kind` | string | Generic doctor issue kind. |
| `code` | string | Concrete family issue code, such as `node.app_ssh_unreachable`. For node update posture this is one of the `node.updates_*` codes. |
| `key` | string | Stable affected-resource or family sub-scope key within the family and scope. For node update posture this is `node.updates`. |
| `summary` | string | Human-readable issue summary. Automation must not parse it. |
| `restorable` | boolean | Whether the issue can be restored by `doctor --restore` mode (or accepted as the restore option in `doctor --fix` interactive prompts). |
| `adoptable` | boolean | Whether the issue can be adopted by `doctor --adopt` mode (or accepted as the adopt option in `doctor --fix` interactive prompts). |
| `details` | object | Optional family-specific diagnostic metadata. Omitted when absent. |

Action objects are emitted by `doctor` only when a resolution mode is selected (`--fix` for interactive, `--restore`, or `--adopt`). Verify-mode runs do not emit action records. Dry-run action objects use `status=planned` and must not remove their matching issue from `issues[]`.


## Error Shapes

### Drift detected

When drift remains, return an error envelope with the diagnostic payload under
`error.data.doctor`:

```json
{
  "error": {
    "code": "drift_detected",
    "message": "Doctor found drift.",
    "data": {
      "doctor": {
        "mode": "verify",
        "healthy": false,
        "scope": {
          "self": false,
          "node": "app-1",
          "app": null,
          "workspace": null,
          "key": null,
          "families": ["node"]
        },
        "summary": {
          "issues": 1,
          "fixed": 0,
          "adopted": 0,
          "skipped": 0,
          "conflicts": 0,
          "failed": 0,
          "planned": 0
        },
        "issues": [
          {
            "family": "node",
            "node": "app-1",
            "kind": "unverifiable",
            "code": "node.app_ssh_unreachable",
            "key": "app-1.ssh",
            "summary": "Gateway cannot reach app-1 over SSH.",
            "restorable": false,
            "adoptable": false
          }
        ],
        "actions": []
      }
    },
    "meta": {
      "issues": 1
    }
  }
}
```

### Validation failed

```json
{
  "error": {
    "code": "validation_failed",
    "message": "--self and --node are mutually exclusive.",
    "meta": {
      "fields": ["self", "node"]
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `doctor.mode` | `verify`, `interactive`, `restore`, `adopt` |
| `doctor.scope.families[]` | `node`, `app`, `workspace`, `process`, `proxy`, `firewall_rule`, `tool`, `schedule`, `database_connection` |
| `doctor.issues[].kind` | `missing`, `extra`, `divergent`, `unverifiable` |
| `doctor.actions[].status` | `completed`, `created`, `updated`, `skipped`, `conflict`, `failed`, `planned` |
| `error.code` | `drift_detected`, `mode_not_supported`, `probe_failed`, `scope_not_found`, `authorization_failed`, `gateway_unavailable`, `validation_failed` |

The `error.code` values listed here are exhaustive for `doctor`. Add a new value
to this renderer contract before implementing another JSON failure code.
