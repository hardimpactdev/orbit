# Realtime events with Reverb

## Problem

The web app and `realtime:tail` need the Gateway to push events. The Gateway publishes through Laravel Reverb, and clients subscribe at `wss://reverb.orbit`. [Realtime events](/reference/events) defines the channels and the events.

## Cause

Reverb holds long-lived WebSocket connections, so it runs outside the Gateway process. Its Laravel host loads the internal `hardimpactdev/reverb-manager` package for rolling app changes. The Gateway installs and runs it as the `websocket` role, the same way the `metrics` role runs Prometheus and Grafana.

## Solution

### Add the role

```bash
orbit node:role:add gateway websocket
```

The `websocket` role is a singleton. It conflicts with no other role, so it can share a Node with `gateway` and `vpn`. No Project, Instance, Route, or `.env` edit is involved.

### What the converge does

1. It installs the role packages: `caddy`, `composer`, `git`, `openssl`, `php-curl`, and `php-xml`. `php-curl` and `php-xml` let `composer install` pass its platform check on a fresh Ubuntu 26.04 Node.
2. It generates a Laravel `APP_KEY` for the Reverb server the first time, and stores it encrypted as a setting of that Node. It also creates the Gateway's own [Reverb app](/reference/websocket-apps), `gateway`, when it is missing. Later converges reuse both.
3. It checks out `https://github.com/hardimpactdev/orbit-reverb.git` at `main` into a separate release under `/opt/orbit/websocket.releases` and runs `composer install --no-dev` as the managed user. It validates that release before stopping Reverb and switching `/opt/orbit/websocket` to it.
4. It writes the app's `.env` with mode `0600`. It contains restricted registry credentials, with no static app list.
5. It installs `orbit-websocket.service`, which runs `php artisan orbit:reverb:start --host=127.0.0.1 --port=8790` with `Restart=always`. Each converge restarts Reverb, so it loads the current code, fetches the fresh registry, and clients reconnect. App changes use the registry API without convergence.
6. It issues an Orbit CA certificate for `reverb.orbit` and adds a Caddy site on the Node that proxies to Reverb. Caddy admits the WebSocket upgrade.
7. It publishes `reverb.orbit` in private DNS with the Node's WireGuard address.

Before any change, the converge refuses a Node that lacks an address its Caddy sites bind, so a refused converge leaves a running Reverb alone. The converge stops the runtime again only when it created the role assignment. A preparation failure leaves the existing process running. An activation failure reports an error and requires forward recovery with a compatible release. Orbit does not automatically start a static app list that could contain revoked credentials. That covers `--converge-existing`, a retry after a failed converge, and a relocate target. A failed rollback reports `websocket.rollback_failed`.

`ORBIT_WEBSOCKET_REPOSITORY`, `ORBIT_WEBSOCKET_REF`, `ORBIT_WEBSOCKET_INSTALL_PATH`, and `ORBIT_WEBSOCKET_PORT` in the Gateway `.env` change the defaults. Another Reverb app must accept client events from channel members (`accept_client_events_from` set to `members`), as `orbit-reverb` does. Without it, the [Node agent channels](/reference/events#node-agent-channels) carry no agent events.

The Gateway reads the connection from the active role assignment. It needs no broadcast setting in its `.env`.

### Move the role

```bash
orbit node:role:relocate <node> websocket --force
```

Relocate copies the server's `APP_KEY` to the target when the target has none, and never overwrites one. The apps are Gateway records, so they do not move. It converges the target and points `reverb.orbit` at it. It then waits 31 seconds, the private DNS answer TTL plus one second, so clients that resolved the old address resolve again. Then it removes the runtime and publication from the source. The Reverb checkout stays on the source. Clients keep the same key. [`node:role:relocate`](/cli/node#orbit-noderolerelocate) describes `--from` for a target that already holds the role.

### Remove the role

`orbit node:role:remove <node> websocket --force` withdraws the Caddy site, stops and disables the unit, removes the certificate and DNS record, and deletes the server's `APP_KEY`. `--purge-data` also deletes the checkout. With `--offline`, the Gateway removes only the DNS record and the `APP_KEY`. The process remains required for app-change confirmation until shutdown is verified. Node deletion is blocked while any required process remains. The apps stay, so a new role serves them with the same keys.

## Limits

This covers one Reverb server behind one `websocket` assignment. That server serves several [Reverb apps](/reference/websocket-apps). Production starts with one process. Apply confirmation accounts for every serving process. App rotation closes only that app’s sockets. Package upgrades still need an announced reconnect window.

## Verification

```bash
orbit realtime:show
orbit doctor --node=<node-id> --family=role
getent ahostsv4 reverb.orbit
```

`orbit realtime:show` reports `configured` and `wss://reverb.orbit`. `getent` resolves `reverb.orbit` to the role Node's WireGuard address. On the Node, `systemctl is-active orbit-websocket` prints `active`. From a Node that trusts the Orbit CA, `curl -i -X POST https://reverb.orbit/apps/<app-id>/events` answers `401` with `Authentication signature invalid`, which proves that Reverb answers behind the Caddy site.
