---
title: "orbit tasks:show"
sidebarTitle: "tasks:show"
description: "Show one task as a detail tree, followed by its brief and a table of its subtasks in position order."
---

```bash
orbit tasks:show [group] [--json]
```

Token totals use the thread observations already recorded by task operations. Showing a task does not contact its agent sessions. A slow or unavailable session does not delay the task detail.

The tree shows the ID, title, Project, status, whether the task is asking for assistance, the assistance kind, the question, the reason, Instance, pull request, models, tokens, line diff, and duration. The subtask table shows the position, ID, title, status, deliverables, tokens, line diff, duration, assistance kind, and the question or reason of each subtask. A direction request shows its question in that last column. A failure shows its reason. A subtask or task that is not asking shows an em dash in the kind, question, and reason columns, even when an old value is still stored. JSON includes `assistance_requested`, `assistance_kind`, `assistance_question`, and `assistance_reason` on the task and each subtask, and `fails_on_base` on every command deliverable. When that value is true, the detail names the deliverable under Fails on the start commit. Showing an active task refreshes its metrics, as the [tasks reference](/reference/tasks#tokens-and-line-diff) describes.

The tree shows **VM power** when the task's `vm_power` is not `null`. JSON includes `vm_power` when power is known: `running`, `stopped`, or `destroyed`; it omits the field when the API reports `null`. [VM power](/reference/compute-drivers#vm-power) describes how those values map to the task VM's state, separately from task status.

On the task, `watched_pr_url`, `watched_pr_number`, and `watched_pr_state` report the pull request found on `task-{id}` while subtasks are open. Those fields do not change `pr_url`, which remains the reviewed pull request Orbit opened.

A task of a review-and-merge Project, or one that reviews an incoming pull request, also has `review_and_merge` in JSON: `enabled`, `pr_branch`, `merge_status`, `merge_reason`, `merged_sha`, and `reviewed_commits`. Each reviewed commit has `sha`, `source`, `review_task_id`, `pushed_at`, `github_review_id`, and `recorded_at`. Other tasks return `null`. The tree adds `Review and merge`, `Pull request branch`, `Merge`, and `Merged commit`, and a table lists the reviewed commits. A final review subtask has `type` `final_review`. [Review and merge](/reference/tasks#review-and-merge) defines these fields.
