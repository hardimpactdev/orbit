# Short-lived credentials for Services dependency detection

Status: approved by Nick on 2026-10-28; implementation contract. This extends [Services detection](service-dependency-detection.md). Scope: one Orbit PR and one orbit-swamp PR, each about 800 changed lines or fewer, cross-linked and reviewed as a contract pair.

## Goal and evidence

Services uses the Gateway's existing GitHub App installation without a standing GitHub secret or a gh login. Detection remains VM-free. Project 20 uses `github_app` source access and `git@github.com:nckrtl/website.git`. Run `d8506789-de27-43a3-985f-31f081c758d1` reported `source_acquisition_failed` and `batch_pr_lookup_failed`; the producer discarded command stderr, so authentication is not yet a proven command-level cause. Before Services detection, task source acquisition used Gateway repository access. This change supplies that access explicitly and closes the diagnostic gap.

## Gateway contract and trust boundary

Add `POST /api/v1/projects/{project}/dependency-read-token`, with an empty JSON object body. The caller cannot supply a repository, installation, permissions or expiry. Authorize the active WireGuard peer using the existing `REMOTE_ADDR` identity check, require Gateway access, and require its Node ID to equal a Gateway-owned `dependency_detection.services_node_id` setting. The orchestrator verifies Services with `orbit node:show 17 --json`, backs up `/home/orbit/shared/gateway.env` as `orbit` with mode `0600`, sets its single `ORBIT_DEPENDENCY_DETECTION_SERVICES_NODE_ID=17` entry, and runs `php /home/orbit/orbit/apps/gateway/artisan gateway:release:configure` (never `config:cache` in a release). It then checks `POST /api/v1/projects/20/dependency-read-token` from Services, discarding the token without logging it. [The Gateway runbook](https://github.com/hardimpactdev/orbit/blob/feat/dependency-read-tokens/docs/reference/github-app.md#enable-during-deployment) contains exact backup and route-check commands; missing configuration refuses requests. A Node name, forwarded header or caller-supplied ID grants nothing. There is no Services role today; this proposal does not invent one or grant all Gateway peers token access. Peer identity trusts processes on Services, not an individual Unix user.

Resolve the Project and canonical GitHub repository from Gateway state. Require `source_access: github_app` and a covering installation of the existing App. Refuse missing Projects/repositories, unsupported hosts/source access and absent installations. Never fall back to CLI authentication, anonymous acquisition or broader credentials.

Mint a fresh installation token restricted to exactly that repository, with `contents: read` and `pull_requests: read` (plus GitHub's implicit metadata read). Preserve GitHub's actual `expires_at`; validate the returned repository scope, permissions and expiry, which must be in the future and no more than one hour away, allowing only small clock skew. Do not use the existing cached string-only token API. The successful HTTP 200 reply is:

```json
{"data":{"project_id":20,"repository":"github.com/nckrtl/website","clone_url":"https://github.com/nckrtl/website.git","token":"<ephemeral>","expires_at":"2026-10-28T17:00:00Z"}}
```

Use `Cache-Control: no-store`. Exclude this synchronous route from `RecordCommandActivity`, create no Operation, and put no token in command-result attributes, exception context or HTTP debug logging. Sensitive PHP arguments and debug representations redact it. Only this reply contains the token; it is never an ordinary Project field. Errors contain fixed codes, never upstream response bodies: `dependency_token.forbidden` (403), `project.not_found` (404), `dependency_token.repository_unavailable` (422), `dependency_token.refused` (403), or `dependency_token.unavailable` (503). Bound minting to five seconds, within the scan deadline; no automatic retry loop.

## Swamp credential lifetime and process boundary

Before acquisition, request one token and verify Project ID, canonical repository, HTTPS clone URL and expiry against scan configuration. Keep it in a private in-memory scope through clone and PR lookup, then release references in `finally`; JavaScript cannot promise memory zeroisation. Never write it to a file, resource, method argument/output, process record or global environment. Keep the two-minute scan deadline and terminate descendants before releasing the scope. A missing, expired or refused token stops acquisition, including for public repositories.

Invoke trusted Git with the canonical HTTPS URL, an isolated HOME/config, hooks/filters disabled, no redirects, submodules, external protocols or ambient credential helpers. A trusted GIT_ASKPASS helper receives the token only in that child's environment; the helper contains no token and answers only the expected GitHub prompt. No token appears in argv, origin URLs or `.git/config`. Repository content cannot select an executable in this credentialed process. Invoke trusted `gh pr view` with child-only `GH_TOKEN`, isolated config and the existing three-second deadline. Neither command runs through a repo script.

Package planning receives only the sanitized manifest/lockfile tree and the existing explicit environment allowlist. It receives no token, helper variables, credential config or credential-bearing Git metadata. Do not temporarily mutate `Deno.env`. A PR refresh between scans obtains and discards its own token, only when a refresh is due; it never reuses a persisted credential. Move network lookup outside the shared model lock; publish under the short lock only after re-reading current state so stale evidence cannot replace a newer publication. Requests share a bounded refresh budget; minute ticks cannot accumulate waiting token requests.

## Failure states and diagnostics

Treat the GitHub token as a bounded RFC 6750 bearer value, including signed tokens with periods and hyphens. Reject whitespace and control characters. Do not assume GitHub tokens contain only letters, digits and underscores.

Capture Git/gh stderr privately and classify it into fixed codes: `token_missing`, `token_refused`, `token_unavailable`, `token_invalid`, `git_auth_failed`, `git_repository_unavailable`, `git_transport_failed`, `git_failed`, `gh_auth_failed`, `gh_lookup_failed`, `command_timeout`, or `command_aborted`. Unknown stderr maps to the generic command code. Settings preflight failures use `project_settings_unavailable`; unexpected scan failures use `scan_failed`. Never persist raw stderr, upstream messages, URLs containing credentials or token substrings. The bounded diagnostics resource records Project ID, run ID, stage, code and nullable exit status, including when the scan throws. Tests inject secret-bearing stderr to prove this boundary.

Acquisition failures retain the existing `source_acquisition_failed` source outcome and last-good report pointers, with the detailed safe code in step output. PR failures publish `batch_pr.status: unknown`, a safe error code, and retained last-success time/value; they never prove absence or crash the workflow. Token failure before either operation yields both unavailable source and unknown PR evidence. Success still requires authoritative group/publish evidence and a successful GitHub lookup. The frozen v1 fixtures, limits and freshness rules stay unchanged.

## Tests and release gate

The repository ships both `dependency-scanner` and `dependency-pr-reader` model definitions. The scanner preserves the existing Services ID `a7d392d3-8ca3-4418-823d-74183c0d8a38`, so its resources retain their owner. The minute workflow uses `model_method` and runs the reader after project work. Native tests validate the shipped workflow and definitions before executing them. At deployment, an existing untracked scanner definition can conflict with the newly tracked path; `deploy-services` refuses that conflict before interrupting schedules. The orchestrator must preserve that definition outside the checkout and reconcile its ID and path before deployment, without deleting model resources. This PR performs no live adoption.

- Gateway: Services succeeds; other peers (including Gateway-authorized peers), spoofed headers, unset identity, missing Project, wrong host/source access and missing installation fail closed. Assert exact one-repository read permissions, bounded expiry, timeout, and no token in Activity, Operations, logs or errors.
- Swamp: happy scan and standalone PR refresh; Git and gh receive the token, package tools never do, even on cancellation/failure. Test HTTPS/config isolation, identity/expiry rejection, safe stderr classification, missing/refused tokens, unknown PR retention and publication races. Sentinel-token assertions cover every persisted/output surface.
- Keep both PRs independently testable with matching contract fixtures; post one paired READY only after CI is green. Nick merges/deploys Gateway first, apply its identity setting, then Services. No access or secret changes are required. Run one normal Project 20/main detection after deployment, then read exact index/report versions with `data.get` and report byte sizes, counts, freshness and compact JSON. Sources must succeed and PR state must be `open` or `absent` before orbit#1553 merges. On failure, report evidence and stop without a retry loop.
