---
title: Native Caddy command steps
description: Complete public Caddy input and placed publication actions.
---

Caddy publication admits the complete Node configuration before dispatch. The workflow receives public configuration, version and listen addresses as inputs. Its steps do not read intent or report progress through the Gateway.

The native workflow exposes candidate preparation, bounded content writes, inspection, validation, activation, service enable and service reload as separate placed actions. Failure restoration is a native dependency branch. Operational Python is visible inside each command/shell step's `run` block; TypeScript only shapes public input and output. No private material is needed for a Caddy configuration generated by the canonical public renderer.

The shared Swamp command-step helper reads the native terminal result. The Gateway records the Operation outcome through its family projector. A Caddy Operation submitted during a release remains submitted until that native result arrives.

The shared full-input dispatch and terminal subscriber are merged. Their production source uptake is verified; family end-to-end result projection still requires its own live proof. Built-in command/shell steps on logical Nodes 1 and 18 remain unavailable until the shared SSH proxy transport is proved. Serializing publication does not refresh an admission snapshot: the revision policy for each Node must be settled before concurrent mutation parents use this workflow.

The reusable public capture is `NativeCaddyPublicationInput::forNode(Node): array`. A composing parent keeps its own Operation identity and places every Caddy action on the captured publication Node. The native workflow takes `intent.caddy_publication`, an empty `execution_secrets` object, and the authoritative `operation_id`, `kind`, and `node_id`. Its fixed terminal selector is `completion/result`. It reports `ready`, `result`, and `version`.

All Caddy mutation steps use the same native behavior identity for the effect Node. Swamp orders actions from different parent workflows using its native model locks. Input and observation models use the native run ID so another parent cannot replace a resumed observation. Each service change rechecks the candidate digest. Compensation refuses to overwrite or reload a newer publication. Native resume restarts from activation after compensation; it never treats an old activation receipt as current.

A matching file is unchanged only when its generation has a successful load receipt for the current systemd service invocation. A missing receipt or a different service invocation requires an actual load. Compensation compares the exact generation as well as its digest, so it preserves a newer publication with identical content. Restoration invalidates the prior generation’s receipt before switching the file back, so its old load cannot stand in for the pending restoration reload. The receipt records a completed service action; it adds no lock, retry loop or Gateway callback.
