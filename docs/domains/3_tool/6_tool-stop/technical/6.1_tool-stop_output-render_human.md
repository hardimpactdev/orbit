# Human Renderer: `orbit tool-stop`

[Back to `tool-stop` technical contract.](1_tool-stop.md)

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render an in-progress tree after input resolution and before gateway reads, node inspection, or node apply begins.

```text
┌ Stopping Tool
○ Resolve target
○ Read gateway tool configuration
○ Run command action
└ Working...
```

## Success Output

Human success output is one concise sentence:

```text
Stopped <tool> on <node>.
```

Do not append expected-state, observed-state, managed-flag, version, endpoint,
or config metadata to the human success line. Detailed inspection belongs to
`tool:show`, JSON output, `tool:logs`, or `doctor --family=tool`.

## Failure Output

Human-rendered failures show the failing field or condition, a concise prose error, and actionable recovery guidance when the operator can resolve the issue.

For `tool.remote_action_failed`, include immediate apply diagnostics when
available:

```text
Exit code: <exit_code>
stderr: <brief stderr>
```

When the tool declares a log source, suggest:

```text
orbit tool:logs <tool> --node=<node>
```

Also suggest:

```text
orbit doctor --family=tool --restore
```
