# JSON Renderer: `orbit process:add [name] [command]`

[Back to `process:add` technical contract.](1_process-add.md)

This page describes the JSON-rendered output for `process:add`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces non-interactive input mode.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Success data contains the process definition and derived runtime units. Partial post-configuration drift is reported under `success.meta.warnings[]`.

Warning objects contain:

| Field | Meaning |
| --- | --- |
| `code` | Singular product warning code, such as `process.runtime_unit_missing`, with the owning family recorded separately. |
| `family` | State family that owns the warning. |
| `message` | Human-readable warning summary. |
| `next_command` | Suggested command to inspect or repair the warning. |

## Success Example

```json
{
  "success": {
    "data": {
      "process": {
        "name": "vite",
        "app": "docs",
        "command": "npm run dev",
        "restart_policy": "never",
        "crash_notification": "agent_ide",
        "runtime": "docker"
      },
      "runtime_units": [
        {
          "name": "orbit_docs_main_vite",
          "context": "main"
        }
      ]
    },
    "meta": {
      "warnings": []
    }
  }
}
```

## Warning Example

```json
{
  "success": {
    "data": {
      "process": {
        "name": "vite",
        "app": "docs",
        "command": "npm run dev",
        "restart_policy": "never",
        "crash_notification": "agent_ide",
        "runtime": "docker"
      },
      "runtime_units": []
    },
    "meta": {
      "warnings": [
        {
          "code": "process.runtime_unit_missing",
          "family": "process",
          "message": "Process configuration was written, but one runtime unit was not rendered.",
          "next_command": "orbit doctor --fix --family=process --restore"
        }
      ]
    }
  }
}
```

## Error Example

```json
{
  "error": {
    "code": "validation_failed",
    "message": "The process name is required.",
    "meta": {
      "field": "name"
    }
  }
}
```

## Authorization Error

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'process:add' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "process:add",
      "serving_node": "app-1"
    }
  }
}
```

## Error Code Vocabulary

- `validation_failed`: missing or invalid `name`, `command`, `app`, `restart_policy`, `crash_notification`, or `runtime`.
- `authorization_failed`: caller lacks `process:add` on the target app's owning node.
- `process.name_collision`: the owning app already has a process definition with the same name.
- `gateway_unavailable`: the CLI cannot reach the gateway API before configuration is written.
