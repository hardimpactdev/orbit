# JSON Renderer: `orbit app:show [app]`

[Back to `app:show` technical contract.](1_app-show.md)

This page describes the JSON-rendered output for `app:show`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](5.2_app-show_input-mode_non-interactive.md),
even when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Fields

`app:show` intentionally keeps `success.data.app` limited to the canonical app
JSON entity. Show-only registry expansion lives under the sibling
`success.data.details` object so automation can consume the app entity without
also accepting command-specific relationship fields.

| Field | Type | Meaning |
| --- | --- | --- |
| `app` | object | Canonical app JSON entity defined in [`5_app/README.md`](../../README.md#app-json-entity). |
| `details.domain` | string \| null | Primary domain registered for the app. `null` when no primary domain is configured. |
| `details.document_root` | string | Configured document root path on the owning node. |
| `details.node.name` | string | Owning app-role slug. |
| `details.node.host` | string | Owning app-role host or address recorded in node configuration. |
| `details.agent_ide.adapter` | string \| null | Effective agent IDE adapter resolved for this app. `null` when no adapter is configured at any resolution level, or when an explicit app-level override disables agent IDE. |
| `details.agent_ide.inherited_from` | string | Resolution source for the rendered adapter. See [Agent IDE Resolution Reporting](#agent-ide-resolution-reporting). |
| `details.agent_ide.workspace_discovery` | string \| null | Whether the resolved adapter exposes workspace discovery for this app. `null` when `details.agent_ide.adapter` is `null`. |
| `details.workspaces[]` | object[] | Full registry list of workspaces owned by this app. Not truncated. |
| `details.workspaces[].name` | string | Workspace slug. |
| `details.workspaces[].branch` | string \| null | Branch recorded for the workspace, or `null` when not recorded. |
| `details.processes[]` | object[] | Full registry list of process definitions owned by this app. Not truncated. Runtime status belongs to the `process` family / process events, not `app:show`. |
| `details.processes[].name` | string | Process slug. |
| `details.routes[]` | object[] | Full registry list of app-owned proxy routes. Not truncated. |
| `details.routes[].host` | string | Route hostname as recorded in `proxy`. |
| `details.routes[].kind` | string | Route kind. Always `app` for app-owned routes returned by `app:show`. |
| `details.routes[].owner` | string | Route owner family. Always `app` for routes returned by `app:show`. |

`app:show` is a registry read. It does not return live runtime container, document-root,
route, process, or node-reachability checks. Use
`doctor --family=app --json` for app readiness and drift output.

If real-world apps grow lists large enough to require pagination, paging
metadata will be added under `success.meta` (mirroring `app:list`). The
default contract emits full lists with no truncation indicator.

### Agent IDE Resolution Reporting

`details.agent_ide` reports the effective resolved view, not the full chain. The
resolution order defined in
[`architecture.md` §Agent IDE Integrations](../../../../architecture.md) is collapsed
into one effective adapter plus one source label.

`details.agent_ide.inherited_from` values:

| Value | Meaning |
| --- | --- |
| `app` | The app has an explicit agent IDE setting and that setting is in effect. |
| `node` | The app inherits, and the owning node has a node-level adapter set. |
| `default` | Neither the app nor the owning node has an explicit setting; no agent IDE is configured. |

`details.agent_ide.workspace_discovery` values:

| Value | Meaning |
| --- | --- |
| `available` | The resolved adapter implements workspace discovery for this app. |
| `unavailable` | Reserved for a future explicit live adapter check. `app:show` does not emit this value in its registry-only read path. |
| `unsupported` | The resolved adapter does not implement workspace discovery. |
| `null` | `details.agent_ide.adapter` is `null`; no discovery is meaningful. |

A future workspace-level override (per
[`architecture.md` §Agent IDE Integrations](../../../../architecture.md)) will be
reported by `workspace:show`, not by `app:show`.

## Error Shapes

### Missing required input

```json
{
  "error": {
    "code": "validation_failed",
    "message": "App name is required.",
    "meta": {
      "field": "app"
    }
  }
}
```

### App not found

```json
{
  "error": {
    "code": "app.not_found",
    "message": "App 'docs' not found or not visible.",
    "meta": {
      "app": "docs"
    }
  }
}
```

### Not authorized

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'app:read' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "app:read",
      "serving_node": "app-1"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to show app details.",
    "meta": {}
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `details.agent_ide.inherited_from` | `app`, `node`, `default` |
| `details.agent_ide.workspace_discovery` | `available`, `unavailable`, `unsupported`, `null` |
| `error.code` | `validation_failed`, `app.not_found`, `authorization_failed`, `gateway_unavailable` |

The `error.code` values listed here are exhaustive for `app:show`. Add a new
value to this renderer contract before implementing another JSON failure code.
Live check outcomes never appear here: the registry read either succeeds or
the read itself fails with one of the codes above.
