## Progress Tree

`workspace:setup` renders a step tree during execution. Steps are shown
sequentially and updated in real-time. Human mode starts by rendering a
`Resolve workspace identity` row before workspace target resolution, so
no-argument calls from adapter-managed directories do not leave a blank terminal
while Orbit probes the adapter. Once the target is resolved, Orbit renders the
app-specific setup tree.

```text
┌ Setting Up Workspace
○ Resolve workspace identity
○ Apply and verify workspace change
○ Configure routing for https://feature-a.my-app.orbit.local
○ Apply runtime artifacts on app-1
○ Run setup step: composer install
○ Run setup step: php artisan migrate
○ Run setup step: npm install
○ Start processes
○ Run HTTP probe
└ Working...
```

When setup steps are configured, the setup-step row shows the active setup
command while it is running. The row keeps its canonical label, but its message
is updated with the current step ordinal and command:

```text
┌ Setting Up Workspace
● Applied and verified workspace registration  feature-a
● Registered proxy routes                      ready
● Installed runtime container artifacts                  ready
◉ Run workspace setup steps                    Running setup step 2/3: composer install
○ Render inherited runtime units
○ Check workspace readiness
└ Working...
```

After all setup steps complete, the same row resolves to the aggregate setup
summary:

```text
┌ Setting Up Workspace
● Applied and verified workspace registration  feature-a
● Registered proxy routes                      ready
● Installed runtime container artifacts                  ready
● Ran workspace setup steps                    3 steps
● Rendered inherited runtime units             vite
● Checked workspace readiness                  200
└ Workspace ready and available at: https://feature-a.my-app.test
```

For successful human runs, the final progress-tree footer is the success
summary. `workspace:setup` does not print an additional prose success block
after the tree; the URL belongs in the footer.

## Conditional Steps

- **Setup steps**: Only shown if the parent app defines setup steps.
  The active setup command is shown in the setup-step row while the configured
  steps are running. Skipped step rows are omitted silently to keep output
  focused.
- **Processes**: Only shown if processes are started.
- **HTTP probe**: Final setup-time URL probe. Probe failure renders a non-fatal
  warning under the success line; it does not turn the command outcome into a
  failure or create a doctor issue code.

## Human Strings

The final tree footer is:

- **Success**: "Workspace ready and available at: {url}"

`workspace:setup` does not render a separate prose success block after a
successful human tree. JSON responses still include `result.action` so machine
callers can distinguish `set_up`, `adopted`, and `converged`.

- **Success with warning**: The success line above is rendered, followed by
  a `Warning:` block summarizing each entry from `success.meta.warnings[]`
  with its message and the suggested `next_command`. For example:
  "Warning: Setup completed, but the HTTP probe for '{url}' did not return a
  serving response within 10s. Rerun
  `orbit workspace:setup {name}` after fixing the app."
- **Failure (setup step)**: "Setup step '{step}' failed with exit code
  {exit_code} on node '{node}'. The workspace path is still set up; rerun
  `orbit workspace:setup {name}` after fixing the script."

## Prose Errors

Errors are rendered with clear, actionable summaries:

```text
Error: Setup step "npm install" failed with exit code 1.

The command was run in /var/www/my-app/feature-a on node app-1.
Workspace configuration and runtime artifacts remain in place. Rerun
"orbit workspace:setup feature-a" after fixing the script,
or see "orbit workspace:log feature-a" for the full execution output.
```
