# One package per update group

Maintained projects use the [group worker](task-worker-maintenance.md) for package,
detection and summary methods. Gateway owns checks, repair turns, publication
and cleanup.

The manual `dependency-package` workflow accepts one existing external group for a [configured project](dependency-projects.md), one manager (`composer` or `js`), package, exact stable version, purpose (`major` or `security`) and advisory IDs with their source URLs from detection. It never creates a live group by itself. Each group has exactly one child. Start only after Nick authorizes a live run.

Admission records the immutable target in Swamp. The group must be an unused backlog group for its configured Project. Before admitting a new package, the previous package run in that same Project must have completed after its PR merged (or completed unchanged). A failed/parked run blocks the sequence. To abandon it, use the existing cancellation and cleanup path, then explicitly acknowledge its factory assistance gate to reach terminal `failed`; only a clean cancelled group with destroyed VM and ended children releases the sequence. Safety or operator assistance still blocks admission. Admission and ticks reuse the behavior lock, keyed jobs and official `@swamp/software-factory`; there is no queue or new engine. Provision obtains a new task VM from the Project's configured default branch, after the previous group's completion. Reuse of a VM or a pre-provisioned group is refused.

`provision → package maintenance → handoff check → publish → wait for merge → complete`

Worker package runs select the configured ecosystem and path, pass the exact
package target to its extension, and run detection afterwards. The default path
is `.`; pass `path` for another configured application.

A failed command or local check gets one repair turn, a fresh run of the same
package maintenance, then one recheck. The agent fixes the cause; Swamp reruns
the extension. The fresh run independently checks the security
audit. Cumulative change evidence survives it. A blocked turn, second failure,
unknown execution or infrastructure failure parks. Preserve other direct ranges
and policy. Publication uses the passed check and summary; no-change completion
remains available. Board assistance is separate from factory consent.

The worker workflow also supports `detect` with the configured paths and policy.
It combines ecosystem major candidates and current advisory evidence. Detection
is evidence only: choose an explicit version before admission. A finding does not authorize a
policy bypass. Invalid output cannot select a target.

Security targets require advisory IDs and source URLs from current detection.
The extension verifies that selected advisories no longer affect the package and
uses only the documented package-specific age exception. Do not guess a fixed
version. Use a fresh group after any abandoned package run has ended and cleaned
up.

Fixture acceptance covers two packages in sequence, refusal before the first merges/completes, fresh provision identity, immutable single-package args, lost replies/restarts, green and one-repair paths, the repair cap, safety/assistance preservation and no publication before passed checks. Live acceptance follows the [deployment prerequisites](task-worker-maintenance.md#deployment-and-proof). Apply the reviewed Swamp commit, then run an authorized group and inspect maintenance, audit and check evidence. Return its exact PR head without merging.

Rollback: stop ticking the explicit item; reconcile any active operation before cancellation or cleanup. Retain Swamp target and receipt state. Revert the reviewed workflow/client only after no package operation is active. Never resolve operator/safety assistance to make rollback proceed.

Run the manual workflow with a local JSON input file (use real versions/URLs from current detection, not fixture versions):

```json
{"workItem":"tg-<new-group>","manager":"composer","package":"livewire/livewire","version":"<fixed-x.y.z>","purpose":"security","advisories":["<current-PKSA-id>"],"advisoryUrls":["https://github.com/advisories/<current-GHSA-id>"]}
```

`swamp workflow run dependency-package --input-file <input.json>` admits/starts the explicit item and performs one tick. Repeat the same command to reconcile it, or tick `orbit-driver-package` for that same item. Return the published PR and exact head to Nick and stop at human review; no merge action exists here. Never use the fixture's synthetic versions as a live target.

Local validation: `~/.swamp/deno/deno test --allow-all tests/package_stage_test.ts tests/package_routing_test.ts tests/routine_stage_test.ts tests/routine_routing_test.ts tests/gateway_stage_test.ts tests/group_assistance_test.ts tests/driver_test.ts`. These use disposable repos and a loopback fixture Gateway. Never reset an admitted package run to reuse its group; keep target/receipt state and use a new group after operator reconciliation.
