# JSON Renderer: `orbit tool:list`

[Back to `tool-list` technical contract.](1_tool-list.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "tools": []
    },
    "meta": []
  }
}
```

Command-specific result data uses the canonical tool entity from [`README.md`](../../README.md#tool-json-entity) unless the command returns credentials.

Because `tool:list` is a registry-read command and does not perform live node
inspection, `success.data.tools[].observed_state` and
`success.data.tools[].observed_version` are always `null`. Both keys remain
present for canonical tool entity schema stability until a command contract
adds an explicit live option. `version` remains the gateway-owned intended or
registry-known version.

## Error Shape

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Required input is missing or invalid.",
    "meta": {
      "field": "node"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed` | Stable command failure code. |
| `error.message` | string | Human-readable failure summary. |
| `error.meta` | object | Field, target, caller, or remote-action context for automation. |

Gateway-originated error codes, messages, and metadata are preserved end to end,
including `authorization_failed` and `gateway_unavailable`.
