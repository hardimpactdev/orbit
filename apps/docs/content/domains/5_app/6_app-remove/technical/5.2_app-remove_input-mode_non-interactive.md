# Non-Interactive Input: `orbit app:remove`

[Back to `app:remove` technical contract.](1_app-remove.md)

**Input mode:** Non-interactive.

Use this mode without a TTY or whenever `--json` is present. This mode can
never render prompts. `--json` forces non-interactive input mode; it selects a
renderer and does not imply destructive consent. When `--force` is missing,
validation fails before side effects.

## Required Input

| Field | Missing behavior |
| --- | --- |
| `project` | `validation_failed` with `meta.field=app`. |
| `force` | `validation_failed` with `meta.field=force` and `meta.reason=destructive_consent_required`. |

`--force` is required for every non-interactive invocation, including
`orbit app:remove <slug> --json`.

## Resolution and authorization

The supplied `project` must be an exact logical slug. Before effects, Orbit
enumerates every instance, serving node, and dependent artifact and authorizes
`app:remove` across the complete serving-node set. Any denial stops the entire
cascade with `authorization_failed`; there is no partial or parent-only path.

Hostnames and dotted instance selectors return `validation_failed` with
`meta.field=app` and `meta.reason=logical_slug_required`. A missing project
returns `app.not_found`.
