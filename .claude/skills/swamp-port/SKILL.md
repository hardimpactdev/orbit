# Port a kind to Swamp

Port one family or parent kind per PR, inside a production-equivalent dev topology (F13). The PR carries the topology receipt. The Gateway admits and projects; Swamp does the work. The [porting reference](../../../docs/swamp/porting.md) holds the template, the legacy-to-native table, the anti-patterns and the changelog. The [Swamp shape guide](../../../swamp/docs/swamp-shape.md) and [PLAN boundary decisions](../../../docs/swamp/porting.md#check-all-seven-boundary-decisions) are binding. Where this skill and the guide disagree, the guide wins; tell lane 26.

## The loop (F13)

1. Claim the kind from the port queue (`port-queue-*.md` in `~/swamp-execution` on beast). At most five port lanes run at once, one per topology slot.
2. Call Recall `resolve` for the kind and its family. Read the [Swamp manual](https://swamp-club.com/manual) pages for workflows, behavior definitions, vaults and remote execution.
3. **The legacy sequence is the spec (F9).** Read the pre-Swamp Gateway action, its agent actions and its feature tests at the migration baseline: `git show 6291bb036:<path>`. List its phases in order, with each phase's Node and edge cases, including values the Gateway rewrites before execution, such as setup macros (#2304). Write the parity tests first.
4. Start the topology: `bin/swamp-proof up --topology <name>`. Its Gateway VM carries the `gateway` and `swamp` roles (F14); its Nodes carry what the kind needs (`app-dev`, `app-prod`, `app-prod-2`, optional `+ingress`, `router`, `database`), joined by WireGuard. Topologies are versioned in `swamp/proof/topologies/`.
5. Port in your beast worktree (Build it, below). Each legacy phase becomes one script-file step. A phase-order change needs a written reason in the PR body, approved by a sub-orchestrator; lane 26 lists it under "Documented F9 deviations" in `docs/swamp/porting-retros.md`.
6. Run the whole path in the topology as often as you need: request, Gateway admission and intent, Swamp, Nodes and terminal projection. Read full stderr and per-step timings. Fix Gateway and Swamp bugs alike.
7. When the parity tests pass within budget (F8), the final run writes the receipt (`bin/swamp-proof receipt` in B's tool); put it in the PR. The topology differs from production: test repositories, the Orbit CA, no production data or scale. Its Swamp worker enrolls as `orbit-node-209`, so workflows keep `target: orbit-node-209` unchanged. Run `bin/swamp-proof down`; idle topologies die after 60 minutes (F11). A topology fault fixes the topology in the same PR and bumps its version (F12).
8. Lane 26 reviews and records lessons; the sub-orchestrator merges; one short live check after the load confirms it landed. It is not a second proof.

Never load `swamp/` into production serve or log in to 209 for a port. If Swamp has a real gap, stop and send it to your sub-orchestrator with evidence. Do not build around it.

## Build it

Copy the workflow and Gateway declaration from the [template](../../../docs/swamp/porting.md#fill-the-workflow) and fill every `REPLACE_*` token. `REPLACE_F1_RUN` stays a plain script invocation until lane 16 ships F1.

- **Inputs:** the full non-secret intent under `intent`, and names-only `{vault, key}` descriptors under `execution_secrets`. Secrets are never inputs. Encode empty maps as objects, not `[]` (#2273). Never pass a Gateway macro or alias to a shell; expand it through the Gateway supplier before the step runs (#2304).
- **Vaults:** list every vault the workflow reads, in parents and children. `vaults: []` when there is none, by convention.
- **Placement:** every step runs on `target: orbit-node-209`. Reach another Node with official `@swamp/ssh` from 209 using the intent's `identity_file`, stored `host_keys` and `sudo: true`. Use one selector in the effective placement: `target` only, with no `labels` at any inherited scope. Copy placement from `firewall.inspect`, not `node.bootstrap_probe`.
- **Scripts:** one script file per action group, shipped through the behavior manifest `additionalFiles` and run as a placed `command/shell` step on 209, or through `@swamp/ssh` `exec` with the body in argv for another Node; `script` only when the script reads no input or secret. Split only at a resume point, a Node change or a guard. TypeScript only shapes typed inputs and outputs.
- **Secrets in steps:** one whole `${{ vault.get(...) }}` expression per variable in `task.inputs.env`, or in `@swamp/ssh` `exec` `stdin`. Hand it to tools on stdin or in a 0600 file, never argv. For a script on another Node that reads a secret or input, use `exec` with `argv: [timeout, N, python3, -I, -c, <asset body>, <public args>]` and the secret on `stdin`; `env` uses `SendEnv`, so do not rely on it. A Node never returns a secret to the Gateway or prints one as step output. Generate Gateway-owned secrets, such as `APP_KEY`, at admission; Node-held keys stay on the Node (decision 3). Never rewrite a shipped script's source to inject input.
- **Few steps:** step count dominates run time. Op 6639 took 957 s for 4.6 s of SSH work. Until the extensions lane reports the cause, one script per Node per phase does the reads, precondition checks, writes and result JSON. Use a typed TypeScript step only for a result the script cannot print, and a separate check step only for another Node's read. Each extra step needs a named Node change or guard in the PR. Do not split for resume: pinned e459 loses inline SSH `globalArgs` when it resumes a failed run. Never wrap an SSH call in TypeScript envelope and decode steps (#2261 reached 66 steps). A typed result step returns `{stdout}` itself; add no `printf` step after it. Resolve assets once, outside `forEach`.
- **Refusals first:** the action script checks preconditions before its first write and prints a public `error_code`. It keeps a bounded, redacted tail of child output; a runner that discards it makes every failure unreadable (#2304).
- **Control flow:** `dependsOn` with `condition`, `guard`, `allowFailure`, `concurrency`, per-kind `queueTimeout` (F8), native resume. No loops, sleeps, lock files or receipts, except a bounded poll inside a phase script for external state (VM started, image ready, DNS visible): fixed interval, coreutils `timeout <phase budget>`, nonzero exit with a readable F1 error on a bad state or timeout, interval and budget stated in the PR, counted toward the kind budget. Never poll to retry a failed action or to wait on Gateway or Orbit state. The shape gate still flags `sleep` and polling loops; until lane 0b accepts this bounded form, such a PR cannot pass the gate. Add no baseline row. Swamp has no step retry key. Never read outputs of a failed or skipped step.
- **Fan-out:** `forEach.in` never reads outputs of a step in the same job; official e459 expands it before they exist. Read `inputs`, literals, or outputs of an earlier job this job `dependsOn`. Otherwise pass the list as inputs to a `type: workflow` child. Give each item its own `behaviorName`. Keep the legacy failure scope from `6291bb036`, not from an earlier Swamp port: legacy sweep stopped a host's work at its first failure. Reproduce such a scope with one script per host, or one child per host on `allowFailure`, so a failure stops that host and other hosts continue. Find the legacy feature tests with `git show 6291bb036:<test path>` before calling parity unverifiable. Never put `data.query` or another unbounded data read in step inputs; read one stable record with `data.latest` (B7, #2310).
- **Errors (F1, pending, lane 16):** shipped scripts will run through the shared F1 wrapper, and the shared projector will report the failed step and the last 4 KB of redacted stderr for any failed step. Until it lands, add no family wrapper.
- **Result:** on e459 a step that exits nonzero keeps no outputs. The action step sets `ignoreExitCode: true`, prints the public JSON and is the `terminal_result`. An `accepted` assert on `steps.action.outputs.exitCode == 0` fails the run. With several effect steps, a `result` step on `condition: always` maps the first failed step to an `error_code`, reading `"x" in steps && steps.x.status`, never outputs.
- **Time budget (F8):** measure the kind's p95 from native history and set a run budget from it. PLAN sets `instance.create` at under 10 s with a 60 s budget; that is policy, not proof. Every step gets an explicit `queueTimeout`: set it on the workflow, never the serve's 600 s default (guide rule 6). A job or step may override it; the proof file's `queue_timeout_seconds` equals the workflow value. Each phase script runs under coreutils `timeout <phase budget>`, so phases fit the budget. Serve `max-run-duration` is the hard ceiling, set from the longest legitimate kind (extensions lane); the Gateway marks `operation.timed_out` at the kind budget (lane 16). Add no family timer.
- **Gateway:** validate and record immutable intent at admission, start with shared `StartSwampRun`, push changed secrets with `SwampCommandStep::executionCopy`, project through the family projector. No callbacks, holds, pollers or retries.
- **Delete** the old executor, its tests, its embedded scripts, its callbacks, and the CLI, SDK and docs paths that served only it, in the same PR. Do not touch `apps/agent`. Remove the kind's rows from `swamp/config/swamp-shape-baseline.json`.

## Check it

- `swamp workflow validate` on the pinned runtime for every changed workflow.
- The family's native test under `swamp/` and `deno test` for changed behaviors; shellcheck or ruff for every script.
- Parity tests: port the legacy feature tests so each legacy case gives the same public result natively.
- Gateway Pest tests for admission, identity, inputs envelope and projection, run with a file path or `--filter`.
- The shape gate and placement lint.
- Report Orbit app and test net lines and Swamp lines separately.
- State the measured p95, its sample, the run budget and `queueTimeout` in the PR body. Every workflow, children included, sets an explicit `queueTimeout`.
- Receipt (F13): a kind whose behavior changes carries a `bin/swamp-proof receipt` from its topology run. Any change under `swamp/workflows/`, to a grant or to a declaration counts as a behavior change. Only deletion, docs and test PRs fix forward. A live-outage fix may merge without a receipt if it says so; a live check follows the load.
- Proof file: `swamp/proof/<kind>.json` (`swamp/proof/README.md`, or `designs/swamp-proof-fixture-v0.md` on beast until it lands) holds the `prepare` and `request` CLI calls, a partial expected `envelope`, budgets, F9 phases, parity tests, `queue_timeout_seconds` and default topology. No secret appears in the file or in argv; a kind gets secrets through the topology Gateway's normal path.

## Review a kind PR

Lane 26 reviews every kind PR against the [PR and review checklist](../../../docs/swamp/porting.md#pr-and-review-checklist) and the [anti-patterns](../../../docs/swamp/porting.md#anti-patterns). A kind PR fails review without a measured p95 and a run budget, without a topology receipt when it changes behavior, with more than about two native steps per legacy call and no written reason, with a redesigned legacy sequence and no written reason, with a `forEach` over same-job step outputs, or with an extra step whose Node change or guard it does not name. Report PASS, or each deviation as `file:line`, the rule broken, and the native replacement. Keep source conformance separate from CI, served-source uptake and live evidence.

## Improve this skill

After every merged PR that touches `swamp/`, run a short retro: what was slow, what the reviewer or conformance audit flagged, what broke live. For each proof receipt, record what the proof caught and whether the kind or the topology was at fault in the Proof receipts table of `docs/swamp/porting-retros.md`, and fold topology lessons into the topology. Fold each lesson into the reference in a PR the same hour, add one row to its `## Changelog` with the PR number, op id or other source, and one row per PR to `docs/swamp/porting-retros.md`. When a lesson comes from a conformance finding, cite its canonical ID and update that row instead of adding a duplicate.
