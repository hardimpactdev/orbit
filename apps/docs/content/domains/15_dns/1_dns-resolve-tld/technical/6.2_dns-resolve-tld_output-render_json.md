# JSON Renderer: `orbit dns:resolve-tld [tld] [target]`

[Back to `dns:resolve-tld` technical contract.](1_dns-resolve-tld.md)

This page describes the JSON-rendered output for `dns:resolve-tld`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even when
the process has a TTY. `--json` does not imply destructive consent for
`--reset`; non-interactive reset still requires `--force`.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Gateway-node rejections, validation failures, destructive-consent failures,
unsupported-platform failures, resolver write failures, and resolver refresh
failures must all use this envelope.

## Success Shape

```json
{
  "success": {
    "data": {
      "dns": {
        "tld": "test",
        "target": "10.6.0.7",
        "action": "resolve",
        "status": "resolved",
        "changed": true,
        "source": "local_resolver",
        "resolver_backend": "dnsmasq"
      }
    },
    "meta": []
  }
}
```

Reset success uses the same shape with `action: "reset"`, `target: null`, and
`status: "reset"` or `status: "already_absent"`.

Already-converged resolve uses `status: "already_resolved"` and
`changed: false`.

| Field | Type | Meaning |
| --- | --- | --- |
| `dns.tld` | string | Development TLD without a leading dot. |
| `dns.target` | string \| null | Target IP address for resolve; `null` for reset. |
| `dns.action` | string | Requested action. |
| `dns.status` | string | Result status. |
| `dns.changed` | boolean | Whether local resolver state changed. |
| `dns.source` | string | Always `local_resolver`. |
| `dns.resolver_backend` | string | Platform resolver backend used for the local change. |

## Error Shapes

### Not supported on gateway

```json
{
  "error": {
    "code": "validation_failed",
    "message": "This command is not supported on gateway nodes.",
    "meta": {
      "reason": "not_supported_on_gateway"
    }
  }
}
```

### Validation failed

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Target must be an IPv4 or IPv6 address.",
    "meta": {
      "field": "target",
      "reason": "invalid"
    }
  }
}
```

### Destructive consent missing

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Reset requires --force in non-interactive mode.",
    "meta": {
      "field": "force",
      "reason": "destructive_consent_required"
    }
  }
}
```

### Unsupported platform

```json
{
  "error": {
    "code": "node.unsupported_platform",
    "message": "This platform does not support automatic local DNS resolver configuration.",
    "meta": {
      "platform": "linux-unknown"
    }
  }
}
```

### Resolver write failed

```json
{
  "error": {
    "code": "local_resolver_write_failed",
    "message": "Failed to update local DNS resolver configuration.",
    "meta": {
      "tld": "test",
      "resolver_backend": "dnsmasq"
    }
  }
}
```

### Resolver refresh failed

```json
{
  "error": {
    "code": "local_resolver_refresh_failed",
    "message": "Local DNS resolver configuration changed, but the resolver could not be refreshed.",
    "data": {
      "dns": {
        "tld": "test",
        "target": "10.6.0.7",
        "action": "resolve",
        "status": "refresh_failed",
        "changed": true,
        "source": "local_resolver",
        "resolver_backend": "dnsmasq"
      }
    },
    "meta": {
      "tld": "test",
      "resolver_backend": "dnsmasq"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `dns.action` | `resolve`, `reset` |
| `dns.status` | `resolved`, `already_resolved`, `reset`, `already_absent`, `refresh_failed` |
| `dns.changed` | `true`, `false` |
| `dns.source` | `local_resolver` |
| `error.meta.reason` | `missing`, `invalid`, `forbidden`, `unsupported_value`, `unreadable`, `destructive_consent_required`, `not_supported_on_gateway` |
| `error.code` | `validation_failed`, `node.unsupported_platform`, `local_resolver_write_failed`, `local_resolver_refresh_failed` |

The `error.code` values listed here are exhaustive for `dns:resolve-tld`. Add a
new value to this renderer contract before implementing another JSON failure
code.

Partial resolver changes after refresh failure are diagnostic data and belong
under `error.data`, not `error.meta`.
