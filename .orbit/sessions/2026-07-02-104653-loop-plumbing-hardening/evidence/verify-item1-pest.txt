This directory\\n\n  is already gitignored.\\n\n- Name the branch and worktree directory after the feature or fix in kebab-case\\n\n  (e.g. `.worktrees/app-node-security-foundations`).\\n\n- Do all editing, test runs, and verification from inside the worktree path.\\n\n\\n\nRun this from the main checkout:\\n\n\\n\n```bash\\n\nbin/orbit-prepare-worktree <branch-name>\\n\n```\\n\n\\n\nUse `--base=<ref>` when the todo must start from a branch other than `main`.\\n\nDo not use `--with-e2e` for feature work. CLI command changes require focused\\n\nPest coverage plus retained topology proof when topology behavior is in scope.\\n\nThe script creates or reuses `.worktrees/<branch-name>/`, installs\\n\ndependencies, prepares Laravel app state, links `.env.e2e` when available, and\\n\nruns `composer test` unless `--skip-tests` is explicitly passed.\\n\n\\n\nIf preparation fails, leave the worktree in place for inspection and report the\\n\nfailing step instead of dispatching implementation onto a broken checkout.\\n\n\\n\n## E2E Readiness And Resource Pool\\n\n\\n\nThis section is for reading shared E2E provider state and existing artifacts\\n\nonly. Agents must not run `composer test:e2e*` commands. Normal feature\\n\ncompletion uses retained topology proof instead of prepared E2E.\\n\n\\n\nThe E2E provider pools are shared across every Orbit worktree on this machine.\\n\nWorktrees symlink `.env.e2e` back to the main checkout, so provider selection,\\n\nrunner capacity, lease directories, and host pools are shared state. Read the\\n\nactive providers from `.env.e2e`, not from hard-coded hostnames: Docker feature\\n\ntests use `ORBIT_E2E_DOCKER_TEST_RUNNERS`, and Incus preparation/topology work\\n\nuses the configured Incus host variables such as `ORBIT_E2E_INCUS_HOSTS` and\\n\n`ORBIT_E2E_INCUS_HOST_SLOTS`.\\n\n\\n\nActive `orbit-e2e` containers, networks, volumes, VMs, or lease files on those\\n\nconfigured providers are normal while other features run in other worktrees.\\n\nResource existence or container count alone is not a stale-resource signal.\\n\n\\n\nWhen inspecting a user-run E2E lane in a worktree:\\n\n\\n\n1. `composer e2e:preflight` \u2014 verifies the configured Incus host is\\n\n   reachable. This is a manual diagnostic command; do not run it as an agent\\n\n   unless the task is retained topology setup rather than E2E testing.\\n\n\\n\n2. Treat the provider pool as a blocking lease pool. If the user reports a long\\n\n   wait at startup, it usually means every configured slot is currently leased\\n\n   by another worktree. Do not reap merely because resources exist on a\\n\n   provider.\\n\n\\n\n3. Use host diagnostics only after a wait exceeds\\n\n   `ORBIT_E2E_SLOT_WAIT_SECONDS`, or when recovering from an interrupted run.\\n\n   Derive Docker hosts from `.env.e2e`:\\n\n\\n\n   ```bash\\n\n   set -a; [ ! -f .env.e2e ] || . ./.env.e2e; set +a\\n\n\\n\n   printf '%s\\n' \"${ORBIT_E2E_DOCKER_TEST_RUNNERS:-}\" \\\\n\n     | tr ',' '\\n' \\\\n\n     | while IFS=: read -r host slots container_cap; do\\n\n         [ -n \"$host\" ] || continue\\n\n\\n\n         if [ \"$host\" = \"local\" ]; then\\n\n           docker ps \\\\n\n             --filter \"name=orbit-e2e\" \\\\n\n             --format '{{.Names}}\\t{{.Status}}'\\n\n         else\\n\n           DOCKER_HOST=\"ssh://$host\" docker ps \\\\n\n             --filter \"name=orbit-e2e\" \\\\n\n             --format '{{.Names}}\\t{{.Status}}'\\n\n         fi\\n\n       done\\n\n   ```\\n\n\\n\n   Interpret output as context only. The resources may belong to live runs from\\n\n   other worktrees.\\n\n\\n\n4. If the shared pool is busy, report that the user-run command can wait or\\n\n   reduce only that command's temporary demand. For Docker, the user can pass a\\n\n   smaller `ORBIT_E2E_DOCKER_TEST_RUNNERS` value or\\n\n   `ORBIT_E2E_PARALLEL_PROCESSES=<n>` in the command environment. Do not commit\\n\n   or permanently edit `.env.e2e` just to make one worktree smaller; that file\\n\n   controls every worktree.\\n\n\\n\n5. Reaping is destructive recovery, not pre-run hygiene. Use the dry run only\\n\n   as inventory, and remember that its output can include legitimate resources\\n\n   from other worktrees:\\n\n\\n\n   ```bash\\n\n   composer e2e:reap-docker\\n\n   composer e2e:reap-incus\\n\n   ```\\n\n\\n\n   Run with `--force` only after confirming the resources belong to an\\n\n   interrupted run you own, or after confirming no live E2E process can be using\\n\n   the configured providers:\\n\n\\n\n   ```bash\\n\n   composer e2e:reap-docker -- --force\\n\n   ```\\n\n\\n\n   Do not use `--older-than=0m` on shared providers unless intentionally\\n\n   deleting retained or abandoned resources you own.\\n\n\\n\nThe slot pool is a blocking lease pool: workers that cannot lease a slot\\n\nwait, they do not fail loudly. A long hang at the start of `composer\\n\ntest:e2e:docker` or `composer test:e2e:incus` usually means the configured\\n\npool is fully booked by another worktree, not a real failure.\\n\n\\n\n## Retained Incus Inspection Gate\\n\n\\n\nRetained Incus is the mandatory hands-on verification step whenever the change\\n\ntouches real VM/node behavior: OS package installs, role baselines, doctor\\n\nrestore, tool repair, SSH/sudo, WireGuard, systemd, host mutation, gateway API\\n\nshims, source-mounted checkout behavior, or anything that previously failed\\n\nonly inside an Incus topology.\\n\n\\n\nAny feature that creates or changes a CLI command must also pass a retained\\n\ningress VM Solo-terminal gate before live/release-candidate deployment. This\\n\nincludes new commands, flags, options, arguments, human output, JSON schemas,\\n\nvalidation, prompts, command side effects, and command-family behavior.\\n\nCLI retained topology proof must run in a Solo terminal, not only through a\\n\ndetached host command or captured artifact. Keep that Solo terminal open\\n\nthrough feature completion and leave it available afterward. The preserved\\n\nterminal lets the user later validate the addressed CLI commands and their output.\\n\nThe retained topology may be reaped after feature completion, but the Solo\\n\nterminal stays preserved as the validation anchor.\\n\n\\n\nFor CLI changes, use this ordering:\\n\n\\n\n1. Create or update focused Pest tests for the command contract.\\n\n2. Implement the smallest slice that makes the focused command behavior work.\\n\n3. Spawn or request a Solo terminal.\\n\n4. Acquire a retained Incus topology with the relevant source-mounted VM.\\n\n5. Verify which Orbit launcher will be exercised. For source-mounted retained\\n\n   topology proof, run the command through the source checkout\\n\n   (`./apps/cli/orbit` from `/home/orbit/orbit-run`) or prove that\\n\n   `/usr/local/bin/orbit` resolves to that source checkout. For\\n\n   release-candidate or live-node proof, use the installed binary path being\\n\n   validated.\\n\n6. Open an interactive shell inside the relevant retained VM, usually the\\n\n   ingress or operator VM, before running the changed command. The Solo\\n\n   terminal should land at `/home/orbit/orbit-run` inside the VM so the user can\\n\n   watch progress, spinners, blinking indicators, prompts, and streaming output\\n\n   while the command runs.\\n\n7. Run or request CLI reviewer PTY frame analysis from the same runtime context\\n\n   before asking the user to inspect human UX/output. For retained Incus proof,\\n\n   prefer running the capture script inside the Solo terminal shell attached to\\n\n   the target VM. The reviewer inspects `summary.txt`, `chunks.jsonl`, and\\n\n   `transcript.txt` for cadence, liveness, skipped frames, wrapping, ANSI\\n\n   framing, and final shape.\\n\n8. Prove the observed human output, JSON output, prompts, failure paths, and\\n\n   side effects that changed.\\n\n9. Give the user a chance to inspect and confirm the VM-observed CLI behavior\\n\n    only after the reviewer has summarized the PTY confidence basis or exact\\n\n    remaining mismatch.\\n\n10. Then run broader quality or release-candidate flow when applicable.\\n\n\\n\nDo not spend the live topology or release-candidate path on a CLI change before\\n\nthis retained VM proof and user verification point. Do not treat retained Incus\\n\nas optional \"extra confidence\" for those changes. The retained check is the\\n\noperator-facing proof gate for feature completion.\\n\n\\n\nAcquire the topology from the implementation worktree and source-mount only the\\n\nroles that need the current checkout:\\n\n\\n\n```bash\\n\ncomposer e2e:incus -- --start --topology=<kind> --checkout-roles=<roles> --json\\n\n```\\n\n\\n\nFor CLI command changes, use the topology that creates a dedicated ingress VM.\\n\nSource-mount the ingress role, plus only the other roles whose current checkout\\n\nis needed for the command under test:\\n\n\\n\n```bash\\n\ncomposer e2e:incus -- --start \\\\n\n  --topology=operator_gateway_app-dev_app-prod_ingress \\\\n\n  --checkout-roles=ingress \\\\n\n  --json\\n\n```\\n\n\\n\nIdentify the target instance from the retained topology output or manifest, then\\n\nopen that retained VM in a Solo terminal and stop at a VM shell prompt before\\n\nstarting the command. Run the exact changed command path from\\n\n`/home/orbit/orbit-run`, covering human and `--json` output when either contract\\n\nis affected, plus the relevant failure or prompt path. Record the launcher proof\\n\n(`command -v orbit`, `readlink -f`, or the explicit `./apps/cli/orbit` source\\n\nlauncher command) next to the observed output.\\n\n\\n\nA host-wrapped one-shot command such as\\n\n`ssh <host> 'incus exec <instance> -- ... <orbit command>'` is useful for\\n\nmachine transcripts, JSON capture, or fallback diagnosis, but it does not\\n\nsatisfy the retained Solo-terminal inspection gate for human rendering. The\\n\ngate is only satisfied when the Solo terminal is attached inside the VM before\\n\nthe human command starts. If the current Solo environment cannot open that\\n\ninteractive VM shell, use the configured Incus host with `incus exec` as a\\n\nfallback and report that the user-inspection gate was downgraded.\\n\n\\n\nInspect through the configured Incus host from `.env.e2e`; do not assume a\\n\nhost name unless the environment says so. Typical Beast-backed inspection looks\\n\nlike:\\n\n\\n\n```bash\\n\nssh beast 'incus list --format csv -c ns | grep <retained-id> || true'\\n\nssh -tt beast 'incus exec <instance> -- sudo -iu orbit bash -lc \"cd /home/orbit/orbit-run && exec bash -i\"'\\n\n# then run inside the VM shell:\\n\n./apps/cli/orbit <command>\\n\nssh beast 'incus exec <instance> -- bash -lc \"<host command such as gh --version>\"'\\n\n```\\n\n\\n\nFor source-mounted Incus topologies, `/home/orbit/orbit` is the synced source\\n\nmount and `/home/orbit/orbit-run` is the VM-local runtime mirror. Run Orbit\\n\ncommands from `/home/orbit/orbit-run` unless explicitly testing the source\\n\nmount itself. After local worktree edits, refresh a retained topology with:\\n\n\\n\n```bash\\n\ncomposer e2e:incus -- --sync --id=<id>\\n\n```\\n\n\\n\nThat sync is one-way from the implementation worktree to the runner-host source\\n\nmount and then to each recorded VM runtime mirror. It transfers filesystem\\n\ndeltas for included files to the runner host, not only Git-dirty files, and then\\n\nrefreshes the VM-local runtime mirrors. Keep the implementation worktree as the\\n\nsource of truth. VM-side edits in `/home/orbit/orbit-run` are scratch work and\\n\nare overwritten by the next sync; VM-side edits in `/home/orbit/orbit` mutate\\n\nthe runner-host copy, not the local worktree.\\n\n\\n\n`--sync` refreshes files on disk but does not reload the long-running gateway\\n\nAPI container. After a sync, the gateway lease container keeps serving the\\n\npre-sync code and returns HTTP 500 on every gateway call (including paths the\\n\nchange never touched, e.g. single-node `doctor`), which reads as a product\\n\nregression but is not one. Restart the gateway lease containers on the gateway\\n\nVM before re-verifying:\\n\n\\n\n```bash\\n\nssh <incus-host> 'incus exec <gateway-instance> -- bash -lc \\\\n\n  \"docker restart orbit-gateway-e2e-topology-lease-http orbit-gateway-e2e-topology-lease-tls\"'\\n\n```\\n\n\\n\nThen re-run the changed command. A 500 on an unrelated gateway path right after\\n\n`--sync` is a stale-container signal, not a code defect \u2014 restart first, then\\n\nclassify.\\n\n\\n\nRecord the retained topology id, topology kind, checkout roles, inspected\\n\ninstances, Solo terminal or fallback session, commands run, and observed result\\n\nin the Solo report. If you mutate state for a focused check, isolate unrelated\\n\nprepared-state drift first and say what was isolated.\\n\n\\n\nAfter feature completion, release and verify retained topology cleanup:\\n\n\\n\n```bash\\n\ncomposer e2e:incus -- --stop --id=<id> --json\\n\nssh <incus-host> 'incus list --format csv -c ns | grep <id> || true'\\n\n```\\n\n\\n\nIf `--stop` misses owned instances because the retained manifest is incomplete,\\n\ndelete only the owned leftovers by exact instance name, verify the grep is\\n\nempty, and report the cleanup anomaly. Do not close or archive the Solo terminal\\n\nas part of topology cleanup; preserve it for later user validation of the\\n\ncommand address/output transcript.\\n\n\\n\n## Workflow\\n\n\\n\n1.
