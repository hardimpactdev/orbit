# instance:show verification cases

`instance:show` reads Orbit's records and has no chart. The proof runs the built CLI against a fresh nested topology with development and production Instances, Routes with and without web roots, deploy steps, Processes, automatic deployment in each state, and an Instance being removed, and compares the output with the Gateway records. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Development Instance | Show an active development Instance, and the development `default` Instance. | The detail is titled `Instance: <name>` and shows every field of the page with the recorded values. `Project` shows the slug and `Node` the name. No deploy steps, Production user or Production home appear. `default` shows `Auto deploy` as `on, without a merge check`. |
| Production Instance | Show a production Instance with deploy steps in both phases, and one with none. | The detail adds Deployment branch, Production user, Production home and Auto deploy. The deploy steps table lists Name, Phase, Command and Timeout in phase and placement order, or says `No deploy steps found.`. |
| Automatic deployment | Show a production Instance with auto deploy off, on without a merge check, on with a merge check, with a tick result, paused, and with an error. | `Auto deploy` reads `off`, `on, without a merge check` or `on, after <merge check> passes`. With `off`, no state, pause or error line appears. While it is on, the state shows the result and 12 characters of the commit, the pause shows its reason, the deployment and the resume command until it is resumed, and the error its code. |
| Routes | An Instance with its own Route and two web-root Routes, one without a web root recorded. | The Routes table lists each Route by ID order with its domain, web root or `Instance root`, and status. JSON has `route` for its own Route and all of them under `routes`. An Instance without a Route shows no table. |
| SSR port | An Instance with and without an assigned SSR port. | `SSR port` shows the number or `—`, and JSON has `ssr_port` as a number or null. |
| Removal | An Instance being removed normally, one removed with force, and one whose removal failed. | The detail shows Removal mode, Removal progress, Removal step, Removal failed step and Removal error code, with `—` for a missing one. JSON has the `removal` object. |
| Processes | An Instance with Processes in each state, and one without. | The table lists ID, Name, Runtime, Desired, Runtime status and Status. The empty case says `No Processes.`. |
| Selector | In a terminal, press Enter on a Process, Escape, and Ctrl-C. Then use a terminal too narrow for the selector, and run it piped to a file. | Enter prints that Process's log tail and the command ends with `process:logs`'s exit status, also when the read fails. Escape and Ctrl-C end with `input.cancelled` and exit 1. The narrow terminal gets the table as labeled records. The piped output has the table and no escape codes. Fails today: Escape and Ctrl-C exit 0, and a narrow terminal exits 0 with no output. |
| Missing values | An Instance without a branch, a Vite port, a root override or a URL. | Each missing value shows `—`. JSON keeps its null. |
| Records only | Make the Node unreachable over SSH, and show without pressing Enter. | The command succeeds and sends nothing to any Node. Pressing Enter on a Process reads its log over SSH and fails with that command's error. |
| Missing input | In a terminal, run the command with no argument and cancel the list. Then run it noninteractively and with `--json`. | The terminal lists Instances by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `instance.id_invalid`, with no request. Fails today: the Instance is a required argument, so every call without it is refused by the parser. |
| IDs only | An Instance by name, the ID `0`, the ID `-1` passed after `--`, and `abc`. | `instance.id_invalid`, with no request. Fails today: `-1` without `--` is read as an option and gives a parser error. |
| Unknown and access | An ID that does not exist, and a caller without a grant to the Instance's Node. | `http.404` and `node_access.required`. Nothing is shown. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail and tables at the wide width and labeled records at the narrow one, with no column lost. The piped output has no animation or escape codes. With `--json`, stdout holds only the JSON, without the Processes. |
