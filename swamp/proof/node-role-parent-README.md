## Analytics ClickHouse parity gap

Analytics has no native contribution in this draft. Its retained `configureRoleClickhouse` call only publishes the host files; `analyticsStorage` discards the returned `changed` fact. That retained path does not install the Process mounts, converge/replace its container or restart it after a file-only change. Keeping the worker route does not establish parity for this phase. Its per-Node placement remains required; Analytics must not be reported as migrated or retirement-ready.

At the F9 baseline, [NativeAnalyticsClickhouseConfigurationManager::converge](https://github.com/hardimpactdev/orbit/blob/6291bb036a6db5df372d3561abe959d0ef44612d/apps/gateway/app/Infrastructure/Analytics/NativeAnalyticsClickhouseConfigurationManager.php) refuses conflicting operator mounts before host writes, publishes the four fixed files on the ClickHouse Process owner, then rechecks mounts under the Process runtime lease. It appends only missing read-only mounts while preserving the remaining runtime configuration and converges the Process to replace its container. With no missing mounts, a file change or failed Process still requires convergence; it then restarts only when desired_state is running. No change on a healthy Process makes no runtime call. It preserves an operator-stopped Process, marks runtime failure on the Process, and allows a later convergence to recover it.

The four sources under `/etc/orbit/analytics/clickhouse/` map read-only to the same relative paths under `/etc/clickhouse-server/`: `config.d/logs.xml`, `config.d/ipv4-only.xml`, `config.d/low-resources.xml` and `users.d/default-profile-low-resources-overrides.xml`. The future native contribution must capture that Process configuration at admission, execute the mount/container lifecycle on its actual owner through the canonical Process contribution, and project proven terminal facts. It must not add a Gateway step callback or fork Process runtime policy.

[Legacy manager tests](https://github.com/hardimpactdev/orbit/blob/6291bb036a6db5df372d3561abe959d0ef44612d/apps/gateway/tests/Feature/Infrastructure/Analytics/NativeAnalyticsClickhouseConfigurationManagerTest.php) specify missing and partial mounts, preserved unrelated volumes, unchanged no-op, file-only restart, operator-stopped state, conflict before writes, publication refusal, and failed replacement followed by recovery. [AnalyticsRoleBaselineTest](https://github.com/hardimpactdev/orbit/blob/6291bb036a6db5df372d3561abe959d0ef44612d/apps/gateway/tests/Feature/Infrastructure/Analytics/AnalyticsRoleBaselineTest.php) requires ClickHouse completion before the Analytics firewall, Plausible startup and dashboard publication; a ClickHouse failure stops those later phases. These are open parity requirements, not tests claimed to pass on a native Analytics contribution.
