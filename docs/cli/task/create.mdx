---
title: "orbit task:create"
sidebarTitle: "task:create"
description: "Create a task. It starts in `backlog` unless you ask for `todo`."
---

```bash
orbit task:create [title] [--project=ID | --parent=ID] [--deliverables=FILE] [--brief=TEXT] [--status=STATUS] [--orchestration=MODE] [--subtasks=FILE] [--preview] [--current-recipe] [--review=MODE] [--implementer-provider=NAME] [--implementer-model=MODEL] [--implementer-effort=LEVEL] [--reviewer-provider=NAME] [--reviewer-model=MODEL] [--reviewer-effort=LEVEL] [--pr-mode=MODE] [--issue=NUMBER] [--json]
```

| Input | Default | Meaning |
| --- | --- | --- |
| `title` | prompt | Short name of the feature. |
| `--project=ID` | prompt | Numeric Project ID. In a terminal, the CLI lists Projects to select from. |
| `--brief=TEXT` | prompt | Goal and acceptance. Pass a file with `--brief="$(cat brief.md)"`. |
| `--status=STATUS` | `backlog` | `backlog` or `todo`. `todo` follows the rule of [a task that leaves backlog](/reference/tasks#tasks-and-subtasks): its own `--deliverables`, or at least two `--subtasks`, each with deliverables. It leaves the task ready for `task:start`. |
| `--deliverables=FILE` | none | JSON file with the deliverables of a [task with no subtask](/reference/tasks#a-task-with-no-subtask), or of the subtask that `--parent` appends. With `--subtasks`, the Gateway answers `validation.failed`. |
| `--subtasks=FILE` | none | JSON file with an ordered array of at most 50 objects, each with a string `title` and `brief` and an optional `deliverables` array. |
| `--orchestration=MODE` | `external` | Swamp executes task groups. The only supported mode is `external`; any other value returns `task.orchestration_invalid`. |
| `--preview` | off | Keep the task's sandbox running during review. See [Request a preview](/reference/compute-drivers#request-a-preview). |
| `--review=MODE` | `manual` | How the gate of the task pull request is passed. `manual`: Nick approves the exact head. `automatic`: its review rounds are removed, so the [gate check](/reference/tasks#gate-check) switches the group to manual mode when its pull request leaves draft. Any other value returns `tasks.review_invalid`. `task:show` returns the mode as `review`. |
| `--implementer-provider=NAME` | Project's, else Gateway's | The implementer's provider in a [task copy](/reference/tasks#copy-turn-agents): `claude` or `codex`. |
| `--implementer-model=MODEL` | Project's, else Gateway's | The implementer's model in a task copy, such as `claude-opus-5-5`. |
| `--implementer-effort=LEVEL` | Project's, else Gateway's | The implementer's effort in a task copy: `low`, `medium`, `high`, `xhigh` or `max`. |
| `--reviewer-provider=NAME` | Project's, else Gateway's | The reviewer's provider in a task copy. |
| `--reviewer-model=MODEL` | Project's, else Gateway's | The reviewer's model in a task copy. |
| `--reviewer-effort=LEVEL` | Project's, else Gateway's | The reviewer's effort in a task copy. |
| `--pr-mode=MODE` | the Project's, else the Gateway's | What Orbit does once the work of a task in a task copy is done. `review_before_pr`: it waits for `task:publish <task>`. `pr_when_done`: it opens a ready pull request by itself. Any other value returns `task.pr_mode_invalid`. `task:show` returns the mode as `pr_mode` with its source. See [Task group modes](/reference/tasks#task-group-modes). |
| `--issue=NUMBER` | none | The GitHub issue of the Project's repository that the task works on. The pull request of its task copy then closes it: Orbit adds `Closes #NUMBER` when the reviewer's body does not close it. A number from 1 up; anything else returns `task.issue_invalid`, and the API answers `validation.failed` on `issue`. `task:show` returns it as `issue`. See [Closes the issue](/reference/tasks#closes-the-issue). |
| `--current-recipe` | off | The task needs the current machine recipe. Its VM waits for the current recipe image and never starts from a fallback image. See [Image fallback](/reference/compute-drivers#image-fallback). |

```bash
orbit task:create "Add tasks CLI" --project=1 --brief="$(cat brief.md)"
orbit task:create "Add tasks CLI" --project=1 --brief="$(cat brief.md)" --deliverables=deliverables.json --status=todo
orbit task:create "Add tasks CLI" --project=1 --brief="$(cat brief.md)" --subtasks=subtasks.json --status=todo
```

Plan one group, and one pull request, for the whole feature. Build and prove the feature end to end in the copy before its pull request opens: [Build a feature in one copy](/reference/tasks#build-a-feature-in-one-copy).

The CLI does not prompt for the status, the deliverables, the subtasks, or the notification. After the Gateway answers, the CLI shows the task as `task:show` does: a task with no subtask shows its work's status and deliverables in place of the subtask table. A task created in `todo` waits for an explicit `task:start <id>`.

## Errors

| Error code | Meaning |
| --- | --- |
| `tasks.project_required`, `tasks.title_required`, `tasks.brief_required` | A `--json` or `-n` call omits a required input. |
| `task.project_invalid`, `task.title_invalid`, `task.brief_invalid`, `task.status_invalid` | A supplied value is outside the accepted form. |
| `task.subtasks_invalid` | The CLI cannot read the subtasks file, or its content is not an array of at most 50 entries with a valid title and brief and, when present, a `deliverables` array. |
| `task.deliverables_invalid` | The CLI cannot read the deliverables file, or its content is not a list of deliverables. Nothing is sent. |
| `tasks.no_subtasks` | `--status=todo` without subtasks or deliverables. Pass `--deliverables`, or at least two subtasks with deliverables. |
| `tasks.one_subtask` | `--status=todo` with exactly one subtask, before its deliverables are checked. Add a second subtask, or fold the subtask into the task: pass its deliverables with `--deliverables` and no `--subtasks`. |
| `tasks.subtask_deliverables_missing` | `--status=todo` while a subtask has no deliverables, or with an empty `--deliverables` list. Give every subtask, or the task, deliverables. |
| `task.pr_mode_invalid` | `--pr-mode` is not `review_before_pr` or `pr_when_done`. The API answers `validation.failed` on `pr_mode`. |
| `task.issue_invalid` | `--issue` is not a number from 1 up. |
| `task.agent_invalid` | An agent option is empty. |
| `validation.failed` | A provider or effort the task copy does not offer, or a model that is no model name. |

Use `--parent=ID` in place of `--project=ID` to append a subtask. Its Project and workspace are inherited. A contradictory Project, a child parent, or a deeper hierarchy is refused. `--deliverables=FILE` gives the subtask its deliverables. Creating in Todo changes board state only. Use `task:start` to start the parent VM.

Child creation refuses the parent options `--status`, `--orchestration`, `--subtasks`, `--review`, `--pr-mode`, `--issue`, `--preview`, `--current-recipe` and the agent options.

A task that names no agent value takes each one from its Project's default, then from the Gateway; [copy turn agents](/reference/tasks#copy-turn-agents) describes the order and how a turn checks the values against the copy.
