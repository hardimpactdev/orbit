title: "orbit tool:remove"

description: "Remove one Tool and delete its record."
---

```bash
orbit tool:remove <tool> [--yes] [--idempotency-key=KEY] [--json]
```

| Option | Meaning |
| --- | --- |
| `--yes` | Skip the confirmation. A call without a terminal, or with `--json`, needs it. |

Without `--yes`, the command reads the Tool first. An unknown ID fails there with `http.404`. In a terminal, the command describes the effect and asks for confirmation. The default answer is No. Declining, Ctrl-C, or end of input exits with `input.cancelled` and changes nothing. Without a terminal, the command fails with `input.confirmation_required`.

For [protected host packages](/reference/tools#protected-packages), including role-owned PHP packages such as `php8.5-xml`, the command deletes only the Tool record and leaves the package installed. It also deletes only the record of a Tool whose package Orbit does not own, such as a first install that failed, was refused or was interrupted, whatever happened since. If an earlier attempt may have written its apt source, the removal runs on the Node to clean the source and leaves the package alone. When the last member's source cleanup is unconfirmed, the Tool stays `failed` with `tool.repository_failed`; run the command again. A removal that would repin surviving members of an unverified source is refused with `tool.repository_unverified`; update or converge a surviving member first. A failed removal keeps the Tool as `failed`. Run the same command again to retry. [Remove a Tool](/reference/tools#remove-a-tool) lists each outcome.

For a [host Conn Server](/reference/tools#host-conn-server-membership), remove withdraws the Tool from rollout without stopping the service. It does not change container Conn.
