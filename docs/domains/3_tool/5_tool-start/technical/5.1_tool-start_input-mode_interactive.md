# Interactive Input Mode: `orbit tool:start`

[Back to `tool-start` technical contract.](1_tool-start.md)

**Input mode:** Interactive.

## Selection

This contract applies only when the process is attached to a TTY and `--json` is not present.

## Prompts

If `[tool]` is missing, prompt with tool catalog search before target
resolution.

If no `--app`, `--node`, or local `node:default` resolves a target when the
command is running on the gateway, prompt for a visible active node before
the progress tree starts. On a client, missing explicit/default target
resolves self through the caller identity known by the gateway instead of
guessing from local rows.

Prompt cancellation fails with `validation_failed` before side effects.

## Target Resolution

Interactive mode uses the same strict target hierarchy as the main technical
contract:

1. `--app`.
2. `--node`.
3. Local `node:default`.
4. Self through gateway-known caller identity.
5. Interactive target selection when available.
6. `validation_failed` with `fields=["target"]`.

`--app` accepts an app slug, app domain, or `<slug>.<node-tld>` selector. When
`--app` and `--node` are both present, they must resolve to the same node.
