```bash
orbit task:check <task> --phase=baseline|handoff [--idempotency-key=KEY] [--json]
```

Run a baseline or handoff check through `tasks.check` on the Gateway. The group must use external orchestration and have a workspace. The subtask must be its current open subtask. A terminal prompts for missing inputs; machine mode requires them. The command follows waits for VM resume, workspace ownership, and the detached check. A failed check is a successful operation with `result.outcome=failed`; inspect the result, including deliverables and redacted output. A command deliverable the check never ran, such as after a failed Project check, reads `not_run` with the reason, not `failed`; it never passes. A passed handoff records its commit. In a task copy, a handoff check first brings in the current default branch head, as `task:sync` does, and merges it into the task branch when the merge is clean, so the checked tree is the tree that publish pushes. A conflict fails the check at once with `tasks.check_conflict` and the conflicting paths, and leaves the workspace as it was: merge by hand and check again. When the base cannot be read, the check runs on the tree as it is and the result says `base: unavailable`. The result names `default_commit` and `merged_default`. In a task copy, a baseline runs no setup steps, because the copied seed already ran them; it runs the Project check alone. The Orbit Project's check in a copy is `bin/task-check`; its parts, the `ci-policy` part among them, are in [the scoped task check](/reference/tasks#scoped-task-check). A task copy whose last completion failed answers HTTP 409 `tasks.copy_completion_failed` until a [retried completion](/cli/task/start#when-the-start-fails) succeeds. A copy that is not `active` yet answers `tasks.copy_not_ready`. Ctrl-C stops following. Use `operation:cancel` to stop the check, or `task:cancel` to end the group. See [Check an external group](/reference/tasks#check-an-external-group).

The agreed [hosted handoff CI prerequisite](/reference/tasks#check-an-external-group) adds `result.ci` to JSON output without changing these inputs or adding a caller-selected CI option. This is docs-first, not a runtime delivery claim: external review-and-merge admission remains unsupported. For a Project requiring CI, the operation also waits for its handoff push and hosted check on `result.commit`, the candidate HEAD; `result.head` is the earlier pre-commit snapshot. Baseline/no-policy returns `ci: null`. Waiting observation is not a usable passed candidate. Cancellation after push stops observation, not GitHub workflows, and retains check evidence. Reviewer and publish commands require the shared candidate eligibility rule, including passed CI from the owning successful operation when required.
