# Verification cases

A verification case proves one command behavior on the nested test fleet ([stage 3](/reference/command-development-pipeline#3-proof)). Cases are declarative YAML specs executed by one shared runner (`swamp/proof/runner/`).

## Trust boundary and preparation

The proof copy is the trust boundary: candidate code runs inside its disposable, credential-free, egress-restricted nested fleet. Every `runner.py batch`, `runner.py case`, and `runner.py setup` prepares the fleet before running cases, with no preparation caching between commands:

- Reads `apps/gateway/resources/agent/frozen-manifest.json` from the candidate checkout and installs the pinned observer with checksum verification on all three nested Nodes (`proof-gateway.yml`, `proof-observers.yml`).
- Restarts observers, discards stale receipts, and waits up to 18 checks (every 5 seconds) for the nested Gateway to record matching versions, digests, and fresh host facts.
- Enforces a 330-second hard preparation deadline (`timeout 330`) and a separate 120-second setup budget; failures stop cases as `infrastructure`.

## Outer machine and nested Nodes

The runner runs on the outer machine hosting `nested-gateway`, `nested-app-dev`, and `nested-app-prod` and drives them via local `incus exec`. It resolves its runtime paths from the process rather than hardcoded constants:

| Fact | Source |
| --- | --- |
| Checkout | Path of `runner.py` |
| User and home | `pwd.getpwuid(os.getuid())` (ignores `HOME`) |
| CLI home and CA | `~/.orbit` and `~/.orbit/nested-ca.pem` (ignores `ORBIT_HOME`) |
| Pinned Ansible tools | `/opt/orbit-shape-gate` ([pinned shape tools](/reference/development-containers#the-pinned-shape-tools)) |
| Terminal width | `COLUMNS=240` for noninteractive human output checks |

On every nested Node, the managed user is `orbit` (`/home/orbit`). When a case sets `cli.as` to another Node, the runner mounts the checkout there, copies `nested-ca.pem`, adds a CLI profile, and runs `php apps/cli/orbit` once before scheduling.

## The case file

Each command has one file at `swamp/proof/<family>/<command>.cases.yaml`, derived from its chart and CLI page. Missing files report `no cases file for COMMAND` ([Choose the cases](/reference/feature-flow#choose-the-cases)).

### File keys

Top-level keys configure target placement, shared fixtures, and exclusions:

| Key | Meaning |
| --- | --- |
| `command`, `chart` | Command name (for example `firewall:allow`) and chart path under `docs/cli`. |
| `target`, `sources` | Default target Node and probing source Nodes. |
| `spread`, `parallel` | Nodes cases rotate across (`spread`), and max concurrent cases (`1`–`16`, default `4`). |
| `baseline` | State captured before `act` for `unchanged` assertions. |
| `vars`, `fixtures` | Reusable argument lists (`"@name"`) and step lists (`use:`). |
| `uncovered`, `waits` | Uncovered paths/codes with reasons, and named deferrals (`waits`). |
| `cases` | List of case definitions. |

### Case keys

Each entry in `cases` defines one independent test (no cleanup needed because batches restore `base`):

| Key | Required | Meaning |
| --- | --- | --- |
| `id`, `batch`, `covers`, `summary` | Yes | Unique verdict ID, batch name from `swamp/proof/batches.yaml`, chart path IDs (`[]` for refusals), and one-line summary. |
| `setup` | No | Precondition steps; failures mark the case `unrun` (`precondition`). |
| `act`, `expect` | Yes (or `stages`) | Command under test and assertions (all `expect` steps run so one verdict lists every failure). |
| `stages` | No | Sequence of `act`/`expect` pairs for multi-round checks on one long Operation. |
| `variants` | No | Variable sets producing separate verdicts (`id[variant]`). |
| `node`, `exclusive` | No | Explicit target Node (overrides `spread`) and `exclusive: true` to force running alone. |
| `read_only` | No | `true` for no-op/refusal cases (no `setup`/`negative`, `request: none`, read steps only). |
| `fails_on_base`, `fails_today`, `negative` | No | Merge-base replay opt-in, temporary failing-today marker, and negative-test mutation block. |
| `timeout`, `waits` | No | Per-case timeout in seconds (default `180`) and deferral name from file `waits`. |

## Steps

The runner supports a closed set of steps (`swamp/proof/runner/spec.py`):

| Step | Phase | Purpose |
| --- | --- | --- |
| `use` | Any | Expand a named `fixture` with parameters. |
| `listener` | `setup` | Start TCP/UDP listeners on free ports (or consecutive `block` ranges). |
| `ufw_rule`, `ufw_delete` | `setup`, `negative` | Insert or delete test-owned UFW rules directly on a Node. |
| `fault`, `busy_node` | `setup`, `act` | Inject `ufw` command failures or hold a firewall write lock (cleaned up on case exit). |
| `agent_report`, `node_down` | `setup` | Wait for fresh agent facts, or stop agent + SSH until offline. |
| `node_access_remove`, `ipv6_addresses` | Batch setup | Remove a Node access grant, or assign IPv6 addresses on the proof bridge. |
| `node_fixture`, `recorded_request` | `setup`, `act` | Seed a recorded Node fixture or send a request through the candidate Gateway HTTP kernel. Runs alone. |
| `executor_key`, `executor_order`, `executor_publish`, `executor_round_trip`, `executor_power`, `executor_lost_result` | `setup`, `act`, `expect` | Provision the proof-only executor key (`executor_key`, runs alone) and exercise signed orders, WebSocket delivery, power ops, and lost-result recovery. |
| `cli` | `setup`, `act` | Run candidate `orbit` (`run`, `forms: [json, human]`, `tty`, `save`, `as`, and `expect`: `exit`, `status`, `code`, `skipped`, `steps`, `request: none`, `human`, `json`). |
| `probe`, `ufw`, `record`, `doctor`, `unchanged` | `expect` (or any for `probe`) | Check TCP/UDP reachability, numbered UFW rows, CLI list counts, Doctor drift, and baseline stability. |
| `service`, `package`, `ansible_changes` | `setup`, `act`, `expect` | Check or stop a systemd unit (`service`), verify an installed package (`package`), or assert zero Ansible changes from saved Operation step artifacts (`ansible_changes`). |

### Signed clone lifecycle

Run `orbit proof instance:destroy --group=ID --json` to prove the signed lane beside Swamp. The `clone_fixture` step builds the locked executor in the task copy and records its source tree and digest under `.orbit-artifacts/proof-clones`. It reuses a staged binary only when its source tree and digest match, and fetches a pinned Rust toolchain in a temporary directory on copies without Cargo. To build the artifact separately, run `python3 tools/swamp-proof-guest/clone_lifecycle.py` in the copy. The fixture refuses an already configured engine, starts the pinned NATS server and the built executor on the disposable nested fleet, enables the create and destroy routes there, and creates an unrouted default from a public repository.

The `clone_create` and `clone_destroy` steps use the public Gateway API. The destroy fixture adds an owned test volume and files at both power stores' real paths; it does not put the clone to sleep. One fault drops only the admitted destroy's saved JetStream receipt before restarting the Gateway consumer. A separate request with the original key checks HTTP admission replay, not transport redelivery. Another fault holds the test volume past container deletion, then retries with a new admission key. The `clone_compare` step uses the same request-to-terminal clock for clean signed and Swamp runs. The signed journal's `done` timestamp comes from before execution; the signed step's Gateway row measures dispatch to receipt application. The `clone_cleanup` step removes the disposable Project, Instances and temporary services and restores the nested Gateway settings.

Run `orbit proof route:destroy --group=ID --json` for the Route withdrawal. The `route_fixture` step is `clone_fixture` with the `route.destroy` route and the `route` family enabled. Its Project's web root is `src`. It also runs the executor with the `dns` family on the VPN Node, which is the nested Gateway, behind the bus guard that admits the Gateway's `orbit` user. The `route_create` step makes a clone's own Route, or with `web_root` another site of it, through the public API; `route:destroy` removes only such a site from a live Instance. The `route_destroy` step reads the Caddyfile, Caddy's admin API, the leaf folder, the DNS records and a DNS answer from the VPN Node, and a TLS request trusting the nested root. A sibling Route must keep all of them and its first HTTP status before, during and after. Its `receipt` fault drops the saved receipt of the Caddy withdrawal, `dns-conflict` adds an unrendered line to the live records, and `via: swamp` turns the `dns` family off. The `route_clone_destroy` step destroys a clone that owns a Route, and `route_compare` compares request-to-terminal times of a signed and a Swamp run.

During an open copy turn, use `python3 swamp/proof/runner/runner.py batch fresh-fleet --file swamp/proof/instance/destroy.cases.yaml --evidence PATH` from the same copy. It runs the same case on the copy's fleet without the outer command's batch reset. Keep the evidence directory for the source and artifact identities, Operation IDs, receipts and timing comparison.

## Batches and concurrency

`swamp/proof/batches.yaml` defines shared batches and their setup steps. Each batch starts from a `base` restore (45-second health bound); read-only cases with no setup run first on a fresh copy so the copy only resets after a mutating batch.

The runner assigns every case one lock class:

- **Alone (`alone`):** Uses `node_down`, `agent_report`, `node_access_remove`, `ipv6_addresses`, `node_fixture`, `recorded_request`, `executor_key`, cross-Node/unresolved CLI calls, or `exclusive: true`.
- **Reader (`reads its Node`):** Only read steps (`probe`, `ufw`, `record`, `doctor`, `unchanged`, `package`) and CLI calls expecting `request: none`. Multiple readers share a Node.
- **Writer (`alone on its Node`):** Any other case; runs exclusively on its placed Node while other Nodes run concurrently.

Noninteractive `node:converge` and `node:role:add` calls on copies with unshifted checkouts (`checkout.shift=false`) get a 600-second CLI limit (240 seconds otherwise). A CLI timeout fails the active case as `infrastructure` and marks remaining waiting cases in that batch `unrun` (`infrastructure`).

## The run

Each case emits one JSON verdict line (at most 1 KB, including up to 3 failed `calls` with `run`, `exit`, `code`, and truncated `stderr`):

| Verdict | Cause | Meaning |
| --- | --- | --- |
| `passed` | | All steps passed. |
| `failed` | `assertion` | An `act` or `expect` step failed. |
| `failed` | `infrastructure` | Execution or transport failed (for example, unreachable fleet or CLI timeout). |
| `unrun` | `precondition` | A `setup` step failed. |
| `unrun` | `infrastructure` | A restore failure or shard budget stopped the batch before the case ran. |

`runner.py` subcommands are `plan` (`--json`, `--steps`, `--lines`), `batch`, `case` (`--negative` to verify `must_fail` assertions detect broken effects), `setup`, and `replay`. Exit codes are `0` (passed), `1` (failed), `2` (unrun), and `3` (spec error). Guest helpers live in `tools/swamp-proof-guest/`.

### Opt into merge-base replay

Set `fails_on_base: true` on a new or changed case that proves behavior absent from the merge base. When replay runs (`runner.py replay`), every eligible flagged case must fail on the merge base with cause `assertion`; a passing or unrun result fails the proof with `CASE@merge-base`. In container copies, merge-base replay is not yet wired into `proof:run`, so `fails_on_base` currently acts as case metadata ([old paths](/reference/old-paths#the-task-vm-proof-run)).
