# Technical Contract: `orbit workspace:setup` (Interactive Input)

This contract defines behavior for **interactive input mode**.

[Back to the canonical contract.](1_workspace-setup.md)

**Input mode:** Interactive.

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present (i.e. without `--json`).

When `--json` is present, use
[`5.2_workspace-setup_input-mode_non-interactive.md`](5.2_workspace-setup_input-mode_non-interactive.md)
even if the process has a TTY.

## Prompts

| ID | Primitive | Label | Required |
| --- | --- | --- | --- |
| `app` | `datatable` | Select parent app | Yes when neither `--app` nor `[name]` is supplied and interactive CWD resolution needs parent-app context. |

## Primitive References

- [`datatable`](../../../../ux/commands/lists/data-table-prompt.md)

## Behavior

- **Validation**: The parent app prompt lists visible registered apps. Supplied
  invalid values fail before side effects.
- **Workspace name validation**: Lowercase letters, digits, and hyphens; max
  63 chars independent of the parent app slug; cannot start or end with a
  hyphen.
- **Parent app selection**: If `--app` is missing and the command needs parent
  app context before resolving a workspace, the user is presented with a data
  table of authorized parent apps.
- **CWD path-ownership lookup runs before prompts**: when `[name]` is
  missing, the gateway path-ownership lookup resolves the CWD first. If it
  returns `workspace`, identity is resolved from the lookup and the
  `workspace`, `app`, and `path` prompts are skipped. If it returns
  `app_root`, the command fails before any prompts with
  `error.code=workspace.path_is_app_root` and the hint to run
  `workspace:new` instead. If it returns `inside_app` or `unregistered`, the
  agent-IDE adapter probe runs before prompts; identity resolved by a single
  adapter skips the corresponding prompts. Prompts proceed for any fields
  still unresolved.
- **Path adoption**: If the supplied path is not yet managed by Orbit, the
  command asks the operator to confirm adoption of the existing path before
  writing workspace configuration.
- **Retry budget**: After 3 failed attempts for the same field, the command
  fails with a validation error.

## Destructive Consent

`workspace:setup` is non-destructive to project source. Managed runtime
artifacts (PHP-FPM pool, runtime config, proxy backend) are gateway-owned and
overwritten without prompting because Orbit owns those file paths. There is
no destructive consent prompt and no destructive-skip flag.
