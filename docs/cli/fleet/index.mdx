After each verified Gateway release, the Gateway brings the managed workload Nodes to the same release, one Node at a time. The `fleet` family shows that rollout and resumes it after a halt. [Fleet rollout](/reference/gateway-recovery#fleet-rollout) explains the rollout set, the order, the steps on each Node, and the catch-up.

## Commands

| Command | Result |
| --- | --- |
| [`fleet:rollout:status`](/cli/fleet/rollout-status) | Show the newest rollout, each Node's result, and the Nodes it leaves out. |
| [`fleet:rollout:resume`](/cli/fleet/rollout-resume) | Resume a halted rollout, optionally past one Node. |

Both commands accept `--json`. JSON output contains only the response.

## How it works

The rollout publishes the CLI and the Node agent on each Node in turn. Each Node runs the `fleet-release-node` child, which runs the shared `node-cli-install` child from Node 209. A rollout then publishes the pinned Node agent from Node 209 with official resources.
