# Parent-callable hub peer mutation

`NodeWireGuardCommandInput::capture(actualContext, prospectiveAddress?, prospectiveName?)` records the full public inventory, the exact prior peer or absence, and the desired context before a parent changes its identity. It works while removal records Removing. The optional address and name are admitted candidate fields. The exact prior peer still comes from the actual Node and its stored identity. Do not pass an identity-substituted clone. A prepared native public key can replace only this context's key.

`@nckrtl/node-hub-command.read({intent, mode, prepared_peer?})` validates that public capture and reads the shipped `hub_peer.py`. Modes are publish, remove, restore-publish and restore-remove. Compensation reverses the same captured before/after pair; it makes no Gateway request and needs no restoration flag. The metadata substitutes only public JSON into a fixed data constant in the script. No secret is part of the script, its arguments or its outputs.

## Domain action and configuration management

The action reads the current hub configuration under native model serialization and changes only the admitted context key/address. It preserves the local private key and unrelated newer peers. Missing/foreign configuration and conflicting same-context state refuse. An already-applied pair is idempotent and still synchronizes kernel state. Publication or activation errors restore the prior file and kernel view. The existing `/run/lock/orbit-wireguard-peer.lock` protects the host-tool transaction; it grants no alternate writer policy. No tunnel restart or DNS effect occurs.

The official-first check covered `@swamp/ssh` script/exec and `@swamp/cfgmgmt` file/template/systemd. SSH directly fits execution and shipping. cfgmgmt file/template deploy complete caller-supplied content, with templates rendered on the control worker. They do not supply an exact peer merge against fresh remote WireGuard state. Using them for this mutation would export the hub private key or replace newer peers with a stale rendered inventory. The domain script therefore performs the peer merge and WireGuard tool transaction locally. Ordinary owned file/service configuration should use cfgmgmt when its native contract fits.

Standalone capture separates desired and explicitly retiring public peers. It preserves unknown fresh host peers and reports `retained_peer_count`; it does not claim orphan deletion or initial hub provisioning. A desired peer missing from the current hub refuses rather than resurrecting a peer removed after admission. Repair that state through its owning peer operation. Initial missing/inactive hub configuration also refuses.

A successful action prints one public object: `{schema_version, hub_id, context_node_id, projected:true, restored:boolean, changed:boolean}`. Standalone output also reports retained_peer_count. Failure prints a closed error_code and exits nonzero. Parent readiness consumes this public result; only the parent's existing aggregate result can claim whole-parent restoration. Shared terminal projection remains the existing subscriber and fixed selector, without a family callback or poller.

## Retarget parent

Retarget admits immutable prior and candidate endpoints. Any role assignment chooses pinned WireGuard verification; a roleless peer uses pinned public SSH, one-action peer preparation/publication, the shared stable hub mutation and private SSH verification. Native compensation restores its saved peer files/service state and the exact captured hub entry. The Gateway commits the endpoint only on terminal native success. The workflow's empty conditional branch uses native forEach expansion; outputs use the expanded step name such as `snapshot-0`, and terminal always waits for endpoint verification.

The reusable `peerActionSteps(name, action, inputExpr, {placement, globalArgs}, dependency?, guard?)` export resolves one shipped action, calls official SSH.script against the named `peer` host, then decodes its typed public result. Actions are snapshot, prepare_key, publish, record_dns, restore and cleanup. The parent supplies service activation and verification steps. Snapshot includes prior files, service state and resolver settings; DNS handoff clears an older recorded uplink, reconfigures it and checks its public resolver once. Failure returns through native compensation, which restores the recorded settings. No polling loop is used.

`NodeNetworkInput::forAdmitted(actual, address, endpointOverride, dnsOverride, tld, rolelessOperator)` captures prospective public peer configuration without changing the actual Node. `NodeWireGuardCommandInput::capture(actual, prospectiveAddress, prospectiveName)` supplies the shared immutable hub intent. Enrollment can prepare its public key, pass it as prepared_peer to the same hub mutation, and reverse that exact mutation during compensation. Parent-owned aggregate restoration remains unchanged.
