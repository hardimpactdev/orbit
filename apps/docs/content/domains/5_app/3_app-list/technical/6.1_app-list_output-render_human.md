# Human Renderer: `orbit app:list`

[Back to `app:list` technical contract.](1_app-list.md)

This page describes the human-rendered output for `app:list`.

**Renderer:** Human renderer.

## Primitive

- Data list: [`DataList`](../../../../ux/commands/lists/data-list.md)

## Selection

Use this renderer by default when `--json` is absent.

## Progress Tree

No progress tree is rendered because `app:list` is expected to stay below one
second. It performs a fast gateway database read and does not perform slow
external work, network probes, or remote node application.

## Success Render

The success output is one `Apps` DataList group. Logical apps are ordered
alphabetically by app name (case-insensitive). Each app is one item whose label
is the app name and whose properties are:

- `Repository`: repository URL or `—`.
- `Instances`: count of placement-visible app instances.
- `Workspaces`: count of placement-visible workspaces across those instances.

Instance and workspace placement rows do not appear in `app:list`; operators
use `app:show <app>` for that detail.

### Example output

```text
 ┌ Apps
 │ blog
 │   Repository: git@github.com:example/blog.git
 │   Instances: 2
 │   Workspaces: 0
 │
 │ docs
 │   Repository: git@github.com:example/docs.git
 │   Instances: 1
 │   Workspaces: 3
 └
```

### Empty result

When no apps are visible:

```text
No apps found.
```

## Error Render

Errors are rendered as concise prose messages.

### Gateway unavailable

```text
Gateway connection is required to list apps.
```

Authorization failures originate at the API permission middleware and are
documented as part of the JSON renderer contract (see
[`6.2_app-list_output-render_json.md`](6.2_app-list_output-render_json.md)).
The command's human renderer does not own that failure shape, so it is not
covered here.
