## Progress Tree

`workspace:new` performs remote work (source provisioning through the selected
workspace driver, proxy route, runtime container, setup steps, and inherited runtime units) that
typically exceeds one second. It uses the shared step-tree renderer to
visualize progress in real time.

```text
┌ Creating Workspace
○ Provision worktree on app-1
○ Register proxy routes
○ Install runtime container artifacts
○ Run workspace setup steps
○ Render inherited runtime units
○ Check workspace readiness
└ Working...
```

When the effective agent IDE adapter is `opencode` or `polyscope`, the first
step names that adapter (`Provision OpenCode workspace on <node>` or
`Provision PolyScope workspace on <node>`) so users can tell which source driver
is active.

The generic worktree step creates `<app path>/.worktrees/<workspace>` and
checks out branch `<workspace>` from the requested `--base` ref. The OpenCode
driver asks OpenCode to create a UI-visible workspace, then aligns the returned
workspace worktree to the requested branch and base ref. The PolyScope step
stores the path returned by the SDK, which may be outside the parent app path.

## Completion Summary

Upon success a one-line summary is printed:

```text
Workspace 'feature-a' created on app 'my-app' (node 'app-1').
URL: https://feature-a.my-app.test
PHP: 8.5 (inherited from app)
```

## Warning Display

Drift that is non-fatal surfaces inline under the affected step and again in a
`Warnings:` block beneath the completion summary. Each warning entry shows
the human-readable message and a retry hint pointing at `next_command`,
mirroring the `app:new`/`app:register` shape. Examples:

- A workspace path that did not get created during application prints
  "Workspace path is missing on 'app-1'." with the hint
  `Resolve with: orbit doctor --fix --family=workspace --restore`.
- A missing runtime container prints "Workspace runtime container configuration is missing."
  with the hint `Resolve with: orbit doctor --fix --family=workspace --restore`.
- A pending workspace proxy route prints the corresponding
  `proxy`-family warning with its own `next_command`.

## Failure Display

Failures are rendered as prose errors with troubleshooting hints. If a
failure occurs during the progress tree, the affected step shows a red
error dot. Validation failures detected before side effects (reserved name
`main`, slug regex, per-app workspace-name collision, unsupported
`--php-version`, unresolved parent app) are rendered without a progress
tree:

```text
✗ Failed to create workspace 'feature-a'
  The workspace name 'feature-a' is already used for app 'my-app'.
```

```text
✗ Failed to create workspace 'main'
  The name 'main' is reserved and cannot be used as a workspace name.
```
