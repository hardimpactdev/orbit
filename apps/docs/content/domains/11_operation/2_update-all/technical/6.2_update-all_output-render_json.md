# JSON Renderer: `orbit update:all`

[Back to `update:all` technical contract.](1_update-all.md)

This page describes the JSON-rendered output for `update:all`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even
when the process has a TTY.

The JSON renderer submits the durable operation start request to the gateway
first, then follows the operation event journal without rendering intermediate
frames. When the gateway reports the selected fleet as all-current for the
desired artifact identities, it emits the terminal envelope and skips
caller-local mutation. When the terminal manifest source is `topology-candidate`
and the desired artifact hash for the caller's local CLI differs, JSON mode
updates that CLI as the post-gateway fan-out target before emitting the terminal
envelope. A caller-local update failure after the gateway phase is a partial
failure.

### Stream JSON renderer

Use `--stream-json` instead of `--json` when callers need newline-delimited
progress frames while the fleet update runs. It follows the same gateway-first
control flow and caller-local fan-out as `--json`, but emits each gateway
progress event before the terminal state as an `event=tree` or `event=step`
frame as it arrives, then a single terminal frame. The renderer follows the shared
[Stream JSON Frames](../../../README.md#stream-json-frames) contract:

- Terminal success uses `event=complete` with the JSON success payload from this
  page (the `updates[]` array and summary metadata) under `success`.
- Terminal failure uses `event=error` with the canonical error object, including
  a caller-local fan-out failure after the gateway phase
  (`error.code = "local_update_failed"`). Once a progress frame has been
  emitted, a later failure is reported as a terminal `event=error` frame rather
  than a plain error envelope.
- `--json` and `--stream-json` together, and any failure that occurs before the
  progress stream opens (such as release-manifest resolution or the start
  request), use the plain JSON error envelope with no `event` key.

`--stream-json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model).

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Gateway authorization failures, gateway failures, local
update failures, and remote target failures must all use this envelope.

## Success Shape

```json
{
  "success": {
    "data": {
      "updates": [
        {
          "target": "gateway",
          "node": "gateway",
          "role": "gateway",
          "status": "completed",
          "operation_run_id": "018f3f8b-5d7a-7f5e-a45b-93067a93d47e"
        },
        {
          "target": "local",
          "node": null,
          "role": null,
          "status": "completed"
        },
        {
          "target": "app-1",
          "node": "app-1",
          "role": "app",
          "status": "completed"
        }
      ]
    },
    "meta": {
      "summary": {
        "total": 3,
        "completed": 3,
        "failed": 0
      },
      "operation_run_id": "018f3f8b-5d7a-7f5e-a45b-93067a93d47e"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `updates[]` | array | Ordered target results. |
| `updates[].target` | string | Human-stable target label. |
| `updates[].node` | string \| null | Gateway node name for remote targets; `null` for the caller-local checkout. |
| `updates[].role` | string \| null | Node role for remote targets; `null` for the caller-local checkout. |
| `updates[].status` | string | Target update status. |
| `updates[].operation_run_id` | string \| null | Durable gateway operation id for gateway-owned update work. |
| `meta.operation_run_id` | string | Durable gateway operation id followed by the CLI. |
| `summary.total` | integer | Number of selected update targets. |
| `summary.completed` | integer | Number of targets that updated successfully. |
| `summary.failed` | integer | Number of targets that failed. |

The `local` target represents the caller-local checkout after the gateway phase.
Gateway-selected non-local installations are listed separately and must not
duplicate the local target.

Operator identities are never remote update targets. Clients other than the
caller are never remote update targets; see the `update:all` technical contract's
[Fleet Selection Rules](1_update-all.md#fleet-selection-rules).

## Error Shapes

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for '*' on 'gateway'.",
    "meta": {
      "reason": "permission_missing",
      "missing_permission": "*",
      "serving_node": "gateway"
    }
  }
}
```

### Local update failed

```json
{
  "error": {
    "code": "local_update_failed",
    "message": "Failed to update local Orbit checkout.",
    "data": {
      "output": "local Orbit entry point did not respond to the version check"
    },
    "meta": {
      "failed_step": "verify_cli"
    }
  }
}
```

### Remote target failure

When any remote target fails after side effects begin, return an error envelope
that preserves every target result:

```json
{
  "error": {
    "code": "remote_update_failed",
    "message": "One or more Orbit installations failed to update.",
    "data": {
      "updates": [
        {
          "target": "local",
          "node": null,
          "role": null,
          "status": "completed"
        },
        {
          "target": "app-1",
          "node": "app-1",
          "role": "app",
          "status": "failed",
          "output": "Permission denied (publickey)."
        }
      ]
    },
    "meta": {
      "operation_run_id": "018f3f8b-5d7a-7f5e-a45b-93067a93d47e",
      "summary": {
        "total": 2,
        "completed": 1,
        "failed": 1
      }
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `updates[].role` | `gateway`, `app-dev`, `app-prod`, `app`, `null` |
| `updates[].status` | `completed`, `failed` |
| `error.code` | `gateway_unavailable`, `authorization_failed`, `local_update_failed`, `operation_plan_missing`, `update_lease_conflict`, `gateway_update_failed`, `scheduler_recovery_failed`, `workload_update_failed`, `remote_update_failed`, `final_verification_failed` |

The `error.code` values listed here are exhaustive for `update:all`. Add a new
value to this renderer contract before implementing another JSON failure code.
Partial target results and captured command output are diagnostic data and
belong under `error.data`, not `error.meta`.

For `update_lease_conflict`, the gateway terminal frame may include additive
`data.conflicting_node` when the conflicting `operation_run` has a
`caller_node_id`. The field is omitted when the caller node is unknown.
