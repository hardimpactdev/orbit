title: "orbit project:destroy"
sidebarTitle: "project:destroy"
description: "Remove a Project that has no Instances and no Routes. Its definitions, setup steps, and update records go with it. Task groups must all be `cancelled` or `completed`; they and their dependent records are deleted with the Project. Any other group status returns HTTP 409 and `project.has_task_groups` without deleting anything. Every associated task VM row must be `destroyed`. A VM in any other state, including `failed`, returns HTTP 409 and `project.task_vm_not_destroyed`; the message names the VM and its state. Nothing is deleted. Wait for destruction and model-key revocation to finish before retrying."
---

Every associated workspace lease must be `released` or `cancelled`. A `cancelled` lease is a withdrawn waiter that never held the workspace. Any other status, including `held`, `queued`, or an unknown status, returns HTTP 409 and `project.task_workspace_lease_active` without changing any records. The message names the Project, lease id, kind, and status. A missing Instance does not prove release. Project deletion does not release leases and deletes only released and cancelled leases and their operations. See [Remove a Project](/reference/projects#remove-a-project).

```bash
orbit project:destroy <project> [--yes] [--json]
```

The CLI shows the Project and asks for confirmation, with No selected. `--yes` confirms without a prompt and is required for JSON and noninteractive calls.
