# JSON Renderer: `orbit process:list`

[Back to `process:list` technical contract.](1_process-list.md)

This page describes the JSON-rendered output for `process:list`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces non-interactive input mode.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Success data contains the resolved context and process definitions with latest durable lifecycle event data when present.

`success.data.context` is present because `process:list` must resolve one node,
instance, or workspace execution scope before it can list process definitions. This
does not imply a context block for registry list commands whose inputs are only
filters.

## Success Example

```json
{
  "success": {
    "data": {
      "context": {
        "node": "app-1",
        "app": "docs",
        "instance": "development",
        "workspace": "feature-docs"
      },
      "processes": [
        {
          "key": "vite",
          "label": "Vite Dev Server",
          "name": "vite",
          "node": "app-1",
          "app": "docs",
          "instance": "development",
          "workspace": "feature-docs",
          "command": "npm run dev",
          "restart_policy": "never",
          "crash_notification": "none",
          "runtime": "systemd",
          "tool": null,
          "service": null,
          "runtime_unit": "orbit_docs_development_feature-docs_vite",
          "status": "running",
          "last_event": {
            "id": 123,
            "type": "started"
          }
        }
      ]
    },
    "meta": []
  }
}
```

`success.data.processes[].key` is the stable process identity slug.
`success.data.processes[].label` is the durable human display label.
`success.data.processes[].name` is a deprecated compatibility alias equal to
`key`; new consumers must use `key` and `label`.

`success.data.processes[].status` is one of `starting`, `running`, `stopping`,
`stopped`, `restarting`, `crashed`, or `unknown` (no durable event yet, or
latest event `failed`). `last_event` remains present when an event exists and
is `null` when status is `unknown` with no event.

## Error Example

```json
{
  "error": {
    "code": "validation_failed",
    "message": "A node, instance, workspace, or app context is required.",
    "meta": {
      "field": "instance"
    }
  }
}
```

## Authorization Error

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized to read process intent.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "process:read"
    }
  }
}
```

## Error Code Vocabulary

- `validation_failed`: node/instance/workspace/`app` context is missing, invalid, mutually exclusive, or ambiguous in non-interactive input mode. An ambiguous bare app selector uses `error.meta.field=instance` and `error.meta.reason=instance_required`. An unknown hostname uses `error.meta.field=app`.
- `authorization_failed`: peer identity is unknown, the peer lacks `process:read` on the resolved node or instance serving node, or browser CORS Origin admission fails (missing/mismatched/unregistered Origin relative to the requested `app`). CORS Origin checks never establish caller identity.
- `gateway_unavailable`: the CLI cannot reach the gateway API.
