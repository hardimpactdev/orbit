# Human Renderer: `orbit vpn-client:new <name>`

[Back to `vpn-client:new` technical contract.](1_vpn-client-new.md)

**Renderer:** Human terminal renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

`vpn-client:new` resolves the active `vpn` role runtime, performs backend
authentication, and writes a backend peer, so the human renderer must render a
progress tree after input resolution and before side effects begin:

```text
┌ Creating VPN client
○ Resolve VPN runtime
○ Authenticate VPN backend
○ Create VPN client
○ Render client config
└ Working...
```

When `--config` is absent, the `Render client config` step is omitted.

## Success Output

```text
VPN client `laptop` created
Address: 10.6.0.7
```

When `--config` is present, print the generated config after the summary:

```text
# --- wg-orbit.conf ---
[Interface]
...
```

The printed config's `DNS =` line points at the WireGuard server DNS endpoint
and includes the private `orbit` search domain.

## Failure Output

Human-rendered failures use one concise error line and no JSON envelope.
Validation failures identify the conflicting field or client name when known.
