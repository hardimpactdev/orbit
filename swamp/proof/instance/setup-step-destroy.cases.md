# instance:setup-step:destroy verification cases

`instance:setup-step:destroy` removes a row of the Project's list and has no chart. The proof runs the built CLI against a fresh nested topology with Projects that have setup lists, and compares the output with the Gateway records. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Remove a step | Remove the middle step of three, with `--yes`. | The step is gone from `setup-step:list`. The other two keep their order, and the total timeout drops by the step's timeout. The result is at once, with no task and no file written on any Node. |
| Remove the only step | Remove the last step. | The list is empty and `instance:setup` succeeds as a no-op. |
| Already set up | Remove a step after an Instance ran it. | The Instance keeps what the step did. |
| Teardown separate | Remove a setup step whose name a teardown step also has. | Only the setup step is removed. |
| Unknown step | A name the Project's setup list does not hold, a repeat after a success, two destroys of the same step at once, and a name that is not a valid step name. | `setup_step.not_found` for the first two, with nothing changed and no prompt in a terminal. One of the two concurrent destroys succeeds and the other gets `setup_step.not_found`. The last gives `http.404`. Fails today: the CLI prompts before it checks the step, so an unknown name is refused only after you confirm; and the invalid name is not `setup_step.not_found`. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C and end of input. Then run it noninteractively and with `--json` without `--yes`. | The prompt names the step, the Project and the effect, with No selected. Each decline ends with `input.cancelled` and removes nothing. The noninteractive and `--json` calls are refused with `input.confirmation_required`, with no request. With `--yes` there is no prompt, also with `--json`. Fails today: the prompt names the Project by ID and does not state the effect. A noninteractive call for an unknown step without `--yes` gets `input.confirmation_required`. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail `Removed setup step: <name>` with the Project by name, Timeout and Command and the request ID at the wide width, and labeled records at the narrow one. The piped output has no animation or escape codes. With `--json`, stdout holds the removed step with `request_id`. Fails today: the output is three lines, `Name:`, `Command:` and `Timeout:`, with no title, Project or request ID, then a progress footer, and the step response carries no Project name. |
| Missing input | In a terminal, run the command with no name and no `--project`, and cancel each list. Then run it noninteractively and with `--json`. | The terminal lists Projects and then the Project's setup steps by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `project.id_invalid` or `lifecycle_step.name_required`, with one error and no request. Fails today: the name is a required argument, the Project is refused even in a terminal, and two missing inputs print two errors. |
| IDs only | A Project by name, the ID `0`, the ID `-1`, and `abc`. | `project.id_invalid`, with no request. |
| Unknown and access | A Project ID that does not exist, and a caller without a grant to any Node that holds an Instance of the Project. | `http.404` and `node_access.required`. Nothing is removed. |
| Activity | After a successful removal and a failed one. | Activity holds no command text in the stored input or result. |
