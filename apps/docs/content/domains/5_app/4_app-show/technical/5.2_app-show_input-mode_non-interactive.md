# Non-Interactive Input Mode: `orbit app:show [app]`

[Back to `app:show` technical contract.](1_app-show.md)

This page describes how non-interactive input mode resolves `app:show` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent after default
  resolution.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are
  known.

## Default Resolution

When `[app]` is missing, non-interactive input mode resolves the target in this
order:

1. **CWD resolution.** Attempt to resolve the app from the current working
   directory context.
2. **Fail.** If CWD resolution fails, fail before side effects.

The failure uses `error.code=validation_failed` with `error.meta.field=app`.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `app` | `[app]` is absent and CWD resolution cannot produce a target. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `app` does not match an existing app name (slug) or app hostname visible to
  the caller;
- the caller is not authorized to inspect the resolved app.

The selected output renderer owns how these failures are displayed. There is
no ambiguous-app failure mode: app slugs are globally unique in the gateway
app registry, so a resolved name maps to exactly one record.
