# JSON Renderer: `orbit node:update [name]`

[Back to `node:update` technical contract.](1_node-update.md)

This page describes the JSON-rendered output for `node:update`.

**Renderer:** JSON renderer.

## Primitive

None. JSON renderer emits the standard envelope only.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](5.2_node-update_input-mode_non-interactive.md), even
when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

### Normal success

```json
{
  "success": {
    "data": {
      "name": "app-1",
      "changed": ["host", "public_ipv4"],
      "action": "updated"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `name` | string | The updated node name. |
| `changed` | array | Names of fields whose configuration values changed. Empty when no values changed. |
| `action` | string | Always `updated`. |

### No-op success

```json
{
  "success": {
    "data": {
      "name": "app-1",
      "changed": [],
      "action": "updated"
    }
  }
}
```

### Success with artifact apply warning

When artifact re-applying fails after configuration is written, the result
remains a top-level `success` because the gateway-owned configuration was
committed. The remaining node-side artifact drift is node-family drift owned by
`doctor --family=node`, not a command failure. The recovery path is reported
under `success.meta.warnings[]`. Exit code is `0`. `success.meta.warnings` is
omitted when there are no warnings.

```json
{
  "success": {
    "data": {
      "name": "app-1",
      "changed": ["host"],
      "action": "updated"
    },
    "meta": {
      "warnings": [
        {
          "code": "node.artifact_enactment_failed",
          "message": "Node artifact re-enactment failed after intent update.",
          "family": "node",
          "next_command": "doctor --fix --family=node --restore"
        }
      ]
    }
  }
}
```

Note: The warning `code` value `node.artifact_enactment_failed`, the literal
`message` text, and the `next_command` string are stable identifiers asserted by
tests and the warning code registry. They retain the legacy spelling while the
surrounding prose has been updated.

Warning fields:

| Field | Type | Meaning |
| --- | --- | --- |
| `code` | string | Stable warning code from the warning code enum below. |
| `message` | string | Human-readable warning message. Automation must not parse it. |
| `family` | string | Doctor family that owns the remaining drift. |
| `next_command` | string | Suggested repair command. |

## Error Shapes

### Missing required input

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Node name is required.",
    "meta": {
      "field": "name"
    }
  }
}
```

### No field provided

```json
{
  "error": {
    "code": "validation_failed",
    "message": "At least one field must be provided to update a node.",
    "meta": {
      "field": "fields"
    }
  }
}
```

### Duplicate field flag

When the same field flag is supplied more than once in a single invocation,
the command rejects the input as a validation failure rather than relying on
shell last-wins behavior.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Field 'host' was supplied more than once.",
    "meta": {
      "field": "host"
    }
  }
}
```

### Node not found

```json
{
  "error": {
    "code": "node.not_found",
    "message": "Node 'app-1' not found.",
    "meta": {
      "name": "app-1"
    }
  }
}
```

### Field role-incompatible

```json
{
  "error": {
    "code": "node.field_role_incompatible",
    "message": "The field 'environment' is not valid for node 'gateway-1' (role: gateway).",
    "meta": {
      "field": "environment",
      "name": "gateway-1",
      "role": "gateway"
    }
  }
}
```

For `--tld`, `node.field_role_incompatible` uses the same shape with
`meta.field=tld` when the target is a gateway node, a client, or an app
node whose effective environment is `production`.

### TLD already in use

```json
{
  "error": {
    "code": "node.tld_in_use",
    "message": "Development TLD 'test' is already assigned to another node.",
    "meta": {
      "field": "tld",
      "value": "test"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to update a node.",
    "meta": {}
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'node:update' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "node:update",
      "serving_node": "app-1"
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `action` | `updated` |
| `error.code` | `validation_failed`, `node.not_found`, `node.field_role_incompatible`, `node.tld_in_use`, `gateway_unavailable`, `authorization_failed` |
| `success.meta.warnings[].code` | `node.artifact_enactment_failed` |

Error metadata:

| Error code | Metadata |
| --- | --- |
| `node.field_role_incompatible` for `--tld` | `field=tld`, target `name`, target `role`. |
| `node.tld_in_use` | `field=tld`, conflicting `value`. |
| `authorization_failed` | `reason=missing_permission`, `missing_permission=node:update`, target `serving_node`. |

The `error.code` and `success.meta.warnings[].code` values listed here are
exhaustive for `node:update`. Add a new value to this renderer contract before
implementing another JSON failure or warning code.
