# Solutions

A solution note records one gotcha: a failure you can hit again, or a finding that saves a later team from repeating the research. Read this directory before you pick a technology approach, and when a failure looks strange.

Update an existing note when you can. Add a note only when it stops someone from rediscovering the same problem. Procedures belong on the command or reference page that owns them. Do not copy pull request narration, commit hashes, test counts, or temporary debugging logs here.

Give the note a short kebab-case file name. Lead with the symptom. Include these parts:

- the problem, as you see it;
- the cause;
- the solution;
- the limits; and
- how to check that it holds.
