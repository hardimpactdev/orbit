# node:remove verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN hub Node, a Metrics Node and disposable Nodes to remove, including a macOS-like peer. It checks the Gateway record, the machine state and real traffic. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Remove a Node with a role | A Linux Node with a role. Remove it and confirm. | The Operation succeeds and the Node record is gone. The role is shed and its services stopped. Public SSH is restored, Orbit's services, files, configuration, containers and firewall rules are gone, and the management keys are revoked. Packages, users, user data and unrelated SSH keys stay. |
| Fleet withdrawal | After the removal. | The hub no longer lists the peer, the Router has no ingress for the Node, Metrics no longer includes it, and its private DNS records are gone. No packet crosses the tunnel to the removed Node. Peer DNS refreshes only if the routing domains changed. |
| Consent in a terminal | Remove a Node with a role, then an offline one. Read the prompt, decline it, then confirm. | The prompt names the Node and the effect, with No selected. Declining ends with `input.cancelled` and no request. Confirming removes the Node. Fails today: the prompt names no effect. |
| Consent without a terminal | Run noninteractively and with `--json`, without `--force`. Then call the API for a Node with roles, and for an offline removal, without `force`. | The CLI is refused with `node.confirmation_required` and sends no request. The API calls get `node.confirmation_required`. Nothing changes. |
| Attached resources | A Node with an Instance, a Database server, a Schedule, a Route and a user firewall rule, one at a time, then an online Node with a Process and a role dependent. | `node.has_instances`, `node.has_database_servers`, `schedule.target_in_use`, `node.has_routes` and `node.has_firewall_rules`, also offline. `node.has_processes` and `node.has_role_dependents` for the online Node only. No Operation and no change. |
| Protected Nodes | Remove the caller, then the Gateway, VPN and control Nodes. | `node.self_removal_forbidden`, `node.gateway_removal_forbidden`, `node.vpn_removal_forbidden` and `node.control_removal_forbidden`. No change. |
| Task VM host and guest | A task VM host with task VMs, one with task VM settings, a guest Node, and a Node whose record changed after admission. | `node.has_task_vms`, `node.task_vm_host_configured`, `node.removal_owner_required` and `node.removal_owner_mismatch`. No change. After the VMs are drained and the settings cleared, the host is removed. |
| Role and runtime busy | Remove a Node while a role operation runs on it, and one whose WebSocket runtime is still up. | `node.role_busy` and `websocket.runtime_shutdown_required`. No change. |
| SSH target unavailable | Remove a Node when a required SSH target cannot be built. | `swamp.ssh_target_unavailable` (503). No Operation and no change. |
| Offline Node | Stop the machine. Remove it with `--offline --force`. | The record and its fleet membership are removed, role publications on other Nodes are withdrawn, and the machine is untouched. The result lists `roles_shed` and `retained_on_node`, which names the Orbit keys and the worker unit that stay. |
| Unreachable without offline | Stop the machine and remove it without `--offline`. | The run fails with `node.removal_incomplete`. The Node stays marked failed. `--offline --force` then removes it. |
| Reachable Node with offline | Remove a reachable Node with `--offline --force`. | It gets ordinary cleanup, as for an online removal. |
| macOS and iPadOS peers | Remove a macOS peer and an iPadOS peer. | The peer's admitted keys are revoked and the Node is withdrawn from the fleet. The account, tools and host tunnel stay. The result retains `user`, `package-managers` and `host-wireguard` for macOS, and `host-wireguard` for iPadOS. Fails today: the result carries one generic retained sentence for every platform. |
| Check before keys | Make the check fail after the cleanup. | The Operation fails and the Node is still reachable with its management keys. The rerun connects, finishes and removes the Node. |
| Failed step | Make a step fail after the roles are shed. | The Operation fails with the failed step. The Node stays with status `failed` and step `remove:operation`, and its claimed roles are marked failed. Finished steps stay and nothing is restored. The hub peer is still listed. The run folder is removed. |
| Rerun after failure | Fix the cause and run the same command. | The Operation succeeds, the record is gone, and no step repeats finished work or leaves duplicates. |
| Budget, cancel and interrupt | Make a step outlast the budget, then cancel a run, then stop the worker mid-run. | `operation.timed_out` for the first. The other two end the same way. In each case the Node stays marked failed and the rerun finishes. |
| Busy removal | Start a second removal of the same Node while one runs. | `node.removal_busy`. The first removal is unaffected. |
| Cancel following | Press Ctrl-C while the CLI follows. | The CLI stops following and the Operation keeps running to its end. `operation:show` follows it again. |
| Lost response | Lose the response to the start, then repeat the command. | Exactly one Operation exists for the removal. Fails today: the CLI needs `--idempotency-key` to avoid a second Operation. |
| Missing input | In a terminal, run the command with no argument. Then run it noninteractively and with `--json` without the Node. | The terminal asks for the Node from an interactive list. Ctrl-C ends with `input.cancelled` and no request. The noninteractive and `--json` calls are refused with `node.id_invalid` and send no request. Fails today: the argument is required and nothing prompts. |
| Refusals | A Node the caller has no access grant to, and an unknown ID. | `node.access_denied` and a not-found error. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result with the Operation and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final Operation. |
