---
title: "orbit instance:auto-deploy:disable"
sidebarTitle: "instance:auto-deploy:disable"
description: "Stop automatic deployment of one production Instance or development container default."
---

```bash
orbit instance:auto-deploy:disable <instance> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID of a production Instance or a ready development container default. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Print the Instance as JSON. |

```bash
orbit instance:auto-deploy:disable 71
```

In a terminal, an omitted Instance is chosen from an interactive list. A noninteractive or `--json` call without it is refused with `instance.id_invalid` and sends no request, and so is a value that is not a positive integer.

The command turns automatic deployment off, so no check deploys. It changes nothing on a Node, stops no deployment that is already running, and a check that is admitted after the disable ends with `deployment.paused` and deploys nothing. It asks for no confirmation: `instance:auto-deploy:enable` turns it on again. Commits that were not deployed stay undeployed. Disabling an Instance that already has automatic deployment off succeeds and changes nothing. See [Automatic deployments](/reference/deployments#automatic-deployments).

Development container defaults start with automatic deployment on. This command turns the same `auto_deploy` flag off for just the selected Instance. The minute scan skips it, and admission and queued execution refuse automatic deployment while it is off. Explicit manual deployment still works. Checkout Instances refuse this command with `instance.auto_deploy_container_default_required` because they are user working trees, not automatic deployment targets.

The command prints a detail titled `Instance: <name>` with ID, `Auto deploy: off` and the request ID. With `--json`, stdout holds the Instance with `auto_deploy`.

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The Instance is missing in a call that cannot prompt, or is not a positive integer. |
| `input.cancelled` | You cancelled the Instance list. |
| `deployment_config.unavailable` | Production deployment configuration is unavailable. |
| `instance.auto_deploy_container_default_required` | Development automatic deployment requires an active container default with a seed snapshot, never a checkout working tree. |
| `instance.auto_deploy_role_inactive` | The development Node or its app-dev role is inactive. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |
