# instance:database:add verification cases

`instance:database:add` writes a registered Database connection into an Instance's stored configuration and has no chart. The proof runs the built CLI against a fresh nested topology with a mysql, a pgsql, a redis and a sqlite connection, an active Instance, an Instance that is not active, and a managed server with a LAN address. It compares the output with the Gateway records and the stored keys. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Add each driver | Add a mysql, a pgsql, a redis and a sqlite connection, each with its own Instance or prefix. | The stored keys match the driver list on the page, and the other keys of the prefix are gone. No Node is touched, no task starts, and the workload `.env` is unchanged until `env:sync`. |
| Prefix | Add with the default prefix, with `--prefix=REPORTING`, and with a second prefix on the same Instance. | Each prefix holds its own keys and mapping. The default is `DB`. |
| Repeat | Run the same add twice, and add again with only the network changed. | The second call is skipped with `database.attachment_unchanged`, `Changed: false`, and the stored keys do not change. The network-only change counts as a change. Fails today: the repeat succeeds with `Changed: false` and no explanation or reason code, and a network-only change that leaves the keys equal reports `Changed: false`. |
| Conflict | Add a different connection under a prefix that holds stored keys, without and with `--replace`. | Without `--replace`: `database.environment_conflict`, with the keys and the mapping unchanged. With it, the keys and mapping are replaced and the old keys of the prefix are removed. |
| Network | Add with `--network=lan` to a managed server with a LAN address, then again with `--network=wireguard`, without and with `--replace`. Then use a server or Node without a LAN address, a sqlite connection, an external connection, and a value other than the two. | The host is the LAN address, then the second call without `--replace` gives `database.environment_conflict` with nothing changed, and with `--replace` the host is the stored host. A missing LAN address, a sqlite connection and an external connection give `database.lan_unavailable` with nothing written. The other value gives `validation.failed`. Fails today: `--network=lan` on a sqlite or external connection succeeds, writes no LAN host and stores the choice. |
| SQLite on another Node | Add a sqlite connection to an Instance on a different Node. | `database.node_mismatch`, with nothing written. |
| Selector | `--instance` by ID, by exact Route domain, by a domain that is not exact, and `--instance=0`, `--instance=-1` and `--instance=abc`. | The ID and the exact domain work. Each other value is refused with `http.404` and nothing is written. |
| Instance state | An Instance that is not active, an Instance whose Route is changing, an Instance without a recorded source profile, and an add whose keys would exceed the stored-configuration limit. | `env.owner_unavailable`, `env.owner_unavailable`, `instance.source_profile_missing` and `env.configuration_invalid`. Nothing is written. |
| Unknown and access | An unknown connection slug, an invalid slug, and a caller without a grant to the Instance's Node. | `http.404`, `database.slug_invalid` and `node_access.required`. Nothing is written. |
| Invalid prefix | A lowercase prefix, one that starts with a digit, an empty `--prefix=`, `--prefix=DB-X`, and one of 33 characters. A prefix with digits and underscore, such as `READ_2`. | `database.prefix_invalid` for each invalid one, with no request. `READ_2` works. |
| Missing input | In a terminal, run the command with no arguments and cancel each list. Then run it noninteractively and with `--json`. | The terminal lists the connections and then the Instances. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `database.slug_required` or `database.instance_required`, with no request. Fails today: the slug is a required argument, so a call without it is refused by the parser, and the Instance is never prompted for. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail with the fields on the page at the wide width and labeled records at the narrow one. The piped output has no animation or escape codes. With `--json`, stdout holds the fields and `request_id`. The Host and Port show `—` for sqlite. No form holds the database name, username or password. Fails today: the detail names the Instance by ID only. |
| Competing changes | Add while `env:sync`, `env:update` or another database change runs on the same Instance. | Both changes complete, no write is lost, and the stored keys equal those of running the two in some order. |
| Activity | After a successful add and a failed one. | Activity and the error hold no stored value. |
