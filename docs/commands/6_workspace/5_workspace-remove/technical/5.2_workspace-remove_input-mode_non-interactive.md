# `workspace:remove` Non-Interactive Input Mode

[Back to canonical technical contract](1_workspace-remove.md)

This page describes how non-interactive input mode resolves
`workspace:remove` input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY (non-tty);
- `--json` is present.

`--json` selects the JSON renderer and forces non-interactive input mode even
when the process has a TTY. `--json` never authorizes destructive removal;
explicit destructive consent must be supplied via `--force`. In
non-interactive input mode, `--force` is the only available destructive
consent surface.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts; no prompts and no fallback prompts are emitted under
  any condition.
- Deny app-node and unknown callers before side effects.
- Fail before side effects when required input is absent.
- Fail before side effects when destructive consent (`--force`) is absent.
- Fail before side effects when supplied input is forbidden or invalid.

## CWD Resolution

CWD-based workspace resolution is allowed in non-interactive mode. If `name`
is omitted and CWD is not inside a registered workspace path, the command
fails before side effects with `error.code=workspace.unresolved_cwd`.
Detection of self-targeting still runs, but no confirmation prompt is
rendered; the operator's `--force` flag covers consent for self-targeting
removal too.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `name` | `[name]` is absent and CWD is not inside a registered workspace path. | Fail before side effects with `error.code=workspace.unresolved_cwd`. |
| `force` | Non-interactive mode and `--force` is absent. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=force`. |

## Validation Failures

Fail before side effects when:

- the caller role is `app` or `unknown` (renders as
  `caller_role_not_allowed`);
- `name` does not match an existing workspace record (renders as
  `workspace.not_found`);
- `name` matches multiple workspaces and `--app` was not supplied (renders as
  `workspace.ambiguous_name`).

The selected output renderer owns how these failures are displayed.
