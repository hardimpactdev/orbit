```bash
orbit instance:migrate <instance> [--force] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID of an active development checkout Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--force` | prompt | Confirm the downtime and the retirement of the checkout. Required without a terminal and with `--json`. |
| `--idempotency-key=KEY` | none | Reuse a key to retry this operation start. |
| `--json` | off | Print the final task as JSON, with every step, and nothing while it follows. |

```bash
orbit instance:migrate 12
orbit instance:migrate 12 --force --json > migrate.json
```

The command moves one checkout Instance into an [Instance container](/reference/development-containers#migrate-a-checkout-instance) on the same Node. It is temporary: [Old paths](/reference/old-paths) lists it until the last checkout Instance has moved.

In a terminal, the CLI asks to confirm that the Instance goes down during the move and that its checkout leaves the live path after it, with No selected. Declining, Ctrl-C or end of input ends with `input.cancelled` and starts no move.

The attached targets in [instance:show](/cli/instance/show) are the connections migrate reads: it grants and probes their network endpoints; SQLite files move with the checkout.

## What moves

| Part | What Orbit does |
| --- | --- |
| Branch | The checkout's current branch. Orbit fetches it from the checkout on the Node; a retained checkout can carry commits that were never pushed |
| Files | Every file that differs from the commit, every untracked file and every ignored file, such as `vendor`, `node_modules`, `storage` and `.env` |
| `.env` | Copied as it is. The checkout's path in it becomes `/srv/workspace` |
| Symlinks | Absolute links into the checkout become relative workspace links. Relative links within the checkout stay as they are. See the [symlink rule](/reference/development-containers#migration-symlinks) |
| Database on a Database server | It stays where it is. The container gets its own way to the port of each server the Instance uses. Orbit checks every target from inside before stopping the checkout |
| SQLite file in the checkout | It moves with the files. Orbit drops its database connection record: the file is part of the workspace |
| Route | The same domain and certificate. It points at FrankenPHP in the container, and the checkout's PHP-FPM pool goes |
| Schedules | Registered Node timers keep their UUID, calendar and enabled or paused state. Their commands run in the container; [Schedule migration](/reference/schedules#checkout-migration) describes the limits and logs |
| T3 | A non-default Instance gets its T3 server, registered as a [new Instance's](/cli/instance/create) is. The default runs none |

Untracked files enter the default's seed snapshot and every clone made from it, as ignored dependencies and build output already do. A later branch that tracks one of those paths can refuse checkout in a clone or deploy. A credentials file someone forgot to ignore travels into the seed like `.env` does.

The Operation result reports `untracked_files_copied` after a successful file-copy phase: the count of archived untracked leaf entries, including ignored files, files inside nested repositories (including their `.git` data), and symlinks. Directories do not count; symlinks count once. Human output says how many were copied. This adds no file paths or contents to the result.

A file created or changed in the old checkout after the copy stays in the retained checkout, as ignored files do today; migration quiesces its Processes before the copy, and retention keeps everything.

The container does not receive the index’s staging state, stashes, or branches that no Instance has checked out. Retirement moves the whole old checkout to a retained path, including all Git metadata and work-tree files. It deletes no Git data. A repository with stashes refuses preflight.

## Retained Git data

Retirement removes the checkout from its old live path by renaming the whole directory. The retained root is `<checkout>.orbit-retired-git`, beside the migrating Instance's checkout. Each retained checkout is a child named by the SHA-256 of its original absolute path. Its `.git`, objects, refs, reflogs, submodule repositories under `.git/modules`, nested repositories and work-tree files all stay there. Tag-only commits, stashes added after preflight and late worktrees remain recoverable because retirement deletes no files or Git metadata. The rename requires the same filesystem; Orbit has no copy-and-delete path. Worktree pointers may still name the old paths and need repair before use.

Find the root and its retention time with `orbit instance:show INSTANCE --json`: the fields are `retained_git_path` and `retained_git_at`, also returned by `GET /api/v1/instances/{instance}`. `retained.json` inside that root records the same path and time. Both API fields are null until retirement prepares that root. The timestamp is when the root was prepared. A failed retirement can leave an empty or partly filled root; its path is recorded before any checkout moves.

Destroying the migrated Instance keeps this directory. After destroy deletes the Instance record, its successful Operation result keeps `retained_git_path` and `retained_git_at`; read it with `orbit operation:show OPERATION --json`. See [instance:destroy](/cli/instance/destroy).

### Recovery

To inspect retained commits, use `git --git-dir=RETAINED_CHILD/.git show REF` on the Instance's Node. Repairing a linked worktree's pointers to the retained repository can make it usable again, but it still depends on that repository. Keep the retained root while any worktree depends on it.

### Manual purge

Orbit has no purge command yet. Before purging the retained root:

- Save all needed data outside it, including refs, stashes, submodule repositories and nested repositories.
- Make every surviving linked worktree independent, or move its shared repository outside the retained root and repair its worktrees against that new location. Repairing pointers back into retention does not meet this requirement.
- Stop anyone from creating or changing worktrees until inspection and purge finish.

Inspect the retained repositories' `worktrees/` entries, including those under `.git/modules` and nested repositories. On the Node, set `retained_root` to the exact recorded path. This read-only check prints each registration file followed by the path of its worktree's `.git` file:

```sh
retained_root='/exact/path/from/retained_git_path'
find "$retained_root" -type f -path '*/worktrees/*/gitdir' -print -exec cat {} \;
```

For every listed target whose worktree survives, check the repository it now uses:

```sh
git -C /path/to/surviving-worktree rev-parse --path-format=absolute --git-common-dir
realpath -- /common/git/directory/reported/above
```

Every resolved common Git directory must exist outside the retained root. A failed command, a path still inside retention, or an unaccounted-for missing target leaves the inspection incomplete: keep the retained root. Account for moved or removed worktrees explicitly; a broken old pointer does not prove independence. Repeat this inspection for every registration printed above.

Only after all data is saved and no surviving worktree uses a retained Git directory, run `rm -rf -- RETAINED_ROOT` on that Node, replacing `RETAINED_ROOT` with the exact recorded path. This is an operator-performed purge; retirement neither performs it nor clears the recorded path and time afterward.

## Before you start

- **Node.** The Instance's Node is on the [build list](/reference/development-containers#the-build-list).
- **PHP version.** A web-serving Project needs its PHP version recorded before the move. A missing version refuses with `project.source_defaults_incomplete`. Set `require.php` in `composer.json` on the default branch, then run `orbit project:update PROJECT --source-access=github_app` to record it. This command also enables source access for a `gh_cli` Project.
- **Service hosts.** In the initial preflight, before creating the container or probing a target, Orbit checks service hosts in the checkout’s `.env` and nested `.env` files, including ignored files. Every direct service requires exactly the same host and port as an endpoint admitted by the container access plan from the Instance’s attached targets. Fleet or WireGuard membership alone grants no access. The check uses the recorded endpoint used by the container ACL, firewall and database probe; an address projected for the target’s selected network does not grant access to that different address. HTTP publisher endpoints use the existing [public egress policy](/reference/development-containers#egress-and-dns): its private IPv4 ranges, Node addresses, IPv6 and private DNS domains are refused. Public names are left for the proxy to resolve and enforce at connection time. Other unresolved names and values refuse conservatively. The check does not prove that a listener is running or that the container can reach it. Orbit neither rewrites service hosts nor creates targets from `.env`. It repeats the check before quiesce.
- **Branch.** The checkout is on the branch that Orbit records for the Instance.
- **Deployments.** Wait for an unfinished deployment before starting the move.
- **Processes.** Ordinary systemd Processes keep their ids and desired states. The `vp-dev` preset also moves; Docker Processes and other presets cannot move. Finish pending Process operations, removals and previous runtime cleanup first.
- **Routes.** The Instance has no Route beside its own.
- **Symlinks.** Links must resolve within the checkout. Orbit checks dependency package links but skips installed package contents, as the [symlink rule](/reference/development-containers#migration-symlinks) defines. Orbit checks before creating the container and again before stopping host writers. It refuses broken links and external targets before downtime with `instance.migrate_symlink_unsupported`, naming every path and target. Resolve the intended data source before retrying; Orbit does not run project setup to repair links.
- **Retirement.** Every checkout scheduled for retirement has no staged or unstaged changes to tracked files and no other worktree registered on its Git directory. Orbit checks before downtime and again before moving the checkout to retention. `instance.migrate_retirement_blocked` names the checkout, other worktree paths and changed files, with total counts and the first 20 entries of each list. Ordinary untracked files, ignored or not, do not block. Submodule changes, including untracked submodule files, still refuse: the parent archive cannot preserve them. Every local branch and a detached HEAD must have no commits unreachable from all remote-tracking refs, and the repository must have no stashes. `instance.migrate_unpushed_commits` names every affected branch (or detached HEAD) and its commit count; `instance.migrate_stashes_present` names the stash count. Orbit reads the local remote-tracking refs without fetching. Orbit never stashes, pushes, prunes or removes blockers for you.

Orbit checks service hosts only when an environment selector names that service. A bare host or host/port declaration is not selection evidence. The cache selector uses CACHE_STORE, falling back to CACHE_DRIVER only when CACHE_STORE is absent; broadcasting uses BROADCAST_CONNECTION with the same fallback to BROADCAST_DRIVER. SESSION_DRIVER, QUEUE_CONNECTION, DB_CONNECTION and MAIL_MAILER select their corresponding service. REDIS_CLIENT selects a client library, not service use. Redis and Memcached host, port, password and URL declarations alone do not select a service. Database connection overrides count only for a selected database-backed cache, session or queue.

A host that is not selected by the env does not refuse migration. This does not prove that the app leaves the service unused: hardcoded application config and dynamic selection are outside this check. Orbit does not boot the app or inspect installed packages to infer service use.

Selected endpoints keep the same exact-target and HTTP proxy checks, whether their hosts are loopback, on the Node or elsewhere. Redis and Memcached use ports 6379 and 11211 when absent. Selected database connections use their common known default port; mixed ports require an explicit port. Selected SMTP mail requires an explicit port because the app may use a different default. Listener and browser settings do not become outbound endpoints without a selected connection.

The parser accepts quoted names, quoted values, supported escapes, comments and surrounding whitespace. Variable references are never expanded. Malformed or unsupported syntax refuses with the same error code, naming only the file and line, without the source value. A directory traversal or file read failure refuses before downtime with the affected path and no exception text; restore leaves the source unchanged. This check reads literal `.env` keys; it does not execute application configuration or inspect service URLs or defaults absent from those files. Each endpoint refusal names the file, key and safe host:port, and asks you to attach the exact target, correct `.env`, or use a non-network driver.

The `vp-dev` preset keeps its id, preset identity, assigned Vite port and running or stopped intent. It runs as `orbit` with the shared runtime’s `current/bin/vp`, binds `0.0.0.0`, and keeps `/__orbit/vite` on the same Route. Its checkout working directory, environment file and absolute environment paths must stay inside the checkout; Orbit maps them to `/srv/workspace`. Private environment values use the same protected delivery as other Processes.

Orbit accepts the unversioned catalogue command, preset version `1`, and the surveyed Node command that unsets the two Vite certificate variables and runs the Node account’s Vite+ binary on the assigned port. A custom command beside the preset refuses. Missing, reserved or conflicting recorded ports, duplicate `vp-dev` Processes, unknown preset versions and external paths refuse before downtime, naming the Process and reason.

A default checkout that is retained can copy uncommitted files. A checkout scheduled for retirement must pass every retirement check.

Orbit prepares the container and probes every attached target before downtime. If a target is unreachable, the checkout keeps serving, its files stay untouched, and its host Processes keep their states.

Nobody works in the checkout during the move. Orbit shows the wake page on the Route, and starts no deployment and no wake of the Instance until the move has ended.

Orbit maps known host executable locations to the container runtime. These locations are `/usr/bin`, `/usr/local/bin`, `/bin`, a home’s `.vite-plus/bin`, and a home’s `.vite-plus/js_runtime/node/<version>/bin/node`. The runtime recipe supplies command names such as `node`, `npm`, `npx`, `vp`, `bun`, `composer`, `deno` and `rg`. `phpX.Y` uses that PHP version; `php` uses the Project’s PHP version. A version absent from the runtime refuses with `instance.migrate_process_binary_unavailable`. A custom path such as `/opt/custom/vp` keeps its meaning even when its name matches a runtime command.

For `/usr/bin/env`, Orbit skips leading `NAME=VALUE` assignments and the options `-i`, `-u NAME`, `--unset=NAME` and `--` before mapping the actual command. A bare command after `env` keeps its PATH lookup. Shell command strings, `env -S` or `--split-string`, and other `env` options stay unchanged; Orbit checks the outer executable before downtime and uses Process readiness to catch a failing command. It does not parse the inner string.

Other absolute executable paths must be executable inside the container before downtime. Otherwise `instance.migrate_process_binary_unavailable` lists every unavailable Process and path. An admission refusal likewise lists every unsupported PHP version. Preset `vp-dev` keeps its preset mapping. Host Process records stay unchanged until cutover succeeds. The task receipt’s `process_translations` lists each projected change with `process_id`, `process_name`, `from` and `to`, including when the move restores the checkout.

Each moved Process whose desired state is running must be active with no pending start or restart job. Orbit reads every running Process, waits five seconds once for the whole set, then requires each to remain active with no pending job, the same nonzero main process ID and the same restart count. This settling window catches immediate crashes and restart loops before the Route moves. A Process that fails this check reports `instance.migrate_processes_failed`, names the Process and triggers recovery.

After a proven cutover, Orbit records each direct moved Process as a Project development definition and links the same Process row in the same transaction. New clones inherit those definitions. Later development deployments apply definition edits to linked copies. The definition stores supported runtime commands by name, such as `php8.5`, `vp` or `node`; Orbit resolves the name from the current runtime when it renders the unit. A supported `vp-dev` copy keeps its preset and uses each clone’s assigned port. An opaque or unknown command that passed readiness keeps its exact guest argv. An incompatible same-name definition refuses before downtime and is checked again at cutover instead of being overwritten. Production definitions keep their existing scope.

A cutover proven by the move result captures these definitions even if checkout retirement fails afterward. A failed preflight or a move restored to the checkout captures none. A one-time data repair captures proven migrated defaults that still have direct Processes. It requires the completed move’s container, seed, Process membership and exact activation content; it skips unknown commands or changed and conflicting rows without adopting them. Each Process is proved separately, so a skipped Process does not prevent capture of proven siblings or other Instances. Missing settled migration proof skips every direct Process on that Instance. A migrated default whose runtime has no seed commit is skipped and recorded with that reason; null seed fields on the Instance itself do not prevent proof from its runtime. Each skipped row is recorded in the Activity log with its Instance id, Process id and name, and reason. Read the findings with `orbit activity:list --command=instance:migrate:repair --json`, then `orbit activity:show <activity-id> --json` for the row's properties. Malformed Instance or Process data is also skipped. Unexpected failures record the exception class and a fixed safe message, without environment values or unit content. Each Process capture has its own savepoint: a failed capture leaves its definition and Process link untouched. Only a database infrastructure failure can abort the release migration. The repair reuses one Activity per skipped Process and updates its reason on a later skip, so repeats duplicate neither definitions nor findings. If a later repair captures that Process, the same Activity reports it as captured and keeps the earlier reason in `skip_reason`. Rolling back its migration keeps the captured definitions and links, because clones or later edits may already depend on them. A separate schema change removes the redundant uniqueness check on Instance Vite ports; host reservations stay unique. Its rollback restores the check only when there are no repeated nonnull Node and Vite-port pairs. Otherwise rollback reports the duplicate-group count and leaves the schema, rows and ports unchanged.

Captured command-name definitions need a renderer that supports this migration feature. Switching Gateway code back leaves the definitions, links and schema in place; it does not make those definitions compatible with an older renderer. Once container copies share a recorded Vite port, Gateway rollback must leave the removed Instance uniqueness index absent. It does not reassign ports or reverse captured data.

## Order

A Project's default Instance moves first. A non-default Instance before its default refuses with `instance.default_not_migrated`.

A non-default checkout is a linked worktree of the default's repository. So the default keeps its checkout on the Node until the last other checkout Instance of the Project has moved. That last move can retain it only after the retirement checks pass. A linked checkout also sees the default in its worktree list; the worktrees must be separated before it can retire.

After the default has moved, an Instance that is still a checkout keeps working until its own move.

## Failure

A failed move leaves the checkout Instance serving as before only if it fails before cutover and restore succeeds. A retirement failure after cutover leaves the container serving; a failed restore keeps the runtime reservation and requires inspection. Successful recovery puts the Route back when the run had started to move it, deletes the new container with its ACL, its firewall rules and its mirror, and drops the reserved runtime record. So the access to the database server that the move added goes too. The checkout and the database are never changed before the Route serves the container. Run the same command again to retry.

The task records whether the Instance moved, was restored and is ready. After a deadline or confirmed cancellation, Orbit reads the native finish. An independent failed phase keeps its code; a deadline-triggered abort keeps `operation.timed_out`, while a user abort stays cancelled. A completed restore drops the container reservation only while this migrate still owns it. A lost worker without a native finish reports an unknown end state and retains its reservation.

When the restore itself fails, the task names the failed step and Orbit keeps the reserved record, so no other Instance takes the address of a container that may be left. The site's state depends on the failed recovery step and must be inspected. Its deployments refuse with `instance.lifecycle_busy` until the same command has run again.

The retirement of the checkout is the last step. When only that step fails, the Instance stays in its container, the task fails with `instance.migrate_retire_failed`, and the source or retained checkout stays on the Node. A retirement check that finds a new blocker reports its refusal code with the same outcome, leaving the source untouched.

Schedule timers stop before copying. A rollback restores their exact captured enabled and active states after the failed container is gone. Success replaces only the moved Schedules’ checkout-dependent services; their UUID timers stay on the Node.

The command starts a task and follows it until it ends, as [`instance:deploy`](/cli/instance/deploy) does. Ctrl-C stops following, not the move, and exits 130.

## Errors

| Code | Meaning |
| --- | --- |
| `instance.id_invalid` | The Instance is missing in a call that cannot prompt, or is not a positive integer. |
| `input.cancelled` | You declined, pressed Ctrl-C, or the input ended. |
| `instance.confirmation_required` | The call cannot prompt and has no `--force`. |
| `instance.migrate_unsupported` | The Instance already runs in a container, is not active, is a production Instance, or its Node is not on the [build list](/reference/development-containers#the-build-list). |
| `instance.default_not_migrated` | The Project's default Instance is still a checkout, or its move has not ended. Move it first. |
| `instance.lifecycle_busy` | A deployment, transfer, removal or another move of the Instance is unfinished. |
| `instance.migrate_unsupported` | The Instance has a Route beside its own. |
| `project.source_defaults_incomplete` | A web-serving Project has no recorded PHP version. Run `orbit project:update PROJECT --source-access=github_app` after setting `require.php` in its source. |
| `operation.kind_unavailable` | A non-default Instance has no Conn layer or no model router. |
| `process_definition.name_taken` | A same-name definition has incompatible intent or includes production; it is not changed. |
| `instance.migrate_process_definition_unproven` | The one-time repair cannot prove a named Instance or Process. It changes no selected rows. |
| `process.target_unsupported` | The Instance has a Docker Process. |
| `process.container_preset_unsupported` | A named Process has an unknown preset or preset version, or unsupported preset options. |
| `process.container_command_unsupported` | A named preset Process has a custom command. |
| `process.container_path_unsupported` | A named preset Process has a working directory, environment file or absolute environment value outside its checkout, or a path with dot segments. |
| `process.container_port_conflict` | A named preset Process has no valid assigned port, shares it with a recorded Process or reserved container service, or duplicates another preset. |
| `instance.database_clone_unsupported` | The Instance's database server has no IPv4 address and port that a container can reach. |
| `instance.host_unavailable` | The Node has no Instance bridge, the bridge is full, no T3 port is free, or the runtime folder lacks the Project's PHP build. |
| `instance.migrate_env_service_unreachable` | A copied `.env` has an unsupported service endpoint or a value the check cannot determine safely. Endpoint errors name the offending keys and safe host:port; syntax errors name only the file and line. Both include recovery actions. The checkout keeps serving. |
| `instance.migrate_branch_changed` | The checkout is not on the branch that Orbit records. Check out that branch, or record the new one with [`instance:rename`](/cli/instance/rename). |
| `instance.migrate_symlink_unsupported` | A checkout link is broken or points outside the checkout. The error names every path, target and reason. The preflight refusal leaves the checkout serving. The same check on the copied workspace fails the move and restores the checkout if a link changed during copying. |
| `instance.migrate_retirement_blocked` | A checkout scheduled for retirement has other worktrees or tracked or submodule changes. The error names up to 20 paths per list and each total count. Before downtime the checkout keeps serving; at the final check the container keeps serving and the checkout stays. |
| `instance.migrate_unpushed_commits` | A planned retirement has local branches or a detached HEAD with commits unreachable from every local remote-tracking ref. The error names each branch or detached HEAD and its commit count. The source stays untouched. |
| `instance.migrate_stashes_present` | A planned retirement has stashes. The error names the count and leaves the source untouched. |
| `schedule.container_trigger_unsupported` | A named Schedule uses a native workflow with fixed placement. Only registered Node timers move. |
| `schedule.container_state_unsupported` | A named Schedule is not active on this Node or has an unfinished Operation. |
| `schedule.container_account_unsupported` | A named Schedule’s account is unavailable or differs from the container’s `orbit` or `agent` account, own group and `/home/<user>`. |
| `schedule.container_shell_unsupported` | A named Schedule’s shell is not `/bin/bash`. |
| `schedule.container_path_unsupported` | A named Schedule’s working directory is missing, outside the checkout, has dot segments or uses a symlink. |
| `schedule.container_command_unsupported` | A named Schedule’s command is outside the supported literal invocation form, references an external path or missing PHP build, or uses a symlink. See [Schedule migration](/reference/schedules#checkout-migration). |
| `schedule.container_artifact_unsupported` | A named Schedule’s host files differ from its registered contract, its timer has an unsupported activation state, or its service is starting or stopping. Nothing has stopped yet. |
| `instance.database_unreachable` | The new container could not reach the database server's port. |
| `instance.migrate_process_binary_unavailable` | A Process executable or PHP version is unavailable in the container. The error names the Process and path; the checkout keeps serving. |
| `instance.migrate_<step>_failed` | A step of the move failed, such as `instance.migrate_workspace_failed`. The checkout serves as before, except after `instance.migrate_retire_failed`. |
| `http.404` | The Instance is unknown. |
| `node_access.required` | The caller has no access grant to the Instance's Node. |

Selected SMTP on `127.0.0.1` or `localhost`, port 1025 or 2525, passes when this move has the Node's main Mailpit endpoint and will apply development mail. Without that endpoint, Orbit refuses and explains that the container will have no mail forwarder. Other ports and hosts keep the ordinary endpoint check. Direct `::1` stays refused because the forwarders listen only on IPv4; PHP's `localhost` connection can fall back to IPv4.

Mail setup runs after the copied `.env` and before application Processes start. It matches exactly `MAIL_MAILER=log`, with or without matching single or double quotes, using the shared [development mail rule](/reference/development-containers#development-mail). The copied file keeps its quote style and line ending; only `log` becomes `smtp`. A failed attempt or missing or malformed receipt records `instance.mail_update_failed` in `warnings`. Application starts, Route cutover and retirement continue, and mail cannot trigger rollback.

Human output shows the mailer outcome and line numbers, the named conflict skip, or the warning and repair command; JSON retains the same result fields, including `guard_line` when a preceding line is outside the shared whitelist. Repair it with [`instance:mail:update`](/cli/instance/mail-update).
