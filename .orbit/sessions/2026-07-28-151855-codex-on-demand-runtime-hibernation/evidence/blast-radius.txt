Results
- App and workspace route registration, drift probing, and repair all render
  through ProxyRouteRenderer; no legacy renderCaddySite implementation remains.
- The wake endpoint is the single internal API route at
  /api/runtime-activations/{type}/{id}.
- The idle sweep and activation path both use ProcessOwnerContext lifecycle
  groups through the existing StartProcesses and StopProcesses actions.
- app-dev app runtime containers, workspace runtime containers, and Docker
  process containers with configured always restart use unless-stopped so an
  intentional stop remains stopped.
- app-dev systemd/launchd app and workspace units are installed disabled and
  with RunAtLoad false, while explicit starts still use the existing drivers.
- Node-owned systemd, launchd, Docker, and role-baseline processes retain their
  persistent policies.
- app-prod runtime and process containers retain always restart behavior.
- Caddy, gateway, VPN, DNS, websocket, S3, metrics, and analytics service
  ownership remains outside the hibernation scope.
- Product docs explicitly preserve Caddy and node/production persistence.

Conclusion
The repository-wide inventory found no additional app-instance/workspace
registration renderer or development runtime restart surface requiring this
feature. The intentionally persistent node and production surfaces remain
separate and unchanged.
