# Human Renderer: `orbit project:show [project]`

[Back to `project:show` technical contract.](1_project-show.md)

This page describes the human-rendered terminal output for `project:show`.

**Renderer:** Human renderer.

## Primitive

- Detail: [Show detail](../../../../ux/commands/details/show-detail.md)
- Placement table: [Table](../../../../ux/commands/lists/table.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[`interactive input mode`](5.1_project-show_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Progress Tree

`project:show` is a registry read. Execution is expected to complete below one
second and does not perform slow external work or live instance-role probes. No
progress tree is rendered.

## Success Output

When the project is found:

```text

┌  Project: docs
│
├  Repository    git@github.com:my/repo.git
│
├  PHP           8.5
│
└  Project deps  findings (2 danger, 14 warning)

┌  Instance: docs.development
├  Driver        orbit
├  Node          app-1
├  URL           https://docs.test
├  Processes     vite
└  Bindings      route:docs.test, websocket:enabled, analytics:enabled

+-----------------+-----------+--------------------------------+
| WORKSPACE       | NODE      | URL                            |
+-----------------+-----------+--------------------------------+
| feature-docs    | app-1     | https://feature-docs.docs.test |
| main            | app-1     | https://main.docs.test         |
+-----------------+-----------+--------------------------------+
```

Instances render in name order. Each instance section renders its own processes
and bindings as comma-separated summaries, followed immediately by only that
instance's workspaces in workspace-name order. Missing values render as `—`.

The project summary never renders a server, path, root, URL, domain, or
environment. Placement facts appear only on instance and workspace rows.

`Project deps` remains only in the logical summary. The renderer does not claim
that this aggregate belongs to an instance or workspace.

When the project has no registered instances, the detail summary is
followed by:

```text
No instances found.
```

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Missing input

```text
Project name is required.
```

### Project not found

```text
Project 'docs' not found or not visible.
```

### Not authorized

```text
This caller is not authorized to inspect 'docs'.
```

### Gateway unavailable

```text
Gateway connection is required to show project details.
```

### Local context invalid

```text
Local node role setting is invalid.
```
