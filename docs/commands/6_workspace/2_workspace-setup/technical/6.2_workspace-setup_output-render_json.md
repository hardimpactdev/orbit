**Renderer:** JSON.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "set_up"
      },
      "workspace": {
        "name": "feature-a",
        "app": "my-app",
        "node": "app-node-1",
        "path": "/var/www/my-app/feature-a",
        "url": "https://feature-a.my-app.orbit.local",
        "php_version": "8.5",
        "php_inherited": true,
        "adopted": false,
        "lifecycle_status": "expected"
      }
    },
    "meta": {
      "node": "app-node-1",
      "http_probe": {
        "url": "https://feature-a.my-app.orbit.local",
        "result": "healthy",
        "status_code": 200,
        "duration_ms": 240
      },
      "warnings": []
    }
  }
}
```

### Fields

- `result.action`: One of `set_up`, `adopted`, `converged`. Describes what
  this run did.
  - `set_up` — first-time setup of a workspace path that is already in
    gateway intent (typically just created by `workspace:new`).
  - `adopted` — first-time setup where the path existed on the app node but
    was unmanaged. `workspace.adopted` is set to `true` for this run.
  - `converged` — idempotent re-enactment where no observable artifact
    change was needed. The durable `workspace.adopted` value is preserved
    across converged re-runs.
- `workspace`: Canonical workspace entity defined in
  [`6_workspace/README.md`](../../README.md#workspace-json-entity).
- `workspace.adopted`: Stays `true` on subsequent converged re-runs after a
  path was adopted through setup.
- `meta.node`: The owning app node slug for execution context.
- `meta.http_probe`: Setup-time HTTP probe result. This is command metadata,
  not durable workspace state and not the registry lifecycle status rendered by
  `workspace:list`.
- `meta.http_probe.url`: URL probed by the command.
- `meta.http_probe.result`: `healthy` or `unhealthy`.
- `meta.http_probe.status_code`: HTTP status code when a response was received;
  `null` when the probe timed out before a response.
- `meta.http_probe.duration_ms`: Probe duration in milliseconds.
- `meta.warnings`: Structured non-fatal command and family handoffs. Command
  warnings are not doctor issue codes unless their `code` is explicitly owned
  by a state family.
- `meta.warnings[].family`: Stable state family for doctor handoffs, or `null`
  for command-owned warnings that are not doctor issue codes.

## Error Envelope

### Setup-step failure

Returned when a sequential setup step exits non-zero. Earlier-phase intent
and runtime artifacts remain in place; the retry path is re-running the
command.

```json
{
  "error": {
    "code": "workspace.setup_step_failed",
    "message": "Setup step 'npm install' failed with exit code 1.",
    "meta": {
      "step": "npm install",
      "exit_code": 1,
      "node": "app-node-1",
      "path": "/var/www/my-app/feature-a",
      "phase": "setup_steps"
    }
  }
}
```

### Validation failure (non-absolute `--path`)

```json
{
  "error": {
    "code": "validation_failed",
    "message": "The --path value must be an absolute path on the owning app node.",
    "meta": {
      "field": "path",
      "reason": "must_be_absolute"
    }
  }
}
```

### Enactment failure

```json
{
  "error": {
    "code": "workspace.enactment_failed",
    "message": "Workspace artifact enactment on node 'app-node-1' stopped before Orbit could classify remaining drift.",
    "meta": {
      "node": "app-node-1",
      "phase": "artifacts",
      "reason": "SSH stream closed before artifact probe completed"
    }
  }
}
```

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This caller is not authorized to set up workspace 'feature-a' for app 'my-app'.",
    "meta": {
      "workspace": "feature-a",
      "app": "my-app"
    }
  }
}
```

## Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (invalid workspace name, non-absolute `--path`, missing required field). `error.meta.field` names the offending input. |
| `workspace.path_outside_policy` | The supplied `--path` resolves outside the parent app's workspace policy. `error.meta.path`. |
| `authorization_failed` | The caller cannot manage the resolved workspace or parent app. `error.meta.workspace`, `error.meta.app`. |
| `workspace.enactment_failed` | Registry write succeeded, but downstream execution failed before Orbit could classify the result as repairable drift or a command-owned setup failure. Retryable PHP-FPM, runtime, or proxy drift is reported under `success.meta.warnings[]` instead. `error.meta.{phase, node, reason}`. |
| `workspace.setup_step_failed` | A sequential setup step returned non-zero. `error.meta.{step, exit_code, node, path, phase=setup_steps}`. Earlier phases are not rolled back; retry by re-running `workspace:setup`. |

## Common Warning Codes

Non-fatal command warnings and repair handoffs are reported in
`success.meta.warnings[]`. Command-owned warnings are not doctor issue codes.
State-family warnings use the stable family code that owns the repair handoff.

| Code | Family | Meaning |
| --- | --- | --- |
| `workspace.http_probe_unhealthy` | `null` | The setup-time HTTP probe returned `>= 500` or timed out. The warning is not a `workspace` doctor issue code; inspect the app or rerun `workspace:setup` after fixing application health. |
| `workspace.fpm_config_missing` | `workspace` | Workspace PHP-FPM configuration could not be installed during enactment. `doctor --family=workspace --fix` will repair it. |
| `workspace.runtime_config_missing` | `workspace` | Managed workspace runtime configuration is absent on the app node. `doctor --family=workspace --fix` will repair it. |

Add a new value to this renderer contract before implementing another JSON
failure code.
