# Human Renderer: `orbit update`

[Back to `update` technical contract.](1_update.md)

This page describes the human-rendered terminal output for `update`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `update` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

`update` downloads the Orbit binary for the local checkout. The host PHP
toolchain is provisioned with the binary, so the renderer shows a single
animated step rather than separate dependency-install or migration steps. The
tree renders immediately, with the step idle (`○`), before the download begins;
the example below shows the step mid-download.

```text
┌ Updating Orbit
◉ Download binary
└ Working...
```

The step animates (cyan `○`/`◉`) while the download runs, then settles to a
green `●` (`Downloaded binary`) on success or a red `●` with the captured
failure output. The footer prints dim `Working...` until completion.

## Success Output

On success the tree footer becomes a full-strength success line:

```text
Updated local Orbit checkout.
```

The footer is rendered by the progress tree itself. It must not suggest that
fleet drift or runtime readiness has been verified.

## Related Multi-Node Renderer

`update` only renders the local checkout update sequence. Multi-node progress
for `update:all` is specified separately in the
[`update:all` human renderer contract](../../2_update-all/technical/6.1_update-all_output-render_human.md).
That renderer shows one row per Orbit node and changes each row through
`Pulling source`, `Installing gateway dependencies`, `Running gateway migrations`,
and `Done`.

## Failure Output

Human-rendered failures must show:

- the failed step settled to a red `●` in the tree;
- a clear prose error in the footer;
- the captured binary-download output beneath the tree when available;
- no JSON envelope.

When the local checkout directory cannot be updated, the renderer prints a
single prose line instead of the tree.

Example:

```text
Failed to update local Orbit checkout.
<captured download output>
```
