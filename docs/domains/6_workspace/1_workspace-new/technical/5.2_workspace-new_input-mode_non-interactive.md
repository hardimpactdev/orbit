# Technical Contract: `orbit workspace:new` (Non-Interactive Input)

**Input mode:** Non-interactive.

[Back to the canonical technical contract.](1_workspace-new.md)

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY. Interactive prompts are never rendered in non-interactive
mode.

## Behavior

- **Required inputs:** `name` is required as a positional argument.
  `--app` is required unless CWD inference can resolve a parent app from
  the `.orbit/config` marker or the gateway path-ownership lookup. Missing
  required input fails immediately before side effects.
- **Validation:** All inputs are validated immediately. Slug regex,
  reserved-name (`main`) rejection, combined-length limit, per-app
  workspace-name collision, and unsupported-`--php-version` checks all
  fail before any side effects.
- **No prompts:** Prompts are never rendered. The command never blocks on
  user input under any condition (`--json` or no TTY).
- **No destructive consent:** `workspace:new` has no destructive path, so
  there is no consent-bypass flag to evaluate in non-interactive mode.

## Failure Semantics

- Missing required input fails before side effects with
  `error.code=validation_failed`.
- `error.meta.field` names the missing or invalid input
  (`name`, `app`, `php_version`).
- `error.meta.reason` may describe the missing-input rule that failed.
- `--json` always emits the structured `error` envelope; non-`--json`
  non-TTY callers receive the same exit codes with prose error messages on
  stderr.
