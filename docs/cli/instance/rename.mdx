```bash
orbit instance:rename <instance> --branch=BRANCH [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Positive numeric Instance ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--branch=BRANCH` | unchanged | Record this local branch. Symbolic `HEAD` must already name it. |
| `--domain=HOST` | unchanged | Currently returns `operation.kind_unavailable`; native Route replacement is not available through rename. |
| `--json` | off | Return the recorded Instance JSON, or an error, without prompts or progress. |

Supply a nonempty branch. The command needs no `--yes` or `--force`. In a terminal, an omitted Instance selector uses the shared Instance selection prompt; in noninteractive or JSON mode it returns `instance.id_invalid`.

Rename the branch locally before recording it. The [Node agent](/reference/node-agent#checkouts) reports the checkout within seconds of the change. The Gateway checks that report: the checkout's top level and origin, and the branch that symbolic `HEAD` names. It reads nothing on the Node and starts no task. A dirty or unpublished branch can be recorded. Normal removal still requires clean, published source.

```bash
# In the Instance checkout:
git branch -m t3code/login-redirect
orbit instance:rename 1 --branch=t3code/login-redirect
```

A changed branch updates `selected_branch` and `branch_override`. Recording the already recorded branch writes nothing and preserves its existing override. The command is safe to repeat. See [recorded branch behavior](/domains/applications#record-a-renamed-branch).

The Gateway trusts the report only while the Node agent is online. When the agent is silent, or has not reported the checkout, the command refuses with `instance.branch_not_checked_out` and says it can't verify. Try again when the agent reports.

## Human output

The command prints the Instance with its selected branch. Success exits with status `0`; a refusal exits with status `1`.

## JSON and API output

The API is `POST /api/v1/instances/{instance}/rename` with `{"branch":"t3code/login-redirect"}`. It answers HTTP 200 with the Instance. The MCP tool is `instance-rename`, with `instance` and `branch`. Refusals use the shared API error shape.

## Errors

| Code | Meaning |
| --- | --- |
| `validation.failed` | Neither field was supplied, or a supplied value is null, empty, wrong-type, or an invalid Git branch name. |
| `operation.kind_unavailable` | A domain was supplied; native Route replacement is unavailable through rename. |
| `instance.id_invalid` | The CLI Instance selector is missing in noninteractive mode or is not a positive numeric ID. |
| `instance.rename_unsupported` | The Instance is production or is not a development checkout, including linked worktrees. |
| `instance.rename_inactive` | The development checkout is not active. |
| `instance.lifecycle_busy` | Another lifecycle operation owns the Instance. |
| `instance.branch_not_checked_out` | The reported symbolic `HEAD` names another branch or is detached, the checkout's top level or origin differs from its record, or the Node agent has not reported it recently. |

Authentication, access and missing-record errors retain the shared API error contract.
