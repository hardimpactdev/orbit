## Progress Tree

After complete inventory, authorization, and consent, render one branch per
instance so cleanup cannot be mistaken for a logical-record-only operation.

```text
┌ Removing logical app `my-app`
○ Remove logical app, all instances, and gateway dependents
│
○ Clean `my-app.development` on `app-dev-1`
○ Clean `my-app.production` on `app-prod-1`
└ Working...
```

Successful rows complete normally. Cleanup left after gateway removal marks
that row as a warning, continues remaining branches, and appears in the drift
footer with the instance, serving node, family, and repair command.

## Success Output

```text
Logical app 'my-app' removed with 2 instances and all dependents.
```

With drift:

```text
Logical app 'my-app' removed with 2 instances; cleanup left drift:
- my-app.production on app-prod-1 [app]: runtime configuration remains
  (run `doctor --family=app --restore`)
```

## Failure Output

- Missing consent: `Use --force to remove the logical app and every instance.`
- Cancelled confirmation: `Removal cancelled; no instances were removed.`
- Invalid selector: `Use the logical app slug. To remove one instance, run app:instance remove.`
- Authorization denied: identify every unauthorized serving node and state
  that no confirmation or removal ran.
- Gateway removal failure: identify the logical app and state that the complete
  gateway cascade was rolled back and node cleanup did not run.
