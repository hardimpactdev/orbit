# instance:clone verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, an `app-dev` Node with a candidate Instance of a Laravel Project (private repository, stored environment values, a SQLite database, a Vite+ requirement), and an `app-prod` Node with a TLD. It checks the Gateway records, the destination's files, users, services and Caddy, the vault, and real HTTPS responses. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Clone | Clone a clean candidate to the production Node. | The task succeeds. The destination has the account `orbit-app-<project>`, its home, the committed source in `releases/initial` at the candidate's commit, no `current`, the home `.env` with mode `0640` in group `orbit-env`, and the pinned Vite+ runtime. The Instance is active with no release. |
| Source only | Leave working files, dependency directories and logs on the candidate. | None of them is copied, and the candidate keeps running unchanged. |
| Environment | A candidate with `DB_*` values, WebSocket credentials, a development driver such as `QUEUE_CONNECTION=sync`, a candidate-node URL and a path outside the production home. | `DB_*` and the WebSocket credentials are not copied. `APP_ENV=production` and `APP_DEBUG=false` are forced. The result lists key-only warnings for the development driver, the candidate URL and the outside path, with no values. |
| SQLite | Clone with `--sqlite-source-path`. | A consistent snapshot is installed as `<home>/database.sqlite` with mode `0600`, owned by the account, a connection is attached under `DB`, and the digest matches. The snapshot files are removed on every Node, also after a failure. |
| Processes and Schedules | A Project with production Processes and Schedules. | The Processes are installed enabled but not started, the per-minute scheduler is a timer on the destination, and the other Schedules are published as native schedules after success. |
| Preview Route | A web Project, with `--preview-name=shop.com` on a Node with the TLD `prod.orbit`. | The key is made on the Node and the Gateway signs the CSR. Caddy serves `shop.com.prod.orbit` over TLS, probed from the control Node, and the Route is active after success. No DNS step ran. A non-web Project gets no Route. |
| Branch | Clone with `--branch` for an existing branch, a branch that does not exist, an invalid branch name, and the candidate's own branch. | The existing branch is fetched. The missing one fails the task at the fetch. The invalid name gives `validation.failed`. For the candidate's branch the commits must match. |
| Repository access | A private repository, a public one, and an origin with credentials. | The scoped token is written as a `0600` credential file, removed by the next step, and never in argv. A public origin is fetched anonymously. The origin with credentials is rejected on the Node. |
| Candidate state | A dirty candidate, one with submodules, one with another branch checked out, one whose origin is another repository, one whose commit moves after admission, one not active, one on an inactive Node, and one with no recorded source profile. | `instance.clone_candidate_source_invalid`, `instance.clone_candidate_changed`, `instance.clone_candidate_inactive` and `instance.source_profile_missing`. Nothing is written on the destination for the failed checks. |
| Candidate refusals | A candidate without a configured branch, with an attached Database connection, on a task VM Node, and one whose database slug is taken. | `instance.clone_candidate_branch_invalid`, `operation.kind_unavailable` twice, and `instance.clone_database_slug_taken`. Nothing is reserved. |
| Destination refusals | An inactive Node, a Node with no `app-prod` role, a task VM Node, a web Project's Node in an active Cluster, a web Project's Node with no TLD, a Project with a production Instance on the Node, an invalid name, an invalid preview name, a bad SQLite path, a failing GitHub token, a target of this name being removed, and a preview domain another Route owns. | `instance.node_inactive`, `instance.node_not_app_prod`, `operation.kind_unavailable` twice, `route.tld_required`, `instance.production_placement_conflict`, `validation.failed` for the name, preview and path, `operation.github_token_forbidden`, `instance.removal_conflict` and `route.domain_conflict`. Nothing is reserved. Fails today: an invalid name gives `validation.failed`, not `instance.name_invalid`. |
| Cluster and non-web | A non-web Project cloned to a Node in an active Cluster, and a non-web Project with a preview name. | The clone succeeds without a Route or a TLD. The preview name is still required. |
| Missing configuration | A candidate with no stored environment configuration. | `env.configuration_missing`. |
| Failure | Make the candidate check, the fetch, the `.env` write, the Vite+ install, the SQLite restore or the Caddy step fail, and a step with no specific code. | The task fails with the failed step. The new Instance stays reserved and shows the error, the pending Route shows it too, what the destination got stays, the candidate is unchanged, and `--json` shows no `warnings`. A step with no specific code ends with `operation.native_failed`. A Project with no Vite+ requirement skips that step. A failed snapshot cleanup is not an error. |
| Retry | Run the identical command after the failure, and after completion. | The first reuses the Instance, its Route and its database connection and repeats only what is missing. The second returns the first successful admission. |
| Changed retry | Retry with another candidate, Node, preview name, branch or SQLite path, also after completion. A new name is also tried. | `instance.clone_retry_conflict`. The new name gives `instance.production_placement_conflict`. Nothing changes. |
| Next steps | After a clone, run `instance:deploy`. | The first deploy selects a release and starts the Processes and Schedules. |
| Interrupt | Cancel a run, let one time out, and stop the executor mid-run. | Each ends like a failed step, the target stays reserved and the identical command resumes. |
| Progress and output | Follow a clone in a terminal, a narrow terminal and a pipe, and press Ctrl-C. | A tree of the steps. Ctrl-C stops following, exits 130 and leaves the clone running. The piped output has no animation or escape codes. With `--json`, nothing prints while it follows, then stdout holds only the final task with the `warnings`. Fails today: one `native` row replaces the tree. |
| Missing input | In a terminal, run the command with no arguments and cancel each list, then leave the name and the preview name empty. Then run it noninteractively and with `--json` without each input. | The terminal lists candidates and `app-prod` Nodes by name and asks for the name and the preview name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `instance.candidate_id_invalid`, `node.id_invalid`, `instance.name_required` or `instance.preview_name_required`, with no request. Fails today: the three arguments are required, so every call without them is refused by the parser, and the preview name is not prompted. |
| IDs only | A candidate or Node by name, the ID `0`, the ID `-1` passed after `--`, and `abc`. | `instance.candidate_id_invalid` or `node.id_invalid`, with no request. Fails today: `-1` without `--` is read as an option and gives a parser error. |
| Idempotency option | Run with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers it. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one target exists: the identical repeat reuses it. |
| Unknown and access | A candidate or Node ID that does not exist, and a caller without a grant to the candidate's Node or to the destination. | `http.404` and `node_access.required`. Nothing is reserved. |
