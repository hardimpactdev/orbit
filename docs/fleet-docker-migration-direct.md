# Native Docker migration

`fleet.docker_migrate` runs one native parent on its admitted Node. The Gateway records the fixed recipe, Docker Process identities, desired states and hashes. Commands and environment stay on the approved private-material path. The native worker uses the canonical Docker migration transaction and Process system lower. No agent actions or child Operations run.

`plan` reads Docker state without writing a journal or changing containers. `migrate` requires operator confirmation; fallback is explicit. `restore-policies` uses the existing private journal and never selects fallback. After prepare or policy recovery, the same native run reconciles recorded managed Processes and checks every final container state and health. Confirmed Process refusals are collected while remaining Processes are attempted. An unknown outcome fails the native run without inventing a completion or retry.

The canonical Docker lower preserves private inventory, ownership, pinned package transactions, metadata/images, original data roots and volume custody. The frozen agent code remains unchanged. Production applications must be checked after a real migration.
