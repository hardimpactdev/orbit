# `app:new` Interactive Input Mode

[Back to technical contract](1_app-new.md)

**Input mode:** Interactive.

Interactive mode applies only when:

- the CLI is attached to a TTY;
- `--json` is not present;
- `--stream-json` is not present.

It resolves missing input before the gateway create request.

## Prompt Flow

Prompts use these stable IDs and appear in this order when their source value
is missing.

| Step | Prompt ID | Primitive | Field | Label | Rendered when | Default | Validation timing |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | `app_new.node` | `datatable` | `--node` | `Select target node:` | `--node` is missing. | Configured `node:default`, when eligible; otherwise the first row. | Row selection is local; the gateway validates the invocation-specific role before source work. |
| 2 | `app_new.name` | `text` | `[name]` | `App name (slug):` | `[name]` is missing. | none | When `[name]` is read or the prompt is submitted. |
| 3 | `app_new.source_mode` | `select` | source branch | `How should the app source be created?` | No source option is supplied. | `new` | Selection submission. |
| 4a | `app_new.template_repository` | `text` | `--template-repo` | `Template repository (GitHub owner/repo):` | Template mode is selected and `--template-repo` is missing. | none | When the option is read or the prompt is submitted. |
| 4b | `app_new.new_repository` | `text` | `--new-repo` | `New private repository (GitHub owner/repo):` | Template mode is selected and `--new-repo` is missing. | none | When the option is read or the prompt is submitted. |
| 4c | `app_new.repository` | `text` | `--repo` | `Repository URL (or GitHub owner/repo):` | Clone mode is selected and `--repo` is missing. | none | When the option is read or the prompt is submitted. |

### 1. Node Resolution
If `--node` is missing, Orbit first asks the operator to choose the target app
node:
- **Primitive:** `datatable`
- **Prompt:** "Select target node:"
- **Rows:** Visible active nodes with the `app` role.
- **Validation:** Rows are active nodes with `app-dev` or `app-prod`. The
  gateway then requires `app-dev`, or `app-prod` with `--domain`, before source
  work.

When a valid local `node:default` node is configured, it is
preselected as the first row in the table. The operator can press Enter to keep
it or move to another visible node before continuing.

### 2. App Name
After the target node is resolved, Orbit prompts for the app name when
`name` is missing from the command line.
- **Prompt:** "App name (slug):"
- **Validation:** Must match `^[a-z0-9](?:[a-z0-9-]*[a-z0-9])?$` and be 40
  characters or fewer. Global registry availability is checked by the gateway
  after input resolution; app names are not scoped to the selected node.

### 3. Source
When no source flags are supplied, Orbit asks how the app source should be
created.

- **Primitive:** `select`
- **Prompt:** "How should the app source be created?"
- **Choices:** "New repository from template" and "Clone existing repository".
- **Default:** "New repository from template" (`new`).

Explicit `--repo` selects clone mode without this prompt. Supplying either
`--template-repo` or `--new-repo` selects new-from-template mode and prompts
only for the missing half of that pair. Orbit validates an explicitly supplied
half before asking for the other value.

### 4. Source Details

For **New repository from template**, Orbit asks in this order:

1. **Prompt:** "Template repository (GitHub owner/repo):"
2. **Prompt:** "New private repository (GitHub owner/repo):"

Both answers must use `owner/repo` syntax. The new repository is private.

For **Clone existing repository**, Orbit asks:

- **Prompt:** "Repository URL (or GitHub owner/repo):"

- Orbit does not prompt for git credentials, SSH keys, or personal access
  tokens. GitHub inputs are cloned with `gh repo clone` on the target app
  node; non-GitHub inputs are cloned with `git clone`. Both paths use the
  credentials that node already has provisioned. If those credentials are
  missing or wrong, source creation fails with `app.source_creation_failed`
  and the operator addresses node-side credentials directly.
- Repository URLs containing credentials, query strings, fragments,
  whitespace, or control characters are rejected at the prompt rather than
  forwarded to the gateway.

## Behavior

- **Validation Errors:** If input fails validation, the user is re-prompted
  until valid input is provided or the command is cancelled (Ctrl+C).
- **Default Values:** Optional flags like `--php-version` and `--root` use their
  defaults unless explicitly overridden; they are not typically prompted for
  unless part of an "advanced" flow.

## Test Mapping

There is no gateway-side coverage for this input mode: `app:new` interactive
input is resolved entirely in the CLI before the gateway create request is sent.

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/App/AppNewInteractiveInputModeTest.php` | Interactive prompt flow for `app:new` (scope below). |

`AppNewInteractiveInputModeTest` covers the node-resolution datatable when
`--node` is missing. A configured `node:default` remains prompted and is
preselected even when the gateway returns it later. The test also covers name
validation before gateway contact, the complete zero-argument prompt order,
and both source branches. It proves that machine mode never prompts when
required input is missing. Stable prompt IDs are contract identifiers; the
test asserts their labels and order.
