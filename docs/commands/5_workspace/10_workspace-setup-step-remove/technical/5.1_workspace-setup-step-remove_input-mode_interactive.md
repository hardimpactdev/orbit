# Technical Contract: `orbit workspace-setup-step:remove` (Interactive Input)

This contract defines behavior for **interactive input mode**.

[Back to the canonical contract.](1_workspace-setup-step-remove.md)

**Input mode:** Interactive.

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_workspace-setup-step-remove_input-mode_non-interactive.md`](5.2_workspace-setup-step-remove_input-mode_non-interactive.md)
even if the process has a TTY.

## Responsibilities

- Read supplied arguments and options.
- Prompt for missing required fields.
- Validate field-local values immediately.
- Require destructive confirmation before side effects.
- Skip the confirmation prompt when `--force` is present.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `workspace_setup_step_remove.step` | `--step` is missing. |
| 2 | `workspace_setup_step_remove.confirm` | `--force` is absent. |

## Prompt Mapping

### `workspace_setup_step_remove.step`

| Property | Value |
| --- | --- |
| Primitive | `integer` |
| Label | `Step ID to remove` |
| Source | `--step` |
| Required | yes |
| Default | none |

### `workspace_setup_step_remove.confirm`

| Property | Value |
| --- | --- |
| Primitive | `confirm` |
| Label | `Remove setup step {id} from app '{app}'?` |
| Source | interactive destructive consent |
| Required | yes |
| Default | `false` |

## Behavior

- **Validation**: Each field is validated as it is entered. A non-positive
  `step`, a step that does not belong to the resolved `(app, phase=setup)`,
  or an unauthorized `app` triggers a re-prompt with a validation message.
- **Destructive Consent**: After the target step is valid, the
  confirmation prompt is rendered unless `--force` is supplied. The
  confirmation label includes the resolved `step.id` and `app` slug so the
  operator sees exactly which record will be removed.
- **`--force` Skip**: When `--force` is supplied, the confirmation prompt
  is not rendered and the command proceeds directly to the gateway edit.

## Failure Semantics

- If the user declines the confirmation prompt, fail before side effects
  with `error.code=validation_failed`, `error.meta.field=force`, and the
  human message `Operation cancelled.`
- If the user aborts a prompt (Ctrl+C / SIGINT), exit without side effects.
- Validation re-prompts do not consume the destructive-consent prompt; the
  confirmation is always reached after the target step is valid (or the
  operator aborts).
