# Technical Contract: `orbit app:register` (Interactive Input)

This contract defines behavior for **interactive input mode**.

[Back to the canonical contract.](1_app-register.md)

**Input mode:** Interactive.

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_app-register_input-mode_non-interactive.md`](5.2_app-register_input-mode_non-interactive.md)
even if the process has a TTY.

## Prompts

| ID | Primitive | Label | Required |

| `app` | `text` | App instance | Yes |
| `node` | `datatable` | Select target node | Yes (if no default) |
| `path` | `text` | App-instance path on node | Yes (for adoption) |

## Behavior

Interactive input mode validates input as it is entered, prompts for missing
options, and confirms adoption intent. Existing placement is selected with a
dotted instance; bare logical shorthand succeeds only for one eligible visible
instance. First adoption derives `development` or `production` and creates the
logical app with that instance atomically.

- **Validation**: Each field is validated as it is entered.
- **Re-prompt**: Invalid values trigger a re-prompt with a validation message.

### Node selection

When `--node` is missing, the command presents a data table of authorized nodes.

### Path adoption

When the logical app is not registered and a path is provided, the command
confirms intent to adopt it as the deterministic first instance.
