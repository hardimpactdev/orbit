---
title: "orbit task:status"
sidebarTitle: "task:status"
description: "Show whether the tasks extension is on, every task asking for assistance, every open review-and-merge pull request, and the task places of each host."
---

```bash
orbit task:status [--json]
```

JSON returns `enabled` as `true` or `false`, `last_tick_at`, and `assistance` as a list in ascending task id order. `last_tick_at` is always null; Swamp owns execution. The human output omits that field. Each entry has the task's `id`, `project_id`, `project`, `project_code`, `title`, `status`, `assistance_kind`, `assistance_question`, and `assistance_reason`. The list is empty when no task is asking, and it is present while the extension is off. The human output shows direction requests first, under `Needs your direction`, with the task reference, title, status, and question. Failures follow under `Failures`, with the task reference, title, status, and reason. An empty list says `No groups are asking for assistance.` The [tasks reference](/reference/tasks#direction-requests) defines the four kinds: `direction`, `failure`, `removal_failure`, and `observation`.

JSON also returns `merges`: each open task with a pull request in a review-and-merge Project, or with an incoming pull request, in ascending task id order. An open task without a pull request is absent. Each entry has `id`, `project_id`, `project`, `project_code`, `title`, `status`, `pr_url`, `pr_branch`, `merge_status`, and `merge_reason`. The human output lists them under `Review and merge` with the task reference, title, status, merge status, and reason, and omits the section when the list is empty. [Merge on green](/reference/tasks#execution-ownership) defines the merge status.

JSON also returns `capacity`, with `hosts` and `queue`. Each host has `node_id`, `node`, `task_places`, `task_used`, `task_free`, `ci_places`, `ci_used`, `ci_free`, and `holders`. Each holder is one live task VM with `vm`, `pool`, `group_id`, `title`, `status`, `last_activity_at`, and `active_operation_id`. Each queue entry has `position`, `operation_id`, `kind`, `group_id`, `title`, and `waiting_since`. The human output lists them under `Task places`, one row per holder or free place, and under `Waiting for a place` when the queue is not empty. [Task places](/reference/tasks#task-places) defines the fields.
