```bash
orbit node:role:remove <node> <role> [--force] [--purge-data] [--offline] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `node` | yes | Numeric Node ID. |
| `role` | yes | The role to remove. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--force` | prompt | Confirm the removal without prompting. Required without a terminal and with `--json`. |
| `--purge-data` | off | Also delete role data. For `metrics`, the Prometheus and Grafana volumes and the stored credentials. For `websocket`, the Reverb checkout. For `ci-runner`, the Incus project, network and ACL. |
| `--offline` | off | Remove the role from a Node Orbit cannot reach: only the work on other Nodes runs. A reachable Node still gets ordinary cleanup. |
| `--idempotency-key=KEY` | generated | Reuse a key to retry the same [Operation start](/reference/operations#start-an-operation). |
| `--json` | off | Print the final Operation as JSON. |

```bash
orbit node:role:remove 7 database --force
```

In a terminal, an omitted Node is chosen from an interactive list and an omitted role from the Node's roles. Without `--force`, the CLI first shows the removal and its dependent cleanup, then asks to confirm with the Node's name and the role, with No selected; this is the consent for `--purge-data` and `--offline` too. Declining, Ctrl-C or end of input exits 1 with `input.cancelled`. A noninteractive or `--json` call without `--force` is refused with `validation.failed` (`field: force`, `reason: destructive_consent_required`); without the Node it is refused with `node.id_invalid`, and without the role with `node_role.role_required`. A declined or refused call starts no Operation.

`vpn`, `router` and `swamp` cannot be removed with this command. `app-dev` cannot be removed while the Node owns Instances, nor `app-dev` and `app-prod` while a Route targets them, nor `ingress` while public Routes use it, nor `analytics` while tracking hosts exist (`analytics.tracking_hosts_exist`). Removing the last role restores public SSH first, as [Public SSH](/reference/node-provisioning#public-ssh) describes. A CI role is not removed while CI guests still run on the Node: the run fails with `node.removal_incomplete`, and the rerun after they are drained succeeds. An unreachable Node is refused with `node.removal_incomplete` unless you pass `--offline --force`. Removal keeps role data, CI resources, release data and container volumes unless you pass `--purge-data`.

The command removes a role that is `active` or `failed`. A role that is `provisioning` or `removing` is refused until its claim is stale. A failed removal leaves the role `failed` at `remove:STEP` with the step's own error code. Finished steps stay and nothing is rolled back; run the same command again, because each removal step is safe to repeat. A failed public SSH restore leaves the Node reachable.

A role whose runs never changed the Node is removed from the Gateway record alone. The Gateway keeps that fact on the assignment. It is true only while every run for the assignment, from its first add on, failed at `Read the OS release` or `Require supported Ubuntu`. One run that ended any other way makes it false for good. So does a lost run result. It is also false for an assignment that `node:add`, a relocation or Metrics created, and for one that existed before the Gateway kept this fact.

When the fact holds, the Gateway starts no run and does not contact the Node, and the Operation ends `succeeded` at once. `--purge-data` is accepted there and has no effect. The `--offline` removal described above is not built yet: the Gateway refuses `--offline` with `operation.kind_unavailable`, on this path too. After the record is gone, `node:role:add` adds the role again.

Only one add, converge or remove runs on a Node at a time; a second call is refused with `operation.target_busy`. A role the Node does not hold, including one a finished removal already took, returns `http.404`, except `ingress`: a confirmed removal of an `ingress` role that the Node does not hold succeeds and changes nothing.

The CLI follows the Operation and prints the final result with the request ID.

## Errors

| Code | Meaning |
| --- | --- |
| `node.id_invalid` | The Node is missing or is not a positive integer, and the CLI cannot prompt. |
| `node_role.role_required` | The role is missing and the CLI cannot prompt. |
| `validation.failed` | Consent is missing, the role is protected (`vpn`, `router`, `swamp`), the role is in progress, `app-dev` has Instances, or a Route depends on the role. Nothing changes. |
| `analytics.tracking_hosts_exist` | Tracking hosts still use the `analytics` role (409). |
| `operation.kind_unavailable` | The Node is not active, or not managed over SSH. |
| `operation.target_busy` | Another add, converge or remove holds the Node. |
| `node.removal_incomplete` | The Node is unreachable and `--offline` was not given, or CI guests still run. The role is `failed` at that step. |
| `http.404` | The Node has no such role (except `ingress`), or the Node is unknown. |
| `node_access.required` | The caller has no access grant to the Node. |
