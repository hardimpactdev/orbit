# Human Renderer: `orbit node:remove [name]`

[Back to `node:remove` technical contract.](1_node-remove.md)

This page describes the human-rendered terminal output for `node:remove`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. Prompt behavior belongs to
[`interactive input mode`](5.1_node-remove_input-mode_interactive.md).
Non-interactive validation failures are rendered here as prose errors when
`--json` is absent.

## Progress Tree

Render the complete progress tree after input resolution and destructive
consent, before removal side effects begin. Destructive consent is either the
interactive confirmation prompt or `--force`. `node:remove` performs
gateway-owned registry writes and WireGuard peer teardown, so the human renderer
must not leave the operator without progress feedback even when the happy path
usually completes quickly.

Full flow:

```text
┌ Removing Node
○ Validate removal
○ Remove node grants
○ Remove WireGuard peer
○ Remove node record
└ Working...
```

When the WireGuard peer is already absent, the WireGuard step completes as a
successful idempotent step and the footer remains the normal removed footer.

When WireGuard detach fails after gateway configuration can still be removed,
the cleanup step completes as a warning, the
node record removal still runs, and the footer shows drift:

```text
┌ Removing Node
○ Validate removal
○ Remove node grants
○ Remove WireGuard peer
○ Remove node record
└ Node `app-1` removed with drift

Drift detected: WireGuard: <error message>
Run: orbit doctor --family=node --adopt
```

## Success Output

When removal succeeds with no drift:

```text
Node 'app-1' removed
```

When removal succeeds and the removed node is the current caller's own node:

```text
Node 'operator-1' removed
  This machine no longer has Orbit gateway access.
```

When removal succeeds but WireGuard detach partially failed:

```text
Node 'app-1' removed
  Drift detected: WireGuard: <error message>
  Run: orbit doctor --family=node --adopt
```

## Failure Output

Human-rendered failures must show:

- the failing phase or field;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Missing node

Already-absent removal renders this validation failure. It is not a successful
idempotent removal.

```text
Node 'app-1' not found.
```

### Gateway node removal

Rendered for any target node with role `gateway`.

```text
The gateway node cannot be removed with this command.
```

### Gateway unavailable

```text
Gateway connection is required to remove a node.
```

### Authorization failed

```text
This node is not authorized for 'node:remove' on 'app-1'.
```

### Missing destructive consent

Rendered for non-interactive human output when `--force` is absent.

```text
Use --force to remove this node.
```

### Cancelled confirmation

```text
Operation cancelled.
```
