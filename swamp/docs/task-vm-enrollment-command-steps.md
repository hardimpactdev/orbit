# Task VM enrollment command steps

Enrollment command steps receive the full public intent captured at admission. `TaskVmEnrollmentWorkflowInput::capture(TaskVm)` returns this intent. Provision roots can call `fromCaptured(array $intent, array $placement, array $connection)` after their canonical capture; the connection contains only address and public SSH host key. The supplier removes private references and bindings. It keeps the VM, guest, provider host, Gateway, issuer, router, hub, bootstrap, network and Pi Process identities.

The family projector must return the outer `{intent, execution_secrets}` envelope. The declaration opts in with `workflow_inputs: true`; `terminal_result: {job, step}` selects a result only. Shared core supplies authoritative operation ID, kind and root Node ID last. Execution-copy descriptors are `{vault, key}` names made by the shared `SwampCommandStep` helper. They remain outside public intent. No family step calls the Gateway to fetch intent or report progress.

`task-vm-enrollment-incus-public` places each step on the captured Incus host. Separate inline shell actions wait for cloud-init, inspect the guest account, verify the observer binary digest and read the public SSH host key. Commands use the exact project and VM name. No observer action is invoked. A failed observation skips every later action through native dependencies. Outputs contain public JSON.

`task-vm-runtime-command-confirm` places each step on the admitted guest. It verifies account and hostname, sudo readiness, the pinned Pi file digest, the observer service, the Pi service, and one authenticated capabilities request. The last step returns public readiness plus the captured Process identity and content hash. The Pi token resolves from a vault only in the capabilities step's environment. The request refuses redirects, has a five-second timeout and makes no retry. Invalid identity, pin or service state stops before authentication. Script diagnostics never include private values.

These fragments are preparatory and do not switch an enrollment writer or authorize a run. The Incus fragment performs observations only. UpCloud provider creation and SSH bootstrap are owned here but are not implemented in this checkpoint. Provision's Incus provider prefix stays with its owner, and `provision_direct.ts` stays intact for the Tasks caller.

Full root composition still requires root16's full-input/terminal subscriber, lane11's supported execution-copy transport, lane21's canonical issuer and worker fragments, the model/Pi owner's runtime actions, and the hub owner's fresh concurrent membership publication contract. No stale peer snapshot, intermediate Gateway checkpoint, custom retry or alternate secret transport substitutes for those dependencies. Builtin steps on proxy Nodes 1/18 remain blocked by the shared runtime owner. No grandfather entries are removed while old operational callers remain.

Focused verification uses the pinned official Swamp binary in disposable native repositories, an isolated Incus boundary and a synthetic local vault. Runtime tests keep the real inline shell, vault resolution and disposable HTTP server. They do not establish fleet readiness or perform live admission.
