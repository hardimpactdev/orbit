# Non-Interactive Input Mode: `orbit node:show [name]`

[Back to `node:show` technical contract.](1_node-show.md)

This page describes how non-interactive input mode resolves `node:show` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent after default resolution.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are known.

## Default Resolution

When `[name]` is missing, non-interactive input mode resolves the target in this
order:

1. **Local default development app node.** If a local default development app
   node is configured, use that node name.
2. **Calling node.** If the local caller has a verified active node record,
   use the calling node's name.
3. **Fail.** If neither default can be resolved, fail before side effects.

The failure uses `error.code=validation_failed` with `error.meta.field=name`.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `name` | `[name]` is absent and no default can be resolved. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `name` does not match an existing active node record visible to the caller;
- the caller is not authorized to inspect the target node.

The selected output renderer owns how these failures are displayed.
