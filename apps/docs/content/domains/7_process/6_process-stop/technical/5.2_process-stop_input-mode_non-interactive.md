# `process:stop` Non-Interactive Input Mode

[Back to `process:stop` technical contract.](1_process-stop.md)

This page describes how non-interactive input mode resolves `process:stop` input without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces non-interactive input mode even when the process has a TTY.

## Responsibilities

- Read supplied arguments, options, and local context.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required node, instance, or workspace context is absent.
- Fail before side effects when supplied input is forbidden or invalid.
- Treat omitted `[name]` as all-process selection for the resolved node, instance, or workspace context.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `context` | No `--node`, `--instance`, local instance context, or resolvable `--workspace` is available. | Fail before side effects with `error.code=validation_failed` and `error.meta.field=instance`. |
| `instance` | `--instance` is a bare app slug and that app has more than one instance. | Fail before side effects with `error.code=validation_failed`, `error.meta.field=instance`, and `error.meta.reason=instance_required`. |
