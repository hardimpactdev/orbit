```bash
orbit proof:run <commit> [--all] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `commit` | yes | Full 40 or 64 character lowercase commit SHA. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--all` | off | Run every case, not only the cases that the commit selects. |
| `--idempotency-key=KEY` | generated | Retry the same start with a permanent key. See [Start keys](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Print the final result as JSON, with the verdict of each case. |

```bash
orbit proof:run 0123456789abcdef0123456789abcdef01234567
```

In a terminal, an omitted commit is asked for with a text prompt. A noninteractive or `--json` call that omits it is refused with `proof.commit_invalid`, and so is a value that is not a full lowercase SHA. A refused call sends no request.

The command takes the commit and nothing else. The calling Node needs an access grant to the Gateway Node. Continuous integration calls it for every change to command code; see [the proof CI](/reference/feature-flow#the-proof-ci).

Built so far: the trust check, the case selection, the run in a task VM and the verdict of each case. The CI job `proof-run` exists but is report-only until a run passes end to end. Not built yet: the receipt store.

## Which commits Orbit proves

Orbit proves only code that it can trust. The commit must be the head of a branch of the Orbit repository. A commit from a pull request from elsewhere is accepted only when it is the head of that open pull request, the pull request carries the label `run-proofs`, and a maintainer approved exactly that commit. A new push needs a new approval. Orbit fetches the commit itself, so a caller cannot change what runs.

## Which cases run

Orbit lists the files that differ between the commit and its merge base with `main`, and maps each path to commands with the selection list in the commit. The cases of those commands run. `--all` runs every case. A change to the selection list, or a file list that GitHub returns incomplete, also runs every case. [Choose the cases](/reference/feature-flow#choose-the-cases) holds the mapping rule.

When only paths that need no proof changed, such as documentation and charts, the command succeeds with `Skipped — nothing to prove (proof.nothing_to_prove)`. It starts nothing. A path that matches no line of the selection list is refused with `proof.path_unmapped`, so a new kind of file never passes unproven by accident. Paths that are marked as having no case yet, and commands without a case program, are listed as uncovered in the result and do not fail the run.

## The run

Orbit creates a task group on the Orbit Project and records every input of the run: the provision of its VM, the cancel that destroys it and the commands to prove. It then starts one Swamp run, `operation-proof-run`, on Node 209, and records the result once, when that run ends. No Gateway step runs in between.

The run starts with the same provision as any task: `operation-task-provision` as a child workflow. The workspace starts exactly at the commit that you prove. The VM is a regular task VM, so it carries the Pi token and the model key of every task VM. It also gets the proof Swamp Club key that the nested fleet needs, through the same protected delivery as the `swamp-proof` Project; no other task of the Orbit Project gets it. If no host has room, the provision waits as it does for a task.

Next the run resets the nested fleet from the ready copies of the VM, `proof-fleet-prepare`. Orbit's own Swamp runs `request.py` and then each phase of `phases.py` over official SSH in the VM: a Gateway, an `app-dev` Node and an `app-prod` Node from the ready copies, the commit synced into them, and the memory snapshot `base`. The VM has no Swamp of its own for this.

Then the run starts `proof-fleet-verify` for each selected command, one after another. It runs on Node 209 and reaches the VM over SSH like every other step. The runner reads the cases file of the command, `swamp/proof/<family>/<command>.cases.yaml`, at the tested commit and runs its cases with the CLI built from the commit. The second and later command start with a restore of `base`. At the end, whatever the cases did, the run destroys the VM with the child `operation-task-cancel`. At most 8 commands run in one proof.

The cases run in batches. The first batch starts on the fresh fleet; each later batch restores `base` first and then applies its declared start state. Inside a batch the cases run one at a time. Each case asserts the promised effect, the recorded state and the Node state, on its own resources, and undoes nothing. A case that did not pass triggers a restore of `base` before the next case. A restore that fails or is not healthy within 45 seconds stops the run: the cases that did not run end `unrun` with cause `infrastructure`, and the verdicts already reached stay. Orbit retries nothing. [Verification cases](/reference/verification-cases#the-run) describes the workflow.

Each case has its own timeout, 180 seconds unless the case sets another. The operation `proof.run` has a budget of 50 minutes.

## The execution switch

`proof:run` works in two stages. Admission checks the commit and selects the cases. Execution creates the group and runs them. Execution is off by default: the Gateway setting `proof.execution` (`ORBIT_PROOF_RUN_EXECUTION`) is `false`. While it is off, a commit that selects cases is refused with `proof.execution_disabled`, and the error details name the selected cases and the uncovered paths. The command then works as a dry run: it creates no group and starts nothing. A commit with nothing to prove still succeeds, and every refusal of admission still applies.

## Verdicts

Each selected case ends `passed`, `failed` or `unrun`. A case that exceeds the budget is `failed`. A case is `unrun` when its setup could not start or the run stopped before it. Neither `failed` nor `unrun` counts as a pass. If the fleet never becomes ready, every selected case is `unrun`.

The result names the commit, each case with its verdict and duration, the uncovered paths and the evidence directory in the VM. The `program` of a case is the cases file and the case id, `swamp/proof/firewall/allow.cases.yaml#new-restricted-allow`; a `failed` or `unrun` case also carries its cause and the failed checks. The VM is destroyed after the run, so the evidence lasts only as long as a receipt store is not built; the verdicts stay in the result.

| Outcome | Exit status |
| --- | --- |
| Every selected case passed, or nothing needed a proof. | `0` |
| A selected case failed or did not run. | Nonzero. The command names each such case and the receipt link. |
| Orbit refused the request. | Nonzero, with the one-line error envelope. |
| You pressed Ctrl-C. | `130`. |
| The process received SIGTERM. | `143`. |

Ctrl-C, or `operation:cancel` on the run, stops the Swamp run, and the Gateway then cancels the group the normal way, which destroys the VM. A case that was running stops with the VM. The group is always cancelled when the run ends.

## After the run

Orbit cancels the group after success and after failure, which destroys the VM. The verdicts stay as they are. If the cancel fails, the group stays for another `tasks:cancel`.

A repeat starts a new run, because a proof checks the commit as it is now. The same `--idempotency-key` returns the original run instead of starting another.

## Errors

| Code | Meaning |
| --- | --- |
| `proof.commit_invalid` | The commit is missing or is not a full lowercase SHA, and the CLI cannot prompt. |
| `proof.commit_not_found` | The Orbit repository has no such commit. |
| `proof.commit_untrusted` | The commit is not the head of a branch of the Orbit repository, nor the head of an open pull request with the label `run-proofs` and a maintainer's approval of exactly that commit. |
| `proof.path_unmapped` | A changed path matches no line of the selection list. The details name the path. |
| `proof.cases_failed` | A selected case failed or did not run. The result holds each verdict. |
| `proof.run_failed` | The VM or the test fleet did not become ready, or the cases printed no verdict. Every selected case is `unrun`. |
| `proof.execution_disabled` | Cases are selected, and proof execution is switched off. The details hold the commit, the selected cases and the uncovered paths. |
| `proof.selection_invalid` | The selection list of the commit is malformed. The details name the line. |
| `proof.github_unavailable` | GitHub could not be read, so the commit or its cases cannot be checked. Run the command again. |
| `proof.swamp_unavailable` | No active Swamp Node exists to run the proof. |
| `node_access.required` | The calling Node has no access grant to the Gateway Node. |
| `extension.disabled` | The tasks extension is off. |
