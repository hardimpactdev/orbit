# Technical Contract: `orbit workspace:setup` (Non-Interactive Input)

This contract defines behavior for **non-interactive input mode** (e.g., CI,
scripts, or when `--json` is present).

[Back to the canonical contract.](1_workspace-setup.md)

**Input mode:** Non-interactive.

Use this input mode when either condition is true:

- the command is running without a TTY (non-tty);
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode (forces
non-interactive) even when the process has a TTY. This input mode never
renders prompts and never waits for user input; there are no fallback
prompts.

## Behavior

- **Validation**: All required inputs must be supplied via flags or derived
  from unambiguous local context. Missing required input causes an immediate
  failure before side effects.
- **No prompts**: The command will never block on user input. Prompts are
  never rendered.
- **Adoption rules**: To adopt an unmanaged path, `[name]`, `--app`,
  and `--path` must be explicitly supplied (or `--app` derivable from local
  context). The path must be absolute on the owning app node.

## Failure Semantics

- Missing required input fails before side effects with
  `error.code=validation_failed`.
- `error.meta.field` names the missing input.
- `error.meta.reason` may describe the missing-input rule that failed.
- Non-absolute `--path` fails before side effects with
  `error.code=validation_failed`, `error.meta.field=path`.

## Destructive Consent

`workspace:setup` has no destructive consent prompt and no destructive-skip
flag. Managed runtime artifacts are gateway-owned and overwritten without
prompting; there is no scenario where non-interactive mode would silently
skip a confirmation that interactive mode would have asked for.
