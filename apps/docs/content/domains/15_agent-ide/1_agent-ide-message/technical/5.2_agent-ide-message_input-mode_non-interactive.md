# Non-Interactive Input Mode: `orbit agent-ide:message [message]`

[Back to `agent-ide:message` technical contract.](1_agent-ide-message.md)

This page describes how non-interactive input mode resolves
`agent-ide:message` input.

**Input mode:** Non-interactive.

## Selection

Use non-interactive input mode when the command runs without a TTY or when
`--json` is present. `--json` forces non-interactive input mode.

## Resolution Rules

- Never render prompts.
- Resolve `message` from `[message]` or standard input when `--stdin` is
  present.
- Resolve target from `--workspace`, `--instance`, or current-directory context.
- If `message` is missing or empty, fail before target resolution with
  `validation_failed`.
- If `[message]` and `--stdin` are combined, fail before target resolution.
- If no target can be resolved, fail before adapter resolution with
  `validation_failed`.
- If `--instance` and `--workspace` are combined, fail before target resolution.
- `--json` selects the JSON renderer and this input mode only; it does not
  change authorization, effective adapter resolution, or delivery semantics.

## Failure Mapping

| Condition | `error.code` | `error.meta` |
| --- | --- | --- |
| Missing or empty message | `validation_failed` | `field=message`, `reason=missing_required_input` |
| `[message]` and `--stdin` combined | `validation_failed` | `field=message`, `reason=conflicting_message_inputs` |
| Missing target | `validation_failed` | `field=target`, `reason=missing_required_input` |
| `--instance` and `--workspace` combined | `validation_failed` | `field=target`, `reason=conflicting_target_options` |
