# Human Renderer: `orbit proxy:add`

[Back to `proxy:add` technical contract.](1_proxy-add.md)

**Renderer:** Human terminal renderer.

## Primitive

- Progress: [Progress tree](../../../ux/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

## Progress Tree

Render an in-progress tree after input resolution and before gateway writes or
backend enactment begins.

```text
┌ Adding Proxy Route
○ Validate proxy route
○ Check ownership boundary
○ Apply and verify proxy route
○ Apply and verify TLS material
└ Working...
```

For redirect routes, the same tree title is used and the footer identifies the
route as a redirect in the success summary.

## Success Output

Render the domain, kind, owner, serving node, target, redirect code when
present, TLS summary, and backend enactment result.

## Failure Output

Validation failures render the rejected field. Domain conflicts render the
existing owner. Replacement-consent failures explain that `--force` is required
in non-interactive mode. Backend enactment failures render the next doctor
command for recovery.
