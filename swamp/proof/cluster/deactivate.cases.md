# cluster:deactivate verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway, a VPN Node, an active Cluster with a Router and member Nodes that have their own TLDs and serve generated, explicit, custom proxy and public Routes, and checks the Gateway record, Caddy, certificates, firewalls, DNS and real HTTPS requests. The steps of the shared Route child have their own cases in `swamp/proof/route/reconcile.cases.md`. Today the command runs synchronously, changes the records and returns the Cluster at once, with no task: every case about the task, its steps, a failure, an interrupt or a lost response fails today for that reason, and a failure past the cutover leaves the Cluster `active` with its Routes already moved. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Deactivate with a TLD | An active Cluster with a TLD, a Router and members with Cluster-scoped Routes. Deactivate. | The task succeeds and the Cluster is `inactive`. Each affected Route has Node scope with generated domains on its Node TLD. Private DNS no longer answers Cluster names with the Router, the LAN ingress rules are gone, and requests reach the workload Nodes. The Cluster, its members and its Router stay. Fails today: the command changes the records and returns the Cluster at once, with no task. |
| Deactivate without a TLD | An active Cluster without a TLD. | The Cluster is `inactive`, Routes take Node scope, and generated domains stay on the Node TLDs. |
| Route kinds | Generated, explicit, custom proxy and tracking-host Routes. | Generated Routes fall back to the Node TLD. An explicit Route keeps its domain. A custom proxy Route keeps its Node scope and keeps serving. A tracking host moves with its Instance's Route. Fails today: the legacy path refuses a tracking host with `route.analytics_native_required`. |
| Public Route | An active public Route that the change would move. | `route.reconciliation_required`. No task, no change. Fails today: the refusal comes only after the private Routes have moved. |
| No Routes | A Cluster whose members serve no Route. | The task succeeds, the DNS answers and LAN rules are gone and the child does not run. |
| Rules last | Probe a LAN member's path to the Router during the run. | The path works until the Routes and DNS have moved, and closes in the last step. |
| Skip | Deactivate an inactive Cluster with no unfinished change. | The command succeeds with `Skipped — already inactive (cluster.state_unchanged)`, starts no task and changes nothing. Fails today: it returns the Cluster without a reason code. |
| Route refusals | A proposed domain that collides with another Route, a generated Route whose Node has no TLD, targets that would span scopes, a tracking host without an active Instance, a Route with no generation basis or one that cannot be reconciled, a targetless Route that would leave its scope, and a Route with another domain change in progress. | `route.domain_conflict`, `route.tld_required`, `route.target_scope_conflict`, `route.target_invalid`, `route.generation_basis_missing`, `route.generation_basis_invalid`, `route.scope_invalid` and `route.domain_change_conflict`. No task and no Route changes, even for the Routes that were valid. |
| Busy | Start the command while a Router change holds the Cluster for more than 30 seconds, and while another Cluster change runs. | `cluster.router_busy`. The running change is unaffected. |
| Failure before the cutover | Make a CSR, signing, publish, probe, `APP_URL` or DNS step of the child fail. | The task fails with the failed step and its code (`app-dev.certificate_request_failed`, `app-dev.certificate_sign_failed`, `route.publish_failed`, `route.probe_failed`, `route.app_url_failed` or `private_dns.publication_failed`). The Cluster stays `active`, every Route keeps its domain and scope, and the prune removes nothing the active Cluster uses. A rerun after the fix succeeds without duplicates. |
| Failure after the cutover | Make the DNS grace, the withdrawal, the DNS removal or the prune (`route.lan_firewall_failed`) fail. | The task fails with the failed step and its code (`route.dns_grace_failed`, `route.withdraw_failed`, `private_dns.publication_failed` or `route.lan_firewall_failed`). The Cluster is `inactive` and the Node scopes serve. |
| Rerun after the cutover | Rerun the command after that failure. | It is not skipped. It finishes the withdrawal, the DNS removal and the prune, and the old Routes are deleted. |
| Interrupt | Cancel a run, let one time out, and stop the worker mid-run. | Each ends like a failed step and the rerun finishes. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one task exists for the change. |
| Confirmation | In a terminal answer the prompt with No, Enter, Ctrl-C, and end of input. Then run it noninteractively and with `--json` without `--force`. | The prompt names the Cluster and the effect, and No is selected. Each decline ends with `input.cancelled` and starts no change. The noninteractive and `--json` calls are refused with `cluster.confirmation_required`. With `--force` there is no prompt, also with `--json`. Fails today: there is no prompt and no `--force`. |
| Missing input | In a terminal, run the command with no arguments and cancel the list. Then run it noninteractively and with `--json` without the Cluster. | The terminal lists Clusters by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `cluster.id_invalid`, with no request. Fails today: the Cluster is a required argument, so every call without it is refused by the parser. |
| IDs only | A Cluster by name, the ID `0`, the ID `-1`, and `abc`. | `cluster.id_invalid`, with no request. |
| Unknown and access | An ID that does not exist, a caller without a grant to a member Node, and for a Cluster with no members a caller without a grant to the Gateway Node. | `http.404` and `node_access.required`. Nothing changes. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | One progress indicator, then the final result naming the Cluster, with the task and request IDs. The piped output has no animation or escape codes. With `--json`, stdout holds only the final task. |
