# Non-Interactive Input Mode: `orbit node:new [name]`

[Back to `node:new` technical contract.](1_node-new.md)

This page describes how non-interactive input mode resolves `node:new` input
without prompts.

**Input mode:** Non-interactive.

## Selection

Use this input mode when either condition is true:

- the command is running without a TTY;
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode even when the
process has a TTY. It never authorizes reset or destructive reprovisioning;
those behaviors are outside `node:new`.

Authorization is owned by the gateway. Callers that are configured but are not
gateways resolve input like other clients and may receive a gateway
authorization failure after the request is forwarded. Unconfigured clients can
only use the first-gateway bootstrap path.

## Responsibilities

- Read supplied arguments and options.
- Apply documented defaults.
- Never render prompts.
- Fail before side effects when required input is absent.
- Fail before side effects when supplied input is forbidden or invalid.
- Evaluate path eligibility as soon as the fields needed for the rule are known,
  so non-interactive callers receive the earliest possible validation failure.
- Return a fully resolved input object to the canonical command flow.

## Required Input Failures

| Field | Missing when | Behavior |
| --- | --- | --- |
| `name` | `[name]` is absent. | Fail before side effects. |
| `host` | A host-provisioned template or `--roles` selection is selected and `--host` is absent. | Fail before side effects. |
| `tld` | `--template=app-development` or a `--roles` selection that includes `app-dev` is selected and `--tld` is absent. | Fail before side effects. |
| `ingress_node` | Private `app-prod` placement is selected and `--ingress` is absent. | Fail before side effects. |
| `redis_node` | A `websocket` template or `--roles` selection is selected and `--redis-node` is absent. | Fail before side effects. |
| `postgres_node` | An `analytics` template or `--roles` selection is selected and `--postgres-node` is absent. | Fail before side effects. |
| `clickhouse_node` | An `analytics` template or `--roles` selection is selected and `--clickhouse-node` is absent. | Fail before side effects. |

`user` defaults to `root` when SSH provisioning is used and `--user` is
absent.

For first-gateway bootstrap, `operator_name` defaults to the normalized local
short hostname when `--operator-name` is absent.

## Forbidden Input Failures

The canonical input contract owns which combinations are forbidden. This table
owns the non-interactive failure behavior for those combinations.

| Supplied input | Forbidden when | Behavior |
| --- | --- | --- |
| `--host` | Client identity with no host-provisioned role. | Fail before side effects. |
| `--template` | `--roles` is supplied, or `--operator` is supplied with a value other than `--template=operator`. | Fail before side effects. |
| `--roles` | `--template` or `--operator` is supplied. | Fail before side effects. |
| `--operator-name` | Outside first-gateway bootstrap. | Fail before side effects. |
| `--tld` | Gateway bootstrap, client identity, `--operator`, database-only, websocket-only, s3-only, metrics-only, analytics-only, ingress-only, or `app-prod` paths. | Fail before side effects. |
| `--ingress` | Any path other than private `app-prod` placement. | Fail before side effects. |
| `--redis-node` | Any path that does not include `websocket`. | Fail before side effects. |
| `--postgres-node` | Any path that does not include `analytics`. | Fail before side effects. |
| `--clickhouse-node` | Any path that does not include `analytics`. | Fail before side effects. |
| `--s3-data-path` | Any path that does not include `s3`. | Fail before side effects. |
| `--user` | Client identity with no host-provisioned role. | Fail before side effects. |

## Validation Failures

Fail before side effects when:

- `name` is not a valid gateway-registry node name;
- `name` is already assigned to an incompatible active node;
- the default `operator_name` cannot be resolved to a non-empty node name;
- `operator_name` is not a valid gateway-registry node name;
- `operator_name` equals `name`;
- `operator_name` is already assigned to an incompatible active node;
- any template or role value is unknown;
- any `--roles` value is non-canonical, including `app-development`,
  `app-production`, `gateway`, `vpn`, or `router`;
- the requested roles conflict with each other before side effects;
- `tld` is not a single lowercase DNS label without a leading dot;
- `tld` already belongs to another active node or gateway development DNS
  mapping.
- private `app-prod` placement resolves but no active `ingress`
  node is available or selected.
- `redis_node` does not resolve to an active `database` role node with Redis
  expected or installed.
- `postgres_node` does not resolve to an active `database` role node with
  PostgreSQL expected or installed.
- `clickhouse_node` does not resolve to an active `database` role node with
  ClickHouse expected or installed.
- `s3_data_path` is supplied and is not an absolute path.

The selected output renderer owns how these failures are displayed.

## Test Mapping

Primary test owners:

| Path | Coverage |
| --- | --- |
| `apps/gateway/tests/Feature/Commands/Nodes/NodeNewNonInteractiveInputModeTest.php` | Non-interactive input behavior (see scope below). |

The non-interactive contract covers:

- no-prompt selection without a TTY;
- `--json` forcing non-interactive mode without authorizing reset;
- missing required field failures before side effects;
- every gateway request requiring `--host`;
- first-gateway bootstrap `operator_name` defaulting from the normalized local
  short hostname;
- `user` defaulting;
- forbidden option failures including `--operator-name` outside first-gateway
  bootstrap;
- invalid value failures;
- renderer-independent validation metadata.

Canonical input tests own the rule table; API and forwarding tests own grant
authorization failures.
