# JSON Renderer: `orbit workspace:show [name]`

[Back to `workspace:show` technical contract.](1_workspace-show.md)

This page describes the JSON-rendered output for `workspace:show`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](5.2_workspace-show_input-mode_non-interactive.md),
even when the process has a TTY.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

`success.data.workspace` embeds the canonical workspace JSON entity from the
[Workspace README](../../README.md#workspace-json-entity) verbatim. Show-only
enrichment lives beside the entity, never inside it.

```json
{
  "success": {
    "data": {
      "workspace": {
        "name": "feature-docs",
        "project": "docs",
        "instance": "development",
        "node": "app-1",
        "path": "/home/orbit/apps/docs/.worktrees/feature-docs",
        "url": "https://feature-docs.docs.test",
        "php_version": "8.5",
        "php_inherited": true,
        "agent_ide": {
          "adapter": "opencode",
          "workspace_id": null
        },
        "adopted": false,
        "lifecycle_status": "expected"
      },
      "node": {
        "name": "app-1",
        "role": "app-dev",
        "environment": null,
        "platform": "ubuntu_24-04",
        "status": "active",
        "host": "1.2.3.4"
      },
      "inherited_processes": [
        { "name": "vite" }
      ]
    },
    "meta": {
      "registry_only": true
    }
  }
}
```

## Success Fields

| Field | Type | Meaning |
| --- | --- | --- |
| `workspace` | object | Canonical workspace JSON entity. Field meanings are owned by the [Workspace README](../../README.md#workspace-json-entity) and are not redefined here. |
| `node.name` | string | Effective workspace node slug. |
| `node.host` | string | Owning node host or address recorded in node configuration. |
| `inherited_processes[]` | object[] | Full registry list of process definitions inherited from the parent project. Not truncated. Runtime status belongs to the `process` family / process events, not `workspace:show`. |
| `inherited_processes[].name` | string | Process slug. |
| `meta.registry_only` | boolean | Always `true` for this command. Signals the payload is a registry read rather than a live probe result. |

`workspace:show` is a registry read. It does not return live runtime container,
document-root, route, process, or node-reachability checks. It does not
report a "stale-versus-tracked" indicator either: detecting workspaces that
Use [`doctor --family=workspace --json`](../../workspace-doctor.md) for
workspace runtime artifact drift output. HTTP probe results captured at setup
time belong to `workspace:setup` command metadata, not this registry view.

Route detail for the workspace hostname belongs to the `proxy` family
(`proxy:list`). Setup-run history belongs to `workspace:history` and
`workspace:log`. Renderer-internal facts such as runtime container names are
implementation detail and are not part of this contract.

If workspaces in real-world use grow inherited-process lists large enough to
require pagination, paging metadata will be added under `success.meta`
(mirroring `project:list`). The default contract emits full lists with no truncation
indicator.

## Error Shapes

### Missing required input

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Workspace name is required.",
    "meta": {
      "field": "name"
    }
  }
}
```

### Workspace not found

```json
{
  "error": {
    "code": "workspace.not_found",
    "message": "Workspace 'feature-docs' not found or not visible.",
    "meta": {
      "name": "feature-docs"
    }
  }
}
```

### Ambiguous workspace

```json
{
  "error": {
    "code": "workspace.ambiguous_name",
    "message": "Workspace name 'feature-docs' is ambiguous.",
    "meta": {
      "name": "feature-docs",
      "projects": ["docs", "api"]
    }
  }
}
```

### Not authorized

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'workspace:read' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "workspace:read",
      "serving_node": "app-1"
    }
  }
}
```

### Gateway unavailable

```json
{
  "error": {
    "code": "gateway_unavailable",
    "message": "Gateway connection is required to show workspace details.",
    "meta": []
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `workspace.lifecycle_status` | `expected`, `setup-pending` |
| `error.code` | `validation_failed`, `workspace.not_found`, `workspace.ambiguous_name`, `workspace.unsupported_for_production`, `authorization_failed`, `gateway_unavailable` |

The `error.code` values listed here are exhaustive for `workspace:show`. Add a
new value to this renderer contract before implementing another JSON failure
code. Live check outcomes never appear here: the registry read either succeeds
or the read itself fails with one of the codes above.
