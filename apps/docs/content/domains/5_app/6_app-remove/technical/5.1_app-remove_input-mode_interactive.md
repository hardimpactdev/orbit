# Interactive Input: `orbit app:remove`

[Back to `app:remove` technical contract.](1_app-remove.md)

**Input mode:** Interactive.

Use this mode only with a TTY and without `--json`.
`--force` skips the confirmation but not inventory or authorization.

## Ordering

1. Resolve or prompt for one app slug.
2. Enumerate every instance, serving node, and dependent artifact.
3. Authorize `app:remove` across the complete serving-node set.
4. Render `app_remove.confirm` unless `--force` is present.
5. Begin effects only after confirmation succeeds.

Any authorization denial stops before the confirmation. The inventory shown in
the prompt is the same frozen inventory used for execution and output.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `project_remove.app` | `[app]` is missing. |
| 2 | `app_remove.confirm` | Inventory and authorization succeeded and `--force` is absent. |

## Prompt Mapping

### `project_remove.app`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select an app to remove` |
| Source | `[app]` |
| Required | yes |
| Choices | Visible app rows. Row key is the exact app slug; columns are name, repository, instance count, and workspace count. |
| Validation timing | When the argument is read or the row is submitted. |
| Invalid terminal behavior | Fail with `app.not_found` when no visible apps exist. |

### `app_remove.confirm`

| Property | Value |
| --- | --- |
| Primitive | `confirm` |
| Label | `Remove app '{app}', instances [{instance_names}], and all listed dependents? This cannot be undone.` |
| Body | Shows every instance with its driver and serving node, followed by exact proxy-route, schedule, workspace, process, runtime, and eligible-path counts. |
| Source | Interactive destructive consent for the complete cascade. |
| Required | yes |
| Default | `false` |
| Validation timing | After complete inventory and authorization, before effects. |
| Invalid terminal behavior | Decline returns `validation_failed` with `meta.field=force` and `meta.reason=cancelled`; no effects. |

When the current workspace belongs to any affected instance, the body also
states that the current environment will be invalidated. The prompt ID and
complete cascade remain unchanged.

## Failure Semantics

- Hostnames and dotted selectors fail with `meta.reason=logical_slug_required`.
- Any serving-node denial returns `authorization_failed` before the prompt.
- Declining or aborting the confirmation cancels the entire cascade; no
  instance or logical record is removed.
- `--force` is consent for every inventoried instance and dependent. It cannot
  request parent-only or partial removal.
