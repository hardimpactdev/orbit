# Interactive Input Mode: `orbit node:default [name]`

[Back to `node:default` technical contract.](1_node-default.md)

This page describes how interactive input mode resolves `node:default` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_node-default_input-mode_non-interactive.md`](5.2_node-default_input-mode_non-interactive.md) even if the process has a TTY.

App-node callers and gateway callers are rejected before this input mode
renders any prompt.

## Responsibilities

- Read any supplied arguments and options.
- When no `name` or `--clear` is supplied, query the gateway for
  visible development app nodes and prompt the operator to choose one.
- For the `set` sub-action, accept `[name]`.
- For the `clear` sub-action, do not prompt; execute the clear directly.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `node_default.name` | No `[name]` and no `--clear` are supplied. |

The `clear` sub-action does not render prompts.

## Prompt Mapping

### `node_default.name`

| Property | Value |
| --- | --- |
| Primitive | `select` |
| Label | `Default development app node` |
| Source | `[name]` or visible development app-node list |
| Required | yes when neither target source nor `--clear` is supplied |
| Choices | Visible development app nodes the current identity may read from the gateway registry. |
| Default | Current local default when it is present in the visible development app-node choices; otherwise none. |
| Validation timing | When `[name]` is read, or when the prompt is submitted. |
| Invalid terminal behavior | Show validation message and re-prompt. |

When `[name]` is supplied on the command line, it is validated
immediately without prompting. If invalid, the command fails before side
effects.

## Failure Semantics

- Missing target input is collected through the `node_default.name` prompt before
  side effects.
- Invalid field-local input shows a validation message and re-prompts until the
  value is valid or the user aborts.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If the target node is not a development app node or is not
  visible, fail before side effects after the name is resolved.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
