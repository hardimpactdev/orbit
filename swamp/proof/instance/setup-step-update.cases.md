# instance:setup-step:update verification cases

`instance:setup-step:update` changes a row of the Project's list and has no chart. The proof runs the built CLI against a fresh nested topology with a Project that has setup lists of different sizes, and compares the output with the Gateway records. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Change the command | Update only `--command`. | The command changes. The timeout and the position stay. The result is at once, with no task and no file written on any Node. |
| Change the timeout | `--timeout=1`, `--timeout=540`, `--timeout=0`, `--timeout=541` and `--timeout=abc`. | The first two are stored. `0` and `541` give `validation.failed`. `abc` gives `lifecycle_step.timeout_invalid` before any request. Fails today: the reason sits under `body`, not under the failed field. |
| Move | Move a step with `--before` and with `--after`, then with both, with one naming no step, and with one naming the step itself. | The first two move it and the others keep their order. The others give `validation.failed`. Nothing is stored for a refusal. |
| Rebalance | Raise a step to 540 seconds with `--rebalance` lowering another, a rebalance alone, a rebalance naming the step itself, one naming an unknown step, one naming a step twice, one with timeout 0 or 541, more than 32 entries, and a malformed value. | The first stores both changes in one write. A rebalance alone succeeds and returns the step unchanged. The next five give `validation.failed`, and the malformed one `lifecycle_step.rebalance_invalid`. Nothing is stored for a refusal. |
| List cap | A change that raises the total over 540 seconds, and a change to a list stored before the cap. | `validation.failed` for the first, with nothing stored. The old list accepts any change that does not raise its total. Fails today: the reason sits under `body`. |
| No change option | The name and Project only, and with only an empty `--command=`. | `validation.failed` (`Provide at least one lifecycle step update field.`). Nothing changes. Fails today: the reason sits under `body`. |
| Same values | Update a step to the values it has. | The command succeeds and changes nothing. |
| Empty values | An empty `--command=`, `--before=` and `--after=` alongside a real change, an empty `--timeout=`, and an empty `--rebalance=`. | The first three are read as omitted. The empty `--timeout=` gives `lifecycle_step.timeout_invalid` and the empty `--rebalance=` gives `lifecycle_step.rebalance_invalid`, before any request. |
| Command limits | A blank command, a 16 KiB one, one over 16 KiB, with a NUL byte, and not valid UTF-8. | The 16 KiB one is stored. The others give `validation.failed`. Fails today: a blank command passes the Gateway and is stored. |
| Unknown step | A name the Project's setup list does not hold, a name of its teardown list, and a name that is not a valid step name. | `setup_step.not_found` for the first two, with nothing changed. The last gives `http.404`. Fails today: that case is not `setup_step.not_found`. |
| Rename | Try to change the name. | There is no option. Remove the step and create it again. |
| No run | After an update. | The step ran nowhere. A later `instance:setup` or `instance:create` uses the new values. |
| Output forms | A wide and a narrow terminal, a 16 KiB command, output piped to a file, and `--json`. | A detail `Setup step: <name>` with the Project by name, Timeout and Command and the request ID at the wide width, and labeled records at the narrow one, with the command wrapped and never cut. The piped output has no animation or escape codes. With `--json`, stdout holds the step with `request_id`. Fails today: the output is three lines, `Name:`, `Command:` and `Timeout:`, then a progress footer, with no title, Project or request ID, and the step response carries no Project name. |
| Missing input | In a terminal, run the command with no name and no `--project`, and cancel each list. Then run it noninteractively and with `--json`. | The terminal lists Projects and then the Project's setup steps by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `lifecycle_step.name_required` or `project.id_invalid`, with one error and no request. Fails today: the name is a required argument, the Project is refused even in a terminal, and two missing inputs print two errors. |
| IDs only | A Project by name, the ID `0`, the ID `-1`, and `abc`. | `project.id_invalid`, with no request. |
| Unknown and access | A Project ID that does not exist, and a caller without a grant to any Node that holds an Instance of the Project. | `http.404` and `node_access.required`. Nothing changes. |
| Activity | After a successful update and a failed one. | Activity holds no command text in the stored input or result. |
