# Technical Contract: `orbit workspace-teardown-step:add` (Non-Interactive Input)

This contract defines behavior for **non-interactive input mode** (e.g., CI,
scripts, or when `--json` is present).

[Back to the canonical contract.](1_workspace-teardown-step-add.md)

**Input mode:** Non-interactive.

Use this input mode when either condition is true:

- the command is running without a TTY (non-tty);
- `--json` is present.

`--json` selects the JSON renderer and forces this input mode (forces
non-interactive) even when the process has a TTY. This input mode never
renders prompts and never waits for user input; there are no fallback
prompts.

## Behavior

- **Validation**: All required inputs must be supplied via flags or derived
  from unambiguous local context. Missing required input causes an
  immediate failure before side effects.
- **No prompts**: The command will never block on user input. Prompts are
  never rendered.
- **App Resolution**: `--app` must be supplied explicitly, resolvable from
  the caller's `.orbit/config` marker, or resolvable through gateway
  path-ownership lookup keyed on `(caller node identity, absolute cwd)`.
  If none of those resolve to an authorized app, the command fails with
  `error.code=validation_failed`, `error.meta.field=app`. Project files
  such as `composer.json`, `package.json`, and `.php-version` are never
  inspected.
- **Timeout Validation**: `--timeout` must be a strict positive integer.
  `0` is rejected before side effects with `error.code=validation_failed`,
  `error.meta.field=timeout`,
  `error.meta.reason=must_be_positive_integer`.

## Failure Semantics

- Missing required input fails before side effects with
  `error.code=validation_failed`.
- `error.meta.field` names the missing or invalid input.
- `error.meta.reason` may describe the missing-input rule that failed
  (e.g. `must_be_positive_integer` for `--timeout=0`).

## Destructive Consent

`workspace-teardown-step:add` has no destructive consent prompt and no
destructive-skip flag. The command writes one new gateway record and never
removes or overwrites existing records; there is no scenario where
non-interactive mode would silently skip a confirmation that interactive
mode would have asked for.
