# JSON Renderer: `orbit proxy:remove`

[Back to `proxy:remove` technical contract.](1_proxy-remove.md)

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Shape

```json
{
  "success": {
    "data": {
      "route": {
        "domain": "redirect.docs.test",
        "kind": "redirect",
        "owner": {
          "type": "custom",
          "name": null
        },
        "node": "app-1",
        "target": {
          "type": "redirect",
          "value": "https://docs.test"
        },
        "redirect_code": 302,
        "tls": {
          "managed_by": "orbit",
          "trusted_by_gateway_ca": true
        },
        "status": "removed"
      }
    },
    "meta": {
      "backend_removed": true,
      "tls_removed": true,
      "removal_reason": "custom",
      "warnings": []
    }
  }
}
```

Orphan-owner force removal uses the same envelope with
`success.meta.removal_reason=orphan_owner` and
`success.meta.owner_type` set to the public owner type that was missing
(for example `workspace`).

## Error Shape

Cleanup failure is a hard error. The registry row remains; cleanup flags stay false:

```json
{
  "error": {
    "code": "proxy.cleanup_failed",
    "message": "Proxy route 'redirect.docs.test' registry is intact, but backend/TLS cleanup failed: Failed to remove extra proxy route redirect.docs.test from app-1",
    "meta": {
      "domain": "redirect.docs.test",
      "node": "app-1",
      "backend_removed": false,
      "tls_removed": false,
      "next_command": "doctor --family=proxy --restore --node=app-1"
    }
  }
}
```

Missing destructive consent uses the shared validation shape:

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to remove this proxy route.",
    "meta": {
      "field": "force",
      "reason": "destructive_consent_required"
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `success.data.route` | object | Removed proxy route (custom or orphan-owner). |
| `success.data.route.status` | `removed` | Registry deletion completed after successful cleanup. |
| `success.meta.backend_removed` | boolean | Whether backend route cleanup completed. |
| `success.meta.tls_removed` | boolean | Whether route-scoped TLS cleanup completed. |
| `success.meta.removal_reason` | `custom` or `orphan_owner` | Why gateway configuration removal was allowed. |
| `success.meta.owner_type` | string | Present when `removal_reason=orphan_owner`; public owner type that was proven missing. |
| `error.code` | `validation_failed`, `gateway_unavailable`, `authorization_failed`, `proxy.not_found`, `proxy.owned_route_denied`, `proxy.cleanup_failed` | Stable command failure code. |
| `error.meta.backend_removed` / `error.meta.tls_removed` | boolean | On `proxy.cleanup_failed`, both are `false` and the registry row remains. |
| `error.meta.next_command` | string | Doctor repair handoff for genuine cleanup failure. |

## Test Mapping

| Path | Coverage |
| --- | --- |
| `apps/cli/tests/Feature/Commands/Proxy/ProxyWriteCommandTest.php` | JSON `proxy:remove` destructive consent failure, forced DELETE success envelope, cleanup metadata, and gateway error passthrough. |
| `apps/gateway/tests/Unit/Services/Proxy/ProxyRouteIntentTest.php` | Cleanup failure keeps the registry row and returns hard `proxy.cleanup_failed`. |


Documented `error.code` values named for coverage tracking: `validation_failed`,
`gateway_unavailable`, `authorization_failed`, `proxy.not_found`,
`proxy.owned_route_denied`, and `proxy.cleanup_failed`. Destructive consent is
classified by `error.meta.reason=destructive_consent_required` and is asserted
through the forced and unforced `proxy:remove` CLI paths.

There is no gateway-side coverage for this command-local mapping: input handling and renderer behavior live in `apps/cli`. Gateway API behavior is mapped in the command contract file when a gateway-side surface exists.
