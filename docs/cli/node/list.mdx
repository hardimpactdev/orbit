---
title: "orbit node:list"
sidebarTitle: "node:list"
description: "List the Nodes you can reach with their status, agent, roles, and addresses."
---

```bash
orbit node:list [--json]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--json` | off | Print the Nodes as JSON. |

The list shows what Orbit has recorded for each Node. It does not contact the Nodes, so it works while a Node is unreachable. A caller sees the Nodes it has an access grant to; the Gateway Node, and any Node with a grant to it, sees every Node. Nodes are sorted by name, then ID.

| Column | Meaning |
| --- | --- |
| `ID`, `NAME` | The Node's ID and its unique name. |
| `STATUS` | The Node's recorded status. A Node whose add or removal failed keeps `failed_step` and `error_code` in JSON. |
| `AGENT` | The Node agent's liveness: `online`, `offline`, `not seen`, or `unknown`. [`node:show`](/cli/node/show) also shows since when an agent is offline. A Node without an agent shows `—`. |
| `ROLES` | Every assigned role, comma-separated, including assignments that are not active. |
| `PLATFORM`, `TLD`, `USER` | The Node's platform, its development TLD with a leading dot, and its managed user. |
| `CLUSTER` | The name of the Cluster the Node belongs to. |
| `WIREGUARD`, `LAN` | The Node's WireGuard and LAN addresses. |

JSON includes each Node's `role_assignments` with the [shared recorded lifecycle and failure details](/cli/node#recorded-role-assignments).

A missing value shows `—`. In JSON the Cluster has its `cluster_id` and its name, and each Node carries its `agent` state. An empty list says `No nodes.`.
