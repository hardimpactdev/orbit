Record assistance on an external, non-terminal group after all its children have ended. This does not select or reopen a subtask. A request sets group Direction using explicit operator replacement semantics. A resolution clears group Direction only; it never clears a safety failure or a child's request. Neither sends work. The [post-child assistance contract](/reference/tasks#group-assistance-after-all-children-end) owns the guards and effects.

```bash
orbit tasks:group:comment:create [group] [--type=TYPE] [--body=TEXT] [--author=NAME] [--json]
```

| Option | Interactive default | Meaning |
| --- | --- | --- |
| `group` | select a task group | Numeric group ID; no subtask ID is accepted. |
| `--type=TYPE` | select | `assistance_requested` or `resolution`. |
| `--body=TEXT` | prompt | Nonblank text, at most 100,000 characters. Name the work item, stage, cycle and decision when asking. |
| `--author=NAME` | local login name | Author, at most 255 characters. Required explicitly with `--json` or `-n`. |
| `--json` | off | Return the comment and request ID as JSON. |

A terminal prompts for missing inputs. A `--json` or `-n` call requires them before any network call. There is no agent-thread or receipt option. `tasks.group_closed` refuses an ended group, and `tasks.assistance_subtask_open` refuses a group with an open child. Read the full current request before answering; there is no versioned matching-resolution protocol. Repeating a write may add another audit comment even when assistance state is unchanged.
