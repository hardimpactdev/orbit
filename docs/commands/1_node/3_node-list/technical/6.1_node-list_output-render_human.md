# Human Renderer: `orbit node:list`

[Back to `node:list` technical contract.](1_node-list.md)

This page describes the human-rendered terminal output for `node:list`.

**Renderer:** Human renderer.

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `node:list` takes no required
arguments and does not prompt in any input mode.

## Progress Tree

`node:list` is a read-only registry query. Execution is expected to complete
below one second and does not perform slow external work in the base operation.
No progress tree is rendered.

When `--doctor` is present, doctor checks may take longer. The human renderer
may show a simple spinner or progress indicator while doctor checks run, but the
current contract does not require a full progress tree because doctor is an
explicit secondary operation.

## Success Output

Human output is a table grouped by role. The `STATUS` column renders the
durable registry lifecycle (`provisioning` or `active`), matching the JSON
contract. The `PLATFORM` column renders the structural platform-version
identifier (`ubuntu_24-04`, `macos_15-4`) or `unknown` when the gateway has
not detected the platform yet.

```text
ROLE      NAME        ENVIRONMENT   PLATFORM       STATUS
app       app-1       development   ubuntu_24-04   active
app       app-2       production    ubuntu_24-04   active
gateway   gateway-1   —             ubuntu_24-04   active
control   control-1   —             macos_15-4     active
```

When filters reduce the result set:

```text
ROLE   NAME   ENVIRONMENT   PLATFORM       STATUS
app    app-1  development   ubuntu_24-04   active
```

When no nodes match the filters, or when no nodes are visible to the
authenticated caller:

```text
No nodes found.
```

When `--doctor` is present and no issues are found:

```text
ROLE      NAME        ENVIRONMENT   PLATFORM       STATUS
app       app-1       development   ubuntu_24-04   active

Doctor: All nodes healthy.
```

When `--doctor` is present and issues are found, the command still exits
zero. Doctor findings are reported under the table without changing the
exit status of the list operation:

```text
ROLE      NAME        ENVIRONMENT   PLATFORM       STATUS
app       app-1       development   ubuntu_24-04   active

Doctor: 1 issue found.
  app-1: WireGuard peer not responding (node.wireguard_peer_missing)
  Run `orbit doctor --family=node --fix` to repair.
```

## Failure Output

Human-rendered failures must show:

- the failing field or condition;
- a clear prose error;
- no JSON envelope;
- next-step guidance only when the operator can act on it.

### Invalid filter value

```text
Invalid value for --role: 'invalid'. Allowed values: gateway, app, control.
```

### Gateway unavailable

```text
Gateway connection is required to list nodes.
```

### Authorization failed

```text
This node is not authorized to read the node registry.
```

### Local context invalid

```text
Local node role setting is invalid.
```
