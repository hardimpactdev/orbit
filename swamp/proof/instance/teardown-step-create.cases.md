# instance:teardown-step:create verification cases

`instance:teardown-step:create` records a row on the Project and has no chart. The proof runs the built CLI against a fresh nested topology with a Project that has teardown lists of different sizes, and compares the output with the Gateway records. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Add at the end | Create a step with only `--project` and `--command`. | The step is last in `teardown-step:list`, with the timeout 240. The result is at once, with no task and no file written on any Node. |
| Position | Create steps with `--before=NAME` and `--after=NAME`. | Each lands at the named place and the others keep their order. |
| Timeout | `--timeout=1`, `--timeout=540`, `--timeout=0`, `--timeout=541`, and `--timeout=abc`. | The first two are stored. `0` and `541` give `validation.failed`. `abc` gives `lifecycle_step.timeout_invalid` before any request. |
| Name | `a`, a name of 63 characters, a name of 64, one with an upper-case letter, a leading hyphen, and a duplicate, then the identical create repeated. | The first two are stored. The others give `validation.failed`, and the repeat gives the same refusal: there is no skip. Two creates of the same name at once store one. |
| Command | A 16 KiB command, a multiline one, one whose multibyte characters reach exactly and then pass 16 KiB, an empty `--command=`, a blank one made of spaces, one with a NUL byte, one that is not valid UTF-8, one over 16 KiB, and `@orbit/ci-caches`. | The first three that fit are stored whole. The empty one gives `lifecycle_step.command_required` before any request, in a noninteractive call. The others give `validation.failed`. `@orbit/ci-caches` is rejected when the list runs, not when it is recorded. Fails today: a blank command passes the Gateway and is stored, and `@orbit/ci-caches` is stored without a refusal. |
| Before and after | `--before` with `--after`, `--before` naming no step, and an empty `--before=`. | `validation.failed` for the first two, and nothing is stored. The empty one is read as omitted and the step goes at the end. |
| List limits | Create the 33rd step, and a step that makes the timeouts total 541 seconds, and a change to a list stored before the cap. | `validation.failed`, and nothing is stored, for the first two. The old list accepts any change that does not raise its total. Fails today: every refusal says only `The request data is invalid.` with the reason under `body`, not under the failed field. |
| Rebalance | Add a 180-second step to a full list with `--rebalance` lowering another step, a rebalance naming the step itself, one naming an unknown step, one naming a step twice, one with timeout 0 or 541, more than 32 entries, and a malformed value. | The first stores both changes in one write. The next five give `validation.failed`, and the malformed one `lifecycle_step.rebalance_invalid`. Nothing is stored. |
| No run | After a create. | The step ran nowhere. The next `instance:destroy` of a development Instance of the Project runs it, and a failing step stops that removal. `instance:setup` and `instance:create` do not run it. |
| Output forms | A wide and a narrow terminal, a 16 KiB multiline command, output piped to a file, and `--json`. | A detail `Teardown step: <name>` with the Project by name, Timeout and Command and the request ID at the wide width, and labeled records at the narrow one, with the command wrapped and never cut. The piped output has no animation or escape codes. With `--json`, stdout holds the step with `request_id`. Fails today: the output is three lines, `Name:`, `Command:` and `Timeout:`, then a progress footer, with no title, Project or request ID, and the step response carries no Project name. |
| Missing input | In a terminal, run the command with no name, no `--project` and no `--command`, and cancel each prompt. Then run it noninteractively and with `--json`. | The terminal asks for each input. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `lifecycle_step.name_required`, `project.id_invalid` or `lifecycle_step.command_required`, with one error and no request. Fails today: the name is a required argument, the Project and the command are refused even in a terminal, and two missing inputs print two errors. |
| IDs only | A Project by name, the ID `0`, the ID `-1`, and `abc`. | `project.id_invalid`, with no request. |
| Unknown and access | A Project ID that does not exist, and a caller without a grant to any Node that holds an Instance of the Project. | `http.404` and `node_access.required`. Nothing is stored. |
| Activity | After a successful create and a failed one. | Activity holds no command text in the stored input or result. |
