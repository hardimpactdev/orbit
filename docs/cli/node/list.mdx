```bash
orbit node:list [--json]
```

The command takes no Node ID or selector. It lists visible Nodes, sorted by name and then ID.

| Option | Default | Meaning |
| --- | --- | --- |
| [`--json`](/reference/cli-ux#input-and-output-modes) | off | Print the Node list as JSON. |

## Output

The human table uses [shared list formatting](/reference/cli-ux#results) and shows:

| Column | Meaning |
| --- | --- |
| ID | Numeric Node ID. |
| Name | Unique Node name. |
| Status | Recorded Node lifecycle status. |
| Agent | Recorded agent liveness. |
| Roles | Role assignments. |
| Platform | Recorded host platform. |
| TLD | Node domain suffix. |
| User | Managed OS user. |
| Cluster | Cluster name. |
| WireGuard | Recorded WireGuard address. |
| LAN | Recorded LAN address. |

JSON returns `nodes` and `request_id`. Each Node keeps its IDs, recorded addresses, agent state, `roles` names and Node-level `failed_step` and `error_code`. It also includes `cluster_name` alongside `cluster_id`, and `assignments`.

The shared role projection used by `node:list`, `node:show` and `node:role:list` includes every assigned role in any status (`active`, `provisioning`, `failed`, `removing`), with identical `role`, `status`, `failed_step` and `error_code` values. Each assignment also has its `id`; absent failure fields are null. Native failed-step labels keep their recorded spaces and case. Human output may compact an assignment as `gateway (active)` or `app-dev (failed)`.

An empty result succeeds with `No nodes.`; JSON has an empty `nodes` array. A Node without a Cluster has a null `cluster_name` and `cluster_id`.

### Missing and stale agent data

Agent liveness comes from recorded heartbeats, not from a request-time probe. See [Node agent liveness](/reference/node-agent#liveness) for the shared rules.

- A Node whose agent has never reported shows `not seen` (`not_seen` in JSON).
- A Node with stale heartbeats shows `offline`, with its last seen time in `agent.since`.
- If the Gateway's agent view is missing or stale, liveness is `unknown`, not `offline`.
- A Node with no observing agent has a null `agent` in JSON.

All these Nodes remain in the result with their available recorded fields. Missing or stale facts neither fail the list nor trigger a refresh.

## Large fleets

The list uses one Gateway query per page of Nodes and no per-Node work beyond the shared projection. Listing 200 Nodes completes in under 1 second. This is a query and projection requirement, not an extra CLI paging option.

## Example

```bash
orbit node:list
```

## How it works

Access follows the [shared Node authority rule](/cli/node#authority). The Gateway reads only stored Node records and agent facts. It does not contact a Node, Grafana or another external system during the request. It starts no Operation and changes no records. Running it again reads the current recorded state; there is no change to replay or skip.
