# Human Renderer: `orbit doctor`

[Back to `doctor` technical contract.](1_doctor.md)

This page describes the human-rendered terminal output for `doctor`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../ux/progress/progress-tree.md)
- Result tables: [Table](../../../ux/lists/table.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `doctor` has optional filters
and fails invalid combinations before probes or side effects.

## Output Contract

Human output is an operator report, not a terse status line. It must make these
facts visible without requiring JSON:

- selected mode: `verify`, `fix`, or `adopt`;
- resolved scope: family list, node, app, workspace, and whether `--self`
  resolved the caller identity;
- whether the final result is healthy;
- summary counts for remaining issues and attempted actions;
- issue groups by family and kind;
- action results for `--fix` or `--adopt`;
- manual next steps for issues that cannot be resolved automatically.

Healthy output must not imply that unselected families, nodes, apps, or
workspaces were inspected. When the resolved scope is narrow, the scope line
must stay narrow.

## Progress Tree

`doctor` may perform gateway, remote probe, and repair/adoption work, so the
human renderer must show an in-progress tree after scope authorization and
before probes or side effects begin.

```text
┌ Running Orbit Doctor
○ Resolve scope
○ Authorize scope
○ Probe node
○ Probe app
○ Probe workspace
○ Probe process
└ Working...
```

The family probe steps are populated from the resolved family scope in the order
reported by the JSON payload. Omitted `--family` uses every doctor-supported
family. Narrow family scopes render only selected families; they must not show
placeholder steps for unselected families.

In `--fix` or `--adopt` mode, action steps appear immediately after the family
that owns them.

```text
┌ Running Orbit Doctor
○ Resolve scope
● Probe app
○ Fix app.fpm_config_missing for docs
└ Doctor actions complete
```

Each step is updated in place as it starts, succeeds, is skipped, or fails. The
final tree must make remaining drift and failed actions visible.

## Result Layout

After the progress tree completes, render the report in this order:

1. Status heading.
2. Scope summary.
3. Summary table.
4. Centered result divider.
5. Clean result banner, only when the run is healthy and no actions were
   attempted.
6. Issue groups, only when issues remain.
7. Action table, only when actions were attempted.
8. Next-step hints for unresolved issues when available.

The status heading is one of:

| Condition | Heading |
| --- | --- |
| Healthy verify | `Doctor healthy.` |
| Unhealthy verify | `Doctor found drift.` |
| Healthy fix | `Doctor repaired drift.` |
| Unhealthy fix | `Doctor could not repair all drift.` |
| Healthy adopt | `Doctor adopted compatible reality.` |
| Unhealthy adopt | `Doctor could not adopt all drift.` |

The scope summary is rendered as short key-value lines:

```text
Mode: verify
Scope: families=node,app node=beast app=— workspace=— self=false
```

Use `—` for omitted human-display scope values. JSON keeps `null`.

The summary table contains:

| ISSUES | FIXED | ADOPTED | SKIPPED | CONFLICTS | FAILED |
| --- | --- | --- | --- | --- | --- |

Column values come from `doctor.summary`. If a summary key is absent, render
`0` rather than omitting the column.

## Result Divider

After the summary table, render the old centered result divider before the
clean banner, issue groups, or action table. The divider label is:

```text
DOCTOR RESULT
```

The label is spaced and centered within a dim horizontal rule:

```text
──────────── D O C T O R   R E S U L T ────────────
```

The divider width should align with the widest rendered result table when
practical. It separates the summary counts from the diagnostic result body.

## Clean Result Banner

When `doctor.healthy=true`, `doctor.issues=[]`, and `doctor.actions=[]`, render
a bordered green success banner after the summary table. This preserves the old
doctor result affordance: a clean run should have a visible positive result, not
just an absence of rows.

The banner text is:

```text
Everything is healthy!
```

The banner uses the same bordered success-box style as the old doctor renderer:

```text
 ┌────────────────────────────────┐
 │                                │
 │     Everything is healthy!     │
 │                                │
 └────────────────────────────────┘
```

The box width should align with the widest rendered result table when practical.
If no table is rendered, use enough padding for the message to read as a banner
rather than a normal line.

## Drift Output

Human-rendered failures must show:

- selected mode and scope;
- remaining issue count grouped by family and kind;
- action results for `--fix` or `--adopt`;
- manual next steps when an issue cannot be fixed or adopted automatically;
- no JSON envelope.

Example verify failure:

```text
Doctor found drift.
Mode: verify
Scope: families=node node=app-1 app=— workspace=— self=false

Summary

┌────────┬───────┬─────────┬─────────┬───────────┬────────┐
│ ISSUES │ FIXED │ ADOPTED │ SKIPPED │ CONFLICTS │ FAILED │
├────────┼───────┼─────────┼─────────┼───────────┼────────┤
│ 1      │ 0     │ 0       │ 0       │ 0         │ 0      │
└────────┴───────┴─────────┴─────────┴───────────┴────────┘

──────────── D O C T O R   R E S U L T ────────────

1 issue found
node / unverifiable
┌───────┬──────────────────────────┬────────────────────────────────────────┬──────────────────────────────────────────┐
│ NODE  │ KEY                      │ SUMMARY                                │ NEXT                                     │
├───────┼──────────────────────────┼────────────────────────────────────────┼──────────────────────────────────────────┤
│ app-1 │ node.app_ssh_unreachable │ Gateway cannot reach app-1 over SSH.  │ check WireGuard and SSH reachability... │
└───────┴──────────────────────────┴────────────────────────────────────────┴──────────────────────────────────────────┘
```

Example fix failure:

```text
Doctor could not repair all drift.
Mode: fix
Scope: families=app node=beast app=docs workspace=— self=false

Summary

┌────────┬───────┬─────────┬─────────┬───────────┬────────┐
│ ISSUES │ FIXED │ ADOPTED │ SKIPPED │ CONFLICTS │ FAILED │
├────────┼───────┼─────────┼─────────┼───────────┼────────┤
│ 1      │ 1     │ 0       │ 0       │ 0         │ 0      │
└────────┴───────┴─────────┴─────────┴───────────┴────────┘

──────────── D O C T O R   R E S U L T ────────────

1 issue found
app / missing
┌───────┬──────────────────┬─────────────────────────────────────────┬────────────────────────────────────────────┐
│ NODE  │ KEY              │ SUMMARY                                 │ NEXT                                       │
├───────┼──────────────────┼─────────────────────────────────────────┼────────────────────────────────────────────┤
│ beast │ app.path_missing │ App path is missing on the owning node. │ restore the app path or register a path... │
└───────┴──────────────────┴─────────────────────────────────────────┴────────────────────────────────────────────┘

Actions
┌────────┬───────┬──────┬───────────┬────────────────────────┬──────────────────────────────────┐
│ FAMILY │ NODE  │ MODE │ STATUS    │ KEY                    │ SUMMARY                          │
├────────┼───────┼──────┼───────────┼────────────────────────┼──────────────────────────────────┤
│ app    │ beast │ fix  │ completed │ app.fpm_config_missing │ Recreated PHP-FPM pool for docs. │
└────────┴───────┴──────┴───────────┴────────────────────────┴──────────────────────────────────┘
```

Issue groups sort by family order, then kind order: `unverifiable`, `missing`,
`divergent`, `extra`. Within a group, preserve family probe order. Each issue
group renders a table with:

```text
NODE  KEY  SUMMARY  NEXT
```

If `detail.next` or an equivalent family-supplied next-step value is present,
render it in the `NEXT` column.

If no next step is supplied, the renderer may omit the `Next:` line; it must not
invent a command that could mutate state.

## Action Output

Action tables are rendered in `--fix` and `--adopt` mode when
`doctor.actions` is non-empty. They include completed, skipped, failed, and
conflicted actions.

```text
Actions
┌────────┬───────┬──────┬─────────┬─────────────────────────────┬────────────────────────────────────────────┐
│ FAMILY │ NODE  │ MODE │ STATUS  │ KEY                         │ SUMMARY                                    │
├────────┼───────┼──────┼─────────┼─────────────────────────────┼────────────────────────────────────────────┤
│ tool   │ beast │ fix  │ skipped │ tool.version_mismatch       │ Composer self-update is not safe for this. │
│ proxy  │ beast │ fix  │ failed  │ proxy.route_config_mismatch │ Failed to rewrite Caddy route docs.test.   │
└────────┴───────┴──────┴─────────┴─────────────────────────────┴────────────────────────────────────────────┘
```

Failed or conflicted actions must remain visible even when the corresponding
issue is also listed. A completed action that resolves an issue may appear only
in the action table; the resolved issue does not remain in the issue groups.

## Empty Scope Output

When the selected scope has no rows for a family, the command can still be
healthy, but the output must say that the scope was empty:

```text
Doctor healthy.
Mode: verify
Scope: families=app node=beast app=— workspace=— self=false

No app records matched the selected scope.
```

An empty-scope note is informational and does not make the run unhealthy.
