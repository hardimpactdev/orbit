Push an [eligible checked candidate's](/reference/tasks#check-an-external-group) commit for an external group. When hosted CI is required, the owning handoff operation must have succeeded with passed CI on that check/commit. Optionally open or update its pull request. See [Publish an external group](/reference/tasks#publish-an-external-group).

```bash
orbit task:publish 42 --check=17 --title="Deliver the feature" --body="Adds the feature."
```

The optional `task` argument is the numeric task group ID. `--check` supplies the eligible handoff check ID. Supply `--title` and `--body` together to publish a pull request, or omit both to push only. Add `--draft` to open a new pull request as a draft; it needs `--title` and `--body`, and an open pull request keeps its state. `--idempotency-key` reuses an operation start. The command follows the operation with the shared display and supports `--json`.

A group whose workspace is a [task copy](/reference/tasks#task-copy) publishes the same way and gets the same result. Its commit leaves the copy as a bundle; the push and the pull request run on the Swamp worker, so the copy never holds a token. A range from the copy's start that holds the copy's `.env` in any commit fails with `tasks.publish_secret_path`, and nothing is pushed. A range that holds the `.env` content or one of its values under another name fails with `tasks.publish_secret_content`, which names the commit; a content check that cannot run fails with `tasks.publish_secret_unchecked`. A copy publishes only for a nested-fleet trial Project or a Project on the Gateway's `ORBIT_TASKS_COPY_PUBLISH_PROJECTS` list. Any other copy publish fails at once with HTTP 409 `tasks.copy_publish_held`; the checked commit stays in the copy until the Project is released for publishing.
