# Interactive Input Mode: `orbit app:root [app] [root]`

[Back to `app:root` technical contract.](1_app-root.md)

This page describes how interactive input mode resolves `app:root` input before
command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_app-root_input-mode_non-interactive.md`](5.2_app-root_input-mode_non-interactive.md)
even if the process has a TTY.

Authorization is gateway-side and grants-only. When the caller's grant on the
app's owning node does not include `app:root`, the gateway rejects the request
with `authorization_failed` before this input mode renders any prompt; the CLI
surfaces the rejection.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values that can be corrected.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `app_root.app` | `[app]` is missing. |
| 2 | `app_root.root` | `[root]` is missing after `app` is resolved. |

## Prompt Mapping

### `app_root.app`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select an app` |
| Source | `[app]` |
| Required | yes |
| Choices | Visible registered apps. |
| Default | none |
| Validation timing | When `[app]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

### `app_root.root`

| Property | Value |
| --- | --- |
| Primitive | `text` |
| Label | `Document root` |
| Source | `[root]` |
| Required | yes |
| Choices | none |
| Default | none |
| Validation timing | When `[root]` is read or when the prompt is submitted. |
| Invalid terminal behavior | Show validation message and re-prompt when lexical validation fails. |

The `root` value is validated lexically against the gateway-known app path. It
must be relative, non-empty, and remain inside the app path after normalization.
Filesystem reality is not probed during input mode; see
[`1_app-root.md#validation`](1_app-root.md#validation).

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid supplied app input fails before side effects. Prompted app input is
  selected from visible registered apps.
- App eligibility is evaluated as soon as `app` is known. If the app does not
  exist or is not visible to the caller, fail before side effects.
- Root validation is evaluated as soon as `root` is known.
- If the user aborts a prompt, exit with the standard command failure status and
  do not start side effects.
