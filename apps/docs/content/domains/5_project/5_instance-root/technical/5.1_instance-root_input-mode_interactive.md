# Interactive Input Mode: `orbit instance:root [project.instance] [root]`

[Back to `instance:root` technical contract.](1_instance-root.md)

This page describes how interactive input mode resolves `instance:root` input before
command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_instance-root_input-mode_non-interactive.md`](5.2_instance-root_input-mode_non-interactive.md)
even if the process has a TTY.

Authorization follows the shared gateway-owned classes. A normal caller needs
`instance:root` on the selected instance's serving node; gateway implicit authority is the named
exception. The gateway rejects unauthorized requests before this input mode
renders any prompt.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values that can be corrected.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `instance_root.instance` | `[instance]` is missing. |
| 2 | `instance_root.root` | `[root]` is missing after `instance` is resolved. |

## Prompt Mapping

### `instance_root.instance`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select an instance` |
| Source | `[instance]` |
| Required | yes |
| Choices | Eligible visible instances, rendered as dotted selectors. |
| Default | none |
| Validation timing | When `[instance]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

### `app_root.root`

| Property | Value |
| --- | --- |
| Primitive | `text` |
| Label | `Document root` |
| Source | `[root]` |
| Required | yes |
| Choices | none |
| Default | none |
| Validation timing | When `[root]` is read or when the prompt is submitted. |
| Invalid terminal behavior | Show validation message and re-prompt when lexical validation fails. |

The gateway stores the selected instance path. Validate `root` lexically
against that path; it must be relative, non-empty, and remain inside after
normalization.
Filesystem reality is not probed during input mode; see
[`1_instance-root.md#validation`](1_instance-root.md#validation).

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid supplied instance input fails before side effects. Prompted input
  selects a visible dotted instance. A bare logical slug succeeds only for one
  eligible visible instance.
- Instance eligibility and serving-node authorization are evaluated as soon as
  `instance` is known, before the root prompt or effects.
- Root validation is evaluated as soon as `root` is known.
- If the user aborts a prompt, exit with the standard command failure status and
  do not start side effects.
