# JSON Renderer: `orbit update:all`

[Back to `update:all` technical contract.](1_update-all.md)

This page describes the JSON-rendered output for `update:all`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present.

`--json` also disables interactive prompts and forces the
[`non-interactive input mode`](../../../README.md#invocation-model), even
when the process has a TTY.

The JSON renderer updates the caller-local checkout before submitting the update
request to the gateway. If the caller-local checkout fails, it stops before
submitting the gateway request.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Gateway authorization failures, gateway failures, local
update failures, and remote target failures must all use this envelope.

## Success Shape

```json
{
  "success": {
    "data": {
      "updates": [
        {
          "target": "local",
          "node": null,
          "role": null,
          "status": "completed"
        },
        {
          "target": "gateway",
          "node": "gateway",
          "role": "gateway",
          "status": "completed"
        },
        {
          "target": "app-1",
          "node": "app-1",
          "role": "app",
          "status": "completed"
        }
      ]
    },
    "meta": {
      "summary": {
        "total": 3,
        "completed": 3,
        "failed": 0
      }
    }
  }
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `updates[]` | array | Ordered target results. |
| `updates[].target` | string | Human-stable target label. |
| `updates[].node` | string \| null | Gateway node name for remote targets; `null` for the caller-local checkout. |
| `updates[].role` | string \| null | Node role for remote targets; `null` for the caller-local checkout. |
| `updates[].status` | string | Target update status. |
| `summary.total` | integer | Number of selected update targets. |
| `summary.completed` | integer | Number of targets that updated successfully. |
| `summary.failed` | integer | Number of targets that failed. |

The `local` target represents the caller-local checkout. Gateway-selected
non-local installations are listed separately and must not duplicate the local
target.

Operator identities are never remote update targets. Clients other than the
caller are never remote update targets; see the `update:all` technical contract's
[Fleet Selection Rules](1_update-all.md#fleet-selection-rules).

## Error Shapes

### Authorization failed

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for '*' on 'gateway'.",
    "meta": {
      "reason": "permission_missing",
      "missing_permission": "*",
      "serving_node": "gateway"
    }
  }
}
```

### Local update failed

```json
{
  "error": {
    "code": "local_update_failed",
    "message": "Failed to update local Orbit checkout.",
    "data": {
      "output": "orbit-runtime container unavailable"
    },
    "meta": {
      "failed_step": "install_dependencies"
    }
  }
}
```

### Remote target failure

When any remote target fails after side effects begin, return an error envelope
that preserves every target result:

```json
{
  "error": {
    "code": "remote_update_failed",
    "message": "One or more Orbit installations failed to update.",
    "data": {
      "updates": [
        {
          "target": "local",
          "node": null,
          "role": null,
          "status": "completed"
        },
        {
          "target": "app-1",
          "node": "app-1",
          "role": "app",
          "status": "failed",
          "output": "Permission denied (publickey)."
        }
      ]
    },
    "meta": {
      "summary": {
        "total": 2,
        "completed": 1,
        "failed": 1
      }
    }
  }
}
```

## Enum and identifier values

| Field | Values |
| --- | --- |
| `updates[].role` | `gateway`, `app`, `null` |
| `updates[].status` | `completed`, `failed` |
| `error.code` | `gateway_unavailable`, `authorization_failed`, `local_update_failed`, `remote_update_failed` |

The `error.code` values listed here are exhaustive for `update:all`. Add a new
value to this renderer contract before implementing another JSON failure code.
Partial target results and captured command output are diagnostic data and
belong under `error.data`, not `error.meta`.
