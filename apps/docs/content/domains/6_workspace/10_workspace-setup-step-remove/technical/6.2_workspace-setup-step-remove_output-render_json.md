# Technical Contract: `orbit workspace-setup-step:remove` (JSON Renderer)

**Renderer:** JSON.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

[Back to the canonical contract.](1_workspace-setup-step-remove.md)

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

## Success Envelope

```json
{
  "success": {
    "data": {
      "result": {
        "action": "removed"
      },
      "step": {
        "id": 12,
        "app": "hauser",
        "app_instance": "nmbp",
        "phase": "setup",
        "order": 2,
        "command": "composer install",
        "timeout_seconds": 600
      }
    },
    "meta": {
      "remaining_step_count": 3
    }
  }
}
```

### Fields

- `result.action`: Literal `"removed"`. The only outcome verb for this
  command. `workspace-setup-step:remove` is imperative and never converges
  toward an absent state; an already-absent target is a hard validation
  failure, not a silent no-op.
- `step.id`: The original numeric registry identifier of the removed
  record. Captured before the delete; it is absent from the gateway
  registry by the time the response is rendered.
- `step.app`: The logical app slug of the resolved instance.
- `step.app_instance`: The required app instance that owned the removed step.
- `step.phase`: Literal `"setup"`. The discriminator that separates this
  policy list from teardown steps.
- `step.order`: The original `order` position the removed step occupied
  before compaction.
- `step.command`: The shell command string the removed step held. Captured
  before the delete.
- `step.timeout_seconds`: The strict positive integer timeout the removed
  step held. Captured before the delete.
- `meta.remaining_step_count`: The number of surviving setup-step records
  for `(app_instance, phase=setup)` after the delete and order compaction. The
  surviving sequence is contiguous from `1` to `remaining_step_count`.

`workspace-setup-step:remove` does not emit non-fatal warnings. Drift
between gateway configuration and node reality is reported by
[`doctor --family=workspace`](../../workspace-doctor.md), not by this
write command. Past executions of the removed step remain in
[`workspace:history`](../../6_workspace-history/workspace-history.md);
this command does not mutate that history and does not report on it.

## Error Envelope

### Step not found

Returned when the supplied `--step` does not match an existing setup-step
record for the resolved `(app_instance, phase=setup)`. Already-absent removal is
not idempotent — this is the imperative validation failure shape.

```json
{
  "error": {
    "code": "workspace.step_not_found",
    "message": "Setup step '12' not found for app 'docs' in phase 'setup'.",
    "meta": {
      "step_id": 12,
      "app": "docs",
      "phase": "setup"
    }
  }
}
```

### Validation failure (step)

Returned when `--step` is missing in non-interactive mode or is not a
strict positive integer.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Step ID must be a positive integer.",
    "meta": {
      "field": "step",
      "reason": "must_be_positive_integer"
    }
  }
}
```

### Validation failure (app)

Returned when the app instance cannot be resolved from `--app`,
`.orbit/config`, or gateway path-ownership lookup, and prompting is
disabled (non-interactive mode).

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Could not resolve app instance.",
    "meta": {
      "field": "app",
      "reason": "missing_required_input"
    }
  }
}
```

### App not found

```json
{
  "error": {
    "code": "workspace.app_not_found",
    "message": "App 'docs' not found.",
    "meta": {
      "app": "docs"
    }
  }
}
```

### Missing destructive consent

Returned in non-interactive input mode when `--force` is absent, and when
the operator declines the interactive confirmation prompt. `--json` never
implies `--force`.

```json
{
  "error": {
    "code": "validation_failed",
    "message": "This is a destructive operation. Use --force or confirm the prompt.",
    "meta": {
      "field": "force"
    }
  }
}
```

## Common Error Codes

| Code | Meaning |
| --- | --- |
| `validation_failed` | A supplied input failed gateway-side static validation (missing or non-positive `--step`, unresolved app instance, missing destructive consent, or cancelled confirmation). `error.meta.field` names the offending input (`step`, `app`, or `force`). |
| `workspace.app_not_found` | Resolved app slug does not exist in gateway configuration. `error.meta.app`. |
| `workspace.step_not_found` | The supplied `--step` does not exist for the resolved `(app_instance, phase=setup)`. `error.meta.{step_id, app, phase}`. |
| `authorization_failed` | The caller lacks `workspace:write` on the target app's owning node. `error.meta.reason=missing_permission`, `error.meta.missing_permission=workspace:write`, and `error.meta.serving_node` names that node. |
| `gateway_unavailable` | A non-gateway caller has no configured gateway or cannot reach the gateway API. |

## Enum and identifier values

| Field | Values |
| --- | --- |
| `result.action` | `removed` |
| `step.phase` | `setup` |
| `error.code` | `validation_failed`, `workspace.app_not_found`, `workspace.step_not_found`, `authorization_failed`, `gateway_unavailable` |

The `error.code` values listed here are exhaustive for
`workspace-setup-step:remove`. Add a new value to this renderer contract
before implementing another JSON failure code.
