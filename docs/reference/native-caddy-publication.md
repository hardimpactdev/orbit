---
title: Native Caddy command steps
description: Complete public Caddy input and placed publication actions.
---

Caddy publication admits the complete Node configuration before dispatch. The workflow receives public configuration, version and listen addresses as inputs. Its steps do not read intent or report progress through the Gateway.

The native workflow exposes candidate preparation, bounded content writes, inspection, validation, activation, service enable and service reload as separate placed actions. Failure restoration is a native dependency branch. Operational Python is visible inside each command/shell step's `run` block; TypeScript only shapes public input and output. No private material is needed for a Caddy configuration generated by the canonical public renderer.

The shared Swamp command-step helper reads the native terminal result. The Gateway records the Operation outcome through its family projector. A submitted release-handoff Caddy Operation remains submitted until that native result arrives.

The shared full-input dispatch and terminal subscription must be integrated before enabling this rewrite. Built-in command/shell steps on logical Nodes 1 and 18 remain unavailable until the shared SSH proxy transport is proved. Serializing publication does not refresh an admission snapshot: the whole-Node publication revision policy must be settled before concurrent mutation parents use this workflow.

The reusable public capture is `NativeCaddyPublicationInput::forNode(Node): array`. A composing parent keeps its own Operation identity and places every Caddy action on the captured publication Node. The native workflow takes `intent.caddy_publication`, an empty `execution_secrets` object, and the authoritative `operation_id`, `kind`, and `node_id`. Its fixed terminal selector is `completion/result`. It reports `ready`, `result`, and `version`.
