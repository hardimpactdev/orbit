Allow incoming traffic on one Linux Node. UFW does not restrict ports published by Docker; see the [firewall overview](/cli/firewall).

## Usage

```bash
orbit firewall:allow <port> --node=ID [--from=SOURCE] [--protocol=PROTO] [--label=TEXT] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `port` | yes | Destination port from 1 through 65535, or an inclusive ordered range such as `8000:8100`. Service names are not accepted. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--node=ID` | required | Positive numeric target Node ID. The calling Node needs an access grant to it. |
| `--from=SOURCE` | `any` | Source IPv4 or IPv6 address, CIDR, or `any`. An address or CIDR affects its address family only; `any` affects both. |
| `--protocol=PROTO` | both | `tcp` or `udp`. Omit it for both; `any` is not an accepted value. |
| `--label=TEXT` | none | Description of at most 255 characters; not rule identity. See [labels and comments](/cli/firewall#rule-identity). |
| `--idempotency-key=KEY` | none | Global [keyed-start option](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Machine output under the [CLI input and output standard](/reference/cli-ux#input-and-output-modes). |

```bash
orbit firewall:allow 5432 --node=7 --from=10.6.0.0/24 --protocol=tcp --label="office postgres"
orbit firewall:allow 6000:6100 --node=7 --protocol=udp
```

Prompts and output follow the [CLI standard](/reference/cli-ux). See the firewall family's [rule identity and repeat behavior](/cli/firewall#rule-identity), [source ordering](/cli/firewall#order-on-the-node), and [safe change order](/cli/firewall#change-rules-without-an-exposure-window).

An equal, well-placed line keeps its existing comment. If TCP is already correct, an allow for both protocols adds only UDP. A managed rule for a disjoint source network does not force the existing line to move.

Orbit already allows SSH, recovery SSH, the WireGuard port and the ports its roles need. An allow succeeds with `Skipped — already applied (firewall.rule_exists)` when its ports lie inside one protected port or range Orbit already opens and its source is one that entry already admits. Orbit records a succeeded Operation without an operator rule or Node contact; this uses recorded intent, not a live UFW check. Another firewall change on the Node still prevents this skip (`operation.target_busy`). A range extending beyond that entry, or a source it does not admit, is a normal allow.

A normal allow requires active UFW; Orbit does not enable it. A failed execution keeps the rule visible as failed. Lines added before the failure remain, and a line deleted for reordering may be absent. There is no rollback; repeat the command after fixing the cause to repair the same record without duplicates.

## Errors

See the [firewall error codes](/cli/firewall#error-codes) for input, access, conflict and overlap refusals, and [Operation errors](/reference/operations#errors) for shared admission failures. These execution results affect recovery:

| Code | Meaning |
| --- | --- |
| `firewall.backend_inactive` | UFW is inactive; no rule is applied on the Node. |
| `firewall.verify_failed` | The final check does not find every expected line in the required order. |
| `operation.native_failed` | An execution step fails before returning a public check result; partial changes may remain. |
