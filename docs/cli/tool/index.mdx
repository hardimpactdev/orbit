The `tool` family manages packages on a Node. A Tool is one package that Orbit manages through one Tool Manager. The [Tools reference](/reference/tools) explains where Tools run, the supported managers, and the discovery, adoption, install, update, and removal rules.

## Commands

| Command | Result |
| --- | --- |
| [`tool:manager:list`](/cli/tool/manager-list) | List the managers a Node supports and their state. |
| [`tool:scan`](/cli/tool/scan) | List installed apt, Homebrew and Vite+ packages from the Node agent's reports, without taking ownership. |
| [`tool:adopt`](/cli/tool/adopt) | Register one supported installed package from the Node agent's report, at once and without changing it. |
| [`tool:install`](/cli/tool/install) | Install one package, and install its manager first when needed. |
| [`tool:list`](/cli/tool/list) | List the Tools on a Node. |
| [`tool:show`](/cli/tool/show) | Show one Tool. |
| [`tool:update`](/cli/tool/update) | Update one Tool within its constraint. |
| [`tool:remove`](/cli/tool/remove) | Remove one Tool and delete its record. |
| [`tool:converge`](/cli/tool/converge) | Apply the desired coordinates of registered Tools on one Node. |
| [`tool:apt-repository-add`](/cli/tool/apt-repository-add) | Add or republish one signed apt repository on a Node. |
| [`tool:apt-repository-list`](/cli/tool/apt-repository-list) | List the apt repositories of a Node and their state. |
| [`tool:apt-repository-show`](/cli/tool/apt-repository-show) | Show one apt repository. |
| [`tool:apt-repository-remove`](/cli/tool/apt-repository-remove) | Remove one apt repository that no Tool references. |
| [`tool:mode`](/cli/tool/mode) | Inspect or export the Gateway's active Tool policy. |
| [`tool:mode:set`](/cli/tool/mode-set) | Switch policy without changing packages on any Node. |

Every command accepts `--json`. Install, update, remove, converge, and the apt repository add and remove follow an Operation. Human output shows its steps; JSON output is the final Operation receipt. These writes accept `--idempotency-key=KEY` to replay a start after a lost reply. Adopt answers at once from the Node agent's report and prints the agent's liveness first. Scan is a direct read of the same reports. `--node` takes a positive numeric Node ID. The CLI refuses any other value with `tool.node_id_invalid`.

## Apt repositories

A signed [apt repository](/reference/tools#apt-repositories) is its own record on a Node. Add it once, then name it on `tool:install`, `tool:adopt`, and `tool:update` with `--repository=NAME`. A Tool write never publishes or changes the repository; it refuses a repository that is missing or not ready.

```bash
orbit tool:apt-repository-add --node=NODE_ID --name=rex --definition='{"uris":["https://pkgs.superlogical.com/rex/apt"],"suites":["preview"],"components":["main"],"architectures":["amd64"],"signing_key":{"url":"https://pkgs.superlogical.com/rex/keys/rex-archive-keyring.gpg","fingerprint":"E28636AC71905C6DDE40C1EDFAA6B80F641307A7"}}'
orbit tool:install rex --node=NODE_ID --manager=apt --repository=rex
```

To move to the stable suite once it has a published InRelease, remove the repository's Tools and the repository, add it again with `"suites":["stable"]`, and install them again. A name never takes another definition. Adding the same name and definition again, or converging the Node, republishes the repository: that is the recovery for a failed or unconfirmed one, and for a key rotation under the same definition. Removing the last Tool leaves the repository; `tool:apt-repository-remove` removes it once no Tool references it.
