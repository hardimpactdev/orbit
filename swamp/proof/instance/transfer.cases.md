# instance:transfer verification cases

The proof runs the built CLI against a fresh nested topology with a Gateway and two `app-dev` Nodes, in one Cluster and in two, with development Instances (a checkout and a linked worktree, with and without dirty work, Processes, Schedules, a Route and extra web-root Routes) and a production Instance. It checks the Gateway records, both Nodes' files and processes, certificates, DNS, Caddy and real HTTPS requests. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Move | Transfer an Instance to another `app-dev` Node in the same Cluster. | The task succeeds. The destination holds an independent checkout with the same history, branch, origin, staged and unstaged work and untracked files. The Project setup steps ran there and its Processes run. The Route answers from the destination, and the old placement is deleted. The Instance record names the destination and the Operation keeps the true source Node. |
| Across Clusters | Transfer to a Node in another Cluster. | The Route moves to the destination's scope, and generated domains follow its TLD. |
| Linked worktree | Transfer a linked worktree, then one whose common repository is shared or uses alternates. | The first becomes an independent checkout. The source index and the common repository are unchanged, and a common checkout with other linked worktrees is not removed. The second fails after the Processes stop with `instance.transfer_source_shared` or `instance.transfer_source_invalid`, and the source is restored. |
| `.env` | After a transfer, with and without an owned MySQL or PostgreSQL database. | The source `.env` stays behind. The destination `.env` is rendered from the stored configuration with mode 0640 in group `orbit-env`. An Instance that owns such a database also gets a `.env.testing`. Fails today: the workflow writes only `.env`. |
| Missing configuration | An Instance with no stored environment configuration. | `env.configuration_missing`. Nothing moves. |
| Name | Transfer with `--name`, with an invalid name, with a name already owned in the Project, and with a path that is occupied, also one that becomes occupied during extraction. | The destination uses the name and its path and generated domain. `validation.failed`, `instance.identity_conflict` and `instance.destination_exists` leave everything in place; the late collision gives `instance.transfer_destination_exists` and restores the source. |
| Schedules | An Instance with Schedules. | They move with it. During the move no fire runs on either Node, and afterwards each Schedule's trigger is on the destination. After a failed move it is on the source again. |
| Processes | Processes that run and ones that are desired stopped. | The destination installs them before the Route is published, running ones are verified, and stopped ones stay stopped. |
| Web-root Routes | Extra Routes with a web root that are active, one that is not, one that is changing, and a public one across Clusters. | The active ones move with the Instance. The others are refused with `instance.transfer_route_conflict`. Their IDs stay unchanged. |
| Domain conflict | A new generated domain that another Route owns. | `route.domain_conflict`. Nothing moves. |
| Refusals | A production Instance, an Instance that is not active, one with no authoritative Route, one with an incomplete Route domain change, one being removed, the same Node as destination, an inactive Node, a Node with no `app-dev` role, a Node outside an active Cluster, a destination Cluster with no active Router, and a source with no recorded source profile. | `instance.production_refused`, `instance.lifecycle_conflict` (three times), `instance.removal_conflict`, `instance.same_node`, `instance.node_inactive`, `instance.node_not_app_dev`, `instance.standalone_unsupported`, `route.router_required` or `cluster.router_required`, and `instance.source_profile_missing`. Nothing moves. The Project is not checked against the destination Node: the chart requires it, and the code has no such check (Fails today). |
| Unavailable | `--sqlite-source-path`, a VM placement, and a destination with no stored absolute apps path. | `operation.kind_unavailable` before anything is reserved or moved. |
| Source Router | A source Route whose original Router is unknown. | `instance.transfer_source_router_unknown`. |
| Failure before cutover | Make the archive, the copy, the extraction, a setup step, the Process install or the Route publication fail. | The task fails with the failed step. The source publication and runtime are restored, only a destination checkout Orbit proved it made is discarded, and an occupied unproven path is never deleted. A run that only restored the source gives `instance.transfer_failed`. The Instance is unchanged and the identical command succeeds after the fix. |
| Failure after cutover | Make the TLS check fail, then the retirement of the source, then cancel. | The destination stays authoritative, the Instance is placed on it, and the source is kept for repair. A rerun of the identical command finishes the cleanup. |
| Cleanup failure | Make the recovery cleanup fail. | The failure stays visible and nothing unproven is deleted. |
| Retry rules | Retry with a different request, and while a recovery is pending. | `instance.transfer_retry_conflict` for the first. A pending recovery gives `instance.transfer_recovery_pending`. Fails today: nothing records a pending recovery. The identical command resumes. |
| Open transfer | `instance:destroy` of the Instance, and `route:destroy` of its Route, while a transfer is open. | Both are refused with `instance.transfer_incomplete`. |
| Setup changed | Change the Project's setup steps after admission and before the run. | `operation.execution_forbidden`. Start the transfer again. |
| Interrupt | Cancel a run, let one time out, and stop the executor mid-run. | Each ends like a failed step and the identical command resumes. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C and end of input, also for a transfer being retried. Then run it noninteractively and with `--json` without `--force`. | The prompt names the source Node, the destination Node, the Instance and the effect, with No selected, and says "Retry transfer" for a retry. Each decline ends with `input.cancelled` and no request. The noninteractive and `--json` calls are refused with `instance.confirmation_required`. Fails today: the source Node shows only its ID. |
| Progress and output | Follow a transfer in a terminal, a narrow terminal and a pipe, and press Ctrl-C. | A tree of the steps. Ctrl-C stops following, exits 130 and leaves the transfer running. The piped output has no animation or escape codes. With `--json`, nothing prints while it follows, then stdout holds only the final task. Fails today: one `native` row replaces the tree. |
| Missing input | In a terminal, run the command with no arguments and cancel each list. Then run it noninteractively and with `--json` without the Instance and without the Node. | The terminal lists Instances, then the active `app-dev` Nodes, by name. Cancel ends with `input.cancelled` and no request. The noninteractive calls are refused with `instance.id_invalid` or `node.id_invalid`, with no request. Fails today: both are required arguments, so every call without them is refused by the parser. |
| IDs only | An Instance or Node by name, the ID `0`, the ID `-1` passed after `--`, and `abc`. | `instance.id_invalid` or `node.id_invalid`, with no request. Fails today: `-1` without `--` is read as an option and gives a parser error. |
| Idempotency option | Run with `--idempotency-key`. | The option is refused as unknown. Fails today: the CLI offers it. |
| Lost response | Lose the response to the start and repeat the command. | Exactly one transfer exists: the identical repeat resumes it. |
| Unknown and access | An Instance or Node ID that does not exist, and a caller without a grant to the source or to the destination. | `http.404` and `node_access.required`. Nothing starts. |
