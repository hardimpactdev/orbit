```bash
orbit process:start <process> [--idempotency-key=KEY] [--json]
```

A competing operation on the same Instance makes the command wait up to 30 seconds and then return `process.operation_busy`. A competing operation on the same Process returns `process.runtime_lock_failed`.

On a container Instance, a Process whose definition the Project removed answers `process.removing` (409). The next deployment of the default removes it.

## How it works

<div className="flow-at" data-chart="process/start"></div>

### Executor path

On the Gateway engine, the start is one signed `process.ensure_state` order on the Process's Node, for a host systemd unit or a host Docker container of a Node Process or an app-dev Instance Process. It applies the boot policy (disabled for an on-demand Process) and reads the state back. A dev-server Process (`vp-dev`, `vite`), a Process of an Instance outside app-dev, a unit in an Instance container, a Gateway release-container Process and a Node's host Horizon unit stay on Swamp. A failure records `operation.native_failed` as the Swamp flow does; the order's own code stays on its engine step. The run holds the Process lock until its terminal receipt, and another Operation on the Process is refused `operation.target_busy` meanwhile. Runtime proof on a nested fleet is pending. When the Gateway engine does not admit the whole Operation, it runs the Swamp flow above.
