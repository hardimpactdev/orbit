# `app:remove` Interactive Input Mode

[Back to `app:remove` technical contract.](1_app-remove.md)

This page describes how interactive input mode resolves `app:remove` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_app-remove_input-mode_non-interactive.md`](5.2_app-remove_input-mode_non-interactive.md) even if the process has a TTY.

App-node callers are rejected by the gateway before this input mode renders any
prompt. CLI callers that cannot reach the gateway fail with `gateway_unavailable`
before any prompt renders.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- Require destructive confirmation before side effects.
- Skip the confirmation prompt when `--force` is present.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `app_remove.app` | `[app]` is missing. |
| 2 | `app_remove.confirm` | `--force` is absent and the resolved app exists. |

## Prompt Mapping

### `app_remove.app`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select an app to remove` |
| Source | `[app]` |
| Required | yes |
| Choices | Gateway app registry rows visible to the caller. Row key is the app name. Columns are host, node, and repository. |
| Default | First visible app row. |
| Validation timing | When `[app]` is read or when the selected row is submitted. |
| Invalid terminal behavior | If no app rows are visible, fail before side effects with `app.not_found`. |

### `app_remove.confirm`

| Property | Value |
| --- | --- |
| Primitive | `confirm` |
| Label | `Remove app '{name}' and all owned artifacts? This cannot be undone.` |
| Self-targeting label | `Remove app '{name}' and all owned artifacts? You are currently inside a workspace for this app and your environment will be invalidated.` |
| Source | interactive destructive consent |
| Required | yes |
| Default | `false` |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | If declined, fail before side effects with `Operation cancelled.` |

The interactive prompt SHOULD list dependent artifact counts (proxy routes,
workspaces, schedules, processes) inline as part of the confirmation message
body so the operator can size the destructive scope before consenting.

Use the self-targeting label when the caller is inside a workspace of the
target app. The self-targeting prompt uses the same prompt ID, primitive,
default, and cancellation behavior.

## Failure Semantics

- Missing required input is collected through the app datatable before side
  effects.
- Invalid supplied field-local input fails before side effects. The datatable
  only returns visible registered apps, so selected rows are valid by
  construction.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If the target app does not exist, fail before side effects
  after the name is resolved.
- If `--force` is present, skip `app_remove.confirm`.
- If the user declines the confirmation prompt, exit with the standard command
  failure status and do not start side effects.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
