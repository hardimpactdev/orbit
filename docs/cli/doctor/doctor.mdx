```bash
orbit doctor [--node=ID] [--family=FAMILY ...] [--json]
```

| Option | Default | Meaning |
| --- | --- | --- |
| `--node=ID` | accessible Nodes | Inspect one positive numeric Node ID. |
| `--family=FAMILY` | all families | Repeat to select families. Current checks belong to `node`, `role`, `process`, and `firewall`. |
| `--json` | false | Return the report as JSON. |

The Gateway answers at once with the report, from the facts each Node's [agent](/reference/node-agent#facts) reported. It starts no run and never reaches a Node. Node access applies first. Nodes sort by name and ID; the family order is fixed.

Each Node's report starts with its agent: online, offline since a time, or not seen. Human output prints that line first for every Node. While an agent is offline, each finding of its Node is marked `possibly outdated, agent silent since <time>`: the facts stop at that time.

Human output lists Node, Family, Status, Checked, Resource and Finding. JSON returns the same report, with node/family/check counts and counts of drift, unverifiable and informational issues. Exit 0 means the performed checks have no drift or unverifiable findings. Exit 1 means a check found drift, could not be verified, or the request failed.

## How Doctor reads the Node

Doctor compares the Gateway's records with three facts: `host` (platform, architecture and filesystem space), `units` (role services, Process units and containers, and awake markers) and `ufw` (whether UFW is enabled, and its rules). The agent's liveness gives the agent check. There is no Swamp run, SSH read or repair action.

A check whose fact has not arrived yet, or cannot be read, gives one unverifiable `<family>.inspection_failed` finding for the family and Node: "not observed yet". Other checks continue. The root filesystem check also accepts a `/` reading that the Gateway [kept from an earlier report](/reference/node-agent#facts), but only for 180 seconds after the Gateway received the agent's first report without `/`. After that it is unverifiable. A Node without an observing agent, such as a Mac, gets its lifecycle checks only. A parked task VM gets an informational finding and no other check.

## What each family checks

| Family | Checks |
| --- | --- |
| `node` | Recorded lifecycle; [Instance bridge refresh health](/reference/development-containers#prepare-a-node) (`node.instance_bridge_unhealthy`); platform and architecture; root filesystem free space; the agent's liveness: never seen (`node.agent_missing`) or silent (`node.agent_view_stale`); a reboot due for more than 3 days (`node.reboot_due`, from the [fleet reboot](/reference/gateway-recovery#fleet-reboot) passes). |
| `role` | Recorded lifecycle and current state of each service required by an active Linux role. |
| `process` | Current registered systemd unit or Docker container presence and running/stopped state. A systemd `activating/auto-restart` snapshot is crash-loop evidence. A cumulative restart count alone is not. |

| `firewall` | Rule lifecycle, UFW active state, and missing or extra lines by port, protocol and source. |

A stopped, non-keep-alive development Process desired running is healthy only when the agent reports its awake marker absent. An agent before 0.10.0 reports no markers, so that check is unverifiable there, and so is a Process unit it does not list. This inspection takes no timed samples and does not infer a restart rate.

The existing family selectors `project`, `instance`, `schedule`, `tool`, `database_connection`, `route` and `database_server` remain accepted by the API, but have zero Doctor checks. A healthy family with `checked: 0` supplies no verdict on its resources. Use the owning native operation and its result for configuration validation.

`checked` counts the checks performed for a family: platform, disk, agent and reboot for `node`, one per role service, one per Process, and one for UFW. Lifecycle findings need no fact. Checks without a usable fact remain in the count and give unverifiable findings.

## Informational package discoveries

Doctor does not discover packages. Use the Tool family's native scan and adoption operations. Doctor reads no package-manager scope and stores no inventory.
