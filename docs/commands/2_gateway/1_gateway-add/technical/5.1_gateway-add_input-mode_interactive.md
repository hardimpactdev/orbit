# Interactive Input Mode: `orbit gateway:add [gateway_ip]`

[Back to `gateway:add` technical contract.](1_gateway-add.md)

This page describes how interactive input mode resolves missing `gateway:add`
input before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_gateway-add_input-mode_non-interactive.md`](5.2_gateway-add_input-mode_non-interactive.md) even if the process has a TTY.

Gateway and app-node callers are rejected before this input mode renders any
prompt.

## Responsibilities

- Read any supplied arguments and options.
- Derive the gateway WireGuard API address from the active WireGuard network
  when `gateway_ip` is omitted.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- Return a fully resolved input object to the canonical command flow.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `gateway_add.gateway_ip` | `gateway_ip` cannot be derived unambiguously from the active WireGuard network and is not supplied. |

If `gateway_ip` is supplied or derivation succeeds unambiguously, no prompt is
rendered.

## Prompt Mapping

Prompt mappings use stable prompt IDs and Laravel Prompts primitive names.

### `gateway_add.gateway_ip`

| Property | Value |
| --- | --- |
| Primitive | `text` |
| Label | `Gateway IP` |
| Source | `[gateway_ip]` |
| Required | yes, when derivation fails |
| Choices | none |
| Default | none |
| Validation timing | When `[gateway_ip]` is read or when the prompt is submitted. The value must be an Orbit WireGuard IPv4 address in `10.6.0.0/16`. |
| Invalid terminal behavior | Show validation message and re-prompt. |

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid field-local input shows a validation message and re-prompts until the
  value is valid or the user aborts. There is no generic retry cap.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If a blocker is already knowable and the current prompt can
  correct it, show a validation message and re-prompt at that prompt instead of
  asking for later unrelated input. If the blocker cannot be corrected by the
  current prompt flow, stop before side effects.
- Gateway and app-node callers fail before prompts or side effects.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
