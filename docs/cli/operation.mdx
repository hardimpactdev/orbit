An [operation](/reference/operations) is a long piece of work, such as an Instance deploy or rollback, that Swamp runs as a native workflow. The Gateway records its intent, status and result. The command that starts it, such as [`instance:deploy`](/cli/instance#orbit-instancedeploy) or [`instance:rollback`](/cli/instance#orbit-instancerollback), returns or stops following without stopping the operation. These commands find it again.

Starting commands follow the parent Operation until its result arrives. Ctrl-C stops following and leaves the Operation running. Read it again with `operation:show`.

## Commands

| Command | Result |
| --- | --- |
| [`operation:list`](#orbit-operationlist) | List the newest operations. |
| [`operation:show`](#orbit-operationshow) | Show one Operation and its native result. |
| [`operation:cancel`](#orbit-operationcancel) | Ask one operation to stop. |

Every command accepts `--json`.

## orbit operation:list

List the 50 newest operations on Nodes you can access, newest first.

```bash
orbit operation:list [--status=STATUS] [--kind=KIND] [--instance=ID] [--json]
```

| Option | Meaning |
| --- | --- |
| `--status=STATUS` | `queued`, `running`, `waiting`, `succeeded`, `failed`, or `cancelled`. |
| `--kind=KIND` | An operation kind, such as `instance.deploy`. |
| `--instance=ID` | Only operations on this Instance. |

The table shows ID, Kind, Target, Status, By, and Started. JSON returns the list of parent records.

```bash
orbit operation:list --status=running
```

## orbit operation:show

Show the parent Operation, including its kind, target, status, error code, result and times.

```bash
orbit operation:show <operation> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `operation` | yes | Numeric operation ID. |

JSON returns the parent record, as `GET /api/v1/operations/{operation}` does. The command exits `0` for any status; read `status` for the outcome.

For [`tasks.analyze`](/cli/tasks#orbit-tasksanalyze), inspect `result.outcome`, not just operation status. A successful operation can report `blocked` or a changed checkout. `result.artifact` retains the complete bounded report with its digest and byte length. Use `operation:show <operation> --json` to recover that complete evidence after the starting command stops following.

```bash
orbit operation:show 42
```

## orbit operation:cancel

Record a cancellation request for the native workflow. Swamp applies the kind's cancellation boundary and records the final outcome. A cancellation request does not prove that execution has stopped.

```bash
orbit operation:cancel <operation> [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `operation` | yes | Numeric operation ID. |

The command returns the record at once and does not wait for the operation to stop. A cancel of an operation that already ended changes nothing.

```bash
orbit operation:cancel 42
orbit operation:show 42
```
