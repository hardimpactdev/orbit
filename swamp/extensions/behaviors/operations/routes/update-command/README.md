# Native Route update

`NativeRouteUpdateInput::capture(Route, input)` freezes previous, staged and
final publication catalogs at admission. `NativeRouteUpdateProjection` applies
the shared terminal result. An unchanged request or pending replacement has no
host duties. The update root composes workload preparation, forward publication,
workload selection, and complete restoration on failure.

The root declares `orbit-control-inputs` so native children can resolve the
admitted execution copies. Signing reads only the captured forward or
restoration certificate list selected by the existing `restoring` flag. The same
stable scope may name different domains in those two phases; each phase keeps
its own domain authority and rejects a mismatched CSR.

`routeMutationSteps(name, intentExpr, mode, guard?, parentRunId = "run.id", ingress = false, withdrawal = false)`
keeps its existing callers unchanged. The update phase children pass the root
signing ID and opt into captured public ingress transitions. The ingress child
composes the canonical pinned tuple child for TCP ports 80 and 443, with
explicit any-source rules and migration disabled. Capture uses the whole site
catalog so shared public listeners survive. These stages require the shared
child to prove the observed rule state before publication completes.

Official extensions checked: existing Route children use cfgmgmt files, official
SSH validation/reload, certificate signing and the approved private DNS grace.
The cfgmgmt firewall model cannot consume admitted pins; its separate pin
preflight did not bind the later firewall connection. Every ingress observation
and action now uses the canonical official SSH pin policy. The Instance workload
child documents its narrow ACL and served-link actions. No new transport,
callback, lock, journal, delay or retry mechanism is added. Vault descriptors
retain the closed shared execution-copy shape; private environment bytes reach
the canonical URL child only through official SSH stdin.

The disposable native fixtures exercise the parent and failure recovery on the
pinned runtime. Official firewall/SSH fixtures cover action validation and
failed effects. They prove source composition, not live Node acceptance. The
temporary legacy LAN migration child and allowance remain until all applicable
Nodes have migrated and old writers are closed.

Create and removal use the same captured catalogs, workload child and terminal
result. Create prepares workload TLS before Router selection and verifies the
public endpoint. Removal withdraws DNS before native grace, Caddy removal and
resource cleanup. Offline selection runs in a separate readiness job so its
immutable selected lists exist before effect fanout expands. Unreachable effect
Nodes return explicit residue; an unavailable DNS participant blocks admission.
The replaced standalone callback executors are deleted. Retained composing
parents and Instance-transfer helpers remain separate consumers.
