# Interactive Input Mode: `orbit node:update [name]`

[Back to `node:update` technical contract.](1_node-update.md)

This page describes how interactive input mode resolves `node:update` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_node-update_input-mode_non-interactive.md`](5.2_node-update_input-mode_non-interactive.md) even if the process has a TTY.

Unconfigured clients are rejected before this input mode renders any prompt.
Callers that are configured but are not gateways resolve input locally and
forward to the gateway, where grant authorization is enforced.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for missing required fields before side effects.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when a resolved value violates a domain rule that
  cannot be corrected by re-prompting.
- When no field flags are provided, prompt for which field to change.

## Prompt Order

| Step | Prompt ID | Rendered when |
| --- | --- | --- |
| 1 | `node_update.name` | `[name]` is missing. |
| 2 | `node_update.field` | No supported field flags are provided. |

## Prompt Mapping

### `node_update.name`

| Property | Value |
| --- | --- |
| Primitive | `datatable` |
| Label | `Select a node to update` |
| Source | `[name]` |
| Required | yes |
| Choices | Visible active nodes. |
| Default | none |
| Validation timing | When `[name]` is read or when the selected row is submitted. |
| Invalid terminal behavior | Supplied invalid values fail before side effects; prompted rows are already valid choices. |

### `node_update.field`

| Property | Value |
| --- | --- |
| Primitive | `select` |
| Label | `Which field would you like to update?` |
| Source | interactive field selection |
| Required | yes |
| Choices | `host`, `user`, `tld`, `public_ipv4`, `public_ipv6`, `orbit_agent_capable` (role-filtered) |
| Default | none |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | Show validation message and re-prompt. |

When a field is selected, prompt host, user, TLD, and IP address values with
`text`. Prompt Orbit Agent capability with a boolean choice equivalent to
`--orbit-agent-capable` or `--no-orbit-agent-capable`.

`tld` is available for every active node target. In operator-forwarded
interactive mode, where the target row is not available locally, `tld` may be
selected and the gateway applies canonical syntax and uniqueness validation.

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid supplied node input fails before side effects. Prompted node input is
  selected from visible active nodes.
- Path eligibility is evaluated as soon as the prompt result makes the selected
  path knowable. If the target node does not exist, fail before side effects
  after the name is resolved.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
