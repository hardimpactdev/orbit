# `app:new` Human Renderer

[Back to technical contract](1_app-new.md)

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

The human renderer provides a live progress tree during app creation and a
concise summary upon completion.

## Progress Tree

`app:new` performs source creation through the selected node execution
transport and then writes and applies app state, so it renders a progress tree.

```text
┌ Creating Project
○ Prepare project creation
○ Create project source
○ Register project
○ Apply instance runtime
└ Working...
```

### Steps

1. **Prepare project creation:** Starts the tracked creation operation.
2. **Create project source:** Creates a private repository from the selected
   template and clones it, or clones the selected existing repository, on the
   target node.
3. **Register app:** Atomically records the canonical app and named
   first instance.
4. **Apply instance runtime:** Runs the runtime and route convergence for that
   instance. The footer means command-owned writes completed; it does not
   assert application HTTP readiness.

## Completion Summary

Upon success, a summary is rendered:

```text
Project 'docs' created.
```

## Warning Display

Drift that is non-fatal surfaces inline under the affected step and again in a
`Warnings:` block beneath the completion summary. Each warning shows the
human-readable message and a retry hint pointing at `next_command`. Examples:

- A pending production domain prints "Domain 'docs.example.com' is not yet
  active." with the hint
  `Retry with: orbit instance:register docs.production --domain=docs.example.com`.
- When the PHP image is unavailable on the node, the output prints "PHP 8.5 is not available on
  'app-1'." with the hint
  `Resolve with: orbit doctor --family=instance --restore`.

## Failure Display

Failures are rendered as prose errors with troubleshooting hints. If a failure
occurs during the progress tree, the affected step shows a red error dot.
Validation failures detected before any side effects (e.g. unsupported
`--php-version`, name collision) are rendered without a progress tree.
