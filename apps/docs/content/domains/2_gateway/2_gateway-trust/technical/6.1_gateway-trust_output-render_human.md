# Human Renderer: `orbit gateway:trust`

[Back to `gateway:trust` technical contract.](1_gateway-trust.md)

This page describes the human-rendered terminal output for `gateway:trust`.

**Renderer:** Human renderer.

## Primitive

- Progress: [Progress tree](../../../../ux/commands/progress/progress-tree.md)

## Selection

Use this renderer when `--json` is not present.

The human renderer does not own input prompting. `gateway:trust` does not prompt
for missing gateway configuration; invalid or missing local configuration is
rendered as prose when `--json` is absent.

## Progress Tree

`gateway:trust` performs network and local OS trust-store work, so the human
renderer must show an in-progress tree after input resolution and before side
effects begin.

```text
┌ Trusting Gateway CA
○ Resolve configured gateway
○ Fetch trust material
○ Install local trust
○ Store trust metadata
└ Working...
```

When the selected CA is already trusted and local metadata matches:

```text
┌ Trusting Gateway CA
○ Resolve configured gateway
○ Fetch trust material
○ Check local trust
○ Install local trust skip: Already trusted
○ Store trust metadata skip: Already trusted
└ Gateway CA already trusted for <gateway_url>.
```

The final tree must make the failed step visible when the command exits with
failure.

## Success Output

On successful trust installation:

```text
Gateway CA trusted for https://10.6.0.2.
```

On already-trusted convergence:

```text
Gateway CA already trusted for https://10.6.0.2.
```

Success output must not imply that local node identity, gateway access policy,
app routes, or runtime readiness were verified.

## Failure Output

Human-rendered failures must show:

- the failed phase or field;
- a clear prose error;
- next-step guidance only when the operator can act on it;
- no JSON envelope.

Missing gateway configuration:

```text
No gateway is configured. Run orbit gateway:add first.
```

Local config load failures from `OrbitConfigStore` are not rewritten into
canonical human prose. An unreadable, invalid, or permission-unsafe
`~/.config/orbit/config.json` surfaces as an uncaught
`OrbitConfigStoreException` (CLI process failure), matching the canonical and
JSON contracts.

Invalid configured gateway:

```text
Configured gateway endpoint is invalid.
```

Gateway unavailable:

```text
Could not fetch the gateway CA from https://10.6.0.2.
```

Invalid trust material:

```text
Gateway returned invalid CA material.
```

Unsupported platform:

```text
This platform does not support automatic gateway CA trust installation.
```

Trust-store failure:

```text
Failed to install the gateway CA into the local trust store.
```
