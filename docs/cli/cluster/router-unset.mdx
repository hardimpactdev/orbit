title: "orbit cluster:router:unset"

description: "Clear the Router from a Cluster that is inactive or has no TLD."
---

```bash
orbit cluster:router:unset <cluster> [--force] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `cluster` | yes | Numeric Cluster ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--force` | prompt | Confirm without prompting. Required without a terminal and with `--json`. |
| `--idempotency-key=KEY` | generated | Reuse a key to retry the same [Operation start](/reference/operations#start-an-operation). |
| `--json` | off | Print the final Operation as JSON. |

```bash
orbit cluster:router:unset 3 --force
```

In a terminal, an omitted Cluster is chosen from an interactive list, and the CLI asks to confirm with the Cluster's name and the effect, with No selected. Declining, Ctrl-C or end of input exits 1 with `input.cancelled`. Without `--force`, a call that cannot prompt is refused with `cluster.confirmation_required`, and an API or MCP client must send `force: true`. Without the Cluster it is refused with `cluster.id_invalid`. A declined or refused call starts no Operation.

<Warning>
Orbit refuses to clear the Router while the Cluster owns a Route (`cluster.routes_require_router`, or `route.reconciliation_required` for an active Route) or while the Cluster is active with a TLD (`cluster.active_router_required`). Deactivate the Cluster or remove its TLD first.
</Warning>

Clearing the Router removes its Router sites and certificates and reloads its Caddy, then removes the LAN rules that only the Router needed. Caddy and the packages stay, and the WireGuard baseline rules are never removed. If no Node holds any Router state, or the Cluster has no Router, the command clears the assignment at once and starts no Operation. Otherwise the CLI follows the Operation and prints the final result with the request ID.

Each Cluster has one Router operation owner. A concurrent Router change on the same Cluster waits up to 30 seconds and then fails with `cluster.router_busy`.

A failed step leaves the Router's assignment marked failed. Steps that finished stay done and nothing is rolled back, because the Cluster serves no traffic through the Router. After you fix the cause, run the same command again; it skips what is already removed.

## Errors

| Code | Meaning |
| --- | --- |
| `cluster.id_invalid` | The Cluster is missing or is not a positive integer, and the CLI cannot prompt. |
| `cluster.confirmation_required` | The call cannot prompt and has no `--force`, or an API client sent no `force`. |
| `cluster.routes_require_router`, `route.reconciliation_required` | The Cluster owns a Route, or an active Route depends on the Router. |
| `cluster.active_router_required` | The Cluster is active with a TLD. |
| `cluster.router_busy` | Another Router change holds the Cluster. |
| `http.404` | The Cluster is unknown. |
| `node_access.required` | The caller has no access grant to a member Node of the Cluster. |
