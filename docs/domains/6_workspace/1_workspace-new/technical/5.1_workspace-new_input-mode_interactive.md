# Technical Contract: `orbit workspace:new` (Interactive Input)

**Input mode:** Interactive.

[Back to the canonical technical contract.](1_workspace-new.md)

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_workspace-new_input-mode_non-interactive.md`](5.2_workspace-new_input-mode_non-interactive.md)
even if the process has a TTY.

## Prompts

| ID | Primitive | Label | Triggered when |
| --- | --- | --- | --- |
| `workspace_name` | `text` | "Workspace name" | `name` argument is missing. |
| `parent_app` | `datatable` | "Select parent app" | `--app` is missing and CWD inference (`.orbit/config` marker, gateway path lookup) cannot resolve a parent app. |

- [`text`](../../../../commands/ux/inputs/text-prompt.md)

## Behavior

- **Validation:** Each field is validated as it is entered. Invalid values
  trigger a re-prompt with a validation message.
- **Re-prompt cap:** After three failed attempts on the same field, the
  command exits `2` with a validation error rather than looping forever.
- **Defaulting (no prompt):** `--base` defaults to `main` and
  `--php-version` inherits from the parent app; neither is prompted unless
  the operator opts into an advanced flow on a future surface.
- **Reserved name:** `main` is rejected at the prompt with the
  `validation_failed` re-prompt path; the user is informed that `main` is
  reserved for the primary app instance in runtime unit naming.

## Destructive Consent

- N/A. `workspace:new` is a creation command and does not overwrite
  existing workspace paths. A workspace-name collision within the same app fails before
  any side effects with `validation_failed`. There is no destructive
  consent path on this command, and no consent-bypass flag is offered or
  honored.
