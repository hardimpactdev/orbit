```bash
orbit instance:migrate <instance> [--force] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `instance` | yes | Numeric Instance ID of an active development checkout Instance. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--force` | prompt | Confirm the downtime and the retirement of the checkout. Required without a terminal and with `--json`. |
| `--idempotency-key=KEY` | none | Reuse a key to retry this operation start. |
| `--json` | off | Print the final task as JSON, with every step, and nothing while it follows. |

```bash
orbit instance:migrate 12
orbit instance:migrate 12 --force --json > migrate.json
```

A linked worktree can move while its owner remains an active host checkout on the same Node. Migration starts from the stock image and copies this Instance's workspace; it needs no migrated default or seed. A non-default keeps its T3 and model-router prerequisites. Migrate the owner after its last dependent leaves.

The command moves one checkout Instance into an [Instance container](/reference/development-containers#migrate-a-checkout-instance) on the same Node. It is temporary: [Old paths](/reference/old-paths) lists it until the last checkout Instance has moved.

In a terminal, the CLI asks to confirm that the Instance goes down during the move and that its checkout leaves the live path after it, with No selected. Declining, Ctrl-C or end of input ends with `input.cancelled` and starts no move.

Orbit first resolves the same source credential as deploy and reads the Project's default branch once, before stopping any Process or changing the Node. The remote read has a 30-second limit; a slow successful read within that limit passes. `source.read_timed_out` says “Could not reach the source in 30 s”; `source.head_unavailable` reports other remote-read failures. The checkout keeps serving on refusal. `gh_cli` Projects keep their existing local-copy migration and skip this App preflight. The Instance's local branches and commits need not exist on the remote; migration carries them from the checkout. Git authentication refusal reports `source.github_app_denied` with the App and repository, while network and missing-ref failures keep `source.head_unavailable`. Public repositories remain readable anonymously. See [source credential errors](/reference/github-app#instance-source-credentials).

The whole-run budget is 5,700 seconds. It covers the declared workflow timeouts, including Node preparation, restoration and cleanup, rounded up to five minutes, plus 600 seconds for admission and settlement.

A previous migrate that awaits settlement refuses a new admission with `instance.migrate_settlement_pending` (409). The response names the previous Operation and its hold-limit time. Retry after the reconciler settles it. The existing 60-minute hold limit after expiry stays in force. At that limit, a result the reconciler still cannot read ends with `instance.migrate_result_unavailable` and releases the Gateway hold. Orbit keeps the container and address reservation; it does not claim that the move restored the checkout.

The attached targets in [instance:show](/cli/instance/show) are the connections migrate reads: it grants and probes their network endpoints; SQLite files move with the checkout.

A missing finish receipt gets a 60-second grace from the recorded native end. The original run deadline caps this grace. A receipt that arrives during the grace keeps the normal outcome.

After the grace, verified end and rollback release the runtime reservation. The Operation fails with `instance.migrate_result_unavailable`. Its result keeps `native_status` and the error keeps the known native failure facts; a cancelled root stays visible as cancelled. Without rollback proof, recovery waits until the run deadline. It then records that code and keeps the reservation and Instance runtime. It never treats a completed move as a rollback.

A retained reservation refuses another migrate with `instance.migrate_recovery_required`. The refusal names the previous Operation, missing evidence and owner recovery. No Orbit command repairs missing rollback or cutover proof today.

## What moves

| Part | What Orbit does |
| --- | --- |
| Branch | The checkout's current branch. Orbit fetches it from the checkout on the Node; a retained checkout can carry commits that were never pushed |
| Files | Changed, untracked and ignored files, plus missing directories, including empty ignored trees. Added directories keep their modes, including setgid and sticky bits |
| `.env` | Copied as it is. The checkout's path in it becomes `/srv/workspace` |
| Symlinks | Absolute links into the checkout become relative workspace links. Relative links within the checkout stay as they are. See the [symlink rule](/reference/development-containers#migration-symlinks) |
| Database on a Database server | It stays where it is. The container gets its own way to the port of each server the Instance uses. Orbit checks every target from inside before stopping the checkout |
| SQLite file in the checkout | It moves with the files. Orbit drops its database connection record: the file is part of the workspace |
| Route | The same domain and certificate. It points at FrankenPHP in the container, and the checkout's PHP-FPM pool goes |
| Schedules | Registered Node timers keep their UUID, calendar and enabled or paused state. Their commands run in the container; [Schedule migration](/reference/schedules#checkout-migration) describes the limits and logs |
| T3 | A non-default Instance gets its T3 server, registered as a [new Instance's](/cli/instance/create) is. The default runs none |

Untracked files enter the default's seed snapshot and every clone made from it, as ignored dependencies and build output already do. A later branch that tracks one of those paths can refuse checkout in a clone or deploy. A credentials file someone forgot to ignore travels into the seed like `.env` does.

The Operation result reports `untracked_files_copied` after a successful file-copy phase: the count of copied untracked files that Git does not ignore, selected by `git ls-files --others --exclude-standard -z` at archive time. A selected nested repository contributes its archived leaf files. Directories do not count; symlinks count once. Ignored files are still copied. Human output says how many were copied. This adds no file paths or contents to the result.

Empty directories are copied when the Git checkout and file archive would not create them. This includes nested ignored directories and empty link targets such as `storage/app/public`. Their exact modes are restored after the shared file-mode rule; ownership uses the same `orbit` user and `work` group as the file copy. Restoration runs as the workspace owner and refuses symlink components or paths outside the workspace.

The directory scan skips `.git` metadata, does not follow directory symlinks, and does not enter tracked submodules. The existing file archive still handles selected nested repositories as before. Dependencies such as `vendor` and `node_modules` remain in the copy scope.

Any change to a carried path, including a new or deleted untracked or ignored file, makes the final source snapshot differ. Migration refuses retirement and keeps the source intact; after cutover the container keeps serving. Compare and carry those later changes before any manual cleanup.

## Local Git state

The files phase carries every local branch and tip, the selected HEAD, all stash entries and the complete ordered stash reflog, including duplicate messages, identities, times and timezones. A surviving stash ref with an expired reflog keeps its tip and objects without inventing log entries. Objects reachable through alternate stores become independent objects in the container.

Clean/smudge filters, including Git LFS filters on tracked paths, refuse before downtime with `instance.migrate_git_filter_unsupported`. Use an unfiltered checkout and preserve any filtered data separately. Intent-to-add entries refuse with `instance.migrate_git_intent_to_add`; stage their contents or remove those index entries before retrying. Neither refusal changes source data.

Git reads use a private view with controlled configuration. Repository-defined filters, diff and textconv commands, merge drivers, hooks, fsmonitor, transport helpers and other executable config are not used. Source metadata discovery and attribute queries do not run those programs.

Tracked edits arrive with their working-tree bytes, deletions and renames. Staged changes stay staged: Orbit rebuilds the logical index from its entries and carries staged blobs that no commit references. It copies no source hooks, config, alternates or worktree registrations into the container.

Before existing path rewrites and application starts, Orbit compares branches, HEAD, stash history, index entries, porcelain status and hashes of every carried regular file and symlink target, including untracked and ignored paths. Both repositories pass Git object checks. A mismatch fails before cutover; restore discards the container and leaves the original Git metadata unchanged. The private source snapshot stays on the Node until retention or restore completes and is checked again immediately before retirement.

Hash verification excludes only the root `.git` metadata, tracked submodule contents and filesystem sockets. Git metadata has its own checks; submodule contents and sockets do not move. Selected nested repositories still move as complete archived directories. Directory and special-file kinds are compared without opening pipes or devices.

Retirement still moves the whole old checkout, including every Git metadata file and working-tree file, to the retained path. It deletes no Git data. An owner's other worktrees, registered descendants, unsafe links, changed branch or Git identity, and submodule changes still refuse.

## Retained Git data

Retirement removes the checkout from its old live path by renaming the whole directory. The retained root is `<checkout>.orbit-retired-git`, beside the migrating Instance's checkout. Each retained checkout is a child named by the SHA-256 of its original absolute path. Its files, including untracked and ignored files such as `.env`, `storage`, `vendor` and `node_modules`, all stay there. An owner keeps its whole Git directory. A linked worktree gets an independent `.git`: common objects, refs and reflogs, overlaid with its own HEAD, index, reflogs and private metadata. Alternate object stores are materialized into this copy, then removed from its configuration. Orbit verifies the copy before unregistering only the original, now-missing worktree entry. The owner's store and sibling registrations stay in place. The rename requires the same filesystem; Orbit has no copy-and-delete path. Owner submodule or nested worktree pointers can still need repair before use.

Find the root and its retention time with `orbit instance:show INSTANCE --json`: the fields are `retained_git_path` and `retained_git_at`, also returned by `GET /api/v1/instances/{instance}`. `retained.json` inside that root records the same path and time. Both API fields are null until retirement prepares that root. The timestamp is when the root was prepared. A failed retirement can leave an empty or partly filled root; its path is recorded before any checkout moves.

Destroying the migrated Instance keeps this directory. After destroy deletes the Instance record, its successful Operation result keeps `retained_git_path` and `retained_git_at`; read it with `orbit operation:show OPERATION --json`. See [instance:destroy](/cli/instance/destroy).

### Recovery

A retained linked checkout supports `git -C RETAINED_CHILD status` and history recovery without its former owner's store. To inspect a commit, use `git --git-dir=RETAINED_CHILD/.git show REF`. Keep an owner's retained root while any worktree depends on it.

#### Interrupted unregister

An interrupted unregister reports `instance.migrate_retire_failed` and the exact identity receipt path. That receipt is `<retained-root>/<source-path-hash>.json`, beside the retained child; it is separate from `retained.json`. Its state stays `pending`, and repeating retirement refuses even after someone removes the stale registration.

Run this recovery on the Instance's Node with access to the retained root and owner Git metadata. Replace uppercase paths below with quoted absolute paths.

1. Read `RECEIPT`. Use its `source` as `OLD_PATH`, `identity.git_dir` as `PRIVATE_GIT_DIR`, and `identity.common_dir` as the owner's common Git directory. `RETAINED_CHILD` is the receipt path without `.json`. Confirm `identity.linked` is true and `state` is `pending`.

   ```sh
   cat -- RECEIPT
   test ! -e OLD_PATH
   test ! -L OLD_PATH
   if test -e PRIVATE_GIT_DIR; then
     cat -- PRIVATE_GIT_DIR/gitdir
   fi
   git -C OWNER rev-parse --path-format=absolute --git-common-dir
   ```

   If the registration still exists, its `gitdir` must name exactly `OLD_PATH/.git`. Its private directory must be an immediate child of the recorded common directory's `worktrees` folder. The owner's reported common directory must match the receipt. If any identity cannot be proved, keep the retained data and stop recovery.

2. Check the independent copy before unregistering anything.

   ```sh
   git -C RETAINED_CHILD rev-parse --absolute-git-dir
   git -C RETAINED_CHILD rev-parse --path-format=absolute --git-common-dir
   test ! -e RETAINED_CHILD/.git/commondir
   test ! -e RETAINED_CHILD/.git/objects/info/alternates
   test ! -e RETAINED_CHILD/.git/objects/info/http-alternates
   git -C RETAINED_CHILD fsck --full
   git --no-optional-locks -C RETAINED_CHILD status --short
   git -C RETAINED_CHILD rev-parse HEAD
   ```

   Both directory reads must resolve to `RETAINED_CHILD/.git`. Check the selected branch and commit against the migration result, and confirm all retained files are present. If `.git` is missing or is still the original gitfile, complete the [interrupted installation](#interrupted-git-installation) first.

   If the private entry still exists, compare its index and HEAD with the retained copy:

   ```sh
   cmp -- PRIVATE_GIT_DIR/index RETAINED_CHILD/.git/index
   git --git-dir=PRIVATE_GIT_DIR rev-parse HEAD
   git -C RETAINED_CHILD rev-parse HEAD
   ```

   Both HEAD reads must agree. If the private entry is already absent, confirm `OLD_PATH` is absent from the owner's worktree list and skip its removal; reconcile the receipt in step 4.

3. Once the original path is absent and the identity checks pass, remove exactly its missing registration at the owner.

   ```sh
   git -C OWNER worktree remove --force OLD_PATH
   test ! -e PRIVATE_GIT_DIR
   git -C OWNER worktree list --porcelain
   git -C RETAINED_CHILD fsck --full
   ```

   Confirm `OLD_PATH` is absent from the list and every other registration is unchanged. This removes the missing original registration; the retained child and sibling files stay in place.

4. Reconcile only this receipt after unregister succeeds. The following manual step preserves its identity fields and changes `state` to `complete`.

   ```sh
   python3 - RECEIPT <<'PY'
   import json
   import os
   import sys
   from pathlib import Path

   receipt = Path(sys.argv[1])
   data = json.loads(receipt.read_text())
   assert data["state"] == "pending" and data["identity"]["linked"] is True
   assert not os.path.lexists(data["source"])
   assert not os.path.lexists(data["identity"]["git_dir"])
   assert (receipt.with_suffix("") / ".git").is_dir()
   updated = receipt.with_suffix(".complete")
   updated.write_text(json.dumps({**data, "state": "complete"}) + "\n")
   updated.chmod(receipt.stat().st_mode & 0o777)
   updated.replace(receipt)
   PY
   ```

Orbit has no receipt reconciliation command. This manual update lets a repeated retirement phase pass the incomplete-retirement guard. It does not start a retry or change the failed Operation's result. An operator command for this recovery is a follow-up; the migrated container keeps serving.

#### Interrupted Git installation

If rename completed but installing the independent `.git` failed, the verified copy stays at `<retained-root>/.recovery-*/.git`. Identify the matching copy by checking its HEAD and index against the exact `PRIVATE_GIT_DIR` from the pending receipt. Keep all candidates if no unique match can be proved.

```sh
git --git-dir=RECOVERY_GIT fsck --full
git --git-dir=RECOVERY_GIT rev-parse HEAD
git --git-dir=PRIVATE_GIT_DIR rev-parse HEAD
cmp -- PRIVATE_GIT_DIR/index RECOVERY_GIT/index
```

The common directory must resolve to `RECOVERY_GIT`, with no owner pointer or alternates:

```sh
git --git-dir=RECOVERY_GIT rev-parse --path-format=absolute --git-common-dir
test ! -e RECOVERY_GIT/commondir
test ! -e RECOVERY_GIT/objects/info/alternates
test ! -e RECOVERY_GIT/objects/info/http-alternates
```

If `RETAINED_CHILD/.git` is still the old gitfile, confirm its pointer resolves to the recorded private directory from the original path, then remove only that file:

```sh
rm -- RETAINED_CHILD/.git
```

Once the retained `.git` path is absent, install the verified copy:

```sh
test ! -e RETAINED_CHILD/.git
test ! -L RETAINED_CHILD/.git
mv -- RECOVERY_GIT RETAINED_CHILD/.git
```

Repeat the independent-copy checks above, then remove the missing original registration and reconcile the receipt. Keep the retained files throughout recovery.

### Manual purge

Orbit has no purge command yet. Before purging the retained root:

- Save all needed data outside it, including refs, stashes, submodule repositories and nested repositories.
- Make every surviving linked worktree independent, or move its shared repository outside the retained root and repair its worktrees against that new location. Repairing pointers back into retention does not meet this requirement.
- Stop anyone from creating or changing worktrees until inspection and purge finish.

Inspect the retained repositories' `worktrees/` entries, including those under `.git/modules` and nested repositories. On the Node, set `retained_root` to the exact recorded path. This read-only check prints each registration file followed by the path of its worktree's `.git` file:

```sh
retained_root='/exact/path/from/retained_git_path'
find "$retained_root" -type f -path '*/worktrees/*/gitdir' -print -exec cat {} \;
```

For every listed target whose worktree survives, check the repository it now uses:

```sh
git -C /path/to/surviving-worktree rev-parse --path-format=absolute --git-common-dir
realpath -- /common/git/directory/reported/above
```

Every resolved common Git directory must exist outside the retained root. A failed command, a path still inside retention, or an unaccounted-for missing target leaves the inspection incomplete: keep the retained root. Account for moved or removed worktrees explicitly; a broken old pointer does not prove independence. Repeat this inspection for every registration printed above.

Only after all data is saved and no surviving worktree uses a retained Git directory, run `rm -rf -- RETAINED_ROOT` on that Node, replacing `RETAINED_ROOT` with the exact recorded path. This is an operator-performed purge; retirement neither performs it nor clears the recorded path and time afterward.

## Before you start

- **Node.** The Instance's Node is on the [build list](/reference/development-containers#the-build-list).
- **PHP version.** A web-serving Project needs its PHP version recorded before the move. A missing version refuses with `project.source_defaults_incomplete`. Set `require.php` in `composer.json` on the default branch, then run `orbit project:update PROJECT --source-access=github_app` to record it. This command also enables source access for a `gh_cli` Project.
- **Service hosts.** In the initial preflight, before creating the container or probing a target, Orbit checks service hosts in the application directory’s `.env` and files named by this Instance’s Process units or Schedules. The application directory follows the same root/subfolder rule as the container; each Schedule names its source working directory’s `.env`. Each admitted Process also selects its working directory’s `.env` when that directory is inside the checkout. Orbit never discovers environment files by walking the checkout, so dependency fixtures under `vendor` or `node_modules` are excluded unless a unit explicitly names one. An answering direct service requires exactly the same host and port as an endpoint admitted by the container access plan from the Instance’s attached targets. Fleet or WireGuard membership alone grants no access. The check uses the recorded endpoint used by the container ACL, firewall and database probe; an address projected for the target’s selected network does not grant access to that different address. HTTP publisher endpoints use the existing [public egress policy](/reference/development-containers#egress-and-dns): its private IPv4 ranges, Node addresses, IPv6 and private DNS domains are refused. The exception is a [private name of the access plan](/reference/development-containers#private-names-of-the-access-plan) at exactly its port: an Instance that holds a private websocket app may name `REVERB_HOST=reverb.orbit` with `REVERB_PORT=8443`. Port 443 of that name stays refused; run `orbit env:sync` on the checkout first to write 8443. Public names are left for the proxy to resolve and enforce at connection time. Other unresolved names and values refuse conservatively. Attached endpoints keep their existing admission checks; this does not prove that the container can reach them. Orbit neither rewrites service hosts nor creates targets from `.env`. It repeats the check before quiesce.
- **Branch.** The checkout is on the branch that Orbit records for the Instance.
- **Deployments.** Wait for an unfinished deployment before starting the move.
- **Processes.** Ordinary systemd Processes keep their ids and desired states. The `vp-dev` preset also moves; Docker Processes and other presets cannot move. A checkout never has a `vite` Process: that preset runs only in a container. Finish pending Process operations, removals and previous runtime cleanup first.
- **Routes.** The Instance has no Route beside its own.
- **Symlinks.** Links must resolve within the checkout. Links into `.git` must name [metadata created by the new repository](/reference/development-containers#migration-symlinks); other Git metadata targets refuse before downtime. Orbit checks dependency package links but skips installed package contents, as the [symlink rule](/reference/development-containers#migration-symlinks) defines. Orbit checks before creating the container and again before stopping host writers. It refuses broken links and external targets before downtime with `instance.migrate_symlink_unsupported`, naming every path and target. Resolve the intended data source before retrying; Orbit does not run project setup to repair links.
- **Retirement.** An owner must have no other registered worktree (the moving Instance's own worktree and a prunable, unlocked registration whose folder is gone do not count), and no retiring checkout may contain a registered descendant. Submodule changes, including untracked submodule files, still refuse because the parent archive cannot preserve them. Ordinary tracked edits, staging, local branches and stashes are carried. All source data stays in the checkout or retained folder on refusal; move other worktrees first, preserve submodule work separately, repair identity or links, or return to the recorded branch before retrying.

Orbit checks service hosts only when an environment selector names that service. A bare host or host/port declaration is not selection evidence. The cache selector uses CACHE_STORE, falling back to CACHE_DRIVER only when CACHE_STORE is absent; broadcasting uses BROADCAST_CONNECTION with the same fallback to BROADCAST_DRIVER. SESSION_DRIVER, QUEUE_CONNECTION, DB_CONNECTION and MAIL_MAILER select their corresponding service. REDIS_CLIENT selects a client library, not service use. Redis and Memcached host, port, password and URL declarations alone do not select a service. Database connection overrides count only for a selected database-backed cache, session or queue.

A host that is not selected by the env does not refuse migration. This does not prove that the app leaves the service unused: hardcoded application config and dynamic selection are outside this check. Orbit does not boot the app or inspect installed packages to infer service use.

Selected endpoints keep the same exact-target and HTTP proxy checks, whether their hosts are loopback, on the Node or elsewhere. Redis and Memcached use ports 6379 and 11211 when absent. Selected database connections use their common known default port; mixed ports require an explicit port. Selected SMTP mail requires an explicit port because the app may use a different default. Listener and browser settings do not become outbound endpoints without a selected connection.

The parser accepts quoted names, quoted values, supported escapes, comments and surrounding whitespace. Variable references are never expanded. Malformed or unsupported syntax refuses with the same error code, naming only the file and line, without the source value. File selection is not a containment guard: explicitly named absolute paths and symlink targets are followed. A named file read failure refuses before downtime with the affected path and no exception text; restore leaves the source unchanged. This check reads literal `.env` keys; it does not execute application configuration or inspect service URLs or defaults absent from those files. Each endpoint refusal names the file, key and safe host:port, and asks you to attach the exact target, correct `.env`, or use a non-network driver.

The `vp-dev` preset keeps its id, preset identity, assigned Vite port and running or stopped intent. It runs as `orbit` with the shared runtime’s `current/bin/vp`, binds `0.0.0.0`, and keeps `/__orbit/vite` on the same Route. The container's PHP unit points `INERTIA_SSR_HOT_URL` at that retained port ([Processes in a container](/reference/development-containers#processes)). Its checkout working directory, environment file and absolute environment paths must stay inside the checkout; Orbit maps them to `/srv/workspace`. Private environment values use the same protected delivery as other Processes.

Orbit accepts the unversioned catalogue command, preset version `1`, and the surveyed Node command that unsets the two Vite certificate variables and runs the Node account’s Vite+ binary on the assigned port. A custom command beside the preset refuses. Missing, reserved or conflicting recorded ports, duplicate `vp-dev` Processes, unknown preset versions and external paths refuse before downtime, naming the Process and reason.

Every moving checkout can carry uncommitted tracked files and staging state. Extra owner worktrees and the other retirement guards still apply.

Orbit prepares the container and probes every attached target before downtime. If a target is unreachable, the checkout keeps serving, its files stay untouched, and its host Processes keep their states.

Nobody works in the checkout during the move. Orbit shows the wake page on the Route, and starts no deployment and no wake of the Instance until the move has ended.

Orbit maps known host executable locations to the container runtime. These locations are `/usr/bin`, `/usr/local/bin`, `/bin`, a home’s `.vite-plus/bin`, and a home’s `.vite-plus/js_runtime/node/<version>/bin/node`. The runtime recipe supplies command names such as `node`, `npm`, `npx`, `vp`, `bun`, `composer`, `deno` and `rg`. `phpX.Y` uses that PHP version; `php` uses the Project’s PHP version. A version absent from the runtime refuses with `instance.migrate_process_binary_unavailable`. A custom path such as `/opt/custom/vp` keeps its meaning even when its name matches a runtime command.

For `/usr/bin/env`, Orbit skips leading `NAME=VALUE` assignments and the options `-i`, `-u NAME`, `--unset=NAME` and `--` before mapping the actual command. A bare command after `env` keeps its PATH lookup. Shell command strings, `env -S` or `--split-string`, and other `env` options stay unchanged; Orbit checks the outer executable before downtime and uses Process readiness to catch a failing command. It does not parse the inner string.

Other absolute executable paths must be executable inside the container before downtime. Otherwise `instance.migrate_process_binary_unavailable` lists every unavailable Process and path. An admission refusal likewise lists every unsupported PHP version. Preset `vp-dev` keeps its preset mapping. Host Process records stay unchanged until cutover succeeds. The task receipt’s `process_translations` lists each projected change with `process_id`, `process_name`, `from` and `to`, including when the move restores the checkout.

Each moved Process whose desired state is running must be active with no pending start or restart job. Orbit reads every running Process, waits five seconds once for the whole set, then requires each to remain active with no pending job, the same nonzero main process ID and the same restart count. This settling window catches immediate crashes and restart loops before the Route moves. A Process that fails this check reports `instance.migrate_processes_failed`, names the Process and triggers recovery.

After a proven cutover, Orbit records each direct moved Process as a Project development definition and links the same Process row in the same transaction. New clones inherit those definitions. Later development deployments apply definition edits to linked copies, and remove a linked copy whose definition the Project removed. The definition stores supported runtime commands by name, such as `php8.5`, `vp` or `node`; Orbit resolves the name from the current runtime when it renders the unit. A supported `vp-dev` copy keeps its preset and uses each clone’s assigned port. An opaque or unknown command that passed readiness keeps its exact guest argv. Later checkout migrations reuse a compatible same-name definition, comparing the intended container units after validating the source Process’s checkout paths. An incompatible same-name definition refuses before downtime and is checked again at cutover instead of being overwritten. Production definitions keep their existing scope.

A cutover proven by the move result captures these definitions even if checkout retirement fails afterward. A failed preflight or a move restored to the checkout captures none. A one-time data repair captures proven migrated defaults that still have direct Processes. It requires the completed move’s container, seed, Process membership and exact activation content; it skips unknown commands or changed and conflicting rows without adopting them. Each Process is proved separately, so a skipped Process does not prevent capture of proven siblings or other Instances. Missing settled migration proof skips every direct Process on that Instance. A migrated default whose runtime has no seed commit is skipped and recorded with that reason; null seed fields on the Instance itself do not prevent proof from its runtime. Each skipped row is recorded in the Activity log with its Instance id, Process id and name, and reason. Read the findings with `orbit activity:list --command=instance:migrate:repair --json`, then `orbit activity:show <activity-id> --json` for the row's properties. Malformed Instance or Process data is also skipped. Unexpected failures record the exception class and a fixed safe message, without environment values or unit content. Each Process capture has its own savepoint: a failed capture leaves its definition and Process link untouched. Only a database infrastructure failure can abort the release migration. The repair reuses one Activity per skipped Process and updates its reason on a later skip, so repeats duplicate neither definitions nor findings. If a later repair captures that Process, the same Activity reports it as captured and keeps the earlier reason in `skip_reason`. Rolling back its migration keeps the captured definitions and links, because clones or later edits may already depend on them. A separate schema change removes the redundant uniqueness check on Instance Vite ports; host reservations stay unique. Its rollback restores the check only when there are no repeated nonnull Node and Vite-port pairs. Otherwise rollback reports the duplicate-group count and leaves the schema, rows and ports unchanged.

Captured command-name definitions need a renderer that supports this migration feature. Switching Gateway code back leaves the definitions, links and schema in place; it does not make those definitions compatible with an older renderer. Once container copies share a recorded Vite port, Gateway rollback must leave the removed Instance uniqueness index absent. It does not reassign ports or reverse captured data.

## Order

A linked worktree can move before its owner. The owner can retire only after its last registered dependent leaves.

Retirement reads the real Git topology. A linked checkout leaves the owner's common store in place. Owner retirement refuses while any other worktree remains registered. Two registrations do not count: the moving Instance's own worktree, which retires first in the same batch, and an entry that Git marks prunable, that is not locked and whose folder is gone. Orbit never prunes such an entry; it stays in the owner's retained `.git`. So the move of the last worktree also retires its owner's old checkout. A worktree added between the checks still refuses at the next check. The owner's stashes stay in its retained `.git`; they do not enter the container.

After the default has moved, an Instance that is still a checkout keeps working until its own move.

## Failure

A failed move leaves the checkout Instance serving as before only if it fails before cutover and restore succeeds. A retirement failure after cutover leaves the container serving; a failed restore keeps the runtime reservation and requires inspection. Successful recovery puts the Route back when the run had started to move it, deletes the new container with its ACL, its firewall rules and its mirror, and drops the reserved runtime record. So the access to the database server that the move added goes too. The checkout and the database are never changed before the Route serves the container. Run the same command again to retry.

The task records whether the Instance moved, was restored and is ready. After a deadline or confirmed cancellation, Orbit reads the native finish. An independent failed phase keeps its code; a deadline-triggered abort keeps `operation.timed_out`, while a user abort stays cancelled. A completed restore drops the container reservation only while this migrate still owns it. A lost worker without a native finish reports an unknown end state and retains its reservation.

When the restore itself fails, the task names the failed step and Orbit keeps the reserved record, so no other Instance takes the address of a container that may be left. The site's state depends on the failed recovery step and must be inspected. Its deployments refuse with `instance.lifecycle_busy` until the same command has run again.

The retirement of the checkout is the last step. When only that step fails, the Instance stays in its container, the task fails with `instance.migrate_retire_failed`, and the source or retained checkout stays on the Node. A retirement check that finds a new blocker reports its refusal code with the same outcome, leaving the source untouched.

Schedule timers stop before copying. A rollback restores their exact captured enabled and active states after the failed container is gone. Success activates their container pairs and removes the host pairs. The source timezone is made explicit in the container timer; the stored calendar stays unchanged.

The command starts a task and follows it until it ends, as [`instance:deploy`](/cli/instance/deploy) does. Ctrl-C stops following, not the move, and exits 130.

## Warnings

For an unattached endpoint selected by a loaded environment file, Orbit first tries a plain TCP connection from the Node when the host is loopback or private. Only an explicit connection refusal (`ECONNREFUSED`) on a loopback or private address lets the move continue with `instance.migrate_env_service_unused`. The warning names only the file, key and safe host:port. A stock unused MySQL configuration therefore does not block a flat-file application. A connection that answers, times out or reports an unreachable host or network retains the normal refusal: the service could not be shown unused. The probe runs as root and checks only for an explicit refusal, not whether the application's user can use the service.

A selected MySQL or MariaDB socket (`DB_SOCKET`, or the selected connection's `*_SOCKET` / `*_UNIX_SOCKET` key) takes priority over its TCP host and port. If that path exists on the Node, Orbit refuses and names the key; the container does not inherit the host socket. A missing path lets the existing TCP rule apply. PostgreSQL directory hosts and Redis socket hosts (`unix://` or a path), socket URLs and `unix` schemes cannot become unused-TCP warnings. Relative, unresolved or uninspectable socket paths also refuse, without displaying their values.

Public addresses and names with any public answer keep their existing handling and are never connected to. Private IPv4 ranges, IPv6 unique-local/link-local addresses and loopback are eligible. Resolution and all connection attempts share two seconds per unique endpoint, with at most 20 endpoints per check (40 seconds of network waiting). Further endpoints that cannot be proved unused retain refusal. Unexpected resolver or socket errors also refuse; they never become an unused-service warning. The check repeats before quiesce.

Warnings are a generic `warnings` list of `{code, message}` records in the Operation result. Human output prints each warning; `--json` retains the list.

The copy carries ignored files, so also tool caches built at the old path. PHPStan and Rector, for example, keep paths such as `phar:///fast/apps/<project>/<name>/vendor/...` in their caches and crash when that path is gone. Before any Process starts, Orbit removes, as `orbit`, every file that meets all of these conditions:

- Git ignores it in the workspace.
- It is in a folder named `cache`, at any depth.
- It is outside `vendor` and `node_modules`.
- Its content holds the old checkout path.

Tracked files, untracked files that Git does not ignore, and other ignored files, such as `storage/logs/laravel.log` or `.env`, stay. When Git cannot list the ignored files, Orbit removes nothing. That failure, or a file that Orbit cannot read or remove, records `instance.migrate_tool_cache_clear_failed` in `warnings`. The move goes on.

A Laravel app also built caches at the old path. Before any Process starts, Orbit runs these commands as `orbit` in the application directory, when the container has PHP and the directory has `artisan`: `config:clear`, `route:clear`, `event:clear`, `view:clear` and `clear-compiled`.

Orbit then reads the driver of the default cache store. Only for the `file` driver does it run `cache:clear`. That store lives in the workspace, and only this Instance used it. Statamic keeps its stache there, keyed by file path; a stale stache can fail the first request. `cache:clear` also deletes real data that the app keeps in that store, such as rate-limiter counts or cached tokens. The app builds them again. A store of another driver, such as Redis or a database, is a service outside the workspace, often shared, and Orbit leaves it alone.

A clear that fails records `instance.migrate_cache_clear_failed` in `warnings`, with the commands that failed. The move goes on. Run `php artisan optimize:clear` in the Instance to finish it.

Selected SMTP on `127.0.0.1` or `localhost`, port 1025 or 2525, passes when this move has the Node's main Mailpit endpoint and will apply development mail. Without that endpoint, Orbit refuses and explains that the container will have no mail forwarder. Other ports and hosts keep the ordinary endpoint check. Direct `::1` stays refused because the forwarders listen only on IPv4; PHP's `localhost` connection can fall back to IPv4.

Mail setup runs after the copied `.env` and before application Processes start. It matches exactly `MAIL_MAILER=log`, with or without matching single or double quotes, using the shared [development mail rule](/reference/development-containers#development-mail). The copied file keeps its quote style and line ending; only `log` becomes `smtp`. A failed attempt or missing or malformed receipt records `instance.mail_update_failed` in `warnings`. Application starts, Route cutover and retirement continue, and mail cannot trigger rollback.

Human output shows the mailer outcome and line numbers, the named conflict skip, or the warning and repair command; JSON retains the same result fields, including `guard_line` when a preceding line is outside the shared whitelist. Repair it with [`instance:mail:update`](/cli/instance/mail-update).

Registered legacy timer Schedules move into the container with their identity, calendar, timeout and desired state. Before cutover a failure restores the host timer; after cutover a Schedule problem is a named advisory result and migration succeeds. See [Schedule migration](/reference/schedules#checkout-migration).

Before downtime, Orbit lets Vite+ resolve and prepare pinned Node versions in the new container’s private store. An invalid or ambiguous pin, or a failed download, verification or resolution, stops the move with `instance.node_runtime_prepare_failed`, naming the pin and its specific network, HTTP, checksum, disk or unknown-version reason. The checkout keeps serving. Projects without a Vite+/Node Process do not fetch an unused Node pin.

An attached Node service permits IPv4 loopback only for its exact recorded host key, port key and published port. The container phase admits the endpoint, enables its loopback socket proxy and probes both TCP hops before quiesce; an unreachable database target refuses while the checkout still serves. Attachment records are not inferred from environment values. A selected database URL override refuses before downtime; use the attached host and port keys.
