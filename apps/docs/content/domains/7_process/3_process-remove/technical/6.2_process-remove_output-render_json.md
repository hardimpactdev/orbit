# JSON Renderer: `orbit process:remove [name]`

[Back to `process:remove` technical contract.](1_process-remove.md)

This page describes the JSON-rendered output for `process:remove`.

**Renderer:** JSON renderer.

## Primitive

None. JSON output is emitted as a machine-readable envelope via `$this->line(...)`.

## Selection

Use this renderer when `--json` is present. `--json` also forces non-interactive input mode and never grants destructive consent.

## Envelope

This renderer uses the shared [JSON Envelope](../../../README.md#json-envelope).

Success data contains the removed process identity and cleanup summary. Partial post-configuration cleanup drift is reported under `success.meta.warnings[]`.

Warning objects contain:

| Field | Meaning |
| --- | --- |
| `code` | Singular product warning code, such as `process.runtime_unit_missing`, with the owning family recorded separately. |
| `family` | State family that owns the warning. |
| `message` | Human-readable warning summary. |
| `next_command` | Suggested command to inspect or repair the warning. |

## Success Example

```json
{
  "success": {
    "data": {
      "process": {
        "name": "vite",
        "node": "app-1",
        "app": "docs",
        "instance": "production",
        "workspace": null
      },
      "removed_runtime_units": [
        "orbit_docs_production_main_vite"
      ]
    },
    "meta": {
      "warnings": []
    }
  }
}
```

`success.data.process` carries `name` plus owner context fields `node`,
`project`, `instance`, and `workspace` from the remove payload. It does not emit
`key` or `label` on this command.

## Error Example

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Use --force to remove this process.",
    "meta": {
      "field": "force"
    }
  }
}
```

## Authorization Error

```json
{
  "error": {
    "code": "authorization_failed",
    "message": "This node is not authorized for 'process:remove' on 'app-1'.",
    "meta": {
      "reason": "missing_permission",
      "missing_permission": "process:remove",
      "serving_node": "app-1"
    }
  }
}
```

## Error Code Vocabulary

- `validation_failed`: missing `name`, missing node/instance/workspace context, invalid context combination, missing non-interactive `--force`, or declined interactive confirmation. An ambiguous bare project selector uses `error.meta.field=instance` and `error.meta.reason=instance_required`.
- `authorization_failed`: caller lacks `process:remove` on the resolved node or instance serving node.
- `process.not_found`: the named process does not exist for the resolved owner scope.
- `gateway_unavailable`: the CLI cannot reach the gateway API before removal begins.
