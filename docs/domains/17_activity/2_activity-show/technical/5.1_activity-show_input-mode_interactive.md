# Interactive Input Mode: `orbit activity:show [id]`

[Back to `activity:show` technical contract.](1_activity-show.md)

This page describes how interactive input mode resolves `activity:show` input
before command behavior starts.

**Input mode:** Interactive.

## Selection

Use this input mode only when both conditions are true:

- the command is running in a TTY;
- `--json` is not present.

When `--json` is present, use
[`5.2_activity-show_input-mode_non-interactive.md`](5.2_activity-show_input-mode_non-interactive.md) even if the process has a TTY.

## Responsibilities

- Read any supplied arguments and options.
- Prompt for `id` when `[id]` is missing.
- Validate field-local values immediately when a supplied value is read or a
  prompt is submitted.
- Re-prompt after invalid field-local values.
- Stop before side effects when the resolved id does not identify a visible
  activity entry.

## Prompt Mapping

### `activity_show.id`

| Property | Value |
| --- | --- |
| Primitive | `text` |
| Label | `Activity id` |
| Source | `[id]` |
| Required | yes |
| Choices | none |
| Default | none |
| Validation timing | When `[id]` is read or when the prompt is submitted. |
| Invalid terminal behavior | Show validation message and re-prompt. |

## Primitive References

- [`text`](../../../../ux/commands/inputs/text-prompt.md)

## Failure Semantics

- Missing required input is collected by prompt before side effects.
- Invalid field-local input shows a validation message and re-prompts until the
  value is valid or the user aborts.
- Path eligibility is evaluated as soon as the id is resolved. If the activity
  entry does not exist or is not visible, fail before side effects after the id
  is resolved.
- If the user aborts a prompt, exit with the standard command failure status
  and do not start side effects.
