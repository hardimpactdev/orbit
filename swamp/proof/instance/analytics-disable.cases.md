# instance:analytics:disable verification cases

`instance:analytics:disable` removes the tracking hosts of an Instance, following [its chart](../../../docs/cli/instance/analytics-disable.mmd). The proof runs the built CLI against a fresh nested topology with the analytics role and a real Plausible, an Instance with tracking hosts on a Node, one behind a Router and one with no hosts. It compares the output with the Gateway records, the Caddy sites, the private DNS records and Plausible's site list. See [verifying-commands](../../../.agents/skills/verifying-commands/SKILL.md).

| Case | Setup and action | Required observations |
| --- | --- | --- |
| Disable | Disable an Instance with two tracking hosts, one outside the TLD, with `--yes`. | The private DNS record goes first, then the Caddy sites, and on a Router the tracking certificates. The tracking Routes and the site binding are deleted. Other sites on the Node stay and Caddy was reloaded, not restarted. The hosts no longer answer. |
| Plausible keeps the site | Disable, then read Plausible. | The site, its history and its goals stay. Disable made no call to Plausible, and works with the credentials removed. |
| No hosts | Disable an Instance without tracking hosts. | The result is `Skipped — nothing to change (analytics.tracking_absent)` and the exit status is success. No run starts and nothing changes; with `--json` the record carries `analytics.tracking_absent`. Fails today: the result is `Analytics tracking disabled.` with no reason code. |
| Repeat | Run the same command again after a success. | The same skip as for no hosts. |
| Consent | In a terminal answer the prompt with No, Enter, Ctrl-C and end of input. Then run it noninteractively and with `--json` without `--yes`. | The prompt names the Instance by name and the effect, with No selected. Each decline ends with `input.cancelled` and sends no request. The noninteractive and `--json` calls are refused with `input.confirmation_required`. With `--yes` there is no prompt, also with `--json`. Fails today: the prompt shows the Instance as `#<id>` and does not state the effect. |
| Competing change | Disable while another analytics or Route change runs for the Instance. | `operation.target_busy`. Nothing changes. |
| Placement change | Change the Instance's hosts or placement at the moment of admission. | `analytics.tracking_changed`, with nothing changed. A change after admission is not checked: Fails today, disable checks only at admission. |
| Failure after a partial change | Make private DNS removal fail, Caddy refuse the config, and the final check find a site, one at a time, and a failure outside any named step. | `private_dns.publication_failed`, `route.withdraw_failed`, `route.removal_check_failed` and `analytics.disable_failed`. The tracking Routes and the binding stay, and `operation:show` shows the failed step and its error code. Sections already withdrawn stay withdrawn. After the fix the same command skips what is gone and succeeds. Fails today: the Routes stay `retiring` with no failed step or error code. |
| Output forms | A wide and a narrow terminal, output piped to a file, and `--json`. | A detail with Instance, Domain, Tracking and the request ID at the wide width, and labeled records at the narrow one. The piped output has no animation or escape codes. With `--json`, stdout holds the tracking record with `request_id`. Fails today: with `--json` the command prints the task result and not the tracking record, and the detail shows the Instance as `#<id>`. |
| Missing input | In a terminal, run the command with no argument and cancel the list. Then run it noninteractively and with `--json`. Then use `0`, `-1` after `--`, `abc` and a name. | The terminal lists Instances, and cancel ends with `input.cancelled` and no request. The other calls give `instance.id_invalid`, with no request. Fails today: the Instance is a required argument, so a call without it is refused by the parser, and `-1` without `--` is read as an option. |
| Unknown and access | An Instance that does not exist, and a caller without a grant to the Instance's Node, each with `--yes`. | `http.404` and `node_access.required`. Nothing changes. Fails today: the CLI asks for consent before it checks the Instance. |
| Activity and output | After a successful run and a failed one, read the task, Activity and every command output. | No credential, cookie or token appears. |
