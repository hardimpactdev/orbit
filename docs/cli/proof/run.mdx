```bash
orbit proof:run <commit> [--all] [--report-only] [--keep-failed] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `commit` | yes | Full 40 or 64 character lowercase commit SHA. |

The selection list maps the CLI, Gateway, SDK and native execution files for `node:role:add` to its approved cases. Changes to shared proof admission or failure rendering select every available cases file; test-only changes remain skipped.

| Option | Default | Meaning |
| --- | --- | --- |
| `--all` | off | Run every case, not only the cases that the commit selects. |
| `--report-only` | off | Record reporting intent. Capacity waits and pool eligibility are the same with or without this flag. |
| `--keep-failed` | off | For an operator proof, keep the VM of a failed run for 60 minutes. CI always deletes its VMs. The result names its VM, group and expiry. The Gateway cancels the group at expiry. Other proofs do not preempt it. A passing run deletes its VM. |
| `--idempotency-key=KEY` | generated | Retry the same start with a permanent key. See [Start keys](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Print the final result as JSON, with the verdict of each case. |

```bash
orbit proof:run 0123456789abcdef0123456789abcdef01234567
```

In a terminal, an omitted commit is asked for with a text prompt. A noninteractive or `--json` call that omits it is refused with `proof.commit_invalid`, and so is a value that is not a full lowercase SHA. A refused call sends no request.

The command takes the commit and nothing else. The calling Node needs an access grant to the Gateway Node. Continuous integration calls it for every change to command code; see [the proof CI](/reference/feature-flow#the-proof-ci).

Built so far: the trust check, the case selection, the run in a task VM and the verdict of each case. The CI job `proof-run` is part of Required checks. A failed case or missing verdict fails it. Capacity waits never pass as a proof. Not built yet: the receipt store.

The proof CI summary states the [remaining base-refresh limit](/reference/command-development-pipeline#2-development-environment), including when a run passes.

## Which commits Orbit proves

Orbit proves only code that it can trust. The commit must be the head of a branch of the Orbit repository. A commit from a pull request from elsewhere is accepted only when it is the head of that open pull request, the pull request carries the label `run-proofs`, and a maintainer approved exactly that commit. A new push needs a new approval. Orbit fetches the commit itself, so a caller cannot change what runs.

## Which cases run

Orbit lists the files that differ between the commit and its merge base with `main`, and maps each path to commands with the selection list in the commit. A code change runs the command’s whole cases file. A change only to its cases selects added or changed entries and users of changed fixtures, vars or batch setup. The runner expands and compares both definitions. Changes to the runner, selection code or selection list disable narrowing for every selected command. Tooling alone selects no commands. Unknown fixture keys select the whole file. CI publishes its exact base/head result, and Orbit reads it; a missing or invalid result runs the whole file. Deleted entries select nothing. `--all` and an incomplete file list run every case. A selection-list change alone selects nothing. [Choose the cases](/reference/feature-flow#choose-the-cases) holds the mapping rule.

When only paths that need no proof changed, such as documentation and charts, the command succeeds with `Skipped — nothing to prove (proof.nothing_to_prove)`. It starts nothing. A path that matches no line of the selection list is refused with `proof.path_unmapped`, so a new kind of file never passes unproven by accident. Paths that are marked as having no case yet, and commands without a cases file, are listed as uncovered in the result and do not fail the run.

## The run

CI proofs join one first-come-first-served queue, ordered by their proof Operation id. The front proof takes every free CI place on hosts with usable bases, up to its number of batches. It needs at least one place. A full pool waits within a two-hour admission budget; an expired wait fails clearly. Other CI proofs cannot pass it.

Orbit reads the cases at the trusted commit and expands their variant ids. It sums measured case durations from prior reports for each whole batch, then assigns the longest batches to the least loaded VM. A batch never splits. Unseen cases use the median measured duration, or one second when no measurements exist.

Each VM's share gets a run budget from its batches, at most two hours. When a share of more than one batch needs more, the proof waits for another CI place, as long as some usable place is taken. With every usable place free, it runs anyway. Orbit records the verdicts of each batch as the batch ends, so a share that reaches its budget keeps them; only the cases of its unfinished batches are `unrun`.

Each allocated VM starts from the host base with the task checkout at the tested commit. Orbit checks that commit, restores the nested fleet, and runs the VM's assigned batches in order. Before each batch it restores the head checkout, because replaying a changed case with `fails_on_base: true` may switch it to the merge base. Each batch runs its declared setup. A setup failure leaves missing cases unrun. Execution retries nothing.

Operator proofs use one VM per command through the task pool's FIFO admission. Their optional `--keep-failed` retains a failed VM for 60 minutes. CI ignores that option and always deletes its VMs.

Every run releases its VM after success or failure. If cleanup fails or a run never starts, normal group cancellation deletes the VM. One live or releasing VM holds one place until deletion is confirmed.

Orbit reads the full case reports, checks the expected case identities and merges every VM’s verdicts into one report. A missing, duplicate or unexpected verdict prevents a pass. The proof closes after all runs end and passes only when every selected command has all its cases passed. A selection with no command passes without claiming a VM.

## The execution switch

`proof:run` works in two stages. Admission checks the commit and selects the cases. Execution creates the group and runs them. Execution is on by default: the Gateway setting `proof.execution` (`ORBIT_PROOF_RUN_EXECUTION`) is `true`. Set it to `false` and a commit that selects cases ends with `proof.execution_disabled`, and the proof Operation holds the selected cases and the uncovered paths. While it is off, the command works as a dry run: it creates no group and starts nothing. A commit with nothing to prove still succeeds, and every refusal of admission still applies.

## Verdicts

Each selected case ends `passed`, `failed` or `unrun`. A case that exceeds the budget is `failed`. A case is `unrun` when its setup could not start or the run stopped before it. Neither `failed` nor `unrun` counts as a pass. If the fleet never becomes ready, every selected case is `unrun`.

A run reported as `interrupted` keeps that status and records `outcome: interrupted`. Its coverage is inconclusive, even when every recorded case passed. Orbit keeps completed batch reports when interruption prevents the final report. Completed verdicts stay as they are, including failed cases; missing cases remain `unrun`. After every run ends, the proof is `failed` if any completed case failed or any non-interrupted run did not pass. Otherwise a native interrupted run makes the proof `interrupted`, with `proof.run_interrupted`. Thus a concurrent interruption cannot hide a completed failure. Cancellation, admission interruption, workspace mismatch and timeouts keep their existing failure rules; Orbit does not infer native interruption from them.

The CI summary and receipt preserve `interrupted` and the job exits nonzero. An interrupted outcome never passes, including with all passed rows. Malformed coverage or a nonzero CLI exit cannot pass either.

The result names the commit, each case with its command, selection reason, verdict and duration, and the uncovered paths. The `program` of a case is the cases file and the case id, `swamp/proof/firewall/allow.cases.yaml#new-restricted-allow`; a `failed` or `unrun` case also carries its cause and the failed checks. The VM is destroyed after the run, so the evidence lasts only as long as a receipt store is not built; the verdicts stay in the result.

| Outcome | Exit status |
| --- | --- |
| The proof completed with every selected case passed, or nothing needed a proof. | `0` |
| Native execution was interrupted. | Nonzero; the coverage is inconclusive. |
| A selected case failed or did not run. | Nonzero. The command names each such case and the receipt link. |
| Orbit refused the request. | Nonzero, with the one-line error envelope. |
| You pressed Ctrl-C. | `130`. |
| The process received SIGTERM. | `143`. |

Ctrl-C, or `operation:cancel` on the proof, ends every run at once and cancels their groups, which destroys the VMs. A case that was running stops with its VM. Each group ends when its run ends.

## After the run

The run destroys its VM after success and after failure, and Orbit records the end of the group from that step. If the destroy step did not run or failed, because the run was cancelled, timed out or failed early, Orbit cancels the group the normal way, which destroys the VM. The verdicts stay as they are. If that cancel fails, the group stays for another `task:cancel`.

A repeat starts a new run, because a proof checks the commit as it is now. The same `--idempotency-key` returns the original run instead of starting another.

## Errors

The request answers at once with the proof Operation. The checks of the commit, the selection of the cases and the admission run after that, in a queue job. A refusal of the admission is therefore on the proof Operation, with its code and message, and the command prints it when it follows the proof. The request itself refuses only `proof.swamp_unavailable`, a start that the extension, the access check or the idempotency key refuses, and `proof.commit_invalid`, which the command checks before any request.

| Code | Meaning |
| --- | --- |
| `proof.run_interrupted` | Native execution stopped with inconclusive coverage, without a completed failure taking precedence. |
| `proof.commit_invalid` | The commit is missing or is not a full lowercase SHA, and the CLI cannot prompt. |
| `proof.commit_not_found` | The Orbit repository has no such commit. |
| `proof.commit_untrusted` | The commit is not the head of a branch of the Orbit repository, nor the head of an open pull request with the label `run-proofs` and a maintainer's approval of exactly that commit. |
| `proof.path_unmapped` | A changed path matches no line of the selection list. The message names the path. |
| `proof.cases_failed` | A selected case failed or did not run. The result holds each verdict. |
| `proof.workspace_commit_mismatch` | The workspace of a run's VM was not at the commit under proof when the run checked it, before any case, for example because the import of the commit failed and left a clone of main. No case ran. The result names the commit that was expected and the one the VM had (`workspace.expected`, `workspace.found`, empty when the VM printed none), and the human output prints both. A VM that cannot be reached at all fails as `proof.run_failed`. Run the proof again. |
| `proof.run_failed` | The VM or the test fleet of a run did not become ready, or its cases printed no verdict. Every selected case of that command is `unrun`. |
| `proof.queue_unavailable` | The queue refused the job that admits the proof. No case ran. Run the command again. |
| `proof.admission_interrupted` | The job that admits the proof was lost before it started the runs. No case ran, and each selected case is `unrun`. Run the command again. |
| `proof.capacity_timeout` | No place on a host with a usable base became available within the two-hour admission budget. No case ran. |
| `proof.execution_disabled` | Cases are selected, and proof execution is switched off. The input of the proof holds the selected cases and the uncovered paths. |
| `proof.selection_invalid` | The selection list of the commit is malformed. The message names the line. |
| `proof.github_unavailable` | GitHub could not be read, so the commit or its cases cannot be checked. Run the command again. |
| `proof.swamp_unavailable` | No active Swamp Node exists to run the proof. |
| `node_access.required` | The calling Node has no access grant to the Gateway Node. |
| `extension.disabled` | The tasks extension is off. |
