# Interactive Input Mode: `orbit tool-stop`

[Back to `tool-stop` technical contract.](1_tool-stop.md)

**Input mode:** Interactive.

## Mode Selection

This contract applies only when the process is attached to a TTY and `--json`
is not present.

## Prompts

### `tool_stop.tool`

| Property | Value |
| --- | --- |
| Primitive | `search` |
| Label | `Tool name` |
| Source | `tool` argument |
| Required | yes |
| Choices | Tool names from the local tool catalog. |
| Default | none |
| Validation timing | When the prompt is submitted. |
| Invalid terminal behavior | Re-prompt until a catalog tool is selected or the operator aborts. |

### `tool_stop.target`

| Property | Value |
| --- | --- |
| Primitive | `select` |
| Label | `Target node` |
| Source | `--app`, `--node`, local `node:default`, or gateway-known caller identity. |
| Required | yes |
| Choices | Visible node names when no explicit/default/self target resolves. |
| Default | none |
| Validation timing | Before side effects. |
| Invalid terminal behavior | Re-prompt until a visible tool node is selected or the operator aborts. |

## Target Resolution

Interactive mode uses the same hierarchy as the command contract:

1. `--app` selector: app slug, app domain, or `<slug>.<node-tld>`.
2. `--node`.
3. Local `node:default`.
4. Gateway-known caller identity.
5. Target-node prompt when an interactive caller on the gateway still has no
   target.

When `--app` and `--node` are both present, they must resolve to the same node
before the command starts the stop action.

## Failure Behavior

Prompt abort exits with `validation_failed` and does not start side effects.
