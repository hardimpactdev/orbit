## Usage

```bash
orbit node:converge <node> [--base | --roles=a,b] [--idempotency-key=KEY] [--json]
```

| Argument | Required | Meaning |
| --- | --- | --- |
| `node` | yes | Positive numeric Node ID. |

| Option | Default | Meaning |
| --- | --- | --- |
| `--base` | off | Apply only Orbit's own layer: the agent, the Node’s CLI state, Orbit-owned files and units. |
| `--roles=a,b` | all recorded roles | Apply the base plus only the named roles already assigned to the Node. |
| `--idempotency-key=KEY` | none | Use the shared [keyed-start contract](/reference/operations#retry-a-start-with-a-key). |
| `--json` | off | Follow the shared [CLI input and output standard](/reference/cli-ux#input-and-output-modes). |

```bash
orbit node:converge 7
orbit node:converge 7 --base
orbit node:converge 7 --roles=app-dev,database
```

With no scope flag, Orbit applies the base and every recorded role to repair drift. The two scope flags are mutually exclusive.

## How it works

Access follows the node family's [shared authority rule](/cli/node) (`NodeAccessAuthorizer`). The target must be an active, managed Linux Node. A converge holds the [shared Node admission lock](/reference/node-provisioning#converge-the-orbit-footprint), excluding role addition or convergence, enrollment and agent rekey on that Node. It also reserves its recorded VPN hub against another converge until settlement.

Every run applies these phases in order, idempotently and within the selected scope:

1. **Input.** Prepare the recorded desired state for this attempt.
2. **Agent.** Apply the Node agent, Orbit-owned files and units at the release's versions, and the [kernel policy](/reference/node-provisioning#kernel-policy). Keep the packaged CLI only on [CI runner Nodes](/reference/node-provisioning#orbit-cli); remove the managed CLI link, versioned binaries and root profile on other Nodes. These Nodes need no CLI release. Restart services only when their managed files change.
3. **Software.** Read the selected software pins from `recipe.json`, install them and hold the packages at those pins.
4. **Roles.** Repair the selected roles' configuration.
5. **Tools.** Apply recorded Tools within scope. A failed Tool is marked failed on its own record; other Tools continue, and that Tool failure alone does not fail the Operation. When the Tool helper itself cannot run on the Swamp Node, the phase fails and marks no Tool failed ([converge the Orbit footprint](/reference/node-provisioning#converge-the-orbit-footprint)).
6. **Network.** Apply the recorded network on the hub first, then the Node, and wait for the handshake. The hub side prunes only the peer files of Nodes that are gone or being removed; a Node that joins while the run waits keeps its peer ([Converge the hub](/reference/wireguard-endpoints#converge-the-hub)). With no recorded network in scope there is nothing to apply. A target hub is applied once and waits only for the peers that were live before the change; an offline peer needs no handshake. On the hub, the run also applies and checks [its source unit](/reference/wireguard-endpoints#the-hub-answers-from-its-endpoint-address) and opens SSH on its LAN address to its private network. A Node on the hub's private network first proves that the hub's [LAN endpoint](/reference/wireguard-endpoints#the-lan-endpoint) is the hub, by its SSH host key; without that proof nothing changes. When the hub endpoint changes, only a handshake after the change counts; without one, the Node goes back to its previous files and the phase fails.
7. **Check.** Check the selected software, units, role configuration and recorded tunnel.

A repeat starts a new Operation and applies all phases again; it is not skipped at admission. With no drift, it reports zero changed tasks on the Node. Its elapsed time is reported for measurement; load on the shared execution host can affect it.

A failed phase leaves the Operation failed with its failed step and error code. Completed and partial changes stay on the Node; nothing is rolled back. A new attempt starts at input and safely reapplies every phase. Temporary files are removed when work stops after success or failure; an interruption does not prove cleanup completed, and incomplete cleanup is reported without hiding the original failure.

The Operation's `result.failure`, shown by `orbit operation:show`, contains `task` (nullable, at most 120 printable ASCII characters), `host` (`target` or `hub`, never an address), and `reason`. For each host whose statistics count failure or unreachability, Orbit selects its last failed or unreachable task. Of those tasks, the earliest in play and task order wins; a tie selects `hub`. This excludes earlier ignored and rescued failures. For an unreachable host, its unreachable record wins over an earlier failed one. An ignored failure in an `always` section after the fatal task can be named instead of it: the callback does not mark ignored records.

Converge task names are static because a failed converge shows them. A name is shown only when it has at most 120 letters, digits, spaces, commas, apostrophes, plus and hyphen signs, and no token of 16 or more characters; any other name is withheld. A test holds every converge task name to that rule. Hidden tasks return `task: null` and `reason: "hidden"`. When a host's statistics fail but only censored records identify its failure, Orbit reports that host as hidden. Missing, malformed or task-free failure reports leave `failure` absent. Successful results have no `failure`. Task output, messages, commands, arguments and loop values stay private.

Reasons are selected in this order:

| Reason | Evidence |
| --- | --- |
| `hidden` | The task or result has `no_log`, `_ansible_no_log` or censored output, including a hidden loop result. |
| `unreachable` | The host result marks the host unreachable. |
| `timeout` | The host result has return code 124. |
| `assertion` | The action is `assert` or `fail`, or the result has `assertion` or `evaluated_to`. |
| `command_failed` | The result has a nonzero integer return code; `rc` records it within signed 32-bit bounds. |
| `module_failed` | Any other failed result. |

The failed phase remains in `result.failed_phase`. The Operation's error detail keeps its existing native failure summary.

## Errors

| Code | Meaning |
| --- | --- |
| `node.id_invalid` | The Node ID is missing in noninteractive mode, or is not a positive integer. |
| `http.404` | No Node has that ID. |
| `node_access.required` | The shared authority rule refuses the caller. |
| `node.converge_unsupported` | The Node is not active, managed and Linux. |
| `validation.failed` | Both scope flags were supplied, or the role selection is empty, unknown or not assigned to the Node. |
| `operation.target_busy` | Node convergence, role addition or convergence, enrollment or agent rekey holds the Node, or another converge reserves its hub. |
| `operation.native_failed` | A phase could not complete, including when the Node cannot be reached. The Operation identifies the failed step. In the `network` phase, the failed assertion names the cause: `node.hub_lan_unreachable` when the hub's [LAN endpoint](/reference/wireguard-endpoints#the-lan-endpoint) is not directly routed from the Node's `lan_ip` or does not answer SSH, `node.hub_lan_identity_mismatch` when the machine there does not have the hub's host key (in both cases no WireGuard file changed), `node.hub_switch_no_handshake` when a new hub endpoint got no handshake (the previous files are back), `node.hub_switch_load_failed` when `wg` did not load the configuration for the new hub endpoint (the previous files are back, with no wait for a handshake), `node.hub_switch_unpinned` when the Node could not pin its tunnel to the new endpoint (nothing changed), `vpn.endpoint_not_local` when the hub does not hold its public endpoint address, `vpn.hub_peer_missing` when a recorded peer is not on the hub's interface. |
